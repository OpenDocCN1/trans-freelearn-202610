
- CiviCRM目前的一个弱点是变更跟踪机制有限。虽然v3.2及更早版本能很好地跟踪最近一次修改是由谁在何时完成的，但关于修改性质的信息却很少。V3.3首次引入了全面审计跟踪机制，数据库中任意一项修改都会被记录并可访问。用于审查、交互和从这些变更中恢复的工具起初有限。然而，原始数据将保留在那里，保护你免受意外删除的影响。未来，我们可能会看到质量保证和审核功能，使主管能够监控和批准自助服务和一线工作人员的更改。
- 从开发者角度进一步讨论，v3.3 包含了升级版的 jQuery 和 jQuery UI，以及一套用于安装 CiviCRM 扩展的新机制，这些扩展可用于报表、自定义搜索、支付处理器和其他工具。CiviCRM社区正在迅速扩大，带来了许多新的参与者，他们参与开发和扩展该软件，以满足其组织的需求。该扩展框架为针对特定需求打包和传播工具提供了更大的灵活性。它使社区能够开发和维护专用功能，而无需将其包含在核心下载中。

与每次发布一样，整个软件中都有大量细微改进，旨在提高性能、创建更高效的工作流程并扩展功能。

## 定制与扩展

在本书开头，我们将CiviCRM的开源许可作为该软件的主要卖点之一进行了介绍。开源意味着源代码随时可用，并且可以在不违反许可的情况下进行修改或添加。简而言之，这意味着你可以打开引擎盖，随心所欲地修补。

当然，“修补”并不是真正让你受益的地方。真正受益的是能够真正定制、扩展、添加、重构，或做任何你需要做的事，以确保该软件适合你所在组织的需求。然后，你可以与社区分享，这样你就能从他们改进、编写文档、支持和扩展该软件的努力中受益。这就是开源的真实价值。与专有的闭源软件不同，你并不完全依赖软件所有者的路线图计划（祈祷他们会构建你所期望的功能），也不需要通过他们的技术支持团队来实现软件修改。开源意味着你可以自己修改代码，或者聘请开发人员来帮助你实现需求。

虽然深入探讨CiviCRM定制超出了本书的范围，但我们希望为你提供一些最佳实践和总体方向，以便你能有效开展自己的定制工作。

## 为定制而生

首先要认识到，CiviCRM 生来就是为定制而构建的。如果你与核心团队交流，他们会告诉你，他们构建该软件的明确目的就是使其尽可能易于扩展。他们不希望代码束缚你，而是希望帮助你快速高效地实现定制需求。这通过几种方式实现。

## 钩子与覆盖

软件支持定制的第一种方式是通过代码管理辅助。钩子提供了将代码注入现有流程的工具，是定制的干净（且通常最易升级）方法。

如果你熟悉 Drupal 的钩子结构，你会发现 CiviCRM 的结构也遵循类似模式。当特定事件发生时，你可以将自己的代码插入执行流程，而无需修改任何人的代码。在 Drupal 中，你通过模块实现钩子；在 Joomla! 中，钩子通过一个单一的钩子文件来处理，该文件可以存放在 PHP 覆盖目录中（如后续部分所述）。无论哪种方式，钩子实现都包括调用钩子函数、限制其范围（如适用），以及根据需要修改或添加代码行为。例如，你可以使用 buildForm 钩子来修改网站上显示的配置文件表单的默认值。

有关可用钩子列表及具体实现指导，请访问 `http://wiki.civicrm.org/confluence/display/CRM+DOC/CiviCRM+hook+specification.`

钩子很干净，通常更受青睐，因为你通常只处理和影响与你特定需求相关的代码。在前面的修改默认表单值的示例中，钩子允许你锁定特定表单，只修改所需字段，不触及或影响表单类中的任何其他字段或流程。你的定制“足迹”保持在最小。

然而，有时你可能会有更重要的定制，无法用钩子完成，或者当前没有可用的钩子。在这种情况下，CiviCRM 允许你为 PHP 和模板（`.tpl`）文件定义覆盖目录。覆盖 `.tpl` 文件来修改页面布局，往往比修改决定显示内容的 PHP 代码更容易。

覆盖目录，顾名思义，是一个与核心代码不同的位置，你可以在其中放置修改后的文件，这些文件将“覆盖”核心文件。在使用覆盖目录之前，必须在全局设置中定义它们。访问 **管理 | 配置 | 全局设置 | 目录** 来设置这些位置，并注意帮助文本中的推荐设置（取决于你的 CMS）。配置完成后，你需要将原始核心文件的修改副本放在覆盖目录内相应的文件夹路径中。

例如，假设你在 Drupal 安装中用于 CiviCRM 的 PHP 覆盖目录是 `/var/www/domain.com/public_html/sites/domain.com/files/civicrm/custom_php/`。要覆盖用于创建新个案的表单文件，你需要将修改后的文件放在 `/var/www/domain.com/public_html/sites/domain.com/files/civicrm/custom_php/CRM/Case/Form/Case.php`。

在 Joomla! 中，放置覆盖文件的标准位置将是你的媒体目录。例如：`/var/www/domain.com/public_html/media/civicrm/custom_php/CRM/Case/Form/Case.php`。

> 特定配置文件、贡献页和事件的文件可以与其他配置文件、贡献页和事件的文件分开覆盖。可插入一个额外的目录层级，包含要覆盖的配置文件、贡献页或事件的 ID。例如，`/var/www/domain.com/public_html/sites/domain.com/files/civicrm/custom_tpl/CRM/Contribute/Form/Contribution/11/Main.tpl` 将覆盖 ID 为 11 的贡献页。
