
使用覆盖文件时，有几点重要事项需要注意：

- PHP 覆盖文件夹必须从 CRM 目录构建，如前面示例所示。模板覆盖将从 `/templates/CRM/` 目录构建。换句话说，这些结构是从 `civicrm/` 包子文件夹（在您的核心文件中）构建的。
- 覆盖文件本身应该是原始文件的修改版本。即使您只修改了文件的一小部分，整个文件也会替换相应的核心文件，因此必须包含所有必要的代码。这是钩子（hook）与覆盖文件之间的关键区别——钩子可以在代码行级别进行修改，而覆盖文件则是在文件级别进行修改。
- 请务必使用正确版本的核心文件，并保持核心文件和覆盖文件同步更新。例如，如果您的站点运行的是 v3.2.4，请不要使用 v3.2.5 的核心文件作为覆盖定制的基础。较新的修订版可能包含会破坏您站点功能的额外更改。当将站点升级到较新的版本或修订版时，您应该计划仔细比较覆盖文件中的代码，并使用新的核心版本重新实现您的修改。

这两种定制方法都有助于您遵循开发中的一个重要原则：不要改动核心文件。只要有可能，您就应该避免修改核心代码文件。否则，您将无法顺利升级代码库，并且容易忽视（甚至丢失）重要的修改。

## API

如果您的定制是在 CiviCRM 环境内进行的，您可以轻松访问并使用整个代码中的类和方法。但是，如果您在该环境之外扩展 CiviCRM（例如 Joomla! 扩展或 Drupal 模块），您可能需要使用 CiviCRM 的公共 API。

您可以在线查看 API 列表：`http://wiki.civicrm.org/confluence/display/CRMDO/CiviCRM+Public+APIs`，或通过（相对较新的）API 文档 `http://api.civicrm.org` 查看。

API 可以通过您站点中的 PHP 代码、CiviCRM 的 REST 接口、JavaScript 或 AJAX、Smarty 模板、Drupal 中的 Drush 模块，甚至通过创建其他语言（如 Perl）的标准包装器来调用。根据您的访问方式，您需要相应地调整带有相关参数的函数调用。有关通过这些不同方法实现 API 的更多详细信息，请访问上面提供的 API 链接。

## 社区与合作

核心团队和许多活跃的开发者也经常在 IRC 频道上交流，那里是提问并获取专业答案的好地方。与任何实时聊天室一样，IRC 频道在全天不同时段会有不同的活跃用户数量，以及他们是否有空帮助您解决问题。因此，如果对话看起来很冷清，不要放弃——稍后再来，看看是否有人在。

您可能还想熟悉公共问题跟踪器（http://issues.civicrm.org）。开发团队使用它，并向社区开放，用于跟踪 bug 和功能请求。

如果您遇到看起来像是软件 bug 的问题，请不要立即创建新问题单。它可能只是您的 CiviCRM 实现所特有的问题，也可能是已经被报告甚至已在较新版本中修复的 bug。一个很好的起点是在 http://forum.civicrm.org 上搜索相关帖子。如果找不到任何内容，请尝试在 http://demo.civicrm.org 的演示站点上运行的最新稳定版 CiviCRM 上重现该错误。然后将您的问题发布到相应的论坛，附上收到的错误消息文本、发生问题时您在做什么，以及您是否可以在演示站点上重现该问题。几小时或一天内，您可能会得到有用的回复。可能是建议的修复方法或变通方案、wiki 相关页面的链接，或者要求您在 bug 跟踪器上创建新问题。

如果您能够解决发布到论坛上的问题，最好在话题中更新最终有效的解决方案，以帮助其他可能遇到同样问题的人，并向帮助您的人提供反馈。请记住，他们也是人。许多在论坛上提供帮助的人并没有因为在那里花费时间而获得报酬。一句“谢谢”和尊重的语气对获得帮助大有帮助，而粗暴、自以为是的语气更可能遭到冷遇。

如果您花了一些时间弄清楚了如何做某件未被记录的事情，那么最好在 wiki 上写下您的做法。这不仅会帮助您在六个月后再次需要时记住如何做，也会帮助其他人。其中一些人甚至可能为您的修改提供额外的改进。

论坛不仅仅是用来询问潜在 bug 的。它们也是询问如何做事的好地方。请尽量具体地描述您的请求，说明您已经尝试过哪些方法，并谈谈您正在考虑用什么可能的方法来满足需求。

一种日益流行的学习和分享 CiviCRM 经验的方式是本地聚会。这些相对非正式的活动通常包括演示某地区的人们如何使用 CiviCRM，可能还有一些技术讨论，以及聊天和提问的机会。到目前为止，世界各地的城市都举办过聚会，包括柏林、波士顿、布里斯托尔、布鲁塞尔、布法罗、芝加哥、达拉斯、沃斯堡、德累斯顿、都柏林、日内瓦、伦敦、蒙特利尔、孟买、纽约、旧金山、西雅图、台北、多伦多、华沙和华盛顿。请查看 http://civicrm.org，看看附近是否有聚会，如果没有，可以考虑发起一个。

核心团队和越来越多的其他提供商还举办用户、管理员和开发人员培训活动。还有过几次代码冲刺（code sprint），第一次 CiviCon 于 2010 年在旧金山举行，第二次于 2011 年 3 月在芝加哥举行。面对面的交流为在线社区空间中的分享和社交提供了宝贵的人际维度。最有价值的互动和学习通常发生在走廊里和举杯交谈中。

由于这对您和社区都有好处，我们强烈鼓励您以任何您觉得舒服的方式参与。可能是在 wiki 上查找建议、在论坛上发帖提问、参加聚会，甚至参加培训营。许多人发现他们投入的时间和精力是值得的。

您可能还会发现，在某个时刻，您希望看到 CiviCRM 添加某个功能或进行一些调整。http://civicrm.org/contribute 列出了当前的 Make It Happen 倡议，社区成员可以通过捐款来资助改进和新功能的开发。有能力的人还可以为新倡议提供 50% 的种子资金，以帮助其启动。
