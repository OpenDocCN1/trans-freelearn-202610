In a multi-tier architecture design like the one depicted in Figure 4.3, resources in the private subnet will not have direct access to the internet. These private subnets will not be associated with the public route table and will not be assigned a public or elastic IP address. This is because these resources are meant to be private and accessible only from other resources within the VPC, such as load balancers or databases.

Figure 4.3 – VPC with private subnets and route tables to allow EC2 instances access to the internet via NAT gateways

Nevertheless, resources in the private subnet need access to the internet and even other public services on AWS. To grant those resources access to the internet, while still ensuring higher levels of security, such as not having to assign a public IP address to those resources, you can configure a NAT gateway.
