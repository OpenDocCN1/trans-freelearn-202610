## Using AWS Serverless Application Model (SAM) to Develop and Deploy Serverless Applications

### Overview of AWS SAM

AWS SAM is an open source framework designed specifically for building serverless applications on AWS. It provides a simplified definition of the serverless infrastructure needed in AWS CloudFormation syntax. AWS SAM is an extension of CloudFormation and provides a shorthand syntax to express functions, APIs, databases, and event source mappings. With SAM, you can define your serverless application with just a few lines of code in a YAML configuration file.

### Key Components of AWS SAM

AWS SAM primarily consists of three primary components:

- **SAM template:** A configuration file that follows the YAML format. This file defines the resources in your serverless application using the SAM syntax. You use the template to declare the resources you want to provision for your serverless application. The resources you would declare in a CloudFormation template can also be declared in a SAM template.
- **SAM CLI:** A CLI that provides tools to build, test, and deploy your AWS SAM applications.
- **Deployment methodology:** AWS SAM integrates with AWS CloudFormation, leveraging its capabilities to deploy serverless applications as stacks and manage them throughout their life cycle.

## Developing with AWS SAM

### Creating a New SAM Application

To initialize a new serverless application with AWS SAM, you must use the SAM CLI, which you will have to install. The Project Task section later in this chapter will guide you through the process in a detailed, step-by-step manner. You can then use the sam init code command to create a new SAM project with a predefined template and directory structure, helping you start quickly, as per the following example command:

```
sam init --runtime python3.9 --name todo-list-application
```

### Defining Resources in a SAM Template

To use the SAM service, you will need to create a SAM template within which you define your AWS resources, such as Lambda functions, API Gateway APIs, and DynamoDB tables. A SAM template is very similar in format to a CloudFormation template, which you learned about in Chapter 13, Building Infrastructure Using Code with CloudFormation and Cloud Development Kit (CDK).

The Transform and Resources sections are the only required components within a SAM template. A skeleton template to describe the anatomy of a SAM template is provided as follows:

```
Transform: AWS::Serverless-2016-10-31
Globals:
  set of globals
Description:
  string
Metadata:
  template metadata
Parameters:
  set of parameters
Mappings:
  set of mappings
Conditions:
  set of conditions
Resources:
  set of resources
Outputs:
  set of outputs
```

As part of your SAM template, you must declare the Transform section as Transform: AWS::Serverless-2016-10-31, as this identifies the template as a SAM template file.

The AWS::Serverless transform is a macro hosted by CloudFormation, which transforms the SAM syntax and expands it into a compliant CloudFormation template, allowing CloudFormation to build your serverless architecture. It specifies one or more macros that AWS CloudFormation uses to process your template. You can declare one or more macros within a template. AWS CloudFormation executes macros in the order that they are specified.

Some key components of the template are as follows:

- **Globals (optional)**: The Globals section allows you to declare resources with a common configuration. For example, you may have identical Runtime, Environment, or VPCConfig configurations that must be declared in your AWS::Serverless::Function resources. Rather than duplicating these variables in your individual resources, you can declare them in a Globals section and enable your resources to inherit them.
- **Resources (required)**: Within your SAM template, you can create several resource types. These include the following:
  - `AWS::Serverless::Api`: Enables you to create a collection of API Gateway resources and methods that you can involve using HTTPS endpoints.
  - `AWS::Serverless::Application`: Allows you to embed a serverless application from the AWS Serverless Application Repository or an S3 bucket as a nested application. This is useful for multiple applications that have common application components. By nesting those components, you can focus on the business logic unique to your application.
  - `AWS::Serverless::HttpApi`: Enables you to create an HTTP API rather than a REST API, which is cheaper and offers low latency. Both the REST API and HTTP API are RESTful API products supported by API Gateway. However, a REST API offers more features, such as API keys, per-client throttling, request validation, integration with AWS WAF (Web Application Firewall), or private API endpoints.
  - `AWS::Serverless::Function`: Enables you to create a Lambda function with a Lambda execution role and any event source mappings to trigger the function. An example of an event source mapping could be an SQS queue or an SNS topic.
  - `AWS::Serverless::LayerVersion`: Enables you to create a Lambda LayerVersion resource that contains any required runtime code or libraries required by your Lambda function.
  - `AWS::Serverless::SimpleTable`: Creates a DynamoDB table.
- **Parameters (optional)**: You can declare Parameters, which will allow sam deploy --guided to prompt the user for additional values. The sam deploy command is explained shortly.

A sample snippet of a SAM template.yaml file is as per the following code snippet. The application has a Lambda function invoked by an API call from API Gateway:

```
AWS::TemplateFormatVersion: '2010-09-09'
Transform: AWS::Serverless-2016-10-31

Description: Todo List Application

Resources:
  TodoFunction:
    Type: AWS::Serverless::Function
    Properties:
      CodeUri: src/
      Handler: app.handler
      Runtime: python3.9
      Events:
        Type: Api
        Properties:
          Path: /todos
          Method: get
```

You will note the Transform section within the template, which indicates that this is a SAM template. You will also note the resource type as being a Lambda function.

### Local Testing and Debugging

You can use the SAM CLI to test your application locally. You can invoke functions directly or start a local API gateway to test HTTP endpoints. This is particularly useful for debugging. sam local invoke can be used with an event file or even using a standard input with the stdin command as an event. The commands are illustrated in the following code snippet:

```
sam local invoke TodoFunction --event events/event.json
sam local start-api
```

In the next section, you will learn more about using SAM CLI commands to deploy your application.

### Deploying Your Application

To deploy your serverless application, SAM uses CloudFormation under the hood to create and manage resources. You can use SAM CLI commands to package and deploy your application, as per the commands mentioned in the previous section. The sam deploy command creates a .zip file of your code and dependencies and uploads the file to Amazon S3.
