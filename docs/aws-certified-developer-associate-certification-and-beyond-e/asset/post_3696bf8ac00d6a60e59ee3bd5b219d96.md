## Project Task 9.1 – Updating the Application Backend Code

You will need to update the application to ensure that it can be interfaced with connectivity from the authenticated users in Cognito. Recall that the EC2 instance hosting the application APIs currently runs in an Auto Scaling group, and you want to ensure that any updates are automatically copied to the EC2 instances. Since the application code resides in an Amazon S3 repository (Amazon S3 Todo List Code Repository bucket, as per the preceding diagram), you must update the bucket with the new application code. You can then terminate the existing EC2 instances, forcing the Auto Scaling service to deploy new instances and copying the application to the newly created instances. In the upcoming chapter, you will explore DevOps strategies designed to automate the deployment of new version updates:

1. Log back into your AWS account as the IAM user “Alice” and ensure you work in the N. Virginia region.
2. Navigate to the Amazon S3 console.
3. Select the `todoapprepo` bucket, as per Figure 9.12:

![](img/34ff9b5b5a734dae3450ab701e223c73_372_0.png)

Figure 9.12: Todo app repository bucket

> **Note:** You will note the existing backend application in the .zip format. This file is downloaded to EC2 instances, which use a script (recall the user data script, which is part of the EC2 instance Auto Scaling launch configuration) to configure the instances with the application code files.

4. Click the Upload button and upload the `todo-plus-nodejs.zip` file you downloaded from the GitHub repository, as discussed in the Technical Requirements section earlier. Replace the existing file in the bucket with this new version, as per Figure 9.13:

![](img/34ff9b5b5a734dae3450ab701e223c73_373_0.png)

Figure 9.13 – Copy the updated Node.js application code to the S3 bucket

5. Next, navigate to the EC2 management console by searching for it in the top search bar of your screen.
6. Select Instances from the left-hand menu.
7. In the right-hand pane, you should find that you have two instances running that host the backend application. Recall that you configured an Auto Scaling group to deploy these backend instances in Chapter 7, Building Application Solutions with High Availability, Elasticity, and Data Security.

You must terminate these instances by selecting them and then from the Instance state drop-down list, click Terminate instance as per the following screenshot:

![](img/34ff9b5b5a734dae3450ab701e223c73_374_0.png)

Figure 9.14: Terminate existing instances to force Auto Scaling services to deploy new ones

8. You will be prompted to confirm the termination of these instances. Go ahead and click Terminate in the dialog box that appears.

9. Once these instances have been terminated, the Auto Scaling service will launch new instances using the updated application code from your Amazon S3 bucket acting as the repository. This will usually take a few minutes. Click on Auto Scaling Groups from the left-hand menu in the Auto Scaling section. From the right-hand pane, select `todo-list-auto-scaling-group`, which you created in Chapter 7, Building Application Solutions with High Availability, Elasticity, and Data Security. In the right-hand pane, click Activity. You will find that the two previous instances were deleted and replaced with two new instances, as per the following screenshot:

![](img/34ff9b5b5a734dae3450ab701e223c73_374_1.png)

Figure 9.15: Auto Scaling group launches two new instances in response to the previous step’s termination action of existing instances

## Project Task 9.2 – Updating Frontend Code

In this project task, you will update the frontend application code configured as a static website hosted on an Amazon S3 bucket. In Chapter 3, Understanding Object Storage with Amazon S3, Hybrid Storage, and Static Website Hosting, you configured an Amazon S3 bucket with static website hosting. Then, you deployed the frontend code to the bucket. The original version had a non-functional form to sign up and sign in because, at the time, there was no integration with Amazon Cognito.

This updated code version includes a call to Amazon Cognito to use its hosted UI for the sign-up and sign-in form, which is connected to the Cognito user pool you created in Chapter 2, Securing Access with AWS Identity and Access Management:

1. Ensure you are logged into your AWS Development account.
2. Navigate to the Cognito console by searching for the service in the search bar at the top of the web page. Ensure that you are in the N. Virginia region.
3. From the left-hand menu, select User pools.
4. In the right-hand pane, click the user pool you created in Chapter 2, Securing Access with AWS Identity and Access Management, which should be called `todolist-userpool`.
5. Select the App integration tab, as per the following screenshot:

![](img/34ff9b5b5a734dae3450ab701e223c73_375_0.png)

Figure 9.16: The Amazon Cognito App Integration tab to identify your Cognito Client ID

6. Scroll to the bottom of the page until you reach the App client list section.
7. Make a note of the Client ID.

8. Next, you will need to amend the `index.html` file of the newly updated frontend website:

   I. Extract the contents of the `frontend.zip` file you downloaded from our GitHub repository.

   II. Open the `index.html` file in your favorite editor, such as Visual Studio Code. Next, scroll to the end of the file until you reach the `window.cognitoClientId` in the `<!-- Template Main JS File -->` section of the code, as per Figure 9.17.

   III. Update the Client ID with your Cognito Client ID, replacing the placeholder provided in the quotation marks. Figure 9.17 illustrates a placeholder for making the change. Note that if you created a different stage name than “development” for your API Gateway, as per Project Task 8.5 – Integrating with API Gateway in Chapter 8, Event-Driven Computing with AWS Lambda and Securing Access to Backend APIs with Amazon API Gateway, you must ensure that you updated it here, as per the second placeholder in the following screenshot:

```
<!-- Vendor JS Files -->

<!-- Template Main JS File -->
<script src="main.js"></script>

<script>
  window.cognitoClientId = "Enter Your Cognito Client ID Here" // Put your client id here
  window.BASE_URL = "/development"; // Put your base path here (if different)
</script>

</body>
</html>
```

Figure 9.17: Amend the new version of the index.html page with your Cognito Client ID

   IV. Save the `index.html` file.

9. Next, navigate to the Amazon S3 console.
10. Click on the bucket you configured to host your frontend website.
11. Next, upload the extracted `frontend.zip` files to the bucket’s root in the same folder hierarchy structure. Remember you just updated the `index.html` file earlier. You will also note that an additional file, `main.js`, should be uploaded. Upload all files, as per Figure 9.18:

![](img/34ff9b5b5a734dae3450ab701e223c73_377_0.png)

Figure 9.18: Update the frontend static website bucket with the updated HTML files and folders

12. You should get a confirmation that your files were successfully uploaded.
