Before any updates are performed, CloudFormation will notify you of the changes proposed in your updated template. Some changes will terminate and replace existing resources, for example, if you change the Availability Zone of an EC2 instance. Other changes might only require modifying an existing resource. Some modifications can be carried out without interrupting the resource, whereas others may result in an interruption. Using change sets, you can see how the changes will affect your resources and confirm whether you still want to proceed with the changes or make further modifications to the template before rolling out the updates.

The CloudFormation template in the following code block enables you to deploy a single EC2 instance. Since we are not specifying any other parameter values, the EC2 instance will be deployed in the default VPC, in the default subnet, in the us-east-1a Availability Zone:

```
Resources:
  MyInstances:
    Type: AWS::EC2::Instance
    Properties:
      AvailabilityZone: us-east-1a
      ImageId: ami-07caf09b362be10b8
      InstanceType: t2.micro
```

Note that the resource being created is an EC2 instance. The Properties section details the Availability Zone in which the instance will be deployed, the AMI ID that will be used, and the instance type.
