# Figure 13.1: CloudFormation stack

The example template in Figure 13.1 defines the configuration items associated with a typical VPC. Within the template, you would define the subnets, route tables, security groups, and components such as NAT gateways. The CloudFormation service will then use the information in the template to build a stack, a collection of resources managed as a single unit. Stacks defined by CloudFormation templates can be created, updated, and deleted using the AWS Management Console, the AWS CLI, or the CloudFormation API.

When you upload your template to CloudFormation, the service creates and stores the template in an AWS-managed S3 bucket. You can use your own S3 buckets if you wish. This AWS CloudFormation template can range from simple configuration definitions deploying a few resources to more complex architectures. In the next section, you will learn more about the anatomy of a CloudFormation template.

# Anatomy of a CloudFormation Template

The AWS CloudFormation template is made of several components. An example snippet is shown as follows:

```
Resources:
  VPC:
    Type: AWS::EC2::VPC
    Properties:
      CidrBlock: !Ref VpcCIDR
      EnableDnsSupport: true
```
