# Amazon SQS Queue Types

Amazon SQS provides two types of queues to facilitate different use cases: standard queues and First-in-First-out (FIFO) queues.

# Standard Queues

Standard queues are the default queue type. They provide nearly unlimited transactions per second (TPS) per API action. These API actions are SendMessage, ReceiveMessage, and DeleteMessage.

SQS queues are also regional-specific and redundantly store your messages for processing across multiple Availability Zones. This ensures that there is no single point of failure. Key features and limitations of standard queues are as follows.

# Message Ordering

Standard queues offer only best-effort ordering. This means that, sometimes, your messages might arrive in a different order from the order in which they were sent.

# At Least Once Delivery

Messages are stored on servers that form part of the SQS service. Occasionally, a server hosting a copy of the message might be unavailable when your consumer receives and deletes the messages from the queue. When this server returns online, the message might get delivered again when you perform a receive message action. This can result in duplicate messages getting delivered to your consumers. Because of the nature of standard queues, it is recommended that you design your applications to be idempotent, which means they do not get affected adversely when processing duplicate messages.
