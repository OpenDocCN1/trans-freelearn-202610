
The application architecture, as shown in Figure 2.9, comprises several AWS components. Some of these are as follows:

- **Virtual private clouds (VPCs)**: These enable you to create isolated networks to separate workloads and applications. Certain services, such as EC2 instances, that offer virtual machine compute services, need to be hosted in a VPC. You will use VPCs to separate public-facing workloads from private ones for your Todo List application.
- **Amazon Cognito**: This offers authentication and authorization services for your web and mobile applications. As described in the preceding section, Amazon Cognito will allow end users to sign into the Todo List application.
- **Amazon S3**: This is a highly scalable and durable object storage platform that can also be used to host the static website for our Todo List application.
- **CloudFront**: This offers the ability to distribute and cache content at edge locations to ensure low-latency connectivity. CloudFront can also integrate with **Lambda@Edge** to offer added functionality in response to the requests coming into CloudFront.
- **API Gateway**: This enables developers to create, publish, and manage their APIs. It is also used in accepting and processing up to hundreds of thousands of concurrent API calls, managing API traffic, offering **cross-origin resource sharing (CORS)** support, authorization, and access control, throttling, monitoring, and API version management.
- **Elastic Load Balancers**: These automatically distribute incoming application traffic across multiple targets and virtual appliances in one or more **Availability Zones (AZs)**. There are different types of load balancers, and which ones apply to our application solution are discussed later in this study guide.
- **Auto Scaling groups**: These offer the ability to add automatic scalability features to your fleet of compute resources, such as EC2 instances.
- **Amazon RDS**: This is a fully managed relational database service that will host all the Todo List data for end users.
- **AWS Secrets Manager**: This helps you manage, retrieve, and rotate database credentials and application credentials. You will be using AWS Secrets Manager to store the RDS database credentials for secure access.

In addition to IAM and Amazon Cognito, AWS has also released the new IAM Identity Center. This was previously known as AWS Single-Sign-On and was designed to help speed up building federated access from other AWS accounts and external IdPs to integrations with third-party SaaS-based applications. The IAM Identity Center is ideal for managing your workforce identities across multiple AWS accounts. Let us discuss an overview of the service next.

## Overview of the AWS IAM Identity Center

IAM Identity Center is designed to help centrally create and manage your workforce identities. This service is really an overlay of IAM and AWS Single Sign-On services. With the IAM Identity Center, you can use the default internal AWS IdP or connect and synchronize to an external IdP such as Microsoft AD Domain Services. This makes granting SSO capabilities much more straightforward than standard IAM.

You can use multi-account permissions to assign users access to all AWS accounts within AWS Organizations. This is a much easier approach than trying to configure cross-account access and multiple IAM roles to allow users from one AWS account access to other AWS accounts within your organization.

With the IAM Identity Center, you can also assign access to applications that integrate with the Identity Center or third-party applications that offer SAML 2.0 integration. Several use cases exist for using the IAM Identity Center instead of AWS IAM, particularly with workforce user management.

In the case of our client, TodoPlus Limited, you should consider using the AWS IAM Identity Center to grant access to your existing workforce. Assuming TodoPlus has an existing on-premises workforce, some of whom may need access to the AWS platform to design, build, and deploy the new TodoPlus application, integrating their on-premises IdP, such as AD, would help fast-track their access capability onto the AWS platform. In addition, with IAM Identity Center, granting access to multiple AWS accounts, such as Development, Testing, and Production, to your workforce users via a central web portal is much easier.
