Using the previous example of a music database, you could use the partition and sort keys, which would consist of the artist and song title respectively. However, you may also wish to query your collection based on genre or album title. Here, a GSI would come in handy.

For the index, you could classify the genre as the alternative partition key and the album title would be the sort key.

Note that when you confirm the secondary index, DynamoDB will maintain the index automatically. As you add and delete items from the table, DynamoDB will add and delete any relevant key attributes in the index.

Now that you have understood the fundamentals of the primary (partition) keys, sort keys, and secondary indexes, you can next explore how DynamoDB provisions capacity for your application.

# DynamoDB Capacity Provisioning

When provisioning capacity for DynamoDB, you do not need to specify the instance type or size to define the amount of storage required, as you normally do with Amazon RDS. Instead, AWS fully manages and provisions the required capacity based on your application read and write throughput requirements. To that effect, you only need to define read and write capacity units, which will be discussed next.

Amazon DynamoDB offers two capacity modes that allow you to determine your capacity requirements:

+   - **On-demand** is a flexible billing approach that enables you to provide the required capacity as your application demands change. Amazon DynamoDB will provide the necessary capacity and no capacity planning is required. This mode is ideal when:
+     - You are unsure of the workload types you plan to run
+     - Traffic to your database is unpredictable
+     - You want to be billed on a **pay-as-you go model**

+   - **Provisioned** – in this mode, you define the number of reads and writes per second required by your application. This mode is the default mode when you create a new table. You can also configure the table with auto-scaling to adjust the provisioned capacity as traffic demand changes. This mode is ideal when:
+     - You know your application traffic usage patterns
+     - You have consistent traffic that gradually increases
+     - Capacity forecasting is possible
