So, for example, if you have an input of `{ "lorem": "ipsum" }`, you will get a state output when catching the error, as follows:

```
```json
{
    "lorem": "ipsum",
    "error": {
        "Error": "Error here"
    }
}
```
```

ResultsPath helps you to pass errors into the next state. This means you have access to the error in the next state and you can analyze it and perform any debugging as necessary.

Using Step Functions for error handling ensures that you do not need to overload your Lambda functions, which could result in performance and timeout issues. By subscribing to the features of Step Functions, you can apply complex error-handling logic seamlessly with your application architecture.

In the next section, we provide a brief overview of another feature that will allow you to handle responses from external APIs that are part of your workflow.

# Waiting for a Task Token

Sometimes, your application workflow might be dependent on interactions with and responses from other AWS services, external APIs, or even human approval processes.

For example, during the checkout process of an e-commerce application, you might have to wait for a payment gateway to get a confirmation that a credit card payment was accepted or declined before proceeding to the next step. To facilitate this requirement, you can append `.waitForTaskToken` to the Resource field, which tells Step Functions to wait for the task token to be returned.

An example snippet of the JSON for this follows:

```
```json
"States": {
    "Payment Gateway Process": {
        "Type": "Task",
        "Resource": "arn:aws:states:::lambda:invoke.waitForTaskToken",
        // more fields below
    }
}
```
```

`.waitForTaskToken` will pause the task and wait for a response that contains a task token and either a SendTaskSuccess or SendTaskFailure API call. This enables you to rely on external systems to perform any necessary processing before progressing with the workflow.
