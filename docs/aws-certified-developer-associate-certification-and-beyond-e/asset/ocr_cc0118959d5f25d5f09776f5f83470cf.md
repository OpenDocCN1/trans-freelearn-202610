You can have several mappings, where each map will need its own logical name as in this example, where the mapping name is **RegionMap**.

You can have name-value pairs containing multiple string values within your mapping keys (us-east-1, us-west-1 . . . , etc). For example, in the preceding code snippet, you have keys mapped to two sets of name-value pairs: one named HVMG4 and the other named HVMG2.

Once you have defined your mappings, you can call a value based on a specific key using the `Fn::FindInMap` intrinsinc function. You can also reference **pseudo parameters** to identify details such as which Region you are in or the ID of the AWS account within which you are deploying a CloudFormation stack. This can dynamically identify information and customize your deployment based on the name-value pairs defined in your **Mappings** section.

In the following code snippet, note that the selection of the AMI is based on the Region in which the CloudFormation template is used to deploy a stack:

```
AWSTemplateFormatVersion: "2010-09-09"
Mappings:
  RegionMap:
    us-east-1:
      HVMG4 : ami-0ff8a91507f77f867
      HVMG2 : ami-0a584ac55a7631c0c
    us-west-1:
      HVMG4 : ami-0bdb828fd58c52235
      HVMG2 : ami-066ee5fd4a9ef77f1
    eu-west-1:
      HVMG4 : ami-047bb4163c506cd98
      HVMG2 : ami-0a7c483d527806435
Resources:
myEC2Instance:
  Type: "AWS::EC2::Instance"
  Properties:
    ImageId : !FindInMap [RegionMap, !Ref "AWS::Region", HVMG4]
    InstanceType : m1.small
```

You can use the `!FindInMap` (YAML-formatted) function to identify a mapping called `RegionMap` and pull a corresponding value for an AMI ID that refers to the Region in which the stack is being deployed. This is because you are using the `!Ref AWS::Region` intrinsic function to obtain the Region information and then selecting the AMI that corresponds to the HVMG4 architecture in that Region.
