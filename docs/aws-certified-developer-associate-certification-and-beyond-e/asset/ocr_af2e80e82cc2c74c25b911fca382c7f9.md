# Project Task – Design a CI/CD Pipeline for the Todo List Application

In the following project exercises, you will design and implement a CI/CD pipeline for your Todo List application. This will enable you to benefit from DevOps principles and methodology when managing your application’s lifecycle. Using CI/CD, you can securely store and implement version control to your application’s source code. You can ensure automated builds and tests of changes and enhancements you make to your application, quickly deploy bug fixes, and resolve application issues, whether these are related to user experience or performance. With CI/CD as an integral part of your application design, you can ensure that you respond to market changes, security issues, customer satisfaction, and cost reduction.

The Todo List application comprises two key components: a frontend user interface and a backend component that delivers on user experience. The application aims to be intuitive and engaging for the end user. In the upcoming project task, you will build not one but two CI/CD pipelines, enabling you to release updated code for both the frontend and backend layers independently.

The following summarizes the updated application functionality, which should be implemented using a CI/CD pipeline:

+   - Frontend website – changes proposed for the end user experience:
+     - The ability to filter the data based on category (task type) and status
+     - An **Edit** and **Delete** button against each entry. End users are likely to make simple typo errors in the task description. An **Edit** button will enable the user to resolve any such issues. Similarly, the end user should be able to delete an entry if it was created by mistake.
+   - Backend application – changes proposed for the application:
+     - APIs to facilitate the editing and deletion of todo items.
