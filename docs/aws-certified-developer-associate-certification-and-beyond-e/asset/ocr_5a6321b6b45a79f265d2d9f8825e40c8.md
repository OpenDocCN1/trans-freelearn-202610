+   - **Mock:** This integration type is designed for testing purposes. API Gateway sends a response without sending the request to the backend service, enabling you to test the integration setup without incurring charges. Furthermore, you do not need to create a real backend to complete testing. When configuring mock integrations, you decide how API Gateway responds to the request, specify the response status code, and configure the integration request body mapping template to return the code, for example, a 200 response code.

Ultimately, your choice of integration type will depend on the backend service type and your application's use case.

# Throttling and Traffic Management

Traffic management is essential for maintaining the performance and availability of your backend services. API Gateway offers throttling features that limit the number of requests per second, safeguarding your backend services from being overwhelmed by too many requests at once. API Gateway limits the steady-state **requests per second (RPS)** for all APIs within your AWS account on a regional basis. It also limits bursts, representing the maximum number of concurrent request submissions. If requests increase beyond this maximum, API Gateway returns a 429 Too Many Requests error. These throttling settings can be customized to suit the needs of different stages of your API, such as development, testing, and production.
