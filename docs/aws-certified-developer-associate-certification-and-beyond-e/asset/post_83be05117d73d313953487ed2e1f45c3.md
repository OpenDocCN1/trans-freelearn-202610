Now that you have created the auto-scaling group, you must create an application load balancer responsible for distributing end user traffic to the instances managed by the Auto Scaling group.

> **Important Note**
> 
> As shown in *Figure 7.28*, it is advisable to host the application load balancer internally and serve end user traffic via AWS API Gateway. This is because API Gateway offers secure authorization features.

Since you will be using Amazon Cognito to authenticate users, using a Cognito user pool as an authorizer is also very easy. With this approach, only when users sign into the user pool and obtain valid access tokens can they call an API method to access the backend service for the Todo List application.

With this configuration in place, you avoid situations where someone obtains the DNS name of the load balancer and invokes it. This can also increase the chances of **Denial of Service (DoS)** attacks on your APIs. Hence, it is advisable to use the API Gateway for authorization.

However, it is also important to ensure that the load balancer is then configured as an internal ALB. This requires registering the private subnets to the load balancer instead of the public subnets, enabling it to deploy load balancer nodes only in the private subnet. If anyone obtains the load balancer DNS, it will time out because the DNS names only point to private IP addresses.

The scenario complicates the architecture. This is because there is currently no direct API Gateway integration for private ALBs. The architecture would, therefore, require you to use an NLB and forward API Gateway requests to the private ALB. The API Gateway would also require the use of an API Gateway VPC link, which acts as a secure tunnel to allow traffic between the gateway and the load balancer.

## Project Task 7.7 – Application Load Balancer

In this project task, you will deploy an ALB, which is used to distribute inbound traffic to the EC2 instances deployed by the Auto Scaling group. Load balancers enable you to distribute traffic across multiple instances that all provide access to the same application and thus facilitate high availability for your application. If one of the EC2 instances fails, the load balancers redirect any traffic to other healthy instances.

Although, in this chapter, you have been provided with instructions to build an internal ALB, feel free to experiment by deploying an Internet-facing load balancer.
