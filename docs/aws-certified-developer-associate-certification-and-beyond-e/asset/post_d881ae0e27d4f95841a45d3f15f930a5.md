## An Introduction to Storage Options

With the increasing variety of storage options such as physically attached block storage, network attached block and file storage, and the more contemporary object-based storage, it's important for cloud engineers to be able to choose the right option for their given use case. In the following section, you will look at the three primary categories of storage services offered by AWS – block storage, file storage, and object storage – and the differences between them will be discussed.

### Block Storage

Block storage stores data in fixed-sized chunks on a physical hard drive. The disk is divided into volumes accessible to your EC2 instances (servers) over network interfaces. This allows your servers’ operating system (OS) to access the volume directly, format it, and write and read data to and from it. The server OS oversees the storage partition to which it has been given access and manages how data is written to the volume. For example, with Amazon Elastic Block Storage (EBS), you can provision a 100 GB volume, and the disk cluster allocates 100 GB of available storage.

### File Storage

This is a method of storing data as individual files on a centralized file server, which other devices can share. An example of this is where you have multiple nodes that need access to commonly shared data, or if your workforce needs a central location to share documents and collaborate. The hierarchical nature of file storage is like its real-life counterpart, the filing cabinet. Data is stored in folders and sub-folders, and access to that data requires knowing the location and structure of that hierarchy. This type of storage uses Network File System (NFS), Server Message Block (SMB), and Common Internet File System (CIFS) protocols.

### Object Storage

Object storage is a technology to store data as objects (flat files). These objects are stored as unstructured flat files, without using any of the previously discussed file storage hierarchy architectures. Objects are instead stored with pieces of data that make up the file, with relevant metadata and unique identifiers. One of the real benefits of object storage is the ability to offer infinite scalability and higher durability levels. Because of this, object storage is often used for use cases such as cloud storage, content delivery networks (CDNs), data lakes, archiving and backup, and media streaming.

In this chapter, you’ll explore object storage, specifically focusing on Amazon S3 and its core components and features. In addition to standard storage capabilities, you’ll discover how Amazon S3 can also be used to host static websites, a feature that supports the design of modern web and mobile application solutions.

## An Introduction to Object Storage with Amazon S3

Object storage is an approach that utilizes objects containing data, metadata for contextualization, and an identifier.

Amazon S3 is a widely used object storage solution with high levels of security, scalability, and durability, making it a preferred choice for businesses of all sizes and industries. With Amazon S3, you can secure your data both in transit and at rest, thanks to its tight integration with AWS Key Management Service (KMS), which offers encryption services. In addition, your objects are replicated and stored across multiple devices, across multiple Availability Zones within a given Region, offering higher levels of durability.

Organizations use it for various purposes, such as data lakes, disaster recovery, log archiving, mobile applications, and big data analytics. Amazon S3 also offers tools to optimize, organize, and customize data access based on commercial, organizational, and regulatory requirements. Amazon will never replicate your data across regions, enabling you to ensure that you meet data residency laws. However, should this not be a restriction, you are free to configure replication of your data across regions to fulfill any other requirements, such as ensuring lower latency by making data accessible to local users or for archiving and disaster recovery requirements.

Amazon S3 comprises four primary concepts:

- **Buckets:** These act as the primary container for objects
- **Objects:** These contain the actual data and metadata
- **Keys:** Unique identifiers for each object within a bucket
- **Region:** Denotes the geographic location where the bucket is stored

You will explore each of these concepts in the following sections for a comprehensive understanding.

### Amazon S3 Buckets

Amazon S3 offers two types of buckets that act as containers for your data:

- **General purpose buckets**, the original S3 bucket type, are designed for a wide range of use cases and access patterns. Data is stored as flat files at the root level and given unique global names. Using prefixes and delimiters, data can be categorized for ease of management and better performance.
- **Directory buckets** utilize the S3 Express One Zone storage class (discussed later in this chapter), which is particularly ideal for applications that require very high performance and benefit from single-digit millisecond PUT and GET latencies.

Amazon S3 buckets can host as many objects as you want. They offer 11 “nines” (99.999999999) of durability and 4 nines (99.99) of availability. This is achieved because Amazon S3 replicates your objects across multiple devices and all Availability Zones within a Region for most storage classes. Access to buckets is managed via bucket policies and access control lists (discussed later in this section).

### Amazon S3 Objects

Rather than breaking down data into smaller segments and storing it on block storage, Amazon S3 retains data as complete objects. An object is comprised of three elements – data, metadata, and a unique identifier. Metadata contains context-specific information about the object and is stored as a collection of key-value pairs. It includes essential details such as the content type, length, and last modified date. Two types of metadata can be linked to an object in Amazon S3 – user-defined and system-defined.

Object storage is ideal for data that needs to be highly durable and where the storage platform is scalable. Unlike file and block storage, which have additional technical limitations and higher costs, object storage services such as Amazon S3 are ideal for hosting digital assets such as videos, images, and documents.

For our client, **TodoPlus Limited**, object storage could be used to host archival data on Amazon S3, which generally works out much cheaper. It also hosts assets that could be used for their website and web applications. For example, **TodoPlus Limited** could host training videos on how to use its upcoming Todo List application, which could be made accessible on the internet.

### An Amazon S3 Object’s Key

Objects in Amazon S3 are stored as key-value pairs, where the key is the object’s name and the value is the actual data held as binary. Every item in a bucket possesses a unique key. Moreover, each object has a unique URL, enabling it to be accessed from any location on the internet. The object’s URL comprises the bucket’s name, a key, a URL, and a version number if versioning is enabled on the bucket. This will be discussed later in this chapter.

For example, the `https://packtpub.s3.amazonaws.com/books/chapter_03.pdf` link denotes the object name as books/chapter_03.pdf and the bucket name as packtpub.

Furthermore, `book/` in the preceding URL represents a prefix followed by a delimiter. Multiple objects can be associated with the same prefix, which can help you categorize your data. More importantly, it also facilitates filtering your list requests and allows you to apply access permissions based on those prefixes. In addition, as mentioned previously, using prefixes and delimiters can help improve your read and write throughput.

### Amazon S3 Region Choice

Amazon S3 allows you to specify the Region where you want your buckets to be hosted, considering factors such as compliance and latency. Objects remain in the Region where they were created unless the user decides to move them elsewhere. This enables AWS to ensure any data residency laws are followed. If this regulation doesn’t apply to your use case, then you can replicate data between Regions.

> **Note**
> 
> In the case of our client, **TodoPlus Limited**, data for all US-based customers will reside in the United States. Even though the business will expand its operations across continents, it will need to ensure it follows strict data residency laws. Within the US, there are multiple Regions available, which means **TodoPlus** could host replica copies of the data in a different US Region to create a disaster recovery solution and reduce the risk of single-Region hosting.
