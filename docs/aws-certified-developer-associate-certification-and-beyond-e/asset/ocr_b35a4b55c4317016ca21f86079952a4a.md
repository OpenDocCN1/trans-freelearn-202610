Every API call you make to your AWS account, whether via the Management Console, CLI, or using the SDKs, is recorded in AWS CloudTrail. This enables you to identify what action has taken place in your account, by whom, and when, facilitating an extensive audit trail. By default, management events are logged and retrained for 90 days. However, you can create a CloudTrail trail to log events to an Amazon S3 bucket for an indefinite retention period. You can also send the event captured to CloudWatch Logs and Amazon EventBridge.

A CloudTrail trail can be created for a single region or a multi-region. Multi-region trails capture events across all regions and are a recommended best practice. If AWS builds a new region, it is added to your multi-region trail, enabling you to capture all activities related to your resources across the global infrastructure. When creating a trail using the AWS Management Console, it creates a multi-region trail. If you need to create a single-region trail, you must use the AWS CLI.

Three events can be created with CloudTrail, as follows:

+   - **Management events** provide information about operations performed against resources in your AWS account, such as launching a new EC2 instance, creating a new IAM role, attaching an IAM policy, or terminating an RDS database instance. By default, trails are configured to log all management events.
+   - **Data events** provide detailed information about resource operations performed on or in a resource. For example, when users try downloading an object, a GetObject action is performed on objects in an S3 bucket. You can also capture Lambda function execution activities, such as the Invoke API, whenever a Lambda function is executed.
+   - **Insights events** enable you to identify and respond to unusual activity caused by write API calls or API error rates for both read and write APIs. CloudTrail Insights establishes a baseline by analyzing normal API calls and API error rates and generates events when these call volumes or error rates go beyond normal patterns.

Managing the security of your CloudTrail events is critical, and using encryption and IAM permissions can ensure that only authorized users can encrypt and decrypt the CloudTrail log files. CloudTrail delivers log files to your bucket using server-side encryption with a KMS key (SSE-KMS) by default unless you do not enable KMS encryption. In this case, CloudTrail will encrypt the log files using SSE-S3.

Note that to use an existing S3 bucket with an S3 bucket key, you need to grant CloudTrail permission in the key policy to perform the GenerateDataKey and DescribeKey AWS KMS actions. Without these permissions, you will be unable to create or update a trail.

The benefits of using KMS for encryption are that you manage the keys yourself and can use the same key to encrypt and decrypt log files across all accounts in all regions. To access the log files from an S3 bucket, the user must have read permissions on the bucket as well as have a policy or role applied that allows the decrypt permissions by the KMS key policy. This further enhances your security.
