Options to connect your private on-premises network to the AWS cloud include the following:

+   - **Site-to=Site Virtual Private Network (VPN)**: This allows you to create a relatively inexpensive IPsec VPN connection between your VPC and your remote network. With this, traffic is encrypted while it traverses the public internet.
+   - **Direct Connect**: This is a dedicated fiber optic cabling network between your on-premises office and your local Direct Connect Partner. Traffic is then routed over private networks into the AWS platform, and it never traverses the public internet. AWS Direct Connect offers dedicated and higher bandwidths than traditional VPN connections.

AWS Direct Connect will sometimes require a lead time to be set up as the underlying cable infrastructure may first need to be provisioned between your location and the Direct Connect Partner.

Now that you have understood the key components of VPCs and examined their various security and networking components, it is also imperative that you are able to monitor the types of traffic that flow into and out of your network. AWS provides several monitoring tools to help you. One such tool you might find yourself utilizing is VPC Flow Logs, which you will explore next.

# Monitoring Traffic with VPC Flow Logs

VPC Flow Logs is a service designed to help you monitor IP traffic entering and leaving the entire VPC, a specific subnet, or a specific network interface such as the virtual network card attached to one of your EC2 instances.

This data can then be ingested into Amazon CloudWatch Logs, Amazon S3, or Amazon Kinesis Data Firehose for further analysis and storage. VPC Flow Logs can be used to do the following:

+   - Identify overly restrictive security group rules – for example, when certain types of traffic are not reaching your resources
+   - Monitor the type of traffic that reaches your instances – for example, to help you determine if that traffic is authorized or malicious
+   - Identify the direction of the traffic to and from the resources in your AWS account

Your flow log data is recorded as flow log records and can be pushed out to a CloudWatch Logs group created beforehand. You will also need to set up the necessary permissions in the form of an IAM role to enable your flow logs to be written to the CloudWatch Logs group.

When setting up VPC Flow Logs, you need to define the following:

+   - The resource you want to create the flow log for (e.g., the entire VPC, a subnet, or a network interface)
+   - The type of traffic you wish to capture (accepted traffic, rejected traffic, or all traffic)
+   - The destinations for your flow log data
