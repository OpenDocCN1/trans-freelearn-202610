# FIFO Queues

FIFO queues are designed to overcome some of the limitations of standard queues, as we explain here.

# Message Ordering

The order in which your messages are sent into the queue is the order in which it is received (i.e., first in, first out).

![](bbox=[0.13, 0.26, 0.85, 0.41])

FIFO queues are particularly useful when your application must receive the messages in the order in which they were sent. Examples use cases include the following:

+   - Ensuring students can be enrolled into a course only after registration is complete
+   - Ensuring that commands entered are executed in the right order
+   - An online ticketing system must ensure that tickets are issued in the order they were created

# Exactly Once Processing

With FIFO queues, you do not get duplicate messages. Messages remain available until a consumer processes them and delete them from the queue.

When deciding whether to use standard queues or FIFO queues, it is also important to consider how many messages per second your application will be required to handle. The next section provides an overview of SQS queue throughput considerations.

# Throughput Considerations

Understanding throughput is crucial when deciding which queue type to use for your application:

+   - Standard queues support a nearly unlimited TPS for each action, such as sending, receiving, or deleting messages.
+   - FIFO queues are more limited, supporting up to 300 messages per second with batching or 3,000 messages per second without batching. This knowledge is essential for applications requiring a strict order and uniqueness in message processing.
