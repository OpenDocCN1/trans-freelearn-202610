
Scaling can be done manually by adding or removing EC2 instances from the Auto scaling group or dynamically by defining rules for increasing or decreasing the capacity of the group based on resource use or demand. This allows for creating rules that respond to changes in load, such as number of requests, CPU, and memory usage.

The following discusses the three types of **dynamic scaling policies** available:

- **Target tracking**: This policy adjusts the current intended capacity of the Auto Scaling group based on a target value for a given metric, such as CPU or memory utilization. This policy ensures consistent capacity and will add or remove EC2 instances as needed to maintain the desired usage level, for example, 60%.
- **Step scaling**: This policy adds or removes EC2 instances from the current capacity of the Auto Scaling group based on a set of predetermined scaling adjustments that increase or decrease according to the severity of the alert violation. For example, if the Auto Scaling group has three levels for monitoring CPU utilization, an alert would be triggered at 40% CPU utilization, adding one EC2 instance; at 60% CPU utilization, adding two EC2 instances; and at 80% CPU utilization, adding three EC2 instances.
- **Simple scaling**: This policy allows the capacity of the Auto Scaling group to be increased or decreased with a single scaling adjustment. When a predetermined alert is triggered, a new EC2 instance can be launched.

On-demand instance scaling and spot fleet instance auto-scaling features make it possible to dynamically increase or decrease the capacity of the spot fleet in response to demand. The AWS Auto Scaling mechanism relies on several components that must be created before utilization, which we will discuss in the next section.

## Automatically Adjusting Capacity Using AWS Components

Amazon **Elastic Compute Cloud (EC2)** Auto Scaling relies on several components to manage the workload, including the following:

- **Auto-scaling groups** group instances together for easier scaling and management. Minimum, maximum, and preferred instance counts can be set when creating a group.
- **Configuration templates**, such as launch configurations or launch templates, allow the customization of instance details such as AMI IDs, instance type, key pair, security groups, and block device mapping.
- **Scaling options** allow Auto Scaling groups to be scaled in various ways using Amazon EC2 Auto Scaling. Groups can scale dynamically based on specific triggers or a predetermined schedule.

## Introduction to Encryption on AWS and KMS

Security is paramount when you plan to host and access your application in the cloud. In Chapter 2, Securing Access with AWS Identity and Access Management, you discovered the importance of authentication and authorization. Later, in Chapter 4, Building Private Networks in the Cloud with Amazon VPC, you learned about network security and measures to ensure that only specific traffic related to our application was permitted. In this section, you will learn about data encryption and services on AWS that can help ensure your data isn’t readable to anyone who does not have authorization to view the data. This is a critical component of your overall security design.

The following are two types of encryption methodologies that you need to be aware of when working with data:

- **Encryption in transit** – This refers to encrypted data en route between network endpoints. It may be stored unencrypted on a disk.
- **Encryption at rest** – This refers to data that is encrypted when stored on a disk. As the data is created/stored on a storage system, it is encrypted. Accessing the data from a disk would require decrypting it first to make it readable.

Depending on the services you use on AWS, you can choose to encrypt your data. For end-to-end encryption requirements, you often implement both options.

AWS KMS is an essential service used by Amazon S3 and other services on AWS for encryption. Let's dive deeper by discussing the key features of KMS next and how you can use this service to manage your encryption needs effectively.

### Overview of AWS KMS

**AWS KMS** is the primary service you can use to build and integrate data encryption features for your applications and data hosted on AWS. **AWS KMS is FIPS 140-2-compliant and uses shared security hardware modules** to generate encryption keys, which are used to perform cryptographic operations.

**AWS KMS keys** (previously known as Customer Master Keys or CMKs) perform all the data encryption, decryption, and re-encryption. CMKs are designed to only encrypt data up to a maximum size of 4KB. To encrypt larger datasets, you must create data keys, as discussed later.

**AWS KMS keys** can either be customer-managed or AWS-managed. The following are the differences:

**Customer-managed CMKs** are keys that you create, own, and manage. You have complete control over key policies and the ability to enable and disable them. You can optionally define key rotation policies, which can later be disabled, unlike AWS-managed keys.

**AWS-managed CMKs** are created, managed, and used on your behalf by any service that uses AWS KMS natively. While some services will let you choose either an AWS-managed key or a customer-managed one, often, you can opt for the AWS-managed keys unless you are required to have greater control over the keys. With AWS-managed keys, key rotation is performed automatically yearly and cannot be disabled, and the keys cannot be deleted. AWS-managed keys are also not chargeable.

An important concept to understand is that there are two types of encryption you can work with – *symmetric* and *asymmetric encryption* – and accordingly, you would use symmetric keys or asymmetric keys. Let us look at these next.

### Symmetric KMS Keys

Symmetric KMS encryption keys are used when you want to use the same keys to perform both the encryption and decryption operations. The keys are securely stored in KMS; you must call KMS to perform the required encryption and decryption tasks. Note that AWS services, which are integrated with KMS, only use symmetric encryption.

Symmetric keys can be used to encrypt, decrypt, and re-encrypt data. They can also be used to generate data key and data key *pairs*, which we will discuss later in this section. There is support for multi-regional symmetric encryption and the ability to import your key material if you wish.
