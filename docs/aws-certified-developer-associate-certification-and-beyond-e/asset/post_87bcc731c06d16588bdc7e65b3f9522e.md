
# Project Task 5.1 – Prepare AWS Systems Manager Session Manager for Your EC2 Instances

In this project task, you will perform some pre-requisite tasks to ensure you can use Session Manager to connect to your EC2 instances when you deploy them:

- 1. Log in to your AWS Developer account using the credentials of the IAM user Alice.
- 2. From the top search bar menu, navigate to AWS Systems Manager.
- 3. On the main splash screen, click the Get Started with Systems Manager button as per Figure 5.8. This will take you to the AWS Quick Setup page.

![](img/34ff9b5b5a734dae3450ab701e223c73_194_0.png)

Figure 5.8 – Getting started with AWS Systems Manager

- 4. In the right-hand pane, select us-east-1 from the drop-down list and click Get started, as per the following screenshot:

![](img/34ff9b5b5a734dae3450ab701e223c73_194_1.png)

Figure 5.9 – AWS Systems Manager quick setup

- 5. Now that you have selected the home Region, feel free to review the console quickly. On the left-hand menu, you will note various tools and services offered by AWS Systems Manager. You will also note the **Session Manager** tool listed under **Node management**. Session Manager is a powerful tool, but for this project, you will focus on using it to access backend EC2 instances for remote administration.
- 6. You must create an IAM role, enabling Session Manager to manage your EC2 instances. From the top search box, search for IAM and open its console in another browser tab.
- 7. In your IAM console, from the left-hand menu, select **Roles**.
- 8. In the right-hand pane, click the **Create role** button and perform the following steps:
  - I. Under **Select trusted entity**, ensure that you select the **AWS service** option.

![](img/34ff9b5b5a734dae3450ab701e223c73_195_0.png)

Figure 5.10 – Setting up an IAM role for Session Manager

- II. Select **EC2** from the drop-down list under **Service or use case**.
- III. Under **Choose a use case for the specified service**, select **EC2 Role for AWS Systems Manager** and click **Next**.
- IV. You will note that the `AmazonSSMManagedInstanceCore` IAM policy has already been added to this role. Click **Next**.
- V. Provide a role name, such as `todo-ec2-iam-master-role`.

VI. Provide a suitable description and then click the Create role button at the bottom of the page. You should now get a confirmation that the role has been created, as per the following screenshot.

![](img/34ff9b5b5a734dae3450ab701e223c73_196_0.png)

Figure 5.11 – IAM Role for your EC2 instance to access services such as AWS Systems Manager

Next, let us launch an EC2 instance, which will be used to create your custom AMI.

## Project Task 5.2 – Launch an EC2 Instance

In this project task, you will deploy an EC2 instance in your Todo List VPC public subnet. This EC2 instance will be configured with software that your application will use. Later, you will create an AMI that TodoPlus Limited will use to deploy multiple instances hosting the application.

The purpose of configuring a custom AMI is to ensure you have a corporate image approved for use by your customer and expedite the deployment of instances needed to support your application:

- 1. From the AWS management console, search for EC2 in the top search bar and navigate to the EC2 management console.
- 2. From the left-hand menu, select Instances.
- 3. In the right-hand pane, click the Launch instances button.
- 4. In the Launch an instance console, provide a name for your instance, such as Todo AMI Image Instance.
- 5. Select Amazon Linux under Quick Start and ensure that Amazon Linux 2023 AMI is selected as the image you will work with to create your custom AMI. Also, ensure that you select the 64-bit x86 architecture, as per the following screenshot.

![](img/34ff9b5b5a734dae3450ab701e223c73_197_0.png)

Figure 5.12 – Launching an EC2 instance

- 6. For **Instance type**, ensure that **t2.micro** is selected.
- 7. For **Key pair name – required**, select **Proceed without a key pair (Not recommended)** from the drop-down menu. You are not configuring a key pair for this instance because you will use Session Manager to connect to it, and it does not require a key pair.
- 8. Under **Network settings**, click the **Edit** button.
- 9. Select **todolist-vpc** from the **VPC** drop-down list.
- 10. Under subnet, select **todolist-pub-subnet-01**.
- 11. From the **Auto-assign public IP** drop-down box, select **Enable**.
- 12. In the **Firewall (security groups)** section, click the **Select existing security group** option.

13. Select the default security group from the drop-down list of common security groups, as per the following screenshot:

- 14. Scroll further down and expand the Advance detail section.
- 15. Under the IAM instance profile drop-down list, select the IAM role you created in the previous task.
- 16. Scroll to the bottom of the page and then click Launch instance.
- 17. You should then get a success message confirming the launch of the instance.
- 18. From the left-hand menu, click Instances.
- 19. The instance will take a few minutes to launch successfully. Make sure the Status check section confirms that the two checks have passed, as per Figure 5.14:

![](img/34ff9b5b5a734dae3450ab701e223c73_199_0.png)

In the right-hand pane, select the instance by clicking the checkbox next to the Name instance and click the Connect button.

You have four methods of connecting to the instance. Select Session Manager and click the Connect button.

This will connect you to the EC2 instance shell interface, as per the following screenshot:

![](img/34ff9b5b5a734dae3450ab701e223c73_199_1.png)

When connecting with Session Manager, you will have logged in with the SSM-User account. Change your user to the root user by typing in the `sudo su` command and press **Enter**.

Perform the following steps to install the required software packages:

Update the operating system by typing in the `yum update -y` command and pressing **Enter**. If there are no updates to perform, you will be notified.

Type in `curl -fsSL https://rpm.nodesource.com/setup_20.x -o nodesource_setup.sh` and press enter.

Type in `bash nodesource_setup.sh` and press **Enter**.

Type in `yum install -y nodejs` and press **Enter**.

Type in `npm i -g pm2` and press **Enter**.

Your EC2 instance now has all the software packages you need to build out an AMI. In the next project task, you will create an AMI of this EC2 instance. This AMI can then be used to deploy your EC2 instances, which will perform all backend operations and host your APIs.

## Project Task 5.3 – Create a Custom AMI

You will now create an AMI of the current EC2 instance:

- 1. Ensure you are logged in to your development account as the IAM user Alice.
- 2. Navigate to the EC2 dashboard like before.
- 3. From the left-hand menu, select Instances.
- 4. In the right-hand pane, click the checkbox next to your Todo AMI Image Instance instance label, as depicted in Figure 5.16:

![](img/34ff9b5b5a734dae3450ab701e223c73_200_0.png)

- 5. You should ideally first shut down the instance before taking an image. From the Instance state drop-down list, select Stop instance.
- 6. You will be prompted for confirmation to stop the instance. Go ahead and click Stop.
- 7. Once the instance has shut down, from the Actions drop-down list, select Image and templates, and then select Create image, as depicted in Figure 5.17:

![](img/34ff9b5b5a734dae3450ab701e223c73_200_1.png)

- 8. You will be presented with the Create image page. Here, you will note that the EC2 instance is already listed as the one you are creating an image of.
- 9. Provide a name for your image – for example, todolist-worker-ami.
