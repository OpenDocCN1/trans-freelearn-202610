+   - In this example, the Lambda functions process business logic and perform necessary CRUD (**create, read, update, and delete**) operations on the backend DynamoDB database. The processed data can be stored, retrieved, or modified. The Lambda function might add a new item to the database, update an existing one, or query the database to retrieve information based on the request.

This serverless architecture demonstrates a common pattern for creating scalable and efficient cloud-based applications. By integrating these services, developers can build systems that automatically scale with demand, have built-in high availability, and provide a pay-as-you-go pricing model that reduces the cost of ownership.

AWS API Gateway is a flexible, robust frontend for applications that securely manage traffic, authorize users, and route requests.

The next section provides an overview of the different API types and endpoint configurations.

# ## API Types and Endpoints

At its core, API Gateway offers RESTful and WebSocket API interfaces. RESTful APIs are designed for stateless operations and follow the request/response cycle. RESTful APIs are available either as REST APIs or HTTP APIs. The following are their key attributes:

+   - **REST APIs** are a collection of resources and methods. A resource represents a logical entry point for an app via a resource path. A method refers to the REST API request that a user makes of the API and receives a response to that request, such as the GET or PUT method. REST APIs enable integration with backend services on AWS, and features such as management capabilities using API keys and per-client rate limiting are also only available with REST APIs.
+   - **HTTP APIs** offer a similar functionality as REST APIs, albeit designed with fewer features and thus offered at a lower price point. HTTP APIs only support regional endpoints, whereas REST APIs can also support edge-optimized and private endpoints.

Another type of API is the **WebSocket API**. It also integrates with backend services such as Lambda functions, HTTP endpoints, and other AWS services. WebSocket APIs offer bidirectional communication, which means that while clients can send messages to a service, those services can also independently send messages to clients. This type of API is ideal for building real-time applications such as chat, gaming, or financial trading.

In addition to API types, there are three endpoint types for your APIs. These are as follows:

+   - **Edge-optimized API Endpoints:** These route requests to the nearest CloudFront edge location, enabling you to build solutions for a geographically dispersed user base.
+   - **Regional API Endpoints:** These are intended for clients in the same region as the API. You can incorporate your own CloudFront distribution with your regional APIs, which gives you flexibility in the caching strategies for the distribution.
