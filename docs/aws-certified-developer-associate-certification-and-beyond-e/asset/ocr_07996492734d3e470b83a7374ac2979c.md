+   - **Task Definitions:** These are blueprints for your applications that define how containers should be deployed on the cluster. They include details of what Docker (container) images to use, CPU and memory allocations, networking settings, and more.
+   - **ECS Services:** ECS services allow you to run and maintain a specified number of instances of a task definition simultaneously in an ECS cluster. These are similar to auto-scaling services offered for your EC2 instances. You can define capacity, scaling policies to use, and triggers to configure. Failed tasks are automatically replaced by the ECS service, ensuring continuity and availability.
+   - **Tasks:** An instance of a task definition that runs on a container instance. Tasks can be run manually or managed by a service.
+   - **ECS Cluster:** A logical grouping of services or tasks. The ECS cluster is where you define the infrastructure capacity that can be used and the network environment within which to run your tasks, such as the VPC and associated subnets, monitoring options, and so on.
