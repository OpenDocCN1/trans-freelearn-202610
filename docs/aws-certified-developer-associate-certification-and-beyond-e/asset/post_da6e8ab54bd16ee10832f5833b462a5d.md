You will note that the VPC comprises several components:

- **Region** – You will build out the VPC in the N. Virginia (US-East-1) Region.
- **Availability Zones** – You will utilize two AZs for the purposes of high availability.
- **Subnets** – You will deploy six subnets: two public subnets and four private subnets, of which two will be used to host the backend application layer and another two for the database environment.
- **NAT gateways** – You will deploy NAT gateways to allow access to the internet for the virtual machines deployed in the private subnet.
- **Security groups** – You will create several security groups to ensure traffic is routed from the internet to your backend servers and ultimately to your database using best practices.

## Technical Requirements

To complete the exercises in this chapter, you will need to log in to the **Developer** account, which you created in *Chapter 1, Introduction to AWS Accounts and Global Infrastructure*, using the IAM user “Alice,” which you created in *Chapter 2, Securing Access with AWS Identity and Access Management*.

## Project Task 4.1 – Creating the VPC (us-east-1 Region)

In this task, you will create a basic VPC. You will then be configuring its components in the subsequent steps:

- 1. Log in to your AWS account using the AWS Management Console.
- 2. Navigate to the VPC console and ensure that you are in the N. Virginia Region by selecting it from the top-right drop-down list, as per the following screenshot:

![](img/34ff9b5b5a734dae3450ab701e223c73_158_0.png)

- 3. From the left-hand menu, click Your VPCs.
- 4. Click the Create VPC button in the top-right corner of the screen. You are presented with a Create VPC form. Ensure VPC only is selected as we will build out all the components manually to gain more hands-on experience:

![](img/34ff9b5b5a734dae3450ab701e223c73_158_1.png)

5. For **Name tag**, type in an appropriate name such as `todolist-vpc`, which we will be using later in this study guide.

6. Scroll down and enter the following details:

- I. Under **IPv4 CIDR block**, ensure that **IPv4 CIDR manual input** is selected
- II. For the **IPv4 CIDR**, provide the IP block range of 10.0.0.0/16
- III. Select **No IPv6 CIDR block**, under **IPv6 CIDR block**
- IV. Ensure **Default** is selected under **Tenancy**

7. Click the **Create VPC** button.

## Project Task 4.2 – Creating and Attaching an Internet Gateway

In this task, you will create an internet gateway and attach it to your VPC:

- 1. Ensure you are logged in to your AWS account and are in the VPC console within the N. Virginia Region. You should be able to see your VPC listed:

![](img/34ff9b5b5a734dae3450ab701e223c73_159_0.png)

Figure 4.12 – List of VPCs

- 2. From the left-hand menu, click **Internet gateways**.
- 3. Click the **Create internet gateway** button in the top-right corner of the screen.

4. Provide a name for your internet gateway, such as `todolist-igw`.

![](img/34ff9b5b5a734dae3450ab701e223c73_160_0.png)

5. Click the **Create internet gateway** button. You will receive a success message.

6. You now need to attach the internet gateway to your VPC. From the **Action** dropdown list, select **Attach to VPC**. (If you happen to move away from this screen, you can revisit it by selecting **Internet gateways** from the left-hand menu and then selecting `todolist-igw`.)

7. Under **Available VPCs**, select `todolist-vpc` and then click the **Attach internet gateway** button, as per the following screenshot:

![](img/34ff9b5b5a734dae3450ab701e223c73_161_0.png)

*Figure 4.14 – Attaching the internet gateway to VPC*

You will receive a message stating that the internet gateway has been successfully attached to the VPC. You will now be able to create a public route table. When you create a VPC, AWS creates a default main route table. As you create new subnets, they are automatically associated with the default route table, also known as the **main route table**.

For this exercise, you will use the main route table to host routes for your private subnets and create another route table for your public subnets.

## Project Task 4.3 – Creating a Public Route Table

You will now create an additional route table for your public subnets. Ensure you are logged in to your AWS account and are in the VPC console in the **N. Virginia Region**:

- 1. From the left-hand menu, select **Route tables**.
- 2. In the right-hand pane, you will notice two default route tables. One is for a default VPC, which exists in every Region, and the other is for the VPC you created. AWS does not add a **Name** tag, so it is a good idea to manually set the name tags yourself.
- 3. Hover the mouse next to the hyphen (-) in the **Name** column in the row where the VPC is clearly marked as todolist-vpc to get the option to edit the tag.

![](img/34ff9b5b5a734dae3450ab701e223c73_161_1.png)

*Figure 4.15 – List of route tables*

- 4. You will notice an edit icon pop up. Click it to edit the name and set the name of the route table to `todolist-mainrt`.
- 5. Click the **Create route table** button in the top-right corner of the screen.
- 6. Enter a name for the public route table, such as `todolist-publicrt`.
- 7. Select the `todolist-vpc` from the drop-down menu under **VPC**.
- 8. Click the **Create route table** button in the bottom-right corner of the screen.
- 9. You will be presented with confirmation that the route table has been successfully created. Scroll down, and under the **Routes** pane, click **Edit routes** as per the following screenshot:

![](img/34ff9b5b5a734dae3450ab701e223c73_162_0.png)

Figure 4.16 – Edit routes

- 10. You will then be presented with the **Edit routes** screen. You will need to add a new route to the internet. To do this, click **Add route** and then do the following:
- I. Under destination, type in 0.0.0.0/0.
- II. Under **Target**, select **Internet Gateway** and then `todolist-igw`. Next, click the **Save changes** button. Your public route table has now been created.

Next, you will need to create subnets and later attach the public subnets to the public route tables you just made.

- 7. For **Subnet 4 of 4**:
  - I. Subnet name: `todolist-app-subnet02`
  - II. Availability Zones: `us-east-1b`
  - III. IPv4 CIDR block: `10.0.11.0/24`

  Click **Add new subnet**.

- 8. For **Subnet 5 of 5**:
  - I. Subnet name: `todolist-data-subnet01`
  - II. Availability Zone: `us-east-1a`
  - III. IPv4 CIDR block: `10.0.20.0/24`

  Click **Add new subnet**.

- 9. For **Subnet 6 of 6**:
  - I. Subnet name: `todolist-data-subnet02`
  - II. Availability Zones: `us-east-1b`
  - III. IPv4 CIDR block: `10.0.21.0/24`

- 10. Review the settings you have configured and then click on the **Create subnet** button in the bottom-right corner of the screen.

Once the subnets have been created, they will be attached to the main route table. For private subnets, this is fine, as you will only configure internal routes and routes to a NAT gateway for internet access later in this study guide. However, you need to associate the public subnets with the general route tables as they will allow resources in those subnets direct access to the internet via the internet gateway.

## Project Task 4.5 – Associating Public Subnets with a Public Route Table

In this task, you will associate the public subnets with the public route table you created earlier:

- 1. Log in to your AWS account if you need to and navigate to the VPC console. Ensure that you are in the N. Virginia Region.
- 2. From the left-hand menu, click **Route tables**.
- 3. In the right-hand pane, select the **todolist-publicrt** route table.
- 4. Click on the **Subnet associations** tab.
