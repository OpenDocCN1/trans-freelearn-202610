Suffice it to say that, for now, you can also use Elastic Beanstalk to deploy your Docker containers and are offered the following two options:

+   - **Single Docker:** This option refers to deploying single or multiple containers on EC2 instances. The Docker image can be built by supplying a Dockerfile or retrieving a Docker image. Furthermore, you can use Docker Compose to specify an image to use along with additional components and options that need to be provided in a `docker-compose.yml` file.
+   - **ECS:** This option uses Amazon ECS, a container orchestration and management solution offered by AWS. We will discuss Amazon ECS in detail in Chapter 11, *Deploying a Multi-Tier Application Stack with Amazon ECS, Fargate, and EKS*. With this option, Amazon ECS will perform container deployments and will as managing the Docker environments. Elastic Beanstalk performs all Amazon ECS activities, such as creating clusters, task definitions, and task execution. For this option, you must use the `Dockerrun.aws.json` version 2 file. This file describes how to deploy your Docker containers as an Elastic Beanstalk application and provides support for multiple containers.

An important point about the ECS option is that your Docker images must be prebuilt and stored in a repository, which can be either public or private. Elastic Beanstalk does not provide support for using a Dockerfile for the ECS-managed Docker platform, so you cannot build custom images during deployment with a Dockerfile.

So far in this section, you have learned about some of the advanced features of Elastic Beanstalk. Using these features, you can ultimately provision end-to-end infrastructure environments capable of supporting the most complex of applications on AWS. Furthermore, we also discussed the importance of managing your backend databases with Elastic Beanstalk deployment, specifically around the concept of decoupling your Amazon RDS databases from your Elastic Beanstalk configuration to ensure database retention post-project or at the end of the application’s life cycle.

An important application security concept either using traditional multi-tier architecture designs or utilizing a PaaS solution such as Elastic Beanstalk is how that application connects to a backed-up database solution. While utilizing IAM roles is one method of granting applications temporary credentials to connect to the database, you may also need to use standard database usernames and passwords simply because that is how the application has been built.
