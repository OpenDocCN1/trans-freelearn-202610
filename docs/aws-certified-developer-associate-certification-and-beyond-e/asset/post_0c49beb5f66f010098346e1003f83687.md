## Additional Steps – Important Note

Recall that when you created the security group for the load balancer in *Project Task 8*, you did not create an inbound rule. This is because it is impossible to identify the traffic source as the API Gateway for inbound traffic. However, we need to ensure that only the API Gateway can send traffic to the load balancer, so you do not want to open inbound rules on the security group. The security group is still needed because its security group ID will be referenced to ensure that traffic to the application load balancer is only allowed from the network load balancer.

To facilitate communication between the API Gateway and the network load balancer, you must create a VPC link (endpoint) for the REST APIs, which will send traffic to the load balancer over AWS PrivateLink. However, since we are not creating any inbound rules on the security group, a workaround is required to enable traffic from the VPC link to reach the network load balancer. In this additional step, you will configure this workaround.

- 13. Navigate back to the list of load balancers and select the network load balancer you just created.
- 14. Click the **Security** tab.
- 15. Click the **Edit** button.

Uncheck the **Enable inbound rules on PrivateLink traffic** checkbox, as per the following screenshot:

![](img/34ff9b5b5a734dae3450ab701e223c73_338_0.png)

- 16. Click the **Save changes** button.

Now that the network load balancer is in place, you can create the VPC link to enable traffic over AWS PrivateLink.

## Project Task 8.5 – Integration with API Gateway

In this exercise, you will configure API Gateway:

- 1. Ensure you are logged in to your AWS development account as the IAM user Alice and are in the N. Virginia region.
- 2. From the search bar at the top of the management console, search for API Gateway and navigate to its console page.
- 3. Next, click the Build button in the REST API section. You will be directed to the Create REST API page.
- 4. Select the New API option.
- 5. Next, provide a descriptive name for your API, such as todo-list-api.
- 6. Click the Create API button.
- 7. You will be directed to the Resources section of the API Gateway console.
- 8. Click the Create Resource button. This will direct you to the Create resource page.
- 9. Ensure that you enable the Proxy resource toggle switch, which will ensure that it routes requests from any path to the network load balancer.

When using a proxy resource, you also need to define a greedy path parameter, ensuring you catch all of the resource’s sub-resources. For example, /GET/{proxy+} catches all the resources under GET/.
