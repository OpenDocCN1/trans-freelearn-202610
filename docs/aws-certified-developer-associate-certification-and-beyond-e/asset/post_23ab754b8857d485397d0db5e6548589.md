
An important point to note is that your bucket names must not contain any dots (.) and must be DNS-compliant. In addition, Transfer Acceleration is only supported on virtual-hosted style requests. You must either be the bucket owner to configure Transfer Acceleration or assign `s3:PutAccelerateConfiguration` to another user to delegate this capability.

Another important feature is minimizing retrieval costs by only accessing objects you need. Amazon S3 can retrieve subsets of objects, drastically improving performance and reducing overall costs. We will look at Amazon S3 Select and Glacier Select next.

## Amazon S3 Select and Glacier Select

Amazon S3 Select and Glacier Select are features that enable you to run **structured query language (SQL)** to filter your data held in buckets and retrieve only a required subset. This means you can avoid downloading massive amounts of data, reducing cost and latency. You can use Amazon S3 Select on data held within CSV, JSON, or Apache Parquet file formats and objects held in compressed or encrypted files.

Here are some additional points to consider:

- **Bidirectional replication** is a feature that can be used to synchronize data across Regions for failover purposes or to make applications highly available if there are regional routing issues.
- **S3 Batch Replication** is a feature designed to replicate existing objects to different buckets on demand. The replication service, when initiated, will only replicate objects that are added to a bucket after it has been activated. If there were any objects before enabling the replication service, you must copy these across manually. S3 batch replication can be used to run jobs to replicate existing objects.

## Requirements for Replication

The following are some key requirements to enable replication between two buckets:

- The source and destination Regions must be enabled for the source bucket owner
- Both the source and destination buckets must have versioning enabled
- Amazon S3 should have the necessary permissions to replicate on your behalf
- If the source bucket owner does not own the object it contains, then the object owner must grant READ and READ_ACP permissions with the object ACLs

Amazon S3 bucket replication can help companies fulfill operational and regulatory requirements and facilitate various business use cases.

Another common scenario you might encounter in your role as an AWS developer is handling very large datasets. In the next section, you will learn how to manage data that is very large in size and how this can be efficiently uploaded and downloaded from the Amazon S3 platform.

## Amazon S3 Multipart Upload

Amazon S3 multipart upload is a feature that enables you to upload an object in parts. AWS will split your object into multiple contiguous parts that can be uploaded in any order. Furthermore, if a part fails, you can reattempt the upload of said part. Once all parts have been uploaded, Amazon S3 will reassemble the parts to make up the whole object. The key benefit of this feature is the assurance that large objects stand a better chance of getting uploaded. In addition, the parts are uploaded in parallel, which further improves the throughput, and the final object is reassembled more quickly. AWS recommends uploading any object larger than 100 MB using the multipart upload API.

An object can be uploaded over time, and there is no set expiry, which means you must either complete the operation when all parts have been uploaded or terminate the multipart upload operations. It is important to note that parts of the incomplete object will also continue to reside in your S3 bucket until you delete them, thus incurring storage costs. Using lifecycle management policies, you can purge incomplete parts after a set amount of time.

In the next section, you will learn how to incorporate MFA into Amazon S3 for delete operations. This adds yet another layer of security in ensuring that delete operations are not performed by accident.

## Enforcing MFA Delete

Recall that with versioning enabled, you can prevent the accidental deletion of your object. However, it is still possible to delete specific versions of an object by specifying the version ID in your delete requests. This purges the version from the platform permanently. To further enhance security, you can enable MFA delete. With this feature enabled, you will need to supply two forms of authentication when performing any delete operations on a version of an object or when changing the version state of your bucket. With MFA delete enabled, if your primary credentials are compromised, a bad actor would still require access to your MFA device with the MFA code before any delete operations would be successful.

Once enabled for MFA delete, any requests for delete operations must include the `x-amz-mfa` request header. Furthermore, such requests must be transmitted over HTTPS. The value in this header must contain the authentication device’s serial number concatenated with the authentication code displayed on it, separated by a space. Without this request header, the request will fail.

The following section discusses Amazon S3 server access logging.

## S3 Server Access Logging

Amazon S3 server access logging is a feature that, when enabled, records all requests made to an S3 bucket. This is particularly useful for auditing and analytics on usage. You must enable server access logging at the bucket level. Furthermore, you will need to create another bucket (known as the target bucket), which will act as the destination of the log data. This is necessary because, if you used the source bucket as the destination for log data, it would create an infinite loop of logs, making it difficult to identify relevant log data. Both the source bucket and the target bucket must reside in the same Region. You can also assign a prefix to all log data, making it easier to categorize log information from other data in the bucket.

The following section looks at the AWS Storage Gateway service, designed to help build hybrid cloud offerings.

## Hybrid Storage Solutions with AWS Storage Gateway

AWS Storage Gateway is a hybrid storage service that enables businesses to connect on-premises applications with cloud storage. Storage Gateway supports three types of storage interfaces: file, tape, and volume interfaces. It helps businesses bridge the gap between on-premises and cloud storage by providing a secure and scalable data storage and backup solution.

The architecture comprises a software appliance installed on-premises, communicating with the cloud-based storage service. The software appliance provides an iSCSI interface that enables on-premises applications to access storage volumes in the cloud. Depending on the business requirements, Storage Gateway can be deployed in virtual or hardware form.

Using NFS and SMB protocols, the file interface allows you to store and access files in Amazon S3 through standard file storage protocols. This interface is ideal for storing and sharing files, such as documents and images, across multiple locations.

The tape interface enables businesses to store backups of their data in the cloud for disaster recovery purposes. It provides a virtual tape library (VTL) that emulates a physical tape library, enabling businesses to use their existing backup infrastructure with Amazon S3. This interface is ideal for businesses that need to store large amounts of data for extended periods.

The volume interface (iSCSI) enables businesses to store and access block-level storage in Amazon S3. It provides the seamless extension of on-premises storage to the cloud, enabling businesses to use Amazon S3 as a backup or archival storage tier. This interface is ideal for businesses that need to store large amounts of data that require high performance and low latency.
