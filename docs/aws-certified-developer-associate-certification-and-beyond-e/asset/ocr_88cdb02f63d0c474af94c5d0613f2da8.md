The format of accessing the stage variable in API Gateway is ${stageVariables.variableName}.

Using stage variables enables you to manage multiple release stages for your APIs. Each stage variable points to a specific Lambda alias corresponding to a specific Lambda function in this example. So, when a developer calls the dev endpoint, API Gateway returns the $Latest Lambda function. This is usually the most recently deployed Lambda function and is mutable, meaning it can change. You would want to ensure a fixed function is delivered for production use cases. In this example, when the developer calls the prod endpoint, API Gateway returns the V1 function, which might be the stable version of the application, for example, release for production use cases.

# API Gateway Caching

API Gateway offers a caching feature that helps reduce the number of calls you make to your endpoints, improving the overall latency of requests to your APIs. You can enable caching for a stage, and responses are cached for a specified time-to-live (TTL) period. The default TTL is 300 seconds, and the maximum is 3,600 seconds. The cache size can range between 0.5 GB and 237 GB.

Ideally, you should enable caching for your production workloads but not necessarily your development workloads since this increases costs.
