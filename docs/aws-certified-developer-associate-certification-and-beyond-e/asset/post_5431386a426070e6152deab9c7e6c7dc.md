# Monitoring and Maintaining Application Availability with Amazon CloudWatch

Amazon CloudWatch is a comprehensive monitoring service specifically designed for AWS cloud resources and the applications you run on AWS. It offers the functionality to collect and track metrics, set alarms, and automatically react to changes within your AWS resources. CloudWatch also facilitates the collection, viewing, and analysis of logs for troubleshooting and maintaining the operational health of AWS resources. This chapter will explore the critical role of CloudWatch in ensuring the optimal performance and operational health of applications, enhancing their availability.

CloudWatch offers two monitoring options – Basic and Detailed (enhanced) monitoring:

+   - **Basic monitoring** is cost-free and comprises a set of default CloudWatch metrics. For example, EC2 instance metrics such as `CPUUtilization`, `DiskReadOps`, `DiskWriteOps`, `NetworkIn`, and `NetworkOut` are just some examples of metrics that are sent to CloudWatch every five minutes under basic monitoring.
+   - **Detailed monitoring** is offered by some services and is chargeable. For example, for some services, such as EC2 instances, metrics are published at one-minute intervals, rather than the five-minute intervals of Basic metrics. This gives you more data points to analyze trends and quickly respond to changes or issues. Other services offer more fine-grained metrics, such as Amazon S3. Detailed monitoring is particularly recommended for production workloads and applications.

# CloudWatch Metrics

CloudWatch collects metrics data across all AWS resources you provide. A metric is a collection of related data points in a time-ordered structure. The metrics collected for a service will depend on the resource type. For example, with EC2 instances, CloudWatch collects **CPU Utilization** as a metric to identify the CPU consumption of the instance. Likewise, CloudWatch will collect metrics such as `RequestCount` and `NewConnectCount` for elastic load balancers.

You can also use another service, AWS Compute Optimizer, which integrates with Amazon CloudWatch to provide recommendations on optimizing the provisioning of your compute resources. This service helps you avoid overprovisioning or underprovisioning your compute resources across your EC2 instances, EBS volumes, ECS services running on Fargate, Lambda functions, and RDS database instances.

The service will analyze your compute usage patterns, configuration, and utilization data from Amazon CloudWatch and application monitoring tools to generate recommendations. These recommendations can then be exported to Amazon S3 and integrated with AWS Cost Explorer and AWS Systems Manager. Based on those recommendations, you can reconfigure your resources to improve performance and identify cost-saving opportunities.
