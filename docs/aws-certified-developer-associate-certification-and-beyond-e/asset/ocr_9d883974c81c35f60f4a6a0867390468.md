Organizations use it for various purposes, such as data lakes, disaster recovery, log archiving, mobile applications, and big data analytics. Amazon S3 also offers tools to optimize, organize, and customize data access based on commercial, organizational, and regulatory requirements. Amazon will never replicate your data across regions, enabling you to ensure that you meet data residency laws. However, should this not be a restriction, you are free to configure replication of your data across regions to fulfill any other requirements, such as ensuring lower latency by making data accessible to local users or for archiving and disaster recovery requirements.

Amazon S3 comprises four primary concepts:

+   - **Buckets:** These act as the primary container for objects
+   - **Objects:** These contain the actual data and metadata
+   - **Keys:** Unique identifiers for each object within a bucket
+   - **Region:** Denotes the geographic location where the bucket is stored

You will explore each of these concepts in the following sections for a comprehensive understanding.

# Amazon S3 Buckets

Amazon S3 offers two types of buckets that act as containers for your data:

+   - **General purpose buckets**, the original S3 bucket type, are designed for a wide range of use cases and access patterns. Data is stored as flat files at the root level and given unique global names. Using prefixes and delimiters, data can be categorized for ease of management and better performance.
+   - **Directory buckets** utilize the S3 Express One Zone storage class (discussed later in this chapter), which is particularly ideal for applications that require very high performance and benefit from single-digit millisecond PUT and GET latencies.

Amazon S3 buckets can host as many objects as you want. They offer 11 “nines” (99.999999999) of durability and 4 nines (99.99) of availability. This is achieved because Amazon S3 replicates your objects across multiple devices and all Availability Zones within a Region for most storage classes. Access to buckets is managed via bucket policies and access control lists (discussed later in this section).

# Amazon S3 Objects

Rather than breaking down data into smaller segments and storing it on block storage, Amazon S3 retains data as complete objects. An object is comprised of three elements – data, metadata, and a unique identifier. Metadata contains context-specific information about the object and is stored as a collection of key-value pairs. It includes essential details such as the content type, length, and last modified date. Two types of metadata can be linked to an object in Amazon S3 – user-defined and system-defined.
