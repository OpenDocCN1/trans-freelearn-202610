Since one stack may vary in configuration from another, parameters enable you to reuse your templates across different stacks, giving you flexibility and the ability to extend the life cycle of your templates.

An example of a parameter is depicted in the following snippet:

```
Parameters:
  InstanceType:
    Description: Webserver EC2 instance type
    Type: String
    AllowedValues:
      - t2.nano
      - t2.micro
      - t2.small
    Default: t2.micro
    ConstraintDescription: must be a valid EC2 instance type
```

As depicted in the above code, when this template is deployed using CloudFormation, the user is prompted to either accept the *default* instance type (in this example, `t2.micro`) for launching an EC2 instance or select another instance type from an *array* of allowed values. In this example, the allowed values are `t2.nano`, `t2.micro`, and `t2.small`.

Each parameter will have a logical name (logical ID) that must be unique among all other logical names in the template. In this example, the parameter's logical name is `InstanceType`.

The chosen value is then stored in the parameter as a variable, which you can reference using the `Fn::Ref` intrinsics function from within the **Resources** and **Outputs** sections of the template. When creating a YAML-formatted template, you can use the **!Ref** function, as depicted in the following snippet:

```
Parameters:
  **InstanceType:**
    Description: Webserver EC2 instance type
    Type: String
    AllowedValues:
      - t2.nano
      - t2.micro
      - t2.small
    Default: t2.micro
    ConstraintDescription: must be a valid EC2 instance type
Resources:
  EC2Instance:
    Type: AWS::EC2::Instance
    Properties:
      InstanceType: **!Ref InstanceType**
```
