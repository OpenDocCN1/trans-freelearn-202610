An additional point about provisioned capacity is that you can purchase reserved read and write capacity at a discount to reduce costs. You can switch from one mode to the other once every 24 hours.

When using the provisioned mode, you must define the **read capacity units (RCUs)** and **write capacity units (WCUs)**. Using these parameters, DynamoDB will provision the table with the required infrastructure to support your capacity requirements. The RCU and WCU values enable DynamoDB to ensure you have the right amount of infrastructure resources to meet the application’s demands. Let’s examine how DynamoDB consumes RCUs and WCUs:

+   - **Read requests:**
+     - If you use strongly consistent reads, then each item of up to 4 KB requires **one RCU**.
+     - If you use eventual consistent read, then each item of up to 4 KB in size requires **½ RCU**.
+     - For transactional read requests for an item up to 4 KB in size, you will need two read request units. Transactional read and write requests are different from standard read/write requests in that they guarantee that all operations contained in a single transaction set either succeed or fail as a set.

> **More on Read Consistency**
> 
> With RCUs, you need to decide whether you want strongly consistent reads or eventual consistent reads. With eventual consistent reads, when you perform a read request, the response may not result in recently completed write operations. If you repeat the query, you are likely to retrieve updated data. You get the most up-to-date data with strongly consistent reads, reflecting updates from all previous write operations. The latter is more expensive and is not supported on GSIs.
> 
> To use strongly consistent reads, you must set the `ConsistentRead` parameter to `True` in your API calls for your `GetItem`, `BatchGetItem`, query, and scan requests.
> 
> For example, suppose your item size is 8 KB. In that case, you will require two RCUs for strongly consistent reads, one RCU for eventually consistent reads, and four RCUs for transactional read requests.

+   - **Write requests:**
+     - A write request for an item of up to 1 KB in size requires one WCU
+     - A transitional write request of up to 1 KB in size requires two WCUs

> **More on Read Consistency**
> 
> For example, if your application writes at a rate of 100 writes per second and each item is 4 KB in size, then you would require 400 WCUs (10 x (4KB x 1)).
