In addition to the preceding, specifically for EC2 instances, CloudWatch alarms offer a set of EC2 actions you can perform, as follows:

+   - **Stop this instance:** When an alarm is triggered against a particular EC2 instance, you can instruct CloudWatch to stop the instance. The instance must be backed by an EBS volume, as instance store volumes terminate when you shut down the instance they are attached to.
+   - **Terminate this instance:** This allows you to terminate the instance provided that termination protection is not enabled on the instance.
+   - **Reboot this instance:** This is the same as an operating system reboot.
+   - **Recover this instance:** This attempts to recover the instance by launching it on another host machine. This action is triggered when AWS detects an underlying hardware failure following a `StatusCheckFailed_System` failure error.
+   - You also have *simplified automatic recovery*, a feature enabled by default for supported instances. AWS will attempt to remediate the instance to a healthy state if a system’s status check error is detected. Certain limitations exist, such as the fact that it does not support instances using instance store volumes or is a member of an auto-scaling group.
