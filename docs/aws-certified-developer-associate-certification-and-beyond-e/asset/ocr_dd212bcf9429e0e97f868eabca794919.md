In this project exercise, you will deploy the API Gateway, which will accept inbound connections from the client via the CloudFront distribution, ensuring secure access to the gateway. The API Gateway then enables inbound traffic to the application load balancer via the network load balancer through an API VPC link (a VPC endpoint). As discussed in Chapter 7, Building Application Solutions with High Availability, Elasticity, and Data Security, the reason for this extra complexity is that you want to deploy your application load balancer as an internal load balancer, preventing anyone from attempting access to the backend services by simply navigating to the load balancer’s pubic DNS record. All inbound connections should only come via API Gateway to ensure high levels of security.

At the same time, because there is no direct integration between API Gateway and your internal application load balancer, you will need to deploy a network load balancer. This network load balancer will also be an internal load balancer with an API VPC link (a VPC endpoint); you can define a secure tunnel to allow traffic between the API Gateway and the network load balancer.

This will allow traffic from API Gateway to be forwarded to the application load balancer via the network load balancer, which will then distribute it to the EC2 instances hosting the application stack.
