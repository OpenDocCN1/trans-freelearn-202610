The following are the key steps in the flow of traffic as depicted in the proceeding diagram:

+   1. The end user attempts an HTTPS connection to CloudFront, which results in SSL/TLS negotiations.
+   2. Once established, the end user submits an encrypted request.
+   3. If there is a cache hit, meaning if the content requested exists in a cache, it is returned to the end user, who then decrypts the content.
+   4. If there is a cache miss, CloudFront connects to the origin and performs SSL/TLS negotiations.
+   5. CloudFront then forwards the encrypted request to the origin.
+   6. The origin decrypts the request and processes the message. It then encrypts a response and sends it to CloudFront.
+   7. CloudFront decrypts the response and re-encrypts it, making sure to store a copy in its cache and forward it to the end user.
+   8. The end user then decrypts the response.

When configuring HTTPS connectivity, you can configure HTTPS for both the connection between the end user and the CloudFront distribution and then from the CloudFront distribution to the origin. The following section provides an overview of these two configuration components.

# Configuring HTTPS Communication between End Users and the CloudFront Distribution

This involves configuring cache behaviors to require HTTPS for communication between the end user/viewer and the distribution. You can also configure this communication to allow both HTTP and HTTPS, enabling you to offer some content over HTTP but enforce other content only via HTTPS.

Here, you have two options to configure:

+   - **Using default domain names:** If you use the provided distribution domain name such as `x12121212ebcdef9.cloudfront.net`, you must configure the Viewer Protocol Policy to either the **Redirect HTTP to HTTPS** or **HTTPS Only** setting. HTTP GET and HEAD requests are redirected to HTTPS requests with the former option. POST, PUT, DELETE, OPTIONS, or PATCH requests are redirected to HTTPS only if you are using HTTP 1.1 or above.
+   - **Using custom domain names:** If you use custom domain names, you will need to use an SSL/TLS certificate, which you can configure using the **AWS Certification Manager (ACM)** or purchase a third-party certificate and import it into ACM.

In addition to configuring HTTPS between the end user and your CloudFront distribution, you can configure HTTPS between your CloudFront distribution and your origin. This can be a custom origin or an Amazon S3 origin.
