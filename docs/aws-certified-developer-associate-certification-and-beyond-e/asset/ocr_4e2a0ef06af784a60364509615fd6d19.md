# CloudWatch Built-In Metrics

Built-in metrics are predefined metrics generated by AWS and sent to CloudWatch. For example, built-in metrics include monitoring CPU utilization and network traffic. Disk activity, such as disk read and write, is also included.

CloudWatch needs to ingest metric information from many AWS services, which means it needs to manage metric information efficiently. To achieve this, metrics are grouped into three different levels, as follows:

+   - **Namespace:** At the top level, you have the namespace, a container for CloudWatch metrics. Each AWS service has a namespace to enable CloudWatch to distinguish that service and its metrics collection, as per the following diagram:

![](bbox=[0.19, 0.35, 0.82, 0.58])

+   - For example, the metrics related to Amazon EC2 are grouped into a namespace defined as `AWS/EC2`, whereas the `AWS/RDS` namespace includes DB instance-level metrics. Names are unique within a namespace; for example, for `AWS/EC2`, `CPUUtilization` is distinct from `DiskReadOps`. You can use namespaces to define any other external services for your applications. Note that the `AWS/` namespace is reserved for AWS services only.

+   - **Dimensions:** Within your namespace, metrics are further organized based on dimensions. Dimensions help identify the individual resources of your service and the metric values for each resource. For example, if you have a collection of six EC2 instances, you want to identify the `CPUUtilization` metric for each instance. Dimensions are name-value pairs, allowing CloudWatch to separate metrics by resources or some other perspective to provide more contextual information. You can add up to 30 dimensions to a metric. When sending data points for the `CPUUtilization` metric for your `AWS/EC2` service, AWS also provides information such as the instance ID and the instance type as dimensions.
