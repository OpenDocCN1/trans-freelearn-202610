Each shard in your Kinesis data stream must be read by one KCL instance alone. The instance will have the KCL library installed, which can be an EC2 instance or an on-premises instance. Thus, if you have eight shards, the maximum number of KCL instances would be eight. KCL instances can share reads from multiple shards; however, remember that the number of KCL instances is limited by the number of shards.

The KCL also uses a lease table created in DynamoDB to track the shards in a stream. As records are read from the stream, checkpoints are created in the DynamoDB table. Using the checkpoints in DynamoDB, you can track other workers and share the work among workers.

As per Figure 15.22, the KCL instances can determine which shards to read from based on the checkpoints in DynamoDB. Also, if an instance fails and is replaced, the new instance can pick up operations using this information.
