# Cloning an Existing Elastic Beanstalk Environment

Another useful feature of Elastic Beanstalk is the ability to clone environments. This is particularly useful when you want to deploy a test version of your application to use a different platform branch and evaluate how the application performs. Cloning enables you to quickly create a new environment using the same settings as the original one. This way, you avoid having to manually configure option settings, environmental variables, and other configurations.

When you perform an environment clone, note that Elastic Beanstalk will make a copy of any AWS resources such as load balancers, security groups, and RDS databases for the cloned environment. There are some limitations to cloning, as you can see in the following list:

+   - While you can clone the RDS environment, the RDS data isn’t copied from the original environment.
+   - While you can clone an environment to use a different platform version, you cannot change the platform branch because Elastic Beanstalk cannot guarantee compatibility.
+   - If your Elastic Beanstalk environment was previously configured with a classic load balancer, your new cloned environment will also be configured with a classic load balancer. If you need to change your load balancer type, you will need to create a new environment and deploy your application to the new environment. Later, you can use a URL swap to direct traffic to the new environment.

# Elastic Beanstalk and Docker

In addition to deploying standard applications across the aforementioned platforms, you can also deploy applications as Docker containers. This further enables you to deploy a wide range of applications, because you are not limited to only those support platforms. Docker containers are self-contained environments that comprise the platform, programming language, runtime, libraries, and much more. A form of OS layer virtualization, Docker containers offer much more flexibility than standard virtual machines, allowing you to deploy these multiple containers on a single host machine. You’ll explore Docker in more detail in *Chapter 11, Deploying a Multi-Tier Application Stack with Amazon ECS, Fargate, and EKS.*
