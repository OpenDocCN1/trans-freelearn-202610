
## Networking on Amazon ECS

Networking on Amazon ECS enables you to define how your application is accessed both from within the VPC and from external traffic. The following networking modes are available on Amazon ECS:

- **awsvpc Networking Mode:** This mode assigns an Elastic Network Interface (ENI) to each running ECS task, providing it with an IP address in your VPC. This setup is ideal for tasks requiring high network isolation and direct access to other AWS services or resources within a VPC. It simplifies the network architecture by allowing tasks to interact directly with databases, caches, and other services over the AWS network.

- **bridge Networking Mode:** In this mode, containers on the same EC2 instance share a network bridge, facilitating communication between them. This mode is suitable for applications that need simple inter-container communication and do not require the advanced features or isolation provided by the awsvpc mode. Port mappings expose container ports to the host, allowing external traffic to reach the containers.

- **host Networking Mode:** This mode provides the highest performance networking for containers by eliminating the network isolation between the container and the host. It’s most beneficial for high-throughput applications that do not require the network isolation provided by the other modes. Containers use the EC2 instance’s network stack; the developer or architect must manage port conflicts.

## Load Balancing for Amazon ECS

Amazon ECS can be configured to use Elastic Load Balancing to distribute traffic across your tasks. You can use the Application Load Balancer for HTTP/HTTPS traffic and the Network Load Balancer for TCP/UDP traffic.

Amazon Elastic Load Balancers are container-aware, which means you can run multiple tasks from a single ECS service on the same container instance. This is achieved through a concept known as dynamic host port mapping. Let’s examine this from an architectural perspective with the diagram in *Figure 11.6:*

The points to note are as follows:

- The Application Load Balancer listens on port 80 for incoming requests.
- Containers running web service applications will serve content over HTTP (80).
- A host port is dynamically allocated from the ephemeral port range between 32768 and 61000.

When the container (task) is launched, it is registered with the Application Load Balancer as an instance ID and port combination. This awareness of the host ports ensures that traffic is routed to this instance ID and the port corresponding to that container.

This dynamic host port mapping enables you to run multiple containers using a single ECS service while ensuring that the correct application is accessible from the internet as per the preceding diagram.

When configuring your target group in the awsvpc network mode, you must define your target type as **IP** and not **Instance**. This is because your tasks are associated with an elastic network interface and not an EC2 instance.

## Introduction to Amazon ECS Copilot

Amazon ECS Copilot is a command-line tool that enables you to build and deploy production-ready containerized applications quickly. Copilot is more than just a CLI tool, however. The service aligns with the AWS Well-Architected Framework and best practices to build necessary infrastructure components for your application stack – VPCs, subnets, load balancers, and storage services.

Amazon ECS Copilot also integrates with Continuous Integration and Continuous Deployment (CI/CD) tooling, enabling you to automatically deploy updates and new releases to your application stack.

To use Copilot, you will need to do the following:

- 1. Install the AWS Copilot CLI. Current support is provided for Linux and macOS operating systems.
- 2. Install and configure the AWS CLI.
- 3. Run the AWS configure utility to access credentials.
- 4. Install and run Docker.

Amazon ECS has revolutionized how developers can design, package, and deploy their applications on AWS. Using a shared OS kernel and the ability to package application code with all files and libraries needed to run on any infrastructure has several benefits that go beyond traditional virtualized infrastructure.

Amazon ECS does have an alternative, however: a vendor-agnostic product called Kubernetes. Kubernetes is an open source container orchestration solution used across various cloud providers, such as AWS, Azure, and Google Cloud. This enables easier management of containers across a multi-cloud platform architecture.

To ensure compatibility and capture market share, AWS provides Amazon Elastic Kubernetes Service (Amazon EKS), a managed offering for Kubernetes offering tight integration across other AWS services and tooling. In the subsequent section, you are provided with an overview of Amazon EKS.

## Using Amazon EKS to Run and Manage Containers at Scale

In the dynamic world of cloud computing, adopting containerization technologies has become an essential strategy for deploying scalable and efficient applications. Among these technologies, Kubernetes has emerged as the de facto standard for orchestrating containerized applications, offering powerful capabilities to manage complex deployments at scale. Amazon Elastic Kubernetes Service (EKS) is AWS's fully managed solution that brings Kubernetes' agility, scalability, and reliability to the cloud, enabling developers and operations teams to focus on building software without the overhead of managing the underlying infrastructure.

## Understanding Amazon EKS

Amazon EKS simplifies running Kubernetes on AWS by managing the Kubernetes control plane, the core component responsible for orchestrating containers. This managed service automates tasks such as version upgrades, patching, and scaling the control plane, ensuring your Kubernetes environment is always up to date, secure, and highly available.

## Key Features of Amazon EKS

Amazon EKS offers a range of features that make it a powerful and flexible choice for running Kubernetes on AWS. Here are some of these features:

- **Fully Managed Kubernetes Control Plane**: EKS relieves you from the operational burden of managing the control plane, offering high availability across multiple AWS availability zones.
- **Integration with AWS Services**: EKS provides seamless integration with AWS services, including Elastic Load Balancing for distributing application traffic, IAM for authentication, Amazon VPC for networking, Amazon CloudWatch for logging and monitoring, and, of course, Amazon ECR for image management.
- **Flexibility and Portability**: With EKS, you can run your Kubernetes applications on AWS using Amazon EC2 instances or AWS Fargate for a serverless experience. The compatibility with standard Kubernetes ensures your applications remain portable across different environments.

## Control Plane

The control plane is the heart of any Kubernetes cluster and is responsible for managing the cluster’s state, scheduling deployments, and handling scaling and healing operations. In Amazon EKS, the control plane has several key characteristics:

- **Fully Managed**: Amazon EKS automates the provisioning, scaling, and maintenance of the Kubernetes control plane, ensuring it’s always available and up to date with the latest Kubernetes version.
- **High Availability**: The control plane runs across multiple AWS Availability Zones in a region, reducing the risk of a single point of failure and ensuring your applications remain accessible.
- **Security**: Communication between your worker nodes and the control plane is secured using AWS Identity and Access Management (IAM) and Kubernetes role-based access control (RBAC), providing fine-grained access control.
