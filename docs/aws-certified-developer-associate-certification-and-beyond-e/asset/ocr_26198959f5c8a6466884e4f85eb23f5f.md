Figure 13.10 – Architectural reference for the Production VPC

The key components of your CloudFormation stack are as follows:

+   1. The VPC is configured using a CIDR range of 10.10.0.0/16. Recall that the CIDR range you used for the VPC in the Development account was 10.0.0.0/16. It is recommended that your VPCs do not have overlapping IP addresses to ensure you can establish a VPC peering connection between them if required.

+   2. The CloudFormation template defines an internet gateway that is then attached to the VPC.

+   • The configuration comprises six subnets – two public subnets across two Availability Zones and four private subnets (two for your compute resources, such as EC2, ECS, and so on, and two for your database resources).

+   • A NAT gateway is declared in the template to enable secure access to the internet for compute resources in the private subnet. Note that in this lab project, you will only be deploying a single NAT gateway to minimize any costs as these are a chargeable service. AWS recommends you have one NAT gateway per AZ.

+   • Route tables are defined to ensure that traffic is routed to the correct endpoints in the VPC and associated with their relevant subnets. While not absolutely necessary, the template defines a route table per subnet.

+   • Security groups are then declared in the template to ensure that traffic to internal resources is restricted by port/protocol and source.
