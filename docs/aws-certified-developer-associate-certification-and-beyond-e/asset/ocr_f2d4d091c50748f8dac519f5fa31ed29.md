Manual backups are chargeable based on the storage space consumed and continue to exist even if you delete the database. These will need to be manually deleted if you no longer require them. There is no default expiry set on manual snapshots.

You can copy your manual snapshots to other regions meaning that if required, you can perform restore operations in other regions. Snapshots can also be shared across other AWS accounts. This allows authorized accounts to copy the snapshots. Note that if the snapshot you share is encrypted, then the authorized AWS accounts need to first copy the snapshot and then perform a restore from the copy.

Another important concept to understand is that when you restore from your snapshots, Amazon creates a new database instance. You do not actually restore to an existing DB instance. To perform a restore, you need to provide the snapshot name and the new DB instance name you wish to create from that snapshot. You can then use the restored DB instance as soon as its status becomes available. Note that even if the status is Available, the data restoration may still be in progress in the background; a feature known as lazy loading.

With lazy loading, if you try to access data that hasn’t been restored fully yet, the DB instance will download the data from Amazon S3. Also note that by using the `Select *` statement, you can reduce the effects of lazy loading since you are performing full table scans.

Next, you will explore automatic backups.

# Automatic Backups

The second backup option is automatic backups. Automatic backups start with a full backup, which is a complete point-in-time backup of all the data held on disk. Subsequent backup operations are performed incrementally backing up only the data that has changed or added to the databases.

Here, again, it is important to ensure that your database is configured with Multi-AZ so that backup operations take place on the standby copy of the database and not the master. This allows customers to avoid experiencing the brief I/O suspension when the backup process initializes.

With automatic backups, you can configure a maximum retention period of up to 35 days after which the backups are deleted. When setting up automatic backups you can set the retention period anywhere between 0 and 35 days (where 0 means that you have disabled automatic backups). Furthermore, you can specify a particular time of day to perform the daily backup. When you delete the database, you can choose to retain your automatic backups. Note, though, that automatic backups are still deleted after the configured retention period. If you need to retain a copy of the database, choose to create a final snapshot when you delete the database. This final snapshot is like any other manual snapshot and is under your full control.
