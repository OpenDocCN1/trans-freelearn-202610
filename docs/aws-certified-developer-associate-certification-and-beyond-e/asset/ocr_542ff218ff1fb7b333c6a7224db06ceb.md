Scaling can be done manually by adding or removing EC2 instances from the Auto scaling group or dynamically by defining rules for increasing or decreasing the capacity of the group based on resource use or demand. This allows for creating rules that respond to changes in load, such as number of requests, CPU, and memory usage.

The following discusses the three types of **dynamic scaling policies** available:

+   - **Target tracking**: This policy adjusts the current intended capacity of the Auto Scaling group based on a target value for a given metric, such as CPU or memory utilization. This policy ensures consistent capacity and will add or remove EC2 instances as needed to maintain the desired usage level, for example, 60%.
+   - **Step scaling**: This policy adds or removes EC2 instances from the current capacity of the Auto Scaling group based on a set of predetermined scaling adjustments that increase or decrease according to the severity of the alert violation. For example, if the Auto Scaling group has three levels for monitoring CPU utilization, an alert would be triggered at 40% CPU utilization, adding one EC2 instance; at 60% CPU utilization, adding two EC2 instances; and at 80% CPU utilization, adding three EC2 instances.
+   - **Simple scaling**: This policy allows the capacity of the Auto Scaling group to be increased or decreased with a single scaling adjustment. When a predetermined alert is triggered, a new EC2 instance can be launched.

On-demand instance scaling and spot fleet instance auto-scaling features make it possible to dynamically increase or decrease the capacity of the spot fleet in response to demand. The AWS Auto Scaling mechanism relies on several components that must be created before utilization, which we will discuss in the next section.

# Automatically Adjusting Capacity Using AWS Components

Amazon **Elastic Compute Cloud (EC2)** Auto Scaling relies on several components to manage the workload, including the following:

+   - **Auto-scaling groups** group instances together for easier scaling and management. Minimum, maximum, and preferred instance counts can be set when creating a group.
+   - **Configuration templates**, such as launch configurations or launch templates, allow the customization of instance details such as AMI IDs, instance type, key pair, security groups, and block device mapping.
+   - **Scaling options** allow Auto Scaling groups to be scaled in various ways using Amazon EC2 Auto Scaling. Groups can scale dynamically based on specific triggers or a predetermined schedule.
