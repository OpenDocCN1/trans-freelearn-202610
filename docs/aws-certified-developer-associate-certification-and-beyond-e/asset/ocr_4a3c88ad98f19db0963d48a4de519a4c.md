# Project Task 11.2 – Launch an Instance for Creating Docker Images

As discussed in the Technical Requirements section of this chapter, to facilitate the creation of your container image, you will need to deploy an additional EC2 instance and use it to build your image.

As a precursor to deploying this additional EC2 instance, you must create an IAM role that grants the EC2 permissions to push the Docker image to the ECR repository. You also need permission to remotely access the instance using the Systems Manager and Session Manager. This remote connection to your instance is much more secure since you do not need to open ports or configure firewall rules:

+   1. Ensure that you are still logged into your AWS Development account. Also ensure also that you are operating in the N.Virginia (us-east-1) region.
+   2. Navigate to the IAM Management console by searching for the service in the search bar on the Console Home page.
+   3. From the left-hand menu, click Roles and then, in the right-hand pane, click the Create role button.
+   4. Select AWS service for Trusted entity type and then, under Use case, select EC2. Click Next.
+   5. In the search box in the Permissions policies section, search for and select the AmazonSSMManagedInstanceCore and EC2InstanceProfileForImageBuilderECRContainerBuilds policies.
+   6. Ensure that both policies have been correctly selected, as shown in Figure 11.10:

+   8. Provide a name for your IAM role, such as iam-role-grant-ec2-access-to-ecr.
