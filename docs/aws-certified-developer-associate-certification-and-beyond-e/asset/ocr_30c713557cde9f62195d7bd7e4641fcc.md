In the next section, you will learn how to incorporate MFA into Amazon S3 for delete operations. This adds yet another layer of security in ensuring that delete operations are not performed by accident.

# Enforcing MFA Delete

Recall that with versioning enabled, you can prevent the accidental deletion of your object. However, it is still possible to delete specific versions of an object by specifying the version ID in your delete requests. This purges the version from the platform permanently. To further enhance security, you can enable MFA delete. With this feature enabled, you will need to supply two forms of authentication when performing any delete operations on a version of an object or when changing the version state of your bucket. With MFA delete enabled, if your primary credentials are compromised, a bad actor would still require access to your MFA device with the MFA code before any delete operations would be successful.

Once enabled for MFA delete, any requests for delete operations must include the x-amz-mfa request header. Furthermore, such requests must be transmitted over HTTPS. The value in this header must contain the authentication device’s serial number concatenated with the authentication code displayed on it, separated by a space. Without this request header, the request will fail.

# S3 Server Access Logging

Amazon S3 server access logging is a feature that, when enabled, records all requests made to an S3 bucket. This is particularly useful for auditing and analytics on usage. You must enable server access logging at the bucket level. Furthermore, you will need to create another bucket (known as the target bucket), which will act as the destination of the log data. This is necessary because, if you used the source bucket as the destination for log data, it would create an infinite loop of logs, making it difficult to identify relevant log data. Both the source bucket and the target bucket must reside in the same Region. You can also assign a prefix to all log data again, making it easier to categorize log information from other data in the bucket.

While storing and managing data on the Amazon S3 platform is a key offering from AWS, many customers also require the ability to build hybrid cloud storage solutions. Often, certain types of data need to remain on-premises, either due to specific latency-related issues, ensuring operational efficiency, or data sovereignty laws. These companies may also want to offload a large subset of their total data into the cloud to benefit from lower storage costs and application requirements, or simply for disaster recovery.
