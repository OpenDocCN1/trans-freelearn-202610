In the screenshot in Figure 6.34, you can select either a ‘single user’ or ‘alternating users’ rotation strategy. The ‘single user’ strategy is appropriate for most use cases but carries a slight risk of the database denying calls during the secret rotation. This risk arises because, during the rotation process, there is a very short duration between when the password in the database changes and when the secret is updated. The ‘alternating users’ strategy involves creating two users within one secret. Each time a rotation exercise initiates, one user’s password is updated while the other retains the previous valid password. This strategy is suitable for applications requiring high availability and a reduced chance of denial during the rotation process.

For this project task, ensure you select the ‘single user’ strategy.
