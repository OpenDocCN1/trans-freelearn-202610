
# The Different Pricing Models of EC2

Amazon EC2 offers various pricing models to cater to the diverse needs of its users. These pricing options enable businesses to optimize their cloud computing costs while ensuring they have the required resources for their workloads. You will **explore the four different pricing options next.**

## On-Demand Instances

On-Demand Instances allow you to pay for compute capacity by the hour or by the second, depending on the instance type you choose. There are no long-term commitments or upfront payments required, making this option ideal for short-term, irregular workloads or applications with unpredictable usage patterns. On-Demand Instances provide flexibility and help you avoid the cost and complexity of capacity planning.

## Reserved Instances (RIs)

RIs enable you to reserve compute capacity for a specific period – typically, one or three years – at a discounted price compared to On-Demand Instances. RIs are suitable for predictable, steady-state workloads or applications with long-term commitments. There are three payment options for RIs: All Upfront, Partial Upfront, and No Upfront. The more you pay upfront, the greater the discount you receive. By using RIs, you can achieve significant cost savings while ensuring resource availability for your applications.

## Savings Plans

Savings Plans are a flexible pricing model that offers discounts similar to Reserved Instances but with more simplicity and flexibility. With savings plans, you can reduce your bill and get a maximum of 72% off the On-Demand price in exchange for a one-year or three-year spend commitment. There are three types of Savings Plans:

- **Compute Savings Plans**: These offer discounts across AWS computing services such as Amazon EC2, AWS ECS Fargate, and AWS Lambda. You can also apply your discounts across any instance, including family, size, Region, or operating system. Compute Savings Plans offer more flexibility in how your discounts are applied.

- **EC2 Instance Savings Plans**: These offer discounts specific to a particular EC2 instance family within a Region. You can only apply your discounts across instance size, availability zone, operating system, and tenancy. However, EC2 Instance Savings Plans offer the most significant discounts.

- **Amazon SageMaker Savings Plans**: Offers discounts across any ML instance types, sizes, and Regions up to 64% compared to the On-Demand price.

Savings Plans require a one or three-year commitment, with the option to pay either all upfront, partially upfront, or nothing upfront. This model is ideal for businesses seeking cost savings without being tied to specific instance types or families.

## Spot Instances

Spot Instances allow you to bid on unused Amazon EC2 capacity at significantly discounted prices compared to On-Demand Instances. These instances are ideal for fault-tolerant, flexible workloads that can handle interruptions, as they can be terminated with short notice if the spot price exceeds your bid or if capacity is no longer available. Spot Instances can be used for various applications, such as big data analytics, batch processing, or development and testing environments, helping you achieve substantial cost savings.

Amazon EC2 offers a range of pricing models to accommodate different use cases and budget requirements. By understanding these pricing options, you can make informed decisions to optimize your cloud computing costs while ensuring the necessary resources for your workloads are available.

## Leveraging AMIs to Launch Amazon EC2 Instances

AMIs are templates for creating instances that include the necessary operating system, applications, and configurations. When launching an EC2 instance, selecting an appropriate AMI based on your requirements is crucial, as it determines the operating system and any pre-installed software.

An AMI comprises the following:

- One or more **Elastic Block Store** (discussed later in this chapter) snapshots or a template for the root volume of the instance if you are using an instance-store-backed AMI
- Launch permissions, which grant permissions to AWS accounts that can launch the AMI
- Any block device mappings specifying additional volumes to be attached when launching the instance

### Types of AMIs

There are three types of AMIs to choose from:

- **AWS-provided AMIs**: These are official AMIs provided by AWS, which include various operating systems, such as Amazon Linux, Ubuntu, Windows Server, and more.
- **Community AMIs**: These are created and shared by AWS users and are available for public use. Community AMIs can include pre-installed software and custom configurations.
- **Custom AMIs**: You can create custom AMIs to tailor instances to your specific needs and align with your corporate policies and/or for applications and projects.

The following are some common use cases for instance metadata:

- **Dynamic configuration**: Instance metadata can be used to configure applications running on the instance dynamically. For example, you can retrieve the instance’s public IP address and use it to update DNS records or configure load balancers.
- **Conditional execution**: You can use instance metadata to run scripts or applications conditionally based on the instance type, launch time, or other metadata. This enables you to optimize your application’s behavior based on the instance’s characteristics.
- **Security**: Instance metadata can be used to enhance security by obtaining information about the instance’s security groups or IAM roles. This information can be used to apply fine-grained access control or to audit the instance’s permissions.
- **Logging and monitoring**: You can use instance metadata to tag log files or monitor data with relevant information, such as instance ID or instance type. This makes it easier to identify and troubleshoot issues related to specific instances.

## Instance User Data

When launching an instance, you can specify instance user data, which allows you to provide a script to be executed when the instance is first launched. For example, you can run scripts that are written in bash for Linux or PowerShell for Windows-based EC2 instances. This feature is particularly useful if you need to provision your instances with specific configurations such as upgrading the OS kernel or installing applications and utilities.

While custom AMIs (discussed earlier), can be used to create an image that contains most of the applications and utilities required for your instance, there may be a need to make specific modifications to the instance at launch time. For example, you may have a custom AMI image with the base operating system, a copy of Apache Web Services, and a runtime environment predefined for a web server instance. However, there may be a need to further modify that configuration depending on whether it is being launched in a development, test, or production environment. In this scenario, a script can be supplied as part of the user data at runtime to perform those additional configurations.

## AWS Systems Monitoring: An Overview

AWS provides a comprehensive set of monitoring tools and services, enabling users to track the performance, health, and utilization of their cloud resources, applications, and infrastructure. One key service is Amazon CloudWatch, a monitoring and observability service that collects and analyzes operational data from AWS resources, applications, and services. CloudWatch collects metrics, logs, and events, helping users detect anomalies, set alarms, and automate actions based on predefined thresholds.
