The flow in Figure 9.4 ensures that only users or applications with a valid signed cookie can access the content in the private bucket, which can only be obtained from the RESTful service with the private key. It’s a typical pattern for securing content in cloud storage services, providing controlled access through cryptographic methods.

It is also essential to understand that a signer must create a signed URL or signed cookies. This can either be a trusted key group created in CloudFront or an AWS account containing a CloudFront key pair. AWS recommends using a trusted key group with signed URLs and signed cookies. There are several reasons for this recommendation.

With a trusted key group, there is no requirement to use the AWS account root user to manage the public keys. AWS recommends you do not utilize the root user for day-to-day operations. In addition, key groups allow more flexibility and management of keys, such as rotating keys without changing CloudFront distributions. You can also define IAM permissions to limit what different users can do; for example, allow users to upload public keys but not delete them. Also, as an added feature, a higher number of public keys can be associated with a distribution.

Choosing between a trusted key group and a CloudFront key pair often depends on your operation’s scale and management preferences. Trusted key groups offer better control and management for larger, more dynamic environments.
