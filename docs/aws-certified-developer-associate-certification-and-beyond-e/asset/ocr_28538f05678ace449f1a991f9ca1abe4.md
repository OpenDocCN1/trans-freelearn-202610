# Networking on Amazon ECS

Networking on Amazon ECS enables you to define how your application is accessed both from within the VPC and from external traffic. The following networking modes are available on Amazon ECS:

+   - **awsvpc Networking Mode:** This mode assigns an Elastic Network Interface (ENI) to each running ECS task, providing it with an IP address in your VPC. This setup is ideal for tasks requiring high network isolation and direct access to other AWS services or resources within a VPC. It simplifies the network architecture by allowing tasks to interact directly with databases, caches, and other services over the AWS network.
+   
+   - **bridge Networking Mode:** In this mode, containers on the same EC2 instance share a network bridge, facilitating communication between them. This mode is suitable for applications that need simple inter-container communication and do not require the advanced features or isolation provided by the awsvpc mode. Port mappings expose container ports to the host, allowing external traffic to reach the containers.
+   
+   - **host Networking Mode:** This mode provides the highest performance networking for containers by eliminating the network isolation between the container and the host. It’s most beneficial for high-throughput applications that do not require the network isolation provided by the other modes. Containers use the EC2 instance’s network stack; the developer or architect must manage port conflicts.

In the next section, you will also learn how to distribute incoming traffic using load balancing with your Amazon ECS deployments.

# Load Balancing for Amazon ECS

Amazon ECS can be configured to use Elastic Load Balancing to distribute traffic across your tasks. You can use the Application Load Balancer for HTTP/HTTPS traffic and the Network Load Balancer for TCP/UDP traffic.

Amazon Elastic Load Balancers are container-aware, which means you can run multiple tasks from a single ECS service on the same container instance.
