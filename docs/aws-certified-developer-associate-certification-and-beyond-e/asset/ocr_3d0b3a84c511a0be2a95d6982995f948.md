# Project Task 7.2 – Modify the IAM Role Currently Configured for Your EC2 Instances

In this step, you will perform multiple configurations against the existing IAM role we created for our EC2 instances in *Chapter 5, Understanding AWS Compute Services with Amazon EC2 and Storage Options*. This is because you can only attach one IAM role to your EC2 instances at a time. However, each role can be associated with multiple IAM policies. In *Chapter 5, Understanding AWS Compute Services with Amazon EC2 and Storage Options*, you have configured an IAM role called `todo-ec2-iam-master-role`. This role was configured with AmazonSSMManagedInstanceCore, which enabled you to remotely connect any EC2 instance associated with the role using the AWS Systems Manager Session Manager service.

In this step, you will add two additional policies to the same role; the first one will allow your application running on the EC2 instance to access the secret that contains the credential data for the RDS database, which the application needs to connect to. The second policy you will attach to the role is the one you created in the previous step:

+   1. From the main **AWS Management Console** page, navigate to the IAM console in a new browser tab.
+   2. From the left-hand menu, select **Policies**.
+   3. Click the **Create policy** button.
+   4. You will create the policy using the Visual editor. From the **Select a service** drop-down list, select **Secrets Manager**.
+   5. Expand the **Read** access level, and select the **GetSecretValue** access level, as per the following screenshot:
