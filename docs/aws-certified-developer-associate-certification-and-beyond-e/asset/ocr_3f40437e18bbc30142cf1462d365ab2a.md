AWS GWLBs address these issues. GWLBs are designed to help you deploy, manage, and scale your third-party virtual appliances. A GW LB is comprised of a gateway service and a load balancer service.

As depicted in the diagram in Figure 7.4, when traffic from a source is sent to a destination, its packets need to be first inspected by your virtual appliance.

The traffic first passes through the layer 3 Gateway component, representing the next hop in the route with no-packet rewrites. Once the GW LB receives the traffic, it acts as a layer 4 load balancer, offering typical features such as scaling and flow-stickiness, which gives the appliances visibility of traffic in both directions and acts on it.

It also performs health checks. Should an appliance fail, traffic can be rerouted to another appliance. The original traffic is also encapsulated in a layer 3 header using the Geneve (Generic Network Virtualization Encapsulation) protocol. This ensures that the layer 3 packet is seen without any changes. The appliance sees the packet as is, can decapsulate and inspect it, and take appropriate action to re-send it to the destination. The key benefit here is that the source and destination application need not be aware of the GW LB, ensuring that no application layer changes need to be made.
