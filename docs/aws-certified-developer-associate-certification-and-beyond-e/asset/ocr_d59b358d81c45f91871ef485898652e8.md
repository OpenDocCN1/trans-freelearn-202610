Additional important points to note are as follows:

+   - A dead-letter queue of a FIFO queue must also be a FIFO queue
+   - A dead-letter queue of a standard queue must also be a standard queue

Furthermore, retention periods depend on which queue you are working with. With a standard queue, the expiration of a message is based on its enqueue timestamp, which remains unchanged even if the message is moved into the dead-letter queue. This means that the ApproximateAgeofOldestMessage metric indicates when the message moved into the dead-letter queue. Suppose a message arrives in a standard queue and resides there for 1 day before moving into the dead-letter queue because it could not be processed. If the retention period for the dead-letter queue is set to 3 days, then the message will be deleted after 2 days and ApproximateAgeofOldestMessage is 2 days. It is highly recommended that the retention period of the dead-letter queue be longer than the retention period of the original queue.

For FIFO queues, the enqueue timeset is reset if the message is sent to a dead-letter queue. This means that if you have a retention period for a FIFO dead-letter queue set to 3 days, ApproximateAgeOfOldestmessage is also set to 3 days.

# SQS Delay Queues

By default, messages are immediately visible when they enter the queue. However, if you need to delay the processing of a message, you can set a delay queue. Here, messages remain invisible to consumers for a maximum of 15 minutes (the default is set to 0 seconds). This can be useful if your consumers need more time to process incoming new messages. You can either set a delay at the queue level or override the default value when you send a message to the queue using the DelaySeconds parameter.
