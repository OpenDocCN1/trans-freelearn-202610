For example, developers will require access to development environments that allow them to experiment and design new application features, whereas their access to production environments must be restricted. Similarly, junior system administrators should only be allowed to execute certain tasks and not have full administrative rights on critical workloads.

In this section, you will learn about AWS IAM and see how it may be used to implement crucial elements of cloud security. AWS IAM is a fully managed service that can help you define who or what can access your AWS account, what services can be accessed, and what resources can be created and configured. With AWS IAM, you configure IAM users, groups, and roles with specific permissions that can be used by entities such as human users or applications to interact with your AWS account.

# But First, Let’s Talk about the Root User

When you create your AWS account, a root user is automatically provisioned. It is the primary owner of your AWS account and has the power to close the account down. With complete unrestricted access to your AWS account, it is crucial to ensure you protect this account and keep its credentials safe.

> **Best practice**
> 
> As a best practice, it is advisable not to use the root user account for your day-to-day operations. AWS recommends you create separate individual IAM users (discussed shortly) with enough permissions required to carry out all tasks required to fulfill their job function.

# What Are the IAM Components?

AWS IAM allows you to create and configure identities for your AWS account. You can apply permissions to those identities, determining the level of access granted.

Next, you will be introduced to the various components that constitute AWS IAM.

# *IAM Users*

An IAM user may be either a human being who logs into the AWS interface or a program that needs to make a service request to your AWS environment programmatically. An IAM user account can be assigned to anyone in the company who needs to utilize the AWS services, such as programmers, system administrators, and data scientists. User authentication can either be interactive via the web console or programmatic using the **command-line interface (CLI)**. In addition, applications can make use of **software development kits (SDKs)** for AWS to gain programmatic access and execute **application programming interface (API)** calls to interact with services and resources.
