# Cache Misses and Cache Hits

A cache hit occurs when CloudFront finds the requested object in its cache, meaning it doesn’t need to return to the origin server. On the other hand, a cache miss happens when the object is not found in the cache, prompting CloudFront to fetch it from the origin server. If the content is found, it’s served directly from the cache (cache hit). If not, CloudFront fetches it from the origin and stores it in the cache for future requests (cache miss). The figure depicts a diagram of a CDN scenario. Three main components are illustrated:

+   - **Client**: This represents the user’s device, a computer, or any device capable of sending HTTP requests. It sends an HTTP request for a resource called beach.jpg with a specified size of 300 x 300. The request includes HTTP headers such as User-Agent (which identifies the browser type and operating system, here indicating an old browser, probably Internet Explorer 5.01 on Windows NT), Host (the domain from which the resource is requested), and Accept-Encoding (which indicates that the client can handle gzip and deflate encodings).

+   - **Edge location**: This is part of the CDN infrastructure. It acts as an intermediary between the client and the origin server. The edge location receives the HTTP request from the client, and if it has the requested resource in its local cache, it will serve it directly to the client to reduce latency and offload the origin server. The edge location will forward the request to the origin server if the resource is not in the cache. The diagram indicates that the edge location forwards all query strings and request headers from the client to the origin.
