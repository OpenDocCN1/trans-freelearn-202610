Step Functions offers two types of error-handling options: Retry, which retries a failed state, and Catch, which transitions the error into a failure path that you define.

You can define a Retry field for the Task, Parallel, and Map states. You must define an array of objects, known as retrievers, where an individual retriever has several retries defined and an increasing interval period known as BackoffRate. When an error is encountered and the state has a Retry field, Step Functions will scan through the error names and make retry attempts in line with the field values.

In the following example in Figure 15.17, a Retry field has been configured for an error caused by a timeout. This is defined in the ErrorEquals field.

```
"Retry": [ {
  "ErrorEquals": [ "States.Timeout" ],
  "IntervalSeconds": 3,
  "MaxAttempts": 2,
  "BackoffRate": 1
} ]
```

Figure 15.17 – Step Functions error handling

In this JSON block, Retry makes a maximum of two retry attempts, as defined by the MaxAttempts field. Furthermore, the first retry takes place after a wait period of three seconds, as defined by the IntervalSeconds field. BackoffRate increases the time interval by one second between the first and second retries.

You can also define multiple retry states, such as having States.Timeout followed by States.All, which is a wildcard that matches any error name. Note that this state must appear alone and must appear as the last retriever in the Retry array, as depicted in Figure 15.18:

```
"Retry": [
  {
    "ErrorEquals": [ "States.Timeout" ],
    "IntervalSeconds": 3,
    "MaxAttempts": 2,
    "BackoffRate": 1
  },
  {
    "ErrorEquals": [ "States.All" ],
    "IntervalSeconds": 5,
    "MaxAttempts": 5,
    "BackoffRate": 2
  }
]
```
