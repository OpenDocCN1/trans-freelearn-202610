# Consuming Data with Kinesis Data Firehose

Kinesis Data Streams is not designed to store data persistently, nor can it deliver data natively to other AWS services. You can use the Kinesis Data Firehose service if you need to load data for processing but also want to store it for the longer term. With Kinesis Data Firehose, you can reliably load massive volumes of streaming data into AWS data stores such as OpenSearch Service, Splunk, Datadog, NewRelic, Dynatrace, Sumo Logic, LogicMonitor, MongoDB, and HTTP endpoints as destinations in *near-real time*. In addition, you can load data into HTTP endpoints such as external websites and Splunk. *Figure 15.23* provides an overview of the architecture:

While Kinesis Data Streams delivers data in real time, Firehose uses a buffering system. Data is delivered only every 60 seconds or when the data size reaches 1 MB by default. However, you can configure the S3 buffer size between 1 MB and 128 MB and buffer interval values between 60 to 900 seconds for data delivery to Amazon S3. Hence, Kinesis Firehose is considered to be in *near-real time*. Furthermore, for RedShift, you must first load your data into an Amazon S3 bucket and then perform a RedShift Copy command to load that data into Amazon RedShift.

One key consideration when setting up Kinesis Data Firehose is how data transformation is handled. This often involves integrating AWS Lambda to transform data before it reaches the destination, enabling tasks such as converting formats or applying basic data analysis in transit.
