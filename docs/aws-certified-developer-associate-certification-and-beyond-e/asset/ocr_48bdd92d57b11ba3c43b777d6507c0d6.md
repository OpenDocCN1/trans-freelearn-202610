# CloudFormation Stack Roles

When deploying a CloudFormation stack, the service uses the identity of the IAM principal logged into the AWS account to perform necessary stack operations such as creating, updating, or deleting. The IAM principal must, therefore, have the required permissions either through a policy attached to it (or a group that the user is a member of) or by assuming a role.

Often, in large organizations, you may need to assign the capability of creating and updating stacks to team members who should not otherwise have full access to create and manage the individual resources that make up the stack. For example, you may have a helpdesk team that can be granted the ability to provision CloudFormation stacks, but they must not be able to individually deploy the resources of the stack outside of CloudFormation. In this scenario, you can configure service roles for CloudFormation. Using service roles, you can ensure that you follow the principle of least privilege. The procedure is as follows:

+   - An admin creates an IAM role that grants the necessary permissions to create the resources required by the CloudFormation stacks. The admin must create a trust policy where the trusted entity is the CloudFormation service, as shown in the following policy code:

```
{
  "Version": "2012-10-17",
  "Statement": {
    "Effect": "Allow",
    "Principal": {"Service": "cloudformation.amazonaws.com"},
    "Action": "sts:AssumeRole"
  }
}
```

+   - The helpdesk staff must then be granted the permissions to use CloudFormation to create, update, or delete stacks and to ensure that CloudFormation has the permissions to provision the resources. The helpdesk team should be assigned the permissions to pass the IAM role to CloudFormation using the iam::PassRole action, as per the following code snippet:

```
{
"Sid": "AllowPassingAppRoles",
"Effect": "Allow",
"Action": "iam:PassRole",
"Resource":"arn:aws:iam::<account ID>:role/cfnroles/*"
}
```

Using CloudFormation stack roles, you can add a layer of security to ensure that only authorized personnel can work directly with resources. Other users who may need to deploy infrastructure components can only do so via AWS CloudFormation.
