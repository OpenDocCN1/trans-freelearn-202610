Amazon EBS also offers another type of block storage called EBS Multi-Attach, which allows the simultaneous attachment of a single EBS volume to multiple instances. However, this feature comes with certain restrictions. Amazon EBS presents a diverse range of storage options, such as General Purpose SSDs (gp2 and gp3), Provisioned IOPS SSDs (io1 and io2), Throughput Optimized HDDs (st1), Cold HDDs (sc1), and Magnetic HDDs (MHDS). These options offer different performance levels and costs, allowing you to select the most suitable solution for your application requirements. Although all options are suggested, the ideal choice hinges on the specific demands of the user’s workload.

The storage options provided by Amazon EBS are as listed here:

- **Disks used for general purposes (gp2 and gp3) (SSDs):** These are cost-effective yet provide sufficient throughput for many different kinds of transactional workloads. These include things like virtual desktops, single-instance databases of moderate size, interactive programs that suffer greatly from latency, test beds, and boot drives. Generally speaking, these quantities are what it’s advised to use. Amazon EBS offers two types of general-purpose SSD volumes:
  - **Volumes for General Purpose SSD (gp3)** – latest generation SSD volume for widespread use
  - **SSD General Purpose (gp2) volumes**
- **Provisioned IOPS SSD volumes (SSDs):** These are Amazon EBS storage volumes with the greatest performance, built for critical, IOPS-intensive, and throughput-intensive workloads that demand minimal latency. Amazon EBS provides three different types of Provisioned IOPS SSD volumes:
  - **IOPS SSD (io2) volumes**
  - **IOPS SSD (io2) Block Express volumes**
  - **IOPS SSD (io1) volumes**
- **Amazon EBS HDD-backed volumes** fall into the following categories:
  - **Throughput Optimized Hard Disk Drive (HDD):** An affordable HDD is designed to cater to workloads that are accessed regularly and require high throughput.
  - **Cold HDD:** The most affordable HDD architecture for infrequently accessed workloads.
- **Magnetic volumes:** Magnetic drives, ideal for infrequently accessed data and scenarios requiring cost-effective storage for small volumes, perform read and write operations. Volume sizes for these drives can range from 1 GB to 1 TB, generally providing 100 IOPS with burst capacities in the hundreds.

## Optimizing Backups and Restoration with Amazon EBS Snapshots

Backups of Amazon EBS volumes can be created using Amazon S3, which takes point-in-time snapshots of your data. These snapshots are designed to store only the blocks changed since the last backup, leading to decreased data duplication and reduced storage costs. Each snapshot has instructions allowing you to restore your data to a new EBS volume.

When creating a new EBS volume by cloning an existing one, the new volume becomes an exact copy of the original volume from which the snapshot was taken. Once the new volume is generated, it is immediately usable, with data being loaded in the background. As you access the data that has not yet been loaded, it is downloaded from Amazon S3 and loaded in the background.

### Encrypting Your Amazon EBS Snapshots

These are different ways you can encrypt your Amazon EBS snapshots:

- The encryption used by EBS works flawlessly with snapshots created by EBS.
- Taking a snapshot of a disk that has been encrypted will also encrypt the snapshot for you.
- Volumes created from encrypted snapshots are inherently encrypted as well.
- If you own or have access to an unencrypted snapshot, you have the option to instantly encrypt the volumes created from it.
- A snapshot that you possess that has not been encrypted can be copied and then encrypted at your discretion.
- You can use a different key to re-encrypt a snapshot that you have access to or control before making a copy of it.
- When creating an encrypted volume from a non-encrypted snapshot, the first snapshot is always a complete snapshot.

## Introduction to Amazon EFS

Amazon EFS is a fully managed file storage system that enables you to share data using the **Network File System (NFS)** version 4 protocol. Applications running on your EC2 instance and Lambda functions can all access the file system via mount points and access points. Utilizing Amazon EFS enables you to store and share files without worrying about infrastructure, capacity, or performance. The system can dynamically expand or contract as files are added or removed, supporting petabytes of growth without impacting applications. Amazon EFS is designed for easy setup and customization through its intuitive web services interface, handling the installation and patching of the intricate file system on your behalf.

With Amazon EFS, there are no minimum fees or setup charges, and you only pay for the space occupied by your file system. Various storage tiers cater to different purposes, such as EFS Standard and EFS Standard-Infrequent Access (Standard-IA) storage classes, which offer multi-AZ resilience and the highest levels of durability and availability. In contrast, EFS One Zone and EFS One Zone-Infrequent Access (EFS One Zone-IA) storage classes allow data storage in a single Availability Zone, resulting in additional savings.

The service is engineered for scalability, availability, and durability. Amazon EFS file systems with Standard storage classes distribute data and information across multiple Availability Zones in an AWS Region, can accommodate petabytes, deliver top performance, and facilitate massively parallel data access from numerous computer instances. It operates like a standard file system, featuring a conventional interface and comprehensive file-system access semantics. Using NFS version 4.1, Amazon EFS can be accessed via any Amazon EC2 Linux instance through the NFSv4.1 protocol, allowing you to access and modify files and folders as you would on a regular hard drive after mounting.
