Object storage is ideal for data that needs to be highly durable and where the storage platform is scalable. Unlike file and block storage, which have additional technical limitations and higher costs, object storage services such as Amazon S3 are ideal for hosting digital assets such as videos, images, and documents.

For our client, **TodoPlus Limited**, object storage could be used to host archival data on Amazon S3, which generally works out much cheaper. It also hosts assets that could be used for their website and web applications. For example, **TodoPlus Limited** could host training videos on how to use its upcoming Todo List application, which could be made accessible on the internet.

# An Amazon S3 Object’s Key

Objects in Amazon S3 are stored as key-value pairs, where the key is the object’s name and the value is the actual data held as binary. Every item in a bucket possesses a unique key. Moreover, each object has a unique URL, enabling it to be accessed from any location on the internet. The object’s URL comprises the bucket’s name, a key, a URL, and a version number if versioning is enabled on the bucket. This will be discussed later in this chapter.

For example, the `https://packtpub.s3.amazonaws.com/books/chapter_03.pdf` link denotes the object name as books/chapter_03.pdf and the bucket name as packtpub.

Furthermore, `book/` in the preceding URL represents a prefix followed by a delimiter. Multiple objects can be associated with the same prefix, which can help you categorize your data. More importantly, it also facilitates filtering your list requests and allows you to apply access permissions based on those prefixes. In addition, as mentioned previously, using prefixes and delimiters can help improve your read and write throughput.

# Amazon S3 Region Choice

Amazon S3 allows you to specify the Region where you want your buckets to be hosted, considering factors such as compliance and latency. Objects remain in the Region where they were created unless the user decides to move them elsewhere. This enables AWS to ensure any data residency laws are followed. If this regulation doesn’t apply to your use case, then you can replicate data between Regions.

> **Note**
> 
> In the case of our client, **TodoPlus Limited**, data for all US-based customers will reside in the United States. Even though the business will expand its operations across continents, it will need to ensure it follows strict data residency laws. Within the US, there are multiple Regions available, which means **TodoPlus** could host replica copies of the data in a different US Region to create a disaster recovery solution and reduce the risk of single-Region hosting.
