You may first need to amend this configuration to ensure that you either create a snapshot or, ideally, retain the database. This change must be performed first and as a separate operation from the actual decoupling action. This is because if you submit a change while at the same time attempting to perform a decoupling action, that change will be ignored, and any previous policy defined as part of the database deletion policy will be followed.

Once you have decoupled your database, you can connect to it from other environments. However, you will still need to perform the required connection steps, such as defining the environmental properties, to connect to the database from the new environment and application.

# ## Configuring Elastic Beanstalk to Use HTTPS

Modern web applications accessible over the internet should be architected using higher levels of security and prevent malicious attacks. One such common configuration option is to ensure traffic between your end users and the application is encrypted. This is known as encryption in transit and is facilitated by deploying a **Secure Sockets Layer** (SSL) certification that is used to encrypt data as it is transmitted across the internet.

By default, when setting up Elastic Beanstalk, traffic occurs over standard HTTP, which is not encrypted. You can use HTTPS to ensure that traffic is encrypted, and the process involves assigning an SSL certificate to the environment's Elastic Load Balancer. This can be done in the console as well as via the `.ebextensions/securelistener-[alb|nlb].config` file.

An example configuration of such a file is as follows:

```
```
option_settings:
  aws.elbv2.listener:443:
    ListenerEnabled: 'true'
    Protocol: HTTPS
    SSLCertificateArns: arn:aws:acm:us-east-1:xxxxxxxxxx:certificate/##########################
```
```

The process will also require you to update the relevant security groups to ensure that inbound connections on HTTPS (port 443) are also permitted.

Furthermore, you can also then use a custom domain name for your end users to connect to, as well as to set up and manage your certificates using the **AWS Certificate Manager** (ACM).
