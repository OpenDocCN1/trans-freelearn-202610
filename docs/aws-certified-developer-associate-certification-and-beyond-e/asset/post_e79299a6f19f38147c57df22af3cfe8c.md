## Step 1 – Configure Sign-In Experience

- 1. By default, **Cognito user pool** is selected. In addition to this, you can also enable **Federated identity providers**. This option will allow you to sign in with third-party IdPs such as Facebook, Google, Amazon, and Apple. Note that you could also disable Cognito user pools and only opt for federated sign-in. However, in this case, users will not be able to self-register their profiles and only administrators can create users. For the purposes of this project, select only the default option.

    **Authentication providers**
    Configure the providers that are available to users when they sign in.

    **Provider types**
    Choose whether users will sign in to your Cognito user pool, a federated identity provider, or both. Amazon Cognito has different pricing for federated users and user pool users. Learn more about pricing

    **Cognito user pool**
    Users can sign in using their email address, phone number, or user name. User attributes, group memberships, and security settings will be stored and configured in your user pool

    **Federated identity providers**
    Users can sign in using credentials from social identity providers like Facebook, Google, Amazon, and Apple; or using credentials from external directories through SAML or Open ID Connect. You can manage user attribute mappings and security for federated users in your user pool.

    **Cognito user pool sign-in options** Info
    Choose the attributes in your user pool that are used to sign in. If you select only one attribute, or you select a user name and at least one other attribute, your user can sign in with all of the selected options. If you select only phone number and email, your user will be prompted to select one of the two sign-in options when the sign up.

    - User name
    - Email
    - Phone number

## Step 2 – Configure Security Requirements

    **User account recovery**
    Configure how users will recover their account when they forget their password. Recipient message and data rates apply.

    Self-service account recovery Info

    ☑ Enable self-service account recovery - Recommended

    Delivery method for user account recovery messages Info

> **Note**
>
> As per these default values, you will note that **Enable token revocation** is enabled, as per the following screenshot. This allows you to revoke refresh tokens for a user using the Cognito API or revocation endpoint, which invalidates those refresh tokens that were previously issued.
>
> Another default setting that is enabled is **Prevent user existence errors**. Normally, when a user attempts to log in, Cognito will state whether the username or the password was incorrect or whether the user does not actually exist. With this option enabled, Cognito simply states that either the username or the password was incorrect, even for nonexistent users. This helps protect against credential-guessing attacks, which adds an additional security measure for the user pool.
