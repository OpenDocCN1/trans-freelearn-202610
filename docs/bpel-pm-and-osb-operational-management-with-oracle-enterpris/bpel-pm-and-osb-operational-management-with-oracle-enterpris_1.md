## 前言

Oracle Enterprise Manager 已存在十多年，世界各地的许多数据库管理员都使用一个或多个 Enterprise Manager 产品来更高效地运行其数据库。过去几年中，Enterprise Manager 也大力推动管理中间件和应用程序。这有助于改变最初的市场认知，即 Enterprise Manager 只是 DBA 的最佳朋友。

凭借其旗舰产品 Grid Control 版本 10.2.0.5（于 2009 年 2 月在 Linux 平台发布），Enterprise Manager 加强了其在中间件领域的先前产品。Enterprise Manager 的战略方向与 Oracle 在 2008 年 4 月 29 日完成 BEA 收购后制定的方向一致。最大的改进是在管理 WebLogic Server 以及包含 Oracle BPEL Process Manager 和 Oracle Service Bus（前身为 AquaLogic Service Bus）的 Oracle SOA 平台方面取得的。

过去两年中，Enterprise Manager 进行了几次收购，以补充现有功能并为用户提供完整的解决方案。Auptyma 是这些收购中的第一个，它提供了在生产环境中无需 instrumentation 或开销的深度 Java 诊断功能。该产品更名为 Application Diagnostics for Java（AD4J）。另外，Moniforce 被收购用于管理最终用户在使用应用程序和服务提供商时的体验，该产品更名为 Real User Experience Insight（RUEI）。另一项关键收购是 ClearApp——一家提供建模和监控复合应用程序技术的公司。该产品更名为 Composite Application Modeler and Monitor（CAMM）。

前方仍有若干集成挑战，许多人仍将 Enterprise Manager 视为数据库管理解决方案。该产品在过去两年中增长迅速，尤其是在中间件、SOA 和应用程序领域。Enterprise Manager 是 Oracle 的顶级产品线之一，但仍是 Oracle 产品组合中最好的秘密。随着产品线的广泛存在，Oracle 客户的 IT 部门以低成本拥有方式集中管理这些产品线非常重要。四大管理厂商（CA、IBM、HP、BMC）拥有广泛的产品，但未针对 Oracle 产品进行优化。此外，纯粹的厂商专注于细分领域，并未提供企业管理解决方案。Oracle Enterprise Manager 对于在数据中心拥有一个或多个 Oracle 产品以及非 Oracle 产品的企业发挥着重要作用。

### 本书适合的对象

如果您从事 Oracle BPEL Process Manager、Oracle SOA Suite 或 Oracle Service Bus 工作，那么您就是本书的合适读者。如果您支持这些产品的运营基础设施，您将是更合适的读者。长期以来，应用程序和 SOA 管理员渴望了解分布式服务环境的可视性。如果您或您的团队在生产环境中支持这些产品中的任何一种，您将了解处理日常运营问题的痛苦。本书将利用 Enterprise Manager 功能在很大程度上缓解这些问题。

如果您是 SOA 架构师或以任何方式与 SOA 治理相关（例如，SOA 卓越中心），本书将让您了解在复杂的 SOA 环境中获得生产保障的众多功能。这将帮助您结合其他工具（如 Oracle Enterprise Repository（OER）、Oracle Service Registry（OSR）和 Oracle Web Services Manager（OWSM））来治理 SOA 环境。然而，本书将重点关注使用 Enterprise Manager Grid Control 的运行时 SOA 管理。

如果您喜欢以功能性方法解决运营问题，那么这就是适合您的书。您会发现本书避免对概念进行讲授，而是直接解决实际运营问题。

预计读者对面向服务的架构有一般性的了解，以及对 Oracle SOA 产品（如 BPEL Process Manager 和 Oracle Service Bus）的了解。不需要特定的管理或运营专业知识。本书将帮助您使用基于步骤的功能方法建立管理 Oracle SOA 产品的框架。



## 书中应包含的内容

本书详细介绍了如何在生产环境中设置和自动化各种对 Oracle SOA 产品平稳运行至关重要的操作任务。它将通过逐步练习引导您，帮助管理员从单一基于 Web 的控制台管理这些产品。它将使管理员免于执行单调、耗时且重复的任务。

## 书中不会包含的内容

本书避免对 SOA、BPEL 或 Service Bus 进行解释说明。如果您想使用 JDeveloper 等工具开发 BPEL 和 OSB 服务，本书并非合适的选择。此外，除第一章外，本书也避免讨论 Grid Control 产品的基础问题，如下载和安装。

## 本书涵盖内容

引言章节包含其他章节的前提基础信息。您可以根据需要，按需深入阅读其他章节，具体取决于您希望完成的目标。所有章节均定义了问题陈述，并附有提供的解决方案摘要。解决方案本身是对如何完成特定任务以解决问题进行的逐步讲解。

本书分为三个部分。第一部分涵盖使用 Grid Control 管理 BPEL Process Manager。第二部分侧重于 SOA Suite 的整体管理。第三部分涵盖 Oracle Service Bus 的管理。

第 1 章《Grid Control、BPEL 和 OSB 概述》对 Grid Control 进行了基础介绍，包括下载、安装和基本配置。这是提供从单一控制台管理各种目标的基础设施的基础技术。

## I：BPEL 管理

第 2 章《发现 BPEL PM》讨论 BPEL Process Manager 目标的发现和配置。将 BPEL PM 作为 Grid Control 管理的目标进行发现是在执行其他管理任务之前的第一步。

第 3 章《BPEL 流程监控》讨论查看已部署的 BPEL 流程及其构成的合作伙伴链接。随后讨论如何使用指标和合成测试的组合来监控 BPEL 流程和合作伙伴链接。

第 4 章《BPEL 基础设施管理》描述如何管理底层基础设施组件，如 BPEL Process Manager 服务器、脱水数据库、应用服务器、主机等。管理员可以按组管理多个不同的系统，从而减少检测系统相关问题根本原因所需的时间。

第 5 章《BPEL 服务级别管理》描述如何为 BPEL 流程、合作伙伴链接设置服务级别期望，并通过各种指标跟踪这些级别。这使服务提供商能够监控与服务消费者约定的合同保证。

第 6 章《BPEL 服务仪表板》说明仪表板对于可视化关键服务的服务级别性能和指标的重要性。本章还逐步讲解如何构建一个简单的仪表板，以显示所有关键服务及其主要指标，包括服务级别。运营团队通常使用此方法随时关注服务，并在偏离预期 SLA 时采取行动。

第 7 章《BPEL 部署自动化》说明 BPEL 工件的部署是一项重复且耗时的任务。本章描述如何以自动化方式将 BPEL 工件部署到多台服务器。这确保部署以无错误的方式进行，并减少整体计划停机时间。

第 8 章《BPEL 配置管理》描述如何管理 BPEL 基础设施的配置设置，包括设置基线和进行比较。这有助于诊断因配置更改导致的问题，并使企业范围内的配置标准化。

## II：SOA Suite 管理

第 9 章《SOA Suite 克隆》讨论克隆是一项需要深入产品专业知识的复杂管理任务。本章逐步讲解一个简单场景，将现有 SOA Suite 从一个实例克隆到另一个实例。管理员可以使用此方法以标准化、无错误的方式执行关键且耗时的任务。

第 10 章《Web 应用监控》描述如何使用 Grid Control 服务模型、SLA 规则和合成测试设置和监控 Web 服务。Web 应用也可以被监控——包括记录和回放 HTTP(s) 事务以排查问题。应用管理员可以从最终用户角度主动监控应用。

## III：WebLogic 和 Oracle Service Bus 管理

第 11 章《WebLogic 和 OSB 目标的发现》讨论从单一控制台管理多个 WebLogic 域和 OSB 实例的问题，这是中间件管理员经常遇到的问题。中间件管理员可以使用单一控制台管理所有安装、执行复杂的管理任务，并深入各自的 WebLogic 或 OSB 控制台执行管理活动。所有这些使管理员能够标准化管理任务，从而使 WebLogic 和 OSB 服务器的行为标准化，导致正常运行时间增加。

第 12 章《OSB 部署自动化》讨论将 OSB 项目和资源部署到多个域可能繁琐且耗时。本章逐步讲解典型的部署场景以及如何使用部署流程框架对其进行自动化。这使基础设施团队能够标准化部署，并集中跟踪和管理工件。

引言章节包含其他章节的前提基础信息。您可以根据需要，按需深入阅读其他章节，具体取决于您希望完成的目标。所有章节均定义了问题陈述，并附有提供的解决方案摘要。解决方案本身是对如何完成特定任务以解决问题进行的逐步讲解。

本书分为三个部分。第一部分涵盖使用 Grid Control 管理 BPEL Process Manager。第二部分侧重于 SOA Suite 的整体管理。第三部分涵盖 Oracle Service Bus 的管理。

第 1 章《Grid Control、BPEL 和 OSB 概述》对 Grid Control 进行了基础介绍，包括下载、安装和基本配置。这是提供从单一控制台管理各种目标的基础设施的基础技术。

## I：BPEL 管理

第 2 章《发现 BPEL PM》讨论 BPEL Process Manager 目标的发现和配置。将 BPEL PM 作为 Grid Control 管理的目标进行发现是在执行其他管理任务之前的第一步。

第 3 章《BPEL 流程监控》讨论查看已部署的 BPEL 流程及其构成的合作伙伴链接。随后讨论如何使用指标和合成测试的组合来监控 BPEL 流程和合作伙伴链接。

第 4 章《BPEL 基础设施管理》描述如何管理底层基础设施组件，如 BPEL Process Manager 服务器、脱水数据库、应用服务器、主机等。管理员可以按组管理多个不同的系统，从而减少检测系统相关问题根本原因所需的时间。

第 5 章《BPEL 服务级别管理》描述如何为 BPEL 流程、合作伙伴链接设置服务级别期望，并通过各种指标跟踪这些级别。这使服务提供商能够监控与服务消费者约定的合同保证。

第 6 章《BPEL 服务仪表板》说明仪表板对于可视化关键服务的服务级别性能和指标的重要性。本章还逐步讲解如何构建一个简单的仪表板，以显示所有关键服务及其主要指标，包括服务级别。运营团队通常使用此方法随时关注服务，并在偏离预期 SLA 时采取行动。

第 7 章《BPEL 部署自动化》说明 BPEL 工件的部署是一项重复且耗时的任务。本章描述如何以自动化方式将 BPEL 工件部署到多台服务器。这确保部署以无错误的方式进行，并减少整体计划停机时间。

第 8 章《BPEL 配置管理》描述如何管理 BPEL 基础设施的配置设置，包括设置基线和进行比较。这有助于诊断因配置更改导致的问题，并使企业范围内的配置标准化。

## II：SOA Suite 管理

第 9 章《SOA Suite 克隆》讨论克隆是一项需要深入产品专业知识的复杂管理任务。本章逐步讲解一个简单场景，将现有 SOA Suite 从一个实例克隆到另一个实例。管理员可以使用此方法以标准化、无错误的方式执行关键且耗时的任务。

第 10 章《Web 应用监控》描述如何使用 Grid Control 服务模型、SLA 规则和合成测试设置和监控 Web 服务。Web 应用也可以被监控——包括记录和回放 HTTP(s) 事务以排查问题。应用管理员可以从最终用户角度主动监控应用。

## III：WebLogic 和 Oracle Service Bus 管理

第 11 章《WebLogic 和 OSB 目标的发现》讨论从单一控制台管理多个 WebLogic 域和 OSB 实例的问题，这是中间件管理员经常遇到的问题。中间件管理员可以使用单一控制台管理所有安装、执行复杂的管理任务，并深入各自的 WebLogic 或 OSB 控制台执行管理活动。所有这些使管理员能够标准化管理任务，从而使 WebLogic 和 OSB 服务器的行为标准化，导致正常运行时间增加。

第 12 章《OSB 部署自动化》讨论将 OSB 项目和资源部署到多个域可能繁琐且耗时。本章逐步讲解典型的部署场景以及如何使用部署流程框架对其进行自动化。这使基础设施团队能够标准化部署，并集中跟踪和管理工件。
