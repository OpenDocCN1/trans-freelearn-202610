

现在我们已经了解了数据整理（data wrangling）的优势，让我们来了解数据整理过程中涉及的步骤。

## 数据整理涉及的步骤

与原油类似，原始数据必须经过多个数据整理步骤才能变得有意义。在本节中，我们将学习数据整理涉及的六步流程：

- 1. 数据发现
- 2. 数据结构化
- 3. 数据清洗
- 4. 数据丰富
- 5. 数据验证
- 6. 数据发布

在开始之前，重要的是要理解这些活动可能不需要按顺序执行，或者在某些情况下，你可能会跳过其中任何一步。

另外，请记住这些步骤是迭代的，并且因不同角色而异，例如数据分析师、数据科学家和数据工程师。

举例来说，数据工程师的数据发现可能与数据分析师或数据科学家对数据发现的理解不同：

让我们开始详细学习这些步骤。

数据整理过程的第一步是数据发现。这是数据整理中最重要的步骤之一。在数据发现中，我们熟悉我们拥有的原始数据的种类，我们希望用该数据解决什么用例，原始数据之间存在什么关系，数据格式会是什么样的，例如 CSV 或 Parquet，存储、转换和查询此数据的可用工具有哪些，以及我们希望如何组织此数据，例如按文件夹结构、文件大小、分区等，以便于访问。

让我们通过一个例子来理解这一点。

在这个例子中，我们将尝试了解数据发现如何根据角色而变化。假设我们有两位同事，James 和 Jean。James 是数据工程师，而 Jean 是数据分析师，他们都在一家汽车销售公司工作。

Jean 是组织的新人，她需要分析南加州的汽车销售数据。她已联系 James，请他从生产系统中的销售表中提供数据。

以下是 Jane（数据分析师）的数据发现过程：

- 1. Jane 必须确定她需要生成销售报告的数据（例如，销售交易数据、车辆详细信息数据、客户数据等）。
- 2. Jane 必须找到销售数据存储的位置（数据库、文件共享、CRM 等）。
- 3. Jane 必须确定她需要多少数据（过去 12 个月、过去一个月等）。
- 4. Jane 必须确定她将使用什么工具（Amazon QuickSight、Power BI 等）。
- 5. Jane 必须确定她需要数据以何种格式，以便与她拥有的工具兼容。
- 6. Jane 必须确定她希望将此数据存储在哪里——在数据湖（Amazon S3）、她的桌面、文件共享、沙箱环境等。

以下是 James（数据工程师）的数据发现过程：

- 1. 哪个系统请求数据？例如，Amazon RDS、Salesforce CRM、生产 SFTP 位置等。
- 2. 数据将如何提取？例如，使用 Amazon DMS 或 AWS Glue 等服务或编写脚本。
- 3. 时间表会是什么样？每天、每周或每月？
- 4. 文件格式会是什么样？例如，CSV、Parquet、orc 等。
- 5. 数据将如何存储在提供的存储中？

## 数据结构化

为了支持现有和未来的业务用例更好地为客户服务，组织必须从不同的数据源以不同的形式收集前所未有的大量数据。在现代数据架构中，大多数情况下数据存储在数据湖中，因为数据湖允许你存储各种各样的数据文件，无论是结构化数据、非结构化数据、图像、音频、视频或其他，其原始形式形状和大小各不相同。当数据处于原始形式时，它缺乏明确的结构，这是将其存储在数据库或数据仓库中或用于构建分析和机器学习模型所必需的。在这一点上，它尚未针对成本和性能进行优化。

此外，当你处理流数据（如点击流和日志分析）时，并非所有数据字段（列）都用于分析。

在数据整理的这个阶段，我们通过执行分区和转换文件类型（例如，将 CSV 转换为 Parquet）来尝试优化原始数据集以获得成本和性能优势。

再次，让我们考虑我们的朋友 James 和 Jean 来理解这一点。

对于 Jean，数据分析师而言，数据结构化意味着她希望直接查询或将数据存储在 BI 工具的内存存储中，在 Amazon QuickSight 的情况下称为 SPICE 层，可提供更快的数据访问。

对于 James，数据工程师而言，当他从生产系统提取数据并希望将其存储在 Amazon S3 等数据湖中时，他必须考虑文件格式会是什么样。他可以按地理区域（如县、州或地区）或按日期进行分区——例如，year=YYYY、month=MM 和 day=DD。

## 数据清洗

数据整理过程的下一步是数据清洗。前两个步骤让我们了解数据看起来如何以及如何存储。在数据清洗步骤中，我们开始处理原始数据，使其变得有意义，以便我们可以定义未来的用例。

在数据清洗步骤中，我们通过以下方式使数据变得有意义：

- 删除不需要的列、重复值并填充空值列以提高数据的就绪度
- 执行数据验证，例如识别必填列（如名字、姓氏、SSN、电话号码等）的缺失值
- 验证或修复数据类型以更好地优化存储和性能
- 识别并修复异常值
- 删除垃圾数据或不需要的值，例如特殊字符

James 和 Jane 都可以执行类似的数据清洗任务；然而，其规模可能不同。对于 James，这些任务必须针对整个数据集执行。对于 Jane，她可能只需要对来自南加州的数据执行，并且粒度也可能不同。对于 James，也许仅限于南加州、北加州等地区，而对于 Jean，可能是城市级别甚至邮政编码级别。

## 数据丰富

直到数据清洗步骤，我们主要是在单个数据源上工作，并使其对未来使用变得有意义。然而，在现实世界中，大多数情况下，数据是分散的并存储在多个不同的数据存储中，为了支持构建个性化或推荐解决方案或构建客户 360 或日志取证等用例，我们需要将来自不同数据存储的数据连接起来。

例如，要构建客户 360 解决方案，你需要来自 **客户关系管理（CRM）** 系统、点击流日志、关系数据库等的数据。

因此，在数据丰富步骤中，我们构建流程，将原始数据与从不同来源获得的相关数据进行增强。

## 数据验证

计算机科学中有一个非常有趣的术语，称为 **垃圾进，垃圾出（GIGO）**。GIGO 的概念是，有缺陷或有问题的（垃圾）输入数据会产生有缺陷的输出。

换句话说，输出的质量取决于输入的质量。因此，如果我们提供不良数据作为输入，我们将得到不准确的结果。

在数据验证步骤中，我们通过执行各种数据质量检查来解决这个问题：

- 业务验证数据准确性
- 验证数据安全
- 验证整个数据集中的结果一致性
- 通过验证以下数据质量检查来验证数据质量：
  - 记录数
  - 重复值
  - 缺失值
  - 异常值
  - 不同的值
  - 唯一值
  - 相关性
