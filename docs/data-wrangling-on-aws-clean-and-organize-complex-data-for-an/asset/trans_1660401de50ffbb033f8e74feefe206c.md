
数据清洗和数据验证之间有很多重叠之处，是的，这两个过程之间有很多相似之处。然而，数据验证是在结果数据集上进行的，而数据清洗主要是在原始数据集上进行的。

## 数据发布

完成所有数据整理步骤后，数据就可以用于分析，从而解决业务问题。

因此，最后一步是以所需的访问权限和许可将数据发布给最终用户。

在这一步中，我们主要关注数据如何暴露给最终用户，以及最终数据存储在何处——即关系数据库、数据仓库、数据湖中的精选区或用户区，或通过**安全文件传输协议（SFTP）**。

数据存储的选择取决于最终用户希望通过哪种工具访问数据。例如，如果最终用户希望通过 Amazon QuickSight、Power BI、Informatica 等 BI 工具访问数据，那么关系型数据存储将是理想的选择。如果是数据科学家访问，理想情况下应存储在对象存储中。

我们将在本书后面了解可用于存储原始数据和整理后数据的不同类型的数据存储。

# 数据整理的最佳实践

执行数据整理有很多方法和工具，具体取决于数据整理的方式和人员。例如，如果你正在处理实时用例，如提供产品推荐或欺诈检测，那么与构建**商业智能（BI）**仪表板以显示销售数据相比，你选择的数据整理工具和流程会有很大不同。

无论你要解决哪种类型的用例，每种情况都可以应用一些标准的最佳实践，这些实践将帮助数据整理者更轻松地完成工作。

## 识别业务用例

建议在编写任何代码之前，先决定要使用哪种服务或工具进行数据整理。识别业务用例非常重要，因为这将为数据整理过程奠定基础，并使识别你打算使用的服务变得更加容易。例如，如果你有一个业务用例，比如为小型组织分析 HR 数据，只需要对一个包含 10,000 条记录的小型数据集进行几列拼接、删除几列、删除重复项、删除 NULL 值等操作，并且只有少数用户会访问整理后的数据，那么你不需要投入大量资金去购买市场上花哨的数据整理工具——只需使用 Excel 工作表即可完成工作。

然而，当你有一个业务用例，例如处理从不同合作伙伴处接收的索赔数据，需要处理 JSON 等半结构化文件或 XML 等非结构化数据集，仅提取少量文件数据（如索赔 ID 和客户信息），并且需要执行复杂的数据整理过程（如连接、使用正则表达式查找模式等），那么你应该考虑编写脚本或订阅任何企业级工具来完成工作。

## 识别数据源并获取正确的数据

在识别业务用例之后，重要的是确定需要哪些数据源来解决它。识别数据源将帮助你选择需要哪些服务来获取数据、获取频率以及最终存储方式。例如，如果你要构建信用卡欺诈检测解决方案，就需要实时获取信用卡交易数据；甚至数据清洗和处理也应在实时进行。机器学习推理也需要在实时数据上运行。

类似地，如果你正在构建销售仪表板，可能需要从 Salesforce 等 CRM 系统或 Oracle、Microsoft SQL Server 等事务性数据存储中获取数据。

在识别了正确的数据源之后，重要的是从这些数据源中引入正确的数据，因为这将帮助你解决业务用例并使数据整理过程变得简单。

## 识别你的受众

在执行数据整理时，一个重要方面是识别你的受众。了解受众将帮助你确定他们希望消费哪种类型的数据。例如，与数据科学团队或业务高管相比，营销团队可能有不同的数据整理需求。

这也会让你了解你打算在哪里展示数据——例如，数据科学家团队可能需要 Amazon S3 等对象存储中的数据，业务分析师可能需要 CSV 等平面文件中的数据，BI 开发人员可能需要事务性数据存储中的数据，而业务用户可能需要应用程序中的数据。

至此，我们已经介绍了数据整理的最佳实践。接下来，我们将探讨 AWS 中可用于执行数据整理的不同选项。

# AWS 上可用于数据整理的选项

根据客户需求、数据源和团队专业技能，AWS 提供了多种数据整理选项。在本节中，我们将介绍 AWS 可用的最常见选项。

## AWS Glue DataBrew

AWS Glue DataBrew 于 2020 年发布，是一种可视化数据准备工具，可让你轻松清洗和规范化数据，以便为分析和机器学习做好准备。该服务提供的可视化 UI 使没有编码或脚本经验的数据分析师也能完成数据整理的各个方面。它附带了一组丰富的常见预构建数据转换操作，可以简化这些数据整理活动。与任何软件即服务（SaaS）(https://en.wikipedia.org/wiki/Software_as_a_service) 类似，客户无需预置任何服务器即可开始使用 Web UI，并且只需为使用的资源付费。

## SageMaker Data Wrangler

与 AWS Glue DataBrew 类似，AWS 还提供了 SageMaker Data Wrangler，这是一种基于 Web UI 的数据整理服务，更面向数据科学家。如果主要用例是构建机器学习管道，则应优先选择 SageMaker Data Wrangler。它直接与 SageMaker Studio 集成，使用 SageMaker Data Wrangler 准备的数据可以输入数据管道，以构建、训练和部署机器学习模型。它带有预配置的数据转换，可使用均值或中位数填补缺失数据、独热编码，以及为机器学习准备数据所需的时间序列专用转换器。

## AWS SDK for pandas

对于拥有具备编码和脚本经验的数据集成团队的客户来说，AWS SDK for pandas (https://github.com/aws/aws-sdk-pandas) 是一个很好的选择。它构建在其他开源项目之上，提供了抽象函数来执行典型的数据整理任务，例如从各种数据库、数据仓库和 Amazon S3 等对象数据存储加载/卸载数据。AWS SDK for pandas 简化了与常见 AWS 服务的集成，如 Athena、Glue、Redshift、Timestream、OpenSearch、Neptune、DynamoDB 和 S3。它还支持 MySQL 和 SQL Server 等常见数据库。
