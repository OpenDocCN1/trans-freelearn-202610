+   You can also control access by users at the folder level. Please note that Amazon S3 is an object data store that has a flat file storage hierarchy; the AWS console visualizes data with the same prefix as a folder for easier browsing purposes. So, only provide access to a certain prefix in the case of shared datasets. Consider, for example, that we have data from multiple clients stored under different folders. We can restrict access to specific user roles to a specific folder/prefix. Refer to the following documentation path for a bucket policy example for setting up folder-level access: `https://docs.aws.amazon.com/AmazonS3/latest/userguide/ example-bucket-policies.html#example-bucket-policies-folders`.

+   For situations where you need to provide access to objects in different folders for a group of users, use object tags to restrict access only to certain objects in the S3 bucket. Consider, for example, that we have three different data sources (e-commerce, agents, miscellaneous) that populate user data into the S3 bucket. Each source will upload two files daily, one that contains sensitive data (which shouldn't be accessed by users) and one that doesn't contain sensitive data (which can be accessed by all users).
