# 测验
回答以下问题：

1. GitHub 中的 PR 是什么？
    1. 从仓库拉取代码的请求
    2. 对项目的更改提案
    3. 删除代码的请求
    4. 给 GitHub 支持的消息
    *答案*: B. 对项目的更改提案

2. 真假题：PR 仅用于添加新功能。
    1. 真
    2. 假
    *答案*: B. 假

3. 在 GitHub 中制作 ________ 有助于你以便于团队成员审查的方式提出更改。
    *答案*: PRs

4. 为什么在 GitHub 上审查他人的工作很重要？
    *答案*: 审查他人的工作有助于识别潜在问题，确保质量，并促进协作，使项目更强大

5. 对 PR 提供反馈的目的是什么？
    1. 使项目更复杂
    2. 提高代码的质量和有效性
    3. 减慢项目进度
    4. 决定谁是最好的程序员
    *答案*: B. 提高代码的质量和有效性

6. 真假题：你可以为小更改和大更改创建 PR。
    1. 真
    2. 假
    *答案*: A. 真

7. GitHub 中用于快速更改的功能是什么？
    1. Issues
    2. Wiki
    3. Codespaces
    4. 直接编辑
    *答案*: D. 直接编辑

8. 对于更复杂的工作，________ 是一个有用的 GitHub 功能。
    *答案*: `github.dev`

9. 真假题：只有项目所有者才能创建 PR。
    1. 真
    2. 假
    *答案*: B. 假

10. 在 GitHub 中创建 PR 的一个最佳实践是什么？
    *答案*: 创建清晰、简洁且有效的 PR，便于团队成员理解和集成。

# 挑战 – Space Explorer 中的宇宙协作！
本章带你了解了在 GitHub 上创建和协作 PR 的要点。现在是时候将这些技能应用于我们的 *太空探索者* 游戏了。让我们添加一些璀璨的背景并优化障碍交互！

## 你的任务？
通过添加新背景和优化障碍交互来改进 *太空探索者* 游戏，使用 PR 进行协作和审查：

![图 5.38 – 太空探索者 游戏](image/B21847_05_38.png)
图 5.38 – 太空探索者 游戏

执行以下操作：
1. **为新背景创建分支**：在 GitHub 上，从主项目创建一个名为 `feature-new-background` 的新分支。此分支是绘制游戏宇宙背景的画布。
2. **集成新背景**：我已为你准备了一些很酷的太空背景。使用 `git pull` 命令将其获取到本地 `feature-new-background` 分支。将其集成到游戏中。感受宇宙的生动！
3. **改进障碍交互**：在另一个分支 `enhance-obstacle-interaction` 上，优化飞船与障碍物交互的方式。你能否在飞船撞到障碍物时添加一个很酷的声音效果？我已为你准备了一些声音供你使用。
4. **提交并打开 PR**：使用描述性的提交信息提交更改，例如 `Added cosmic background` 和 `Enhanced spaceship-obstacle interaction`。
5. 为每个分支向主项目打开 PR。描述你的更改并请求反馈。
6. **审查和协作**：邀请朋友或 fellow 程序员审查你的 PR。你的新背景和障碍交互是否超凡脱俗？
7. 讨论，必要时修改，然后当一切看起来都很棒时，将你的 PR 合并到主游戏中。
8. **清理你的空间**：成功合并后，从 GitHub 仓库中删除功能分支。保持整洁是成为优秀程序员的一部分！

## 理解合并冲突及其发生方式
你和你的团队同事都在更新一个单页作品集网站。你正在处理 **关于我** 部分，而你的同事正在为整个页面添加新字体和样式。这就是 **合并冲突** 发挥作用的地方：

![图 6.1 – 合并冲突](image/B21847_06_01.jpg)
图 6.1 – 合并冲突

### 什么是合并冲突？
把合并冲突想象成两个人同时在同一块画布上尝试绘制不同的画。你俩都有自己的想法，但它们在同一空间冲突：

![图 6.2 – 什么是合并冲突？](image/B21847_06_02.jpg)
图 6.2 – 什么是合并冲突？

### 合并冲突是如何发生的？
你和你的同事都从 `main` 分支拉取网站的最新版本以开始工作。你向 **关于我** 部分添加了详细的个人简介和一些图片，而你的同事更改了整个页面的字体样式和配色方案，包括 **关于我** 部分。*图 6**.3* 展示了这种冲突：

![图 6.3 – 合并冲突功能分支](image/B21847_06_03.jpg)
图 6.3 – 合并冲突功能分支

你俩大约在同一时间完成工作并将更改提交到各自的分支。你的同事先完成并将更改合并到 `main` 分支。`main` 分支现在具有你同事的新字体和配色方案。

现在，当你尝试合并你的 **关于我** 更改时，出现了问题。你工作的 **关于我** 部分没有你同事的新字体和颜色。Git 感到困惑，因为与 `main` 分支相比，同一部分网站在你的分支中看起来不同，如 *图 6**.4* 所示。这就是合并冲突的定义：

![图 6.4 – PR 中的合并冲突](image/B21847_06_04.jpg)
图 6.4 – PR 中的合并冲突
