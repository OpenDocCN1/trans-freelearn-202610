## Proximity-based screen lock using BLE

This is something that I have been thinking of for a while to implement and is a real-life problem for me. It's time to look into how practical it can be to use BLE stack with an Ionic application. While working in my office, I have to quite often leave my seat for taking some urgent calls or to attend some meetings. Most of the time I forget to screen lock my laptop. So, I thought of building this proximity based screen lock application using BLE and WebSockets.

Let's first look into how the application will work. The Ionic-based application listens to the iBeacon packets from the continuously broadcasting laptop. As soon as I move from my seat with my mobile, at some point it will exit from the broadcasting region of my laptop. Immediately it will send a socket request over the network to the Node.js based application running on my Ubuntu laptop and call the screen lock command on my laptop. Similarly, as I come back into the broadcasting range, it will send another socket request to unlock the laptop.

The technology stack that we will be using here is:

- Node.js
- Web Sockets
- BLE
- Ionic
- Bash script

We will get started initially by checking if Bluetooth is enabled and asking the user for location permissions, which has become mandatory since Android 6 when using diagnostic plugins:

```typescript
// src/app/app.component.ts

import { Component } from '@angular/core';
import { Platform } from 'ionic-angular';
import { IBeacon, Diagnostic, StatusBar, Splashscreen } from 'ionic-native';

import { TabsPage } from '../pages/tabs/tabs';

declare var cordova: any;

@Component({
  templateUrl: 'app.html'
})
export class MyApp {
  rootPage = TabsPage;

  constructor(platform: Platform) {
    platform.ready().then(() => {
      // Okay, so the platform is ready and our plugins are available.
      // Here you can do any higher level native things you might need.

      StatusBar.styleDefault();
      Splashscreen.hide();

      if (platform.is('cordova')) {

        // Checks if bluetooth is enabled
        IBeacon.isBluetoothEnabled().then((isEnabled) => {
          console.log("isEnabled: " + isEnabled);
          if (!isEnabled) {
            // If not, enableBluetooth() enables it
            IBeacon.enableBluetooth();
          }
        });

        // Check if location is enabled
        Diagnostic.isLocationEnabled().then((result) => {
          // If not, open location settings
          if (!result) {
            Diagnostic.switchToLocationSettings();
          }
        });

        // Diagnostic plugin
        // After Android 6, we need to explicitly
        // ask for permission from the user
        Diagnostic.requestRuntimePermissions([
          cordova.plugins.diagnostic.permission.ACCESS_FINE_LOCATION,
          cordova.plugins.diagnostic.permission.ACCESS_COARSE_LOCATION
        ]);
      });
  }
}
```

Initially, we check isBluetoothEnabled(), which returns a Boolean according to the status. After that, if it returns false, then we call the enableBluetooth() method to enable Bluetooth. Similarly, isLocationEnabled() is called to check initially if the location is enabled and, if not, call the switchToLocationSettings() method, which opens the location settings.

Diagnostic.requestRuntimePermissions() is required to get runtime permissions, which is required for all devices running on Android 6 and over. For the monitoring and ranging of BLE, we need ACCESS_FINE_LOCATION and ACCESS_COARSE_LOCATION permissions:
