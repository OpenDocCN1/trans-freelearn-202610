# Unattended automation

Unattended automation can best be seen as an *extension of the human user*. This type of automation is run from dedicated machines (such as virtual machines on the cloud) and must be triggered directly by **UiPath Orchestrator** through a triggering mechanism, such as a schedule. Unattended automation tends to unlock higher levels of impact than attended automations, as placing an automation on a dedicated machine allows businesses to run automation(s) as often as needed. Additional points on unattended automation are included in Figure 5.9:

|  |  |
|---|---|---|
| **Unattended Automation**
*An extension of the workforce, running independently without human assistance* |  |
| What to Run | • Runs larger, end-to-end process-based jobs that are more “back office” |
| When to Run | • Runs on a regular basis, whether schedule-based or event-based |
| How to Run | • A trigger (scheduled-or event-based) will kick off an automation |
| Where to Run | • Runs on an external machine, either on-premises or in the cloud |
| Why to Run | • Best for longer, more generic tasks that fulfill a full team’s needs
• Does not require human input; can run fully end to end without human intervention
• Typically saves larger amounts of time, as the process automated is generally longer (unattended automations can typically run for hours a day or even 24x7) |
| When to Choose | • When developing for a problem that is standardized across one or more teams, not necessitating human input
• Automation provides large levels of benefits, providing a return on investment required by an implementation effort |

Figure 5.9 – An overview of unattended automation

Because unattended automation runs on external machines, we lose the ability to provide the end user with immediate prompts or guides, as we could with attended automation. On the bright side, UiPath has thought of this and has provided an alternative to Validation Station for unattended automations called **UiPath Action Center.**
