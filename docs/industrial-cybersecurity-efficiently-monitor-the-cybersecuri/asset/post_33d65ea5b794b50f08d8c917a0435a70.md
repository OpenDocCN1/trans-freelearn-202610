## Blue Team observations

Because we have been mostly sticking to native Windows tools, this type of activity is hard to pick up by the Blue Team. It might be suspicious to see a connection between the TEST_REPORTSSER (the exit point of the SOCKS proxy) and the domain controller, but finding that connection is like finding a needle in a haystack. A good approach is to monitor every interactive connection (via the Terminal, a RDP session, or locally or via the system console) into the domain controller. Additionally, if Server Message Block (SMB) signing had been configured (https://docs.microsoft.com/en-us/troubleshoot/windows-server/networking/overview-server-message-block-signing), the responder tool would have had a hard time getting the hashed credentials for admin1. Add these observations to the list:

- Monitor interactive connections to the domain controller.
- Configure SMB signing to prevent sending credentials to unknown SMB servers.
