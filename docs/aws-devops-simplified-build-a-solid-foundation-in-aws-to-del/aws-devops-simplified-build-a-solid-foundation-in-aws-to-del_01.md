## 本书涵盖内容

*第 1 章，使用 AWS 加速您的 DevOps 之旅，* 强调了数字化转型的重要性以及 DevOps 和 AWS 在此转型中的作用。结合作者自身经验中的两个示例，本章涵盖了每个实例的关键学习成果，并侧重于以客户为中心以及优先考虑业务成果而非技术。

*第 2 章，选择合适的云服务，* 涵盖了 AWS 提供的三种服务层级：IaaS、PaaS 和 SaaS。从对全部三种的基本理解开始，它深入探讨了简单性与控制之间的权衡，以及这些层级在特定组织情境中的应用。结合两个真实案例，它涵盖了软件团队采用其中一种层级所获得的好处。

*第 3 章，在云中利用不可变基础设施，* 突出了基础设施不可变性在 AWS 领域的重要性，并演示了如何通过涵盖 HashiCorp 的 Packer 工具的动手部署来提升软件可靠性。最重要的是，本章揭示了一个基于 AWS Cloud9 IDE 的工具箱，用于部署贯穿全书的动手练习，并为新用户介绍 AWS，同时学习安全最佳实践。

*第 4 章，使用 AWS CloudFormation 管理基础设施即代码，* 深入探讨了使用 AWS CloudFormation 进行 **基础设施即代码 (IaC)** 自动化的好处。在解释关键服务构造后，本章转向了 IaC 的良好企业设计策略，并将该服务与 HashiCorp 的另一款著名基础设施自动化工具 Terraform 进行比较。

*第 5 章，推出 CI/CD 管道，* 为由 **持续集成和持续交付 (CI/CD)** 实践支持的稳健软件交付生命周期奠定基础。它涵盖了采用持续部署方法论的典型企业挑战，并提出了一些解决策略。在以完全自动化的应用程序交付管道部署结束之前，本章涵盖了 AWS CI/CD 空间中所有服务的集成以及如何利用它们获得最大收益。

## 如何充分利用本书

您需要具备 DevOps 是什么的基础知识，并结合对关键 AWS 提供的服务的基本理解 – **身份和访问管理 (IAM)**、AWS 控制台和 CLI。理想情况下，您过去曾使用 AWS 或其他云提供商部署过示例应用程序或概念验证，但这不是硬性要求。动手练习还假设具备基本的软件工程技能，以理解本书 GitHub 仓库中可供部署的代码并使用诸如 git 等工具、熟悉 Linux 操作系统以及对 Web 工作原理的基本理解。为了能够部署动手练习，您需要一个活跃的 AWS 订阅以及具有管理员权限的 IAM 用户。

| 书中涵盖的软件/硬件 | 操作系统要求 |
|---|---|
| Amazon Web Services (AWS) | 通过 Web 浏览器访问（Google Chrome、Safari、Firefox 或 Microsoft Edge） |
| Cloud9 IDE – 部署在您的 AWS 账户中，托管在基于 Linux 的服务器上 | Linux（由 AWS 管理） |
| AWS CDK、npm、git、Docker | Linux（预装在托管您 AWS 账户中 Cloud9 IDE 的服务器上） |

AWS Cloud9 完全支持最新版本的 Google Chrome、Safari、Firefox 和 Microsoft Edge。您将使用 Cloud9 在您的 AWS 账户中部署动手练习。如果由于某种原因无法访问该服务，请参阅以下链接获取故障排除信息：https://docs.aws.amazon.com/cloud9/latest/user-guide/troubleshooting.html。

**如果您使用的是本书的数字版，我们建议您自己输入代码或从本书的 GitHub 仓库访问代码（链接在下一节中提供）。这样做将帮助您避免与复制和粘贴代码相关的任何潜在错误。**
