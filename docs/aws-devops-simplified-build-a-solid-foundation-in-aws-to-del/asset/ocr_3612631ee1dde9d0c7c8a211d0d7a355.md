Figure 12.4: Cross-account observability to observe metrics and identify performance bottlenecks

Let’s look at this in a bit more detail, as follows:

+   1. **CloudFormation StackSets**, under the hood, hooks into AWS Organizations events that notify the service of any new accounts that are created in the organization.
+   
+   2. **CloudFormation OAM** requires data sharing to be configured from the *source accounts*. This can be easily accomplished using StackSet instances, which set up the required configuration.
+   
+   3. After the stack instance deployment is complete, observability data, such as logs, metrics, and X-Ray traces are automatically shared with the central monitoring account.
+   
+   4. Software developers, or members of the operations team, can view the aggregated metrics in the central account to understand system behaviors and identify performance bottlenecks. Once they are identified, additional measures can be taken to improve performance or right-size resources for better efficiency.
