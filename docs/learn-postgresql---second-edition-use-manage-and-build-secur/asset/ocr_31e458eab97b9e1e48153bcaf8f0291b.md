+   - If we have a table such as:

```
CREATE TABLE mytable (
    pk serial NOT NULL,
    create_date date not null default now()::date,
    primary key (pk)
)
```

+   - Is it possible to partition that table for range? Yes, it is possible by writing something like the following:

```
CREATE TABLE mytable (
    pk serial NOT NULL,
    create_date date not null default now()::date,
    primary key (pk,creat_edate)
)PARTITION BY RANGE (create_date);
CREATE TABLE

forumdb=> CREATE TABLE part_tags_date_01 PARTITION OF part_tags FOR
VALUES FROM ('2023-01-01') TO ('2023-06-31');
forumdb=> CREATE TABLE part_tags_date_01 PARTITION OF part_tags FOR
VALUES FROM ('2023-07-01') TO ('2023-12-31');
```

See the *Exploring declarative partitioning* section for more details.

+   - What is the default partition?

The default partition ensures that no data is lost; if PostgreSQL does not find any child table in which to store the record, then the record is saved in the default partition.

See the *The default partition* section for more details.

+   - Can we split the data on different disks?

Yes, we can, using tablespaces.

See the *Partitioning and tablespaces* section for more details.

+   - Does PostgreSQL manage indexes on partitioned tables?

Yes, PostgreSQL manages indexes on partitioned tables; if we build an index on a parent table, PostgreSQL will take care to build the index itself on all child tables.
