

例如，我们可以按如下方式重写 my_first_fun：

```
forumdb=> CREATE OR REPLACE FUNCTION my_second_fun (p_id integer) returns setof my_ret_type as
$$
DECLARE
    rw record; -- declare a record variable
    ret my_ret_type;
BEGIN
    for rw in select * from posts where pk=p_id loop
    ret.id := rw.pk;
    ret.title := rw.title;
    ret.record_data := hstore(ARRAY['title',rw.title
        ,'Title and Content',format('%s %s',rw.title,rw.content)]);
        return next ret;
    end loop;
    return;
END;
$$
language 'plpgsql';
CREATE FUNCTION
```

my_first_fun 和 my_second_fun 之间唯一的差别在于以下定义：

```
rw record; -- declare a record variable
```

这次，rw 变量被定义为 record 数据类型。这意味着 rw 变量是一个可以与任何表的任何记录关联的对象。两个函数 my_first_fun 和 my_second_fun 的结果是相同的：

```
title       | Indexing PostgreSQL
record_data | "title"=>"Indexing PostgreSQL", "Title and Content"=>"Indexing PostgreSQL Btree in PostgreSQL is...."
```

## Exploring rules in PostgreSQL

如前所述，规则是简单的事件处理程序。在用户级别，可以管理执行写操作的所有事件，分别是：

- INSERT
- DELETE
- UPDATE

规则背后的基本概念是修改事件的流程。如果我们给定一个事件，当某些条件发生时我们可以做的是：

- 什么都不做然后撤销该事件的操作。
- 触发另一个事件而不是默认事件。
- 与默认事件一起触发另一个事件。

因此，给定一个写操作，例如 INSERT 操作，我们可以执行以下三种操作之一：

- 取消操作。
- 执行另一个操作而不是 INSERT。
- 执行 INSERT，并在同一事务中执行另一个操作。

## Understanding the OLD and NEW variables

在开始使用规则然后使用触发器之前，我们需要理解 OLD 和 NEW 变量的概念。

OLD 和 NEW 变量表示事件前后表中行的状态。OLD 和 NEW 值是表示整个记录的光标。为了更好地理解这一点，请考虑一个 UPDATE 操作；在这种情况下，OLD 变量包含已存在于表中的记录的值，而 NEW 变量包含 UPDATE 操作后表记录将具有的值。
