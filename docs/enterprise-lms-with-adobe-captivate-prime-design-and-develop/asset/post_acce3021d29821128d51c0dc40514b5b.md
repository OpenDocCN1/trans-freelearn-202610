## Developing applications with the Captivate Prime API

API stands for **Application Programming Interface**. It is a type of interface commonly used by developers to connect different applications together. Thanks to the Captivate Prime API, virtually any data contained in your Prime account and any services provided by Captivate Prime LMS can be programmatically accessed and integrated into any type of custom application developed by your in-house development team.

Here are some of the most common use cases involving the Adobe Captivate Prime API:

- Some organizations want to take advantage of the capabilities of Adobe Captivate Prime without using the default learner experience. In this case, they can develop their own personalized learner experience using any technology of their choice. Most often, this customized user experience comes in the form of a website and/or a mobile app entirely designed and developed by the organization's in-house developers. Behind the scenes, this website/application uses the Captivate Prime API to access the necessary data (such as details about the logged-in user, the list of available courses, and the completion status) and to report learner interactions back to Captivate Prime. This is what is referred to as using Captivate Prime as a *headless* LMS.
- You can use the Captivate Prime API to integrate Captivate Prime with enterprise applications not covered by the built-in connectors available in the platform.
- You can use the Captivate Prime API to build custom applications that extend the native capabilities of Captivate Prime.

These are just a few of the many instances in which the Captivate Prime API is useful.

If this sounds a little technical to you, remember that the Captivate Prime API is intended for developers. As a Captivate Prime administrator or integration admin, you don’t need to fully understand the details of how developers implement the Captivate Prime API in the programming language they use to build these custom solutions.

The only thing you should be aware of is that the Captivate Prime API uses a security framework named **OAuth 2.0** to authenticate and authorize external applications. This security framework requires that you generate security tokens for each of the external applications that need access to your Captivate Prime account via the API.

> **OAuth**
> 
> **OAuth** stands for **Open Authorization**. It is an open industry standard used to grant websites and other applications secure access to each other. More information on the OAuth standard can be found on the official OAuth website at `https://oauth.net/`. I strongly suggest you watch the video available on their home page for a quick but thorough explanation of what OAuth is.

To experiment with this workflow, let's say you want to use Captivate Prime as a headless LMS, so you need to develop a custom website/app that will serve as the learner experience for your users. This custom website/app will be hosted by you and will access the necessary Captivate Prime data through the API. Therefore, you need to register this application with your Prime account and generate the necessary security tokens by following these steps:

- 1. Log in to your Prime account as an integration admin.
- 2. From the integration admin home page, click the **Applications** link located in the left sidebar.
- 3. Click the **Register** button located in the upper-right corner of the page to open the **Register a new application** page.
- 4. Type an application name in the **Application Name** field. This is nothing technical, so feel free to choose any name you deem appropriate. Note that this name cannot be changed afterward.
- 5. Provide the URL where your custom application will be hosted in the **URL** field.
  For the purpose of this exercise, just type the URL of your website or any other valid URL.
- 6. Type `https://*.<the_address_of_your_website>` in the **Redirect Domains** field.

These are the domains where it is safe to redirect users after they have authenticated with the OAuth server. Note that you can add multiple redirect domains in this field.

- 7. As a best practice, take the necessary time to provide a brief description of the application you are registering.
- 8. In the Scopes section of the page, select the checkboxes required by your application.

In this example, you are building a custom learner experience, but you will still be using the native Captivate Prime administrator for building courses and administering your LMS. So, you only need to select Learner role read access and Learner role write access.

With this configuration, your custom application will be authorized to read and write anything related to the learner role, but you will not be able to use it to remotely administer your Captivate Prime account.

- 9. If you want this application to be visible to the other administrators of your Prime account, select the No radio button in the For this account only? field; otherwise, leave it as Yes.
- 10. When the Register a new application page looks as in the following screenshot, click the Save button in the upper-right corner of the page:

Figure 16.4 – The Register a new application page

- 11. As soon as you click the **Save** button, the page refreshes and displays the application ID and the application secret. These are the security tokens that your developers need to include in every request they send to the Captivate Prime API.
