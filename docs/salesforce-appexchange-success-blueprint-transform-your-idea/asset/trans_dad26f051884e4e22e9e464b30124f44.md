
为了便于理解，分为集群：PE 和 EE/UE。每个集群内的版本共享相似的功能。

对于使用 scratch org 进行开发的人员来说，scratch org 定义文件中的“edition”属性是你确定该 scratch org 的 Salesforce 版本的工具。通过创建多样化的 scratch org 定义蓝图，你可以轻松创建配置各异的 scratch org 以供检查。务必考虑将此文件加入你的项目书签并与你的版本系统同步。请记住——PE 缺少其他版本中存在的一定功能。因此，基于主要开发 scratch org 定义文件构建的应用可能与 PE 组织不兼容。面向 PE 设计？认识这些区别并使用 PE 组织进行评估至关重要。

要了解特定版本中可用的功能和对象，请查阅版本比较表¹或在线帮助。建议通过在 PE 测试组织中安装应用来测试你的应用，以确保一切按预期运行。你可以使用 Environment Hub 创建 PE 测试组织，详情请参阅 *第 2 章*。

1 https://www.salesforce.com/editions-pricing/sales-cloud/

所有 Salesforce 版本都有限制，限制可使用的应用、对象和标签的数量。然而，幸运的是，对于 ISV 合作伙伴而言，任何在 AppExchange 市场上公开发布的托管包不再计入这些限制。

就 API 访问而言，通常在 PE 组织中不受支持。但是，通过安全审查后，你有资格使用某些 API 来构建复合应用。

支持多个 Salesforce 版本提供了提供更丰富应用版本的機會。这可以通过使用扩展包或利用 Dynamic Apex 实现，详情请参阅 *第 4 章*。

## Process implementation

在设计和执行高效工作流的过程中，管理基础课程中的某些原则可能非常宝贵。以下是你如何在 ISV 之旅中运用它们的方法：

- **流程映射**：该技术涉及概述执行任务或实现特定结果所涉及的每个步骤。通过创建事件序列的可视化表示，你可以更好地理解工作流，识别潜在的低效之处，并突出改进机会。
- **利用自动化**：借助 Salesforce 的自动化工具套件，如 Flow Builder，你可以自动化重复性任务。这不仅提高了运营效率，还能让你的团队专注于战略性和复杂性问题。
- **标准化和文档化**：通过标准化流程来创建执行任务的统一方法。文档确保这些标准化流程被理解并为所有人所用，保证一致性，并在人员变动期间提供参考点。
- **持续改进**：培养持续改进的心态。定期根据反馈、不断变化的业务需求以及 Salesforce 技术的进步来审查和完善你的流程和工作流。
- **绩效指标**：定义关键绩效指标以衡量流程的有效性。定期使用这些指标进行评估可以找出需要关注的领域并跟踪已实施更改的成功情况。
