## 批量数据同步

批量数据同步涉及在计划的间隔内传输大量数据。当不需要实时数据时，此模式很有用，对于大型数据集而言，其比实时传输数据更高效。

一个例子可能是 ISV 需要每晚在 AppExchange 应用程序和远程数据库之间同步数据。应用程序全天收集数据，然后在非高峰时段以单批方式全部发送到数据库。

## 远程调用

远程调用模式涉及远程服务向客户端应用程序发出请求。这与远程过程调用模式相反，在该模式中客户端向服务发出请求。

一个例子是 ISV 将其 AppExchange 应用与外部地址验证服务集成。当用户在应用程序中输入地址时，AppExchange 应用会发送请求以验证地址的准确性和格式。外部地址验证服务随后检查地址并返回验证结果，确保数据的准确性和一致性。

## 基于数据变化的 UI 更新

此模式涉及根据托管在平台外的底层数据的变化来更新应用程序的用户界面。这使应用程序能够向用户提供实时反馈。

例如，ISV 可以使用此模式在托管在其 AWS 实例中的底层数据发生变化时更新其 AppExchange 应用程序中的驾驶舱。一旦检测到更改，应用程序就会更新 Salesforce 驾驶舱以反映新数据。

## 数据虚拟化

数据虚拟化是一种数据管理方法，允许应用程序在无需了解数据的技术细节（例如其在源处的格式或物理位置）的情况下检索和操作数据。这降低了数据错误的风险以及移动可能永远不会使用的数据的工作量，并且不会试图对数据强加单一的数据模型。

例如，ISV 可能会使用数据虚拟化在其 AppExchange 应用程序中提供来自多个来源的数据的统一视图。应用程序可以像所有数据都在单个位置一样访问和操作数据，即使实际上数据分布在多个数据库中。

## 选择合适的集成模式

为您的应用程序选择合适的集成模式是一个关键决策，会显著影响其性能、用户体验和整体成功。在深入编码细节之前，请花点时间进行深思熟虑。通过自问以下问题，您可以简化开发流程，并通过确保选择最合适的设计模式来可能节省数周的努力。
请记住，少量的前期规划在创建稳健高效的集成解决方案方面可以大有裨益。

### 1. 需要什么交互级别？

考虑客户端应用程序与远程服务之间所需的交互程度。您需要立即响应，还是应用程序可以在等待响应的同时独立运行？如果实时交互至关重要，则同步模式可能最佳。另一方面，如果应用程序可以在没有即时反馈的情况下继续运行，您可以探索不会阻塞应用程序进度的异步模式。

### 2. 数据一致性有多重要？

思考在应用程序和远程服务之间保持一致数据的重要性。如果数据准确性至关重要，则促进同步通信和即时反馈的模式可能是合适的选择。然而，如果可以容忍数据中的细微差异，异步模式可能提供更多灵活性。

### 3. 真的需要实时响应吗？

考虑客户端应用程序是否必须在继续之前等待远程服务的响应。如果不是，允许非阻塞通信的模式，例如“即发即弃”，可能更有优势。这种方法可以防止应用程序工作流程和响应能力的延迟。

### 4. 数据量是多少？

评估需要传输的数据量。对于大型数据集，批量数据同步模式可能比实时传输更高效、更实用。这可以帮助您管理网络资源并保持应用程序的性能。

### 5. 谁发起请求？

检查远程服务是否需要向客户端应用程序发起请求。根据通信方向，您可能需要选择特定的调用模式，例如“远程调用”模式，以适应这些场景。

### 6. 是否需要实时 UI 更新？

思考应用程序的用户界面是否应根据外部数据变化实时更新。如果是，则“基于数据变化的 UI 更新”等模式可以帮助您提供动态且响应迅速的用户体验。

### 7. 是否涉及不同的数据源？

如果您的应用程序需要在不强加单一数据模型的情况下处理来自各种来源的数据，请考虑“数据虚拟化”模式。这种方法可以在无需大量数据转换工作的情况下统一数据。

通过花时间思考这些问题，您为集成解决方案奠定了坚实的基础。请记住，一个小时的深思熟虑的规划可以转化为开发过程中节省的数周时间，从而实现更高效、更有效、更成功的 AppExchange 应用程序。因此，在编写第一行代码之前，请参与这一关键的最优模式选择阶段。

## 外发集成的可用技术

Salesforce 提供了一系列工具和方法来促进与外部系统的外发集成。在本节中，我们将探讨 Salesforce 平台提供的最流行和最广泛使用的外发集成技术。

### 使用 Flow 的声明式

Salesforce 中的声明式外发集成主要通过使用 Flow 实现。Salesforce Flow 是一款强大的工具，允许用户无需编写代码即可自动化业务流程。在外发集成的领域中，Flow 提供两种主要方法：外发消息和外部服务。

外发消息是 Salesforce 在满足特定条件时发送给外部系统的 SOAP 消息。它们旨在通知外部系统 Salesforce 数据的变化。另一方面，外部服务为流程直接集成第三方 API 提供了一种方式，支持使用 GET、POST、PUT、PATCH 和 DELETE 等方法的 HTTP 调用。在创建外部服务包时，开发人员可以向外部服务注册包添加命名凭据组件，或者订阅者可以在其组织中建立与外部服务注册中指示的命名凭据匹配的命名凭据。

### 使用 Lightning Web Components 的编程方式

Lightning Web Components (LWC) 虽然主要设计用于在 Salesforce 平台上构建动态用户界面，但也能够执行编程外发集成。

LWC 利用现代 Fetch API 向外部服务进行调用。此 API 提供了一种灵活高效的方式来获取资源，无论是通过 HTTP 还是 HTTPS。LWC 中的 Fetch API 允许开发人员向外部服务发出异步请求。开发人员可以指定请求方法（GET、POST、PUT、DELETE）、标头和请求正文，然后在收到响应后进行处理。

在从 LWC 进行调用之前，将 API 端点的基本 URL 添加到 Salesforce 中的内容安全策略 (CSP) 受信任站点至关重要。

### 使用 Apex 的编程方式

Apex 是 Salesforce 的专有编程语言，是希望以编程方式进行外发集成的开发人员的基石。它提供了一套全面的工具和方法来促进与外部系统的通信。
