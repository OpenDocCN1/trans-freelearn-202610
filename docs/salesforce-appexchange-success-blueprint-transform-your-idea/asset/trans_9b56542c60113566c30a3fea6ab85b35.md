## 推出免费试用

你有几种向潜在客户提供免费试用的选择，如下所示：

- **From Salesforce, through AppExchange**: 客户可以直接从 AppExchange 列表启动试用。
- **Using HTML forms on your external website**: 潜在客户提交表单后，Salesforce 会基于 Trialforce 模板提供试用。使用此类表单时，你可以采用 `SignupRequest` API。
- **Employing the SignupRequest API independently**: 这适用于寻求更精细自定义的人。试用可以以编程方式激活。

好了， fellow space travelers！有了这些路线在你的星图上，你现在就可以将你的应用送入轨道，以多样且动态的方式与潜在客户建立联系，就像我们银河系中的星星一样。

请记住，随着你的产品不断发展，你的试用模板也应随之发展。任何更新或品牌变更都需要在试用中体现。

## 在网页上集成试用

将免费试用直接展示在你的网站上，是扩展 AppExchange 解决方案覆盖范围的有效方法。利用 HTML 表单结合 SignupRequest API 不仅能推动用户参与你的业务，还能向潜在客户全面展示你的解决方案。提交表单后，Salesforce 会分配一个与你预定义的 Trialforce 模板相符的试用。

## 了解 SignupRequest API

SignupRequest API 在激活网站上的免费试用时作为工具。执行对 SignupRequest 对象的 API 调用使你能够为潜在客户生成注册，收集深入的注册数据，分析这些信息，并将注册数据与你现有的业务运营同步。

## 在网站上实施试用

要在你的网站上实施试用，请执行以下步骤：

- 1. **Activation of SignupRequest API**: 要激活 **SignupRequest** API，请使用你的 **Partner Business Org (PBO)** 凭据在 Salesforce Partner Community 中打开一个支持案例。这将使 API 在你的组织中运行。
- 2. **Selection of a sign-up form hosting option:** 评估并选择适合你的注册表单的托管解决方案。这可能从托管在 Heroku 上的 Node.js 和 React 应用，到托管在 Experience Cloud 网站上的 Lightning 组件、托管在 Sites 上的 Visualforce 页面或 Web-to-Lead 表单不等。
- 3. **Creating sign-ups through the API:** 实现对 `SignupRequest` 对象的 API 调用以创建面向潜在客户的注册，从而让你自定义注册流程。
- 4. **Generating proxy sign-ups for OAuth and API access:** `SignupRequest` 对象允许你以编程方式创建组织，而不会向用户发送任何系统生成的电子邮件。因此，你可以获取 OAuth 访问令牌登录该组织并从中执行 API 请求，而无需任何用户操作。
- 5. **Provisioning trial orgs:** 利用 Trialforce 为潜在客户提供你解决方案的免费试用。

遵循这些步骤，你可以将 AppExchange 解决方案的免费试用顺畅地集成到你的网站中，从而提升潜在客户体验并放大你的产品提供的可见性和采用率。

## 通过从 AppExchange 直接安装来促进应用试用

有时，对潜在客户最有效的试用体验可能只是允许他们直接从你的 AppExchange 列表获取你的应用程序。这种即时的动手体验让客户能够在他们的 Salesforce 环境中评估你的应用程序，从而真实地了解你的解决方案如何融入他们的工作流程。

这一过程的关键在于 LMA。当客户从 AppExchange 市场安装你的应用时，你的 LMA 中会自动创建一个许可证。默认情况下，该许可证将在预定的试用期后过期，你可以根据业务需求定义该期限。

要指定默认试用期，请按照以下步骤操作：

- 1. 导航到你的 LMA。
- 2. 点击 **Packages** 选项卡。
- 3. 选择相关的托管包。
- 4. 在 **Package Detail** 页面，编辑 **Default Trial Length (Days)** 字段。
- 5. 保存更改。

此设置允许你定义试用期的标准持续时间（通常设置为 30 天）。潜在客户安装你的应用的那一刻，其试用期就开始了，在此期限结束时，除非他们购买完整许可证，否则许可证将自动过期。

当你的应用程序的配置过程得到精简和自动化时，直接安装策略效果最佳。客户通常欣赏流畅、无忧的设置流程，让他们无需大量技术帮助或阅读复杂的设置手册即可开始使用你的应用。

然而，创建无缝的安装流程通常需要你进行相当多的规划、设计和测试。在下一节中，我们将深入探讨优化安装体验的策略和技术，使其尽可能流畅且以客户为中心。这些对安装流程的改进可以显著影响客户对你的应用的最初印象，影响他们从试用用户转变为付费客户的决定。

## 将试用转化为付费客户

将这些试用转化为真实客户的关键在于有效管理试用期并与潜在客户进行战略性互动。在试用期间，保持与潜在客户的密切联系至关重要。推荐的做法是在试用开始后一天联系他们，以解答他们可能有的任何问题。在试用结束前联系也很重要，以便你的销售团队能有效地引导他们成为付费客户。

在第 2 章中，我们探讨了使用你的 PBO 来实施自动化流程的知识。这在设计你的试用流程时特别有用。一个关键的考虑因素是试用期的持续时间。默认情况下设置为 30 天，但根据我的经验，14 天的试用期通常足以让客户对你的产品形成看法。此外，更短的试用期有助于保持更高效的销售周期。

在大多数组织中，安装过程通常由系统管理员处理。此人对采用或卸载你的应用的决定起着关键作用。因此，在设计你的安装流程时，考虑他们的体验至关重要。

设计你的应用安装过程使其直观，并确保说明清晰、易于理解，并适合各种技术技能水平。通过提供用户友好的指南、工具提示和演练，你可以帮助系统管理员，从而积极影响他们对你的应用的印象。
