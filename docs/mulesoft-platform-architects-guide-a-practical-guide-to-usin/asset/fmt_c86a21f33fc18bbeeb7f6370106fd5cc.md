
# MuleSoft 部署考量

## 网络连接选项

**表 18.2：MuleSoft 部署考量（网络连接）**

| 部署模式 | 网络连接选项 |
|----------|-------------|
| **CloudHub 1.0** | 支持 Anypoint Virtual Private Cloud，可通过 VPN IPSec 隧道、VPC 对等连接、AWS Direct Connect 或 Transit Gateway 连接到本地数据中心或任意云 |
| **CloudHub 2.0** | 支持私有空间，可通过 VPN IPSec 隧道和 Transit Gateway 连接到本地数据中心或任意云 |
| **完全客户托管** | 客户必须管理 Mule 应用程序与其他系统之间的网络连接。客户必须使用防火墙或实施 VPN 或任何其他连接选项来控制入站和出站流量，以连接到其他数据中心或私有云 |
| **混合部署** | 客户必须管理 Mule 应用程序与其他系统之间的网络连接。客户必须使用防火墙或实施 VPN 或任何其他连接选项来控制入站和出站流量，以连接到其他数据中心或私有云 |

## 业务连续性

**表 18.3：MuleSoft 部署考量（业务连续性）**

| 因素 | 完全云托管（控制平面和运行时平面在云中） | 完全客户托管（控制平面和运行时平面在本地或客户托管环境中） | 混合部署（控制平面在云中，运行时平面在本地） |
|------|------------------------------------------|---------------------------------------------------------------|-----------------------------------------------|
| **业务连续性** | • 高可用性、容错和智能修复等功能由 MuleSoft 提供和管理<br>• 应用程序可通过添加更多实例（工作节点或副本）或增加 vCore 或副本大小进行水平或垂直扩展<br>• Anypoint Platform 的可扩展性和高可用性由 MuleSoft 管理<br>• 客户无需管理运行 Mule 应用程序或代理的任何基础设施 | • 客户负责高可用性、容错、可扩展性等<br>• 客户负责管理运行 MuleSoft 应用程序的基础设施和网络，并实施 Anypoint PCE<br>• MuleSoft 仅提供用于运行 MuleSoft 应用程序的 Mule 运行时，以及在客户基础设施上设置 Anypoint PCE | • 客户负责管理运行 Mule 应用程序或代理的底层基础设施<br>• 客户需要确保节点或服务器的高可用性和可扩展性<br>• 应用程序可通过在 Runtime Fabric 上增加副本数量和副本大小轻松扩展，实现零停机时间<br>• Runtime Fabric 在应用程序级别提供智能修复和容错机制<br>• 在本地运行的 Mule Runtime 必须部署在集群或组中的多个节点上以确保高可用性。节点扩展只能通过向组和服务器添加额外节点来完成<br>• 客户负责管理底层基础设施和网络<br>• Anypoint Platform 将完全由 MuleSoft 管理。MuleSoft 将确保 Anypoint Platform 的可用性和可扩展性<br>• 支持应用程序级别的 Anypoint 集群以确保应用程序的可用性 |
