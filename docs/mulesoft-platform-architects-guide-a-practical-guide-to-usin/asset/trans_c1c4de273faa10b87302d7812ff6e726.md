
# 目标读者

- 具备集成与 API 知识的技术架构师，希望了解如何使用 MuleSoft Anypoint Platform 实施这些解决方案
- 想要转型为 MuleSoft 平台架构师、计划参加 MuleSoft 平台架构师认证考试并希望深入了解平台能力的 MuleSoft 高级开发人员
- 需要了解并定义 MuleSoft 托管选项、负责组织 Anypoint Platform 战略的基础设施架构师

# 本书内容概览

## 第 1 章：什么是 MuleSoft 平台？

本章将探讨 MuleSoft 与 Anypoint Platform。我们将识别各组件及其相互关系，描述平台在组织中的角色及其作为集成平台即服务 (iPaaS) 提供的高级能力。我们还将回顾传统集成方法的历史，以及 MuleSoft 如何满足现代集成方法的需求。

## 第 2 章：平台基础组件与底层架构

Anypoint Platform 由许多不同的服务、组件和能力组成。本章从高层面考察平台的主要组件、它们对集成的重要性、以及它们是否以及如何交互。本质上，本章开始探索平台的属性和特征，包括 Exchange、Runtime Manager、API Manager、Monitoring。本章还将指向后续章节，以便更详细地探索某些服务（如 CloudHub 2.0）并设计架构以最佳方式利用它们。

## 第 3 章：利用 Catalyst 与 MuleSoft KnowledgeHub

MuleSoft 为客户和合作伙伴提供了一个用于交付企业集成的框架和方法论。本章将描述该方法论，以及它如何利用跨众多 MuleSoft 项目和部署收集的工件、模板和示例库，将业务成果与技术及组织赋能相结合。

## 第 4 章：应用网络简介

通过 API 主导连接生成的结构是一个节点和应用程序的网络。本章将讨论应用网络的逻辑概念、物理表现、优势与挑战。本章将展示设计应用网络不仅能够创建可组合的企业，还会影响不同的平台部署方法。

## 第 5 章：使用加速器提速

MuleSoft 开发并通过 Anypoint Exchange 提供了 8 个加速器。本章将介绍这些加速器如何在 API 生命周期的各个阶段节省时间。读者将了解每个加速器中的构建块如何被使用和定制，以及包含了哪些不同的资产、模式、映射和端点。通过一个零售音乐店的用例，读者将演练设置和定制零售加速器的过程。

## 第 6 章：将期望的业务成果与功能需求对齐

充分利用 MuleSoft 平台的关键步骤是理解期望的业务成果，并将这些成果转化为功能需求。本章探讨功能需求如何与平台能力对齐。读者将看到这些功能需求如何影响架构决策和设计模式，如数据模型、粒度、并发和 HTTP 方法。本章将包括使用有界上下文数据模型与企业数据模型、使用带轮询和回调的异步 API 的示例。

## 第 7 章：微服务、应用网络与 API 主导设计

MuleSoft Platform 非常灵活，能够适应多种架构设计方法。本章将探讨流行的架构设计方法，以及它们部署到（或由）Anypoint Platform 管理时的样子。本章还将比较和对比这些架构方法，分析各自的优缺点，并提出设计解决方案的最佳实践。

## 第 8 章：非功能性需求对架构设计的影响

每位架构师都必须管理一组非功能性需求。这些需求描述了解决方案的技术约束，并记录了解决方案应如何表现。期望什么样的性能？可用性如何？灾难发生时会怎样？谁可以访问以及何时访问？安全性是否关键？需要什么样的加密？读者将在本章中看到这些问题的答案如何影响架构设计，以及设计应如何使用 MuleSoft Platform。

## 第 9 章：使用 Anypoint iPaaS (CloudHub) 实现无忧部署

本章将介绍使用 MuleSoft CloudHub 的部署方法。本章将探讨两种云 iPaaS 环境的差异与相似之处。本章还将探讨将解决方案部署到 Anypoint CloudHub 产品的不同方式，以及每种方法的优缺点。同时也将审视设计和架构方法的许可影响。

## 第 10 章：使用 Anypoint iPaaS (CloudHub 2.0) 实现无忧部署

本章将介绍使用 MuleSoft CloudHub 2.0 的部署方法。本章将探讨两种云 iPaaS 环境的差异与相似之处。本章还将探讨将解决方案部署到 Anypoint CloudHub 2.0 产品的不同方式，以及每种方法的优缺点。同时也将审视设计和架构方法的许可影响。

## 第 11 章：使用 Runtime Fabric 容器化运行时平面

本章将介绍 Anypoint Runtime Fabric (RTF)。本章将探讨使用 EKS 和 AKS 等行业标准进行容器化的基本概念。然后将探讨 RTF 如何与这些容器概念和平台对齐。本章还将考察 MuleSoft 通过 RTF 支持的不同方法，包括自管理容器和 Anypoint 管理容器。

## 第 12 章：部署到自己的数据中心

作为混合集成平台即服务，MuleSoft 可以在任何地方运行，包括在企业自己的数据中心、自己的硬件上。本章将探讨如何设置服务器以运行 MuleSoft 引擎，以及如何将其连接到控制面以便进行管理。本章还将简要介绍 Private Cloud Edition (PCE)，以及它如何允许组织在自己的开发中心内，从自己的硬件和服务器上运行控制平面和运行时平面。

## 第 13 章：政府云与 EU 控制平面：特殊考量

本章将展示使用政府云以及 EU 控制平面时的一些重要差异。本章将简要介绍 FedRAMP 合规性。读者将了解政府云部署在一个特殊的 AWS 区域中，该区域符合 FedRAMP 要求。
