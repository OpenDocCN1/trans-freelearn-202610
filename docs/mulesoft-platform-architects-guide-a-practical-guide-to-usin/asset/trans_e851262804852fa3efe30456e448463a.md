

*   始终为白天流量高的应用程序部署夜间批处理作业。这样，应用程序可以在白天获得额外的 CPU，而夜间批处理作业可以在夜间获得额外的 CPU。
*   为了优化未分配 CPU 的利用面，请将应用程序的多个副本分布在工作节点之间。

无论您使用何种策略，建议都要进行性能测试，并验证已分配给应用程序的资源。与分配较少 `vCores` 的应用程序相比，分配了更多 `vCores` 的应用程序部署所需时间更短。

## 总结

在本章中，我们涵盖了非功能性需求（NFR），包括灾难恢复 (DR)、容错、高可用性以及 `vCores` 的分配与优化。通过实施非功能性需求来确保业务连续性，对于 API 实施至关重要。

应用程序性能的基础是应用程序规模调整。如果分配的内存或 CPU 少于应用程序所需，会导致应用程序性能低下。

## MCPA – Level 1 认证

MCPA – Level 1 认证验证架构师具备构建用于运行 MuleSoft 应用程序网络的稳健且安全平台的知识和技能。

它还确保架构师能够执行以下活动：

*   根据组织需求选择合适的平台，并确保组织的合规性、安全性和策略
*   为创建 API 标准、安全最佳实践、可复用组件、模板和加速器提供指导
*   启用稳健的平台应用程序监控和警报机制

## 考试形式

考试语言为英语。这是一场在线闭卷考试，意味着您不能携带任何笔记或书籍，且有监考，这意味着特殊软件将在考试期间监控您的电脑屏幕和操作行为。

考试时长为 120 分钟，共有 60 道多项选择题。要通过考试，您需要至少获得 70% 的分数，即至少答对 42 道题。没有扣分机制，意味着答错题不会扣分。

## 有效期

认证自通过之日起两年内有效。您可以尝试考试五次，每次尝试之间需间隔 24 小时。五次尝试均失败后，您需要重新购买并注册认证。

## MCPA – Level 1 维护考试

为了延长认证的有效期，您可以参加 MCPA – Level 1 维护考试。该考试时长为 45 分钟，共有 25 道多项选择题。您需要至少获得 70% 的分数才能通过。同样没有扣分机制。您可以尝试该考试两次，每次尝试之间需间隔 24 小时。

## 如何准备 MCPA – Level 1

备考的最佳方式是积累搭建和构建 MuleSoft 平台的经验。考试中的大多数问题都是基于场景的，因此实践经验对通过考试至关重要。

参加讲师指导的培训，例如 *Anypoint Platform Architecture: Application Networks*（Anypoint 平台架构：应用程序网络），这是由 MuleSoft 官方提供的。该培训包含两次免费的 MCPA – Level 1 考试机会。

阅读本书也将帮助您备考。它探讨了 Anypoint Platform 提供的架构和功能，并涵盖了 MuleSoft 支持的托管选项，如 CloudHub、CloudHub 2.0、Runtime Fabric Manager 和本地部署的 Mule Runtime。读完本书后，您将掌握 MuleSoft 平台架构和组件。

MuleSoft 提供了格式与真实考试相似的模拟考试。题目风格相同，难度级别相近。您可以多次尝试模拟考试，以在真实考试前建立信心。

## 为什么要参加 MCPA – Level 1 考试？

该认证将验证您在 MuleSoft 平台方面的技能和知识。

其证书将使您在市场上脱颖而出，使您处于比他人更高的位置，并且是业内公认的认证之一。

## 谁应该参加 MCPA – Level 1 考试？

以下是该考试的理想候选人：

*   **高级开发人员**，最好拥有 MuleSoft 认证开发人员 – Level 1 认证，对 MuleSoft 有深刻理解，并希望通过以优化、可持续、可扩展和可复用的方式组合集成解决方案，获得开发应用程序网络架构的专业知识
*   **技术架构师**，具备集成和 API 知识，并希望了解如何使用 MuleSoft Anypoint Platform 实施这些解决方案
*   **MuleSoft 高级开发人员**，希望担任 MuleSoft 平台架构师角色，并希望深入了解平台功能
*   **基础设施架构师**，需要了解并定义 MuleSoft 托管选项，并负责其组织的 Anypoint Platform 战略

## 考试涵盖哪些主题？

MCPA 是架构师最负盛名的考试之一。它验证架构师对 MuleSoft 平台的技能和深入知识。以下是考试所需理解的关键主题列表：

*   **CloudHub 1.0 的架构设计与实施：**
    *   设置 Anypoint Virtual Private Cloud、Anypoint 专用负载均衡器，以及网络连接选项，如 Anypoint Virtual Private Network、VPC 对等连接、AWS Direct Connect 和 AWS Transit Gateway
    *   应用程序部署到 CloudHub 以及选择合适的 Worker 数量和 Worker 规格
    *   非功能性需求，如可扩展性、高可用性和容错性
    *   静态 IP 地址和共享负载均衡器的概念
*   **CloudHub 2.0 的架构设计与实施：**
    *   设置私有空间和网络连接选项，如 Anypoint Virtual Private Network 和 AWS Transit Gateway
    *   入口负载均衡器、私有和公共端点，以及入站和出站防火墙规则
    *   理解共享空间
    *   非功能性需求，如可扩展性、高可用性和容错性
    *   应用程序部署选项
*   **客户托管 Mule Runtime 的架构设计与实施：**
    *   在本地设置 Mule Runtime
    *   Anypoint 集群、服务器组和 HTTP 负载均衡器
    *   Anypoint Platform **Private Cloud Edition (PCE)**
    *   可扩展性、容错性、灾难恢复和高可用性
    *   应用程序部署选项
*   **Runtime Fabric Manager 的架构设计与实施：**
    *   在自管理的 Kubernetes 和裸金属服务器/虚拟机上设置 Runtime Fabric Manager
    *   `CPU bursting`（CPU 突发）的概念
    *   副本、副本规格和副本集群
    *   应用程序部署选项
    *   高可用性、容错性和可扩展性
*   **启用 Anypoint Monitoring：**
    *   Anypoint Monitoring 指标、自定义仪表板、报表等
