# 故障转移处理

在发生 Azure 数据中心中断的情况下，Cosmos DB 会自动触发受影响区域中所有 Cosmos DB 数据库的故障转移。

支持两种类型的故障转移处理：

1. 自动故障转移处理
2. 手动故障转移处理

让我们简要了解一下它们各自的情况。

## 自动故障转移

如果任何读取区域发生故障，Cosmos DB 会自动将该读取区域与写入区域断开连接，并将其所有流量转移到用户提供的首选区域列表。

如果用户未提供任何区域列表，则流量将被转移到主写入区域以进行进一步处理。

一旦读取区域恢复在线，流量将自动转移回该区域。所有这些都无需更改应用程序中的一行代码。

如果写入区域发生故障，则使用共识协议，另一个读取区域将被提升为写入区域。你也可以指定在发生故障时哪个读取区域应成为写入区域。

## 手动故障转移

如果你想将当前的写入区域更改为另一个读取区域，则可以使用手动故障转移功能来实现。你可以将任意选择的读取区域升级为写入区域并转移写入流量。这也确保了绝无数据丢失。

## Cosmos DB 数据模型

Cosmos DB 数据模型基于 `Atom record sequence` (`ARS`) 数据模型。`ARS` 旨在支持多种数据模型，例如基于列的、键值的、基于图的和基于文档的。你将在下一节详细了解 `ARS`。

在撰写本书时，Cosmos DB 支持以下数据模型：

* DocumentDB
* MongoDB
* Tables
* Graph
* Cassandra

Microsoft Azure 团队也在致力于其他数据模型，例如基于列的模型；它们很快就会发布！

DocumentDB 是微软自有的基于文档的数据库，也称为 NoSQL 数据库。DocumentDB 为无模式的基于文档的记录提供 SQL 查询功能。Cosmos DB 提供多种语言的 API 和 SDK，以将 DocumentDB 与你的应用集成！你将在后续章节了解相关内容。
