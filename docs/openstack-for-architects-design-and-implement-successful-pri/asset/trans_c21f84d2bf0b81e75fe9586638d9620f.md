

## 容器的影响

在过去几年里，Linux 容器席卷了技术世界，并从两个不同的方面影响了 OpenStack。首先，OpenStack 现在被视为部署容器化平台即服务技术（如 Kubernetes 和 Cloud Foundry）最灵活的基础设施之一。其次，OpenStack 现在越来越多地作为一组容器化服务进行部署。围绕 OpenStack 中容器的这两种用例，又涌现出许多 Big Tent 项目。

Magnum 是一个流行的项目，可自动化容器编排环境的配置。Magnum 使用 Nova 计算服务在 OpenStack 租户内部配置这些环境，其方式与 Trove 和 Sahara 相同。自 OpenStack 的 Newton 版本起，Magnum 支持 Docker Swarm、Kubernetes 和 Apache Mesos 集群，并将其抽象为容器的“bays”。另一个专注于容器的流行项目是 Kuryr，它允许用户将 Neutron 网络从基础设施层桥接到应用层。

也许在 OpenStack 的管理和部署方面最大的新兴变化是使用容器来部署 OpenStack 服务。这项工作由 Kolla 项目开创，该项目使用 Ansible 和 Docker 来部署和管理 OpenStack 服务。此后该做法已扩展到其他项目——Fuel 安装程序目前正转向基于 Docker 的部署策略，而 OpenStack-Ansible 项目（OSA）则使用 LXC 容器来部署 OpenStack 服务。随着这些努力获得共识，组织应评估容器化部署方法是否适合自己。

## 制定路线图

参与这样一个快速变化的项目是令人兴奋的。这种兴奋应被希望获得应用开发团队采用的云架构师所利用。建立开发者社区兴趣的一种方式是不断扩展私有云中可供他们使用的服务数量。如前所述，将 Trove 或 Designate 等服务的 capabilities 添加到云中，可简化开发人员和运维人员的工作。将开发团队纳入新功能早期采用者也是建立信任和信心的好方法。

## 引入新功能

能够逐步向 OpenStack 部署中添加新功能的前提是拥有可推进功能的一组测试环境。云工程团队应拥有一个可用于开发和测试新功能的私有环境，以及另一个可让最终用户在功能推广到生产云环境之前进行测试的环境。拥有多个环境还能让新功能充分“烘焙”，从而使云运维人员能够看到新功能对日志、性能和其他方面的影响。仪器化也可以在较低环境中开发和测试。

新功能或 capabilities 应逐步引入平台。在规划阶段，应定义 capabilities 的用例并编写测试用例。这些新功能和 capabilities 也应以与代码相同的方式进行测试和部署；首先在测试环境中，然后进入生产环境。随着功能部署到较低环境，文档应得到更新，并且 capabilities 的测试用例应添加到监控方案中。测试这些新 capabilities 的一种简单方法是编写一个练习它们的示例 Heat 编排模板。例如，将数据库的配置添加到已由 Heat 部署的现有应用栈中。然后该模板也可以作为服务的文档提供给应用团队。

## 发布新版本

OpenStack 最受讨论和批评的方面之一一直是主要版本升级流程。好的一面是，它也是项目中最详尽记录和测试的方面之一。OpenStack 的每个主要组件都提供在版本之间的升级路径，并且大多数现在都支持滚动升级。已做了大量工作来解耦各种服务的 API 版本，以确保服务可以一次一个地更新而不会停机。事实是，升级一个运行中的私有云是困难的。私有云用户期望其工作负载持续可用。因此，我们合作过的许多 OpenStack 采用者都不愿意在生产环境中更新其云。

虽然部署一个 OpenStack 版本然后运行几年是完全可能的（例如 Red Hat 等商业厂商为给定版本的 OpenStack 提供长达三年的支持），但我们绝对不推荐这样做。部署了 Icehouse 版本的 OpenStack 并运行了几年的组织最终将为 Newton 版本重新设计大部分配置管理和部署流程。这项工作需要大量时间和精力。逐步进行版本升级或每年部署一个新版本的组织在新版本发布时需要管理的变更量会小得多。

增量变更对开发者社区的影响也更小。如前所述，不断改进和更新你的基础设施即服务将保持社区的参与度，并消除每次发布新平台时都需要重新培训他们的需求。

## 总结

在本书中，我们介绍了作为云架构师在 OpenStack 方面的新兴实践中的主要关注领域。我们向你展示了一些技术和建议，使你能够与公司利益相关者合作并提供架构领导力，以便为企业中的 OpenStack 创建整体设计。成功设计、部署和运营 OpenStack 云需要对计算、网络、存储和软件设计领域有广泛的知识。它还需要对公司战略使命、流程以及实施私有云的成功标准有深入的理解。成功的云架构师在设计 OpenStack 云时，会结合自己知识与深层技术领域的主题专家知识和实践。本书旨在为架构师提供一个框架，以便他们能够与企业其他部门协作，使用现代软件开发方法论创建成功的 OpenStack 部署。虽然本书为 OpenStack 架构提供了坚实的基础，但我们希望它能为你提供工具和信心，开始你自己的 OpenStack 架构设计之旅。
