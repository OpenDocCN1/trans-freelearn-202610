We are starting a Calculator process and calling it afterwards by using the start_link/2 and call/2 functions, both belonging to the GenServer module. To look at the actual message sent when we call the calculator process, let's create a dummy process that only echoes the message it receives to the stdout:

```
iex> defmodule Echo do
...> def echoes() do
...> receive do
...> message ->
...> IO.puts "Echo on #{inspect(self())}: #{inspect(message)}"
...> end
...> end
...> echoes()
...> end
...> end
```

```
{:module, Echo,
<<70, 79, 82, 49, 0, 0, 5, 148, 66, 69, 65, 77, 65, 116,
85, 56, 0, 0, 0, 145, 0, 0, 0, 16, 11, 69, 108, 105,
120, 105, 114, 46, 69, 99, 104, 111, 8, 95, 95, 105,
110, 102, 111, 95, 95, 9, 102, ...>>,
{:echoes, 0}}
```

```
iex> echo = Process.spawn(&Echo.echoes/0 , [])
#PID<0.467.0>
```

If we now use GenServer to send the echo process a synchronous message with call/2, we can see the structure of the message being sent. The message has the format {:"$gen_call", from, contents}, where the second element of the tuple is a {pid, reference} tuple identifying the sender and the message, and the last element is the contents we passed on the call. We got a timeout because GenServer.call/2 is synchronous and, as such, the caller expects a reply, respecting the GenServer protocol in the meantime. However, it got none:

```
iex> GenServer.call(echo, {:hello, :echo})
Echo on #PID<0.467.0>: {:"$gen_call", {#PID<0.448.0>,
#Reference<0.2270275367.1586495491.177847>}, {:hello, :echo}}

** (exit) exited in: GenServer.call(#PID<0.467.0>, {:hello, :echo}, 5000)
** (EXIT) time out
(elixir) lib/gen_server.ex:774: GenServer.call/3
```

We will now send an asynchronous request with GenServer.cast/2 so that we can observe its message structure. Compared to the previous synchronous message, it misses the second element of the tuple, identifying the sender and the message. This makes total sense, since the server handling the request doesn't need to reply to the message.
