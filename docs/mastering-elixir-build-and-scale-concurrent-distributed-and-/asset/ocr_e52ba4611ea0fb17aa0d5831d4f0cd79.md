After compiling the required files, we demonstrate the regular usage of this `CacheSupervisor`. Then, we let the timer expire, and we can see that the supervisor didn't restart the process. This happened because the restart strategy is `:transient`, and the process exited normally. Then we start a new process, by putting some content into the cache again. After that, we kill this newly created process, and immediately see a log message stating that `CacheWorker` has started. This time, since the exit reason was `:kill` (and not `:normal`) the supervisor intervened, starting a new process in the place of the crashed one. As we can observe from the example, we can then access the content for our `id`, even though our server process crashed.
