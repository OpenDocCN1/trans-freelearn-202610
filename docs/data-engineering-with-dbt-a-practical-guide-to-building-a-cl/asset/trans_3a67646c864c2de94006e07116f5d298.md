

编写本书的团队的一个关键目标是讨论数据工程和数据架构，同时展示 dbt 的工作原理，以及如何使用它来解决我们在构建数据平台时都面临的常见问题。

在处理数据几十年之后，我有自己的一套主观做法，这构成了实用数据平台的主体，这是我试图在简单性、效率（开发者和平台的效率）和通用性之间取得平衡的尝试。

通常，这些目标会相互冲突，有时我提出了不同的替代方案。这是因为最佳行动方案可能是主观的，或者取决于实际用例。

最后，我希望我已经让你对数据工程和 dbt 的工作原理有了深入的了解，并让你有能力进一步学习，并将我所展示的内容调整到你的实际需求中。

## 延伸阅读

Snowflake 和 dbt 是两款以光速发展的产品，几乎每季度都会推出新功能，因此我们的主要建议是熟悉它们的文档网站并加入它们的社区，这些是信息和支持的重要来源。

你可以在以下位置找到它们：

- dbt Cloud 文档：https://docs.getdbt.com/
- Snowflake 文档：https://docs.snowflake.com/

在静态媒体中捕捉这种演变是困难的，总会有一些重要的东西被排除在外，例如 Snowflake 中 SELECT 命令的 EXCLUDE（我们在它可用时就开始使用）或 dbt 中的指标（它们仍需成熟并得到支持才能正确使用）。
