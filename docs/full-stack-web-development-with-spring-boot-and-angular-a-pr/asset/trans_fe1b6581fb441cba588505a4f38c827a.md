只要将 frontend 文件夹的路径映射到 Frontend Maven Plugin 的 workingDirectory 属性和 Apache Maven AntRun Plugin 的 fileset 属性（后者允许你在 Maven 中运行 Ant 任务），你就可以随意命名 frontend 文件夹。

让我们使用两个 Maven 插件：frontend-maven-plugin 和 maven-antrun-plugin，这是我们下一节需要的。

## 使用 frontend-maven-plugin

在本节中，我们将使用 frontend-maven-plugin，它会在本地安装 npm 和 Node.js，还会在 frontend 文件夹中运行 npm build 命令，并复制 npm build 生成的构建文件。

那么，我们开始吧：

- 1. 打开你的 pom.xml 文件，将以下代码作为 Maven pom 文件中的一个构建插件插入：

```
<plugin>
    <groupId>com.github.eirslett</groupId>
    <artifactId>frontend-maven-plugin</artifactId>
    <version>1.12.1</version>
    <configuration>
        <workingDirectory>frontend</workingDirectory>
        <installDirectory>target</installDirectory>
    </configuration>
...
// See full code on https://github.com/PacktPublishing/Spring-Boot-and-Angular/tree/main/Chapter-16/superheroes
</plugin>
```

上述配置表明，在构建 Spring Boot 应用程序时，该插件会在 frontend 工作目录中安装 Node.js v16.17.0 和 npm CLI 8.19.1。它还会执行 npm install 命令，以下载 Angular 应用程序的所有依赖包。

在完成所有必要的安装后，该插件接下来会执行 npm run build 命令，该命令将创建 Angular 应用程序的生产构建。

- 2. 接下来，我们必须使用以下代码编辑 Angular 应用程序的 package.json 文件中的 npm build 脚本：

```
"build": "ng build --configuration production",
```

上述代码告诉 Angular，npm run build 用于生产构建。

3. 我们还必须编辑 Angular 的 environment 文件夹中的 environment.prod.ts 文件。将代码改为：

```
export const environment = {
  production: true,
  apiURL: "http://localhost:8080/api/v1",
  authURL: "http://localhost:8080"
};
```

apiURL 和 authURL 只是临时的。我们会在应用程序的实际部署中更改它们，并使用真实的 API URL 和 Auth URL 属性。我们需要添加上述代码，因为在开发中我们在应用里使用了 apiURL 和 authURL，但缺少生产环境的值。

当应用程序为生产环境构建时，Angular 应用将从 environment.prod.ts 中获取值，而不是使用 environment.ts 文件。

现在，让我们了解 maven-antrun-plugin，并再次配置我们的 pom 文件。

## 使用 maven-antrun-plugin

本节将在 Spring Boot 应用程序中使用 maven-antrun-plugin。打开你的 pom.xml 文件，将以下代码插入 build 块中的某个插件内，放在 frontend-maven-plugin 配置的下方：

```
<plugin>
  <artifactId>maven-antrun-plugin</artifactId>
  <executions>
    <execution>
      <phase>generate-resources</phase>
      <configuration>
        <target>
          <copy todir="${project.build.directory}/classes/public">
            <fileset dir="${project.basedir}/frontend/dist/superheroes"/>
          </copy>
        </target>
      </configuration>
      <goals>
        <goal>run</goal>
```

```
</goals>
</execution>
</executions>
</plugin>
```

这里，maven-antrun-plugin 的配置会在运行任务之前，将 "${project.basedir}/frontend/dist/superheroes" 路径中的文件和文件夹复制并粘贴到 todir="${project.build.directory}/classes/public" 路径中。这会将前端应用复制到 Spring Boot 的 JAR 文件的根文件夹中。

现在，让我们配置应用的 Spring MVC 配置。

## 实现 WebMvcConfigurer

在本节中，我们将通过添加配置文件，使 Spring Boot 应用程序成为 Angular 应用程序的宿主。为此，我们必须向 Spring Boot 应用程序的 config 目录中添加一个配置类，并将其命名为 MvcConfig。

创建 MvcConfig 类后，将 WebMvcConfigurer 接口添加到文件中，如下所示：

```
@Configuration
public class MvcConfig implements WebMvcConfigurer {
    @Override
    public void addResourceHandlers(ResourceHandlerRegistry registry) {
... //See full code on https://github.com/PacktPublishing/Spring-Boot-and-Angular/tree/main/Chapter-16/superheroes
    }
}
```

前面的代码也可以在本章的 GitHub 仓库中找到。

MvcConfig 类实现了 WebMvcConfigurer，并重写了 addResourceHandlers 方法。

将 "/**" 参数传入 addResourceHandler，如下所示：

```
addResourceHandler("/**")
```

这将使配置影响所有项目路由。这部分属于应用程序面向外部的 URI。

然后，将面向外部的 URI 路径映射到资源所在的目录，如下所示：

```
addResourceLocations("classpath:/public/")
```

最后，添加新的 ClassPathResource("/public/index.html")。这会将 Spring Boot 应用程序未处理的请求重定向到 Angular 应用程序或前端应用程序。

我们很快就要将两个应用程序打包成一个了。下一节我们将学习如何做到这一点。

## 打包 Spring Boot

在本节中，我们将打包 Spring Boot 应用程序和 Angular 应用程序。其思路是将两个应用程序合并，为你提供一个可部署的单一 JAR 文件。让我们学习如何做到这一点。

在完成所有配置之后，现在只需按顺序运行以下 Maven 命令即可：

```
mvn clean
mvn package
```

mvn clean 命令通过删除 target 目录来清理 Maven 项目，而 mvn package 命令则构建 Maven 项目并创建可执行的 JAR 文件。

这两个 Maven 命令足以创建一个包含 Spring Boot 和 Angular 包的可执行 JAR 文件；参见图 16.2：
