

## 自动注册元数据

当 Zabbix agent 连接到服务器时，它会发送其主机名。但它还可能向服务器发送一些自定义字符串。发送的内容由 agent 守护进程配置文件中的一个配置参数 `HostMetadata` 控制。这可用于定义主机类型：数据库或应用。或者它可以列出主机上运行的各个服务。由于我们可以在自动注册动作中匹配接收到的元数据，因此我们可以列出所有正在运行的服务，以管道分隔。在动作条件中，我们可以查找 `|MySQL|` 并将新主机链接到适当的模板。

> 元数据限制为 255 个字符。

直接在配置文件中控制元数据参数是可能的，但可能很麻烦。有一种方法可以让 agent 动态获取该值。不是使用 `HostMetadata`，我们将定义 `HostMetadataItem` 并指定一个 item 键。我们可以使用内置的 item 键之一，或配置用户参数并运行脚本。请注意，我们也可以在此处使用 `system.run` item 键，并在 `HostMetadataItem` 参数中直接指定任何命令，即使未启用远程命令也是如此——因为它不是从网络到达的，所以不被视为远程命令。例如，以下是一个有效的 `HostMetadataItem` 行：

```
HostMetadataItem=system.run[rpm -qa mariadb]
```

如果在基于 RPM 的系统上存在 `mariadb` 包，agent 将在元数据中发送它；我们可以在动作条件中匹配它并将该主机链接到 MariaDB/MySQL 模板。

此参数还有另一个用例。你可能已经注意到，只要存在自动注册动作，某人就可能恶意或意外地创建大量主机，从而可能极大地减慢 Zabbix 的速度。没有秘密挑战机制来防止这种情况，但我们可以在这里使用元数据。动作条件可以检查元数据中是否包含特定的秘密字符串——如果存在，则创建主机。如果不存在，则发送电子邮件供某人调查。请注意，密钥不能太长，因为 255 个字符的长度限制仍然适用。

## 摘要

在本章中，我们了解了 Zabbix 中允许自动创建和维护配置的几个功能：

- 低级发现或 LLD
- 网络发现
- 活动 agent 自动注册

LLD 允许使用 Zabbix agents 发现实体——它内置支持网络接口、文件系统和 CPU。我们讨论了如何使用用户宏上下文支持按发现的实体自定义阈值和其他值。Zabbix 还可以发现 SNMP 表，如网络接口，但它并不限于此——任何 SNMP 表都可以被发现。我们还查看了创建自定义发现，包括 MySQL 数据库发现。

LLD 提供了一种通过正则表达式过滤结果的方法，我们检查了全局正则表达式如何使这里以及其他地方（如日志监控）变得更容易。

之后，我们探索了网络发现，它涉及扫描地址范围并自动添加主机，可能将它们链接到适当的模板并添加到主机组。

在另一个方向上，有活动 agent 自动注册，其中活动 agent 可以加入，服务器会自动开始监控它们。此功能的元数据支持允许对要链接哪些模板或主机应属于哪些主机组进行相当精细的规则。我们注意到，如果不使用，agent 上的活动检查应被禁用；否则会给整个 Zabbix 基础设施带来不必要的负载。

在下一章中，我们将探索内置的 Web 监控功能。它允许我们定义由步骤组成的场景。步骤检查页面并可能查找特定的 HTTP 响应代码或返回页面中的字符串。我们还将尝试登录应用程序并从一个页面提取数据然后传递到另一个页面。

## 监控 Web 页面

在本章中，我们将查看 Zabbix 内置监控 Web 页面的功能。我们将检查 Web 页面的不同部分并监控其故障，以及监控下载速度和响应时间。我们还将了解 Zabbix 如何从某个页面提取值然后重用该值。除了更高级的场景和基于步骤的解决方案外，我们还将探索可用于 Zabbix agent 的与 Web 监控相关的 item。

### 监控简单的 Web 页面

互联网在现代生活的方方面面都很重要：社交、商业、娱乐，以及其他一切都通过网络进行。鉴于投入到这个网络的资源，许多人负责维护网站——无论是内部托管的站点还是委托给外部托管提供商的站点，我们至少想知道其基本健康状况。我们可以从在真实网站上监控一些简单的事情开始。

### 创建 Web 监控场景

Zabbix 中的 Web 监控通过场景进行，而场景又包含步骤。每个步骤由一个 URL 和对其进行的检查组成。这允许检查单个页面并验证多个页面按顺序正常工作。Zabbix 中的 Web 监控场景仍然分配给主机，并且也可以进行模板化。为了了解其工作原理，我们可以监控开源地图项目 OpenStreetMap 的几个页面。

虽然我们可以将 Web 监控场景附加到任何现有主机，但这并不能正确反映场景监控的内容，因此我们将创建一个专用主机。由于只有一个 OpenStreetMap 网站，我们不会为此使用模板。导航到 Configuration | Hosts，点击 Create host，并填写以下值：

- **Name:** OpenStreetMap
- **Groups:** 如果 In Groups 框中有任何组，请标记它们并点击 ▶ 按钮
- **New group:** Web pages

我们不必在此更改任何其他值，因此点击底部的 Add 按钮。现在我们准备创建场景本身——在主机列表中，点击 OpenStreetMap 旁边的 Web 并点击 Create web scenario。在场景属性中，输入以下值：

- **Name:** Main page
- **New application:** Webpage
- **Update interval:** 300

现在进入各个步骤。Web 监控的步骤是对 Web 服务器执行的实际查询；每个步骤都有一个 URL。切换到 Steps 选项卡并在 Steps 部分点击 Add。在新弹出窗口中填写以下值：

- **Name:** First page
- **URL:** http://www.openstreetmap.org/
- **Required string:** Enter OpenStreetMap is a map of the world, created by people like you. 此字段将在返回的页面中搜索特定字符串，如果找不到该字符串，此步骤将失败。我们可以在此处使用 POSIX 正则表达式，但不能使用第 12 章《Automating Configuration》中讨论的全局正则表达式。
- **Required status codes:** Enter 200。在此处，可以指定可接受的 HTTP 返回代码，以逗号分隔。同样，如果返回代码不匹配，此步骤将被视为失败。状态代码 200 表示 OK。

> required string 仅针对页面源进行检查，而不是针对 HTTP 标头。场景仅下载步骤 URL 指向的内容；Web 页面的其他元素永远不会被下载。
