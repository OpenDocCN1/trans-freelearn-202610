我们目前已停止 SMTP 服务器，以验证 **1 => 启动** 和 **0 => 关闭** 这两个映射是否都有效——正如我们所见，它们是有效的。值映射对于像代码值一样工作的返回数据非常有用——例如服务状态、硬件状态（如电池），以及其他类似的监控数据。我们之前在值映射配置界面中看到了一些预定义的示例，你可以根据自己的需求随意修改或创建新的映射。

值映射可用于整数、小数值（浮点数）和字符串。字符串的一个用例可以是备份软件可能返回的不同备份级别的映射：

- I => 增量备份
- D => 差异备份
- F => 完整备份

![](img/f5313a804532fabacc8d07cc8607eeba_133_0.png)

当你只需要记住一个只有两种可能状态的监控特征时，值映射似乎不太有用；但当存在许多不同的可能状态和许多可能的映射时，它就变得非常有用，这样在大多数情况下，你都能快速了解每个数值的含义，并且你随时可以为自定义开发的解决方案创建自己的映射。

## 单位

我们之前为一些监控项配置了单位，使用了诸如 B 或 ms 这样的值。虽然在监控部分很容易看到效果，但在不同单位的处理上存在一些细微差别。

单位是一个自由文本字段。你可以在这里输入任何内容，但某些单位在数据显示时会改变其行为：

- **B/Bps**：默认情况下，当应用 **K、M、G、T** 等单位前缀时，Zabbix 会使用 1,000 的倍数。如果单位设置为 **B** 或 **Bps**，所使用的倍数将变为 1,024
- **s**：以秒为单位的传入值将被转换为人类可读的格式
- **uptime**：以秒为单位的传入值将被转换为人类可读的格式
- **unixtime**：传入的 Unix 时间戳将被转换为人类可读的格式

有趣的是，对于我们的 ICMP ping 监控项，我们没有使用这些单位中的任何一个；我们使用了 ms。原因是，在某些极小往返时间的情况下，以秒为单位的值可能太小，无法在 Zabbix 数据库模式中正确存储。通过在监控项配置中应用 1,000 的倍数，我们将传入的秒值转换为毫秒，这样就不会超出数据库模式的限制。一个缺点是，如果 ping 花费很长时间，该值将不会以秒显示——我们将不得不从毫秒值中推算出来。

> 单位不影响存储的值，只影响显示的内容。我们可以放心地来回更改它们，直到它们正确为止。

## 自定义间隔

我们刚才简要讨论的另一个监控项属性是自定义间隔。大多数监控项类型的间隔都是可配置的，这决定了监控项值的采集频率。但如果我们想根据星期几或一天中的时间段来更改这个间隔呢？这正是自定义间隔让我们能够做到的。自定义间隔有两种模式：

- 灵活间隔
- 自定义调度

## 灵活间隔

灵活间隔在指定时间内覆盖正常间隔。例如，一个监控项可以每 60 秒采集一次值，但该监控项在周末可能并不重要。在这种情况下，可以添加一个灵活间隔，间隔为 3600，时间规格为 6-7, 00:00-24:00。在周六和周日，该监控项将每小时只检查一次：

![](img/f5313a804532fabacc8d07cc8607eeba_135_0.png)

> 单个监控项最多可添加七个灵活间隔。

天数用数字 1-7 表示，并使用 HH:MM-HH:MM 的 24 小时制表示法。

> 如果你想知道的话，这里每周从星期一开始。

也可以将正常间隔设置为 0，并配置灵活间隔。在这种情况下，监控项将只在灵活间隔中指定的时间进行检查。此功能可用于仅在特定工作日检查某个监控项，甚至模拟一个粗略的调度器。如果一个监控项的正常间隔为 0，灵活间隔为 60 秒，时间规格为 1,09:00-09:01，那么该监控项将在周一早上 9 点被检查。

> **重叠的灵活间隔**
> 
> 如果两个具有不同值的灵活间隔重叠，则在重叠期间使用最小的值。例如，如果向同一监控项添加了时间周期分别为 1-5,00-24:00 和 5-6,12:00-24:00 的灵活间隔，那么在周五的 12:00 到 24:00 期间，将使用间隔值最小的那一个。

多个自定义间隔也可以用分号分隔指定——wd1-5/2 和 wd1; wd3; wd5 都会在周一、周三和周五开始时轮询一个监控项。

## 复制监控项

再看同一个概览界面，有了针对之前晦涩数字值提供的文本提示，数据似乎更容易理解了，但显示上仍有一些不尽如人意的地方。请注意 **另一台主机** 的 **CPU 负载** 监控项以及 **测试主机** 的所有其他值所显示的破折号。我们没有在两台主机上创建对应的监控项，而监控项数据显示在这里，这意味着应该为每台主机创建缺失的监控项以收集数据。但重新创建所有监控项会非常无聊。幸运的是，这个问题有一个简单直接的解决方案。

前往 **配置 | 主机**，点击 **测试主机** 旁边的 **监控项**。我们只为该主机配置了一个监控项，因此勾选该监控项旁边的复选框。让我们再次查看列表底部的可用按钮：

![](img/f5313a804532fabacc8d07cc8607eeba_137_0.png)

这次，我们不想更新选中的监控项，而是将它们复制到另一台主机，所以点击 **复制** 按钮。我们想将这些监控项复制到特定主机，因此在 **目标类型** 下拉框中选择 **主机**，在 **组** 下拉框中选择 **Linux 服务器**，这样我们应该会得到一个简短的主机列表。我们正在从 **测试主机** 复制到 **另一台主机**；勾选 **另一台主机** 条目旁边的复选框，然后点击 **复制** 按钮：

![](img/f5313a804532fabacc8d07cc8607eeba_137_1.png)
