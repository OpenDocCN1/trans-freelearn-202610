## 第 2 章 编译

Angular 的核心是一个复杂的编译器，它接收一个 `NgModule` 类型并生成一个 `NgModuleFactory`。

![](img/79f67e6cb2f5bd357461768fccf131e0_5_0.png)

`NgModule` 中声明了组件。在创建模块工厂时，编译器会获取模块中每个组件的模板，并利用已声明组件和管道的信息，生成一个组件工厂。组件工厂是一个 JavaScript 类，框架可以使用它来实例化组件。

![](img/79f67e6cb2f5bd357461768fccf131e0_6_0.png)

```
NgModule

Component/Directive Types

Pipe Types

...

Template

Component Factory
```

### 它是如何实现的？

为什么我们之前没有在 Angular 1 中做到这一点？为了让 AOT 工作，应用程序必须清晰地区分静态数据和动态数据。而且编译器的构建方式必须使其只依赖静态数据。在设计并构建 Angular 时，我们投入了大量精力来实现这一点。而类和装饰器这些新版本 JavaScript 和 TypeScript 支持的原始特性，让这一切变得容易得多。

为了在实践中看到这种分离是如何工作的，让我们看下面的例子。在这里，装饰器中的信息是静态已知的。Angular 知道 `talk` 组件的选择器和模板。它也知道该组件有一个名为 `talk` 的输入和一个名为 `rate` 的输出。但框架不知道构造函数或 `onRate` 函数做了什么。

```typescript
@Component({
  selector: 'talk-cmp',
  template: `
    {{talk.title}} {{talk.speaker}}
    Rating: {{ talk.rating | formatRating }}
    <watch-button [talk]="talk"></watch-button>
    <rate-button [talk]="talk" (click)="onRate()"></rate-button>
  `
})
class TalkCmp {
  @Input() talk: Talk;
  @Output()...
}
```

### 权衡取舍

由于 AOT 优势显著，我们建议在生产环境使用它。但与其他任何事情一样，也存在权衡取舍。为了让 Angular 能够提前编译你的应用程序，元数据必须是静态可分析的。例如，以下代码在 AOT 模式下将无法工作：

```typescript
@Component({
  selector: 'talk-cmp',
  template: () => window.hide ? 'hidden' :
    '{{talk.title}} {{talk.speaker}}
    Rating: {{ talk.rating | formatRating }}
    <watch-button [talk]="talk"></watch-button>
    <rate-button [talk]="talk" (click)="onRate()"></rate-button>'
})
class TalkCmp {
  //...
}
```

`window.hide` 属性不会被定义。因此编译将无法指出错误。为了让编译器变得更智能，我们做了大量工作，使其能够理解你在构建应用程序时使用的大多数日常模式。但某些东西永远不会奏效，比如前面的示例。

## 第 3 章 NgModules

### 提供者（Providers）

我将在第 5 章《*依赖注入*》中介绍提供者和依赖注入。这里我只想指出，NgModules 可以包含提供者。并且导入模块的提供者会从左到右与目标模块的提供者合并，也就是说，如果多个导入模块定义了同一个提供者，最后一个模块胜出。

```typescript
@NgModule({
  providers: [
    Repository
  ]
})
class TalksModule {}

@NgModule({
  imports: [TalksModule]
})
class AppModule {}
```

### 引导（Bootstrap）

要在 JIT 模式下引导 Angular 应用，你需要将一个模块传递给 `bootstrapModule`：

```typescript
import {platformBrowserDynamic} from '@angular/platform-browser';
import {AppModule} from './app';

platformBrowserDynamic().bootstrapModule(AppModule);
```

这会将 `AppModule` 编译成模块工厂，然后使用该工厂实例化模块。如果你使用 AOT，可能需要自己提供工厂：

```typescript
import {platformBrowser} from '@angular/platform-browser';
import {AppModuleNgFactory} from './app.ngfactory';

platformBrowser().bootstrapModuleFactory(AppModuleNgFactory);
```

我说“可能需要”，是因为 CLI 和 WebPack 插件会替你处理这件事。必要时，它们会将对 `bootstrapModule` 的调用替换为 `bootstrapModuleFactory`。

### 懒加载

正如我之前提到的，NgModules 不仅仅是编译单元，它们也是分发单元。这就是为什么我们引导 NgModule，而不是组件——我们不分发组件，我们分发模块。这也是为什么我们也懒加载 NgModules。

```typescript
import {NgModuleFactoryLoader, Injector} from '@angular/core';

class MyService {
    constructor(loader: NgModuleFactoryLoader, injector: Injector) {
        loader.load("mymodule").then((f: NgModuleFactory) => {
            const moduleRef = f.create(injector);
            moduleRef.injector; // module injector
            moduleRef.componentFactoryResolver; // all the component factories of the lazy-loaded module
        });
    }
}
```

当应用程序运行在 JIT 模式时，加载器会编译模块；而在 AOT 模式下则不会。`@angular/core` 自带的默认加载器使用 SystemJS，但与 Angular 中的大多数东西一样，你可以提供自己的加载器。

## 第 4 章 组件与指令

要构建一个 Angular 应用，你需要为每个 UI 元素、屏幕和路由定义一组组件。一个应用总是有根组件（通常只有一个），它包含所有其他组件。为了让事情更简单，在本书中我们假设应用只有一个根组件，因此我们的 Angular 应用将有一个组件树，可能看起来像这样：

![](img/79f67e6cb2f5bd357461768fccf131e0_20_0.png)

AppCmp 是根组件。FiltersCmp 组件具有 speaker 输入和 filter 按钮。TalksCmp 是你在底部看到的列表。TalkCmp 是该列表中的一项。为了理解 Angular 中组件的构成，让我们仔细看看 TalkCmp：

```typescript
@Component({
  selector: 'talk-cmp',
  template: `
    {{talk.title}}  {{talk.speaker}}
    {{talk.rating | formatRating }}
    <watch-button [talk]="talk"></watch-button>
    <rate-button [talk]="talk"></rate-button>
  `
})
class TalkCmp {
  @Input() talk: Talk;
  @Output() rate: EventEmitter;
  //...
}
```

### 输入和输出属性

一个组件有输入和输出属性，它们可以在组件装饰器中定义，也可以使用属性装饰器定义。

```typescript
class TalkCmp {
  @Input() talk: Talk;
  @Output() rate: EventEmitter;
  //...
}
```

数据通过输入属性流入组件。数据通过输出属性流出组件，因此得名：输入和输出。

![](img/79f67e6cb2f5bd357461768fccf131e0_22_0.png)

输入和输出属性是组件的公共 API。当你在应用中实例化组件时，会用到它们。

```html
<talk-cmp [talk]="someExpr" (rate)="onRate($event.rating)"></talk-cmp>
```

你可以通过方括号使用属性绑定来设置输入属性。可以通过圆括号使用事件绑定来订阅输出属性。
