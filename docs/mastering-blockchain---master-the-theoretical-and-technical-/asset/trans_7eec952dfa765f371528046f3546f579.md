

## 作为服务的区块链

随着云平台成熟度的不断提高，许多公司开始提供 **区块链即服务 (BaaS)**。最突出的例子是微软的 Azure，在其中以太坊区块链作为服务提供，以及 IBM 的 Bluemix 平台，提供 IBM BaaS。预计这一趋势在未来几年只会增长，将会有更多公司提供 BaaS。EgaaS（**电子政务即服务**）是另一个例子，它实际上是 BaaS，但为治理功能提供应用特定的区块链。该项目的目标是在没有文件流转和官僚开销的情况下组织和控制任何活动。

## 减少电力消耗的努力

从比特币的区块链中可以清楚地看出，工作量证明机制是非常低效的。当然，这种计算可以保护比特币网络，但这种计算没有其他益处，并且浪费了大量电能。为了减少这种浪费，现在更注重绿色选项，例如权益证明算法，它们不需要像比特币工作量证明算法那样庞大的资源。预计这一趋势将会增长，尤其是以太坊计划采用权益证明。

## 改进提案

两种主要的区块链技术，即比特币和以太坊，都具有在现有协议中提出改进的正式机制。这些被称为改进提案，BIPs 和 EIPs。这两种机制都允许来自世界各地的开发人员和技术爱好者参与，并帮助比特币和以太坊随着时间的推移发展成为更成熟、更安全的技术。在下面的章节中，将讨论两个区块链的著名改进提案。

## BIPs

在本节中，将讨论一些最新的 BIPs。

### BIP 152

该提案是对比特币网络引入紧凑区块的改进建议，以节省带宽。在当前状态下，比特币协议在带宽效率方面并不理想，该提案旨在通过允许节点之间中继紧凑区块来解决该问题。为了实施该提案，需要进行多项更改，例如新的数据结构和消息。目前，该提案处于草案状态。它可在 GitHub 上获取，网址为 https://github.com/bitcoin/bips/blob/master/bip-0152.mediawiki。

### BIP 151

该改进提案旨在引入点对点通信加密。该提案是在针对比特币协议的各种安全问题做出的，例如流量分析和操纵的可能性。该提案将有助于挫败通过源 IP 和比特币网络上的交易内容识别用户的企图。BIP 中提出了多个新消息以在参与节点之间请求和启用加密。它可在 https://github.com/bitcoin/bips/blob/master/bip-0151.mediawiki 获取。

### BIP 150

该提案提出了一种对等身份验证方法。这将允许解决中间人攻击，并提供保证，即对等方正在连接到合法节点。它可在 GitHub 上获取，网址为 https://github.com/bitcoin/bips/blob/master/bip-0150.mediawiki。

### BIP 147

该提案旨在解决虚拟栈元素可塑性问题。签名可塑性是一个已知问题，可以由任何中继节点通过简单地更改与交易关联的签名来执行。这是一个共识层级的改进提案，需要软分叉才能实施。BIP 147 在 GitHub 上有文档记录，网址为 https://github.com/bitcoin/bips/blob/master/bip-0147.mediawiki。

### BIP 146

该改进旨在解决签名编码可塑性问题。这需要软分叉才能实施。如果实施，这将解决与 ECDSA 签名编码机制中的根本限制相关的签名可塑性问题。这种限制是 ECDSA 的固有特性。其次，由于如果签名验证失败，验证脚本评估仍将继续并允许对签名设置任何值。本 BIP 是为了解决此问题而提出的提案。它记录在 https://github.com/bitcoin/bips/blob/master/bip-0146.mediawiki。

还有许多其他 BIPs 用于建议比特币协议的改进。在本节中，仅介绍了最新的五个提案。近年来，已针对比特币提出了近 90 项改进提案，这一过程仍在继续。

## EIPs

以太坊有自己的改进提案版本，称为 EIPs。以下是一些最近的 EIPs 的讨论。

### EIP 170

该改进提案旨在解决在预处理阶段或从磁盘读取代码时由于合约代码过大而导致燃气使用过度而可能出现的一定漏洞。建议将合约代码大小限制为 23,999 字节。关于该提案的进一步讨论导致了对该提案的进一步改进，并已被接受。然而，这尚未实施。

### EIP 150

该改进提案是在针对以太坊区块链的拒绝服务攻击做出的回应。它已作为硬分叉实施，自以太坊主网区块 2463000 起生效。该 EIP 解决了因交易垃圾邮件攻击而产生的问题，例如，反复调用 EXTCODESIZE 操作码，导致区块链验证过程变慢。该 EIP 是为了增加若干操作码的燃气成本，以阻止因这些操作码过度重复使用而导致的拒绝服务攻击。

### EIP 161

该提案旨在允许从以太坊区块链中删除空账户。这是在针对以太坊区块链的拒绝服务攻击的回应中制定的，攻击者创建了大量空账户。这是因为账户创建成本低。这称为状态 trie 清理，它将允许通过向账户发出 CALL 指令来删除空账户。

### EIP 160

该建议旨在提高 EXP 操作码成本。该改进提案的核心思想是使 EXP 操作的成本与操作的复杂性成比例。该提案有助于阻止因调用计算密集型操作而产生的拒绝服务攻击。

### EIP 155

该改进提案旨在消除在主以太坊区块链上重放来自不同链的交易的可能性。例如，如果在以太坊网络上进行交易，则可以在以太坊经典网络上重放；该 EIP 解决了此问题。此外，任何已在测试网络上进行过的交易都不应能够在主网络上重放。

上述所有改进都导致了硬分叉，并作为对最近以太坊拒绝服务攻击的回应而实施。改进提案是向以太坊区块链引入新增强功能和协议级错误修复的关键机制。已实施或提出的以太坊改进提案约有 11 项。所有这些都记录在 GitHub 上，网址为 https://github.com/ethereum/EIPs/。

## 其他挑战

除了上一章讨论的安全性和隐私之外，在区块链能够实现主流采用之前，还需要解决几个其他障碍。这些包括监管、政府控制、不成熟的技术、与现有系统的集成以及实施成本。

监管被认为是需要解决的最大挑战之一。核心问题是区块链，尤其是加密货币，未被任何政府承认为法定货币。即使在某些情况下，它在美国和德国被归类为货币，但它仍然远未被接受为正常货币。此外，区块链在当前状态下未被承认为可被金融机构使用的平台。没有任何金融监管机构将其接受为可被授权使用的平台。然而，世界各地的监管机构已采取各种举措来研究和提出监管。比特币在当前状态下完全不受监管，尽管政府已做出一些征税尝试。在英国，根据欧盟增值税指令，比特币交易免征增值税，但脱欧后这种情况可能会改变。然而，在某些情况下，资本利得税仍可能适用。

预计金融监管机构很快将对区块链技术，尤其是英国金融行为监管局最近宣布可能批准一些使用区块链的公司之后，提出一些监管尝试。

普遍担忧的是，区块链技术尚未真正准备好用于生产部署。尽管比特币区块链已发展成为一个坚实的区块链平台并在生产中使用，但它并不适用于每个场景。这在金融和医疗等敏感环境中尤其如此。然而，随着之前章节中讨论的大量努力正在进行以改进技术并解决任何技术限制，例如可扩展性和隐私，预计这种情况很快就会改变。安全也是另一个普遍担忧，已被许多研究人员强调，尤其适用于金融和医疗行业。欧洲联盟网络和信息安全局最近的一份报告强调了应解决的分布式账本特定问题。报告中强调的一些问题包括智能合约管理、密钥管理、反洗钱和反欺诈工具。报告中还强调了对监管、审计、控制和治理的需求。

与现有遗留系统的集成也是主要问题。目前尚不清楚区块链如何与现有金融系统集成。

采用的障碍或多或少与监管、安全和互操作性相关。可以通过多种方式与现有系统集成。
