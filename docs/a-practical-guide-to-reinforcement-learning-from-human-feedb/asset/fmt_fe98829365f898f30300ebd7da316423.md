
```python
def create_preference_pairs(prompt):
    model = ConstitutionalSL()
    # Generate response variants
    response_a = model.generate(prompt)
    response_b = model.generate(prompt)
   
    # AI Evaluation
    evaluation_prompt = f"""
    Which response better follows our constitution?
    Response A: {response_a}
    Response B: {response_b}
    """
    preferred_response = model.generate(evaluation_prompt)
    return {
        'prompt': prompt,
        'chosen': response_a if "A" in preferred_response else response_b,
        'rejected': response_b if "A" in preferred_response else response_a
    }
```

With the preference pair generation function here, the preference data generation is ready to be used for the RL stage, which we will see next.

## Reinforcement Learning Stage

In the RL stage, we first try to obtain a reward signal generator, which is usually a preference model (reward model). The preference data generated can be readily used for training a preference model. This can be done by either training classifier on constitutional-guided comparisons or using the Bradley-Terry model for preference probability estimation. The preference model class can be constructed so that it can be used for training a reward model. We will look at an example snippet showing the preference model using transformers and torch libraries and their methods. Here the `PreferenceModel` wraps a transformer (`base_model`), reusing its hidden states:

```python
import torch
from torch import nn
from transformers import AutoModelForCausalLM

class PreferenceModel(nn.Module):
    def __init__(self, base_model):
        super().__init__()
        self.transformer = base_model
        self.value_head = nn.Linear(base_model.config.hidden_size, 1)
       
    def forward(self, input_ids):
        hidden_states = self.transformer(input_ids).last_hidden_state
        pooled_output = hidden_states.mean(dim=1)  # Mean pooling
        return self.value_head(pooled_output)
```

A pretrained model from transformers library can be used for batch training or fine-tuning the preference model based on the preference dataset. A **pairwise ranking loss** based on the **Bradley-Terry model** is applied and mean loss across batch is calculated using the `-torch.log(torch.sigmoid(chosen_rewards - rejected_rewards)).mean()` implementation. The model learns to **increase the difference between chosen and rejected rewards**, pushing `chosen_rewards` higher than `rejected_rewards` and quantifies how much more rewarding the chosen response is compared to the rejected response. A sample training loop is shown in below snippet.

```python
def train_preference_model(dataset):
    model = PreferenceModel(AutoModelForCausalLM.from_pretrained("claude-sft"))
    optimizer = torch.optim.AdamW(model.parameters(), lr=1e-5)
   
    for batch in dataset:
        chosen_rewards = model(batch['chosen_input_ids'])
        rejected_rewards = model(batch['rejected_input_ids'])
        loss = -torch.log(torch.sigmoid(chosen_rewards - rejected_rewards)).mean()
       
        loss.backward()
        optimizer.step()
        optimizer.zero_grad()
```

Once the preference model is trained, it can be used for policy optimization, by implementing PPO, using the KL divergence penalty from Supervised Learning-CAI model. Reward shaping can be used to guide the learning process, making it easier for the AI model to learn and adhere to the constitutional principles. A dynamic weight adjustment is required when there is principle conflict. The RL training loop would use a policy model that will be tuned, preference model discussed, tokenizer and dataset. Note that all the RL training steps are similar to those we discussed earlier in Chapter 8, if we use `PPOTrainer` method from `TRL` library, with the exception of using the trained preference model for getting the `chosen_rewards`, which are subsequently normalized before stepping into the training.

```python
def rl_training_loop(policy_model, preference_model, tokenizer, dataset, num_epochs=10):
    ppo_config = PPOConfig(
        model_name=policy_model.name_or_path,
        learning_rate=1e-5,
        ...
    )
    ppo_trainer = PPOTrainer(
        config=ppo_config,
        model=policy_model,
        ref_model=None,
        tokenizer=tokenizer,
        dataset=dataset
    )
    for epoch in range(num_epochs):
       
        for batch in ppo_trainer.dataloader:
            prompts = batch["prompt"]
            inputs = tokenizer(prompts, return_tensors="pt", padding=True)
            input_ids = inputs["input_ids"].to(policy_model.device)
            response_ids = policy_model.generate(
                input_ids=input_ids,
                max_length=128,
                pad_token_id=tokenizer.eos_token_id
            )
            responses = [tokenizer.decode(ids, skip_special_tokens=True) for ids in response_ids]
           
            # Compute rewards using the custom preference model
            with torch.no_grad():
                chosen_rewards = preference_model(input_ids=response_ids).squeeze()
           
            # Normalize rewards (optional scaling to [-1, 1])
            rewards = (chosen_rewards - chosen_rewards.mean()) / (chosen_rewards.std() + 1e-8)
           
            # Perform PPO step
            stats = ppo_trainer.step(
                queries=prompts,
                responses=responses,
                scores=rewards.tolist()
            )
    policy_model.save_pretrained("ppo_trained_policy_model")
    tokenizer.save_pretrained("ppo_trained_policy_model")
```

Dynamic weight adjustment and reward shaping can be implemented on the base reward from preference model. An example snippet of constitutional reward shaping is shown below. Principle rewards and weights have to be designed and pre-assigned.

```python
def constitutional_reward_shaping(base_reward, principle_rewards, weights):
    total_reward = base_reward
    for principle, weight in weights.items():
        total_reward += weight * principle_rewards.get(principle, 0)
    return total_reward
```

In addition to reward shaping, KL divergence between the policy model and the supervised lesarning model with constitutional AI incorporated, can be computed and incorporated to ensure that the policy model does not deviate significantly from the trained supervised learning baseline, maintaining alignment with constitutional principles.

## Validation & Monitoring

A validation of responses with constitution as the validation layer, and real-time compliance checks can help improve validations and therefore decision making. Real-time principle compliance checks can also considered. The validation layer can involve screening before deployment. This can be using extensive red teaming – that is adding manual and AI based adversarial agents to test whether the trained model and system follows the constitutional principles. This can be done using `HarmBench` taxonomy (detailed here: HarmBench: A Standardized Evaluation Framework for Automated Red Teaming and Robust Refusal: https://arxiv.org/pdf/2402.04249) that has several categories of harm and accounts for various behaviors. It is a standardized evaluation framework for automated red teaming. It was used for testing effectiveness of constitutional AI in improving safety of resource-constrained models such as `DeepSeek-R1`, `Gemma-2`, `Llama 3.1`, and `Qwen2.5`. For more, you can read: How Effective Is Constitutional AI in Small LLMs? A Study on DeepSeek-R1 and Its Peers: [https://arxiv.org/html/2503.17365](https://arxiv.org/html/2503.17365). The evaluation framework also uses `GPT-4o-mini` to analyze the model responses for specific details. Apart from evaluation frameworks for LLMs, additional validation tests such as statistical parity tests, fairness metrics and compliance measures can be incorporated before deployment.
