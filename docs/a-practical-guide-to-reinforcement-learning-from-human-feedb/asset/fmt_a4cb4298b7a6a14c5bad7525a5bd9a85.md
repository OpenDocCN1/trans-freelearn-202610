For quantitative evaluation, using policy preference scores calculated by the `policy_pref_score` function, we can evaluate which trajectory the policy prefers vs ground truth preference labels.

```
def policy_pref_score(policy, frames):
    # log-prob sequence for actions for visual-only clips
    # argmax of policy probabilities at each frame
    t = torch.tensor(
        np.transpose(np.stack(frames).astype(np.float32) / 255.0, (0, 3, 1, 2))
    ).unsqueeze(0).to(DEVICE)  # (1,T,C,H,W)
    with torch.no_grad():
        B, T, C, H, W = t.shape
        frames_ = t.view(B * T, C, H, W)
        emb = frame_encoder(frames_)
        logits = policy(emb).view(B, T, -1)
        probs = F.softmax(logits, dim=-1)
        # compute sum of max action log-probs as proxy score
        maxp, _ = probs.max(dim=2)  # (B,T)
        score = torch.log(maxp + 1e-9).sum().item()
    return score
```

Sample trajectories and their preference match accuracy with respect to ground truth can be computed by comparing to the ground truth labels.

```
# Evaluate on some sample pairs
n_eval = min(40, len(pairs))
correct = 0
for idx in range(n_eval):
    ia, ib = pairs[idx]
    label = labels[idx]
    fa, aa = clips[ia]
    fb, ab = clips[ib]
    # If action logs, use sequence logprob else use proxy
    if aa is not None and ab is not None:
        sA = trajectory_logprob(policy_theta, fa, aa)
        sB = trajectory_logprob(policy_theta, fb, ab)
        preferA = (sA.item() > sB.item())
    else:
        sA = policy_pref_score(policy_theta, fa)
        sB = policy_pref_score(policy_theta, fb)
        preferA = (sA > sB)
    truthA = (label == 0)
    if preferA == truthA:
        correct += 1
acc = correct / n_eval
print(f"Preference-match accuracy over {n_eval} pairs: {acc:.3f}")
```

The preference-match accuracy over `n_eval` pairs might not be sufficient, and can be improved. Next, we list possible approaches to improve this.

## Experiment and Improve

To improve the preference match accuracy, especially in practice, consider the following strategies.

*   **Increase Training Data**: Generate more synthetic trajectories and preference pairs. More diverse and numerous examples help the policy generalize better to the preference function.
*   **Enhance Preference Scoring**: Refine the `traj_smoothness_score` to better capture human-like preferences. Consider adding more nuanced features (e.g., penalize lane departures, reward smooth corrections, or include speed consistency).
*   **Tune DPO Hyperparameters**: Experiment with DPO training parameters.
    *   Increase the number of DPO epochs.
    *   Adjust the KL penalty (`kl_coef`) to balance imitation and preference learning.
    *   Try different temperatures (`temp`) in the DPO loss for sharper preference distinctions.
    *   Use a lower learning rate for more stable convergence.
*   **Improve Model Capacity**: Use a deeper or wider `CNN` for the frame encoder, or try a pretrained model (e.g., `ResNet18`) for better visual feature extraction. Increase the size of the policy network.
*   **Data Augmentation**
    *   Apply random transformations (e.g., brightness, contrast, small shifts) to frames to make the policy more robust.
*   **Curriculum Learning**: Start training on easier preference pairs (large score differences), then gradually introduce harder pairs (subtle differences).
*   **Better Action Supervision**: If possible, use more accurate or diverse action labels for behavior cloning to provide a stronger initialization.
*   **Regularization**: Add dropout or weight decay to prevent overfitting, especially if the dataset is small.
*   **Evaluate and Debug**: Visualize failure cases where the policy disagrees with the preference function to identify systematic errors (e.g., confusion in certain visual scenarios).

By iteratively applying these improvements and monitoring the preference match accuracy, you should see measurable gains in alignment between your policy and the preference function. Notice that most of these practices are similar to supervised learning practices.
