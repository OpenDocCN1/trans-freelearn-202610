
# Deep Q-Network (DQN)

## Key Innovations

### Experience Replay

One of the key innovations in `DQN` is the use of experience replay. Instead of updating the `Q-network` after every single experience, the agent stores the experiences as it gathers them, especially the states, actions, rewards and state at next time step. The process involves gathering batches of this experience data randomly sampled from memory buffer. This breaks the symmetry and correlation between consecutive iterations of the experiences, and smooths out learning, leading to more stable training.

### Target Network

`DQN` also introduces a target network, which is a copy of the `Q-network` that is periodically updated. The target network is used to calculate the `target Q-values` during training, providing a more stable target and reducing the risk of divergence. By decoupling the `target Q-values` from the actively learned `Q-network`, `DQN` mitigates the feedback loop that can cause instability in traditional `Q-learning`.

### Scalability and Performance

By combining these techniques, `DQN` scales effectively to complex, high-dimensional environments. It has been successfully applied to a wide range of tasks, including playing Atari games directly from pixel inputs, where it achieved human-level performance, read here: [https://arxiv.org/pdf/1312.5602](https://arxiv.org/pdf/1312.5602). We will discuss the steps for implementing `DQN` algorithm in the following section.

## Implementation Steps for DQN

### Step 3 – Q-Network Definition

The `QNetwork` class is typically defined by you (or default values from the library can be used). The `QNetwork` includes the architecture and layers of the network. Here, the class defines a simple feedforward neural network with three fully connected layers. This network approximates the `Q-values` for each action given the current state. `input_dim` and `output_dim` are passed to `QNetwork` to configure its input and output layers:

*   The input layer of the network will have `input_dim` units, corresponding to the size of the state representation.
*   The output layer will have `output_dim` units, corresponding to the number of possible actions, with each unit predicting the `Q-value` for each action.

```
class QNetwork(nn.Module):
    def __init__(self, input_dim, output_dim):
        super(QNetwork, self).__init__()
        self.fc1 = nn.Linear(input_dim, 128)
        self.fc2 = nn.Linear(128, 128)
        self.fc3 = nn.Linear(128, output_dim)
        self.relu = nn.ReLU()
    def forward(self, x):
        x = self.relu(self.fc1(x))
        x = self.relu(self.fc2(x))
        x = self.fc3(x)
        return x
```

### Step 4 – Network Initialization

The `Q-network` is instantiated with dimensions of the observation and action spaces of the mountain car environment. `shape[0]` extracts the size of the state space (`observation_space`). For the mountain car environment, the state is represented as a vector with two features—position and velocity of the car, so `shape[0]` would be 2. This dimension indicates the number of input features that the `Q-Network` will process.

```
# Instantiate the Q-network
input_dim = env.observation_space.shape[0]
output_dim = env.action_space.n
q_net = QNetwork(input_dim, output_dim)
```

`env.action_space` refers to the action space of the environment, which details the actions the agent can take. `n` gives the number of discrete actions available in the environment. The action space n is `Discrete(3)`, representing the three possible actions we discussed in earlier section. This dimension is crucial for the `Q-Network`'s output layer, which needs to output `Q-values` for each possible action.

### Step 5 – Target Network

Implementing a target network in the `DQN` code involves maintaining a separate network (a copy of the `Q-network`) that is periodically updated to match the `Q-network`. Implementing a target network has following benefits:

*   **Stability:** If `Q-values` are updated using the current network's predictions. The updates cause the `Q-values` to become unstable and diverge because the network is constantly chasing a moving target. The target network stabilizes training by providing a fixed set of `Q-values` for calculating the target, which reduces the likelihood of the `Q-values` oscillating or diverging.
*   **Avoiding Correlation Issues:** Directly using the same network for both action selection and target calculation can introduce harmful correlations, leading to poor convergence. A target network mitigates this by decoupling the current `Q-value` estimates from the targets used for learning.

While we won't use the same network as `Q-network`, we will use the same architecture for the target network, and initialize with same weights.

```
target_net = QNetwork(input_dim, output_dim)
# Initialize target network with same weights
target_net.load_state_dict(q_net.state_dict())
target_net.eval()
```

### Step 6 – Optimizer and Loss Function

In training neural networks, especially in the context of reinforcement learning like `DQN`, two crucial components are the optimizer and the loss function. An optimizer is a method used to update the weights of the neural network based on the gradients computed during backpropagation. The goal is to minimize the loss function, which measures the difference between the predicted values (`Q-values`) and the target values. The `Adam` (Adaptive Moment Estimation) optimizer is a popular choice for deep learning tasks because it combines the advantages of two other methods: `AdaGrad` (Adaptive Gradient Algorithm, which adapts the learning rate for each parameter) and `RMSProp` (Root Mean Square propagation, which scales the learning rate by a moving average of recent gradient magnitudes). `Adam` maintains two moving averages for each parameter:

*   **First Moment (Mean):** Keeps track of the mean of the gradients.
*   **Second Moment (Uncentered Variance):** Keeps track of the variance of the gradients.
