### Augmenting Synthetic Data

In practice, there can be scenarios when human demonstration data is expensive. In our case with mountain car, while it is not expensive, it can be laborious. In either of these reasons, it is common practice to augment synthetic data to the expert human demonstrations. For training machine learning models, large and diverse datasets are beneficial. The expert trajectories collected and saved in previous section can be augmented with synthetic data. A script `augment_expert_data.py` in the GitHub repository provides a variety of functions to generate synthetic trajectories. The human trajectories can be used to create similar trajectories by perturbing the actions. This can be done by adding a random normally distributed noise to the human action, stepping through the environment loop, and collecting resulting state-action trajectories, as before.

```
def perturb_expert_actions(env, expert_data, noise_level=0.1, num_episodes=100):
    augmented_episodes = []
    for _ in range(num_episodes):
        state, _ = env.reset()  # Start from the initial state of the environment
        new_episode = []
        # Iterate over expert data and perturb actions
        for entry in expert_data:
            # Perturb the action with noise
            perturbed_action = entry['action'] + np.random.normal(0, noise_level)
            perturbed_action = np.clip(perturbed_action, -1.0, 1.0)  # Ensure within action bounds
            # Step the environment with the perturbed action to get the next state
            next_state, reward, done, _, _ = env.step([perturbed_action])
            # Create a new entry for the new episode
            new_entry = {
                'state': state.tolist(),
                'action': float(perturbed_action),
                'next_state': next_state.tolist(),
                'reward': reward,
                'done': done
            }
            new_episode.append(new_entry)
            # Update state for the next iteration
            state = next_state
            if done:
                break
        # Append the new episode to the list of augmented episodes
        augmented_episodes.append(new_episode)
    return augmented_episodes
```

Note that noise level can be varied to generate more diverse actions, but care should be taken to not introduce too much noise. In the next section we will use this generated data to train a behavioral cloning based model.

### Behavioral Cloning

There are several ways to incorporate human expert demonstration in training to improve PPO training performance. Collecting a similarity score between expert action and agent action and adding it to environmental reward, effectively reshaping the reward, can provide some immediate reward feedback instead of the delayed reward at the end of episode. While this is generally a valid approach, for sparse reward or delayed reward problems the agent might not encounter good sequence of actions to gain a high similarity score. A more robust approach is to train the agent to learn the human behavioral policy based on expert demonstrations and initialize the agent policy with learned behavioral policies before training on other exploratory samples. This ensures the agent has experience of good episodes. This is a direct policy initialization approach, and there can be some indirect approaches such as including human expert episodes in a replay buffer and using them as part of rollout episodes of PPO consistently. While we collected episodes with several variables in the last section, we only need states and actions for behavioral cloning. The behavioral cloning model training and inference are provided in the script `expert_behavioral_cloning.py`. This is a complete working code, but we will still cover important snippets here. Firstly, we create the behavioral cloning function, which requires inputting all training variables and setting up training. Note that device selection, agent assignment and optimizer setting is first executed. Expert trajectories are then unzipped to get states and actions, which are then converted to tensors.

```
def train_behavior_cloning(agent, expert_trajectories, num_epochs=10, batch_size=64, lr=0.001):
    device = torch.device("cuda" if torch.cuda.is_available() and args['cuda'] else "cpu")
    agent = agent.to(device)
    optimizer = optim.Adam(agent.parameters(), lr=lr, eps=1e-5)
    # Prepare data
    states, actions = zip(*expert_trajectories)  # Unzip into states and actions
    states = torch.tensor(states, dtype=torch.float32)
    actions = torch.tensor(actions, dtype=torch.float32).unsqueeze(1)
```

The training loop is then started for pre-decided number of epochs and number of steps. The states and actions are batched after randomized selection of indices.

```
# Training loop
for epoch in range(num_epochs):
    perm = torch.randperm(states.size(0))
    for i in range(0, states.size(0), batch_size):
        indices = perm[i:i + batch_size]
        batch_states = states[indices]
        batch_actions = actions[indices]
```

This is followed by going through forward pass of the agent model. Note that we are not emphasizing changing anything with the agent model. We are only updating how we compute actions and log probabilities.

```
# Forward pass
action_means = agent.actor_mean(batch_states)
if agent.is_discrete:
    action_probs = nn.functional.softmax(action_means, dim=-1)
    log_probs = action_probs.log()[range(batch_actions.size(0)), batch_actions]
else:
    action_logstd = agent.actor_logstd.expand_as(action_means)
    action_std = torch.exp(action_logstd)
    # Calculate the log probabilities for continuous actions
    dist = Normal(action_means, action_std)
    log_probs = dist.log_prob(batch_actions).sum(dim=1)
```

We then compute losses. Here negative log probability is used for computing loss, which is standard. This is followed by backward pass and optimization. Note that we add gradient normalization to stabilize training.

```
# Compute loss (negative log likelihood)
loss = -log_probs.mean()
# loss = nn.functional.mse_loss(action_means, batch_actions)
# Backward pass and optimization
optimizer.zero_grad()
loss.backward()
nn.utils.clip_grad_norm_(agent.parameters(), max_norm=1.0)
optimizer.step()
```
