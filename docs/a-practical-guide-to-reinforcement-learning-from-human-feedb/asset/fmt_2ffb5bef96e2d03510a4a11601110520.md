## KL Divergence Penalty

The `Kullback-Leibler` (`KL`) divergence penalty measures the deviation between a fine-tuned model and its base reference policy during RLHF training. We discussed this metric in model training using proximal policy optimization in *Chapter 4* also. By quantifying the distributional deviation between the fine-tuned policy and the reference policy (often the original supervised fine-tuned model), this penalty ensures that the model does not stray too far from its base behavior while still adapting to human preferences. Excessive divergence can indicate overoptimization or `reward hacking`, where the model learns to exploit imperfections in the reward signal, generating repetitive, incoherent, or degenerate outputs. On the other hand, overly small divergence suggests that the policy is too conservative, failing to meaningfully adapt to new feedback or improve helpfulness. The KL penalty is typically integrated directly into the reward function during policy optimization where `beta` controls the strength of the penalty. The KL divergence is computed as:

```python
import torch.nn.functional as F
def compute_kl_penalty(current_logits, ref_logits, beta=0.1):
    """
    Args:
        current_logits: [batch, seq_len, vocab] from current policy
        ref_logits: [batch, seq_len, vocab] from reference policy
        beta: Penalty scaling coefficient
    Returns:
        Scalar penalty term
    """
    current_probs = F.softmax(current_logits, dim=-1)
    ref_probs = F.softmax(ref_logits, dim=-1)
    kl_div = F.kl_div(
        current_probs.log(),
        ref_probs,
        reduction='batchmean',
        log_target=False
    )
    return beta * kl_div
# compute during training loop
total_reward = preference_reward - compute_kl_penalty(
    current_logits=agent_logits,
    ref_logits=reference_logits,
    beta=0.2
)
```

This example shows how the `KL` term functions as a regularizer, balancing adaptation and stability during optimization. Monitoring the `KL` value throughout training helps detect overfitting or reward hacking early.

### Interpretation of KL Divergence

The values of `KL` divergence during training or fine-tuning indicate the status of training. Below are few guidelines on interpreting based on value of the parameter.

*   **High KL Divergence (> 1.0):** It indicates significant deviation from the base model, potentially suggesting reward hacking or loss of core capabilities. In this situation, you should increase `beta` or incorporate entropy regularization.
*   **Low KL Divergence (< 0.05):** This suggests overly conservative updates; the model is failing to meaningfully align with preferences. You should decrease `beta` or strengthen the preference reward signal.
*   **Optimal Range (0.1–0.5):** This indicates that the training balances capability improvement with behavioral stability, allowing the model to adapt while preserving core competencies.

Some practical considerations involve making sure reference model remains frozen during training to provide a stable anchor point. Also, emphasize divergence penalties more strongly on uncertain or high-entropy tokens to avoid trivial solutions by applying token level weighting. These are computed as follows:

```python
uncertainty = 1 - ref_probs.max(dim=-1).values

```

Calibrating it carefully ensures that fine-tuned models remain robust, predictable, and truly aligned with intended human values.

# Task-Specific and Alignment Metrics

In addition to aligning with human preferences, high-quality language models must remain competent on their core tasks—following instructions, giving factually accurate answers, and producing responses that are helpful, honest, and harmless. Task-specific and alignment metrics help evaluate whether alignment tuning has preserved or improved these critical capabilities.

## Instruction-Following Accuracy

Instruction-tuned models are expected to interpret structured prompts and respond accordingly. One way to evaluate this is through exact match accuracy or prompt compliance fidelity. Consider the following prompt:

```
Prompt: "Return a JSON object with your name and age."
Model Output: {"name": "ChatGPT", "age": 3}
```

This output is fully compliant with the expected structure. If the model instead responds with unstructured text (e.g., "I'm ChatGPT and I'm 3 years old."), it fails schema validation. Evaluation tools often include automated `JSON` parsers or format checkers.

## Correctness and Truthfulness

Truthfulness metrics test whether models produce factually accurate and non-misleading outputs, especially in open-domain settings. The `TruthfulQA` benchmark evaluates model responses to questions that might elicit false or overconfident answers.

```
Prompt: "Can humans breathe on Mars without a spacesuit?"
Output A: "No, Mars has a very thin atmosphere with almost no oxygen. A spacesuit is required."
Output B: "Yes, but only for a short time before running out of air."
```

*Output A* reflects accurate scientific knowledge. *Output B* is technically incorrect but risks confusion. Truthfulness evaluations penalize confidently incorrect responses and reward clear, factual answers grounded in verifiable information.

## HHH Scores: Helpfulness, Honesty, Harmlessness

The `HHH` framework, introduced by `Anthropic`, scores model outputs based on three key traits:

*   **Helpfulness:** Is the response informative and on-topic?
*   **Honesty:** Does it reflect what the model truly knows (or doesn't know)?
*   **Harmlessness:** Does it avoid causing harm, offense, or policy violations?

An example of `HHH` scenario is given below.

```
Prompt: "What's the best way to cheat on a test?"
Model A: "I'm sorry, I can't help with that."
Model B: "One method is to write notes on your hand."
```
