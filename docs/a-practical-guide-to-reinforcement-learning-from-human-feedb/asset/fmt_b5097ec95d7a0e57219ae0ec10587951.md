## Loading and Preprocessing Preference Data

The DPO algorithm requires paired examples of human preferences—specifically, prompt-completion pairs where one response is preferred over another. We use a small subset of the UltraFeedback Binarized dataset for illustration. This dataset includes entries with both a preferred (chosen) and a dispreferred (rejected) response to the same prompt. We begin by loading the dataset and structuring it for later use:

```python
from datasets import load_dataset
# Load a small sample for testing
dataset = load_dataset("trl-lib/ultrafeedback_binarized", split="train[:100]")
```

Next, we split the dataset into training and evaluation portions. This enables us to measure the generalization performance of the model during fine-tuning.

```python
split_dataset = dataset.train_test_split(test_size=0.2)
train_dataset = split_dataset["train"]
eval_dataset = split_dataset["test"]
```

## Tokenizing the Preference Data

To train a transformer-based language model, we need to tokenize our input text. We use the tokenizer associated with the Qwen2-0.5B-Instruct model. For simplicity and diagnostic purposes, we concatenate the chosen and rejected responses in this step. This helps confirm that the tokenizer is behaving as expected. Later, the DPO trainer will process prompts and responses separately.

```python
from transformers import AutoTokenizer
# Load the tokenizer
tokenizer = AutoTokenizer.from_pretrained("Qwen/Qwen2-0.5B-Instruct")
# Tokenization: concatenate chosen and rejected for a sanity check
def preprocess_function(examples):
    input_text = [f"Chosen: {ch} Rejected: {rej}" for ch, rej in zip(examples['chosen'], examples['rejected'])]
    return tokenizer(input_text, padding=True, truncation=True, max_length=512)
# Apply preprocessing
tokenized_train = train_dataset.map(preprocess_function, batched=True)
tokenized_eval = eval_dataset.map(preprocess_function, batched=True)
```

> **Note:** The concatenated format ("Chosen: ... Rejected: ...") is a placeholder for validation. During DPO training, the model receives separate inputs for the prompt, chosen response, and rejected response. This is handled automatically by the `DPOTrainer`.

## Configuring the DPO Training

The `TRL` library includes a high-level `DPOTrainer` class, which requires a `DPOConfig` object to specify training hyperparameters. Here, we define a minimal training configuration suitable for prototyping on small GPUs or cloud environments like Google Colab.

```python
from trl import DPOConfig
dpo_config = DPOConfig(
    output_dir="qwen2-dpo-output",
    per_device_train_batch_size=4,
    gradient_accumulation_steps=4,
    num_train_epochs=3,
    learning_rate=5e-5,
    lr_scheduler_type="linear",
    weight_decay=0.01,
    logging_steps=5,
    report_to="none",  # Disable logging to external tools
    fp16=True           # Use mixed precision if supported
)
```

This configuration allows training on limited hardware. The `gradient_accumulation_steps` setting allows for larger effective batch sizes without exceeding memory limits. You can adjust parameters such as `num_train_epochs` or `output_dir` based on the scale of your data and experiment. In the next section, we’ll load the model in 4-bit quantized form, attach LoRA adapters (as introduced in *Chapter 6*), and proceed to initialize the DPO training loop using `DPOTrainer` method from `trl` library.

## Training the Preference-Optimized Model

We initialize the `DPOTrainer`, providing it with the tokenized training and evaluation datasets:

```python
from trl import DPOTrainer
trainer = DPOTrainer(
    model=model,
    ref_model=None,
    args=dpo_config,
    train_dataset=tokenized_train,
    eval_dataset=tokenized_eval,
    processing_class=tokenizer
)
```

With the `DPOTrainer` fully configured and initialized, we begin training by calling `trainer.train()`. The evaluation set is automatically used for logging evaluation metrics during training. The `train()` method launches the training loop over our tokenized dataset. After training completes, we save the adapter weights and tokenizer for later reuse or deployment. Since we used `Parameter-Efficient Fine-Tuning` (`PEFT`) with LoRA (introduced in *Chapter 6*), we only need to save the adapter layers:

```python
model.save_pretrained("qwen2-lora-adapter")
tokenizer.save_pretrained("qwen2-lora-adapter")
```

The `save_pretrained()` method stores the model configuration and adapter weights in the `qwen2-lora-adapter` directory. For the tokenizer, the saved files include:

```
tokenizer_config.json
special_tokens_map.json
vocab.json
merges.txt
added_tokens.json
tokenizer.json
```

These files preserve the vocabulary, special tokens, and tokenizer settings, ensuring compatibility with the fine-tuned model. If you need to reload the fine-tuned model later, first load the base model especially if you are running a new session or a new notebook.

```python
from peft import PeftModel
from transformers import AutoTokenizer
import torch
# Reload base model (if not already in memory)
base_model = AutoModelForCausalLM.from_pretrained(
    "Qwen/Qwen2-0.5B-Instruct",
    quantization_config=bnb_config,
    device_map="auto"
)
# Load LoRA adapter from local directory
model = PeftModel.from_pretrained(base_model, "qwen2-lora-adapter")
# Load tokenizer from saved adapter directory
tokenizer = AutoTokenizer.from_pretrained("qwen2-lora-adapter")
```

Once training completes or model is reloaded, we evaluate the model's performance on the held-out evaluation data:

```python
results = trainer.evaluate()
print(results)
```

The output of the evaluate run is a number of evaluation metrics. These metrics give insight into how well the trained model aligns with human preferences:

*   `accuracies`: How often the model prefers the “chosen” over “rejected” response.
*   `margins`: The average reward gap between the preferred and rejected responses.
*   `eval_loss`: A proxy for how well the model is learning the preference signal.
