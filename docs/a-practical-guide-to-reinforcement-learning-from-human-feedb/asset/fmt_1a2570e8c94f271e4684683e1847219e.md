## Model Generation Parameters

After comparing the outputs, you can notice how the output is modified for the model fine-tuned with domain specific dataset. The model generation and inferencing involve significant amount of experimentation using additional parameter setting. For example, we add `temperature` parameter to adjust temperature for controlled randomness (lower means less randomness). Similarly `top_p` is a parameter to increase diverse but focused output. `top_k` parameter sets the sampling limits on the pool of options for better quality. `no_repeat_ngram_size` prevents repeating n-grams, otherwise word repetition can be observed, and `do_sample` setting is to enable more creative answers. Also, note that we are now not outputting only the first generated response like in previous model generation (`output[0]`), but returning outputs enumerated outputs, which are equal to setting `num_return_sequences`.

## Model Generation Code

```python
model.eval()
input_text = "AI in oncology"
inputs = tokenizer(input_text, return_tensors="pt", padding=True).to("cuda")
# Explicitly set pad_token_id
# Set parameters to influence generation quality
output = model.generate(
    inputs["input_ids"],
    attention_mask=inputs["attention_mask"], 
    max_length=100, 
    num_return_sequences=2, 
    pad_token_id=tokenizer.eos_token_id, 
    temperature=0.7, 
    top_p=0.9, 
    top_k=50,
    no_repeat_ngram_size=2, 
    do_sample=True, 
)
print("Generated Responses:")
for i, generated_sequence in enumerate(output):
    print(f"Option {i+1}: {tokenizer.decode(generated_sequence, skip_special_tokens=True)}\n")
```

## LoRA Configuration

In addition to model generation setting experiments, users can do training experiments by training multiple fine-tuned models by changing the LoRA parameters:

```python
r=8,         
lora_alpha=32,
lora_dropout=0.1,
target_modules=["c_attn"]
```

Note that a higher value of `r`, means more model expressivity but lower computational efficiency. The scaling factor `lora_alpha` dictates how strongly the model will adapt to task specific data used in fine-tuning. The value `lora_dropout` decides percentage of the low-rank parameters that will be dropped out during training. This helps to improve generalization and prevents the model from relying heavily on specific patterns learned using the low-rank matrices. `target_modules` specify which parts of the model will be adapted using LoRA. By specifying `c_attn` we are specifying LoRA to focus the low-rank adaptation on the attention mechanisms of the model. This is fine as attention layers help the model understand dependencies in sequences of text.

## Model Evaluation Metrics

In addition to manual evaluation using model inferencing, for deploying fine-tuned models in production, they have to be thoroughly evaluated using both qualitative and quantitative metrics. Fine-tuning of pretrained foundation models usually is based on what tasks the model needs to serve e.g. model completion, text generation, sentiment analysis or summarization. In order to evaluate fine-tuned models, evaluation datasets can be prepared based on fine-tuning dataset used. These datasets can then be used to test the model outputs on metrics that are relevant to the tasks. For example, tasks such as summarization, can be evaluated using metrics such as recall – this metric indicates the ratio of relevant results retrieved or generated in the output from the model, for total number of relevant results available in the fine-tuning dataset, and precision—the number of relevant output n-grams that are correctly available in the fine-tuning dataset. These metrics can be captured in variations of the well-known metric called `Recall-Oriented Understudy for Gisting Evaluation` (`ROUGE`). For example `ROUGE-n` is a metric that indicates the number of overlaps between the number of n-grams available in the dataset used in fine-tuning and number of n-grams in the generated outputs. `ROUGE-1` for unigram overlaps involving measuring overlaps in single word, and `ROUGE-2` for bi-grams for measuring overlaps of two words at a time are also used sometimes. These statistical metrics only capture partial quality of the output, for example, while `ROUGE` captures overlap, it does not capture fluency of the generated output. These metrics also do not capture bias or other important metrics. Therefore, in addition to statistical metrics, we rely on model based metrics, where the `LLM` model can judge itself or a more advanced `LLM` judges the outputs for all required criteria. For this chapter, the focus is mainly on reducing model update cost and improving training efficiency, while maintaining performance on task inference. Model evaluation process for parameter-efficient fine-tuning, supervised fine-tuning or `RLHF` will be similar. We will defer this topic and elaborately treat it in *Chapter 11*.
