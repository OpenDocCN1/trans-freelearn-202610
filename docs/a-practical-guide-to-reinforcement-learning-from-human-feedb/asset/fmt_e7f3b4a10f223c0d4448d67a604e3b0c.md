
# Reward Hacking and Challenges in Reward Design

Agents may find ways to achieve high rewards by exploiting loopholes in the reward function rather than exhibiting the desired behavior. This is known as reward hacking. Poorly designed rewards can lead to behaviors that maximize rewards but are undesirable, unsafe, or misaligned with the objectives in unintended ways. Consider an example of a cleaning robot with a proxy reward function that encourages cleaning as many areas as possible. The robot might knock down a valuable vase to maximize its cleaning score, even though breaking the vase is undesirable. The proxy reward in this case failed to account for these unintended consequences.

## Design Complexity

Crafting a reward function often requires domain knowledge and expertise, which can be time-consuming and error-prone for humans. In addition, in case of dynamic or changing environments, a fixed reward function may not be appropriate, necessitating continuous adjustments.

## Tradeoffs and Balancing for Multiple Objectives

Balancing multiple objectives within a single reward function can be challenging. For example, an agent might need to balance speed and safety, which can be conflicting goals. In case of grid world, if obstacle is on the shortest path to the goal state, agent has to circumvent the obstacle first. The objective of avoiding the obstacle can be conflicting the objective of reaching the goal, for immediate steps. While this can be resolved by designing task hierarchies and weighting reward functions, in complex environments, determining the appropriate weighting for different components of the reward function can be difficult and may require extensive tuning.

## Scalability

For very large environments with multiple objectives, a single reward function might not scale well. In such cases, creating task hierarchies might be suitable. For tasks that have hierarchical structures, designing rewards that appropriately incentivize progress at different levels of the hierarchy is a complex task in itself.

## Strategies to Overcome Challenges

In order to overcome above challenges, there are several strategies that can be employed. Although not all are completely effective in all scenarios, they can be promising approaches to try. For example, complexity of tasks can be resolved by breaking down the tasks into smaller simpler subtasks with specific objectives. This is called **Task Decomposition**. For example, a pick and place robot with the task of picking an object and placing at another position can be decomposed into three simpler tasks: 1) reaching the goal object without hitting an obstacle, 2) grasping the object, 3) moving the object to the goal location and releasing it. Other issues with reward definition can be identified and improved upon by iteratively designing, testing, and refining the reward function based on the agent’s performance and behavior. Use simulations and controlled environments, it is possible to observe the agent’s actions and adjust the reward signals accordingly. By implementing and comparing multiple versions of the reward function, we can A/B test their effectiveness in achieving desired behaviors. Using inverse RL to infer the reward function by observing the behavior of human experts can also help in capturing the implicit objectives that experts use to perform tasks. An example of infering reward function can be observing state-action trajectories of expert robot motion for pick and place use case, where inferring weights assigned to several decomposed objectives such as collision avoidance, efficiency of reaching a goal (time taken), or safety and compliance e.g. speed or acceleration can be steps towards IRL. While all these strategies can be effective under some scenarios, they require human expertise and experimentation. One way to incorporate human feedback more easily is adding human feedback during the learning process to guide the agent and correct misaligned behaviors. This can be achieved by using human preferences and including them in reward modeling process.

# Techniques for Reward Modeling

Reward modeling techniques are varied and can be broadly categorized based on the source of feedback, the type of learning involved, and the specific methods used to integrate human preferences into the reward function. There are several sources of human feedback, depending upon how it can be sensed or received. Below are some sources enumerated.

## Sources of Human Feedback

### Expert Feedback

Human experts provide desired outcomes or guide the agent towards specific goals. This can be helpful for complex tasks where defining a reward function directly might be challenging.

### Environmental Feedback or Trial-and-Error

The agent learns from its interactions with the environment. Successes lead to positive rewards, while failures lead to negative rewards. This is a more exploratory approach but can be effective for simpler environments. The agent learns from interacting with the environment itself. The environmental feedback is the raw, unprocessed information the agent receives from the environment in response to its actions. This can be:

*   **Success/failure signals:** Did the agent achieve its goal?
*   **State changes:** How did the environment change because of the action?
*   **Resource changes:** Did the agent gain or lose resources?

The raw information provides context for the reward model, for example raw signals can be data points to learn the relationship between the agent's actions, the resulting state of the environment, and the **desired outcome**. For example:

*   In a game where the goal is to collect coins, the raw information might tell the model that the agent bumped into a wall (state change). This, by itself, doesn't tell the model if it's a good or bad outcome.
*   However, by combining this information with other data points (like not collecting a coin), the model can learn that bumping into walls is generally undesirable (negative reward).

In context of RLHF, human feedback can be used to incorporate or add clarity to environmental signals.

### Combined Feedback

This approach leverages both human and environmental feedback to guide the learning process.

## Preference-Based Learning

This technique uses human preferences between different trajectories or actions to learn a reward function. The process involves the following three steps:

1.  **Data Collection**: Collect pairs of trajectories or actions and ask humans to provide preferences between them.
2.  **Preference Modeling**: Use models (often neural networks) to learn a function that predicts human preferences.
3.  **Reward Function Learning**: The model learns a reward function that aligns with the human preferences by optimizing the likelihood of the human-provided preferences.

## Absolute Rating Models

These models directly estimate a score for a single output, reflecting how well it aligns with human preferences. This can be framed as a regression task. Unlike preference-based learning, which relies on relative comparisons, absolute rating models use direct numerical scores.
