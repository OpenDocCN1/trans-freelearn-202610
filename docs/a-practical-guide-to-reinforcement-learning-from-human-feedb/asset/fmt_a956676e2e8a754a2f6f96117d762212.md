# Introduction to Parameter Efficient Fine Tuning

In fine-tuning, a pre-trained model such as a large transformer is further trained on a small, task-specific dataset. The additional training on specific dataset allows the model to learn the task specifics and incorporate new knowledge in the dataset. In the previous chapter, we demonstrated fine-tuning the `distilbert-base-uncased` model to the `imdb` dataset. This model was relatively smaller (66 million parameters) compared to contemporary models (in order of billions) and allowed demonstration on a small dataset. Traditional fine-tuning saves considerable training cost by training on a task specific smaller dataset. It still usually requires updating a large number of parameters, which can be computationally expensive and memory-intensive. To address this, a class of fine-tuning techniques called `parameter efficient fine-tuning` (`PEFT`) has become a common practice. The goal of `PEFT` strategies is to reduce the number of parameters to fine-tune, and this can be achieved through several methods. Broadly, we can classify them as follows:

## Additive Fine-Tuning Methods

In this subclass of fine-tuning, the original pretrained model parameters are frozen, and instead, added parameters are augmented and trained. This fundamentally changes the structure of the model. These methods can use `adapters`—small neural networks augmented with the pre-trained model. This significantly reduces the number of parameters that need to be adjusted.

## Prompt Based Methods

Prominent among these is `prompt tuning`—instead of modifying the model directly, this approach involves learning a set of input prompts that help in conditioning the model output. These prompts are short enough for practical purposes and can capture the desired behavior without any change to the model architecture. These methods use trainable embeddings that prepend or append to the inputs, and guide the model output, while the pretrained model weights are unaltered. This method has shown promise in small data settings and model sizes, but for larger models there are diminishing returns.

## Specification Based Methods

These methods involve specifying model parameters for tuning, either heuristically (randomly or manually) or by learning them. While these methods have been applied in research projects, they have not shown much promise in practice for large language model adaptation.

## Reparameterization Based Methods

This method is based on the premise that pretrained model parameters can be adapted for specific tasks by representing them with a lower rank. This compression to low-dimensional space can be an optimization that leads to lower computation cost. `Low-Rank Adaptation` (`LoRA`) introduces low-rank matrices into the model architecture, updating only these matrices during training. This reduces the number of trainable parameters significantly and also enables effective adaptation to training datasets. In `LoRA`, weight updates involve factorizing the model parameters into low-rank matrices. Training only these matrices provides an efficient adaptation mechanism for the pretrained models, compared to updating all of the weights in case of full fine-tuning.

Among these approaches, `LoRA` is the state of the art technique, and often utilized in research papers as a benchmark technique to compare to. Therefore, we will focus on this technique in more depth in this chapter. Before going through this technique, we will first investigate the Supervised Fine-Tuning process, which specializes in fine-tuning for language models.

# Applying Supervised Fine-Tuning Process Using Hugging Face TRL Library

Fine-tuning using the standard fine-tuning we demonstrated in Chapter 5 can become more complex as we require making several training choices. The `transformers` library allows flexibility to make these choices, but it comes at the cost of longer development time and experimentation. It also requires several customizations and developments to integrate methods necessary for implementing `RLHF`. To address these challenges, the `trl` library dedicates to providing tools and techniques that help the development of post-training model processes. The modular architecture also helps with scaling to various hardware setups.

`Supervised Fine Tuning` (`SFT`) method is a modality within the `trl` library, and it is similar to the standard fine-tuning as it is a wrapper around the `Trainer` class of `transformers` library, and both involve adapting a pre-trained model to a specific tasks. The main difference between them is that `SFT` is specifically designed for fine-tuning `large language models` (`LLMs`) and provides tools and features that facilitate training on labeled datasets with prompt-response pairs, tailored for conversational tasks, and allows further model specification and initialization. On the contrary, the general fine-tuning functionality in `transformers`, while more flexible for a wider range of tasks, may require additional dataset formatting and customization when used for `LLM` specific applications, especially around conversational use cases.

`SFT` provides features such as prompt engineering and dataset formatting and relies a lot on prompt-response pairs in the training data. This allows the model to learn to generate outputs and responses based on specific prompts and formats. `trl` offers a dedicated `SFTTrainer` class that simplifies the process of supervised fine-tuning with features like dataset handling and `LLM` evaluation metrics. In this section we will use the `SFTTrainer` and `SFTConfig` from the `trl` library, for fine-tuning a model, in place of `TrainingArguments` and `Trainer` from the `transformers` library that we used in the last chapter. The `SFTConfig` helps configure aspects of the fine-tuning process, and also helps setting up the reward model and other parameters specific to `SFT` in reinforcement learning-based fine-tuning setups.

## Model Choice

`SFTTrainer` is a specialized class developed for causal language modeling. These models predict the next word based on a given input of words or tokens. Some applications include text completion, auto-correction and code generation. These models are inherently different than masked language models, such as `BERT` (`bidirectional encoder representations for transformers`) and `distilBERT` (`a distilled version of BERT`), that we discussed in the last chapter. Due to architectural differences, `SFTTrainer` is suitable for causal language modeling especially large language models such as `GPT` series. For masked models, `transformers` library should be used.
