
# Transformer Architecture: Embeddings, Positional Encoding, and Attention

## Introduction

Transformers emerged from the need to handle long-range dependencies in sequential data, which traditional **recurrent neural networks** (**RNNs**) struggled with, particularly in **natural language processing** (**NLP**). The landmark paper "*Attention is All You Need*" by Vaswani et al. (2017), mentioned earlier, introduced the transformer architecture, which replaced recurrent layers with attention mechanisms. This shift allowed for better parallelization during training and improved performance on tasks involving large datasets. The Transformer is a model designed to understand and generate sequences of data, like sentences. Instead of processing words one by one in order, it looks at all the words at once. The core idea behind it is *self-attention*, which allows the model to focus on different parts of the sentence based on their relevance to each other.

## Embedding the Input

When a Transformer processes text, it starts by converting words into numbers (vectors) that the model can understand. This step is called **embedding**. For example, let’s say we have a sequence of words: , where each `x_i` represents a word in the sequence. Since words are represented as one-hot vectors (large vectors full of zeros with a single 1 indicating the word), we use an **embedding matrix** `W_e` to convert these one-hot vectors into dense, meaningful vectors. As a side note, for practical considerations, each `x_i` can be a token (a defined splitting of word). But, for purpose of understanding, we are considering each word as a token. Mathematically, if `W_e \in \mathbb{R}^{V \times d_model}`, where `V` is the size of the vocabulary and `d_model` is the model’s hidden dimension, each word embedding is: `z_i = W_e^T x_i`. The result is a sequence of embeddings: `Z = (z_1, ..., z_n)`, where each `z_i` is a dense vector of size `d_model`. **Intuition**: Think of embeddings as a way to represent words that captures their meaning. Words with similar meanings will have similar embeddings, which helps the model understand relationships between words.

## Positional Encoding

Transformers process entire sequences in parallel, but this creates a challenge: how does the model know the order of the words in a sentence? For example, "The sun rises from the east" is very different in meaning and semantics from "The east rises from the sun," even though the words are the same. To solve this, the Transformer adds something called *positional encoding* to each word embedding. This encoding injects information about the position of each word in the sequence. The positional encoding for each position `t` is defined mathematically as: `PE(t, 2i) = sin(t / 10000^{2i/d_model})`, `PE(t, 2i+1) = cos(t / 10000^{2i/d_model})`. This creates a unique positional vector `p_t` for each word’s position. The model then adds this vector to the word embeddings: `z_i' = z_i + p_i`. This new sequence is now the input to the transformer’s encoder-decoder architecture, starting with self-attention aspect. A simple component of the architecture is shown below:

Positional encodings help the model know the order of words. Without this, it would treat "The sun rises from the east" and "The east rises from the sun" the same. Using PyTorch these can be implemented as shown in below snippet:

```python
import torch
from torch import nn

class PositionalEncoding(nn.Module):
    def __init__(self, d_model, dropout=0.1, max_len=5000):
        super(PositionalEncoding, self).__init__()
        self.dropout = nn.Dropout(p=dropout)
        pe = torch.zeros(max_len, d_model)
        position = torch.arange(0, max_len, dtype=torch.float).unsqueeze(1)
        div_term = torch.exp(torch.arange(0, d_model, 2).float() * -(torch.log(torch.tensor(10000.0)) / d_model))
        pe[:, 0::2] = torch.sin(position * div_term)
        pe[:, 1::2] = torch.cos(position * div_term)
        pe = pe.unsqueeze(0)  # Shape (1, max_len, d_model)
        self.register_buffer('pe', pe)

    def forward(self, x):
        x = x + self.pe[:, :x.size(1), :]
        return self.dropout(x)
```

In the above snippet, we create a matrix of zeros of shape `(max_len, d_model)` to ensure that `pe` has appropriate dimensions. The dimension of `d_model` accommodates for including both the sine and cosine components, hence it is double of the term productizing in their argument `position * div_term`. Since both the arguments within sine and cosine components use `position` as the first term, it is of shape `(max_len, 1)`. Similarly, the second `div_term` is of shape `(d_model/2)`, adding up to `d_model`, half for sine and half for cosine. In `d_model`, the sine and cosine are applied on even and odd indices respectively, as can be seen from how `pe[:, 0::2]` and `pe[:, 1::2]` are implemented. We add all these in the `__init__` method of the `PositionalEncoding` class. The `forward` method adds positional encoding to the input tensor, and returns after applying `dropout` for regularization, in order to avoid overfitting. Now that we know how positional encoding can be added to input embedding, and importance of word position is incorporated, we will visit the self-attention mechanism that ties the learning of word relationships.

## Self-Attention: Learning Word Relationships

The **self-attention** mechanism is the heart of the Transformer. It allows the model to focus on different words in a sentence when processing each word. For example, in the sentence "The sun rises from the east," when the model processes "rises," it should focus on both "sun" (the subject) and "east" (the object) to understand the meaning. For each word, the model creates three vectors:

*   A **query** `Q`,
*   A **key** `K`,
*   A **value** `V`.

These vectors are calculated by multiplying the input `Z` with learned weight matrices: `Q = Z W_Q`, `K = Z W_K`, `V = Z W_V`. To figure out how much attention each word should give to other words, the model computes a similarity score between the query of one word and the keys of all the words. This is done using the dot product and scaling: `scores = (Q K^T) / sqrt(d_k)`. The `softmax` function ensures that the scores add up to 1, turning them into probabilities. This gives us a weighted combination of the value vectors, where words that are more important get more weight. Self-attention lets each word "look at" other words in the sentence and focus on the ones that matter most to understanding the meaning. It is like highlighting the most important words for each part of the sentence.
