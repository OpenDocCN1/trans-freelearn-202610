
# RLHF Fine-tuning with PPO Training Loop

## Training Loop Overview

Once the PPO training parameters are set up and data is structured for batch training, the RLHF fine-tuning process follows an iterative training loop where the model generates responses, receives feedback in the form of rewards, and updates its policy using PPO. Each training step consists of the following key stages:

**1. Generating Model Responses:** The model takes a prompt as input and generates a response using predefined sampling parameters (`generation_kwargs`).

**2. Computing Rewards:** The generated response is evaluated by a reward model that scores how well the output aligns with human feedback.

**3. Updating the Policy:** The `PPOTrainer` instance uses the computed rewards to optimize the model's policy, improving future responses. A KL-divergence constraint helps maintain stability, preventing drastic shifts in behavior.

**4. Memory Optimization:** Since training large language models can be memory-intensive, we apply optimizations such as batch size limits, clearing CUDA cache, and reducing sequence lengths to enable training on resource-constrained hardware.

While the full implementation can be found in the sample notebook, we will walk through key parts of the code to better understand the reasoning behind specific design and implementation choices. The core aspects of the training loop are shown in the following snippet.

## Code Implementation

```
for epoch in range(NUM_EPOCHS):
    for batch_idx, batch in enumerate(ppo_trainer.dataloader):
        if batch_idx >= 30:  # Limit batches for demo
            break
        query_tensors = batch["input_ids"]
        response_tensors = []
        for i, query in enumerate(query_tensors):
            generation_kwargs["attention_mask"] = batch["attention_mask"][i].unsqueeze(0)
            response = ppo_trainer.generate(query, **generation_kwargs)
            response_tensors.append(response.squeeze()[len(query):])  # Remove prompt tokens
        batch["response"] = [tokenizer.decode(r, skip_special_tokens=True) for r in response_tensors]
        texts = [p + " " + r for p, r in zip(batch["prompt"], batch["response"])]
        rewards_tensor = compute_reward(texts)
        reward_history.append(rewards_tensor.mean().item() if isinstance(rewards_tensor, torch.Tensor) else float(rewards_tensor))
        stats = ppo_trainer.step(query_tensors, response_tensors, rewards_tensor)
        kl_div = stats.get('ppo/policy/approxkl') or stats.get('ppo/policy/policykl') or stats.get('objective/kl')
        kl_divs.append(kl_div)
        if batch_idx % 20 == 0:
            print(f"Batch {batch_idx} Reward: {reward_history[-1]:.4f} KL: {kl_div:.4f}")
```

## Code Explanation

The training loop iterates over `NUM_EPOCHS` and `ppo_trainer.dataloader`, which provides batches of data during training. Each batch contains `batch["input_ids"]`, structured as tensors and assigned as `query_tensors`. At this point, the batch **does not** yet include model-generated responses—response generation is deferred until inside the training loop to optimize memory usage.

Each batch also includes `attention_masks`, stored within the `RLHFDataset`, which are appended to the `generation_kwargs` and passed per query when calling `ppo_trainer.generate(query, **generation_kwargs)` to produce model responses. These responses are collected into `response_tensors`, which, along with `query_tensors`, are inputs required for the PPO update.

Reward computation uses the `compute_reward` method, which takes text inputs constructed by combining the decoded batch prompts and generated responses. After obtaining rewards, the PPO step is performed via `ppo_trainer.step(query_tensors, response_tensors, rewards)` to optimize the policy. As seen in the core training loop, the model generates responses per query, computes corresponding rewards using the `compute_reward()` method, and applies PPO updates through `ppo_trainer.step()`.

After each update, in this case, you can do memory management by clearing memory using `clear_memory()`.

Through this iterative RLHF process, the policy model gradually improves its responses based on the rewards it receives. Early outputs may not align well with human preferences, but successive PPO updates encourage the model to optimize toward preferred, coherent, and diverse responses. The KL-divergence penalty acts as a regularizer, ensuring updates are smooth and the model does not deviate drastically from its original behavior.

## Metrics to Track

Fine-tuning language models using PPO (Proximal Policy Optimization) in the RLHF framework involves several dynamic components. Tracking the right metrics is essential not only for debugging and convergence monitoring but also for ensuring that the model is aligning with human preferences without diverging too far from its base capabilities. Below are key metrics that should be monitored throughout PPO training:

### KL Divergence

KL divergence monitors how much the fine-tuned policy deviates from the original reference model. It is one of the most important signals in PPO-based RLHF. It reflects how far the policy has moved from the reference distribution—typically the base, pretrained model. Excessively high KL divergence suggests that the model is becoming overly specialized or overfitted for the reward function, potentially losing generality or linguistic fluency. On the other hand, very low or negative KL values might suggest under-training, poor learning signal, or even issues in numerical stability. In practice, KL divergence is often regularized in the PPO loss function using a coefficient (`kl_coef`), which may need to be adjusted during training.

### Reward Score

The reward score measures the quality of generated responses according to the learned reward model. The reward model plays a central role in RLHF by quantifying how aligned a model's output is with human preferences. During PPO training, each new response is scored by this model, and its average reward provides insight into how much the agent is improving. A rising reward trend generally reflects alignment progress, assuming the reward model is accurate and calibrated. However, consistently high rewards without a matching improvement in human-perceived quality may indicate reward hacking—where the model optimizes for spurious patterns in the reward model rather than genuine alignment.

### Entropy

Entropy indicates how diverse or deterministic the model's output distribution is. It measures the randomness of the model's policy—the higher the entropy, the more exploratory the behavior. In language generation, this translates to producing a wider range of responses. Maintaining healthy entropy during training helps prevent premature convergence to overly narrow or repetitive outputs. Entropy typically decreases as training progresses, since the policy becomes more confident. However, maintaining moderate entropy is important to preserve diversity and prevent repetitive or generic outputs. If entropy drops too quickly, the model may become too deterministic, reducing creativity and potentially overfitting to the training distribution.
