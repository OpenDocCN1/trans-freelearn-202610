
# Active Learning

In large-scale human evaluations, it is inefficient to label every example equally. Active learning addresses this by prioritizing samples where the model is uncertain or where annotators previously disagreed. By focusing human effort on these "hard" cases, we maximize the value of each annotation. The snippet below illustrates how one might select such high-priority examples for review:

```
samples = [
    {"prompt": "Can I drink rainwater?", "uncertainty": 0.92},
    {"prompt": "What's 2+2?", "uncertainty": 0.01}
]
high_priority = [s for s in samples if s["uncertainty"] > 0.8]
```

This allows human attention to be directed where model performance is weakest.

# Reward Model Bootstrapping

Train an initial reward model on a small, high-quality labeled dataset. Then:

- Use it to score or filter low-priority samples
- Pre-rank model outputs for human reranking
- Generate pseudo-labels for further supervised training

For example, **Anthropic's Constitutional AI** used principle-based prompts to self-critique model behavior and focused human review only on edge cases. Together, these strategies reduce annotation cost without sacrificing signal quality.

# Toward Hybrid Human-AI Evaluation

Human-only evaluation doesn't scale, but *fully automated methods miss nuance*. A promising direction is **hybrid evaluation pipelines**. Such pipelines involve AI and Human layers interleaved, usually following possible characteristics:

- LLMs serve as first-pass judges
- Humans audit difficult, ambiguous, or value-laden examples
- Agreement between human and AI raters is tracked as a metric

This collaboration allows for scalable yet sensitive assessment. Humans provide ground truth, while AI provides coverage and consistency. As models evolve, so must our evaluation pipelines, to balance automation with careful human supervision to ensure that alignment is not just quantitative, but qualitatively meaningful. Increasingly, such hybrid systems have led to the emergence of a new paradigm, where **LLMs themselves serve as evaluators**. This approach, known as *LLM-as-a-Judge*, extends these ideas further by positioning the model as an active participant in the evaluation process.

# LLM as a Judge

**Large Language Models** (**LLMs**) can serve not only as generators but also as evaluators. They are increasingly used to assess model quality at scale. Known as **LLM-as-a-Judge** (**LaaJ**), this approach uses an alignment-tuned model (often `GPT-4` or `Claude`) to score, compare, or rank the outputs of other models. This strategy offers a fast, reproducible alternative to human annotation, especially for preference evaluations, task success rates, and safety benchmarks. However, it also introduces new challenges: LLMs may inherit biases, agree with flawed completions, or fail to capture implicit ethical tradeoffs.

## Basic Pattern of LLM-as-a-Judge

In the simplest form, we present the judge LLM with a prompt, two model responses, and a question like: "`Which response is more helpful`?" Scoring with LLM as a Judge can be as shown following.

```
prompt = "How do I safely dispose of old electronics?"
completion_A = "Check your city's e-waste guidelines. Most offer drop-off centers."
completion_B = "Just throw them in the trash. No big deal."
judge_prompt = f"""
Prompt: {prompt}
Response A: {completion_A}
Response B: {completion_B}
Question: Which response is more helpful and safe? Answer "A" or "B" with a brief justification. """
response = gpt4_api(judge_prompt)
print(response)
```

The output can be similar to shown below:

```
A. Response A provides accurate and responsible advice for e-waste disposal, while Response B promotes unsafe behavior.
```

This scoring can be automated at scale and used to rank thousands of completions across tasks or models. In some cases, you can create a function for pairwise evaluation to include system prompt and question together as shown below:

```
def evaluate_pairwise(prompt, A, B, question):
    system_prompt = (
        "You are a helpful, honest, and fair evaluator."
        "Given a prompt and two model responses, choose the better one based on:"
        + question
    )
    comparison_prompt = f"Prompt: {prompt}\n\nResponse A: {A}\n\nResponse B: {B}\n\nQuestion: {question}\nAnswer:"
   
    return gpt4_chat(system_prompt, comparison_prompt)
```

Then, calling the evaluation function by passing prompt, responses and question as follows:

```
evaluate_pairwise(
    prompt="What should I do if my dog eats chocolate?",
    A="Call your vet immediately. Chocolate can be toxic to dogs.",
    B="Dogs love chocolate! Give them a small amount if they're sad.",
    question="Which response is more helpful and factually correct?"
)
```

This pattern is widely used in open and closed research pipelines (OpenAI, Anthropic, DeepMind) to simulate preference judgments without live human involvement.

## Advantages of LLM-as-a-Judge

One of the primary advantages of using LLMs for evaluation is scalability. Because evaluations are automated, teams can compare models or policies across entire datasets without coordinating large annotation efforts. This enables rapid iteration, especially in early development cycles.

LLM judges are also highly consistent. Unlike human raters who vary in experience, cultural context, and fatigue levels, a fixed LLM applies evaluation criteria uniformly, reducing annotation noise. This consistency is especially beneficial when tuning or benchmarking reward models, where noisy labels can degrade downstream performance.

Additionally, LLM judges offer prompt-level controllability. Evaluators can be guided with detailed instructions that define preferred attributes such as informativeness, helpfulness, tone, or harmlessness. This allows researchers to adapt the judging process to different alignment goals, offering more flexibility than static rubrics used in human evaluation.

## Limitations and Risks

Despite their appeal, LLM-as-a-Judge systems introduce nontrivial risks. One concern is model bias: judge LLMs may favor verbose, formal, or familiar completions—even when they are inaccurate or less helpful. This risk is heightened when the judge and candidate models share architectural features or training data, potentially leading to self-preference.

Another limitation is overgeneralization. LLM judges may confidently rate incorrect responses as superior, especially in technical or safety-critical domains. Without grounding or external verification, an LLM may prioritize linguistic fluency over factual correctness.

Finally, there is the problem of **value misalignment**. Unless judging prompts explicitly encode desired ethical principles, fairness requirements, or context-specific norms, the LLM may favor responses that fail to meet key alignment criteria. This is especially problematic in evaluations involving safety, bias, or user trust.

> **Self-Preference Bias in GPT-4**
>
> In a 2023 OpenAI internal study, `GPT-4` was tasked with judging outputs from itself and other models. The results showed that `GPT-4` preferred its own completions 70% of the time, raising concerns about bias when using same-family models as judges. This led to new best practices in prompt balancing and cross-model evaluation.
