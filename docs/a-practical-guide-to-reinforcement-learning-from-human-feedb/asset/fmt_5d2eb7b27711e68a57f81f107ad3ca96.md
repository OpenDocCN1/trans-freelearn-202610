
# Batch vs Online RL

In `Batch RL` or `Offline-RL`, the agent learns from a fixed dataset collected offline, and experiences are from some past interactions, but there is no interaction with the environment during learning. `Online-RL` is typical case where the agent learns by interacting with the environment and consistently updating policy or value function as part of the learning process, as the observations are gathered during the experience.

# Exploration-Exploitation Strategies

`RL` algorithms can also be categorized based on how the agent balances exploration and exploitation during training. When an agent tries new actions, discovers new scenarios, and how these new actions affect evolution of states and resulting rewards, it is called exploration. When an agent tries to maximize actions that are known to yield high reward, without taking risk with new actions, it is called exploitation. Some examples are `epsilon-greedy`, `Boltzmann exploration`, `Upper Confidence Bound`, and `Thompson Sampling`.

While the categorization of `RL` algorithms can be exhaustive, many of the algorithms fit within several of the categories above. For the purpose of `RLHF`, we will focus on a few key base algorithms, e.g. `Q-learning` in this chapter for value-based algorithm approach, and later introduce policy-based approach also in following chapters. # Navigating RL Environments: A Grid World Environment

In `RL`, agent-environment interaction is the scenario that needs to be optimized. In order to optimize this scenario, agents take optimal actions leading to desirable states. The sequence of actions that lead to optimal states is the policy. To train an agent, real world environments could be used. But, they can be dangerous, expensive, and sometimes inefficient. Training an agent to learn sufficiently complex policies can require millions of iterations. This is where simulations of real world environments can be helpful. While simulations may not capture the real world completely, only capturing relevant information and environmental properties that lead to state transitions relevant in real world are sufficient in many industrial and real world problems. In some cases, simulation scenarios and real world have a gap and pose a difficulty during real-world implementation, often termed as `sim2real gap`. This is more significant where simulation model involves physics and three-dimensional geometry based assets, and less of a problem for text, image, or applications where upon deployment of agents, the end environment is still a digital world. In this chapter, we introduce a grid world representation of the real world. The simplified environment will help us with the focus needed in learning the `RL` related concepts, without needing the cognitive overhead of a complex domain. The environment consists of a grid of cells. Each cell can be either accessible or inaccessible, forming a layout of the world. The agent is positioned in one of the cells within the grid. The agent can take actions to move from one cell to another. Using the state-action-reward framework, we define them in context of the grid world problem.

## Grid World Components

### States
Each cell in the grid represents a state of the environment. The state of the environment changes as the agent moves around the grid.

### Actions
The agent can take actions to move around the grid. Typically, the agent can move up, down, left, or right. However, depending on the variant of the problem, some actions may be unavailable due to obstacles or boundaries.

### Rewards
Each cell in the grid may have a reward associated with it. The agent's objective is usually to maximize its total reward over time. Rewards can be positive, negative, or zero.

### Terminal States
Some cells in the grid may be designated as terminal states. When the agent enters a terminal state, the episode ends, and the agent may either receive a final reward or not, depending on the problem setting.

### Policy
The policy determines the agent's behavior in the environment. It maps states to actions, guiding the agent on how to select actions in different states to achieve its goal, which is often to maximize cumulative rewards.

### Transition Dynamics
Moving from one state to another may not always be deterministic. There could be stochasticity involved, such as wind blowing the agent off course or the agent slipping in icy terrain.

## Building the GridWorld Environment

To create a gridworld representation of the world, we first create a `GridWorld` class in python. Here are steps for building the gridworld environment.

### Initializing the Environment

The `__init__` method initializes the grid world environment with its parameters such as `grid_size`, `obstacle_positions`, `start_position`, and `goal_position`. Number of states is initialized to the size of the grid. It also initializes `Q_values` for each state-action pair to zero.

```python
def __init__(self, grid_size, obstacle_positions):
    self.grid_size = grid_size
    self.start_position = (2, 2)
    self.goal_position = (5,5) #(grid_size[0] - 1, grid_size[1] - 1) for generalizing
    self.obstacle_positions = obstacle_positions
    self.actions = [(0, 1), (0, -1), (1, 0), (-1, 0)]  # right, left, down, up
    self.action_symbols = ['→', '←', '↓', '↑']  # Action symbols for visualization
    self.num_actions = len(self.actions)
    self.num_states = np.prod(self.grid_size)
    self.Q_values = np.zeros((self.num_states, self.num_actions))
```

### Methods for Constructing the Simulator

Then, we add an additional method to construct the grid world simulator. Below are methods for converting `state (i, j)` to its corresponding index in the `Q_values` array for that state, and vice-versa given index in the `Q_values` array to its corresponding `state (i, j)`.

```python
def state_to_index(self, state):
    return state[0] * self.grid_size[1] + state[1]

def index_to_state(self, index):
    return (index // self.grid_size[1], index % self.grid_size[1])
```
