
## Encoder-Decoder Structure

### The Encoder

The encoder processes the input sentence, performing several layers of multi-head attention and feed-forward networks to transform the input into a rich representation.

### The Decoder

The decoder generates the output sentence (such as a translation) by using both the previous words in the output sequence and the encoder’s representations of the input. Each decoder layer performs **self-attention** to focus on the output sequence generated so far and **encoder-decoder attention** to focus on the input sequence’s encoding. The decoder continues this process until the full output sequence is generated.

Typically, the positional encoding is applied before the input is passed through the encoder layers. The encoder class can be written as below integrating positional encoding and transformer encoder layer:

```python
class TransformerEncoderLayer(nn.Module):
    def __init__(self, d_model, num_heads, d_ff, dropout_rate=0.1):
        super(TransformerEncoderLayer, self).__init__()
        self.attention = MultiHeadAttention(d_model, num_heads)
        self.ffn = nn.Sequential(
            nn.Linear(d_model, d_ff),
            nn.ReLU(),
            nn.Linear(d_ff, d_model)
        )
        self.layernorm1 = nn.LayerNorm(d_model)
        self.layernorm2 = nn.LayerNorm(d_model)
        self.dropout1 = nn.Dropout(dropout_rate)
        self.dropout2 = nn.Dropout(dropout_rate)

    def forward(self, x, mask):
        attn_output = self.attention(x, x, x, mask)
        out1 = self.layernorm1(x + self.dropout1(attn_output))  # Residual connection
        ffn_output = self.ffn(out1)
        return self.layernorm2(out1 + self.dropout2(ffn_output))  # Residual connection
```

```python
class TransformerEncoder(nn.Module):
    def __init__(self, d_model, num_heads, d_ff, num_layers, dropout_rate=0.1):
        super(TransformerEncoder, self).__init__()
        self.positional_encoding = PositionalEncoding(d_model, dropout_rate)
        self.enc_layers = nn.ModuleList([TransformerEncoderLayer(d_model, num_heads, d_ff, dropout_rate) for _ in range(num_layers)])

    def forward(self, x, mask):
        x = self.positional_encoding(x)
        for layer in self.enc_layers:
            x = layer(x, mask)
        return x
```

```python
def test_transformer_components():
    pos_encoding = PositionalEncoding(d_model=64)
    sample_input = torch.randn(10, 50, 64)  # (batch_size, seq_len, d_model)
    pos_encoded_output = pos_encoding(sample_input)
    assert pos_encoded_output.shape == sample_input.shape, "Positional encoding test failed!"
    self_attn = MultiHeadAttention(d_model=64, num_heads=8)
    attn_output, _ = self_attn(sample_input, sample_input, sample_input)
    assert attn_output.shape == sample_input.shape, "Multi-head attention test failed!"
    enc_layer = TransformerEncoderLayer(d_model=64, num_heads=8, d_ff=256)
    encoder_output = enc_layer(sample_input, None)
    assert encoder_output.shape == sample_input.shape, "Encoder layer test failed!"
    print("All tests passed!")

test_transformer_components()
```

For tasks like text generation, the decoder layer is responsible for generating tokens sequentially. It uses masked self-attention to ensure that future tokens are not visible to the model, preserving autoregressive behavior. The decoder is similar to the encoder in structure but with key differences:

*   **`Masked Multi-Head Attention`**: This ensures that when predicting the next token, the decoder only attends to the tokens generated so far, not future tokens. This masking is crucial for auto-regressive tasks, where you want to generate sequences step by step.
*   **`Cross-Attention Layer`**: In addition to the self-attention (like in the encoder), the decoder has an extra attention layer that attends to the output from the encoder. This allows the decoder to focus on relevant parts of the input sequence while generating the output.

In practice, transformer implementations use distributed training frameworks to improve training efficiency, and can have very complex implementations. There are, however, several libraries with transformer implementations e.g. `PyTorch`, `HuggingFace` and `TensorFlow` have transformer implementations. In this chapter we have shown encoder and representation learning snippets above. The decoder aspect is necessary for sequence generation, and we will continue henceforth using transformer library to simplify implementation, and focus more on fine-tuning aspects with pretrained models rather than training language models from scratch. ## Fine-Tuning Language Models

In this section we will first understand how pretrained language models can be loaded, and then step through the process of fine-tuning. Pretrained language models are models with transformer architecture that have been already trained on a body of data, in this case text data. This significantly saves time when we are trying to solve similar problems where previously learned skills or representations can be utilized. Fine-tuning on pretrained models also helps with reducing carbon footprint, as training of large models requires lot of energy.

We will now explore the `HuggingFace` transformer library, which provides a variety of pretrained models and tools for various natural language processing (`NLP`) tasks like text classification, translation, and summarization. It is a popular library for working with state-of-the-art transformer models. Moreover, it also enables performing tasks across multiple modalities such as text, vision and audio. In addition to transformer library, we will also use the `datasets` library from `Hugging Face` that provides easy access to a wide range of datasets and utilities for data processing. Using the `datasets` library simplifies tasks like loading, transforming, and preprocessing datasets, common to workflows of training machine learning models. This simplification will allow us to focus on using these datasets to infer from pretrained models, and later fine-tune them with specific data.

Unlike traditional machine learning workflows, fine-tuning model workflow involves model selection, fine-tuning and evaluation phase, instead of training and evaluation phase. There exist some similarities with `ML` workflow, as far as data preparation phase is concerned. In Figure 4, we can see that the workflow can be divided into three phases: 1) Data preparation that includes collection, exploratory analysis, and preprocessing, 2) model selection, tuning the model and evaluating, 3) Deployment, monitoring and maintenance. The first and third phases are similar to traditional machine learning workloads, so we will mainly rely on `datasets` libraries for the first phase, which has a variety of datasets.
