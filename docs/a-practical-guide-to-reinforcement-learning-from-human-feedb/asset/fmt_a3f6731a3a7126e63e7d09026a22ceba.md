
## RLCD

RLCD generates contrastive responses using positive and negative prompts. A simple example function for generating RLCD response pairs is as follows:

```python
def generate_response(prompt, max_length=50):
    inputs = tokenizer(prompt, return_tensors="pt")
    output = model.generate(**inputs, max_length=max_length, do_sample=True, temperature=0.7)
    return tokenizer.decode(output[0], skip_special_tokens=True)
```

```python
def rlcd_generate_preference_pair():
    pos_prompt = "Describe the weather in an optimistic way."
    neg_prompt = "Describe the weather in a depressing way."
    response_pos = generate_response(pos_prompt)
    response_neg = generate_response(neg_prompt)   
    return response_pos, response_neg  # Preference pairs
```

RLCD offers a scalable alternative to human-labeled comparisons by generating contrastive preference pairs through prompt engineering, reducing label noise and improving alignment quality. However, it still relies on reward models. The next step in simplifying alignment is to bypass reward modeling entirely—through Direct Large Model Alignment.

## Direct Large Model Alignment

While **RLCD** eliminates the need for human annotations, it still requires careful prompt design to generate the contrastive pairs. Furthermore, it relies on a teacher model to guide the learning process, which adds complexity to the training pipeline and may result in inefficiencies if the teacher model is not perfectly aligned. DLMA leverages contrastive prompt pairs to automatically generate preference data, which is then evaluated using the same contrastive approach to calculate a self-rewarding score. This method achieves alignment without the need for human-annotated preference data and, when combined with **Direct Preference Optimization (DPO)**, outperforms traditional RLHF in certain contexts. DPO, which replaces the reinforcement learning step in policy optimization, will be discussed in greater detail in Chapter 10. Rather than requiring an explicit reward model, DLMA evaluates its self-generated data through contrastive scoring, making the reward modeling process implicit and automated. The self-rewarding mechanism assigns numerical preference scores to responses, enabling the model to fine-tune itself without relying on external rewards. DPO fine-tunes the model directly using these self-generated preference pairs. Unlike PPO in RLHF, DPO aligns the model without requiring online reinforcement learning, reducing instability and simplifying the training process. For an in-depth realization of DLMA, you can refer to this paper, Direct Language Model Alignment from Online Feedback: [https://arxiv.org/abs/2402.04792](https://arxiv.org/abs/2402.04792). To realize the DLMA preference data generation and scoring, and compare with RLCD, you can implement in a simple snippet as follows. First write a function for self-rewarding score using full sequence log probabilities. The `dlma_generate_and_score` function generates multiple responses and assigns a self-rewarding score based on token log probabilities. A function to compute normalized log probability score for an entire response sequence, `compute_log_prob` helps with calculating mean log probability over the sequence, which is used as score of the response. The logits calculation first ignores last token since its not used in input `outputs.logits[:, :-1, :]`. Using `inputs.input_ids[:, 1:]` shift labels to align with logits, then use `torch.nn.functional.log_softmax` to calculate log probabilities `log_probs` that actually converts these logits into log-probabilities over the **entire vocabulary** (logits transformed via `log_softmax`). The gather method of `log_probs` helps in extracting the log probabilities **only for the correct next token** at each position in the sequence.

```python
def dlma_generate_and_score():
    prompt = "Describe the weather today, with extreme optimism or pessimism."
    response_1 = generate_response(prompt)
    response_2 = generate_response(prompt)
    def compute_log_prob(response):
        inputs = tokenizer(response, return_tensors="pt")
        with torch.no_grad():
            outputs = model(**inputs)
            logits = outputs.logits[:, :-1, :]
            labels = inputs.input_ids[:, 1:]
            log_probs = torch.nn.functional.log_softmax(logits, dim=-1)
            selected_log_probs = log_probs.gather(2, labels.unsqueeze(-1)).squeeze(-1) 
            return selected_log_probs.mean().item()
    score_1 = compute_log_prob(response_1)
    score_2 = compute_log_prob(response_2)
    return (response_1, score_1), (response_2, score_2)
```

We take the **mean log probability** to score the overall response, giving a **single number** as a **self-rewarding score.** You can experiment with the notebook `RLCD_DLMA_play.ipynb` from github repository in the directory for this chapter. Try changing the prompt for another example. Note that DLMA generates a response and also scores it, in comparison to RLCD where it generates a pair of responses that can be scored by another model.

## Self Improving Methods

Self improving methods do not use explicit feedback, are self-improving based on and relying on generated examples and self-evaluations. So, they can be potentially unstable, unless carefully designed and setup. But, they do have minimal human involvement.

### Rewindable Auto-regressive Inference

RAIN represents an approach that enables frozen, pre-trained LLMs to improve alignment without any additional training or parameter updates. The method integrates self-evaluation and **rewind** mechanisms that allow models to assess their own generations and use these evaluations to guide rewinding and regeneration for improved safety. The key aspect of RAIN involves searches on tree with token sets and dynamically reducing weights on harmful token sets, backward rewinding from such token sets and forward generating other tokens until the output is self-evaluated as harmless. The method mimics human behavioral patterns such as contemplating, weighing, and reflecting on consequences before speaking. Remarkably, RAIN operates without extra alignment data or gradient computation, and has shown improvement in the harmlessness rate of LLaMA 30B while maintaining helpfulness. You can review more here: RAIN: Your Language Models Can Align Themselves without Finetuning: [https://arxiv.org/abs/2309.07124](https://arxiv.org/abs/2309.07124).
