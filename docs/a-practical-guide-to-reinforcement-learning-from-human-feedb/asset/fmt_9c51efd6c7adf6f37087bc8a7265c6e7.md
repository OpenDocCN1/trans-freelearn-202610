### Step 4: Optimize for Memory Efficiency

Training even small language models using RLHF can strain memory. To mitigate this, apply the following memory-saving strategies:

*   **Use mixed-precision training** (`fp16` or `bf16`) when supported, using `accelerate` or trainer configs.
*   **Enable gradient checkpointing**, which trades compute for memory by recomputing intermediate activations during backpropagation.
*   **Adjust batch size** and **sequence length** to fit within available memory.
*   Monitor memory usage actively with: `!nvidia-smi`

## Settings and Configurations for Memory Optimization and Reproducibility

For running notebook experiments, it is crucial to be able to reproduce experiments, and improve iteratively. One of the best practices to keep notebook results relatively reproducible is to set a seed for randomization. A snippet of seed settings to enable reproducibility is as follows:

```
SEED = 42
torch.manual_seed(SEED)
np.random.seed(SEED)
set_seed(SEED)
```

Here, we are using a lightweight model, `gpt2`, in order to reduce memory usage. In addition to this choice, there are a few more parametric trimmings that we are using here. For the example we consider, we will limit generated text length by keeping `MAX_NEW_TOKENS = 32`, a small batch size for memory efficiency `BATCH_SIZE = 2 or 4`, truncated sequence length `MAX_SEQ_LENGTH = 32`, and a small number of training samples `NUM_SAMPLES = 4000`, and `NUM_EPOCHS = 2`. To ensure stable training and efficient memory usage, we use optimizations such as gradient checkpointing and mixed precision (set to true for larger models).

```
# Configuration - Memory-optimized settings
MODEL_NAME = "gpt2" 
MAX_NEW_TOKENS = 32 
BATCH_SIZE = 4 
MAX_SEQ_LENGTH = 32 
LR = 1.5e-5
NUM_EPOCHS = 2 
NUM_SAMPLES = 4000 
OPTIMIZE_MEMORY = True
if OPTIMIZE_MEMORY:
    # Enable gradient checkpointing (trades computation for memory)
    os.environ["PYTORCH_CUDA_ALLOC_CONF"] = "expandable_segments:True"
    MIXED_PRECISION = False
```

To optimize memory usage during training, particularly when working with large models or batch processing, it is useful to define a utility function to clear unused memory resources. The function `clear_memory()` invokes Python’s garbage collector and clears the CUDA cache, while also resetting peak memory statistics. It is important to exercise caution and call this function **only between training batches or iterations** to avoid disrupting active computations. Incorporating `clear_memory()` at appropriate points within the training loop can help mitigate out-of-memory errors and maintain efficient GPU memory utilization:

```
def clear_memory():
    import gc
    gc.collect()
    if torch.cuda.is_available():
        torch.cuda.empty_cache()
        torch.cuda.reset_peak_memory_stats()
```
