
## Dataset Preparation

It contains human-written prompts along with assistant responses labeled as `chosen` (preferred) and `rejected` (less preferred). For efficient fine-tuning, we preprocess the dataset by extracting prompts and their respective `chosen` and `rejected` responses. In addition, we filter out overly long prompts for memory efficiency and handle potential formatting inconsistencies. Prompts and responses are tokenized and formatted for use in the `RLHF` training loop. An example function that preprocesses the dataset is shown as follows:

```python
def prepare_dataset(dataset):
    data_dict = {'prompt': [], 'chosen': [], 'rejected': []}
    for item in dataset:
        try:
            prompt = item['chosen'].split('Human:')[-1].split('Assistant:')[0].strip()
            chosen = item['chosen'].split('Assistant:')[-1].strip()
            rejected = item['rejected'].split('Assistant:')[-1].strip()
            if len(prompt.split()) < 100:
                data_dict['prompt'].append(prompt)
                data_dict['chosen'].append(chosen)
                data_dict['rejected'].append(rejected)
        except:
            continue
    return pd.DataFrame(data_dict)prepare dataset
```

To efficiently fine-tune `RLHF` models, we define a custom dataset class that processes the `Helpful-Harmless` dataset. The preprocessed dataset consists of prompts, along with assistant responses labeled as `chosen` and `rejected`. To optimize memory usage, the class pre-tokenizes the prompts and stores them as memory-efficient tensors. The tokenized data is then fed directly into the `PPOTrainer`, where it is used for fine-tuning the policy network. This avoids redundant tokenization calls during training. The dataset class also ensures that input sequences are properly truncated to a fixed length for consistent model training. While you can check full implementation of the class with comments in the notebook expanding into methods for getting additional attributes, an example trimmed version is shown as follows.

```python
class RLHFDataset(Dataset):
    def __init__(self, data, tokenizer, max_length=MAX_SEQ_LENGTH):
        self.tokenizer = tokenizer
        self.prompts = data['prompt'].tolist()
        self.max_length = max_length
        self.input_ids = []
        self.attention_masks = []
        self.preprocess()
    def preprocess(self):
        for prompt in self.prompts:
            encodings = self.tokenizer(
                prompt,
                truncation=True,
                max_length=self.max_length,
                padding="max_length",
                return_tensors="pt"
        )     
        self.input_ids.append(encodings['input_ids'].squeeze())
        self.attention_masks.append(encodings['attention_mask'].squeeze())
```

## Reward Model Setup

The `RewardTrainer` method from the `TRL` library implements a `pairwise preference–style reward modeling` approach. It trains a reward model using `chosen vs. rejected` response pairs — as we explored in depth in Chapter 7. In this chapter, instead of training from scratch, we demonstrate how to use a `pretrained reward model`. A strong option is `OpenAssistant/reward-model-deberta-v3-base`, which is trained on human preference data and suitable for real `RLHF` fine-tuning:

```python
reward_tokenizer = AutoTokenizer.from_pretrained("OpenAssistant/reward-model-deberta-v3-base")
reward_model = AutoModelForSequenceClassification.from_pretrained(
    "OpenAssistant/reward-model-deberta-v3-base"
).to(DEVICE)
```

In early prototyping stages, you may consider using proxy reward signals from models like sentiment classifiers or toxicity detectors, which offer fast inference and easy integration. For example: `distilbert-base-uncased-finetuned-sst-2-english` provides a score based on sentiment (positive or negative). `unitary/toxic-bert` outputs toxicity likelihood to help penalize unsafe or harmful language. These models are standard classifiers and are **not trained on human preference data**, so their scores may not fully capture nuanced behaviors such as helpfulness, factual accuracy, or overall alignment. Nonetheless, they can be useful for quick experimentation or task-specific objectives like reducing toxicity. For this chapter, we use `OpenAssistant/reward-model-deberta-v3-base`, a purpose-built reward model trained on preference data, to demonstrate a complete and realistic `RLHF` training pipeline grounded in human-aligned reward signals. In `RLHF`, the policy model generates responses that are evaluated by a reward model, which assigns a scalar reward score reflecting human preference alignment. To efficiently compute rewards over multiple responses, we process the texts in small batches, tokenize them, and run inference through the reward model. The resulting scores are collected and returned as a list of reward tensors, which are then used to guide policy optimization in the `PPOTrainer`. An example implementation of the reward computation function, `compute_reward`, is shown below.

```python
def compute_reward(texts):
    batch_size = 4
    all_scores = []
    for i in range(0, len(texts), batch_size):
        batch_texts = texts[i:i + batch_size]
        inputs = reward_tokenizer(
            batch_texts,
            return_tensors="pt",
            padding=True,
            truncation=True,
            max_length=512,
        ).to(DEVICE)
        with torch.no_grad():
            outputs = reward_model(**inputs)
            scores = outputs.logits.squeeze(-1)
            all_scores.extend(scores.cpu().tolist())
    return [torch.tensor(score) for score in all_scores]
```

## Using LoRA for Efficient Fine-Tuning

Fine-tuning large language models can be memory-intensive. To address this, we use `LoRA` (Low-Rank Adaptation)—a `PEFT` method discussed in Chapter 6. `LoRA` introduces trainable low-rank matrices into attention and feedforward layers, drastically reducing the number of trainable parameters while keeping the base model frozen. We define a `LoRA` configuration and pass it into the model via the `peft_config` parameter:

```python
from peft import LoraConfig, TaskType
lora_config = LoraConfig(
    r=8,
    lora_alpha=16,
    target_modules=["c_attn", "c_proj", "c_fc"],
    lora_dropout=0.05,
    bias="none",
    task_type=TaskType.CAUSAL_LM
)
```

## Model Initialization

To efficiently manage memory while fine-tuning a language model using `RLHF`, we carefully sequence the loading of models, tokenizer, and dataset. Before initializing any components, we invoke the utility function `clear_memory()` to release unused memory resources and prevent unnecessary peak allocation. The primary language model we fine-tune is `gpt2` (you may also use `distilgpt2`, a lighter distilled version) which we load using `AutoModelForCausalLMWithValueHead`. This wrapper from the `trl` library allows integration of a scalar value head used in `PPO`-based `RLHF` training. We enable **gradient checkpointing** to reduce memory consumption during backpropagation, trading off some additional computation. The reference model (`ref_model`) is then loaded separately to avoid GPU memory spikes. It is a frozen copy of the policy model and serves as a comparison baseline during reward-based optimization. It is used during `PPO` training to compute `KL divergence` between the current and original model outputs.

```python
clear_memory()
model = AutoModelForCausalLMWithValueHead.from_pretrained(
    MODEL_NAME,  # e.g., "gpt2"
    peft_config=lora_config,
    use_cache=not OPTIMIZE_MEMORY
)
# Optionally enable gradient checkpointing

# torch.compile(model)  # Optional with PyTorch 2.x
clear_memory()
ref_model = AutoModelForCausalLMWithValueHead.from_pretrained(
    MODEL_NAME,
    peft_config=lora_config,
    use_cache=not OPTIMIZE_MEMORY
)
```
