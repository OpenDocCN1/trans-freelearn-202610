
In real-world scenarios, human preferences might involve multiple aspects. These models learn to assign rewards considering these objectives simultaneously (e.g., `Absolute-Rating Multi-Objective Reward Model` (`ArmoRM`) as discussed in `Interpretable Preferences via Multi-Objective Reward Modeling and Mixture-of-Experts`: [https://arxiv.org/abs/2406.12845](https://arxiv.org/abs/2406.12845)).

## Inverse Reinforcement Learning (IRL)

`Inverse Reinforcement Learning` (`IRL`) aims to infer the underlying reward function from observed expert behavior. `IRL` is based on the premise that expert behavior is optimal with respect to some unknown reward function. By observing the actions taken by an expert, `IRL` attempts to reverse-engineer the reward function that the expert is implicitly optimizing. This involves two major steps:

1.  **Expert Demonstrations**: Collect trajectories or sequences of states and actions from experts performing the task. These trajectories represent the expert’s behavior and serve as the primary data for `IRL`.
2.  **Reward Function Estimation**: Use optimization techniques to infer the reward function that would make the observed expert behavior appear optimal. This involves formulating the problem as an optimization task where the objective is to find the reward function that best explains the expert’s actions.

All the reward modeling methods differ in what human signals are collected and how they are used to predict rewards. They involve a common supervised learning step of using input data and training a model that learns to predict an output, which is a reward. It can be used to learn complex reward functions that are difficult to define manually, especially in large or dynamic environments. The model can be potentially fine-tuned with additional data to adapt to slightly modified environments or goals, making it more adaptable and scalable. Readers can refer to `Maximum Entropy Inverse Reinforcement Learning`: [https://cdn.aaai.org/AAAI/2008/AAAI08-227.pdf](https://cdn.aaai.org/AAAI/2008/AAAI08-227.pdf) for further information.

## Reward Model Class

The `RewardModel` class, in the `reward_models.py` file in the repository, defines the architecture of the neural network based model for predicting rewards. It inherits from `nn.Module` and defines a feedforward neural network that will be trained. `nn.Module` is a fundamental class in PyTorch, a popular deep learning library, used for building neural networks. Inheriting from `nn.Module` allows `RewardModel` to access functionalities for building neural network layers. This function initializes the model's parameters during creation. It takes three arguments: `state_size`: The dimension of the agent's state representation (e.g., robot's position). Here, it's set to 2 (adjustable for your specific problem). `hidden_size`: The number of neurons in the hidden layer, controlling the model's complexity (set to 64 here). `output_size`: The number of reward values the model outputs. In this example, it's set to 3, likely corresponding to multiple reward categories (e.g., progress, safety, and goal-efficiency). The model consists of two fully-connected layers (`fc1` and `fc2`). `fc1`: Takes the concatenated state and next state (combined size `state_size * 2`) as input and feeds it through a `ReLU` activation function. This layer extracts relevant features from the combined state information. `fc2`: Takes the output from the first layer and transforms it into the desired number of rewards (`output_size`).

```python
# RewardModel class definition
class RewardModel(nn.Module):
    def __init__(self, state_size=2, hidden_size=64, output_size=3):
        super(RewardModel, self).__init__()
        self.fc1 = nn.Linear(state_size * 2, hidden_size)  # Adjusted to take both state and next_state as input
        self.fc2 = nn.Linear(hidden_size, output_size)  # Output 3 rewards: progress, safety, and goal-efficiency
    def forward(self, state, next_state):
        x = torch.cat((state, next_state), dim=1)  # Concatenate state and next_state
        x = torch.relu(self.fc1(x))
        rewards = self.fc2(x)
        return rewards
```

The `forward` function defines how the data flows through the network. It takes the current state and the next state as input arguments. It concatenates the state and next state to create a single input for the network. The combined state information is then passed through the first layer with a `ReLU` activation. Finally, the output from the first layer is fed into the second layer, resulting in the predicted rewards. By training this `RewardModel` with human feedback data, the model learns to associate specific state transitions with rewards that align with human preferences. This information is then used to guide the RL agent towards behaviors that are deemed desirable by humans. This is just the first step in RLHF integration. ## Incorporating Human Feedback in Reward Design

Among the discussed reward modeling techniques, preference-based learning, absolute rating models and multi-objective reward models are suitable for direct feedback integration of human signals. Directly integrating human feedback is often preferred over relying solely on `Inverse Reinforcement Learning` (`IRL`) due to its limitations in gathering human feedback:

*   **Indirectness:** `IRL` infers the reward function based on observations. This can be prone to errors and biases in the observed behavior.
*   **Complexity:** `IRL` algorithms can be computationally expensive, especially for complex tasks or when human demonstrations are limited.
*   **Limited Scope:** `IRL` typically focuses on inferring the reward function from actions. It might miss out on broader human preferences or values not directly captured by the observed behavior.

### Examples of Direct Feedback Integration

To integrate direct human feedback into the RL system, there have been at least three practiced methods that are most used:

*   **Reward Labeling:** Humans directly label different states or actions with positive, negative, or neutral rewards.
*   **Preference Learning:** Humans express their preferences between different outputs generated by the agent, guiding the agent towards more desirable behavior.
*   **Evaluative Feedback:** Humans provide written or spoken evaluations of the agent's outputs, which can then be used to refine the reward signal.

In summary, RLHF often favors direct feedback integration because it allows for clear, efficient, and flexible ways to incorporate human values into the training process. While `IRL` offers valuable insights, the ability to directly leverage human preferences often leads to more robust and human-aligned RL agents. Note, however, that there are applications where immediate human preferences might not be feasible to collect (e.g., in real-time dynamic scenarios), and human demonstration would require to be relied upon, for example in case of autonomous driving where human actions and behavior can be acquired from demonstrations of driving.
