
# Continuous Mountain Car and PPO

In the discrete action Mountain Car environment, the agent has a limited set of predefined actions (e.g., move left, move right, do nothing). However, in the continuous version, the agent can choose from a wide range of actions, which is more realistic for many real-world problems. Here, we will use the continuous version of the mountain car simulator. The difference here is that actions can be any number between -1 and 1. There are more details on simulator details documented in [https://gymnasium.farama.org/environments/classic_control/mountain_car_continuous/](https://gymnasium.farama.org/environments/classic_control/mountain_car_continuous/), but we will discuss the relevant system dynamics and rewards for completeness.

In case of discrete action Mountain Car, there is a negative reward of -1 for every timestep, until the episode terminates when the car climbs the mountain and reaches the flag. It is a sparse scenario but incentivized to keep episodes short. For the continuous-action mountain car, a negative reward of `\-0.1 x action^2` is received at each timestep to penalize for taking actions of large magnitude. If the mountain car reaches the goal, then a positive reward of +100 is added to the negative reward for that timestep. Since large actions also create momentum and help with climbing and reaching the goal, this is a more difficult credit assignment. In real-world scenarios, assigning rewards can be difficult so, we will continue to use rewards from the `gymnasium` library for keeping focus on the algorithm here in lieu reward shaping.

In previous sections we realized that DQN is effective for discrete action spaces, but cannot be directly applied to continuous action spaces because DQN would require discretizing the action space, which isn't ideal for environments with a large or infinite number of possible actions. Policy gradient methods on the contrary are a natural solution for continuous action spaces, since they allow the agent to learn a parameterized policy that can produce actions from a continuous range by modeling the action probability distribution. The vanilla policy gradient algorithm uses a stochastic policy to map states to actions, optimizing this policy using rewards from the environment. However, it requires baseline subtraction to reduce variance, as discussed in advantage actor critic algorithm, and further improved stabilization of learning using generalized advantage estimates (GAE). To further improve learning stability and monotonic improvement, we add further improvements on top of GAE, using PPO algorithm, one of the key updates being a clipping mechanism to prevent large updates in policy.

Continuous control mountain car can have a wider exploration region of states and actions, leading a more complex learning and requiring longer simulation and training. Therefore, we need to apply some techniques for accelerating training. One of the common approaches is using vectorized environments that parallelizes training, as we will discuss in the following section.

## Accelerating Training Using Vectorized Environments

To accelerate training, it is very common in RL practices to use vectorized environments. Vectorization involves setup where multiple independent instances of the same environment are run simultaneously. Instead of interacting with a single environment at a time, the agent interacts with several environments in parallel. Each environment operates independently and might be in a different state. Since these environments run in parallel, either on separate CPU cores or using efficient multiprocessing techniques, the time spent waiting for the environment's feedback (i.e., the next observation and reward) is reduced significantly. In addition, the agent can collect a larger batch of experiences in a shorter period. The Gymnasium library provides built-in support for vectorized environments through the `gym.vector` module.

A simple code example of implementing vectorized environments for mountain car continuous action problem with random action samples is as below snippet of code. This below code first imports the gymnasium library, and creates a vectorized environment with 4 copies of MountainCar environment, specifically for `MountainCarContinuous-v0` version. The observations for all of the environments are collected by resetting the vectorized environments. For demonstration purposes, we run 100 iterations or number of steps of the vectorized environments, and for each iteration first sample the actions randomly using the `action_space.sample` method for each of the environments, and step through each of the them using the `step` method. Then, we handle each of the environment episodes based on whether `dones` variables is True, and print the terminated episodes and corresponding rewards. In the complete implementation, you can log these and also plot them to monitor episodes and debug training if required. This is followed by closing the environment using `close` method.

```
import gymnasium as gym
env = gym.vector.make('MountainCarContinuous-v0', num_envs=4)
observations = env.reset()
for _ in range(100):
    actions = env.action_space.sample()
    observations, rewards, dones, infos = env.step(actions)
    for i in range(4):
        if dones[i]:
            print(f"Episode {i} finished with reward {rewards[i]}")
# Close the environments
env.close()
```

## Key Updates for Implementing PPO

Training of continuous action spaces is relatively more difficult in comparison to discrete action spaces, as it has a much larger action space. As a result, the training time for continuous action environments is much longer than for discrete action environments. To accelerate training, and improve training stability and other training related improvements, several techniques are implemented for PPO algorithms. We will go over these:

*   **Clipped Objective Function (Surrogate Loss):** Introduces a `clipped objective` to prevent large updates to the policy, which can lead to instability. The ratio of new policy probability to old policy probability is clipped within a certain range, ensuring that updates are small and controlled.

*   **Multiple Epochs per Batch:** Allows `multiple epochs` of optimization on the same batch of data, which increases the sample efficiency. The policy is updated several times using the same data, extracting more information from each collected batch.

*   **Value Function Loss:** Adds more flexibility by allowing `separate learning rates` for the policy (actor) and the value function (critic). This allows fine-tuning of learning for each component, leading to better convergence. (PPO also optionally includes a `clipped value function loss`, similar to the policy objective clipping, to avoid overfitting the value function to the current policy.)

*   **Entropy Regularization:** Maintains exploration by encouraging a certain level of randomness in the policy, preventing it from becoming too deterministic.

*   **Mini-batch Updates:** Uses `mini-batch` updates, which further increases sample efficiency and stabilizes learning. Smaller mini-batches allow more gradient updates and smoother policy changes over time.
