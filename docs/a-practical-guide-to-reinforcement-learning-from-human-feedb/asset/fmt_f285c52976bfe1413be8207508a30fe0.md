## Overview and Motivation

We start with motivating the use of DPO for trajectory alignment, outlining the pipeline. For complete DPO introduction and generic pipeline, you can refer to Chapter 10. For trajectory smoothening, the pipeline involves following steps.

1. Generate synthetic driving trajectories with different behavioral patterns (smooth, jittery, aggressive, centered)
2. Create preference pairs based on trajectory smoothness and lane centering
3. Train a neural policy using DPO to learn human preferences for smooth, centered driving
4. Evaluate the learned policy on trajectory quality metrics

## Synthetic Data Generation

To enable rapid experimentation, the notebook generates synthetic driving scenes that mimic `CARLA` front-camera views. This includes different driving behaviors (smooth, jittery, aggressive, centered), with code for both frame rendering and trajectory generation. Frame rendering is a simple synthetic road frame: road, lane divider, and a car center offset by `x_offset` and `y_offset`.

```
def render_synthetic_frame(x_offset, y_offset, speed=1.0, img_h=IMG_H, img_w=IMG_W):
    img = Image.new("RGB", (img_w, img_h), (100, 120, 120))
    draw = ImageDraw.Draw(img)
    # road rectangle
    draw.rectangle([int(img_w*0.1), 0, int(img_w*0.9), img_h], fill=(40,40,40))
    # lane center line (dashed)
    for i in range(0, img_h, 8):
        draw.rectangle([img_w//2-2, i, img_w//2+2, i+4], fill=(200,200,200))
    # add roadside color
    draw.rectangle([0,0,int(img_w*0.1),img_h], fill=(30,100,30))
    draw.rectangle([int(img_w*0.9),0,img_w,img_h], fill=(30,100,30))
    # draw ego-car marker near bottom, offset by x_offset,y_offset
    cx = img_w//2 + int(x_offset)
    cy = int(img_h*0.8 + y_offset)
    draw.ellipse([cx-5, cy-5, cx+5, cy+5], fill=(255,60,60))
    # Add a debug print to verify x_offset is actually changing
    if abs(x_offset) > 0.1:
        print(f"Car at x_offset={x_offset:.1f}, cx={cx}")
    return np.array(img)

def gen_synth_traj(kind="smooth", traj_len=TRAJ_LEN):
    x = 0.0
    y = 0.0
    frames = []
    actions = []
    for t in range(traj_len):
        if kind == "smooth":
            dx = np.clip(np.random.randn()*0.8, -2,2)  # gentle drift
        elif kind == "jittery":
            dx = np.random.randint(-25, 26)  # large jumps
        elif kind == "aggressive":
            dx = np.random.choice([-8, 8])
        elif kind == "centered":
            dx = int((0 - x)*0.2) + np.random.randint(-1,2)
        else:
            dx = np.random.randint(-4, 5)
        x = float(x + dx)
        action = 0 if dx < -0.5 else 2 if dx > 0.5 else 1
        actions.append(int(action))
        frames.append(render_synthetic_frame(x_offset=x, y_offset=y))
    return frames, np.array(actions, dtype=np.int64)
```

## Preference Scoring

A key step in preference-based RL is defining what makes one trajectory preferable to another. Here, a scoring function combines smoothness and lane centering, using robust red-pixel detection for the car marker.

### Preference Scoring: Defining "Good" Driving

We need to define what makes one trajectory better than another. Our scoring function combines:

* **Smoothness Score (70% weight)**, which measures how consistent the car's lateral position is across frames and penalizes large frame-to-frame movements. A higher smoothness score means smoother driving.
* **Centering Score (30% weight)** measures how close the car stays to the lane center, and penalizes deviation from the middle of the road. A higher score means better lane keeping.

These are realistic metrics from autonomous driving perspective. For the scope of this use case, we will just use these and apply a **red pixel detection** to reliably find the car marker. The color pixel detection is a more robust than brightness-based detection which could confuse lane lines with the car.

## Neural Network Architecture

We use a lightweight CNN as a frame encoder and a simple policy network, first trained via behavior cloning (supervised learning) and then fine-tuned with DPO. Our system includes a frame encoder, `frame_encoder`, a small CNN that converts 64×64 RGB frames into feature embeddings, and a policy network, `policy_ref` that maps these embeddings to action probabilities (left/straight/right).

```
class SmallFrameEncoder(nn.Module):
    def __init__(self, out_dim=64):
        super().__init__()
        self.net = nn.Sequential(
            nn.Conv2d(3, 16, 5, stride=2, padding=2), nn.ReLU(),
            nn.Conv2d(16, 32, 5, stride=2, padding=2), nn.ReLU(),
            nn.AdaptiveAvgPool2d((4,4)),
            nn.Flatten(),
            nn.Linear(32*4*4, out_dim), nn.ReLU()
        )
    def forward(self, x):
        return self.net(x)

frame_encoder = SmallFrameEncoder(out_dim=128).to(DEVICE)

# Policy model (reference policy)
class SimplePolicy(nn.Module):
    def __init__(self, emb_dim=128, num_actions=3):
        super().__init__()
        self.model = nn.Sequential(
            nn.Linear(emb_dim, 64), nn.ReLU(),
            nn.Linear(64, num_actions)
        )
    def forward(self, emb):
        return self.model(emb)  # logits

policy_ref = SimplePolicy(emb_dim=128, num_actions=3).to(DEVICE)
```
