
## Generating Human Feedback

Let us develop some functions that can help with generating representative human feedback data. First, we write a function that takes an agent's current state, the next state after taking an action, and information about the environment (goal location and obstacles) as input. It then calculates three reward components that mimic how a human might evaluate the agent's progress:

### Progress Reward

This reward incentivizes the agent to move closer to the goal. It calculates the distance between the next state and the goal position. The closer the agent gets, the higher the reward. This is achieved by using the `np.linalg.norm` function to compute the Euclidean distance between the next state and goal position, and then multiplying by -1 (as moving closer results in a smaller distance value).

### Safety Reward

This reward discourages the agent from entering obstacle locations. It assigns a penalty of -5 if the next state coincides with any obstacle position in the environment (provided in `obstacle_positions`). If the next state is safe (not an obstacle), the reward is 0.

### Goal Efficiency Reward

This reward encourages the agent to reach the goal directly. It grants a high reward (+10) if the agent reaches the goal state (according to `np.array_equal`), and a penalty of -1 otherwise.

By combining these rewards, the function provides a composite signal that reflects desirable behaviors for the agent: getting closer to the goal (positive progress reward), avoiding obstacles (positive safety reward), and reaching the goal efficiently (positive goal efficiency reward). However, the reward model allows the three rewards to be treated separately, and provides more control over deciding how these rewards could be combined at a higher level. This is similar to the multi-objective reward model, allowing reward rating per step of the trajectory.

```python
def simulate_human_reward(state, next_state, goal_position, obstacle_positions):
    next_state_array = np.array(next_state)
    goal_position_array = np.array(goal_position)
    progress_reward = -np.linalg.norm(next_state_array - goal_position_array)
    safety_reward = -5 if next_state in obstacle_positions else 0
    goal_efficiency_reward = 10 if np.array_equal(next_state_array, goal_position_array) else -1
    return np.array([progress_reward, safety_reward, goal_efficiency_reward])
```

The `generate_human_feedback` function generates a dataset of simulated human feedback for various state transitions within the gridworld environment. It takes the grid world's size, goal location, obstacle positions, and the desired number of samples (`num_samples`) as input. It also takes possible actions that the agent can take in the grid world environment: moving up, down, left, or right (represented by tuples like (0, 1) for up, `actions = [(0, 1), (0, -1), (1, 0), (-1, 0)]`), and initializes an empty list `data` to store the generated feedback samples. It iterates for `num_samples`, randomly samples a starting state (agent's position) within the grid world boundaries, selects an action from the available actions, and calculates the next state the agent would reach after taking the chosen action. Once it has the current state, next state, and the environment information (goal and obstacles), it calls the `simulate_human_reward` function to get the corresponding human-like rewards for this specific state transition. It appends a tuple containing the current state, next state, and the calculated rewards (progress, safety, and goal efficiency) to the `data` list. The function returns the generated dataset `data`, which serves as training examples for the `RewardModel`. This simulated feedback dataset provides a variety of scenarios for the `RewardModel` to learn from. By incorporating these rewards during training, the model learns to associate state transitions with human-preferred outcomes, allowing it to guide the RL agent towards behaviors that are considered desirable in the given environment.

## Training the Reward Model

The `train_reward_model` function takes the simulated human feedback data (`data` generated earlier) and trains the `RewardModel` class to predict those rewards accurately, as shown in the `reward_modeling.py` file in the repository, also added in the snippet on `train_reward_model` function as follows.

```python
def train_reward_model(data, state_size=2, hidden_size=64, output_size=2, num_epochs=100, batch_size=64, learning_rate=0.001):
    reward_model = RewardModel(state_size, hidden_size, output_size)
    optimizer = optim.Adam(reward_model.parameters(), lr=learning_rate)
    criterion = nn.MSELoss()
    for epoch in range(num_epochs):
        np.random.shuffle(data)
        batch_losses = []
        for i in range(0, len(data), batch_size):
            batch = data[i:i + batch_size]
            states = torch.tensor([item[0] for item in batch], dtype=torch.float32)
            next_states = torch.tensor([item[1] for item in batch], dtype=torch.float32)
            rewards = torch.tensor([item[2] for item in batch], dtype=torch.float32)
            optimizer.zero_grad()
            predictions = reward_model(states, next_states)
            loss = criterion(predictions, rewards)
            loss.backward()
            optimizer.step()
            batch_losses.append(loss.item())
        avg_loss = np.mean(batch_losses)
        print(f"Epoch {epoch+1}/{num_epochs}, Loss: {avg_loss:.4f}")
    return reward_model
```

The training process can be divided into three steps as follows:

### Setting Up the Model and Training Environment

It creates an instance of the `RewardModel` class, specifying the state size (based on the environment representation), hidden size (controls model complexity), and output size (number of predicted rewards – 3 in this case, combining progress, safety, and goal efficiency). It defines an optimizer (`optim.Adam`) to update the model's weights during training. This optimizer uses the learning rate (`learning_rate`) to control the step size of these updates. It defines a loss function (`nn.MSELoss`). This function measures the mean squared error (`MSE`) between the predicted rewards from the model (`predictions`) and the actual rewards provided in the human feedback data (`rewards`). Minimizing this `MSE` loss encourages the model to make predictions that closely match the human-provided rewards.
