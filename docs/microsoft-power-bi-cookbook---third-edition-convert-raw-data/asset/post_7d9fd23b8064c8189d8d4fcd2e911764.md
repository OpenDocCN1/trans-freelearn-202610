## How it works

The requirement for both visualizations in this recipe is to display the distribution of the product list prices that have been sold online in the current calendar year. The first example (steps 1 to 5) uses the standard hist() function with R's base graphics, and the second example (step 7) uses the ggplot() function provided by the ggplot2 package for R.

The light gray background color is set via the par() function, and arguments to the hist() function define the X- and Y-axes, the text strings for the titles, data labels, font sizes, and the light blue color of the bars. The seq() function is used to configure the X-axis intervals (bins), with a width or bin size of $500 and a maximum price of $2,500.

ggplot2's geom_histogram() function requires a continuous variable, and thus the ListPrice column is converted to a numeric data type in the prices variable. The vector expression (seq()) used for the X-axis (bins from 0 to 2,500 in increments of 500) in the prior example is used as the parameter for the breaks argument of geom_histogram() and stat_bin(). Likewise, the expression for the Y-axis in the prior example is reused but passed as a parameter to the coord_cartesian() function. The qplot() function, short for quick plot, is also available in the ggplot2 package, and it can result in the faster development of relatively complex visualizations with less code—often in just one line.

## Leveraging the WINDOW Function

The DAX function WINDOW is a relatively recent addition to the DAX language along with similar and related functions—INDEX, OFFSET, ORDERBY, and PARTITIONBY. These functions were released as part of an effort to bring visual-level calculations to Power BI.

In this recipe, the WINDOW function is used to compute a rolling 3-month average as well as a running total.

## Getting ready

To prepare for this recipe, follow these steps:

- 1. Download Leveraging the WINDOW Function Start.pbix from the following GitHub repository: https://github.com/PacktPublishing/Power-BI-Cookbook-Third-Edition.
- 2. Open Leveraging the WINDOW Function Start.pbix in Power BI Desktop.
- 3. Edit the AdventureWorks query, and change the Source line to point to your SQL server with the AdventureWorksDW2022 database installed.
- 4. Click Close & Apply from the ribbon of the Home tab.
- 5. Save your work.

## How to leverage the WINDOW function

To implement this recipe, carry out the following steps:

- 1. In the Table view, create the following measures in the Calculations table:

```
Internet Gross Sales = SUM('Internet Sales'[SalesAmount])
Internet Sales Discounts = SUM('Internet Sales'[DiscountAmount])
Internet Net Sales = [Internet Gross Sales] - [Internet Sales Discounts]
```

- 2. In the Report view, use the Filters pane to add a page filter for the CalendarYear column from the Dates table, and select 2012 and 2013 only.
- 3. Add a table visual, and place the CalendarYear and MonthNumberOfYear columns from the Dates table along with the Internet Net Sales measure in the Columns field well. Ensure that the CalendarYear and MonthNumberOfYear columns are set to Don't summarize.
- 4. Create the following two measures:

```
Internet Net Sales Running Total =
SUMX (
    WINDOW (
        1, ABS, 0, REL,
        ALLSELECTED (
            'Dates'[CalendarYear],
            'Dates'[MonthNumberOfYear]
        ),
        PARTITIONBY ( 'Dates'[CalendarYear] )
    ),
    [Internet Net Sales]
)
Internet Net Sales 3-Month Average =
AVERAGEX(
    WINDOW(
        -2,REL,0,REL,
        ALLSELECTED('Dates'[CalendarYear], Dates[MonthNumberOfYear]),
        ORDERBY('Dates'[CalendarYear], ASC, Dates[MonthNumberOfYear], ASC),
    ),
    [Internet Net Sales]
)
```

## Enhancing and Optimizing Existing Power BI Solutions

Power BI’s intuitive, low-code graphical interfaces enable users with limited technical experience to quickly generate visually compelling content. In many cases, such as with small or aggregated source data and minimal security and analytical requirements, these lightweight, sub-optimally designed solutions can prove to be sufficient even with only Power BI Pro licenses. However, meeting the more demanding requirements of larger, more complex solutions entails additional tools, design techniques, and in some cases, resources such as Power BI Premium Per User or Fabric capacity.

For larger Power BI projects—particularly when the options of Power BI Premium and Analysis Services are not available—it becomes important to identify opportunities to improve report query performance and to more efficiently use system resources to store and refresh the semantic model.

Additionally, the data import process can often be made more resilient and less resource-intensive. Furthermore, the application of standard coding syntax, variables, and comments in both Power Query (M) and DAX expressions further improves the sustainability of Power BI semantic models.

This chapter’s recipes contain top semantic modeling, DAX measures, and M query patterns to enhance the performance, scalability, and reliability of Power BI semantic models. This includes performance tuning examples of both semantic models and measures, error handling and query folding examples of M queries, and supporting details on the DAX and M query engines.

In this chapter, we will cover the following recipes:

- - Extending and enhancing semantic models
- - Improving DAX measure performance
- - Pushing query processing back to source systems
- - Strengthening data import and integration processes
- - Isolating and documenting DAX expressions
