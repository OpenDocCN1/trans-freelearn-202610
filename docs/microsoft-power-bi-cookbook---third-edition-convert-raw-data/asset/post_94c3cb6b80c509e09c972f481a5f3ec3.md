## Working with Premium and Microsoft Fabric

Power BI is not the only data analytics platform with a history at Microsoft. In parallel to the continued investments in Power BI, Microsoft has also sought to produce a holistic and integrated set of capabilities targeting modern use cases including data science, data engineering, and multiple data lake, data warehouse, and lakehouse architectures. In particular, Microsoft leveraged its experience with SQL Server to develop a massively parallel processing (MPP) on-premises appliance called Parallel Data Warehouse (PDW). Later, this appliance was rebranded as Analytics Platform System (APS). As workloads transitioned to the cloud, Microsoft created Azure SQL Data Warehouse (SQL DW) based on the same technologies in 2016. With increased complexity and competition in the data analytics space, Microsoft added additional capabilities and rebranded the entire platform as Synapse Analytics. SQL DW was only a small component of this new platform and thus was rebranded to Dedicated SQL Pools.

Throughout the past decade or so, there was only minimal integration between the two platforms, Power BI and what is now known as Azure Synapse Analytics. This all changed in 2023 when Microsoft announced Microsoft Fabric. Microsoft Fabric essentially surfaced Azure Synapse Analytics workloads within the Power BI service, creating a single data analytics platform by effectively merging the two data analytics platforms at Microsoft. Microsoft Fabric is now the single, unified platform for all future development and Power BI is simply one component of this larger framework.

With this move to Microsoft Fabric, Microsoft created a new licensing mechanism, Fabric capacities (F SKUs). Unlike Power BI Premium, which included capacity, network, premium features, and storage for a single monthly price, F SKUs are charged per hour of usage, while storage and network are billed separately. Power BI Premium capacities (P SKUs) automatically inherited all Microsoft Fabric workloads, with an F64 SKU being equivalent to a P1 SKU.

The recipes in this chapter cover features and functionality particular to Power BI Premium capacities and Microsoft Fabric including data warehouses, lakehouses, and machine learning:

- Creating a data warehouse
- Engineering data with a lakehouse
- Backing up semantic models
- Leveraging Direct Lake
- Applying data science

By the end of this chapter, you will have a firm understanding of Microsoft Fabric and Power BI Premium capabilities and features.

## Creating a Data Warehouse

Gartner defines a data warehouse as follows:

> “A data warehouse is a storage architecture designed to hold data extracted from transaction systems, operational data stores, and external sources. The warehouse then combines that data in an aggregate, summary form suitable for enterprise-wide data analysis and reporting for predefined business needs.”

Data warehouses have been a staple of business intelligence architectures for decades given their ability to deliver a central and single source of truth for use by a variety of applications and use cases. By handling data quality and integration needs in powerful upstream tools like Azure Data Factory pipelines and producing a consolidated set of dimension and fact tables with surrogate keys for relationships/joins via familiar SQL queries and support for historical tracking, a well-designed and managed data warehouse remains a highly valuable asset.

Regardless of the specific history of the term data warehouse, today the data warehouse is a staple of today’s enterprise business systems and a core component of business intelligence and reporting for many organizations. Microsoft Fabric provides data warehouse capabilities via cloud-based, lake-centric technologies built upon the SQL Server engine, distributed processing, and centralized storage within OneLake, Microsoft’s logical, centralized data lake for Fabric.

This recipe provides guidance for how to create and use a data warehouse within Microsoft Fabric.
