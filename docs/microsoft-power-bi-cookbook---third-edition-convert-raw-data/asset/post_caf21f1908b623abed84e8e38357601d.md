
## Getting ready

To prepare for this recipe, follow these steps:

- 1. Ensure that you have provisioned an Azure Data Lake Storage Gen2 account within your Azure tenant.
- 2. Ensure that you have a Power BI Premium capacity (P SKU), Power BI Premium Per User (PPU) license, Microsoft Fabric capacity (F SKU), or a Power BI Embedded capacity (A SKU) provisioned.
- 3. In the Power BI service, open the Admin portal (see the Accessing the Admin Portal recipe in Chapter 14,).
- 4. For Premium, Embedded, and Fabric capacities, select Capacity settings from the left navigation pane of the Admin portal.
- 5. Select the Power BI Premium, Power BI Embedded, or Fabric Capacity, then expand the Workloads section and ensure that the XMLA Endpoint setting is set to Read Write. You may have to wait up to 10 minutes for this change to take effect.

![](img/5e366dc9e90fe4b1ca9dd97c82976bbd_564_0.png)

Figure 13.17: XMLA Endpoint setting

- 6. If using a PPU license, select Premium Per User from the left navigation pane of the Admin portal and under Dataset workload settings or Sematic model workload settings, ensure that the XMLA Endpoint is set to Read Write.
- 7. Navigate to a workspace in the service and choose Workspace settings. On the Premium tab of the Workspace settings dialog, ensure that the License mode is Premium capacity, Premium per user, Fabric capacity, or Embedded.
- 8. At the bottom of the Premium tab of the Workspace settings dialog, copy the Workspace connection string:

![](img/5e366dc9e90fe4b1ca9dd97c82976bbd_564_1.png)

Figure 13.18: Workspace XMLA endpoint

- 9. Click on the Azure connections tab of the Workspace settings dialog, configure the Connect an Azure Data Lake Gen2 storage account settings, and click the Connect to Azure button. It is important that the workspace does not contain any dataflows or the connection will fail.

- 10. Exit the Workspace settings dialog and publish Power BI Desktop files to the workspace or otherwise create semantic models within the workspace.

You are now ready to complete this recipe.

- 5. Review the options in the Backup Database dialog and then click the OK button:

This completes backing up the semantic model.

## How it works

Connecting workspaces to an Azure Data Lake Gen2 storage account and correctly configuring the XMLA endpoint for a workspace to Read Write. It may seem odd that backing up a semantic model requires the XMLA endpoint to be configured for both read and write access since backing something up generally only requires read access. However, consider that the backup file (.abf) is being backed up to the Azure Data Lake Gen2 storage account via the XMLA endpoint and thus, write access is required for the XMLA endpoint.

## There’s more...

In addition to backing up a semantic model via the SSMS user interface, the backup can also be performed via running a query. The below query could be run to back up a semantic model of a Power BI workspace connected via the XMLA endpoint:

```
{
  "backup": {
    "database": "Designing Mobile Layouts",
    "file": "Designing Mobile Layouts.abf",
    "allowOverwrite": true,
    "applyCompression": true
  }
}
```

Finally, you can confirm that the backup file was created via Azure Storage Explorer. Azure Storage Explorer can be downloaded here: https://azure.microsoft.com/en-us/products/storage/storage-explorer/.

Within Azure Storage Explorer, navigate to the storage account configured in the *Getting started* section of this recipe. Expand the **Blob Containers** section in the left navigation beneath the storage account. Under **Blob Containers** will be a container called **power-bi-backup**. Within that blob is a folder with the same name as the workspace.

The backup file (.abf) is located in the folder for the workspace.

## Leveraging Direct Lake

Historically, Power BI had two semantic model modes, **Import** and **DirectQuery**. With import mode, data is ingested from source systems into tables within an Analysis Services semantic model. With DirectQuery, the semantic model dynamically queries source systems for data when needed. Many have often included live connections as a third semantic model mode. However, this is technically incorrect as live connections simply create a connection between a report and an existing semantic model and are thus not a semantic model mode in and of itself. Microsoft later introduced the Composite semantic model mode, which allows Import mode and DirectQuery mode to be combined within a single semantic model.

In addition to semantic model modes, Power BI also has storage modes for tables within the semantic model. Naturally, import mode semantic models use a table storage mode of import and DirectQuery semantic models use a table storage mode of DirectQuery. When composite semantic models were introduced, Microsoft added an additional table storage mode known as **Dual storage mode**, which enabled a table to operate in cached mode (import) or query data sources directly (DirectQuery). Microsoft also introduced the concept of hybrid tables, tables that included multiple partitions with at least one partition being in import storage mode and another partition in DirectQuery storage mode.

When Microsoft launched Fabric, an additional third table storage mode was introduced, Direct Lake. This recipe demonstrates how to create a semantic model with tables in Direct Lake storage mode.

## Getting ready

To prepare for this recipe, follow these steps:

- 1. Ensure that you have a Power BI Premium capacity (P SKU) or Microsoft Fabric capacity (F SKU) provisioned.
- 2. Complete the Installing SQL Server and the AdventureWorks Database recipe from Chapter 1, Installing and Licensing Power BI Tools.
- 3. Ensure that you have a data gateway installed and a gateway connection configured to your SQL Server database. See the Creating an On-Premises Data Gateway recipe from Chapter 1 and Configuring On-Premises Gateway Data Connections in Chapter 11.
- 4. Create a new workspace and assign the workspace to the Premium or Fabric capacity.
- 5. Navigate to the workspace and in the upper-right corner, choose New and then More options.
- 6. Under Data Engineering, select Lakehouse, provide a name for your lakehouse, and click the Create button.
- 7. Populate your lakehouse using a New Dataflow Gen2 dataflow.
- 8. Use your AdventureWorks database on your SQL Server as a data source, selecting various dimension and fact tables such as DimCustomer, DimDate, DimProduct, DimReseller, DimSalesTerritory, FactInternetSales, and FactResellerSales.
- 9. Allow the dataflow to complete its initial refresh.
- 10. Open the lakehouse and verify that the tables are loaded into the lakehouse.

You are now ready to complete this recipe.
