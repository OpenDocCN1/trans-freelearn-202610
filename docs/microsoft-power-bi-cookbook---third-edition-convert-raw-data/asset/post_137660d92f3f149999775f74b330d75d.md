## Importing Data

The output of Power Query (M) queries can either be loaded (imported) as compressed in-memory local tables or can merely define source tables for a data source to use via a DirectQuery connection. The import storage mode is the default and preferred option for most scenarios, as this delivers the best possible performance while also providing greater modeling flexibility, with more DAX functions supported and easier integration of distinct sources. Import is the default storage mode for Power BI Desktop. The collection of imported tables and DirectQuery tables is referred to as a semantic model.

Import semantic models created in Power BI Desktop use the same in-memory, columnar-compressed storage engine (VertiPaq) featured in Analysis Services Tabular Import models. Import mode models support the integration of disparate data sources (for example, SQL Server and DB2) and allow more flexibility in developing metrics and row-level security roles, via full support for all DAX functions.

There are some limits for Import mode semantic models, however. For example, Power BI Pro license users cannot publish Power BI Desktop files to shared capacity in the Power BI service that is larger than 1 GB. Power BI Premium (dedicated, isolated hardware) supports semantic models of 10 GB in size and larger (with large semantic models enabled, the semantic model size is limited by the Premium capacity size or the maximum size set by the administrator). With such large semantic models, it is important to consider employing incremental refresh where only new and changed data is refreshed and imported, instead of the entire semantic model being refreshed. Additionally, import mode creates an extra “hop” in which a copy of data from one source is loaded to another, and this loading process will have to be either scheduled or orchestrated. IT professionals would understandably prefer the simplified architecture of leveraging an existing data source in DirectQuery mode for reporting, yet in most scenarios, the many benefits of import mode justify its overhead.

This recipe describes the process of using M and Query Editor to develop the Import mode queries for a standard star-schema analytical model.

## Getting ready

To prepare for this recipe, we will first build a query through the user interface that connects to the AdventureWorksDW2022 SQL Server database. This query will be used as a reference query for additional queries we will create later in the recipe. To create this query, follow these steps:

1. Open Power BI Desktop and create a new report.
2. Click on **Get Data** from the **Home** tab of the ribbon. Select **SQL Server** from the list of database sources. For future reference, if the data source is not listed in **Common data sources**, more data sources are available by clicking **More...** at the bottom of the list.
3. A dialog will appear, asking for connectivity information. Ensure that **Data Connectivity mode** is set to **Import**. Enter the name of your SQL server as well as the AdventureWorksDW2022 database. In *Figure 2.1*, the SQL server is installed locally and runs under the default instance of MSSQLSERVER. Since it is the default instance, only the computer name hosting the SQL instance or localhost, a reference to the current computer is used. If the **Database** field is left blank, this will simply result in an extra navigation step to select the desired database.

![](img/5e366dc9e90fe4b1ca9dd97c82976bbd_65_0.png)

*Figure 2.1: SQL Server Get Data dialog*

4. If this is your first time connecting to this database from Power BI, you may be prompted for some credentials. In addition, you may also be warned that an encrypted connection cannot be made to the server. Simply enter the correct credentials to connect and click the **Connect** button. For the encryption warning, simply click the **OK** button to continue.
5. A navigation window will appear, with the different objects and schemas of the database. You can check the box next to any table or view but for this example, check the box next to the **DimGeography** table, and then click the **Transform Data** button.
