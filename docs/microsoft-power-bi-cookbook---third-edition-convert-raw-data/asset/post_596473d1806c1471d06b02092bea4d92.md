
+   6. Sort the Exclusive Duration column in descending order.
+   7. Here, we can see that the most expensive operation occurs early on in the process, at index 16 out of 3,000+ rows, and appears to be the initial selection of columns, with the Data Source Query being the following:

```
select [__].[CurrencyKey],
    [__].[DateKey],
    [__].[AverageRate],
    [__].[EndOfDayRate],
    [__].[Date]
from [dbo].[FactCurrencyRate] as [__]
order by [__].[CurrencyKey],
    [__].[DateKey]
```

It should be evident that diagnosing a single step of a query is faster and consumes fewer system resources than analyzing the entire query. Thus, it is recommended that you run only Aggregated diagnostics over an entire query to identify problematic steps, and then run Detailed diagnostics on those steps individually.

If you look at the Currency Rates_SelfJoin_Detailed query, the most expensive operation is on line 50, and it is the DbDataReader operation. The SQL statement identified is actually on line 49 with the operation Execute Query. Thus, we can conclude that the most expensive operation performed was not executing the query but, rather, reading the data generated by the query.

The section keyword defines a logical container of named, grouped expressions. Expressions can be prefixed with the shared keyword in order to expose the named expression to the global environment.

## Designing a Semantic Model

The self-service, low-code nature of Power BI tools and services lend themselves to rapid, agile development in which significant data insights can be obtained quickly despite both imperfect data sources and an incomplete understanding of business requirements and use cases. However, rushing through the design phase can undermine the sustainability of the solution, as future needs cannot be met without structural revisions to the model or complex workarounds. A balanced design phase in which fundamental decisions, such as DirectQuery versus in-memory, are analyzed, while simultaneously using a limited prototype model to generate visualizations and business feedback can address both short- and long-term needs.

This recipe describes a process for designing a semantic model and identifies some of the primary questions and factors to consider while doing so.

## Getting ready

Visually and analytically impressive examples of Power BI's reporting capabilities can often cause stakeholders to underestimate the effort and complexity associated with data integration and semantic modeling.

It is important to rein in any unrealistic expectations and confirm feasibility. Project stakeholders are often anxious to see report development results but it's important to set reasonable expectations given the long term value of the semantic model as a single source of truth over the given source data. Although technically each Power BI report can have its own semantic model, the severe version control, manageability, and resource/scalability issues associated with this report-centric approach strongly implies that BI developers should strive to create models capable of supporting many reports well into the future. A standard model design process described in this section will go a long way in accomplishing this objective.
