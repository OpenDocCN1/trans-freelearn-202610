While DAX traditionalists have lauded DAX’s CALCULATE function as well as time intelligence functions for years, more modern approaches such as using a No CALCULATE approach (so dubbed by Brian Julius) can significantly improve DAX query performance. With its focus on the use of VAR statements, simple FILTER functions, the SUMMARIZE function, and X aggregators (SUMX, AVERAGEX, etc.), the No CALCULATE approach also tends to be easier to debug and learn for newer users of DAX given the nuances and complexities of the CALCULATE function and the black-box nature of DAX’s time intelligence functions.

# There’s more…

Another example of where a DAX measure can be optimized is in this example where a measure must be filtered by complex conditions, such as a range of dates. Perform the same analysis as in this recipe but with the following three measures:

```
Last 7 Days 1 =
    VAR __Date = MAX('Dates'[Date])
    VAR __MinDate = __Date - 6
    VAR __Table = FILTER(ALL('Internet Sales'), [OrderDate] >= __MinDate && [OrderDate] <= __Date)
    VAR __Result = SUMX(__Table, [Internet Sales])
RETURN
    __Result

Last 7 Days 2 =
    VAR __Date = MAX('Dates'[Date])
    VAR __MinDate = __Date - 6
    VAR __Table1 = FILTER(ALL('Internet Sales'), [OrderDate] <= __Date)
    VAR __Table2 = FILTER(__Table1, [OrderDate] >= __MinDate )
    VAR __Result = SUMX(__Table2, [Internet Sales])
RETURN
    __Result

Last 7 Days 3 =
    VAR __Date = MAX('Dates'[Date])
    VAR __MinDate = __Date - 6
    VAR __Table1 = SUMMARIZE(ALL('Internet Sales'), [OrderDate], "Sales", [Internet Sales])
    VAR __Table2 = FILTER(__Table1, [OrderDate] <= __Date)
    VAR __Table3 = FILTER(__Table2, [OrderDate] >= __MinDate )
    VAR __Result = SUMX(__Table3, [Sales])
RETURN
    __Result
```
