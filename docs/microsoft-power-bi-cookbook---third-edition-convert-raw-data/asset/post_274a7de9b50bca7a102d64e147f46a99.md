
The **Contributor** role is primarily used for individuals or groups that simply need to add content to the workspace. Contributors cannot impact the permissions of the workspace or the permissions of content within the workspace.

The **Viewer** role provides the ability to see and view all content within the workspace and create subscriptions to reports within it.

It is important to understand that the **Admin**, **Member**, and **Contributor** roles all nullify **row-level security (RLS)**. This means that any member of those roles can always see everything within all semantic models published to the workspace, regardless of RLS rules and roles. RLS rules and roles still apply to the **Viewer** role.

It is common for the **Viewer** role to be used as an easy way to give large numbers of users access to all content within a workspace. However, this is not a recommended practice. Since the **Viewer** role has view access to all content, even content that is in development can still be seen by members of this role. It is recommended to instead use apps to widely share content with others and only consider using the **Viewer** role in exceptional scenarios.

## Configuring On-Premises Gateway Data Connections

The promise of leveraging the Power BI service and mobile application to provide access to a rich set of integrated dashboards and reports across all devices requires thoughtful configuration of both the data sources and the semantic models that use those sources. For many organizations, the primary business intelligence data sources are hosted on-premises, and thus, unless Power BI reports are exclusively deployed on-premises via Power BI Report Server, the on-premises data gateway is needed to securely facilitate the transfer of queries and data between the Power BI service and on-premises systems. Additionally, the semantic models that typically support many reports and dashboards must be configured to utilize an on-premises data gateway for either a scheduled refresh to import data into Power BI or to support DirectQuery and Live Connection queries generated from Power BI.

This recipe contains two examples of configuring data sources and scheduled refreshes for published semantic models. The first example configures two on-premises data sources (SQL Server and Excel) for an import mode Power BI semantic model and schedules a daily refresh. The second example configures a separate on-premise SQL Server database for a DirectQuery Power BI semantic model and sets a 15-minute dashboard tile refresh schedule.

### Getting ready

To prepare for this recipe, follow these steps:

- 1. Download, install, and configure the on-premises data gateway as per *Creating an On-Premises Data Gateway* in *Chapter 1, Configuring Power BI Tools*.
- 2. Ensure that you are a gateway administrator as per the *There’s more...* section of the recipe *Controlling Data Gateway Installations* in *Chapter 14, Administering and Governing Power BI*.

It is strongly recommended to have at least two administrators for each gateway installed to provide redundancy and backup of administrative functions.

### How to configure on-premises gateway data connections

In this example, an import mode semantic model has been created with Power BI Desktop to retrieve from two on-premises data sources: a SQL Server database and an Excel file. To implement this recipe, do the following:

- 1. Identify the server name and database name used in the Power BI Desktop file.
- 2. Identify the full path of the Excel file.
- 3. In the Power BI service, click on the gear icon in the top-right corner and select **Manage connections and gateways**.
- 4. In the Data (preview) interface, click the Connections tab and then the New button:

Figure 11.16: Creating a new gateway connection

- 5. In the New connection dialog on the right, choose the Gateway cluster name installed in step 1 of this recipe, provide an intuitive connection name that won’t conflict with other sources, and enter the server, database, and credential information:

Figure 11.17: Adding a SQL Server database as a source for an on-premises data gateway

The server and database names for the gateway must exactly match the names used in the Power BI semantic model.

If configuring an Analysis Services data source for a gateway, ensure that the credentials used are also an administrator for the given Analysis Services instance. The server administrator credential is used in establishing the connection, but each time a user interacts with the Analysis Services data source from Power BI, their UPN (user principal name) is passed to the server via the EffectiveUserName connection property. This allows RLS roles defined in the Analysis Services database to be applied to Power BI users.

- 6. Ensure that the source uses the appropriate privacy level, such as **Organizational** or **Private** under **General settings** for **Privacy Level.**
- 7. Click the **Create** button. Users can be added to the specified gateway and connection per the *There’s more...* section of the recipe *Controlling Data Gateway Installations* in *Chapter 14, Administering and Governing Power BI.*
- 8. Add an additional data source for the Excel file using the file data source type.
- 9. Like the SQL Server data source, authorize users for this gateway and connection.
- 10. Publish an import mode Power BI Desktop file (semantic model) to a workspace in the Power BI service.
- 11. Access the workspace and, for the semantic model, click the **Schedule refresh** icon:

![](img/5e366dc9e90fe4b1ca9dd97c82976bbd_489_0.png)

*Figure 11.18: Schedule refresh for a semantic model*

- 12. Expand the **Gateway and cloud connection** section.

The gateway will appear as an option for data refresh if the following three criteria are met:

- The user is listed on the **Users** page of the data source(s) within the gateway.
- The server and database names configured in the Power BI service for the gateway match the names used in the Power BI Desktop file.
- Each data source used by the semantic model is configured as a data source for the gateway.

- 13. In the Data sources included in this semantic model section, use the Maps to dropdown to select the configured gateway data source connection.

![](img/5e366dc9e90fe4b1ca9dd97c82976bbd_490_0.png)

Figure 11.19: Associating the data source with the Power BI gateway data connection

- 14. Click the Apply button to connect the data sources to the gateway.
- 15. Now expand the Refresh section and toggle Configure a refresh schedule to On.
- 16. Click the Add another time link to add a scheduled time for the refresh to occur.
- 17. Once you’ve finished adding refresh times, click the Apply button.

Data caches used by dashboard tiles are updated after refresh operations for import mode semantic models (or manually). The Power BI service also caches data for report visuals and updates these caches as semantic models are refreshed. Dashboard tiles can be refreshed manually in the Power BI service via the Refresh visuals menu item (top-right, circular arrow icon). Likewise, reports can be manually refreshed from the Power BI service, but this is only relevant for DirectQuery and Analysis Services live connections; this does not initiate a refresh for an import mode semantic model.

Import mode semantic models can be refreshed via the schedule in the Power BI service or via the REST API. Power BI data refresh APIs allow BI teams to trigger refresh operations in the Power BI service programmatically.

For example, a step can be added to an existing nightly (or more frequent) data warehouse or ETL process that initiates the refresh of a Power BI semantic model that uses this data source. This allows dashboards and reports in the Power BI service to reflect the latest successful refresh of the data source(s) as soon as possible. In other words, the gap or lag between the source system refresh and the Power BI semantic model scheduled refresh can be reduced to the amount of time needed to refresh the semantic model in the Power BI service.

To trigger a refresh for a semantic model in the Power BI service, simply make the following HTTP request:

```
POST https://api.powerbi.com/v1.0/myorg/groups/{group_id}/semantic_models/{semantic_model_id}/refreshes
```

See the documentation on Power BI REST API authentication and the Power BI REST API reference in the See also section of this recipe.
