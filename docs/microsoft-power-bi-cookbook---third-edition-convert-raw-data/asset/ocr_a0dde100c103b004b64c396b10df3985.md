# How it works

Single-direction cross-filter relationships only propagate filters in the direction of the relationship. Thus, when the Products table is set to filter the Internet Sales table in a single direction, other filters affecting Internet Sales are not propagated to the Products table. With bidirectional cross-filter relationships, filters affecting one side of the relationship are always propagated to the other side of the relationship unless DAX measures use functions such as CROSSFILTER() to override the default behavior defined by the model relationships.

Bidirectional relationships between fact and dimension tables should generally be avoided when the given dimension table is also related to other fact tables. This can cause over-filtering or unintended filter contexts. However, bidirectional relationships are an integral part of efficient solutions to common (and otherwise complex) modeling scenarios, such as actual versus budget, and classic many-to-many scenarios.
