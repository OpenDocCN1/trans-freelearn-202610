## Building Power BI Reports into PowerPoint Presentations

Microsoft PowerPoint remains a standard slide presentation application, and the integration of data analyses and visualizations from external tools is very commonly an essential component of effective presentation decks. Microsoft now provides its customers with multiple options for surfacing Power BI content within PowerPoint presentations without the need for any third-party add-ins and licenses. One option is the ability to create a new PowerPoint slide deck from scratch by converting each page of a report to their own PowerPoint slide. Another highly valued integration described in the There’s more... section is the ability to insert live and interactive Power BI reports within PowerPoint slides thus enabling data exploration and storytelling during meetings or presentations without leaving PowerPoint.

The title page also includes a last data refresh and a date and time download value. Each report page is converted into a slide that contains a high-quality, rendered image of the report page. Any Alt Text specified for visuals is included in the Notes for each page.

Similar to other planning and precautions with highly visible content such as executive dashboards, it is important to obtain knowledge and confidence in the data sources, refresh process, data quality, and ownership. For example, if the source semantic model retrieves from multiple sources, including ad hoc Excel files, and has a history of refresh failures, then the report might not be a good candidate for a PowerPoint presentation. A report based on an IT-managed Analysis Services model that has already been validated and has a clear owner would be a better choice.

Background images will be cropped with a chart’s bounding area, and thus it is recommended to remove or avoid background images. Additionally, the exported report pages always result in standard 16:9 PowerPoint slide sizes, and thus custom or non-standard page sizes should also be avoided. Shapes such as rectangles and lines to provide custom groupings, borders, and background colors for visuals may also need to be removed for proper PowerPoint rendering. Finally, non-certified visuals, R visuals, and Python visuals should be avoided in reports where exporting to PowerPoint is used.

## Integrating with Power Automate and Power Apps

Power BI’s tools and services are predominantly read-only given their mission to derive insights from data rather than to create new data or modify existing data. While data analysis and visualization is of course an essential function, it’s only the actions that are taken based on insights that generate value. For this reason, the Power Platform includes Power Automate and Power Apps two rich and mature applications that support the automation of business processes and the development of business applications for creating and editing business data.

Power BI Desktop now includes visuals for Power Automate and Power Apps allowing report authors to easily expose capabilities from these tools directly within Power BI reports. For example, a Power BI report page could expose a Power Apps form for a user to optionally edit the values of a product. Additionally, a Power BI report could contain Power Automate visuals that empower users of the report to trigger various workflows, such as sending an email or refreshing a semantic model.

In this recipe, a Power Automate workflow is created to support a streaming semantic model in the Power BI service. Specifically, the Power Automate workflow is configured to read from an on-premises SQL Server table every five minutes and push this data into Power BI, providing near real-time visibility and support for data-driven alerts and notifications.
