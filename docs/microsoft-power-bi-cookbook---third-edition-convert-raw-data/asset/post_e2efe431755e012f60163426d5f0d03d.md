
## Getting ready

To prepare for this recipe, follow these steps:

- 1. Ensure that you have a Power BI Premium capacity (P SKU) or Microsoft Fabric capacity (F SKU) provisioned.
- 2. Complete the Installing SQL Server and AdventureWorks Database recipe from Chapter 1, Installing and Licensing Power BI Tools.
- 3. Ensure that you have a data gateway installed and a gateway connection configured to your SQL Server database. See the Creating an On-Premises Data Gateway recipe from Chapter 1 and Configuring On-Premises Gateway Data Connections in Chapter 11.

You are now ready to complete the steps for this recipe.

## How to create a data warehouse

To implement this recipe, do the following:

- 1. Log in to the Power BI service at https://app.powerbi.com.
- 2. Ensure you are in a workspace enabled for Fabric workloads.
- 3. In the lower-left corner, click the Power BI icon and then select Data Warehouse:

![](img/5e366dc9e90fe4b1ca9dd97c82976bbd_551_0.png)

Figure 13.1: Additional workloads in Microsoft Fabric

- 4. Under the New heading, select Warehouse.
- 5. Provide a Name for your warehouse and click the Create button.

- 6. Select New Dataflow Gen2 under Build a warehouse or in the upper-right corner, select Get data and then New Dataflow Gen2:

![](img/5e366dc9e90fe4b1ca9dd97c82976bbd_552_0.png)

Figure 13.2: Build a data warehouse

- 7. In the upper-right corner, select Get data and then SQL Server database.

- 8. Enter the connection settings for your SQL Server and the Connection credentials should automatically update to your pre-configured data gateway connection.

- 9. In the Choose data dialog, select the DimCustomer, DimDate, DimProduct, DimReseller, DimSalesTerritory, FactInternetSales, and FactResellerSales tables and click the Create button.

- 10. The interface presented is essentially the same as Power Query Editor in Power BI Desktop. Rename the queries to Customers, Dates, Products, Resellers, Sales Territories, Internet Sales, and Reseller Sales respectively.

- 11. Move the Internet Sales and Reseller Sales queries to a group called Facts and the other queries to a group called Dimensions.

- 12. Select the Customers query and expand the DimGeography column, selecting the City, StateProvinceName, and EnglishCountryRegionName columns.

- 13. Repeat step 12 for the Sales Territories query.

- 14. Select the Products query and expand the DimProductSubcategory column for the EnglishProductSubcategoryName and DimProductCategory columns.

- 15. Expand the DimProductCategory column for the EnglishProductCategoryName column.

- 16. Click the name of the dataflow in the upper-right corner and provide a descriptive Name value:

Figure 13.3: Build a data warehouse

- 17. Click the Publish button in the lower-right corner.

- 18. Wait for the Dataflow Gen2 refresh to complete.

You have now successfully created your data warehouse.

## How it works

Microsoft Fabric provides two data warehouse experiences, the Synapse Warehouse covered in this recipe and the SQL analytics endpoint of the lakehouse (see the Engineering Data with a Lakehouse recipe in this chapter). While the latter only supports read-only queries, and the creation of views and table-valued functions (TVFs), the former supports full transactional Data Definition Language (DDL), such as CREATE, DROP, and ALTER commands, and Data Manipulation Language (DML), which includes commands such as INSERT, UPDATE, and DELETE.

There are two methods for populating a warehouse within Fabric: data pipelines and Dataflow Gen2 queries. Data pipelines are an evolution of Azure Data Factory, the cloud successor to SQL Server Integration Services (SSIS). In fact, Data Factory includes the ability to provision an SSIS runtime in order to store and execute SSIS packages. The key difference between data pipelines and dataflows is that data pipelines are an orchestration mechanism and do not transform data while a dataflow is designed to transform data. Dataflow Gen2 is an evolution of the original Power BI dataflows (now called Dataflow Gen 1) and dataflows can actually be included as an activity within a data pipeline.

Creating a warehouse actually creates two artifacts: the warehouse itself as well as an associated semantic model. Creating a Dataflow Gen2 creates the dataflow itself as well as four additional artifacts: a SQL analytics endpoint and its associated semantic model, as well as a staging warehouse and its associated semantic model. These last four objects generally appear just after creating the Gen2 dataflow, as shown in Figure 13.4, but are subsequently hidden as they are backend components that are part of how Gen2 dataflows operate.
