# # Testing the image

One of the reasons that CI is so popular among software developers is that it provides a way to automatically run a test suite against the new build to ensure that it works properly. The tests provide a level of security in knowing that whatever changes the developers made, these did not break the functionality of the software. This is just as valuable for Docker images that are going to be deployed to, potentially, hundreds or thousands of servers.

There are several ways of implementing the tests:

+   • The first is to include the tests in the `git` repository, but not adding them to the image. This keeps the image small, but requires that all of the tools needed for testing are installed on the runner. Some runners, such as the docker-in-docker executor may not include the tools needed to run the tests.
