Jobs can define a list of `tags` which are used to define which runner is used. In the preceding example, the image will be built by a runner with the `docker` tag. If multiple tags are set, the runner must match all of them to be used. This makes it possible to create runners that can build certain types of projects and not others.

Finally, the `script` option is a list of commands to run to build the project. Each command must succeed before the next command is run. If any of them fail, the build stops and it is marked as having failed. The commands can be regular system commands as in the example or scripts from the repository.

In this example, the runner first builds the image. The `--pull` flag is used with `docker build` to ensure that the latest copy of the base image is used to build the new image. If the build succeeds, the new image is pushed back into the repository. A list of available images is available in the **Registry** section on the project page:
