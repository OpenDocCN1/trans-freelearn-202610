```
database_name=WebCache_2788
```

### 7.2.3 安装 SCS Target 5.2.5 SP2

我们现在将在 Web 服务器主机上安装 SCS Target 5.2.5 SP2。

- 1. 停止 SCS Target 服务并在 Web 服务器主机上解压 site_caching_services_5.2.5_SP2_all.zip。此 ZIP 包含 webcache.jar 文件。
- 2. 将解压后的 webcache.jar 文件复制到 Web 服务器主机上的以下位置：
- `<SCS Target Installation Directory>\product\jre\win\lib\ext`
- 示例：Windows 上的典型位置可以是： `c:\Documentum\SCS\product\jre\win\lib\ext`
- 3. 重启 SCS Target 服务。

如果 SP2 升级未正确完成，在发布期间如果 Content Server 主机和 Web 服务器主机（SCS Source 和 Target）上的 webcache.jar 版本不匹配，则会看到以下错误消息：

```
ERROR: Failed to login to the target server. Network error retrieving target result
com.documentum.webcache.utils.d: Local class not compatible: stream
classdescserialVersionUID=1602290069170353386 local class
serialVersionUID=4590497449032455007
```

就这样！我们已完成将 SCS Target 升级到 SP2。现在我们可以从 Documentum 发布内容和元数据了。

## 8 设置 Documentum Application Builder

Documentum Application Builder（以前称为 Documentum Developer Studio）是一种用于创建 Documentum 应用程序打包单元（称为 DocApps）的工具，其中包含对象类型、生命周期、工作流模板和其他 Documentum 对象。

回顾我们在第 2 章中关于 DocApps 的讨论。DocApp 可以使用 Documentum Application Builder 创建，并可以使用 Documentum Application Installer 归档并部署到其他 Docbase。

DocApp 可以包含多种类型的 Documentum 对象，例如：

- 对象类型
- 生命周期
- 工作流模板
- 权限集模板
- 别名集
- 作业
- 方法
- 过程
- 关系类型
- 数据对象

使用 Documentum Application Builder（DAB）我们可以通过简单的图形向导创建这些对象。请注意，**Workflow Manager** 特用于创建工作流模板。安装 DAB 也会自动安装 Workflow Manager。Workflow Manager 与 DAB 无缝集成，因此可以从 DAB 内部打开，也可作为独立应用程序打开。

### 8.1 Documentum Application Builder

Documentum Application Installer（DAI），用于部署 Documentum DocApps，如果用户正确选择选项，也会随 DAB 安装程序一起安装。使用简单的用户界面，我们可以在自己的自定义 DocApps 中创建不同类型的 Documentum 对象，而无需担心 Docbase 连接和会话等细节。

请注意，DAB 不必安装在 Content Server 主机上。只要相关 Docbase 的 DocBroker 连接可用，它就可以安装在单独的桌面上。
