Figure 4.5: Generating renditions via CRS

The process of generating renditions via CRS is as follows:

+   1. The client sends a rendition request to the Content Server.
+   2. The Content Server stores the rendition request from the client in a dm_queue.
+   3. CRS polls the dm_queue at pre-configured intervals to find out if there are any pending rendition requests to be served.
+   4. CRS creates renditions as per the rendition requests in dm_queue, and sends them across to Content Server, which saves the renditions in the Docbase.

We can configure the frequency with which CRS polls the Docbases for rendition requests. Also, note that one CRS workstation can serve the rendition requests for a maximum of eight Docbases.
