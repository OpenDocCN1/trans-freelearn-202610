## 11.5 $value() 关键字

$value() 是一个重要的关键字，在设计条件值辅助时应考虑。让我们通过一个简单的示例来了解其使用方法和好处。

考虑一个属性 cust_name，它代表某些办公室员工姓名的下拉列表，例如 Tom、Harry 和 Chris，如图 11.35 所示。

| cust_name |
|-----------|
| Tom       |
| Harry     |
| Chris     |

图 11.35：员工姓名表

另一个属性 cust_age 需要代表每个办公室工作人员的年龄下拉列表。根据 cust_name 中选择的姓名，需要填充 cust_age 中的值。

例如，代表办公室工作人员姓名和对应年龄的表如表 11.36 所示：

| Name | Age |
|------|-----|
| Tom | 23 |
| Harry | 45 |
| Chris | 19 |

图 11.36：员工姓名和年龄表

可以建立如下的条件值辅助：

```
If cust_name = "Tom"
Then cust_age = 23
Else If cust_name = "Harry"
Then cust_age = 45
Else If cust_name = "Chris"
Then cust_age = 19
Else ...
```

如果办公室工作人员人数接近 100 人？您会定义这么多条件语句吗？这既不是好的实现，Application Builder 也不支持这么多条件值辅助语句。

$value() 在这种情况下可以帮到你。让我们看看如何操作。

设计一个注册表（例如 cust_employee_data），其列为 emp_name 和 emp_age。用所有员工的实际值及其年龄填充底层表中的行。按如下方式为属性 cust_age 定义值辅助：

```
select emp_age from dm_dbo.cust_employee_data where emp_name = '$value(cust_name)'
```

得益于 $value()，在运行时 Documentum 会在 where 子句中替换属性 cust_name 的值，因此查询会返回正确的员工年龄，而无需编写多个条件语句！有趣且非常有用，不是吗？

## 12 创建生命周期、别名集和权限集

在上一章中，我们为新闻文章对象创建了自定义对象类型和一些属性。现在让我们为新闻文章对象设计一个自定义生命周期，以便从新闻文章对象类型创建的实例（或内容对象）可以在将内容上线之前在各个生命周期阶段（如暂存（或审查）、审批等）之间移动。Documentum 中的生命周期对象与一些相关对象（如别名集、权限集（ACL）等）相关联，建议快速浏览介绍性章节以回顾我们之前讨论的基础知识。

总体而言，在设计生命周期时，您需要牢记三个重要组件：

- 生命周期用的别名集(s)
- 生命周期流程中各个阶段的权限集（ACL）
- 实际生命周期设计，如阶段、标签、预处理或后处理的任何脚本等。

我们将在本章中通过非常简单的示例介绍这些内容，以便您获得一定的理解和舒适度，而这些理解和舒适度可以在软件项目中设计实时应用程序时进一步扩展和丰富。

### 12.1 生命周期中的别名集

在生命周期的上下文中，别名集是一组别名，使生命周期能够在众多环境中移植。别名只不过是在给定上下文中称为别名名称的某些实际值的占位符或符号名称。别名值是别名名称的实际值。别名名称和值的配对构成一个别名，而一组这样的别名构成一个别名集。

想象一下，新闻文章的内容对象是由内容作者创建并由内容经理审阅的。在某个部门，内容作者可能是 Mr. X，内容经理可能是 Ms. Y。在另一个部门，内容作者和经理可能是不同的人，不一定是 Mr. X 和 Ms. Y。
