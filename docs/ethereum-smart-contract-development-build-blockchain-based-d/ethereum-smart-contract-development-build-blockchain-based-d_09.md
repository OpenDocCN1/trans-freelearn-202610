## Token versus coin

本章的标题具有误导性。它是有意被误导的。这是为了让你意识到从以太坊的角度来看加密货币和代币之间的细微差别。当你探索网络以获取有关加密货币的知识时，你会发现加密货币、币和代币这些术语经常被互换使用。

图 8.1 表示一种分类，突出了它们之间的细微差别：

![](img/8c91673d39176d2e910ac52c4bc35d8b_246_0.png)

图 8.1：代币与币

简单来说，以下四点总结了币和代币之间的区别：

- 币是其自身区块链上的独立货币，而代币主要基于单一区块链变体。
- 币通常具有有限的功能，价值存储，而代币可以存储复杂、多方面的价值。
- 币大多是通过挖矿区块链生成的，而代币是通过在区块链上执行智能合约生成的。
- 因此，当我们在本章中说加密货币时，我们实际上指的是代币，因为本书是关于以太坊智能合约的。凭借这一微小却至关重要的信息，我们将探索下一节，了解如何通过遵循 ERC20 兼容性从零开始开发以太坊代币。

## ERC20 token development using Truffle

Truffle 是用于以太坊的开发、测试和资产流水线的框架。它还具有使用 ERC190 标准集成的包规范。ERC190 是一份评论请求，规定了以太坊智能合约包规范的一套规则。

以太坊的资产流水线是一个概念，借鉴自 Ruby on Rails。这是一个提供框架来按所需执行顺序连接、压缩或压缩 JavaScript、Solidity 和 CSS 资产的功能。此功能帮助开发人员创建压缩和预处理的类似库的模块，可以被其他编码模块重用，这有助于提高生产力。

这就是我们如何使用 Truffle 框架部署一个基本的 ERC20 合规代币。我们可以添加更多功能以纳入其他 ERC20 合规功能，这些功能对于具有安全增强功能的完整代币是必需的。

在智能合约章节中，我们讨论了为什么我们需要像 ERC20 这样的合规性，并承诺列出 ERC20 代币中强制要求的各种函数。

一个 ERC20 合规代币必须具有以下具有相同命名约定的函数列表：

```
totalSupply ()
```

此函数没有参数，并返回流通中的代币总供应量。

例如，如果我们创建一个模仿比特币理念的 ERC20 代币，那么 `totalSupply()` 将获取 2100 万作为数字：

```
balanceOf (owner)
```

前述函数在括号内有一个参数，即所有者的地址。因此，此 `balanceOf` 函数需要所有者的地址来返回余额值。

```
transfer (to,value)
```

前述函数有两个参数，即 to 的地址，即接收者地址，以及需要发送到该地址的代币数量的值。

```
transferFrom (from,to,value)
```

前述函数有三个参数，即发送者地址、接收者地址以及需要转移的代币价值。

```
approve (spender,value)
```

前述函数使所有者能够批准第三方实体在指定最大值范围内花费代币。

```
allowance (owner, spender)
```



## 加密货币套利交易

阿贾伊是个孤儿。我们是高中同学。为了支持学业，他常做零工。清晨，他卖蔬菜；夜晚，他卖手镯。由于通勤时间过长，他没能完成学业并毕业。20年后：他经营着一家活动管理公司，拥有两栋别墅和三辆轿车，全部出租用于活动用途。他仍住在童年时期的那栋一层公寓里。他不再支付租金，因为他已从房主手中现金买下了它。

几天前我们在一栋他的别墅里见面，当时有第三方在那里举办晚宴。我随口问他是什么让他如此成功。他告诉我，首先，他从未借过任何贷款。即便现在，他也没有信用卡。其次，是铁路轨道。

你看，我们的房子离火车站非常近。我们几乎每晚都能听到火车的汽笛声。阿贾伊告诉我，他在上学期间赚到了大部分钱。车站有双向铁轨，本地列车每半小时从市中心枢纽往返于偏远村庄。

他习惯从坐在右站台的火车小贩那里买蔬菜，然后卖给左站台的晨练者和慢跑者。

我们的学校在左边。当放学铃响时，他会去买手镯然后回家。一旦黄昏开始降临，他便带着手镯来到右站台旁的寺庙附近。

阿贾伊没有任何正规的商业培训，却清楚地知道套利

## ICO 故事

YouTube 上存在一段视频日志，链接如下：

https://www.youtube.com/watch?v=4bf4xZg_4U&feature=youtu.be&t=4m19s

截至撰写时，它仅获得了 285 次观看。这是 2013 年在圣何塞举行的比特币大会的片段。在视频的 4 分 19 秒处，一位 panelist 提出了他关于在比特币区块链协议之上开发一个新协议的想法，该协议具有一些新的 X、Y 和 Z 功能，并由一组值得信赖的软件开发者来构建。他还强调，他希望在不去任何风险投资公司的情况下创建这家初创公司。相反，他将发行一些代币供大众购买作为投资，这将作为启动资金。这些代币的价值将随着初创公司的成长而增加，这反过来会奖励此类代币的早期采用者。

“我要了，”有人喊道，视频就此结束。

视频中的这个人是 J.R. Willet，而他在本视频中开创的想法就是**首次代币发行（ICO）**的概念。可惜，这个想法在比特币区块链上从未起飞，因为没有早期采用者。几年后，Vitalik Buterin 利用这一概念在以太坊区块链上推广 ICO，并在 2017 年前九个月内筹集了约 20 亿美元的以太币资金。

ICO 是一种不受监管的方式，通过智能合约向投资者提供新加密货币或加密代币的单位，以市场已建立的加密货币，如比特币和以太坊进行交换。

好消息是，像以太坊、Augur 和 Golem 这样合法的 ICO，是众筹模式和**首次公开募股（IPO）**的结合体。坏消息是，如今市场上大多数 ICO 出来时根本没有概念验证，而这是任何众筹模式的核心，而且它们也没有受到美国证券交易委员会的监管，而这是所有 IPO 中证券发行的支柱。*图 8.7* 体现了这一困境。这样的困境催生了我们需要识别的诈骗、庞氏骗局和水龙头。

![](img/8c91673d39176d2e910ac52c4bc35d8b_257_0.png)

图 8.7：ICO 困境

现在，你可能会想知道，为什么在过去几个月发生了这么多黑客攻击后，我仍会将以太坊视为合法的 ICO。要回答这个问题，我们需要明白，以太坊上发生的所有黑客攻击都是由于智能合约上的糟糕编码实践，而不是基础设施本身，即以太坊区块链或以太坊虚拟机和 solidity。

最重要的是，就 ICO 而言，出售的代币是以太币，它们是用于在以太坊区块链上通过 gas 运行智能合约的代币。

这就引出了我们可以识别诈骗 ICO 的一点。诈骗 ICO 的重要特征是，运行在区块链上的智能合约不会使用 ICO 上的代币。

想象一下：你会买或投资一家声称自己是钻石商人但却给你烤杏仁作为投资代币或收据的公司吗？要么它为你在代币上投资的金额提供等价的法律纸质合同，要么提供某种有价值的石头。

庞氏 ICO 是一种不同类型的金融欺诈。事实上，庞氏骗局的概念 150 年前就已在离线世界中出现，投资者被承诺只要能诱骗其他投资者参与该计划，就能连本带息收回投资。没有产品的附属业务也是一种庞氏业务。以太坊世界不幸地已成为新型庞氏 ICO 的温床。

图 8.8 表示了由意大利撒丁岛卡利亚里大学数学与信息学系的 Massimo Bartoletti 等人识别的基于以太坊的庞氏骗局分类（arXiv:1703.03779v5）：

![](img/8c91673d39176d2e910ac52c4bc35d8b_258_0.png)

图 8.8：基于以太坊的庞氏智能合约

水龙头与 ICO 无关。它们基本上是用户必须完成某些繁琐任务才能赚取以太币的网站。任务可以简单到点击网页、参与调查、玩游戏、撰写评论，或简单地复制粘贴附属链接。每项任务赚取的以太币极低，而从水龙头向用户钱包转账以太币的门槛可能极高或需要花费大量时间。水龙头是欺诈的边缘案例，因为有些确实会向因附属关系和坚持而成长的用户付款。然而，这些并不是合法的矿工在挖以太坊；相反，他们是被免费以太币诱惑而沦为用户奴隶的人。

## Fiat2Crypto 和 Crypto2Crypto 交易所

加密货币尚未成为支付日常购买的理想金融工具。

例如，要使用比特币钱包买一杯咖啡，我们必须将 BTC 发送到交易所进行兑换，等待确认处理完成，以大幅亏损的价格出售比特币，然后将法币资金转到我们的卡上。在某些情况下，我们的资金流动将由一名实际的人作为快递员负责。对于以太坊来说，这甚至更加繁琐。

有很多如雨后春笋般出现的交易所门户，但这些风险很高。几个经时间考验的交易所是 poloniex.com 和 cex.io。

爱沙尼亚张开双臂拥抱加密货币。该国计划在 2018 年开设一家名为 Crypterium 的加密银行。

图 8.9 描绘了 Crypterium 的 ICO 销售。加密银行 Crypterium 将是一个基础的 DApp，具有以下兑换设施：

- **Fiat2Crypto**：DApp 从用户提取法币资金并将加密货币存入用户账户
- **Crypto2Crypto**：DApp 从另一用户的钱包提取加密货币，并将相同或不同类型的加密货币发送到用户账户（例如，BTC/ETH、ETH/BTC、BCH/BTC）
- **Crypto2Fiat**：DApp 从用户的钱包或账户提取加密货币，并将等值的法币货币（USD/EUR/GBP 等）发送到用户的银行账户。

## Parity 漏洞重现

在上一章关于 Solidity 的内容中，我们讨论了由库合约中的多签钱包引发的 Parity 漏洞。发生该漏洞后，Parity 团队对库合约进行了必要的修复。然而，在此过程中，他们忘记了审计库智能合约的其他部分，而这些部分存在新的漏洞。

图 8.10 显示了可供外部用户访问的自毁代码片段。一个化名为 devops199 的新手开发者访问了此函数并意外执行了它。因此，整个库合约被自毁并从区块链上移除。

影响在很久之后才被意识到，当时调用该库的钱包变得毫无意义，而价值数百万美元的代币永远被困在这些悬空的钱包合约中。这样的黑客故事让我们认识到对任何开源代码进行同行评审的重要性，并说明了我们为何应使用冷钱包而非热钱包。

```solidity
// kills the contract sending everything to `_to`.
function kill(address _to) onlymanyowners(sha3(msg.data)) external {
    suicide(_to);
}
```
