# 前言

当一种新语言被创建时，程序员和技术评论家会迅速问“为什么？”，无论它是编程语言、标记语言还是建模语言。设计者往往受到批评而不是赞扬，仿佛寻找新的更好方法是一件坏事。批评者错得不能再错了。这并不意味着每种新工具或想法都会在理论上或实践中成功。然而，如果我们希望前进甚至保持步伐，我们必须继续尝试。世界不会停滞不前，我们也不能。作为一名保守的技术人员（前任卢德派），我时不时会提醒自己这一点。

在当今这个时代，当一位作者写一本关于技术的书时，其他人会迅速问“为什么？难道互联网上没有你需要知道的一切吗？”。当然，如果你知道去哪里找，能够区分精华与糟粕（卢德派喜欢经过时间考验的格言），并且你的崇高目标是从原始资料工作的话。如果，然而，你是一名 2018 年的程序员，你可能没有奢侈和时间去对每个以越来越快的速度出现的最新技术进行纯研究。

到这一步，你正在寻找 TL;DR（Too Long; Didn't Read），对吧？你已经读了三段，感觉压力山大想要继续前进。你的时间宝贵，不容浪费。我完全同意。这就是你应该阅读本书的原因。它是 Red 语言的 TL;DR，而 Red 语言是软件开发的 TL;DR。

如果你从未听说过 Red，你不知道它有什么特别之处，如何使用它，或它能做什么。本书会告诉你。它不是入门书或技术手册；它是一次介绍。它是你朋友 Ivo，在鸡尾酒会上招手让你过去说“嘿，这是 Red。我觉得你们两个会合得来。Red 是…”并在点燃你兴趣的同时列出 Red 的简历。

你与 Red 越多交流，它就越能打开你的思维，让你思考新的方式。这就是你的工作，记住吗？思考和解决问题。编写代码是，或应该是，附带的。可悲的是，现代软件开发的复杂性使事情颠倒过来，同时也吸走了制作软件的乐趣。Red 希望改变这一点，而本书将帮助你入门。

Red 看起来很熟悉，但也很陌生。它易于接近，但技术上很先进。没有什么能与之相比（除了它的前身 Rebol，当然）。一分钟你把它用作脚本语言，下一分钟它就从你当前的环境中交叉编译你的响应式 GUI 应用程序，带有 C 级速度扩展，编译成每个约 1 MB 大小的独立可执行文件。你看起来像个超级英雄，但你的副手在做所有的工作。

或者也许你认为我们不需要任何新语言。

# 作者简介

**Ivo Balbaert** 是比利时安特卫普社区学院 CVO Antwerpen 的（网页）编程和数据库前讲师。他于 1986 年获得安特卫普大学应用物理学博士学位。他在软件行业担任开发人员和顾问工作了 20 年，在安特卫普大学医院担任项目经理 10 年。自 2000 年以来，他一直在从事教学、软件开发和撰写技术书籍的工作，其中包括：

* *Rust Essentials*
* *Getting Started with Julia*
* *The Way to Go*

我特别想感谢我的审阅者 Rudolf Meijer，他澄清了很多问题，使本书变得更好更准确。还要感谢 Red 社区的许多专家，尤其是 Mike Parr、Nick Antonaccio 和 André Ungaretti，而最深的钦佩献给 Red 的创造者 Nenad Rakocevic，以及开启这一切的 Carl Sassenrath，他以 Rebol 开始了这一切。

# 审阅者简介

**Rudolf Meijer** 于 1966 年编写了他的第一个计算机程序。他参与了多种编程语言的创建和正式定义，尤其是 CHILL 和 Ada。他使用过 Fortran II 和 IV、COBOL、Turbo Pascal、Visual Basic、Euphoria、Rebol，现在是 Red。他为 Rebol 的开发做出了贡献，现在也深度参与 Red，曾出版 Red/System 的正式规范，并正在为 Red 本身准备规范。
