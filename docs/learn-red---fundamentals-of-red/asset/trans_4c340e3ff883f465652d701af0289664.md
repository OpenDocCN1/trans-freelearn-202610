# 使用的约定

本书在全文中使用了多种文本约定。

`CodeInText`: 表示文本中的代码词、数据库表名、文件夹名、文件名、文件扩展名、路径名、虚拟 URL、用户输入和 Twitter 句柄。以下是一个示例："控制台可执行文件构建在 `/home/user/.red` 文件夹内，名称格式为 `console-yyyy-m-dd-nnnnn`。"

代码块设置如下：

```
Red [
    Name-Of-Info: "Value of Info"
    Name-Of-Info2: "Value of Info2" 
    ...
]
```

当我们希望引起你对代码块中特定部分的注意时，相关行或项目会以粗体显示：

```
a: [1 2 3]
b: copy a
b ;== [1 2 3]
append a 4
a ;== [1 2 3 4]
b ;== [1 2 3]
```

你可以在每个部分附带的 codefile 中找到代码。每个代码片段的开头，你会看到：

```
;-- see ChapterNN/codefile.red:
```

这意味着该片段位于代码下载中的文件 `ChapterNN/codefile.red` 中（其中 NN 从 01 到 10），以及之后显示的代码片段，直到指示新的 codefile 为止。

在本书中，我们将 program、script、app 或 application 作为同义词使用，因为 Red 源文件可以被编译或解释。

我们在 `;==` 之后显示一段代码的返回值，如 `a: 5 ;== 5`，因为 `\==` 是 Red 控制台的显示方式，而前缀 `;` 使其在脚本中成为注释。

我们选择使所有程序在控制台中无需错误即可立即运行。然而，某些代码明确用于让你看到某些错误。这些代码用注释标出：`\*\*\* Script Error …`。只需删除该行开头的注释 (`;`) 符号即可使错误发生。

以 `#include` 开头的行也一样，只需取消注释即可编译程序。

任何命令行输入或输出都写成如下形式：

```
$ sudo apt-get update
```
