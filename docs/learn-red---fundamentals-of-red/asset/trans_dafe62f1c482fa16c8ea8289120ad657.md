
# 交叉编译能力

Red 编译器的一个令人惊叹的功能是其交叉编译能力，用于构建在与你正在开发的平台不同的平台上运行的可执行文件。这通过 `–t` 标志完成，如下所示：

```
red -t TargetID hello-world.red
```

这里，`TargetID` 可以取以下值：
* MSDOS：Windows，x86，控制台（+ GUI）应用程序
* Windows：Windows，x86，GUI 应用程序
* WindowsXP：Windows，x86，GUI 应用程序，无触摸 API
* Linux：GNU/Linux，x86
* Linux-ARM：GNU/Linux，ARMv5，armel（软浮点）
* RPi：GNU/Linux，ARMv5，armhf（硬浮点）
* Darwin：macOS Intel，仅控制台应用程序
* macOS：macOS Intel，应用程序包
* Syllable：Syllable OS，x86
* FreeBSD：FreeBSD，x86
* Android：Android，ARMv5
* Android-x86：Android，x86

因此，如果我想生成一个名为 `hello-linux` 的 Linux 可执行文件，我会这样做：

```
red -t Linux -o hello-linux hello-world.red
```

对于每个 `\-flag` 选项，都存在一个对应的 `\--option`。例如，`\--release` 与 `\-r` 相同，而 `\--target` 与 `\-t` 相同。详细版本使命令行脚本更易读。在终端中输入 `red -h` 可查看完整列表。

# Red 的编译模型

从之前 `red -r` 发布模式编译的截图中，我们可以看到这分为两步：
1. 第一步没有明确说明，但它将 Red 源代码编译为 Red/System 代码。
2. 第二步将 Red/System 编译为本地代码：

![](assets/6fc97a54-9560-4bda-9f53-444458cd028c.png)

如前所述，编译是通过 REBOL `red.r` 脚本完成的。由于这一点，Red 目前仅为 32 位，自托管将使 64 位二进制文件成为可能。

如果你感觉冒险，可以尝试在 REBOL 控制台内编译 Red。访问：[https://github.com/red/red#running-red-from-the-sources-for-contributors](https://github.com/red/red#running-red-from-the-sources-for-contributors)

目前，执行 Red 程序有两种不同的模式：
* 使用解释器运行，这在内存中进行并涉及一定程度的编译
* 编译为二进制文件中的本地代码然后运行此可执行文件，其中 Red/System 作为中间步骤

最终的编译器架构将比其他语言更复杂，可以称为 **协作执行模型**；编译器将与 JIT 编译器和解释器协作工作。

# 编写 Red 的开发环境

你基本上只需要一个简单的文本编辑器和一个用于编译工作的终端即可。然而，一些语法高亮以及内置的编译和运行系统可以让你的生活更轻松。

## 简单文本编辑器

Notepad++ 是一个免费且多功能的源代码编辑器，仅在 Windows 上运行。在文章 [http://helpin.red/Setup-Notepad.html](http://helpin.red/Setup-Notepad.html) 中，你可以看到如何将其构建为 Red 开发环境。Everedit ([http://www.everedit.net/](http://www.everedit.net/))、Crimson Editor ([http://www.crimsoneditor.com/](http://www.crimsoneditor.com/)) 和 emacs ([https://www.gnu.org/software/emacs/](https://www.gnu.org/software/emacs/)) 也提供语法高亮模式。

一个方便的小型 Windows 编辑器是 Ride ([http://www.mikeparr.info/redlang.html](http://www.mikeparr.info/redlang.html))，由 Mike Parr 用 Delphi 编写：

![](assets/ea3b1a8c-db41-4245-b7df-52f9a9ab5217.png)

要使其与 Red 的最新版本一起工作，请使用菜单中的 Tools | Configure Red System 来导航到你的 Red 二进制文件或 shell 脚本。

## 更复杂的编辑器

Sublime Text ([https://www.sublimetext.com/](https://www.sublimetext.com/)) 提供了一个跨平台解决方案。它可以免费下载和评估；然而，为了继续使用必须购买许可证。一些 Red 插件可用，例如 Sublime-Red ([https://github.com/Oldes/Sublime-Red](https://github.com/Oldes/Sublime-Red)) 或 Rebol-Red-Sublime ([https://github.com/onetom/rebol-red-sublime](https://github.com/onetom/rebol-red-sublime))。它们提供不错的语法高亮、代码片段以及轻松集成构建系统的方式。

目前最好的也是最完整的跨平台选项是 [Visual Studio Code](http://code.visualstudio.com/) 配合由 Red 团队开发的插件 ([https://marketplace.visualstudio.com/items?itemName=red-auto.red](https://marketplace.visualstudio.com/items?itemName=red-auto.red))。它具有许多功能，例如自动补全、代码片段、悬停在函数词上时内置的函数文档，以及语法高亮和典型的文本编辑器功能。

有一个 Red 快捷菜单，即 `Ctrl+K`、`Ctrl+M`。`F6` 解释并 `F7` 编译当前 Red 文件，同时具有完全集成的终端（Windows 中的 PowerShell 控制台）。这里是一个典型的截图：

![](assets/2f8c79a0-fc4f-43ad-8e99-4c3c731cf97a.png)

实际上，Red 非常适合构建一个专用的 **IDE**（**交互式开发环境**）。这是一项巨大的工作，肯定不是 Red 核心团队的优先事项，但也许有一天它会作为社区的努力出现。

同时，这里有一些用 Red 编写的编辑器；它们并不意味着完整，但它们展示了你可以用很少的 Red 代码做什么——RedEd ([http://www.mycode4fun.co.uk/text-editors](http://www.mycode4fun.co.uk/text-editors))、AutoRed ([http://www.mycode4fun.co.uk/red-apps](http://www.mycode4fun.co.uk/red-apps)) 和 Tired ([http://www.mikeparr.info/tired.html](http://www.mikeparr.info/tired.html))（35 行代码！）。

# 总结

到目前为止，你应该有一个运行中的开发环境并且能够使用 Red 控制台。你还学会了如何在开发模式和发布模式下编译和执行一个简单的脚本。你学习了最重要的编译选项，例如使用 `\-o` 重命名输出文件，或使用 `\-t` 将程序交叉编译到另一个部署平台。你也对 Red 的编译模型有了一些了解。最后，我们回顾了现有的编辑器选项，并准备了一个舒适的环境来开始编码，既可以与 Red 控制台交互式工作，也可以与源文件一起工作。
