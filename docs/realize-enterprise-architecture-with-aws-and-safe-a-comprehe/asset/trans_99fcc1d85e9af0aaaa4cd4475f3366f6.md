
## 云转型

将您的数据、应用程序、网络和基础设施迁移到云环境被称为云转型。云的各种形式，包括按需计算、智能开发和人工智能，都必须得到利用。如果由于遗留技术、流程和基础设施而难以获得竞争优势，云似乎可能是完美的解决方案。在 Google 上搜索一下，你会发现几家大型咨询公司可以帮助你规划云转型战略。最终，你需要将应用程序迁移到虚拟世界。尽管提供了许多指南和步骤来帮助你，但归根结底就是迁移你的应用程序。作为企业架构的一部分，企业架构确保组织与其目标保持一致，朝着实现这些目标所做的变更被定义和分析。云计算创造了以服务为中心的新的商业模式。云计算提供了诸多好处，包括成本节约、效率提升、开发周期缩短以及上市时间加快。迁移到云可以帮助公司大幅削减成本，因为它可以提高资产利用率、降低运营成本，并重新定义 IT 员工与管理层之间的关系。

## 一个架构良好的企业架构

在 AWS 上开发最佳实践是我们运行互联网规模系统经验的结果。专家如首席工程师在识别最佳实践方面发挥关键作用，这些最佳实践通常由数据驱动。随着社区工作中涌现出新的最佳实践，首席工程师确保团队遵循这些实践。随着时间的推移，这些最佳实践将被纳入其中，确保合规性。我们在内部评审流程的结果下展示了我们对 Well-Architected Framework 的客户友好型实现。建筑师、内部工程师以及来自领域的其他人员已被纳入其中。此信息可使用 Well-Architected Framework 以可扩展的方式利用。

通过使用具有分布式所有权的首席工程社区，可以根据客户需求形成一个架构良好的企业架构。对整个投资组合的风险进行整体视图对 CTO 和其他技术领导者至关重要。因此，你的组织可以识别跨团队的主题，这些主题可以通过培训、午餐讨论或其他机制来解决，在这些机制中，你的首席工程师可以在团队之间分享他们对特定主题的想法。

作为 AWS 内部评审流程的一部分，架构良好的系统和服务会接受评审。根本原因分析侧重于影响架构方法实施的设计原则；它还提出问题以确保个人不会忽视存在于许多 RCA 中的因素。每当内部系统或服务出现技术问题，或客户联系我们时，我们的评审流程就会接受评审，以查看是否可以改进。产品评审应在产品生命周期的关键里程碑进行，例如在设计阶段早期以避免单向门，并在服务首次发布之前。如果你投入生产后添加新功能并实施新技术，你将继续有更多工作要做。工作负载在增长时会发生变化。如果你希望其架构特性在老化过程中保持完整，则保持良好的卫生实践至关重要。建议在进行重大架构变更之前执行 Well-Architected 评审。

要将评审用作一次性快照或独立测量，你必须确保合适的人员参与对话。在评审会议期间，团队可以首次评估其工作的质量。在评审另一团队的工作负载时，有助于就另一团队的架构进行非正式讨论。为了获得清晰度或深入挖掘，你可以举行第二次或第三次会议来澄清或解决模糊性。业务背景应帮助你在评审问题后决定你的优先事项。此外，你需要考虑这些问题可能如何影响你团队的常规工作。解决反复出现的问题会更早，让你有更多时间为公司创造价值。随着问题的解决和架构的改进，你的评审将被更新。

评审的好处在进行后会变得明显，但新团队可能首先表示抵制。你可以通过教育来解决反对意见，说明评审将如何使团队受益：

- 团队太忙了！（在启动大型项目前使用的说法。）
  - 在推出大型产品之前，请确保其准备充分。你可以通过评审来确定是否犯了任何错误。
  - 为了在产品生命周期的早期制定缓解计划，进行早期评审非常重要。
- 在像超级碗这样的大型活动之前，人们经常说，*没有时间采取行动来应对结果！*
  - 无法改变前面提到的事件。你是否希望在不了解其与架构的关系的情况下经历这种风险？即使你不解决所有问题，如果它们出现，仍然需要操作手册。
- 我们无意让他人知道我们如何实施解决方案：
  - 当将问题指向 Well-Architected Framework 团队时，很明显没有任何问题会透露任何技术或商业专有信息。

你组织内不同团队进行的一系列评审可能会导致发现主题性问题。如果你检查一组团队，问题可能出在某个特定的支柱或主题上。作为全面评审的一部分，你需要确定任何机制、培训或工程师主导的讨论，这些可以帮助你解决这些主题性问题。在许多行业，由于数字技术的 proliferate，变化正在更快地发生。公司被迫每隔几年就重新发明自己，因为获得竞争优势变得越来越困难。政府机构也在改进其提供数字服务的方式，以响应公民的期望和行为。利用数字技术来适应市场变化、取悦客户并加速业务成果的企业更成功。

## 云迁移战略

有数百万客户在使用 AWS，从初创公司到政府机构。业务流程必须数字化并优化，遗留工作负载必须迁移和现代化，商业模式必须重新发明。由云驱动的转型使运营更高效、降低风险并降低成本。此外，它们还能提高员工士气和客户满意度，以及敏捷性。云可以有效地用于数字化转型，但前提是你拥有一套基础的组织能力（你的云就绪性）。通过识别这些能力并提供指导性建议，AWS Cloud Transformation Accelerator 帮助全球数千家组织加速其云转型工作。

一旦你了解迁移到云环境的理由，你就可以制定云迁移战略。在云计算中，无需维护数据中心，可扩展性得到改善，弹性得到改善，团队可以远程协作。当你使用 AWS 时，你可以现代化你的技术，并获得移动能力、云架构、设计和开发的端到端支持。AWS 的 Well-Architected Framework 允许你优化应用程序的开发、维护和升级方式。

通过培训课程、午餐讨论或其他机制促进首席工程师之间关于特定主题的沟通，你的组织可以解决跨团队的主题。你可以使用 Amazon Cloud Architecture Framework 识别和优先考虑转型的机会。评估和改进你的云就绪性，并在转型组织时迭代改进你的路线图，最终将提高你组织的敏捷性。

由于 TOGAF 主要由 VLE 使用，对于较小的公司而言，ADM 就足够了。在敏捷项目中，需求阶段的迭代很常见。在大多数情况下，业务需求会在你明确定义和理解它们之前被提取和澄清。ADM 有 10 个阶段，如下所述。Open Group 网站上的 TOGAF 文档提供了 TOGAF 方法的完整概述以及每个阶段的描述，确定其目标、输入、步骤和成果。

### 初步阶段 – 框架和原则

组织的初步阶段关注在特定企业内定义架构的地点、何物、为何、谁以及如何进行。它解决了企业定义并帮助你识别关键驱动因素和要素。它还允许你确定架构的要求并定义将执行任何架构工作的架构原则。定义框架和管理框架之间的关系，以及确定企业架构的成熟度也被涵盖。
