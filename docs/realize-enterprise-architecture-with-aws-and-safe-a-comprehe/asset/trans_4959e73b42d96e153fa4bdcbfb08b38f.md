
## 企业内部的治理层级

架构治理在治理结构层级中运作并不罕见，尤其是对于大型企业而言，可能包括以下具有各自学科和流程的独立领域：

- 公司治理
- 技术治理
- IT治理
- 架构治理

在企业内部，这些治理领域可以在多个地理层级出现，例如全球、区域和本地。诸如 **开放群组架构框架 (TOGAF)** 之类的企业架构框架并不涵盖公司治理的全部主题。如前所述，由于其通常运作的层级结构，本节及相关小节从企业整体治理的角度描述架构治理。

## 治理的本质

治理的责任是确保业务得到妥善开展。组织的战略目标更有可能通过指导方针以及资源公平有效的使用来实现，而不是通过明显的控制和严格遵守规则。

## 治理——通用视角

**经济合作与发展组织 (OECD)** 已将以下内容确定为公司治理的基本原则：

- 对股东权利、角色和公平性的审查
- 确保组织的战略得到良好指导，董事会有效监督管理层，并对公司的成功承担责任
- 董事会成员通过审查和指导公司战略来监督管理层实现公司目标的情况

作为公司治理结构的一部分，董事会确定谁负责什么以及如何负责，以及决定对公司做什么的规则和程序。

## 治理的特征

源自公司治理，以下治理特征旨在强调在企业及其与其他各方的互动中采用治理的价值和必要性：

- **纪律**
  在整个过程中，所有相关方必须遵循组织的政策、程序和授权结构。
- **透明度**
  授权的组织或服务提供商可以检查所有已实施的行动及其决策支持。
- **独立性**
  将努力在所有流程、决策和所用机制中尽量减少或避免潜在的利益冲突。
- **问责制**
  组织内有若干不同的团体对其行动和决策负有授权和责任；例如，治理委员会。
- **责任**
  组织及其利益相关者期望每个签约方都能负责任地行事。
- **公平**
  不会在任何决策、所用流程或流程的实施中给予一方不公平的优势。

这些特征有助于确立公司的目标，提供实现目标的手段，并有助于监控公司的绩效。

## 技术治理

利用技术开发、生产和营销组织的产品和服务是技术治理的责任。技术治理不仅仅涉及 IT 治理。由于技术在整个组织范围内的普遍存在，技术治理是一项关键能力、要求和资源。

除了运营和盈利能力之外，组织越来越多地依赖 IT 来维护其品牌和声誉，这最终会影响其资产的价值。

## IT治理

将 IT 资源和信息与企业目标和战略保持一致的管理被称为 IT 治理。为了确保企业的 IT 资产支持其业务目标，IT 治理将规划、采购、实施和监控 IT 绩效的最佳实践制度化。随着信息系统灾难和电子欺诈报告的增加，监管机构越来越多地要求公司对信息实施更严格的控制。在当今的企业治理框架中，管理与 IT 相关的风险被广泛接受为关键组成部分。

总之，需要一个得到高层管理支持的 IT 治理战略，明确谁拥有企业的 IT 资源以及谁对其实体整合负有最终责任。

## 架构治理框架

本节从概念上和组织上解释架构治理。在架构治理的诸多方面中，实施治理只是其中之一。其目的是管理和控制组织中的所有流程。企业架构师也会考虑企业架构和其他架构设计。

在传统 IT 孤岛仍然存在的情况下，迁移到云没有标准化，也没有集中管理或合规措施。企业工作负载之间标准差异可能导致组织内部出现竞争利益和不一致，尤其是在各方未保持一致时。经常，IT 组织不知道工作负载部署在哪里或如何部署，可用于监控的指标是什么，或哪些工作负载容易受到安全威胁。缺乏控制和审计跟踪使其成为重大的合规风险。开发人员甚至可能不遵循行业安全标准。集中管理不存在。这需要得到控制。Amazon Web Services (AWS) 使客户能够配置和控制其环境以实现业务敏捷性。作为服务的云计算以及 AWS 管理和治理服务为构建者提供预防性和检测性控制，以构建稳健的基础设施并减少漏洞。

## 公司治理的基本原则

而不是严格执行规则，战略规划更多地是提供方向，以及确保公平合理地分配资源以可持续地实现目标。治理本质上涉及业务事务的适当管理。

公司董事会、管理层、股东和其他利益相关者被赋予不同的权利和责任，并且为公司决策制定了规则和程序。商业计划可作为设定和衡量公司目标以及监控其实现程度的方式。

在亚马逊，产品团队会思考开发某款产品的每一个原因以及为什么任何人会想要它。为了说服目标客户选择该产品，会起草一份引人注目的新闻稿。如果没有这份公告，你的生活将是不完整的。只有这样你才能产生影响力。

随着数字化加速，许多公司正在重新思考其架构。为了满足不断增长的期望，公司应尽可能在尽可能多的数字渠道上提供产品。多国公司随着时间的推移发展出非常复杂的结构，这使得及时对其结构进行更改变得困难。与其扩展应用程序的各个部分，不如对整体进行扩展。微服务架构在集成到软件开发中时可以减少软件吞吐时间。除了提高生产力和灵活性之外，微服务还具有健壮性和弹性，因为它们可以独立构建和部署。

## TOGAF 及其目标

TOGAF 的很大一部分源自美国国防部开发的 TAFIM 框架。TOGAF 以及其他 IT 管理框架强调跨部门协调以及将 IT 计划与业务目标保持一致。在项目开始前在 TOGAF 中定义和组织需求可使项目顺利进行且错误较少。其设计目的是通过四个目标帮助企业组织和解决商业和战略需求：

- 所有利益相关者和团队成员必须使用共同的语言
- 不要为企业架构依赖专有解决方案
- 可以节省时间和金钱，并能更有效地利用资源
- 需要可衡量的投资回报率 (ROI)

尽管 TOGAF 的词典中为企业架构工件添加了新的标题，但其规划方法保持不变。最近的更改似乎使当前 TOGAF 规定与行业最佳实践的重叠最小化。根据 TOGAF，它是一个参考库，其中包含指南、模板、模式和其他类型的参考材料，以加速企业架构的创建。
