业务不断演进，企业必须能够评估这些变化对 IT 格局的影响，以及这些变化将如何影响其运营、客户体验和增长能力。更深入地审视这些问题有助于改善转型过程。此外，企业架构师保持精简且敏捷的 IT 环境，以便 IT 能够运行即将到来的业务转型项目。基于此，本章阐明了 EA 使能就绪性为何至关重要，以及组织可以采取哪些步骤来促进它。在此过程中，我们还确定并提供了一个基础，有助于我们理解建立 EA 实践的过程和流程。本章涵盖了识别所有者以及每个所有者的工作流程，以及角色和职责。我们的主要重点仍然是更详细地解释 EA 建模语言。

## 结论

随着组织系统的日益互联，企业架构通过允许开发团队使用一套清晰、经过验证的方法，甚至产品线，为其应用架构工作，从而在各系统间促进一致性。系统间的通用机制和兼容语义使重用以及系统集成成为可能。通过超越当前技术需求并为未来举措奠定基础，这些团队可以超越单一应用并评估架构对整个企业的影响。

制定、验证然后支持架构框架的任务落在企业架构师的职责范围内。数据、安全、网络和硬件基础设施由你的企业管理员构建。此外，你的应用项目团队将负责实施你的企业架构。这是企业架构师应积极参与并提供支持的工作。

企业架构的范围使其与应用架构区别开来。企业架构师指导应用架构师理解和应用企业架构，就像应用架构师指导应用设计师和实施者理解和应用应用架构一样。与应用架构师类似，企业架构师对系统的设计者和实施者而言具有更广但通常更浅的视角。尽管企业架构由企业架构师制定，但实际实施工作由你的应用开发团队和企业管理员负责。

## 架构治理

为了保持顺畅无缝的工作流程，企业架构领导者必须领先于组织的某些要素。首要之列是团队规模、基础设施和组织结构。然而，数字行业领导者必须考虑随此转型而来的挑战和复杂性。只有结构良好且深思熟虑的业务敏捷模型才能适应系统内的持续进步。选择不断变化会带来很大的风险和不可预测性，这对一些利益相关者来说会令人筋疲力尽。
