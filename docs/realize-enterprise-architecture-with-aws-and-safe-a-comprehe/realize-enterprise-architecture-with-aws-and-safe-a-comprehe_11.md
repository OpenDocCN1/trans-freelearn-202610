# 第 4 部分 – 建立 EA

在本书的结尾，我们将把全部重点放在 EA 使能和就绪度上。一旦确定了进行此次云迁移的需要以及战略上的轻微但微妙的转变，下一步就是了解建立 EA 实践的过程和流程。我们将解释 EA 建模语言，这将为您学习 ArchiMate 做准备。

本书的这一最后一部分将为您提供对 EA 实践基础以及它们如何与 EA 卓越中心保持一致的更好了解。此时，您可能会想知道架构工具和建模语言对于 EA 是否必要。因此，本书详细介绍了使用 ArchiMate 的架构工具。

我们将更深入地研究与运营、客户体验和增长能力相关的挑战和风险，这有助于改进转型过程。企业架构师需要保持精简且敏捷的 IT 环境，以便 IT 部门能够运行即将到来的业务转型项目。鉴于此，这些章节传达了 EA 使能就绪度为何至关重要以及组织可以采取哪些步骤来促进它。

EA 通过允许开发团队使用经过验证的方法和产品线来在整个组织的系统中促进一致性。因此，我们将建立并确定一个基础，以帮助理解建立 EA 实践的过程和流程。进一步讨论了 EA 使能就绪度的重要性以及组织可以采取的增强措施。

总体而言，本书这一最后一部分的主要重点是更详细地解释 EA 建模语言。
