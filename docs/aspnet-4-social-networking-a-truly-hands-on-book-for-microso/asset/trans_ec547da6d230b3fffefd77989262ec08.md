

## 博客

在 **Init** 方法的第一部分，我们检查 **WebContext.BlogID** 属性，以确定是否有可用的数据。如果有，我们就用相应的博客加载 UI；如果没有，则意味着我们正在创建一个新的博客条目。接下来你会看到 SavePost 方法，它负责将加载/新建的博客传递给 BlogService 进行保存。

接下来，我们看一下 Presenter 所用的后台代码。这里会看到 LoadPost 和 btnSave_Click 方法。这里的逻辑并不复杂。但需要注意的一点是，我们在页面中跟踪 BlogID，以便后续知道我们正在处理哪个对象。

```
protected void btnSave_Click(object sender, EventArgs e)
{
    Blog blog = new Blog();
    if (litBlogID.Text != "")
        blog.BlogID = Convert.ToInt64(litBlogID.Text);
    blog.IsPublished = chkIsPublished.Checked;
    blog.PageName = txtPageName.Text;
    blog.Post = txtPost.Text;
    blog.Subject = txtSubject.Text;
    blog.Title = txtTitle.Text;
    _presenter.SavePost(blog);
}
public void LoadPost(Blog blog)
{
    txtTitle.Text = blog.Title;
    txtSubject.Text = blog.Subject;
    txtPost.Text = blog.Post;
    txtPageName.Text = blog.PageName;
    chkIsPublished.Checked = blog.IsPublished;
    litBlogID.Text = blog.BlogID.ToString();
}
```

这处理了数据输入和输出的细节。不过，现在我们来看看如何让 UI 可用。你可能记得之前用过 Xinha 所见即所得编辑器，这里我们也会用到它。要启用它，只需要一个多行文本框控件和一行 JavaScript。

```
---
<asp:TextBox TextMode="MultiLine" ID="txtPost"
             runat="server"></asp:TextBox>
---
<script type="text/javascript">
    xinha_editors[xinha_editors.length] = 'Content_txtPost';
</script>
---
```

有了这些，我们就可以创建博客文章了！

## 9 论坛

在本章中，我们将讨论论坛。**论坛**是一个用户可以向社区发布消息的地方，无论每条帖子之间相隔多久，所有回复都是可见的——可以将其视为一场长期持续的对话。随着主题（threads）及其帖子逐渐变旧，新的内容会开始覆盖旧的内容。这使得网站的这一部分成为一个非常动态的区域，许多用户都会关注。这被认为是一个具有“粘性”的功能！考虑到我们社区的主题——海水鱼——论坛是网站的完美功能。它可以让用户发布他们鱼缸遇到的问题，整个社区都能阅读并与该用户的问题互动。随着时间的推移，你的社区会慢慢把某些用户推举为特定主题的专家。最终（你希望如此），你的网站论坛会成为获取特定类型信息的首选之地。即便没有其他好处，我们亲爱的朋友谷歌和必应也会把人引到你的网站。

### 问题

在开始之前，我们应先讨论正确的术语。论坛实际上是一组用于存储数据的容器。我们首先需要能够创建类别。**类别**是最高级别的容器，因此会有一个非常通用的主题。每个类别可以容纳任意数量的论坛。论坛与顶级类别的主题相关，但更加具体。在每个论坛中，我们可以有多个主题。每个主题都是一个非常具体的讨论话题，用户可以在其中进行讨论。讨论通过帖子进行，这些帖子只是对所属主题的回复，或者是该主题下的一个帖子。

与类别类似，我们维护底层帖子和主题的计数，也维护最后发帖的人和时间。注意，我们有一个指向 BoardCategories 表的外键引用。

### 帖子

正如我们前面所说，BoardPosts 表实际上是一个双重用途的表，同时包含帖子和主题。我们这样做主要是因为大多数情况下，每个条目的数据都是相同的，除了父级 **ThreadID** 列以外。

这里需要注意的字段是 **IsThread**。这是判断帖子是否同时是主题的最简单方法。此外，我们还有 **ThreadID**，它也表示帖子和主题之间的区别：主题不会有 **ThreadID**——一个主题永远不会是另一个主题的一部分（至少现在还没有！）。还要注意，我们有一个指向论坛的外键，即 **ForumID** 外键，表示该主题属于哪个论坛。对于主题，我们还会存储其被查看的次数以及回复数。

这种帖子/主题结构的一个好处是，任何普通帖子都可以轻松移出，作为独立的主题处理。版主经常会发现，主题中的某个帖子比初始主题本身带来了更多流量。在这种情况下，该帖子很容易被提升为独立主题！
