
### Table 7.1: A summary of parameters and calculations

| 1st Dim, 2nd Dim, 3rd Dim, 4th Dim (calculated fields) | Translates the parameter selection into an actual Tableau field | These CASE statements convert the parameter number into a field name. For example, if the parameter value is 1, the calculated field returns [Category]. |
| --- | --- | --- |
| Choose Fixed Dims (parameter) | Selects which dimension(s) will be "fixed" in the FIXED LOD calculation | Similar to the Dim parameters, but this one controls the Case Fixed calculated field. Value 1 means "use the 1st Dim field.". |
| Case Fixed (calculated field) | The actual FIXED LOD calculation that users can experiment with | This is where the magic happens: { FIXED [1st Dim] : SUM([Sales]) }. The FIXED function aggregates Sales at the level of the chosen dimension, ignoring other dimensions in the view. |
| Choose Excluded Dims 1 & 2 (parameters) | Selects which dimension(s) will be excluded from the EXCLUDE LOD calculations | These control the Case Exclude 1 and Case Exclude 2 fields. |
| Case Exclude 1 & 2 (calculated fields) | The actual EXCLUDE LOD calculations | These use { EXCLUDE [1st Dim] : SUM([Sales]) }. The EXCLUDE function removes the chosen dimension from the aggregation, regardless of what's in the view. |
| Product Name (context filter) | Reduces the dataset to products starting with "s" | This filter is applied before the LOD calculations, demonstrating how context filters interact with LODs. |

This playground lets you pick up to four dimensions to display in a table, and then compare three different calculations:

- Sales = normal SUM(Sales) at the view level
- Case Fixed = SUM(Sales) fixed at the chosen dimension (ignores other rows/columns)
- Case Exclude 1 & 2 = SUM(Sales) with specific dimensions excluded from the aggregation

You can experiment by changing the parameters and watching how the numbers change. This is the best way to truly understand LODs.

WHEN 4 THEN SUM({EXCLUDE [4th Dim]: SUM([Sales])})

END
