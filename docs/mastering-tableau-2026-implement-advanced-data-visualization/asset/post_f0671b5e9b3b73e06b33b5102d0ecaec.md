## Web Authoring Enhancements

The 2026.1 release brings several exciting enhancements to the web authoring experience that further close the gap between Tableau Desktop and Tableau Server.

- **Rounded corners:** You can now set a corner radius for dashboard objects directly in web authoring. Say goodbye to jumping through hoops with annotations or images. Just set the radius value to create a simple rounded corner or a more extreme corner radius to create different shapes. This feature is available in Tableau Cloud, Tableau Desktop, and Tableau Public, making it easy to create modern, polished dashboard designs right in your browser.
- **Accessible visualization authoring:** Tableau is committed to increasing accessibility to empower everyone to become creators of data visualizations. Within Web Authoring, you can now navigate to a pill and, using your keyboard and assistive technology, select the context menu option to drop that pill into a drop zone, including the Columns and Rows shelves, Show Me, Pages, Filters, or Marks cards. This feature makes it possible to build visualizations without a mouse, opening up data creation to a wider audience.
- **View data model enhancements:** Be aware of how Tableau data models are used within a viz or worksheet, and which tables supply data to which pills in the viz. If a complex calculation is used within a pill, hovering over the pill now highlights the participating tables in the View Data Model; confirming the logic’s correctness. This allows you to diagnose and evaluate your analysis right in your flow of work and avoid the swivel-chair process between worksheet and data source tabs.
- **Smart filter on table name:** Increase analytic efficiency in large data models by enabling users to filter tables by exact name. Use the same table smart filter "T:" followed by double quotes around the exact table name to bypass substring searches. This small but powerful enhancement saves time when working with complex data models.

## Maintaining Workbooks on Tableau Server

Once you start sharing your work on Tableau Server, you’ll quickly realize that creating a dashboard is only half the battle. The other half is maintaining it over time. What happens when you accidentally break a dashboard after an edit? How do you protect your work from being overwritten by colleagues? And how do you ensure that each user sees only the data they are supposed to see—without creating separate workbooks for every person?

In this section, we will explore three essential workbook maintenance features that every Tableau author should know.

## Revision History

You, as a Tableau dashboard developer or even a Tableau Server admin, want to make sure that your users are always looking at the right data. But then this happens: you edit a dashboard and after your edit, the dashboard displays faulty information. A user calls you and wants the old dashboard back immediately. What do you do? Use revision history!

Tableau Server ships with a revision history that ensures that the past 25 versions of each workbook and data source are retrievable. This setting can be enabled or disabled by the Tableau Server admin. In Tableau Desktop, if you attempt to upload a workbook or data source with the same name as a previously uploaded file, Tableau Desktop will display a warning such as **Workbook name is already in use**.

Publishing will overwrite the existing data source. If you proceed with the upload, revision control will be activated, and the previous version of the file will remain accessible as a revision. To access the revision history for individual workbooks and data sources in Tableau Server, simply select any data source or workbook you uploaded and click on the three dots at the bottom right. In the popup, select **Revision History...**:

## Disable Duplicate Custom View Names

Speaking of version control, the 2026.1 release introduces a new feature to strengthen product reliability and create a more intuitive Custom Views experience. Administrators can now block the creation of duplicate Custom View names and provide a clear inline alert when a save will overwrite an existing view. This eliminates silent failures and prevents confusion, particularly in large enterprise environments where many users might create views on the same dashboard.

Revision histories and custom view management are so helpful! I hope you will not have to use them often but it's always good to have options. The next question many organizations have is, how can I make sure that users only see what they are supposed to see and not just everything that has been published to Tableau Server? One solution is user filters. We will discuss this topic next!

## User Filters

It's important that the sales managers see only their metrics; that is, not the metrics of the other sales managers. In order to accomplish this, do I have to create separate workbooks for each sales manager?
