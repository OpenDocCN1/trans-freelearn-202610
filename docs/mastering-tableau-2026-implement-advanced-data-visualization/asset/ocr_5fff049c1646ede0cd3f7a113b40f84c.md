+   11. In the **State** filter, select only **Alabama**. Note that the **City** filter does not update.
+   
+   12. Enable **Auto Update Filters** via the toolbar. The **City** filter now updates.

Auto updates can be very helpful. The author may pause auto updates, make multiple changes, and then resume auto updates, thereby saving time and increasing performance indirectly.

As a side note, cascading filters such as **Only Relevant Values** or **All Values in Context** may not populate wnen using the pause button or auto updates, as they are reliant on a query being passed first.

# # The run update feature

The **Run Update** icon to the right of the pause/resume auto updates option is meant to refresh once, while the user can keep the disabled **Auto Update** feature in place. The following brief example should help clarify this option:

+   1. Duplicate the **previous** worksheet called Auto Updates and name the duplicate Run Updates
+   2. Pause all updates by clicking on the **Pause Auto Updates** icon
+   3. Select several states at random in the **State** filter
+   4. Click on the **Run Update** icon as shown in **Figure 12.5** and select either **Update Filters** or **Update Worksheet**. The shortcut key for running an update is F9 on Windows. The shortcut on macOS is Shift + Command + 0:

+   5. Select several more states at random in the **State** filter. Note that auto updating is still paused.

To repeat, **Run Update** allows the Tableau author to intermittently refresh the view while keeping auto updates paused. The two update features that we just discussed will make your life as a dashboard developer easier by allowing you to make multiple changes before loading and hence waiting for the refreshed data, but if you want to tackle performance issues at their core, you need some more tools to hand. Auto updates help you avoid unnecessary refreshes while you build, but if the workbook is slow even when you do refresh, you often need to reduce data volume; this is where small extracts help.

A common question I hear from dashboard authors is: "How many worksheets can I put on a dashboard before it becomes slow?"

There's no single answer, but here are practical guidelines based on real-world testing:

+   • 1-5 sheets should give you excellent performance for executive summary dashboards, KPI monitors.
+   • 6-10 sheets should lead to good performance and will be seen in department dashboards, operational views.
