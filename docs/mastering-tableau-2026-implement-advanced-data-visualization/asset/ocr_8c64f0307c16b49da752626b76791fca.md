# Understanding Tableau Server permissions hierarchy

Permissions in Tableau Server follow a hierarchical structure. Understanding this hierarchy is key to setting up access correctly and avoiding confusion when users cannot see what they expect to see.

The permission hierarchy (from highest to lowest):

| Level | What It Controls | Example |
|---|---|---|
| Server | Global access to the entire Tableau Server instance | Who can log in at all |
| Site | Access to a specific site (if multiple sites exist) | Who can see the "Sales" site? |
| Project | Access to all content within a project | Who can see the "Finance" project folder? |
| Content | Access to individual workbooks, data sources, or flows | Who can edit the "Executive Dashboard"? |

Table 13.1: The permission hierarchy

This structure relies on the principle of inheritance, where permissions set at a higher level automatically flow down to lower levels; for instance, giving a user View access to a project folder naturally grants them View access to all workbooks inside it.
