

# 存储现代化最佳实践

- **存储分类**：了解各种存储需求，并根据工作负载、检索频率、延迟、IOPS、存储位置、复制需求、容量和数据格式选择合适的存储类型。利用存储类型选项，根据工作负载需求实现性价比平衡。
- **数据传输**：利用各种存储传输方法进行批量数据传输，例如基于网络的传输、基于设备的传输和软件驱动的数据传输，同时需要考虑速度、数据量、传输频率和延迟。
- **构建冗余**：利用多级冗余来设计系统并保护数据，防止设备故障、数据中心故障和数据丢失。对于非关键数据（可从源数据重新生成的数据），利用云存储内置的冗余就足够了。但是，对于业务关键数据，需要规划额外的数据复制和备份策略。
- **存储策略**：虽然某些存储类型可以灵活地用于多种用途，但基于云的存储类型为各种应用需求提供了专用存储。对于一般应用工作负载，可使用持久化磁盘（HDD、SSD）；对于大规模非结构化数据，可使用对象存储；对于**网络文件系统**（**NFS**）和**网络附加存储**（**NAS**），可使用文件存储。
- **存储生命周期管理**：通过启用自动生命周期管理策略来优化对象存储的使用。例如，将使用频率较低的数据与使用频率较高的数据区分开，并将数据移动到合适的存储类别。实施自动化的数据生命周期管理策略，根据预定义的标准移动、归档或删除数据，以优化存储成本和性能。
- **基于云的内容分发网络（CDN）**：利用基于云的 CDN 来缓存和提供静态数据，以优化成本和访问延迟。
- **数据加密**：建立一致的数据加密方法，对静态数据和传输中的数据进行加密。根据数据类型和数据敏感程度，采用相应的加密方法和密钥管理技术。
- **元数据管理**：实施有效的元数据管理策略，以增强混合存储环境中数据的可发现性和可访问性。
- **数据复制与同步**：实施数据复制和同步机制，以确保本地和云存储环境之间的数据一致性和可用性。使用云存储网关促进本地存储系统与云存储服务之间的无缝通信。

在回顾了企业如何重新构想和思考涵盖计算、网络和存储的基础设施现代化之后，现在让我们来探讨组织如何在云中开发和现代化应用。

# 应用现代化战略

数字化转型的下一个关键方面是应用现代化。随着组织向云原生应用开发和部署过渡，实施稳健的应用现代化战略至关重要。应用现代化并非“一刀切”的方法，它取决于每个组织的长期数字化转型目标以及云战略的选择。然而，组织可以采纳一些基本原则，以提高业务敏捷性、可扩展性和弹性，并减少技术债务。应用现代化可分为两大类——传统应用现代化和云原生应用 DevOps。

## 传统应用现代化

虽然在云原生范式下更容易构想和构建新应用，但重新架构和重写遗留应用并不总是可行的。当组织专注于应用现代化时，明确制定企业中现有遗留应用和传统单体应用的战略非常重要。以下是一些最佳实践：

- **确定优先级并规划迁移**：使用 6R 方法对应用进行分类，为遗留应用现代化发布短期、中期和长期的迁移批次路线图，并将此传达给企业内的利益相关者。这通常是奠定云转型基调的重要第一步。
- **契合度评估**：进行全面的契合度评估，以根据目标状态目标识别适合迁移的候选应用和阻碍因素。例如，某些计划重写的遗留应用，在采用混合云战略的情况下可以保留在本地；而对于采用分阶段转型方法或数据中心退出战略的组织，则可以将这些应用重新托管、共置或迁移到公有云。
- **利用容器实现现代化**：对于使用 Java 和 .NET 技术栈构建的传统应用，利用容器对其进行现代化改造，使其适配云端。企业通常可以将此策略作为中间阶段策略来采用，之后再将应用完全重新架构为云原生。
- **虚拟化策略**：在传统企业中，应用通常运行在各种虚拟化技术上，而这些技术往往是专有的。这些技术可能包括 VMware、Hyper-V 或**红帽虚拟化**（**RHV**）。由于云平台依赖**基于内核的虚拟机**（**KVM**）和 Xen 等开放虚拟化标准，企业必须制定明确的策略来实现虚拟化应用的标准化。
- **通过 API 网关进行抽象**：在某些情况下，一些遗留应用可能并非合理化、现代化或迁移的理想目标。然而，随着组织不断现代化并构建云原生应用，它们将不得不与这些应用无缝集成。API 管理解决方案可以充当抽象层，将遗留应用的功能以标准 RESTful API 的形式暴露出来，使面向客户端的应用免受后端服务变化的影响，并让现代应用和云服务能够使用这些功能。该策略还允许企业快速构建外围应用并交付移动应用等新功能，同时允许底层应用随着时间的推移逐步实现现代化。API 管理还为遗留服务带来了安全性、分析能力和可扩展性。

## 云原生 DevOps

云原生应用开发是一套在云中构建和运行应用的原则和实践，旨在利用云计算平台的独特特性。DevOps 是一套强调开发团队与运维团队之间协作的实践，以确保应用能够快速高效地构建和部署，并且可靠、可扩展。云原生应用 DevOps 是在云中构建和运行敏捷、可扩展、弹性且高效的应用的强大方式。让我们来探讨一些构建云原生应用的最佳实践：

- **微服务架构**：使用微服务架构构建应用，以获得更好的可扩展性、灵活性和可维护性。利用 Docker 和 Kubernetes 等容器和容器编排技术来打包应用，并实现应用服务的自动化部署、扩展和管理。
- **API 与服务网格**：实施 API 以实现微服务之间的通信，并考虑使用服务网格来管理服务与服务之间的通信。采用 API 优先的方法来加速应用设计，以便在混合云和多云环境中治理、分析并全面掌握所有应用 API 的情况。
