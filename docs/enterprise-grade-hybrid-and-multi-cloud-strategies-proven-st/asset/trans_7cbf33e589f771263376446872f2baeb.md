

- **混合云灵活性**：Azure Stack 支持混合云战略，使组织能够在本地和 Azure 公有云中运行工作负载。对于因监管要求、数据驻留问题或特定性能需求而需要将某些工作负载保留在本地的场景，这种灵活性非常有价值。
- **集成的安全性和合规性**：Azure Stack 继承了 Azure 的安全功能和合规认证。这确保在 Azure Stack 上运行的工作负载能够获得与 Azure 公有云中相同级别的安全控制、身份管理和合规标准。
- **面向容器的应用服务**：Azure Stack 通过 **Azure Kubernetes Service**（**AKS**）和 **Azure Container Instances**（**ACI**）支持容器。这使组织能够使用容器化架构现代化应用，同时保持在本地运行它们的灵活性。
- **边缘和断连场景**：Azure Stack 适用于低延迟处理至关重要的边缘计算场景。它使组织能够在偏远地点或连接受限的区域部署 Azure 服务，确保一致的计算体验。

以下是一些关键考量：

- **硬件兼容性和要求**：部署 Azure Stack 需要符合 Microsoft 规格的兼容硬件。组织需要确保其现有基础设施或新投资与 Azure Stack 的要求保持一致。
- **运营复杂性**：虽然 Azure Stack 简化了混合云运营的某些方面，但管理混合环境仍然可能很复杂。组织需要投入培训和资源，以有效运营和维护 Azure Stack。
- **成本考量**：组织应仔细评估部署和维护 Azure Stack 的总体拥有成本（TCO）。这包括硬件成本、许可费用和持续的运营支出。

# 第 9 章 数字化转型的九个方面

何时才是制定云战略的合适时机？对一些企业而言，答案是在采用云的同时；而对另一些企业而言，答案仍不明确。Gartner 在其 *Cloud Strategy Cookbook* 中建议，组织甚至应在启动云转型计划之前就制定云战略 *\[1\]*。该手册认识到，考虑到现代企业多样化的需求和业务目标，一刀切的云方法是不够的。随着现代技术不断模糊业务与 IT 之间的界限，将组织的云战略与业务目标紧密对齐至关重要，这样才能最大化云投资所带来的价值并推动切实成果。随着组织持续采用云计算——无论部署模式是 IaaS、PaaS 还是 SaaS——设计并制定一项将作为未来业务目标基础的数字化战略至关重要。那些主要在数据中心边界内支撑传统 IT 生态系统的工具、流程和技术，已无法支撑基于云的生态系统的规模、多样性、复杂性和需求。踏上云之旅会给企业 IT 的各个职能带来范式转变。一个基本示例是云的共同责任模型：云提供商负责管理和保护部分技术栈，而消费者负责其余部分。这本身就是企业 IT 运营的重大转变，因为组织现在对基础设施或应用程序栈的很大一部分几乎没有或完全没有控制权。此外，这也意味着栈顶层的责任同样受到明确框架的引导和限制。例如，如今大多数组织的 IT 生态系统中都有某种形式的 SaaS 应用——想想用于办公应用的 Microsoft 365、用于在线生产力的 Google Workspace、用于 HR 的 Workday，或用于 CRM 的 Salesforce。所有这些应用都运行在传统 IT 组织无法控制的云环境中。这意味着组织的 IT 足迹刚刚扩展到传统数据中心的边界之外，因此需要一套稳健的战略来覆盖网络连接、集成、应用安全、数据安全和治理。

在本章中，我们将探讨数字化转型的各个方面，它们可以帮助为组织的云战略奠定基础并定下基调。具体来说，我们将探讨以下主题：

- 企业如何构建安全优先的云基础，以确保涵盖网络、数据、应用和资产管理的整体企业安全
- 学习在混合云图景中重新思考基础设施，重点关注基础设施现代化
- 构建云原生应用的策略，重点关注应用现代化
- 利用云原生设计实现数据生态系统现代化
- 学习如何构建云治理模型，以优化云基础设施的成本、性能和资源效率，并最大化云投资的价值
