## 第 9 章 数字化转型的九个方面

何时才是制定云战略的合适时机？对一些企业而言，答案是在采用云的同时；而对另一些企业而言，答案仍不明确。Gartner 在其 *Cloud Strategy Cookbook* 中建议，组织甚至应在启动云转型计划之前就制定云战略 *\[1\]*。该手册认识到，考虑到现代企业多样化的需求和业务目标，一刀切的云方法是不够的。随着现代技术不断模糊业务与 IT 之间的界限，将组织的云战略与业务目标紧密对齐至关重要，这样才能最大化云投资所带来的价值并推动切实成果。随着组织持续采用云计算——无论部署模式是 IaaS、PaaS 还是 SaaS——设计并制定一项将作为未来业务目标基础的数字化战略至关重要。那些主要在数据中心边界内支撑传统 IT 生态系统的工具、流程和技术，已无法支撑基于云的生态系统的规模、多样性、复杂性和需求。踏上云之旅会给企业 IT 的各个职能带来范式转变。一个基本示例是云的共同责任模型：云提供商负责管理和保护部分技术栈，而消费者负责其余部分。这本身就是企业 IT 运营的重大转变，因为组织现在对基础设施或应用程序栈的很大一部分几乎没有或完全没有控制权。此外，这也意味着栈顶层的责任同样受到明确框架的引导和限制。例如，如今大多数组织的 IT 生态系统中都有某种形式的 SaaS 应用——想想用于办公应用的 Microsoft 365、用于在线生产力的 Google Workspace、用于 HR 的 Workday，或用于 CRM 的 Salesforce。所有这些应用都运行在传统 IT 组织无法控制的云环境中。这意味着组织的 IT 足迹刚刚扩展到传统数据中心的边界之外，因此需要一套稳健的战略来覆盖网络连接、集成、应用安全、数据安全和治理。

在本章中，我们将探讨数字化转型的各个方面，它们可以帮助为组织的云战略奠定基础并定下基调。具体来说，我们将探讨以下主题：

- 企业如何构建安全优先的云基础，以确保涵盖网络、数据、应用和资产管理的整体企业安全
- 学习在混合云图景中重新思考基础设施，重点关注基础设施现代化
- 构建云原生应用的策略，重点关注应用现代化
- 利用云原生设计实现数据生态系统现代化
- 学习如何构建云治理模型，以优化云基础设施的成本、性能和资源效率，并最大化云投资的价值

## 构建安全优先的云架构





如果以**国家标准与技术研究院**（**NIST**）维护的**国家漏洞数据库**（**NVD**）中所发布的**通用漏洞与暴露**（**CVE**）数量来衡量，我们会发现仅在过去 7 年中，CVE 数量就增长了惊人的 4.5 倍。根据数据，2016 年 NVD 平均每周发布约 100 个 CVE，而到 2023 年这一数字跃升至每周 450 个 CVE *\[2\]* *\[3\]*。

安全是每个人的事，对于现代企业而言尤其关键，因为随着云计算的普及，现代技术的获取已变得大众化。在网络威胁日益复杂化的时代，为企业构建安全优先的云架构是一项至关重要的任务。

企业在采用云计算时通常会遇到的一个共同挑战，是云引入的共享责任模型。清晰理解共享责任模型，对于保护云中的应用工作负载和数据安全极为重要。由于共享责任模型可能因每个**云服务提供商**（**CSP**）、服务模型以及所使用云服务的不同而各有独特定义，这一任务往往颇具挑战性。

在深入探讨安全控制之前，我们先回顾一下组织在云转型过程中面临的一些常见挑战。根据 *Pandemic 11* 报告，以下是组织在云安全方面面临的首要担忧 *\[4\]*：

1. 身份、凭据、访问和密钥管理不足
2. API 和接口不安全
3. 云配置错误以及变更控制不当
4. 缺乏云安全战略和架构
5. 软件开发实践不安全

除此之外，企业还面临以下由外部威胁向量进一步加剧的挑战：

- **云服务的持续变化**：由于云服务具有动态特性，新服务不断更新和发布，企业必须保持警惕。为了跟上步伐，组织必须建立相应的流程和安全控制，以对照基线安全配置进行验证和测试，从而满足不断变化的要求并保持合规。
- **利用多个服务层**：企业的工作负载通常跨越多种服务类型。这要求在兼顾整体工作负载安全需求的同时，对每种服务类型的安全控制进行统一和验证。例如，支付处理服务可能利用多种服务类型（计算基础设施、API 平台和支付网关 SaaS），同时需要满足**支付卡行业**（**PCI**）合规义务。
- **数据安全**：随着企业数据从本地环境扩展到云端，数据安全成为企业的一个关键决策点。根据监管要求和数据引力，安全组织必须确定数据加密密钥的管理位置，这一点至关重要。
- **外部威胁**：随着新的安全漏洞和**高级持续性威胁**（**APT**）持续增加，这可能构成重大挑战。例如，暴力破解/**分布式拒绝服务**（**DDoS**）攻击、恶意软件或勒索软件攻击，以及**中间人**（**MITM**）攻击，都可能成为企业必须防范的新攻击向量。

让我们探讨企业在构建云基础时必须考虑的一些基础安全原则。

## 基础安全原则

对希望利用云计算优势同时确保数据和应用程序安全的企业来说，构建安全的云环境极为关键。通过实施基础安全原则，组织可以建立稳固的安全态势，保护数据和应用程序，并与内外部利益相关者建立信任。让我们进一步了解这些原则：

- **着陆区设计**：云服务部署最基础的方面是着陆区设计。着陆区定义了组织云部署的基础方面，如组织策略、互联互通、资源管理、安全、网络以及**身份和访问管理**（**IAM**）。在组织开始在云上部署工作负载之前，健全的着陆区设计必不可少。同样重要的是，将着陆区设计模块化，并在考虑可扩展性和增长需求的前提下进行适配。
- **零信任架构（ZTA）**：云中的零信任安全是一种消除云环境内隐式信任的综合方法 *\[5\]*。零信任不假设网络内的用户或设备值得信赖，而是要求对所有访问请求进行持续验证和认证。这通过**多因素认证**（**MFA**）、最小权限访问和微隔离等机制实现。通过将访问限制在必要范围内，零信任最小化攻击面，从而降低入侵风险。
- **风险评估**：定期进行正式风险评估至关重要，以确保组织的安全要求既满足内部安全义务，也满足外部安全义务。这提供了风险摘要以及组织检测和应对安全威胁的能力。一些最佳实践包括利用**云安全联盟**（**CSA**）的**云控制矩阵**（**CCM**）和**互联网安全中心**（**CIS**）基准进行风险评估。
- **定义并采用安全蓝图**：自动化是跟上不断变化的安全态势的关键。安全组织的主要职责之一是为云中的一些常见部署定义安全蓝图。这些蓝图可以标准化企业资产部署，同时支持更快的部署和集中治理。
- **分层安全设计/左移安全策略**：企业必须采用分层的**纵深防御**（**DiD**）安全设计，利用应用程序或工作负载每一层的安全功能来限制攻击向量。另一种策略是在开发和部署阶段融入安全最佳实践；例如，测试应用程序代码中的安全问题、在部署期间扫描容器镜像、自动扫描以及检测配置错误和安全反模式。
- **自动化部署和安全监控**：通过自动化部署来消除手动部署活动中的人为错误，不仅能提高开发和部署速度，更重要的是能改善组织的安全态势。同样，投资自动化工具来扫描基础设施漏洞并自动化扫描**持续集成/持续部署**（**CI/CD**）管道，也是一项安全最佳实践。
- **用于安全自动化的机器学习（ML）**：机器学习在增强企业云安全方面发挥着关键作用，它为威胁检测、**事件响应**（**IR**）和整体风险管理提供了高级能力。随着云环境变得更加复杂、动态和互联，基于机器学习的安全自动化可以帮助实现高级威胁检测、**用户与实体行为分析**（**UEBA**）以及零日预测分析，并改善云中工作负载的整体安全性。





*   **遵守数据主权和数据驻留要求**：根据企业性质，遵守当地法规以及数据驻留和数据主权要求至关重要。从头开始架构应用程序以满足合规要求，往往能节省大量时间和精力；例如，在面向公共部门的安全云区域中托管工作负载，并利用机密**虚拟机**（**VM**）防止内存数据泄露。
*   **补偿性控制**：在云端的共享责任模型下，组织应努力通过技术补偿性控制、合同保护和第三方认证来降低风险。例如，利用云原生安全控制对静态数据和传输中数据进行加密可作为一种技术补偿性控制，而**业务伙伴协议**（**BAA**）或**云数据处理附录**（**CDPA**）可作为合同保护 *\[6\]*。
*   **风险保护计划**：最后，企业还可以利用网络保险计划，更好地了解、修复风险，并实现高水平的安全态势。
*   **安全审计和评估**：定期开展渗透测试，以识别和解决网络基础设施中的漏洞。使用自动化漏洞扫描工具，定期评估云环境的安全态势。

## 自动化云资产管理

拥有准确的资产清单，并充分了解所有云资产及其关系，对企业安全至关重要。随着团队开始构建应用程序或将工作负载迁移到云端，资产管理可能迅速变得复杂且难以管控。使用**基础设施即代码**（**IaC**）工具（如 Terraform）自动化资产管理，有助于满足企业安全最佳实践。安全团队还必须专注于实施自动化资产监控和告警，以监控资产的不合规情况和偏离安全蓝图的行为。在混合云部署模型的背景下，企业还可以利用现有的**安全信息和事件管理**（**SIEM**）系统作为**单一视图**（**SPOG**），以管理和监控整个企业的资产。

## IAM

**IAM** 是保护企业资源的关键组件，特别是在多云和混合云环境中，资源分布在本地数据中心和云服务提供商（CSP）之间。实施有效的 IAM 实践有助于组织管理用户访问、保护敏感数据并确保合规。以下是一些 IAM 最佳实践：

*   **集中式身份管理（IdM）**：实施一个跨越本地和云环境的集中式 IdM 系统。这种集中化有助于简化用户预配、取消预配和访问管理流程，同时也能安全地集中管理身份。
*   **实施破玻璃应急程序**：云中的破玻璃应急程序是指一种紧急访问机制，在发生锁定等紧急情况时，授予临时的特权访问权限以访问云中的关键系统或数据。此程序通常保留用于高度敏感的操作，或在其他访问方法不可用时使用。它通过严格的安全控制来实施，以防止未经授权的使用。一旦激活，破玻璃应急程序允许指定人员绕过正常的访问限制，从而使他们能够快速解决关键问题或降低风险。
*   **通过单点登录（SSO）联合访问**：使用安全的联合协议，如**安全断言标记语言**（**SAML**）或**开放授权**（**OAuth**），实现本地和云环境之间的身份联合，允许用户一次性认证并无缝访问资源。
*   **启用 MFA**：强制要求访问关键系统和数据时使用 MFA。这增加了一层额外的安全保障，即使凭证泄露，也能降低未经授权访问的风险。
*   **保护超级管理员账户**：避免使用现有用户账户，为超级管理员访问创建新账户。确保破玻璃应急程序有完善的文档记录，启用 MFA，并结合物理安全令牌和备用账户使用。
*   **记录所有活动**：确保所有云活动均被记录并集成到集中式 SIEM 中。这也有助于审计访问并满足合规要求。
*   **实施最小权限原则（PoLP）**：过度授权用户访问权限通常是与云资源配置错误及内部威胁风险相关的首要安全风险。在整个组织中采用 PoLP 或**即时**（**JIT**）访问策略。实施针对特权访问的强有力控制，如会话录制和监控，可降低未经授权操作的风险。
*   **自动化策略控制**：利用云原生工具自动审查访问策略、权限和不必要的特权，以便及时将安全风险降至最低。

## 网络安全

将网络扩展到传统数据中心之外会对网络安全产生影响。本地网络通常具有明确、可预测的网络边界或边界，更容易通过网络防火墙、**入侵检测系统**（**IDS**）和物理路由器进行保护。确保强大的网络安全，特别是在混合云环境中，对于保护敏感数据、保持合规和防范网络威胁至关重要。保护混合云网络的一些最佳实践如下：

*   **分段和微分段**：将网络划分为多个段，以隔离不同类型的数据和服务。如果一个网段被攻破，这能限制攻击者的横向移动。实施微分段以应用细粒度的访问控制，特别是在多层应用程序中。这限制了各个工作负载之间的通信。
*   **致力于零信任网络**：零信任安全模型意味着默认不信任任何人，无论他们从何处访问网络，除非伴随其他层级的访问检查，如身份检查、上下文或受信任设备。
*   **保护跨云连接**：使用**虚拟专用网络**（**VPN**）或专用连接（如 Google Cloud Interconnect、AWS Direct Connect 或 Azure ExpressRoute）确保本地和云环境之间的安全连接。使用 TLS/SSL 等协议加密 Web 流量，使用 IPsec 加密站点到站点 VPN，以保护传输中的数据。
*   **保护云边界**：利用纵深防御（DiD）网络安全策略，在不同层级定义网络防火墙策略和规则，以允许或拒绝网络流量。
*   **自动化网络流量检查**：利用云原生工具，如云 IDS、基于 ML 的**下一代防火墙**（**NGFW**）、防火墙规则日志记录和流量镜像，来检查、监控和保护云中的工作负载。
*   **应用安全**：部署**Web 应用防火墙**（**WAF**）以保护 Web 应用免受常见安全威胁和漏洞的侵害。通过适当的身份验证、授权和加密来保护 API，防止未经授权的访问和数据泄露。
*   **网络监控和日志记录**：实施持续的网络监控，以及时发现异常和潜在安全事件。集中管理本地和云环境的日志，以全面了解网络活动。
*   **实施云访问安全代理（CASB）**：实施集中式 CASB 解决方案，特别是在混合云和多云部署中，以监控和管理云服务的使用，并确保合规和数据安全。

## 应用安全




在混合云环境中保护应用安全对于保护敏感数据、确保合规性以及维护业务运营的完整性至关重要。组织在云端开发应用时采用分层安全方法，并将安全实践**左移**，这至关重要。以下是在混合云或多云环境中应用安全的一些最佳实践：

- **实施安全应用开发最佳实践**：培训开发人员掌握安全编码实践，并利用自动化 DevOps 工具缓解应用代码中的常见漏洞，例如注入攻击、缓冲区溢出和**跨站脚本攻击**（**XSS**）。

- **使用安全加固的虚拟机或容器镜像**：强制执行策略，仅利用安全加固的虚拟机镜像和容器镜像进行应用开发和部署。利用云原生产品，如屏蔽虚拟机。

- **自动化应用发布**：由于复杂的应用开发环境错综复杂，手动部署、更新和修补它们非常困难，尤其是在遵循一致的安全要求时。自动化部署流水线可以消除人为错误、标准化开发反馈循环、实现快速产品迭代并保障应用发布安全。

- **实施 DevOps 安全**：特别是在云原生应用开发中，攻击者可能会破坏 CI/CD 流水线，从而影响整个技术栈。建立最佳实践，如二进制授权、保护制品或容器注册表、容器镜像漏洞扫描、加密容器镜像，以及在 CI/CD 流水线中进行签名验证。

- **补丁管理**：通过实施稳健的补丁管理流程，使所有应用组件、框架和库保持最新安全补丁。组织必须为补丁频率、优先级、漏洞扫描和测试程序制定明确准则，并实施自动化补丁管理工具以简化和加速部署流程。

- **依赖项扫描**：定期扫描第三方库和依赖项中的已知漏洞。解决并更新应用堆栈中的任何易受攻击组件。此外，建立流程验证第三方组件——尤其是开源组件——保持最新并符合企业安全标准。

- **实施动态应用安全测试 (DAST)**：使用 DAST 工具模拟真实攻击场景，并在运行时识别漏洞。

# 数据安全

云中数据安全的重要性怎么强调都不为过，因为组织越来越依赖云服务来存储、处理和管理其数据。实施强有力的安全措施以防范不断演变的威胁、确保合规性并维护数据信任，势在必行。以下是企业可采用的一些最佳实践，以保护混合云环境中的数据：

- **数据分类**：根据敏感度和法规要求对数据进行分类，并根据分类应用相应的安全措施。利用自动化工具在数据生命周期早期对数据进行分类和保护。

- **实施全面的数据治理**：数据治理是一系列流程的组合，确保数据被编目、保护、准确、可用且可获取。建立稳健的数据治理实践，包括数据管理性和数据生命周期管理。基于数据引力，实施数据治理最佳实践，如数据编目、自动元数据收集和企业数据质量检查，以识别和整理数据资产。

- **数据加密**：加密本地环境与云环境之间传输过程中的数据。实施专为数据分类设计的加密机制。例如，针对**联邦信息处理标准**（**FIPS**）140-2 3 级数据安全，利用**硬件安全模块**（**HSM**）进行密钥管理。

- **实施数据丢失防护 (DLP)**：部署 DLP 解决方案以监控、检测和防止未经授权的敏感数据访问和传输。实施数据掩码和遮盖技术以保护敏感信息，并使用令牌化用令牌替换敏感数据，降低处理和存储关键信息的相关风险。

- **备份和灾难恢复 (DR)**：实施关键数据的定期备份，并确保**灾难恢复计划**（**DRP**）包含数据恢复程序。纳入将任务关键型数据备份到不可变、版本控制、冗余存储中的程序，以缓解和防止勒索软件等攻击。

- **数据保留策略**：定义并强制执行数据保留策略，以确保定期清除不必要的数据，降低暴露风险。

- **使用密钥管理器管理机密**：集中采用密钥管理解决方案来存储和保护机密，如应用凭据、数据库密码、API 密钥、账号密钥和 TLS 证书。实施最佳实践，如自动密钥轮换策略。

# 数据主权和数据驻留

数据主权和数据驻留要求通常基于区域性和行业特定法规。不同组织可能有不同级别的要求。随着应用和数据跨越本地环境和云端，了解并管控数据如何以及在何处存储、访问和处理以符合法规要求非常重要。一些最佳实践包括：

- **确保数据主权**：对于有数据主权要求的企业，控制并防止云提供商访问数据至关重要。一些技术包括将加密密钥存储和管理在本地密钥管理器中、授予对密钥请求和访问的细粒度访问控制，以及保护使用中的数据。

- **管理运营主权**：在目标云环境中实施策略，如保障计划，以确保企业工作负载仅部署在特定区域和可用区，并根据地理位置和认证限制云人员访问，以符合法规。

- **管理软件主权**：软件主权是指无论目标环境如何，都能快速部署或迁移软件应用的能力。这是一项重要的 DevOps 实践和考量，以确保软件主权得以维持。

- **管理数据驻留**：数据驻留是指企业静态数据的存储位置。这包括确保数据仅在授权区域存储、备份和复制。

现在我们已经了解了如何构建安全优先的云基础，让我们探讨企业如何在云中重新思考基础设施。

# 重新思考基础设施




数字化转型的下一个方面是基础设施现代化。构建混合云基础设施涉及整合本地和云资源，以创建灵活且可扩展的 IT 环境。企业必须重新思考基础设施，以实现更高的自动化、一致性和可扩展性，这些对于有效管理动态 IT 环境至关重要。企业可以采用的策略之一是将基础设施资源视为牛群而非宠物。这种方法符合 DevOps 的原则，非常适合云原生和容器化应用，因为应用对底层基础设施的依赖微乎其微。然而，这是企业 IT 传统看待基础设施方式的范式转变，传统上基础设施被视为不可替代且单独管理。我们将基础设施组件分为计算基础设施、网络基础设施和存储基础设施。

## 计算基础设施

计算基础设施是基础但关键的组成部分，构成了组织交付可扩展、灵活且高效计算资源能力的支柱。无论采用何种云战略，以下是企业可以采用的一些最佳实践：

* **标准化基础设施**：必须为服务器定义标准化配置，以确保整个基础设施的一致性。避免手动配置更改，并依赖自动化工具识别和修复配置漂移，以确保基础设施一致性。

* **自动化基础设施**：利用 `IaC` 工具（如 `Terraform` 或 `Ansible`）以可重复且自动化的方式定义和部署基础设施配置。将基础设施变更集成到 `CI/CD` 流水线中，以自动化测试、部署和回滚流程。

* **解耦基础设施**：将服务器视为不可变实体，通过替换或更新整个实例而不是修改现有实例。这降低了配置漂移的风险并确保一致性。将应用层与底层基础设施解耦，以确保应用可移植性并最大化使用无状态的无服务器计算选项。将实例视为短暂且可丢弃的。不要在单个服务器上排查和修复问题，而是通过自动化将其替换为新实例。在解耦架构时实现缓存逻辑，并利用实时迁移等功能减少对基础设施的依赖。

* **为规模而构建**：利用自动扩缩容组或类似的云原生功能，根据需求自动调整实例数量。这确保了可扩展性以及对不同工作负载的响应能力。

* **计算选择**：利用多种计算选项并提供选择能力，以支持不同成熟度水平的 DevOps 团队。例如，制定明确策略，提供裸金属解决方案、`VMs`、容器编排和无服务器技术，供 DevOps 团队按需选择。

* **自愈系统**：设计自愈系统，通过自动检测故障并从故障中恢复，减少在基础设施问题发生时对人工干预的需求。

* **声明式基础设施**：使用声明式方法定义基础设施的期望状态。声明基础设施应呈现的样子，并让自动化工具将其带到该状态。

* **版本控制**：对基础设施代码进行版本控制，以跟踪变更，并在需要时回滚到先前配置。

* **测试**：将自动化测试纳入部署流水线，在基础设施变更进入生产环境之前进行验证，包括功能测试、安全测试和性能测试。

* **持续改进**：基于基础设施性能探针建立反馈回路，持续评估和改进基础设施。监控性能，收集事件反馈，并利用这些信息优化和增强配置。

## 网络基础设施

为混合云和多云战略设计网络基础设施，涉及创建无缝且安全的环境，整合本地和云资源。在本地和云生态系统之间建立稳健、冗余且安全的网络连接，对于提供低延迟的**服务质量**（**QoS**）和改善客户体验至关重要。以下是一些最佳实践：

* **尽早设计虚拟网络**：考虑尽早设计虚拟网络，兼顾长期目标并预留扩展空间。设计跨越所有所选云提供商的统一网络架构。在设计中考虑带宽、延迟和数据传输成本等因素。这包括谨慎分配稀缺网络资源（例如将连续的 `IP` 范围分配给不同云生态系统）、`IPv6` 采用策略、防火墙配置和流量路由，因为后期更改网络配置往往极其困难且具有挑战性。

* **冗余网络**：在建立本地和云生态系统之间的连接时，考虑建立冗余网络连接，用于回退和网络**高可用性**（**HA**）。如果存在极端的 `HA` 要求，考虑通过多个**服务提供商**（**SPs**）来配置冗余网络。

* **云互联**：定义连接云和本地网络的网络策略。利用直连或专用网络链路，在本地基础设施与每个云提供商之间建立高性能、低延迟的连接。对于多云战略，考虑采用云交换设计，以便集成并让跨多个云的服务直接通信。使用 `VPNs` 通过互联网建立安全、加密的连接，适用于敏感度较低的数据传输。

* **网络 QoS**：实施网络 `QoS` 措施，优先处理关键网络流量。定义带宽分配策略，以确保关键应用获得最佳性能。

* **统一 DNS**：实施统一的 `DNS` 策略，利用 `DNS` 转发或与云 `DNS` 服务集成，实现本地和云资源之间的无缝解析。这在跨多个云解析 `DNS` 时通常是一个常见挑战。

* **统一网络安全策略**：在本地和云环境中实施一致的安全策略。利用防火墙、**入侵检测系统（IDS）/入侵防御系统**（**IPS**）和加密来保护传输中的数据。利用 `TLS/SSL` 等加密协议保护传输中的数据，以确保所有互连点的加密标准一致。

* **负载均衡**：制定策略，在本地和云环境中设计并实施负载均衡，以高效分配工作负载并确保最佳资源利用率。这对于设计和构建跨本地和云的高可用应用服务尤其有帮助。

## 存储基础设施

定义存储基础设施战略需要深入理解企业的各种存储需求、数据主权要求以及数据引力。为混合云战略设计整体存储基础设施，涉及创建灵活高效的数据存储环境，无缝整合本地和云资源。以下是一些用于设计和构建存储基础设施的最佳实践：





# 存储现代化最佳实践

- **存储分类**：了解各种存储需求，并根据工作负载、检索频率、延迟、IOPS、存储位置、复制需求、容量和数据格式选择合适的存储类型。利用存储类型选项，根据工作负载需求实现性价比平衡。
- **数据传输**：利用各种存储传输方法进行批量数据传输，例如基于网络的传输、基于设备的传输和软件驱动的数据传输，同时需要考虑速度、数据量、传输频率和延迟。
- **构建冗余**：利用多级冗余来设计系统并保护数据，防止设备故障、数据中心故障和数据丢失。对于非关键数据（可从源数据重新生成的数据），利用云存储内置的冗余就足够了。但是，对于业务关键数据，需要规划额外的数据复制和备份策略。
- **存储策略**：虽然某些存储类型可以灵活地用于多种用途，但基于云的存储类型为各种应用需求提供了专用存储。对于一般应用工作负载，可使用持久化磁盘（HDD、SSD）；对于大规模非结构化数据，可使用对象存储；对于**网络文件系统**（**NFS**）和**网络附加存储**（**NAS**），可使用文件存储。
- **存储生命周期管理**：通过启用自动生命周期管理策略来优化对象存储的使用。例如，将使用频率较低的数据与使用频率较高的数据区分开，并将数据移动到合适的存储类别。实施自动化的数据生命周期管理策略，根据预定义的标准移动、归档或删除数据，以优化存储成本和性能。
- **基于云的内容分发网络（CDN）**：利用基于云的 CDN 来缓存和提供静态数据，以优化成本和访问延迟。
- **数据加密**：建立一致的数据加密方法，对静态数据和传输中的数据进行加密。根据数据类型和数据敏感程度，采用相应的加密方法和密钥管理技术。
- **元数据管理**：实施有效的元数据管理策略，以增强混合存储环境中数据的可发现性和可访问性。
- **数据复制与同步**：实施数据复制和同步机制，以确保本地和云存储环境之间的数据一致性和可用性。使用云存储网关促进本地存储系统与云存储服务之间的无缝通信。

在回顾了企业如何重新构想和思考涵盖计算、网络和存储的基础设施现代化之后，现在让我们来探讨组织如何在云中开发和现代化应用。

# 应用现代化战略

数字化转型的下一个关键方面是应用现代化。随着组织向云原生应用开发和部署过渡，实施稳健的应用现代化战略至关重要。应用现代化并非“一刀切”的方法，它取决于每个组织的长期数字化转型目标以及云战略的选择。然而，组织可以采纳一些基本原则，以提高业务敏捷性、可扩展性和弹性，并减少技术债务。应用现代化可分为两大类——传统应用现代化和云原生应用 DevOps。

## 传统应用现代化

虽然在云原生范式下更容易构想和构建新应用，但重新架构和重写遗留应用并不总是可行的。当组织专注于应用现代化时，明确制定企业中现有遗留应用和传统单体应用的战略非常重要。以下是一些最佳实践：

- **确定优先级并规划迁移**：使用 6R 方法对应用进行分类，为遗留应用现代化发布短期、中期和长期的迁移批次路线图，并将此传达给企业内的利益相关者。这通常是奠定云转型基调的重要第一步。
- **契合度评估**：进行全面的契合度评估，以根据目标状态目标识别适合迁移的候选应用和阻碍因素。例如，某些计划重写的遗留应用，在采用混合云战略的情况下可以保留在本地；而对于采用分阶段转型方法或数据中心退出战略的组织，则可以将这些应用重新托管、共置或迁移到公有云。
- **利用容器实现现代化**：对于使用 Java 和 .NET 技术栈构建的传统应用，利用容器对其进行现代化改造，使其适配云端。企业通常可以将此策略作为中间阶段策略来采用，之后再将应用完全重新架构为云原生。
- **虚拟化策略**：在传统企业中，应用通常运行在各种虚拟化技术上，而这些技术往往是专有的。这些技术可能包括 VMware、Hyper-V 或**红帽虚拟化**（**RHV**）。由于云平台依赖**基于内核的虚拟机**（**KVM**）和 Xen 等开放虚拟化标准，企业必须制定明确的策略来实现虚拟化应用的标准化。
- **通过 API 网关进行抽象**：在某些情况下，一些遗留应用可能并非合理化、现代化或迁移的理想目标。然而，随着组织不断现代化并构建云原生应用，它们将不得不与这些应用无缝集成。API 管理解决方案可以充当抽象层，将遗留应用的功能以标准 RESTful API 的形式暴露出来，使面向客户端的应用免受后端服务变化的影响，并让现代应用和云服务能够使用这些功能。该策略还允许企业快速构建外围应用并交付移动应用等新功能，同时允许底层应用随着时间的推移逐步实现现代化。API 管理还为遗留服务带来了安全性、分析能力和可扩展性。

## 云原生 DevOps

云原生应用开发是一套在云中构建和运行应用的原则和实践，旨在利用云计算平台的独特特性。DevOps 是一套强调开发团队与运维团队之间协作的实践，以确保应用能够快速高效地构建和部署，并且可靠、可扩展。云原生应用 DevOps 是在云中构建和运行敏捷、可扩展、弹性且高效的应用的强大方式。让我们来探讨一些构建云原生应用的最佳实践：

- **微服务架构**：使用微服务架构构建应用，以获得更好的可扩展性、灵活性和可维护性。利用 Docker 和 Kubernetes 等容器和容器编排技术来打包应用，并实现应用服务的自动化部署、扩展和管理。
- **API 与服务网格**：实施 API 以实现微服务之间的通信，并考虑使用服务网格来管理服务与服务之间的通信。采用 API 优先的方法来加速应用设计，以便在混合云和多云环境中治理、分析并全面掌握所有应用 API 的情况。





*   **为互操作性而构建**：规划本地与多云环境之间的互操作性，以实现灵活性和风险缓解。设计应用程序时，应允许在不同云提供商之间轻松迁移数据。利用声明式方法来管理跨环境的策略。

*   **通过无服务器实现扩展**：利用无服务器架构处理应用程序功能，以降低运维开销并提高资源利用率。无服务器计算平台能够根据流量自动扩展资源，从而消除基础设施管理和容量规划的需求。它鼓励设计响应事件和采用异步通信模式的应用程序。

*   **现代化 DevOps**：在应用开发中采用 DevOps 实践，并实施 CI/CD 流水线以自动化测试、部署和发布流程，从而实现更快、更可靠的软件交付。在软件交付中利用安全的软件供应链实践，例如用于存储、管理和保护容器镜像的无服务器 CI/CD 流水线制品注册表，实施二进制授权以控制部署，并使用 AI 辅助 IDE 插件以提升代码质量和开发人员生产力。使用 IaC（基础设施即代码）定义和管理基础设施，允许以声明式方式抽象目标部署平台，从而实现一致且可重复的部署。

*   **为韧性进行架构设计**：通过构建分布式环境中的冗余和故障转移机制来设计系统以应对故障。实施混沌工程原则，以主动测试并提高系统韧性。

*   **数据管理**：选择可扩展且与云服务兼容的云原生数据库和存储解决方案。考虑采用事件溯源和**命令查询职责分离**（**CQRS**）以实现数据一致性和可扩展性。

让我们现在探讨如何在云原生环境中现代化企业数据生态系统。

# 数据现代化

云环境中的数字化转型的下一个方面是数据管理。云原生数据管理代表了一种战略紧迫性，旨在帮助企业利用现代 IT 架构的全部潜力。通过遵循云原生设计原则，集成先进技术，并优先考虑安全性和合规性，组织可以构建一个坚韧且灵活的数据基础设施，以适应数字环境不断变化的需求。在混合云中迈向有效的云原生数据管理之旅，不仅仅是一次技术进化；它是对数据驱动型企业未来的战略投资。随着企业数据呈指数级增长——来自社交媒体、IoT 设备以及曾经不存在且对业务功能不关键的现有市场趋势等新数据源——拥有一个清晰且健全的数据策略对企业至关重要。随着企业内部出现新的数据管理功能和角色，例如**首席数据官**（**CDO**）和**首席数据与分析官**（**CDAO**），这一点得到了证实。现代数据也经历了一种独特的范式转变，如今企业处理的数据越来越倾向于非结构化和半结构化。根据一项 IDC 调查，到 2025 年，全球数据圈将达到 175 ZB，其中 80% 的数据是非结构化数据 *[7]*。在一篇题为*你的数据战略是什么？*的文章中，**哈佛商业评论**（**HBR**）认为，企业用于制定业务决策的数据不到 50%，而被利用进行分析的非结构化数据甚至不到 1% *[8]*。这意味着组织现在更擅长收集和存储海量数据，但缺乏从中实现价值的手段。以下是企业可以采用的一些基础数据现代化原则：

*   **构建平台无关性**：开放数据格式已经革新了现代数据湖架构，实现了完整的数据互操作性、可移植性和灵活性，并防止供应商锁定。开放格式促进了各种系统之间的无缝数据交换，使将分析、处理引擎和其他工具集成到企业数据湖环境变得更加容易，同时通过启用多个应用程序和分析工具以一致的格式读写数据来增强数据可访问性。随着数据湖架构的演进，开放格式支持新数据源的集成和新兴技术的采用。对于寻求保护其数据湖基础设施未来的企业来说，这种适应性至关重要。

*   **促进模式演进**：选择支持模式演进的开放格式，允许随时间推移更改数据结构而无需重新组织整个数据湖。这是一个重要的灵活性优势，因为企业经常需要适应不断变化的业务需求。开放格式的选择还提供了高效的压缩算法，降低了存储成本并提高了性能。例如，Parquet 和**优化行列式存储**（**ORC**）是列式存储格式，提供出色的压缩比，适用于大规模数据湖。

*   **单副本数据湖架构**：构建单副本数据湖架构涉及为多种数据源创建一个统一和集中的存储库，减少冗余并促进数据一致性。企业今天面临的一个常见挑战是数据蔓延和数据孤岛。例如，同一数据集为多个部门、多种用途被复制多次，导致数据量、数据管道、数据治理、数据不一致性和数据安全挑战呈指数级增长。这还导致了*数据不信任综合征*，即企业无法再保证数据源的可信度。企业可以利用的一种策略是联邦数据网格架构，其中数据作为服务由业务数据域提供。

*   **通过 AI 释放数据价值**：随着非结构化数据持续增长，传统平台工具不具备实现其价值的能力。在数据生态系统中嵌入 AI 能力，在释放数据潜能方面可能极其强大。随着 AI 格局的快速演变，组织必须调整并适应 AI 策略和新兴技术。例如，组织可以利用 AI，基于浏览活动和用户行为向客户提供相关的、实时的、个性化的推荐。

*   **整合和统一工具**：制定策略以整合和统一企业内部利用的数据平台和工具。这可以包括标准化专有数据仓库平台、合理化数据湖以及整合分析工具，从而简化流程，减少技术债务，提高整体生产力。

数字原生数据管理涵盖七大领域——*摄取*、*处理*、*存储*、*分析*、*激活*、*保护*和*治理*。

# 现代数据架构

## 数据接入

高效的数据接入是现代数据架构的关键组成部分，可确保多样化数据无缝、及时地流入集中式存储库。数据接入的最佳实践包括采用可扩展的事件驱动架构，以实现对来自众多数据源（从遗留系统到 SaaS）的数据进行实时或近实时的处理。采用诸如 Apache Avro 或 Parquet 之类的 schema-on-read 方法，可确保在处理不同数据类型时具备灵活性。使用 Apache Kafka 等开放标准编排数据管道，可实现数据跨系统的可靠、安全移动。在接入阶段优先考虑数据质量检查、验证和错误处理，对于维护数据完整性至关重要。元数据管理实践和数据血缘记录有助于全面理解所接入的数据，从而为治理和合规工作提供支持。同样重要的是，采用模块化和可扩展的方法来适应不断变化的数据源和不断变化的业务需求，确保数据接入流程的适应性和可持续性。

## 数据处理

现代数据架构中的高效数据处理可使组织从海量多样的数据集中获取宝贵洞察。数据处理的最佳实践包括利用 Apache Spark 或 Apache Flink 等分布式数据处理框架来处理大规模数据处理任务。实施实时流式处理、批量数据传输、数据分区和并行处理策略，可通过充分利用底层基础设施的全部处理能力来提升性能。在适用的情况下，内存处理和缓存机制有助于缩短查询响应时间。作为数据处理阶段的一部分，组织应审慎地优先考虑容错性，设计稳健的错误处理、重试机制和检查点策略，以确保数据处理工作流的韧性。与 Apache Airflow 等数据编排工具的集成可简化工作流管理和调度。采用无服务器计算和云原生技术，可根据需求自动扩展，从而优化资源利用率和成本。

## 数据存储

遵循单副本数据湖架构的原则，数据存储策略对于适应不断增长的数据量和数据多样性至关重要。组织可以利用基于云的存储解决方案来实现可扩展性、持久性和成本效益，从而规划数据湖仓。为关系型、NoSQL、内存缓存和对象存储中的结构化、半结构化和非结构化数据制定稳健的策略。实施数据分区和索引策略可以优化查询性能，尤其是在大型数据集中。定期根据使用模式对数据进行归档和分层存储有助于成本优化。组织还应考虑将数据湖用作各种数据类型的集中存储库，通过版本控制和文档记录促进数据存储的灵活性和敏捷性，从而增强数据血缘和元数据管理。

## 数据分析

培养数据驱动型文化有助于提升组织的竞争优势，使分析洞察无缝融入决策流程。这涉及采用高级分析和现代机器学习技术，从海量数据集中提取可操作的智能。利用 Apache Spark 等开放分布式计算框架，可为复杂的分析任务实现可扩展和并行的数据处理。通过自助式 AI 驱动的分析工具实现数据民主化，可使业务用户独立探索和分析数据。持续监控分析绩效并建立用户反馈循环，能够实现迭代改进和优化。

## 数据激活

在现代数据架构的背景下，数据激活是将洞察转化为可执行结果的关键步骤。在企业内部实现数据激活的民主化对众多人员而言十分重要。一些策略包括构建统一的语义层，以便为各种分析平台和工具上的分析提供数据服务。企业还可以在分析中利用现代 AI 能力，例如**生成式 AI**（**GenAI**），并为非传统业务用户提供数据服务，以满足临时报告和快速获取洞察的需求。

## 数据安全

鉴于数据日益复杂和庞大，加之网络威胁不断演变，在云原生现代数据架构中确保强大的数据安全至关重要。数据安全的最佳实践包括：对静态数据和传输中的数据实施强加密机制，并利用 SSL/TLS 进行安全数据传输；纳入 DiD 安全策略，包括实施统一访问控制和 IdM 以执行 PoLP，确保用户无论通过何种访问方式都只能访问其角色所需的数据；以及采用数据脱敏和匿名化等 DLP 机制，在分析和共享过程中保护**个人身份信息**（**PII**）和敏感数据。

## 数据治理

统一的数据治理是现代数据架构成功的基础，确保数据得到负责任的管理、保护和利用。数据治理的一些最佳实践包括为数据质量、隐私和安全制定明确的政策和标准。组织应明确不同**业务部门**（**BU**）对数据的所有权和问责制，培养责任和管理文化。实施全面的元数据管理策略也有助于理解和跟踪数据血缘，增强透明度和合规性。定期审计和监控数据访问、使用和变更，有助于维护数据的完整性和安全性。

在了解了如何在云端实现数据生态系统现代化之后，接下来让我们探讨如何优化云成本并实施云治理，以从云采用中最大化业务价值。

# 云优化与成本治理

随着云原生继续推动整个企业的创新，优化和治理对于在创新与成本控制之间取得适当平衡至关重要，从而实现可持续、负责任且成功的长期云应用。FinOps 代表了财务、运营和工程团队之间协作管理云支出的文化。据麦肯锡称，到 2030 年，价值驱动因素可使云在整个《福布斯》全球 2000 强企业中带来超过 3 万亿美元的**税息折旧及摊销前利润**（**EBITDA**）价值 *\[9\]*。该研究还定义了企业如何在以下三个维度上最大化所获取的云价值：

## 焕新

该维度定义了企业可从云支出（包括应用程序开发、基础设施和维护）中的 IT 成本效率中获得的潜在价值。IT 成本优化涉及优化应用程序开发、IT 维护和基础设施方面的成本，提高业务韧性，并利用最新云技术的进步来改善整体 IT 运营。

## 创新

该维度定义了企业可通过解锁云中的现代技术（如高级分析、物联网和自动化）所能获得的价值，包括收入提升。企业可以利用新的用例来推动创新，并通过降低技术获取门槛和实现技术民主化来加速**上市时间**（**TTM**）。




- **先驱**：先驱维度涉及试验新兴技术并探索新的商业模式。例如，试验诸如区块链、量子计算、**增强现实/虚拟现实**（**AR/VR**）和生成式 AI 等现代云技术，可以帮助企业引领变革和数字颠覆。

根据*Flexera 2023 云状态报告*，82%的企业将管理云支出列为首要组织挑战*\[10\]*。让我们回顾一下云 FinOps 框架，企业可以利用该框架来掌握成本治理并最大化在云中实现的收益。

云 FinOps 框架是一套最佳实践和指导原则，组织可以遵循这些原则来优化云资源的财务管理。其目标是对齐财务、运营和技术团队的目标，确保云操作的成本效益。早期采纳 FinOps 并将其作为组织内的一项实践，对于最大化云投资的商业价值至关重要。云 FinOps 框架的核心是在整个组织中培养 FinOps 文化，促进协作和共同承担云成本的责任。该框架通常由以下几个关键支柱组成，核心是一个 FinOps**卓越中心**（**CoE**）。对于拥有成熟云采用的现代企业，应努力建立 FinOps CoE，其主要目标是通过教育和赋能人员、利用云技术的持续进步、建立标准化流程，同时保持维护和改进整体绩效、生产率和效率的目标，来最大化云投资的收益。领导层的参与和支持对于推动协作文化至关重要，对于 FinOps CoE 的成功极其关键，否则可能会疏远团队，而不是共同朝着共同的目标努力。让我们详细看看这些 FinOps 阶段。

## 信息阶段

*信息*阶段是组织 FinOps 旅程的第一步。这是一个关键阶段，涉及从各种来源收集数据，以获取组织云使用情况和支出模式的见解。正如著名的管理名言所说：“*你无法改进你无法衡量的事物*。”*信息*阶段对于衡量并清晰理解组织的云支出至关重要。然后可以利用这些数据创建报告、识别异常、将支出与同行进行基准比较、将成本分配给适当的 BU，并为云资源创建分类法和标签。然后可以利用这些信息对如何优化整体云支出做出明智的决定。该阶段的主要目标之一是收集详细的云资源分配信息，使 FinOps 团队能够将云资源利用率和成本与企业成本中心和业务利益相关者联系起来。这种可见性有助于责任分配、避免意外成本、识别改进机会以及向利益相关者展示云的业务价值。

以下是在*信息*阶段通常执行的一些最佳实践：

- 基于**总拥有成本**（**TCO**）估算整体云成本
- 创建提供云使用情况和支出模式见解的报告
- 通过云成本管理和建议工具，赋予团队可见性，以使其能够就绩效、成本和异常做出明智的业务决策
- 通过创建分类法、标签和项目层次结构，将成本分配给 BU
- 利用统一的云成本管理工具来报告、基准和预测成本
- 利用云提供商提供的迁移工具和服务，发现和评估本地资源，以规划迁移和现代化
- 将云支出与同行进行基准比较

## 优化阶段

FinOps 框架中的下一个阶段是*优化*阶段。此阶段涉及识别并抓住优化组织云支出的机会，同时保持工作负载的相同性能水平。*信息*阶段获得的见解将用于指导优化工作。FinOps 团队可以利用多种自动化技术来优化云成本和资源。这些技术可以包括使用承诺使用折扣，如预留或承诺实例以及长期承诺以降低成本，评估云环境并调整资源大小，采用等效的云原生功能（如无服务器），以及利用工具自动扩展或关闭不必要的资源。具体而言，此阶段关注的活动包括：

- **关键绩效指标（KPI）**：用于跟踪进度和衡量优化工作成功率的指标
- **利用云原生推荐服务**：这有助于提高云成本效益、性能、可靠性和安全性
- **成果**：你希望通过优化工作实现什么目标？
- **优化使用**：这包括识别和消除不必要或低利用率资源
- **优化费率**：这包括与云提供商谈判以获得更好的价格
- **业务案例**：这些文件将证明你优化工作的必要性，并帮助你获得资金

## 运营阶段

*运营*阶段是 FinOps 框架的最后阶段。它涉及建立组织持续云成本管理和云治理的标准框架，使组织能够长期保持最佳的云使用和成本效率。在此阶段，重点将是组织和文化的 FinOps 最佳实践采纳。以下是*运营*阶段的一些最佳实践：

- 在云资源中建立护栏，以帮助确保云合规性，避免错误配置，并实施一致的资源共享策略治理
- 在组织和项目层面实施云成本管理、预算和警报策略，以减轻成本失控
- 利用云原生资源见解和最佳实践来优化持续和未来的云采用
- 利用**云采用框架**（**CAF**）和**架构框架**（**WAF**）来采纳最佳实践，改善云旅程
- 通过教育团队 FinOps 最佳实践，使团队能够学习新技能以最大化价值和效率，从而促进团队协作
- 制定计划以激励最能利用和采纳 FinOps 最佳实践的团队

在本章中，我们探索了数字化转型的各个方面以及企业可以利用的最佳实践，无论部署模式如何，都能建立坚实的云基础。我们回顾了企业如何必须从构建安全优先的云基础开始，以确保涵盖网络、数据、应用和资产管理的整体企业安全。我们还学习了如何在云原生生态系统中重新思考基础设施现代化。

然后，我们探索了企业可以利用的策略来使应用景观和数据生态系统现代化。最后，我们回顾了优化云成本、最大化价值以及提高云资源效率和性能的最佳实践。
