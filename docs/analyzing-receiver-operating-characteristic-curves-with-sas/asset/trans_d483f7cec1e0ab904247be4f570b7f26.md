交叉验证的需求不仅限于由 PROC LOGISTIC 拟合的线性 logistic 模型。其他接受类似数据但使用不同方法拟合模型的 SAS 过程，例如 PROC GENMOD、PROC GAM 和 PROC PROBIT，也能从交叉验证方案中受益。很难编写一个适用于所有过程的通用宏，因为每个过程的输出语法和输出传送系统 Output Delivery System (ODS) 表名都不同。但相对容易将 %XVAL 宏为不同过程量身定制。宏中的初始 DATA 步在数据集中添加一个变量 XV，该变量取值从 1 到 K，表示观测值属于哪一折。此部分独立于统计预测模型或使用的 SAS 过程。你必须修改使用 PROC LOGISTIC 的代码部分。此修改需要特定过程的专业知识，可能由具有特定过程和宏编程经验的用户完成。

## 8.6 ROC 曲线的 Bootstrap 验证估计

另一种通过验证获得 ROC 曲线的样本重用方法是使用 bootstrap 样本。这不如交叉验证直观，但在某些情况下，其估计的方差可能更低。

Bootstrap 验证首先通过形成 B 个 bootstrap 样本开始。对于交叉验证，K 是一个较小数字，约为 5 到 10，而对于 bootstrap 验证，B 通常会更大，至少数百个，也许 1,000 个。然后每个 bootstrap 样本用作训练样本。然后原始数据集和 bootstrap 样本用作测试样本。感兴趣的度量，例如 AUC，使用原始数据作为测试样本估计的值与使用 bootstrap 样本作为测试样本估计的感兴趣度量之间的差异是 *乐观* 的度量。此差异可以从感兴趣度量的重代入估计中减去，以获得 bootstrap 验证估计。这样产生的估计有时称为 *乐观校正* 或 *乐观调整* 估计。

算法如下：

+   1. 在原始数据集上计算感兴趣的度量 M，记为 Mₒ。
+   2. 创建 B 个 bootstrap 样本。对于 i=1, ... B，执行以下操作：
+      a. 在 bootstrap 样本上训练模型
+      b. 使用训练好的模型在原始数据上计算 M；记为 Mₒᵢ
+      c. 使用训练好的模型在 bootstrap 样本上计算 M；记为 M_bᵢ
+      d. 计算差异：dᵢ = Mₒᵢ − M_bᵢ
+   3. 从 Mₒ 中减去 mean(dᵢ)。这是 bootstrap 验证的感兴趣度量。

%BVAL 宏，其语法与 %XVAL 宏相似，生成两个数据集 BVAL1 和 BVAL2，分别包含使用原始数据和 bootstrap 样本的预测概率。它还计算乐观 AUC、乐观校正和校正后 AUC。

```
%bval(dsn=liver,outcome=complications,covars=age_at_op comorb lobeormore_code bilat_resec_code numsegs_resec,B=100);
```

输出 8.5 是使用 100 个 bootstrap 样本运行 %BVAL 宏得到的结果。

## 输出 8.5

| The SAS System |
| Optimistic AUC | Optimism Correction | CorrectedAUC |
| 0.695842 | 0.007179 | 0.688663 |

当从重代入估计 0.695842 中减去 0.007179 的乐观校正时，AUC 的 bootstrap 验证估计为 0.6887。注意，这与上一节中获得的五折交叉验证估计几乎相同。实际上，对于合理大的数据集，留一法、k 折交叉验证和 bootstrap 方法会产生相似的结果，选择将取决于应用领域的传统以及软件的可及性。

## 9.1 引言

SAS Enterprise Miner 是一套数据挖掘工具。它于 1998 年推出，主要由营销分析师、数据库营销人员、风险分析师、欺诈调查员以及其他试图在大量数据中寻找模式的专业人士使用。SAS Enterprise Miner 运行在标准的 SAS 平台上，但它使用图形用户界面 GUI，与 SAS 使用的其他任何界面都不同。此外，虽然其运行的 SAS 引擎是可访问的，但 SAS Enterprise Miner 的设计前提是用户将通过其 GUI 访问它。这与本书迄今为止的重点 Base SAS 和 SAS/STAT 形成对比，后者主要通过程序编辑器和运行代码段来访问。

SAS Enterprise Miner 为数据挖掘提供多种方法，包括聚类、降维、链接分析和预测建模。本章重点关注预测建模。在第 8 章中，我们研究了多变量预测模型的 ROC 曲线，并保留 logistic 回归来演示多变量模型中出现的问题以及使用 SAS/STAT 的解决方案。在许多方面，本章是第 8 章的扩展，因为它使用 SAS Enterprise Miner 的功能来检查分类树和神经网络。

SAS Enterprise Miner 具有内置功能，可作为模型评估的一部分生成 ROC 曲线。此外，你可以从生成 ROC 曲线时在后台创建的表中创建一个 SAS 数据集。此数据集然后可与前几章中开发的技术一起用于增强绘图。最后，你可以在 SAS Enterprise Miner 中使用为此目的开发的预测模型对数据集进行评分。评分结果也可以保存为 SAS 数据集，使你能够根据需要访问第 3 章至第 6 章的建模方法。事实上，甚至可以生成用于评分的 SAS 代码。

本章无意作为 SAS Enterprise Miner 的全面指南。模型构建和选择的核心数据挖掘步骤仅在有助于你理解所得数据曲线的程度上进行介绍。我们在此使用的各种中间步骤，例如缺失数据插补，可能不适用于其他数据挖掘练习。要获得 SAS Enterprise Miner 的扎实背景，请参阅 Patricia Cerrito 所著的《使用 SAS Enterprise Miner 进行数据挖掘入门》2006 年版。

本章的读者是 SAS Enterprise Miner 用户，尤其是那些尚未使用该软件进行 ROC 曲线分析的用户。这里假设你已熟悉第 3 章水平的 ROC 曲线，因此此时快速阅读第 3 章可能有用。

## 9.2 房屋净值贷款示例

本章示例的数据来自 SAS Enterprise Miner 的示例数据库 Sampsio.Hmeq。库 Sampsio 在加载 SAS Enterprise Miner 时内部定义，其中包含此数据集。它包含近 6,000 条记录和 13 个变量，其中一个是数据挖掘语言中的结果变量或目标。数据集描绘了一家金融服务公司的房屋净值贷款记录。约 20% 的过去房屋净值信用额度导致违约。为了试图降低违约率，或许生成申请人定制的利率，公司希望建立一个预测房屋净值贷款违约风险的模型。目标变量称为 BAD，值为 1 表示违约，0 表示正常服务贷款。12 个预测变量及其简要定义如下：

+   - CLAGE：最老信用额度年龄（月）
+   - CLNO：信用额度数量
+   - DEBTINC：债务收入比
+   - DELINQ：拖欠信用额度数量
+   - DEROG：重大不良报告数量
+   - JOB：债务人职业
+   - LOAN：贷款金额
+   - MORTDUE：现有抵押贷款到期金额
+   - NINQ：近期信用查询次数
+   - REASON：贷款原因（债务合并或房屋改善）
+   - VALUE：房产价值
+   - YOJ：在现职工作年限

目标是使用数据集中另外 12 个变量为 BAD 变量找到一个预测模型。虽然我们将逐步进行构建预测模型所需的步骤，但重点是使用 SAS Enterprise Miner 的内置功能构建 ROC 曲线，以及探索如何将预测值导出到 SAS 数据集，以便可以使用前几章中讨论的方法和宏执行自定义分析。
