## 前言

> “计算机软件行业最令人惊叹的成就是，它持续抵消了计算机硬件行业稳定而惊人的进步。”
> 
> – 亨利·彼得罗夫斯基

我们生活在分布式系统时代。计算机已经从房间大小的工业大型机，缩小到比拇指指甲还小的嵌入式设备。然而，与此同时，我们每天构建、维护和使用的软件应用已经发展到无法衡量的程度。我们构建的分布式应用运行在遍布世界各地的虚拟机集群上，数十亿人每天依赖这些系统，例如电子邮件、聊天、社交网络、生产力应用和银行服务。我们一周七天、一天二十四小时在线，并且沉迷于即时满足。一代人之前，我们愿意等到周末之后支票兑现，或者允许 28 天送达。今天，我们期望即时反馈，为什么不呢？现代网络是实时的、即时的、按需的，并且构建在以光速在全世界传输的数据包之上；当它不是这样时，我们就会注意到。我们都有过那种沮丧的感觉……你知道，当你刚刚在页面上输入信用卡号购买昂贵的音乐会门票，而网站响应时间过长时。在分布式时代，性能和响应速度是提供卓越用户体验的基本组成部分。然而，对于一位试图按时交付下一个功能的开发者来说，性能往往是最具挑战性的需求之一。如何找到应用程序性能中的瓶颈？如何衡量这些问题的影响？如何分析它们，设计和测试解决方案及变通方法，并在生产环境中监控它们，从而确信它们不会再次发生？这本书给出了答案。在书中，James Singleton 对现代性能优化技术及其如何应用到你的 .NET 和 Web 应用中进行了务实、深入且均衡的探讨。James 从我们应该将性能视为系统核心功能这一前提出发，展示了如何使用 Glimpse、MiniProfiler、Fiddler 和 Wireshark 等性能分析工具来追踪导致性能问题的瓶颈和缺陷。他阐述了有效性能调优、监控、插桩背后的科学原理，以及在对运行中的系统进行更改以尝试提升性能时，使用准确且可重复的测量的重要性。

本书接着讨论了现代应用开发的几乎每一个方面：数据库调优、硬件优化、压缩算法、网络协议和对象关系映射器。对于每个主题，James 都描述了常见性能问题的症状，确定了这些症状的根本原因，然后描述了可用于在你自己应用中测量和修复这些根本原因的模式和工具。书中深入探讨了高性能软件模式，如异步方法和消息队列，并配有实际示例，展示如何在最新版本的 .NET 框架中实现这些模式。最后，James 展示了如何不仅将负载测试作为发布流程的一部分，还可以在生产环境中持续监控和测量系统，让你在潜在问题开始困扰最终用户之前就发现并修复它们。

当我在 Spotlight 与 James 共事时，他始终展现出非凡的知识广度，从 ASP.NET 到 Arduino，从 ReSharper 到电阻。某一天，他会用 ASP.NET 和 JavaScript 构建响应式前端界面；第二天，他会把微控制器接入星球大战玩具来制作构建监控器，或者想办法把浴室门锁连接到内网，这样我们骑自行车通勤的员工就能从办公桌前看到办公室淋浴间何时空闲。在 James 离开 Spotlight 之后，我一直关注他与 Cleanweb 和 Computing 4 Kids Education 的合作。他是那种真正理解技术的社会和环境影响的稀有开发者；无论是提供出色的用户交互，还是仅仅节约电力，提升系统性能都是让你的用户感到满意的绝佳方式。通过这本书，James 将他多年的实践经验和教训提炼成一本真正优秀的 .NET 开发者综合参考书，帮助那些想要理解如何构建响应迅速且可扩展应用的开发者。对于希望全面理解应用性能的新开发者来说，这是一个很棒的资源；而对前沿技术和模式的覆盖也意味着它同样适合那些希望确保自己不会落伍的经验丰富的开发者。买下它，阅读它，与你的团队分享，让我们一起让 Web 变得更好。

## 前言

微软已经发布了其开源、跨平台 Web 应用框架 ASP.NET Core 的第二个主要版本。它运行在 .NET Core 之上，后者同样是开源的，并且现在也已发布 2.0 版本。ASP.NET Core 主要使用 C# 编程语言，但也可以使用 F# 和 VB.NET。你不再受限于在 Windows 上使用 ASP.NET，现在可以在 Mac 上进行开发并部署到 Linux。新平台还提供了更高的性能。

第 2 版才是第 1 版本应有的样子，因为第一个稳定版本实际上并未达到生产就绪状态。在发布候选阶段的后期，还进行了重大更改。值得庆幸的是，新的工具让一切稳定下来，你现在可以真正认真地使用 ASP.NET Core 了。

在当今世界，一个只在开发人员工作站上运行良好、却无法在生产环境中提供高性能的 Web 应用是不可接受的。Web 应用如今大规模部署的方式已经发生了改变，开发实践也必须适应这一点并善加利用。通过阅读本书，你将学到构建高性能 Web 应用的现代方法，以及如何使用 ASP.NET Core 来实现。

这是一本高层次的书籍，所提供的性能技巧适用于采用任何编程技术栈的 Web 应用开发。不过，它特别聚焦于 C# 和 ASP.NET Core。读者应当已经知道如何构建 Web 应用，但不一定需要掌握 .NET Core。

本书从一般性角度（HTTP、HTTPS、HTTP/2、TCP/IP、数据库访问、压缩、I/O、资源优化、缓存、消息队列以及其他关注点）以及 C#、ASP.NET Core 和 .NET Core 的角度，全面阐述 Web 应用性能改进技术。这包括深入探究最新框架的细节，并演示能够提升性能的软件设计模式。

本书将重点指出常见的性能陷阱——这些陷阱往往会在开发人员工作站上悄无声息地出现——并提供尽早发现和解决这些问题的策略。通过提前理解并应对这些挑战，就可以在实际部署时避免任何令人头疼的意外。

本书将介绍许多性能改进方案，以及它们所带来的权衡取舍。我们将采取基于科学与证据的方法，专注于重大问题，避免那些影响甚微的改动，从而在过早优化与低效代码之间取得平衡。



我们假设你了解性能对 Web 应用程序的重要性，但我们将简要回顾为什么它至关重要。然而，你可能没有获得过具体或可操作的建议，也没有多少在实际环境中出现性能问题的经验。

通过阅读本书，你将了解当 Web 应用程序大规模部署到分布式基础设施时可能出现的问题，并知道如何避免或缓解这些问题。你将获得编写高性能应用程序的经验，而无需通过艰难的方式（可能是在深夜）去了解这些问题。

你将看到 ASP.NET Core 的新特性、为何它被从头重建，以及这对性能意味着什么。你将了解 .NET Core 的未来，以及你现在如何在 Windows、macOS 和 Linux 上进行开发和部署。你将体会到 ASP.NET Core 新特性的性能优势，包括 Razor 视图引擎的更新，并了解诸如 Visual Studio Code 之类的跨平台工具。

## 本书涵盖内容

- **第 1 章，ASP.NET Core 2 的新特性**，概述了 ASP.NET Core 1.0 和 ASP.NET Core 2.0 之间的重大变化。我们还将探讨该项目的历史，以说明为什么它一直在快速变化。我们将介绍 C# 6.0 和 C# 7.0 中的一些新特性，看看它们如何让你的开发更轻松。我们还将介绍 .NET Standard 2.0 以及它如何提高库的可移植性。

- **第 2 章，为什么性能是一项特性**，讨论了本书的基本前提，并说明为什么你需要关注软件的性能。响应式应用程序至关重要，仅仅让功能工作是不够的；它们还需要快速。想想你上次听到有人抱怨应用或网站的时候，很可能是因为他们对性能不满意。糟糕的性能不仅让用户不满，还会影响你的利润。有充分的数据表明，快速性能可以提高用户参与度和转化率，这也是搜索引擎给予奖励的原因。

- **第 3 章，设置你的环境**，展示了如何在你选择的操作系统上开始使用最新的工具。如果你想要使用 .NET 进行开发，不再必须使用 Windows 上的 Visual Studio。我们将介绍 VS 2017 以及针对 .NET Core 和 ASP.NET Core 的新集成工具。我们还将介绍 Visual Studio for Mac（以前称为 Xamarin Studio）和跨平台的 VS Code 编辑器（使用 TypeScript 和 Web 技术构建）。我们将展示如何使用 Docker 容器使跨平台开发变得简单且一致。我们还将介绍 dotnet 命令行工具。

- **第 4 章，测量性能瓶颈**，表明解决性能问题的唯一方法是仔细测量你的应用程序。如果不知道问题出在哪里，你解决问题的机会就非常渺茫，甚至不知道自己是改进了还是变得更糟。我们将重点介绍几种手动监控性能的方法，以及一些可用于测量统计数据的实用工具。你将了解如何深入洞察软件的数据库、应用程序、HTTP 和网络层面，从而知道内部发生了什么。我们还将向你展示如何构建自己的基本计时代码，并说明对结果采取科学方法的重要性。

- **第 5 章，修复常见性能问题**，审视了一些最常见的性能错误。我们将展示如何修复一系列不同应用领域中的简单问题——例如，如何通过图像调整大小或编码来优化媒体、SELECT N+1 问题，以及异步后台操作。我们还将稍微讨论一下一旦你知道瓶颈所在，如何使用硬件来提高性能。这种方法为你赢得了一些时间，并允许你以合理的速度妥善地修复问题。

- **第 6 章，解决网络性能问题**，深入探讨了支撑所有 Web 应用程序的网络层。我们将展示远程资源如何拖慢你的应用，并演示如何测量和解决这些问题。我们将研究互联网协议，包括 TCP/IP、HTTP、HTTP/2 和 WebSockets，同时简要介绍加密以及所有这些如何改变性能。我们将涵盖文本和图像资源的压缩，包括一些不常见的图像格式。最后，我们将介绍浏览器、服务器、代理和内容分发网络（CDN）级别的缓存，并展示一些基础知识。

- **第 7 章，优化 I/O 性能**，专注于输入/输出以及它如何对性能产生负面影响。我们将研究磁盘、数据库和远程 API，其中许多都使用网络，尤其是在虚拟化环境中。我们将涵盖批处理请求，以及使用聚合和采样优化数据库使用，旨在减少所需的数据和时间。由于网络在云环境中的普及性，我们将花费大量时间进行网络诊断，包括 ping、路由跟踪和查找域名系统中的记录。你将了解物理距离（或地理位置）如何导致延迟，以及这如何给你的应用程序带来问题。我们还将演示如何使用 .NET 构建你自己的网络信息收集工具。

- **第 8 章，理解代码执行和异步操作**，深入探讨了 C# 代码的复杂性，并研究其执行如何改变性能。我们将了解构成 ASP.NET Core 和 .NET Core 的各种开源项目，包括 Kestrel，一个高性能的 Web 服务器。我们将探讨选择正确数据结构的重要性，并查看不同选项的各种示例，如列表和字典。我们还将研究哈希和序列化，并执行一些简单的基准测试。你将学习一些通过并行化来加速处理的技术，例如单指令多数据（SIMD）或使用任务并行库（TPL）和并行 LINQ（PLINQ）进行并行扩展编程。你还将看到一些由于性能代价而最好避免的做法，例如反射和正则表达式。

- **第 9 章，学习缓存和消息队列**，首先讨论缓存，这被广泛认为是困难的。你将了解缓存如何在浏览器、Web 服务器、代理和 CDN 中从 HTTP 的角度工作。你将学习缓存破坏（或打破缓存）以强制你的更改生效，以及如何在现代浏览器中使用新的 JavaScript Service Worker 来更精细地控制缓存。

  此外，我们将研究基础设施中应用程序和数据库级别的缓存。我们将看到 Redis 等内存缓存的优势，以及它们如何减少数据库负载、降低延迟并提高应用程序的性能。

  我们将研究消息队列，作为构建分布式和可靠系统的一种方式。我们将用一个类比来解释异步消息传递系统的工作原理，并展示一些常见的消息队列风格，包括单播和发布/订阅。

  我们还将展示消息队列如何通过广播缓存失效数据来对内部缓存层发挥作用。你将了解消息代理（如 RabbitMQ）以及用于从 .NET 与它们交互的各种库。

- **第 10 章，性能增强工具的缺点**，集中讨论我们所涵盖技术的负面因素，因为没有任何东西是免费的。我们将讨论各种方法的价值，包括降低复杂性、使用框架和设计分布式架构。我们还将讨论项目文化，并看到高性能不仅仅关乎代码，还关乎人员。

  我们将研究解决分布式调试问题的可行方案，并了解一些用于集中管理应用程序日志的可用技术。我们将简要介绍统计学，以理解你的性能指标，并会触及缓存管理。



你应该具备一些使用 Web 应用程序开发框架的经验，并且期望部署在真实生产环境中能良好运行的应用程序。这些环境可以是虚拟机，也可以由 AWS 或 Azure 等云服务提供商托管。
