Yes, of course, keywords are functions). The keyword call does not return nil, so some-> keeps on threading and moves on to the count function, which returns 2. Also note that some-> helps guard against nil values, as the threading stops as soon as the function called returns nil.

Similarly, we can thread through ->> with some->> and apply a map function:

```
(some->> {:speed [50 90]}
  :speed
  (map inc)
  average
)
; 71
```

A longer some->> threading example could include calls to take, and filter as well:

```
(some->> {:speed [50 90 100]}
  :speed
  (take 2)
  (map inc)
  (filter (fn[x] (> x 60)))
  average
)
; 91
```

Again, as said previously, this is really nice to present very readable code. You know what each steps is doing - it is passing the data from one step to the other.

Sweet, isn't it?
