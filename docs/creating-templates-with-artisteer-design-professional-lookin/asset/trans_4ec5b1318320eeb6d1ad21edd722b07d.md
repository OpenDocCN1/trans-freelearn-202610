直到此刻，我们一直专注于设计静态网站（在 Artisteer 中称为 Website Template）。术语 **static website** 可能让你有点尴尬，因为它自然会被理解为“页面上什么都不动的”。你可能会想，如果你在静态网站上添加例如幻灯片，它就不再是静态的了。这是一种非常自然且合乎逻辑的思考方式，但在这种情况下，常用的术语则完全不同。说到静态网站，我们想的不是其内容，而是页面的生成方式。

## 什么是 CMS

在静态 HTML 网站中，内容是硬编码的——它是页面代码的一部分。这样的网站由众多 HTML 文件组成，并且所有文件都是单独逐一编写的。它们可以使用各种工具来准备（或多或少简化工作），但每个文件都同时包含外观定义和内容。所有这些文件都被复制到 Web 服务器上，使其可供访客访问。这是最自然、最易于理解的网站类型。

动态页面在技术上肯定更先进。它并不以文件的形式存在，而是由 Web 服务器即时生成的。在收到需要显示特定页面的信号后，一种特殊的软件会获取适当的内容（通常来自数据库）并将其放入可用的模板中。内容和模板成功结合后，页面就准备就绪并发送到浏览器。

**Dynamic website** 因此不是静态页面（HTML 文件）的集合，而是在 Web 服务器上安装的用于管理内容、模板并将它们合并为动态页面的软件。

动态网站比其静态对应物运行得更慢，因为每个页面在显示前都必须生成。它们对服务器的要求更高，因为服务器不仅要显示页面，还要生成页面。

> CMS 是一种用于管理网站的通用软件。它通过使用模板将网站的外观与其内容分离，并允许管理员直接在浏览器中输入内容。通常，CMS 系统还允许你操作菜单结构。

市场上存在各种类型的 CMS。有些是商业的，有些是免费的，而最知名解决方案的可能性远远超出我们的定义。Artisteer 支持为几种流行的 CMS 创建模板。

由于内容编辑直接在浏览器中进行，因此无需将新页面上传到服务器。这确实加快了网站管理以及添加新内容和页面的速度。

使用 CMS 系统还有另一个、也许是最重要的优势，那就是向网站添加新内容所需的时间。

假设你有一个由 50 个页面组成的网站。（你现在可能觉得这很多，但事实并非如此。在你认真开始开发网站后，你会很容易超过这个数字。）假设这是一个静态网站，由单独的 HTML 文档组成。共同的元素是页眉、左侧的垂直菜单和页脚。你想添加一个页面并希望它可以通过菜单访问。第一步当然是准备新页面。但之后你会意识到这是一项耗时较少的工作（如果你使用任何 WYSIWYG 编辑器，你可以在其中显示模板并非常快速地输入内容）。真正的难题在于修改菜单。修改刚添加的页面上的菜单是不够的，你必须修改所有其他页面上的菜单！（新页面应可从任何现有页面访问。）由于菜单在每个页面上都是硬编码的（它是其源代码的一部分），而静态网站只是一组单独的 HTML 文档，这意味着你必须编辑和修改所有现有文件！在我们的例子中，添加一个页面需要你修改 50 个现有文件，而且不要忘记在工作完成后你还必须将它们全部上传到服务器。

这种情况不仅适用于菜单，对于任何固定元素也是如此。你想更改页脚中的电话号码吗？你必须修改所有页面的页脚。

但如果你使用 CMS，添加新页面只需几次鼠标点击，菜单就会自动适应新网站的结构。对于页脚也是类似的过程，我们只需要更改一次。修改的便捷性和节省时间正是使 CMS 成为较大网站最佳选择的原因。

但等等！在上一章中，我们可以清楚地观察到，在向项目添加页面后，菜单也会自动适应。页脚或页眉（布局的固定元素）也是如此。

Artisteer 的行为确实类似于 CMS，这也是其最重要的优势之一。但请注意，即使使用 Artisteer，在更改完成后，你仍然必须将所有修改过的文件上传到服务器（并替换旧文件）。

可以把 Artisteer 视为 CMS 的替代品吗？对于小型网站来说，是的。你可以使用 Artisteer 的功能同时设计模板和输入内容，将所有内容集中在一个工具中。但对于较大网站的管理，使用 CMS 会更容易，因为你不必将所有修改过的文件上传到服务器。还有一些事情是 Artisteer 单独无法完成的（例如，使用联系表单发送消息）。这是否意味着 CMS 比 Artisteer 更好？完全不是，它只是不同类型的工具。CMS 是用于管理网站的软件，而 Artisteer 是用于设计模板的软件。
