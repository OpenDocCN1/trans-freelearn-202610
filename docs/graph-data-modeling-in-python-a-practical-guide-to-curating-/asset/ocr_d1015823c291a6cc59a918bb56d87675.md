*Figure 6.1* illustrates a schema for our products, but we may want to store customer information too. We can learn what types of products a customer is interested in by keeping track of their past purchases. To store customers, we will need to give each a unique customer ID, as well as store other useful information about them, such as their name and address.

To store these features, we can create customer nodes, with **ID**, **name**, and **address** as node attributes. For purchases, we can create relationships with products. For each purchase, we can store a **date** and **time** on the edge, to distinguish between multiple purchases of the same item by the same customer.
