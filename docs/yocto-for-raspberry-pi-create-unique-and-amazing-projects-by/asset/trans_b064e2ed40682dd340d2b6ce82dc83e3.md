

如果构建 meta-toolchain-qt5 失败，你可以尝试在不包含 X11 和 Wayland 包的情况下构建它。在使用 meta-raspberrypi 时，将 X11 和 Wayland 与 qt5 一起使用有时会出现问题。使用此命令：$ echo "DISTRO_FEATURES_remove = \"x11 wayland\"" >> conf/local.conf.

如果构建仍有问题，请添加 meta-packt-qt5 层并重试。该层包含一些针对 Raspberry Pi 上 qt5 的变通方案。有关更多信息，请参阅层中的 readme 文件。

设置交叉编译器的环境：

```
$ cd /path/to/extracted_sdk

$ which qmake
/path/to/extracted_sdk/sysroots/x86_64-pokysdk-linux/usr/bin/qt5/qmake
```

SDK 就绪且交叉编译器设置完成后，我们就可以开始为 Raspberry Pi 构建第一个 Qt 应用程序了。第一个示例是一个基于 C++ 的简单 Qt 应用程序，包含一些可点击的小部件。从命令行构建 Qt 应用程序时，可以使用 qmake 创建项目并生成 makefile，如下所示：

```
$ tar -zxf qt_packtpub_app.tar.gz
$ cd qt_packtpub_app
$ ls
qt_packtpub_app.cpp window.cpp window.h
$ qmake -project "QT += widgets"
$ qmake
$ make
```

应用程序准备就绪后，我们需要生成一个带有 Qt 支持的目标镜像，以便在测试新应用程序时使用。我们将以 rpi-basic-image 为基础，在其之上进行一些添加。为了在目标上运行 Qt 应用程序，我们需要添加一组软件包。为此，可以使用名为 packagegroup-qt5-toolchain-target 的预定义软件包组。当然，也可以手动指定所需的 Qt5 软件包以减少占用空间，例如。但在此示例中，我们将保持简单，并确保包含所需的所有内容。如前一章所述，EGLFS 无需任何窗口系统即可工作，因此我们可以删除 X11 和 Wayland 支持以减小镜像占用空间。所有这些操作都可以在 local.conf 中指定：

```
$ echo "IMAGE_INSTALL_append_pn-rpi-basic-image = " packagegroup-qt5-toolchain-target qt5-opengles2-test"" >> conf/local.conf
$ echo "DISTRO_FEATURES_remove = \"x11 wayland\"" >> conf/local.conf
```

配置项目后，我们可以构建基本镜像：

```
$ bitbake rpi-basic-image
```

别忘了添加 Raspberry Pi 7 触摸屏所需的设备树，如前一章所述：

```
$ echo "dtoverlay=rpi-ft5406" >> /path/to/sdcard/boot/config.txt
```

将新构建的应用程序传输到目标设备并运行它：

```
$ /path/to/qt_packtpub_app -platform eglfs
```

## 第 11 章。为 Raspberry Pi BSP 层做贡献

在本章中，我们将学习如何向 meta-raspberrypi 层贡献自定义工具。将解释与该领域相关的常见术语，例如“开源”、“社区”和“上游”。我们还将学习 Git 的基础知识，以及一些可与 sendmail 工具一起使用的更高级 Git 命令。

### 开源

**开源**可以描述为对普通公众开放的源代码。开源软件可以被任何人阅读、修改和重新分发。这意味着开发者可以在自己的项目中使用原始代码，而无需向代码所有者支付任何许可费。成功的开源项目通常由开发者社区构建而成，该社区协作并确保开源项目朝着预定的方向发展。

### 提示

Linux 内核和 OpenStack 是两个最著名的开源项目。Yocto Project 及其子项目是大型开源项目的其他示例，尤其是在嵌入式领域。

开源社区通常至少包含一名 **维护者**。维护者是负责将补丁集成到项目并构建源代码的人。在集成部分，维护者通常扮演着重要角色，要么审查社区开发者提交的补丁，要么确保由其他有相应知识的人来完成。在 Linux 内核等大型开源项目中，内核的不同部分有大量维护者。他们还为每个软件发布版本指定一名维护者，负责维护该版本，例如确保重要的 bug 修复被回移植。

### 为开源项目做贡献

开源项目在很大程度上取决于人们为项目回馈了什么，例如，如果他们在软件中发现故障，则提交错误报告，或帮助项目解决 bug 或开发新功能。开源项目背后的社区通常有限，没有资源独立完成所有工作。Linux 内核、OpenStack 和 Yocto Project 等大型项目背后都有大公司，分配资源来协助这些项目。原因显而易见：这些公司在商业产品中使用该项目，并且有必要确保产品取得良好进展。许多公司还使用该项目的自己的版本，并希望贡献功能和 bug 修复，以降低集成成本。

### 提示

使用开源时，偶尔会使用上游这一术语。上游基本上可以概括为原始来源。“合并上游”这一短语意味着相关补丁应集成到项目的原始源代码中。

### 探索 Git

Git 是 Yocto Project 中使用的版本控制系统，包括 Raspberry Pi BSP 层（meta-raspberrypi）。因此，在考虑为 Yocto Project 及其子项目做贡献之前，Git 是你需要掌握的核心部分。

### 什么是 Git？

Git 是一个分布式版本控制系统，自 2005 年以来一直存在，旨在以速度和效率处理项目，无论规模大小。它最初是为处理 Linux 内核的源代码而创建的。Git 是免费开源的，任何人都可以使用，无需支付任何许可费。Git 的设计高度适合开源项目中的工作方式。除了支持分布式开发之外，它还拥有易于使用的日志记录机制来记录谁做了什么、历史的加密身份验证以及创建分支的简便方法等功能。

许多其他分布式版本控制系统（VCS，如 subversion、Bazaar 等）与 Git 之间的根本区别之一在于 Git 存储信息的方式。在 Git 中，数据可以被视为微型文件系统的快照。保存项目状态时，会对该状态拍摄快照并保存引用。

### 提示

基本的 Git 工作流程大致如下：

- 你修改工作目录中的文件
- 你暂存文件，将它们的快照添加到暂存区
- 你执行提交，该操作将暂存区中的文件按当前状态永久存储到你的 Git 目录中

有关更多信息，请访问 https://git-scm.com/book/en/v2/Getting-Started-Git-Basics。
