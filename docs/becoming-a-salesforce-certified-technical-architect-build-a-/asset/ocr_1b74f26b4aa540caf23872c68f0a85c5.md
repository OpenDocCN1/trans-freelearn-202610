The tools and functionalities that can help you design and configure the data sharing and visibility architecture are listed in the following diagram:

+   - Restriction rules: The records that the user has access to can be filtered using the restriction rules.
+   - Folder access (reports): Report access can be restricted using folders.
+   - Public groups and queues: This can be used to grant access to specific group/queue members.
+   - Territory management: An account-sharing system that grants access to accounts based on the characteristics of the accounts.
+   - Standard teams: Standard features in Salesforce such as the account team and the opportunity team can be used to grant access to some standard objects, with the possibility to use default teams.
+   - Manual sharing and Apex sharing: This enables sharing a record manually or automatically via Apex
+   - Sharing rules: This can be based on the record's owner or based on criteria. Remember that there is a limited number of sharing rules per org.
+   - Role hierarchy: This is used to grant vertical access to data.
+   - Org-wide defaults (OWDs): This defines the base level of access for each object.
+   - Permission sets: These refer to the extra object- and field-level permissions on top of the profile settings.
+   - User profile: This defines the object and field-level permissions.
+   - User license: This controls the basics of which objects are enabled for the user.
+   - Org-level access: Data is separated from other orgs’ data using the org ID. The “My domain” feature can uniquely identify the org. IP restrictions, login policies, and login flows can be used to control access to the org.

Figure 6.2 – Salesforce data access control tools and functionalities

At the bottom of the chart, you can see the org-level security mechanisms. They ensure that the data of one org is not mixed with data from other orgs. Salesforce is based on a multitenant architecture, so data belonging to multiple tenants could be hosted on the same platform. The org ID ensures that users of one org can access the data that belongs only to that org. The other org-level security functionalities are meant to protect the org itself from unauthorized access.
