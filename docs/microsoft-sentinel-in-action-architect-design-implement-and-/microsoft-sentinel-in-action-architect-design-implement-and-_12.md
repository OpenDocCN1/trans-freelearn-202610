# 14 Microsoft Sentinel 的运营任务

与任何服务或解决方案一样，持续的维护例行程序是确保及时的服务改进、保持运营效率、控制成本并——最重要的是——确保服务在检测和响应安全问题方面保持高度有效性的关键流程。

总体而言，安全运营中心（SOC）运营由两个不同的角色执行：SOC 工程师和 SOC 分析师。在小型组织中，这可能是由一个人同时承担两个角色；在大型组织中，这些角色将跨多个团队展开，并由专职专业人员执行。在本章中，我们将提供每个角色所需的日常、每周和每月任务的详细信息，以及根据需要执行的任何临时任务。你可以将此列表用作构建自己的任务列表的起点，以确保 SOC 运营最佳。

本章中的信息旨在为你的规划和持续改进提供起点，以便你执行必要的流程，打造高绩效团队并确保 Microsoft Sentinel 解决方案得到良好管理。

## 每周任务

SOC 工程师的每周任务列表如下：

- 审查数据连接器，确保每个已启用的连接器仍能正常运行。检查是否有新的或预览版连接器，以及现有连接器的更新。如果新连接器可以替代自定义连接器（或 syslog 服务器），请尽快计划替换，以受益于新功能并减少对定制和基于服务器的解决方案的依赖。

- 审查 **Workbooks** 页面和 **News & Guides** 页面，查找新的工作簿模板、连接器公告和任何新更新。确保现有工作簿在更新后仍能正常运行。

## 每月任务

SOC 工程师的每月任务列表如下：

- 审查数据摄取趋势以进行预测成本分析；调整 **pricing** 层级以反映最具成本效益的选项（有关更多详细信息，请参阅*第 1 章《开始使用 Microsoft Sentinel》*中的*Microsoft Sentinel 服务定价*部分）。
- 验证摄取日志的质量并进行降噪调优，尤其是在引入新的数据源之后。
- 验证为每种数据类型设置的当前保留期，并确认其适合调查要求和预算指南。
- 与 SOC 分析师一起进行场景映射练习，以识别额外的检测和响应需求（有关更多详细信息，请参阅*第 1 章《开始使用 Microsoft Sentinel》*中的*场景映射*部分）。将这些知识传递给业务和技术团队的关键利益相关者。
- 审查授予的角色和访问权限，确保分配的权限最少，并且只有**活跃**的团队成员保留所需的角色。

## 临时任务

SOC 工程师的临时任务列表如下：

- 审查对 IT 基础设施所做的任何更改；寻找整合额外日志数据的机会，以获得关键洞察并根据攻击场景配置自动化响应。
- 审查任何可能适用于威胁狩猎场景的新数据资源。
- 通过 Microsoft 的网站、博客、技术社区或活动（如 Microsoft **Ignite** 和 Microsoft **Build**）查看 Microsoft 的公告，以了解 Microsoft Sentinel 平台的潜在更改或任何集成服务和解决方案的更改。如果你部署了非 Microsoft 解决方案，也请检查相应的公告以获取受支持的产品更新。
- 更新 Microsoft Sentinel 架构文档以反映所做的任何更改。
- 与提供高级安全实践的外部服务合作，进一步测试和训练你的 SOC 能力，包括**渗透测试**、**社会工程**，以及定义高级 SOC 活动。
