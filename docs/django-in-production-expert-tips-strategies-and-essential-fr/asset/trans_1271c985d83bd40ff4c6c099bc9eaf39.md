# 使用 Django 项目设置 PostgreSQL

Django 默认集成了 `SQLite3` 用于初始开发目的，这有助于开发者在无需初始数据库设置麻烦的情况下开始项目。在我们的例子中，我们在 [*Chapter 1*](#B18867_01.xhtml#_idTextAnchor014) 中使用了 SQLite3。然而，它是一个基于文件的数据库，不建议在生产中使用，因为它无法扩展。

相反，我们将在整本书中将 `PostgreSQL` 作为与 Django 配合使用的数据库选择。由于始终建议尽可能让本地开发环境与生产环境保持一致，我们将为本地开发设置 PostgreSQL。

重要说明

你可以通过在 `settings.py` 文件中做少量更改，使用其他受支持的数据库，如 MySQL、MariaDB 和 Oracle（[https://docs.djangoproject.com/en/stable/ref/databases/#databases](https://docs.djangoproject.com/en/stable/ref/databases/#databases)）。但请记住，并非所有数据库都支持所有 ORM 功能，因此如果你使用其他数据库，请查阅文档以获取更多详细信息。

在本地系统上设置 PostgreSQL 有时可能是一项艰巨的任务，因此我建议为此目的使用 Docker（我们将在 [*Chapter 11*](#B18867_11.xhtml#_idTextAnchor219) 中了解更多）。然而，为了便于学习，我们将使用 ElephantSQL，一个远程 PostgreSQL 服务器，来开始。ElephantSQL（[https://www.elephantsql.com/](https://www.elephantsql.com/)）提供了一个配置有限的免费 PostgreSQL 服务器；这足以让你跟随本书中我们将学习的所有内容。

那么，让我们看看如何使用 ElephantSQL 创建一个 PostgreSQL 服务器，然后将其用于配置 Django 使用 PostgreSQL。

## 配置 Django 使用 PostgreSQL

在上一章中，我们学习了如何创建 Django 项目结构；我们将继续沿用相同的结构。在整本书中，我们将使用一个博客应用的示例来理解 Django 的不同深入功能。你可以在 [https://github.com/PacktPublishing/Django-in-Production](https://github.com/PacktPublishing/Django-in-Production) 查看项目结构。

一旦你准备好 `myblog` 项目，我们就可以配置数据库。Django 中的数据库配置放在 `settings.py` 文件中。如果你打开默认的 `settings.py` 文件，你将能够找到 `DATABASES` 变量，其中已经配置了 SQLite3：

```
DATABASES = {
    'default': {
        'ENGINE': 'django.db.backends.sqlite3',
        'NAME': BASE_DIR / 'db.sqlite3',
    }
}
```
