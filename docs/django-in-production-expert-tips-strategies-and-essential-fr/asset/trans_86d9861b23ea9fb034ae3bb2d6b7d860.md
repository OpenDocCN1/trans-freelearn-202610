## 生产环境日志记录的最佳实践

我们已经学习了如何在 Django 中设置日志记录以及如何创建和访问日志消息。现在让我们学习在使用生产环境日志记录时应考虑的几个最佳实践：

* 不要在生产环境中使用日志记录来收集错误。我们看到的最常见错误之一是开发人员在生产环境中使用日志记录来捕获错误。虽然这对于小型项目有效，但这种方法不可扩展。应使用 `Sentry` 或 `Rollbar` 等错误监控工具来实现此目的。我们将在 [*第 14 章*](#B18867_14.xhtml#_idTextAnchor283) 了解更多关于这些工具的信息。
* 不要使用电子邮件传输日志。相反，使用日志管理代理将生成的日志传输到日志引擎，以便更好地访问日志。使用 `NewRelic` 或 `ELK` 栈等工具来访问和浏览日志。
* 避免将敏感信息传递给日志。我们的应用程序可能可以访问有关用户的信息，而随着我们开始使用日志来捕获不同的信息，我们应确保不会在日志中捕获敏感信息。例如，避免捕获电子邮件地址、密码、付款详情等。这可以通过使用 Python 日志模块提供的自定义日志过滤器来实现。
* 使用前面所示的通用日志函数。这将使日志具有一致的格式，使日志代理更容易解析，并帮助我们更好地扫描它们。
* 在当前用例结束后删除日志。如果我们不删除所有旧的和不必要的日志，这可能会因日志消耗量大而产生高成本。随着应用程序的增长，您应跟踪如何删除旧的日志函数调用。

我们已经学习了如何在 Django 中实现日志记录以及在项目中实现日志记录的最佳实践。这可以被视为 Django 日志记录的样板设置。通过提到的设置，可以获得大部分使用日志记录的信息。但是，如果您有不同的需求，请随时访问官方文档并改进您的设置。

## 在 Django 和 DRF 中分页响应

当客户端发送请求从服务器获取记录时，不建议一次性发送数据库中存在的所有条目。这就是分页概念发挥作用的时候。例如，如果我们保存了 1,000 篇博客，一次性将所有博客发送给客户端的请求将增加页面加载时间并给系统带来性能瓶颈。为了解决这些问题，我们将引入分页的概念。

### 理解分页

让我们举一个例子来理解分页的概念。客户端请求获取博客列表，我们的网站上发布了 1,000+ 篇博客。我们会分小批发送一些博客，例如每次 10 篇。这就是分页。用户将与 UI 交互并请求下一批博客。服务器可以为 API 实现不同类型的分页：

* Cursor API 分页
* Keyset API 分页
* Offset API 分页
* 基于时间的 API 分页

我们将在 *在 DRF 中使用分页* 部分学习所有这些技术。简而言之，我们可以将分页视为我们有一个条目列表，我们在将每个数据切片发送给客户端之前将列表切片成更小的部分的概念。

让我们学习关于可以使用 Django ORM 以最简单的方式实现的基本分页，通过创建一个 `get_blog_without_pagination` 视图，该视图返回所有博客。此视图适用于小规模，但在我们有 1,000+ 博客时，此视图会很慢且不太有用，因为读者不期望阅读全部 1,000+ 博客。将以下代码添加到 `blog/views.py`：

```
def get_blog_without_pagination(request):
    blogs = Blog.objects.all()
    blogs_data = BlogSerializer(blogs, many=True).data
    return Response({'blogs': blogs_data})
```

我们还需要将视图链接到 URL，因此将以下代码添加到 `blog/urls.py` 文件：

```
urlpatterns = [
    . . .
    path('unpaginated/', views.get_blog_without_pagination),
    . . .
]
```

当我们打开 [http://127.0.0.1/blog/unpaginated/](http://127.0.0.1/blog/unpaginated/) 时，我们将获得数据库中创建的所有博客的列表。随着创建更多博客，这不可扩展。
