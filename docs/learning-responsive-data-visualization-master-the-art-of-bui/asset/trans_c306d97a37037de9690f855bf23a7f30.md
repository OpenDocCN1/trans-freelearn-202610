## 在不同屏幕分辨率下隐藏元素

Bootstrap 还提供了非常实用且响应式的实用工具类，用于在特定浏览器宽度下隐藏元素。这些类根据媒体查询断点命名：

- .hidden-xs
- .hidden-sm
- .hidden-md
- .hidden-lg

在手机竖屏模式下隐藏元素只需为元素添加一个类；让我们看看下面的示例：

```
<ul class="nav">
    <li><a href="#menu">Menu</a></li>
    <li class="hidden-xs"><a href="#link">Link</a></li>
</ul>
```

在特定浏览器宽度下显示元素的类，根据元素的 CSS display 属性，在每个断点中都有三种不同的变体：

- .visible-*-block
- .visible-*-inline
- .visible-*-inline-block

> 之所以需要这些额外的类型，是因为当显示模式从 none 变为 block 时，会出现不想要的换行和行为。因此，Bootstrap 强制用户通过类名指定显示属性。

对于这三种块，所有断点类都可用：

- .visible-xs-*
- .visible-sm-*
- .visible-md-*
- .visible-lg-*

仅在特定设备宽度下显示元素也非常简单：

```
<ul class="nav">
  <li><a href="#menu">Menu</a></li>
  <li class="visible-xs-block"><a href="#link">Link</a></li>
</ul>
```

> Bootstrap 4 仅在所有断点上提供 .hidden-*-down 和 .hidden-*-up 类来隐藏特定设备类型的元素。

## 在 LESS 中使用 Bootstrap 的媒体查询

Bootstrap 的样式表是用 LESS 编写的，我们可以轻松使用预定义的断点和媒体查询。

> LESS 是一种类似于 CSS 的预处理器语言，用于编写支持嵌套、变量、函数、混入等功能的样式表。LESS 文件在开发过程中通过 LESS 编译器编译为 CSS 文件。如果你从未听说过 LESS，现在正是通过 http://lesscss.org/ 了解它的好时机。

请确保已安装 LESS 编译器；可以通过在终端中运行以下命令来完成：

```
npm install -g less
```

首先，我们创建一个 style.less 文件，并在文件开头导入 Bootstrap 的 variables.less 文件。这样我们就可以在整个文件中复用 Bootstrap 为颜色、尺寸和配置所做的声明：

```
/* style.less */
@import "bower_components/bootstrap/less/variables.less";
```

现在，我们可以在 LESS 文件中使用 Bootstrap 的媒体查询断点。让我们为所有 div 容器添加一些特定于设备的内边距：

```
/* Extra small devices */
/* No media query since this is the default in Bootstrap */
div {
	padding: 4em;
}

/* Small devices */
@media (min-width: @screen-sm-min) {
	div {
		padding: 8em;
	}
}

/* Medium devices */
@media (min-width: @screen-md-min) {
	div {
		padding: 16em;
	}
}

/* Large devices */
@media (min-width: @screen-lg-min) {
	div {
		padding: 24em;
	}
}
```

现在，我们使用 LESS 编译器，通过在终端中运行以下命令将样式表编译为 CSS：

```
lessc style.less style.css
```

生成的 CSS 类似于此：

```
/* Extra small devices */
/* No media query since this is the default in Bootstrap */
div {
	padding: 4em;
}
/* Small devices */
@media (min-width: 768px) {
	div {
		padding: 8em;
	}
}
/* Medium devices */
@media (min-width: 992px) {
    div {
        padding: 16em;
    }
}
/* Large devices */
@media (min-width: 1200px) {
    div {
        padding: 24em;
    }
}
```

完美！这意味着我们现在可以在 LESS 样式中使用预定义的断点了。

有时，将样式限制在一小组设备上也是必要的。因此，也可以在 LESS 中使用 max-width 媒体查询。同样，以下代码片段取自 Bootstrap 文档 http://getbootstrap.com/css/#grid-media-queries：

```
@media (max-width: @screen-xs-max) { ... }
@media (min-width: @screen-sm-min) and (max-width: @screen-sm-max) {
... }
@media (min-width: @screen-md-min) and (max-width: @screen-md-max) {
... }
@media (min-width: @screen-lg-min) { ... }
```

当我们想为单一设备类型定义样式，而不是为所有屏幕宽度大于或等于定义值的设备定义样式时，这会很有用。

# 浏览器中的矢量图形与 SVG

现在，是时候创建我们的第一个可视化了。在 HTML5 中，我们有大量选项可以直接在浏览器中创建图形：

- Canvas API（例如使用 Paper.js、Processing.js 等）
- WebGL API（例如使用 Three.js、Pixi.js 等）
- SVG 规范（例如使用 RaphaëlJS、D3.js 等）

为了更好地了解哪种技术最适合我们实现响应式可视化的目的，我们需要仔细审视并讨论它们的优缺点。

## 使用 Canvas 实现光栅/像素图形

Canvas 是一种用于在浏览器中创建光栅图形（通常称为像素图形）的 JavaScript API。正如我们在下图中所见，它得到所有主要浏览器以及从第 9 版开始的 Internet Explorer 的支持：

> > 你可以在 MDN 上找到关于 Canvas API 的详细信息：https://developer.mozilla.org/en/docs/Web/API/Canvas_API。

![](img/72559bd4713b2b89631dcca187d7e2db_41_0.png)

像素图形是一种包含特定分辨率下图像中每个像素颜色所有信息的图像。假设我们有一个 8 x 8 像素的图像，这 64 个像素中的每一个都包含其颜色信息；我们在此图像中绘制一个圆：

```html
<canvas id="canvas"></canvas>
<script>
  var canvas = document.getElementById("canvas");
  var ctx = canvas.getContext("2d");
  var centerX = 10, centerY = 10, radius = 10;
  ctx.beginPath();
  ctx.arc(centerX, centerY, radius, 0, 2 * Math.PI, false);
  ctx.fillStyle = "red";
  ctx.fill();
</script>
```

在下图中，可以看到所谓的光栅化过程如何定义圆形哪些像素被着色（蓝色区域的像素）以及哪些像素保持透明（白色区域的像素）：

![](img/72559bd4713b2b89631dcca187d7e2db_42_0.png)

8 x 8 像素圆形的光栅化

![](img/72559bd4713b2b89631dcca187d7e2db_42_1.png)

如果以高分辨率显示此图像（参见左侧的下图），我们会看到边缘清晰的小圆。另一方面，如果放大图像，我们会看到一个非常像素化的 8 x 8 像素图像（参见右侧的下图）；这种效果直接由依赖分辨率的光栅化过程引起：

像素图形，左侧：高分辨率，右侧：放大

这种效果使得使用像素图形进行响应式设计变得非常困难；我们必须始终针对当前分辨率和屏幕大小生成并重新加载可视化。

另一个缺点是，最终图像由像素组成，这使得很难将事件监听器（如 mouseover 或 click 事件）附加到图像的某些组件上。原因是图像中未编码形状或组件，仅包含每个像素的颜色值。

## 使用 WebGL 实现硬件加速的像素图形

WebGL 是一种基于 OpenGL ES 2 的 JavaScript API，用于在浏览器中创建硬件加速的 3D 像素图形。这种技术非常强大，可通过所谓的着色器访问客户端的 GPU；最终可视化通过 Canvas 元素在浏览器中公开。然而，如下图所示，浏览器支持情况并不理想；移动设备仅部分支持该 API，Internet Explorer 仅从第 11 版开始支持。

> > 你可以在 MDN 上找到关于 WebGL API 的更详细信息：https://developer.mozilla.org/en/docs/Web/API/WebGL_API。
