
现在我们对战略路线图、架构和流程有了清晰的认识，可以开始规划实施工作。

## Stage 4 – 针对业务进行定制

本阶段将这些零信任组件与组织内所有正确的位置和利益相关者进行对齐和连接。

本阶段的步骤如下：

- 1. 确定您的产品模型。
- 2. 确定业务职能和组织结构。
- 3. 确定组织的业务流程。

*表 9.4 详细介绍了这些步骤：*

| 剧本步骤 | 负责人 | 描述 |
|---|---|---|
| Stage 4 – 针对业务进行定制 |  |  |
| **确定您的产品模型** | - 组织高级领导者（包括产品和业务线领导者）<br>- 技术高级领导者（尤其是安全）<br>- 安全态势管理<br>- 架构师（尤其是安全、业务和企业架构师）<br>- 管理人员<br>- 应用和产品安全 | *本步骤捕获您组织的产品模型。*<br><br>企业销售商品和服务，这些统称为 *产品*。该产品模型有助于您了解零信任如何应对与产品相关的三个关键要素：<br><br>- **风险**：作为潜在损失的来源。<br>- **机会**：作为提高组织成功的机制。这通常表现为在现有业务线中增加收入，或通过进入新的业务线或地区来开拓新的收入来源。<br>- **做生意便利性**（以敏捷性和成本衡量）。<br><br>这种背景有助于将零信任与组织的收入联系起来，并确定哪些业务职能和流程受到影响，零信任将如何集成和影响它们，以及如何最好地衡量这种影响。这种影响将以人员、组织结构、业务流程和能力来描述。<br><br>该举措将由安全领导者主导，使用安全架构、企业架构和业务领导者。 |
| **确定业务职能和组织结构** | - 组织高级领导者<br>- 技术高级领导者（尤其是安全）<br>- 架构师（尤其是安全、业务和企业）<br>- 管理人员<br>- 相邻/辅助角色（尤其是业务分析师）<br>- 企业安全集成（副首席信息安全官及员工、安全[业务]分析师） | *本步骤捕获您组织提供人员和结构以交付组织提供的产品的业务职能。*<br><br>创建业务职能的高层次评估，以了解零信任将如何影响业务职能和组织结构。<br><br>业务职能提供交付组织提供的产品的人员和结构。对业务职能进行高层次评估，以了解零信任将如何影响业务职能和组织结构。<br><br>该举措将由安全领导者主导，使用业务架构资源。它还将涉及中级和高级业务和技术领导作为信息来源并验证信息。其成果通常包括培训、重新组织以将零信任作为组织能力纳入其中，以及建立程序和政策。业务职能所服务的零信任能力指标也将被审查。 |
| **确定组织的业务流程** | - 组织高级领导者<br>- 技术高级领导者（尤其是安全）<br>- 架构师（尤其是安全、业务和企业）<br>- 管理人员 | *本步骤捕获交付组织提供的产品的业务流程。*<br><br>在本步骤中，您创建业务流程的高层次评估，以了解零信任将如何影响业务职能和组织结构。<br><br>重要的是保持此次初步发现的范围轻且广（深入一英寸，宽达一英里），以免陷入过多细节或过度设计。第一次整体发现应大致了解零信任将如何影响业务流程。例如，零信任可能实现自助式身份和访问管理。对于中型至大型零售商或银行等组织而言，这可能产生巨大影响。<br><br>我们将在角色特定的剧本中查看这些流程的细节。<br><br>该举措由安全领导者主导，使用安全和业务架构资源。它还将涉及中级和高级业务和技术领导，他们作为信息来源和审阅者。零信任影响通常包括培训、重新组织以将零信任作为组织能力纳入其中，以及建立程序和政策。业务职能所服务的零信任能力指标也将被审查。 |

## Stage 5 – 实施并改进

本阶段构建零信任并使其成为现实，将其与业务流程和技术资产集成。

本阶段的步骤如下：

- 1. 构建零信任的可重用组件
- 2. 建立最佳实践
- 3. 实施并改进

表 9.5 涵盖本阶段的步骤：

| 剧本步骤 | 负责人 | 描述 |
|---|---|---|
| Stage 5 – 实施并改进 |  |  |
| **构建零信任的可重用组件** | - 架构师（尤其是安全、业务和企业）<br>- 管理人员<br>- SecOps<br>- 应用和产品安全 | 本步骤构建在生产环境中实施的零信任组件和服务。这些将在组织内用于许多应用程序和业务流程。<br><br>本步骤使用 MVP 技术快速开发和部署每个组件的最小可行版本，并最大化从真实反馈和验证中学习。<br><br>这些零信任组件和服务为企业采用零信任奠定了基础，使用诸如安全信任区域、自适应身份验证以及为数据中心性开发“令牌”服务等要素。<br><br>我们强烈建议采用“先配置后定制”的方法（以避免定制解决方案的成本/复杂性），优先顺序如下：<br>1. 如果可用，重复使用现有组件。<br>2. 如果可用，购买标准组件。<br>3. 仅在需要时构建定制组件。<br><br>如果构建组件不是您的核心业务实践，请寻找购买来满足需求（这在 **软件即服务 (SaaS)** 世界中可以相当快速完成），并避免除非绝对必要之外的定制（因为它们会给您的组织带来长期维护负担）。 |
| **建立最佳实践** | - 架构师（尤其是安全、业务和企业）<br>- 管理人员<br>- SecOps<br>- 技术工程和运营<br>- 应用和产品安全 | 本步骤建立可重复的模式和最佳实践，以指导团队和从业人员，帮助他们避免浪费时间和精力。 |
| **实施并改进** | 整个组织 | 本步骤是组织实施路线图的时候。<br><br>组织中的所有角色都参与本步骤。<br><br>在路线图、治理框架以及文化、培训和沟通计划到位后，组织应开始执行路线图。在每个周期中开始迭代和衡量，根据来自真实环境的经验教训在过程中不断改进和演进。<br><br>这是一个持续的过程，一直执行到路线图结束，并导致一种敏捷的持续改进方法。<br><br>只要团队与其它团队保持沟通，每个团队都应感到有能力推进其职责。为了避免这种快速创新模式中的冲突，团队应不断与其他团队分享他们的计划，征求反馈，并密切关注其他团队正在做什么。这有助于每个人实时调整。 |
