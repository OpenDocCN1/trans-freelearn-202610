
## 第二阶段 – 建立运营模式

本阶段确保零信任与贵组织的运作方式保持一致。这将为您取得成功做好准备，并主动清除零信任在贵组织文化、治理和运营模式中的潜在障碍。

本阶段的步骤如下：

- 1. 确定您的业务运营模式。
- 2. 制定您的治理框架。
- 3. 制定文化变革和技能发展。

表 9.2 详细介绍了这些步骤：

| 剧本步骤 | 负责人 | 描述 |
|---|---|---|
| 第二阶段 – 建立运营模式 |  |  |
| **确定您的业务运营模式** | - 组织高级领导者<br>- 技术高级领导者<br>- 架构师（尤其是安全、企业和业务架构师）<br>- 企业安全集成（副首席信息安全官及员工、安全[业务]分析师） | *本步骤捕获您将用于聚焦和优先考虑战略、治理框架和政策的业务运营模式。*<br><br>本步骤由安全领导者负责，并涉及安全分析师、业务架构师和业务领导者。<br><br>这应包括发现贵业务的运营方式以及贵组织用于治理它的风险管理框架。<br><br>注意：请记住，路线图需要更新以使其与业务运营模式保持一致。 |

## 第三阶段 – 创建架构和模型

本阶段创建具体的计划，以指导技术和业务团队，确保架构、流程和日常运营建立零信任所需的所有组件。

本阶段的步骤如下：

- 1. 开发您的零信任解决方案架构。
- 2. 制定零信任的政策和程序。
- 3. 建立零信任运营。

表 9.3 详细介绍了这些步骤：

| 剧本步骤 | 负责人 | 描述 |
|---|---|---|
| 第三阶段 – 创建架构和模型 |  |  |
| 开发您的零信任解决方案架构 | - 技术高级领导者（尤其是安全、风险和合规）<br>- 架构师（安全、技术和企业架构师，如有） | *本步骤为企业构建量身定制的零信任模型和架构。*<br><br>本步骤将参考模型和架构转化为贵组织的具体且可操作的文档。您将把参考文档定制为组织的 技术环境 并映射能力以制定零信任解决方案架构。这是通过运营支柱完成的工作中的一个基本部分，我们将在剧本中详细说明流程。<br><br>此任务由安全架构师完成，并将涉及技术架构。 |
| **制定零信任的政策和程序** | - 风险和合规角色（风险团队、合规团队） | *本步骤为您的零信任计划构建零信任政策和程序。*<br><br>零信任政策和程序在敏捷性与可持续性之间取得平衡，并满足 **治理、风险和合规（GRC）** 需求。<br><br>所有政策和程序都应以 *零信任* 原则为指导，假设已遭入侵，强制执行最小权限，并明确验证信任。<br><br>政策和程序支持以下内容：<br>- 对资产和身份进行分类<br>- 使用安全区域<br>- 通过涵盖数字身份和自适应访问管理，建立零信任 **身份和访问管理（IAM）**<br><br>这通常是风险、合规、安全分析师和安全架构团队的领域。它由安全领导层负责，导致安全、风险和合规政策的更新，并在实施过程中向下转化为业务和技术团队。<br><br>在零信任 *持续学习* 背景下，该计划还应建立学习材料并更新治理框架，以确保 *全组织* 对政策和程序的理解和应用。 |
| **建立零信任运营** | - 技术高级领导者（尤其是安全、风险和合规）<br>- 架构师（尤其是安全架构师）<br>- **安全运营（SecOps/SOC）**<br>- 安全态势管理<br>- 技术工程和运营<br>- 安全态势管理 | *本步骤为您的零信任计划构建运营要素。*<br><br>零信任在整个组织的操作中引入安全变更，包括以下内容：<br><br>- **SecOps/SOC 现代化**：零信任使 SecOps 专注于快速检测、响应和恢复世界各地的业务资产。这侧重于最大限度地减少对手可以访问环境的时间（以 **平均修复时间（MTTR）** 衡量）。<br>- **态势管理**：组织还将建立态势管理职能，以监控整体安全风险敞口（使用云服务的实时数据）。这些团队将监控已知风险，并积极支持技术运营团队（IT、OT 和 DevOps），以便在攻击者发现并利用之前迅速缓解风险。此持续合规职能为许多控制措施提供 **按需审计**。<br>- **共享战略威胁情报**：与整个组织的团队共享有助于为业务风险决策、架构变更、技术控制和技术团队工作优先级提供信息。<br><br>这是一项与安全架构、SecOps/SOC、态势管理、风险和合规团队的协作工作。它由安全领导层负责，并在实施过程中转化为业务和技术运营团队。 |
