
-   **数字原生** 组织有时被称为“云端原生”，自成立以来就使用敏捷方法和云技术。数字原生组织需要零信任来抵御当今的威胁，但其旅程的起点不同，关注的重点也不同。这与移动电话技术往往在没有铜线电话线路基础设施的国家更快被采用的情况类似。

-   **为敏捷性增加严谨性**：数字原生组织通常需要专注于在文化和流程中引入或加强零信任的安全严谨性，因为它们通常已经具备所需的敏捷文化要素。

-   **不同的平台和不同的技术债务**：数字原生组织通常严重依赖由云厂商维护和保护的云服务以及自定义应用程序和系统：
  -   **云服务** 有助于将运营开销限制在比本地数据中心更低的水平，因为云厂商执行大部分安全和运营工作（尽管并非全部）。这避免了因保持老旧基础设施更新而累积的技术债务的限制（这是本地数据中心所必需的）。
  -   **自定义应用程序和开源组件** 需要管理开源和自定义应用程序组件的生命周期（而大多数成熟组织更专注于管理已安装应用程序的生命周期）。这导致数字原生组织尽早优先考虑零信任的应用程序和产品方面，包括管理 *软件供应链组件* 的安全。

## 是大刀阔斧更好还是规划更小的项目？

人们经常询问是否需要大型项目才能从零信任中获得价值，还是较小的项目（们）有效。

从赞助和战略规划的角度来看，*你应该尽可能做大*。这是什么意思？使其具有战略性，将其与公司的技术、业务和运营模式以及路线图保持一致，并理想情况下获得高层赞助。由组织领导赞助并与业务目标和风险保持一致的战略性零信任举措，比小型、分散的技术项目更能有效交付价值。

较小的零信任举措可以快速交付有意义的价值，但与跨团队的全面转型相比，较小的项目在能够交付的价值方面有限。要获得零信任转型的全部价值和收益，你需要一个由组织领导提供高层赞助的全面转型计划。

需要记住的是，*大型转型是一系列协调且有意的小型变更*（通常由路线图指导，如零信任的情况）。与每个大型转型一样，零信任最终是一系列与更大战略目标保持一致的小型决策和行动。操作手册将此转型分解为可操作的要素，可由每个角色执行，通常彼此独立。

无论零信任项目或举措的规模如何，你都应 *专注于以小步增量进行规划和执行，并在过程中进行调整*，以便保持对不断变化需求的敏捷性。

规划零信任举措（们）的规模和范围时，关键考虑因素如下：

-   **大型零信任转型是最有效的**，并且需要高层赞助。
-   **良好的沟通可以催化高层赞助**，这对大型转型是必需的。
-   **有时需要从小处着手**，但速度更慢且交付的价值更小。

## 良好的沟通可以催化高层赞助

对零信任（或总体安全）缺乏高层赞助通常是由认知、理解和沟通方面的差距驱动的，而非组织领导者缺乏兴趣。

沟通差距通常由缺乏认知和理解驱动：

-   **业务领导者**：大多数组织领导者关心业务运营和知识产权的风险，但不明确如何评估、判断和管理安全风险。有些人甚至错误地认为安全只是一个“技术问题”，技术团队应该能够在没有业务领导参与的情况下处理（与由智能人类罪犯和其他行为者驱动的动态风险相对）。
  这些理解差距仅仅是因为大多数业务领导者没有直接的安全经验，也没有接受过如何在其角色中有效管理安全风险的正式培训。
-   **安全领导者**：许多安全领导者可能不熟悉业务术语和流程，导致他们使用自己熟悉的技术术语和框架来传达安全风险。这种方法对业务领导者来说不熟悉且令人困惑，往往强化了安全只是一个技术问题的错误信念。

这种动态使得业务领导者难以准确判断安全风险并与安全领导者进行富有成效的安全风险讨论，从而导致对零信任或整体安全的赞助不足。
