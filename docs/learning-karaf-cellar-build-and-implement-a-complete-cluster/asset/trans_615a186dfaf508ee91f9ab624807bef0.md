对于特性集群事件，标识符是特性的名称。您可以使用 `features:list` 命令获取特性名称，该命令会给出以下输出：

```
...
[uninstalled] [2.3.2          ] cellar-webconsole
    karaf-cellar-2.3.2  Cellar plugin for Karaf WebConsole
[uninstalled] [1.0.1          ] transaction
    karaf-enterprise-2.3.1 OSGi Transaction Manager
[uninstalled] [1.0.1          ] jpa
    karaf-enterprise-2.3.1 OSGi Persistence Container
[uninstalled] [1.0.0          ] jndi
    karaf-enterprise-2.3.1 OSGi Service Registry JNDI access
[uninstalled] [1.0.0          ] application-without-isolation
    karaf-enterprise-2.3.1 Provide EBA archive support
```

默认情况下，Cellar 按如下方式黑名单某些特性：

```
default.features.whitelist.inbound = *
default.features.whitelist.outbound = *
default.features.blacklist.inbound = config,management,hazelcast,cellar*
default.features.blacklist.outbound = config,management,hazelcast,cellar*
```

Hazelcast 和 Cellar 特性是由 Cellar 本身安装的；因此，无需处理这些特性的集群事件。这就是默认的过滤配置允许所有集群特性事件，除了 config、management、hazelcast 以及所有 Cellar（cellar*）特性。

另一方面，config 和 management 特性默认由 Karaf 提供。由于这些是非常底层的特性，因此不需要处理这些特性的事件。

## The default filter configuration

Cellar 使用以下默认过滤配置：

```
default.config.whitelist.inbound = *
default.config.whitelist.outbound = *
default.config.blacklist.inbound = org.apache.felix.fileinstall*, \
    org.apache.karaf.cellar*, \
    org.apache.karaf.management, \
    org.apache.karaf.shell, \
    org.ops4j.pax.logging, \
    org.ops4j.pax.web
default.config.blacklist.outbound = org.apache.felix.fileinstall*, \
    org.apache.karaf.cellar*, \
    org.apache.karaf.management, \
    org.apache.karaf.shell, \
    org.ops4j.pax.logging, \
    org.ops4j.pax.web

default.features.whitelist.inbound = *
default.features.whitelist.outbound = *
default.features.blacklist.inbound = config,management,hazelcast,cellar*
default.features.blacklist.outbound = config,management,hazelcast,cellar*

default.bundle.whitelist.inbound = *
default.bundle.whitelist.outbound = *
default.bundle.blacklist.inbound = none
default.bundle.blacklist.outbound = none
```

以下是前述配置的说明：

- 所有集群配置事件在默认集群组中均被允许（白名单），对节点而言为入站和出站，除了（黑名单）具有 org.apache.felix.fileinstall*、org.apache.karaf.cellar*、org.apache.karaf.management、org.apache.karaf.shell、org.ops4j.pax.logging 和 org.ops4j.pax.web PID 的配置。
- 所有集群特性事件在默认集群组中均被允许（白名单），对节点而言为入站和出站，除了（黑名单）名为 config、management、hazelcast 和 cellar* 的特性。
- 所有集群 bundle 事件在默认集群组中均被允许（白名单），对节点而言为入站和出站。没有 bundle 被阻止（黑名单为 none）。

## Summary

在本章中，我们学习了如何配置集群事件的过滤。它提供了对集群事件的细粒度管理：按集群组、按方向（入站或出站）、按资源（特性、bundle 和 config），支持使用正则表达式来识别集群事件和过滤类型（白名单或黑名单）。

它还允许集群管理员定义哪些资源应在集群上同步。

在下一章中，我们将看到资源同步的另一个应用：使用 **Distributed OSGi (DOSGi)** 的 bundle 之间远程通信。

在之前的章节中，我们将 Cellar 视为一种配置集群解决方案；在一个节点上对资源执行的操作会创建集群事件并发送到其他节点；这些节点随后会相应地做出反应。Cellar 还提供了除配置集群之外的一些特性。Cellar **Distributed OSGi (DOSGi)** 就是这些附加特性之一。

在本章中，我们将涵盖以下主题：

- DOSGi 是什么以及一个用例
- Cellar DOSGi 实现
- 使用 Cellar DOSGi 的完整示例

## What is Cellar DOSGi?

Cellar DOSGi 是 OSGi 规范中 Remote Service Admin 规范的实现。基本上，它是托管在不同容器中的 bundle 之间服务的远程通信。

使用 OSGi 服务，一个 bundle 将服务（实际上是一个接口）暴露给 OSGi 框架提供的服务注册表。另一个 bundle 可以在服务注册表中查找服务，获取对该服务的引用并使用它。借此，我们在低级组件（bundle）上实现了真正的 **Service-Oriented Architecture (SOA)** 方法。

Cellar DOSGi 提供了分布式服务注册表，并使用 Hazelcast NIO 进行服务的远程使用。

Hazelcast NIO 是 NIO 的数据序列化和传输实现。详情可参阅 Java NIO Javadocs（http://docs.oracle.com/javase/7/docs/api/java/nio/package-summary.html）和 Hazelcast NIO 文档（http://hazelcast.org/docs/2.6/javadoc/com/hazelcast/nio/DataSerializable.html）。

下图显示了两个节点如何通过分布式服务注册表相互通信：

![](img/86f349f6a758f2c3088dbeb4d35dcaca_90_0.png)

在一个节点上，一个 bundle（名为 Service Bundle）可以在分布式服务注册表中暴露一个服务。为此，它只需使用 service.exported.interfaces 服务属性注册服务。我们将在本章后面通过示例了解如何创建服务并定义此服务属性。Cellar 会监听所有服务注册，如果服务具有 service.exported.interfaces 属性，则会自动将其暴露到分布式服务注册表。

另一方面，一个 bundle（名为 Client Bundle）只需执行常规的服务查找。Cellar 在以下情况下拦截此查找：

- 如果服务存在于本地服务注册表中，Cellar 使用它
- 如果服务不存在于本地服务注册表中，Cellar 将查找转发到分布式服务注册表

客户端 bundle 获取对服务的引用。对于本地服务，此引用直接指向 JVM 中的对象。对于远程服务，此引用是位于远程 JVM 中的实际服务的代理。

我们必须注意，DOSGi 不使用集群组（集群组目前用于资源同步）。这意味着不同集群组的节点成员可以使用 DOSGi 相互通信。

为了说明和理解（从用户角度）Cellar DOSGi 的工作原理，我们将创建一个 Greeter 应用程序。

在此应用程序中，我们将有一个 bundle 通过说 hello 暴露服务，以及一个使用该服务的客户端 bundle。

示例的源代码可在 Cellar 源代码的以下链接中获得：

https://github.com/apache/karaf-cellars/tree/cellar-2.3.x/samples/dosgi-greeter

## The API bundle

在 OSGi 中，服务由接口描述。这意味着同一服务的服务 bundle 和客户端 bundle 必须共享相同的接口。

为了解耦接口和实现并能够在不影响服务 bundle 的情况下更新客户端 bundle，一个良好的实践是创建一个仅包含接口的 API bundle。

我们通过在 OSGi 导出包头中按如下方式暴露 API 包来创建此 API bundle：

```
<osgi.export>
    org.apache.karaf.cellar.samples.dosgi.greeter.api*;version="${project.version}"
</osgi.export>
```

API bundle 包含描述 Greeter 服务的接口，如下所示：

```
package org.apache.karaf.cellar.samples.dosgi.greeter.api;

/**
 * Interface describing the Greeter service.
 */
public interface Greeter {

    /**
     * Returns a greet message.
     * @return
     */
    public GreetResponse greet(Greet greet);

}
```

服务提供一个操作：greet 对应于 Greeter 接口的 greet() 方法。此 greet() 方法以对象作为参数（Greet）并返回一个对象（GreetResponse）。
