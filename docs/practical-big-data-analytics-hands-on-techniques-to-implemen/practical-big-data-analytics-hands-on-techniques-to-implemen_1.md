## 前言

本书向读者介绍企业中使用的与大数据相关的广泛主题。大数据是一个庞大的领域，涵盖了技术、统计、可视化、商业智能以及许多其他相关学科。为了从数据中获得真正的价值，而这些数据往往由于数据量或技术限制而无法访问，公司必须在软件和硬件层面都利用适当的工具。

为此，本书不仅涵盖了大数据的理论和实践方面，还补充了高层主题，例如企业中使用大数据、大数据和数据科学计划以及关键考虑因素，如资源、硬件/软件堆栈和其他相关主题。这样的讨论对于计划实施或升级组织大数据和/或数据科学平台的组织中的 IT 部门将非常有用。

本书侧重于三个主要领域：

# 1. 大规模数据集上的数据挖掘

大数据今天无处不在，就像不久前 *数据仓库* 一词无处不在一样。行业中有无数种解决方案。特别是，Hadoop 及其生态系统中的产品已成为企业中既受欢迎又日益常见的选择。此外，更近期的创新，如 Apache Spark，也在企业中找到了永久的位置——意识到他们可能不需要 Hadoop 框架的复杂性，Hadoop 客户已大量转向 Spark。最后，NoSQL 解决方案，如 MongoDB、Redis、Cassandra 以及 Teradata、Vertica 和 kdb+ 等商业解决方案，已取代了更传统的数据库系统。

本书将以相当大的深度涵盖这些领域。Hadoop 和相关产品，如 Hive、HBase、Pig Latin 等已被涵盖。我们还涵盖了 Spark 并解释了 Spark 中的关键概念，如 Actions 和 Transformations。NoSQL 解决方案，如 MongoDB 和 KDB+ 也已得到相当程度的涵盖，并且还提供了动手教程。

# 2. 机器学习和预测分析

第二个被涵盖的主题是机器学习，也以各种其他名称为人所知，例如预测分析、统计学习等。提供了详细的解释，并附有使用 R 和 R 中机器学习包编写的相应机器学习代码。随机森林、支持向量机、神经网络、随机梯度提升、决策树等算法已被讨论。此外，机器学习中的关键概念，如偏差和方差、正则化、特征选择、数据预处理等也已被涵盖。

# 3. 企业中的数据挖掘

通常，涵盖理论主题的书籍很少讨论大数据的高层方面——例如成功的大数据计划的关键要求。本书包含了来自 IT 高管的调查结果，并突出了行业中普遍存在的共同需求。本书还包括一步一步的指南，说明如何根据在大型 IT 部门部署生产解决方案的经验教训，选择正确的使用案例，无论是用于大数据还是基于机器学习。

我们相信，通过对这三个领域的扎实基础知识，任何从业者都可以交付成功的大数据和/或数据科学项目。这就是本书整体结构和内容的首要意图。

## 如果数据一直存在，为什么我们现在才谈论大数据

到 2000 年代初，计算和技术（如存储）的快速进步使用户能够以前所未有的效率收集和存储数据。互联网进一步推动了这一发展势头，为全球范围内以无限容量交换信息提供了平台。技术以惊人的速度发展，并导致了由社交媒体、智能手机等连接设备以及宽带连接的可用性推动的重大范式转变，进而推动了用户参与，甚至在世界偏远地区也是如此。

总体而言，其中大部分数据由基于网络的来源生成，例如 Facebook 等社交网络和 YouTube 等视频分享网站。在大数据术语中，这也被称为 **非结构化** 数据；即数据没有固定的格式，如电子表格，或可以轻松存储在传统数据库系统中的数据。

![](img/8ededb1e0b69e85687f6e488d1044b79_28_0.png)

计算能力的同步进步意味着，尽管生成数据的速度非常快，但从计算上分析它仍然是可行的。机器学习中的算法曾经因数据量和算法复杂性而被认为难以处理，现在可以使用各种新范式（如集群或多节点处理）以更简单的方式进行分析，而这在过去需要专用机器。

- **软件：** 促进对硬件层中托管的数据集进行分析的软件资源，例如 Hadoop 和 NoSQL 系统，代表了大数据堆栈中的下一个级别。分析软件可以分为不同的子类别。分析软件的两个主要高层分类是促进以下功能的工具：
  - **数据挖掘：** 提供对大型数据集进行聚合、跨数据集连接和数据透视表等设施的软件属于此类。标准 NoSQL 平台如 Cassandra、Redis 等是用于大数据分析的高层数据挖掘工具。
  - **统计分析：** 提供超出简单数据挖掘的分析能力的平台，例如运行从简单回归到高级神经网络（如 Google TensorFlow 或 R）的算法，属于此类。

- **数据管理：** 数据加密、治理、访问、合规以及对任何企业和生产环境管理并在某些方面降低运营复杂性都很重要的其他功能构成了下一个基本层。尽管它们不如硬件或软件那样有形，但数据管理工具提供了一个明确的框架，组织可以使用该框架履行其义务，例如安全和合规。

- **终端用户：** 分析软件的终端用户构成了大数据分析参与的最后方面。毕竟，数据平台的好坏取决于其能够被高效利用并解决业务特定用例的程度。这就是从业者的作用所在，他们利用分析平台来获取价值。数据科学家一词通常用来指实现底层大数据分析能力的人，而业务用户则受益于更快访问和传统系统中不可用的分析能力。

## 大数据的类型

数据大致可分为结构化、非结构化和半结构化。虽然这些区别一直存在，但随着大数据的出现，对数据进行这些类别的分类变得更加突出。





## 结构化

顾名思义，结构化数据指的是具有明确组织结构的数据集，例如 Microsoft Excel 或 CSV 文件。从纯数据库角度而言，这类数据可以通过模式（schema）来表示。例如，联合国发布的 2017 年世界幸福指数排名中位列前五的*最幸福*国家所对应的下表，就是结构化数据的典型代表。

我们可以清晰地定义各列的数据类型——排名、得分、人均GDP、社会支持、健康预期寿命、信任、慷慨度和 dystopia 是数值列，而国家则用字母表示，更具体地说，是**字符串**。

## 非结构化

非结构化数据是指任何没有预定义组织模式的数据集，不像上一节表格那样具有明确的组织结构。口头语言、音乐、视频，甚至书籍，*包括本书*，都会被视作**非结构化**。这绝不意味着内容没有组织。事实上，一本书有目录、章节、小节和索引——从这个意义上说，它遵循了确定的组织方式。

然而，将每个词和句子都表示为严格规则集的一部分是徒劳的。一个句子可以由单词、数字、标点符号等组成，并且不像电子表格那样有预定义的数据类型。若要成为*结构化*的，这本书的每个句子都需要具备一组精确的特征，这既不合理也不切实际。

来自社交媒体的数据，例如 Twitter 上的帖子、Facebook 上与好友的消息以及 Instagram 上的照片，都是非结构化数据的例子。

非结构化数据可以以各种格式存储。它们可以是 Blob，而对于文本数据，则可以是存储在数据存储介质中的自由格式文本。对于文本数据，通常使用 Lucene/Solr、Elasticsearch 等技术来进行查询、索引和其他操作。

## 半结构化

半结构化数据是指同时具备组织模式元素和任意性方面的数据。一个个人电话通讯录（如今越来越少见了！）包含姓名、地址、电话号码和备注等列，就可以视为半结构化数据集。用户可能不知道所有联系人的地址，因此一些条目可能只有电话号码，反之亦然。

同样，备注列可能包含额外的描述性信息（例如传真号码、与该联系人相关的亲属姓名等）。这是一个允许用户添加补充信息的任意字段。因此，姓名、地址和电话号码列可以看作结构化的，因为它们可以用表格格式呈现；而备注部分则被认为是非结构化的，因为它可能包含一组任意的描述性信息，无法在通讯录中的其他列中表示。

在计算领域，**半结构化**数据通常以 JSON 等格式表示，这些格式可以封装结构化和无模式或任意的关联，通常使用键值对。一个更常见的例子是电子邮件消息，它既有结构化部分（如发件人姓名、消息接收时间等），这些对所有电子邮件都是通用的；也有非结构化部分，由电子邮件的正文或内容表示。

MongoDB 和 CouchDB 等平台通常用于存储和查询半结构化数据集。

## 大数据来源

当今技术让我们能够以惊人的速度收集数据——无论是在数量还是种类方面。有许多数据来源，但在大数据背景下，主要来源如下：

- **社交网络：** 可以说，我们今天所知的所有大数据的主要来源是过去5-10年间迅速普及的社交网络。这基本上是非结构化数据，以数百万计的社交媒体帖子和通过全球用户在网上的互动按秒生成的其他数据为代表。全球互联网接入的增加对于社交网络中数据的增长来说是一种自我实现的行为。

- **媒体：** 很大程度上是社交网络发展的结果，媒体代表了每天发生的数百万（甚至数十亿）次的音频和视频上传。上传到 YouTube 的视频、SoundCloud 上的音乐录音以及 Instagram 上发布的图片都是媒体的主要例子，其数量继续以不受约束的方式增长。

- **数据仓库：** 公司长期以来一直投资于专门的数据存储设施，通常称为数据仓库（DW）。DW 本质上是公司希望保留和编目以便于检索的历史数据集合，无论是用于内部使用还是监管目的。随着行业逐渐转向将数据存储在 Hadoop 和 NoSQL 等平台的实践，越来越多的公司正在将数据从他们原有的数据仓库迁移到一些更新的技术中。公司电子邮件、会计记录、数据库和内部文档是 DW 数据的一些例子，这些数据现在被转移到 Hadoop 或类似 Hadoop 的平台上，这些平台利用多个节点提供高可用性和容错能力。

- **传感器：** 大数据领域一个较新的现象是从传感器设备收集数据。虽然传感器一直存在，石油和天然气等行业几十年来一直在石油钻塔上使用钻井传感器进行测量，但可穿戴设备（也称为物联网）的出现，例如 Fitbit 和 Apple Watch，意味着现在每个人都可以以十年前几个石油钻塔所拥有的速率来流式传输数据。

  可穿戴设备可以在任何给定时刻从一个个体收集数百个测量数据。虽然目前还不算真正的大数据问题，但随着行业的不断发展，传感器相关数据可能会变得更像通过社交网络活动在网上产生的自发数据。

## 大数据的 4V

在大数据的背景下，4V 这个话题已经被过度使用，开始失去一些最初的魅力。尽管如此，记住这些 V 所代表的意义有助于了解背景语境，以便进行对话。

总的来说，4V 表示如下：

- **Volume（数据量）：** 正在生成的数据量
- **Variety（数据种类）：** 不同类型的数据，如文本、媒体、传感器或流式数据
- **Velocity（数据速度）：** 数据生成的速度，例如在任何给定时间通过社交网络交换的数百万条消息
- **Veracity（数据真实性）：** 这是较新加入 3V 的一个 V，表示数据中固有的噪声，例如记录信息中的不一致之处，需要额外的验证

## 如何判断你是否面临大数据问题，以及从哪里开始寻找大数据解决方案？

最后，大数据分析指的是让数据发挥作用——换句话说，通过使用适当的技术从大量数据中提取有用信息的过程。许多用于表示不同类型分析的术语并没有确切定义，因为它们可以被不同地解释，因此含义可能是主观的。




尽管如此，这里还是提供了一些内容作为参考或起点，帮助你形成初步印象：

- **数据挖掘：** 数据挖掘是指通过对数据集运行查询或基本汇总方法（如聚合）来提取信息的过程。从包含某在线网站一百万件商品所有销售记录的数据集中，找出销量排名前10的产品，这就是挖掘的过程：即从数据集中提取有用信息。Cassandra、Redis和MongoDB等NoSQL数据库就是具有强大数据挖掘能力的工具的典型代表。
- **商业智能：** 商业智能指的是Tableau、Spotfire、QlikView等提供前端仪表盘的工具，使用户能够通过图形界面查询数据。随着用户寻求提取信息，仪表盘产品的重要性也随着数据的增长而同步提升。易于使用、具备查询和可视化功能的界面，能够同时被技术用户和非技术用户普遍使用，这为数据分析访问的民主化奠定了基础。
- **可视化：** 数据可以通过易于理解的视觉化结果展示，既简洁又直观。可视化在更好地理解数据方面发挥了关键作用，尤其是在进行更深入分析之前分析数据集的性质及其分布时。JavaScript在沉寂了很长一段时间后重新崛起，其发展成果如D3.js和百度的ECharts，是开源领域可视化包的一些典型代表。大多数BI工具都包含高级可视化功能，因此，它已成为任何成功分析产品不可或缺的资产。
- **统计分析：** 统计分析是指允许最终用户对数据集执行统计操作的工具或平台。这些工具传统上已经存在多年，但随着大数据的出现，以及大量数据在执行高效统计操作方面带来的挑战，它们获得了越来越多的关注。R等语言和SAS等产品是计算统计领域中常见工具的主要例子。
- **机器学习：** 机器学习通常有多种名称，如预测分析、预测建模等，本质上是一个应用超越传统统计学范畴的高级算法的过程。这些算法不可避免地涉及运行数百或数千次迭代。此类算法不仅本质上复杂，而且计算量非常大。

技术的进步一直是机器学习在分析领域发展的关键驱动力，以至于它现在已成为整个行业普遍使用的术语。自动驾驶汽车、根据交通模式调整的地图交通数据，以及Siri和Cortana等数字助手等创新，都是机器学习在实体产品中商业化的例子。

## 总结

大数据无疑是一个庞大的主题，乍一看可能显得过于复杂。熟能生巧，大数据的学习也是如此——你参与得越多，对相关主题和术语就越熟悉，对这个主题也就越得心应手。
