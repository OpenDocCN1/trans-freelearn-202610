
## 多个地图和自定义事件

让我们创建一个稍微复杂一些的应用程序，使用多个地图并添加事件监听器。一个地图将显示一个国家的缩放视图，而旁边的地图将显示一个特写视图。每当一个地图被移动时，另一个地图的中心点会立即更新。这种类型的地图应用程序对于诸如数据录入流程等事情非常有用，在这些流程中，两个大地图可能比一个带概览地图的大地图更易用。

让我们把本章中学到的一些概念整合起来，创建一个类似类型的应用程序。

### 动手实践 – 创建多个地图和自定义事件应用程序

在本示例中，我们将制作一个应用程序，其中包含两个并排的地图，在移动时相互更新。

- 1. 复制之前的示例。我们将以此为基础进行工作。
- 2. 让我们重新创建第一个地图对象。对于本示例，我们将使第一个地图稍微放大一些并设置 maxResolution，以便地图不能缩放得比几次更多。我们还将使用两个控件——Navigation 和 PanZoomBar。
- 3. 让我们也更改中心点。我们将创建一个变量来存储起始中心坐标（也将由第二个地图使用）并更改 map.zoomToMaxExtent 行。在图层添加到地图后，使用以下代码：

```
map_1 = new OpenLayers.Map('map_1_element', {
    controls: [
        new OpenLayers.Control.Navigation(),
        new OpenLayers.Control.PanZoomBar()
    ],
    maxResolution:0.0054931640625,
    minResolution:0.00034332275390625
});
```

```
var map_center = new OpenLayers.LonLat(-120, 34);
if (!map_1.getCenter()) {
    map_1.setCenter(map_center);
}
```

- 4. 现在对于第二个地图，我们将使其处于更放大的级别并同样限制分辨率。将第二个地图的创建代码更改为以下内容：

```
map_2 = new OpenLayers.Map('map_2_element', {
    controls: [
        new OpenLayers.Control.Navigation(),
        new OpenLayers.Control.PanZoomBar()
    ],
    maxResolution: 0.17578125,
    minResolution: 0.0439453125
});
```

- 5. 接下来，让我们将 map_2 对象的中心点设置为与第一个地图相同的中心点：

```
map_2.setCenter(map_center);
```

- 6. 现在，我们的两个地图对象已按我们想要的方式设置——我们的工作完成了一半。如果打开地图，你应该会看到类似这样的内容：

![](img/1b8cd151c9f278555f9cf255b20d244e_242_0.png)

- 7. 我们的下一个目标是向地图添加事件，以便在地图移动时使地图对象相互更新。这比乍一看要棘手一些。让我们先为每个地图创建一个函数，当触发 moveend 事件时会被调用。

调用 setCenter 时传递 true 作为第三个参数非常重要，这样 moveend 事件不会被触发。如果被触发，我们将陷入无限循环（不好）。

```
function update_map_1(event){
    map_2.setCenter(map_1.getCenter(), null, true);
}
```

```
function update_map_2(event){
    map_1.setCenter(map_2.getCenter(), null, true);
}
```

- 8. 最后，让我们通过为两个地图对象注册事件来完成工作。

```
map_1.events.register('moveend', map_1, update_map_1);
map_2.events.register('moveend', map_2, update_map_2);
```

- 9. 全部完成！打开页面并平移。当你用一个地图完成平移时，另一个地图将被更新。

### 到底发生了什么？

你刚刚创建了一个相当复杂的地图应用程序，其中包含两个地图对象和几个自定义事件。凭借本章和前几章中学到的所有知识，我们可以开始做一些相当有趣的事情。这个示例只是我们只需在 OpenLayers 中做一点工作就能实现的内容的一个小样本。

## 9 使用向量图层

*此时，我们已经介绍了 OpenLayers 的基础。我们已经介绍了核心类——Map、Controls 和 Layers。本书的其余部分将更侧重于完善这些核心知识，扩展已介绍的概念并深入了解使用 API 可以做的更多“高级”事情。*

*我们将介绍如何创建矢量图层、在其中创建和交互对象、从外部文件（如 KML）加载数据等等。在本章中，我们将介绍许多不同类型的示例并在此基础上构建，以演示 Vector Layer 的工作原理。*

### 什么是向量图层？

OpenLayers 的 Vector 类通常用于在地图顶部显示数据并允许实时与数据交互。这是什么意思？基本上，这意味着我们可以从诸如 KML 或 GeoJSON 文件之类的地理空间文件中加载数据，并在地图上显示其内容，并按我们喜欢的方式设置数据的样式。例如，看看这张地图：

![](img/1b8cd151c9f278555f9cf255b20d244e_246_0.png)

这显示了一张以 Google 图层作为底层底图并在其上叠加矢量图层的地图。数据（所有带数字的圆圈）是从 GeoJSON 文件加载的，这是一种许多其他应用程序支持的开放文件格式。在矢量图层中，地图上散布着许多数据点。地图上的每个点都是矢量图层中的一个对象，这些对象被称为 Features。

在这种情况下，每个要素实际上是一个数据点的集群——每个圆圈中的数字代表属于该集群的点数。这种聚类行为是 OpenLayers 可以通过 Strategy 类开箱即用地使用的，我们将在本章后面介绍它。在进入那一点之前，让我们谈谈将矢量图层与其他图层区分开来的主要事情之一。

### 向量图层有什么特别之处？

对于栅格图像，你所看到的就是你所得到的。如果你要在地图上查看一些近距离的卫星图像并看到一堆聚集在一起的建筑物，你不一定会知道关于那些建筑物的任何额外信息。你甚至可能不知道它们是建筑物。由于栅格图层由图像组成，因此解释你所看到的内容取决于用户。这不一定是坏事，但矢量图层提供了更多。

使用矢量图层，你可以显示建筑物的实际几何形状并附加额外信息——例如其价值、所有者、其平方英尺等。正如我们将在本章后面看到的那样，很容易将矢量图层放在现有的栅格图层之上并在特定位置创建要素。我们还将看到只需单击或将鼠标悬停在要素上即可获取有关要素的额外信息。

### 向量图层是客户端的

另一个根本区别是矢量图层通常用作客户端图层。这意味着通常与实际矢量数据的交互仅发生在客户端。例如，当你在地图上导航时，矢量图层不会向服务器发送请求以获取有关图层的更多信息。一旦你获得初始数据，它就存在于你的浏览器中，你通常不需要再次请求相同的数据（在大多数情况下，尽管 WFS 是一个例外；我们将在本章后面介绍）。

由于在大多数情况下矢量数据是在客户端加载的，因此与矢量图层的交互通常几乎是即时的。然而，存在一些限制。矢量图层依赖于用户的浏览器和计算机。虽然除 Internet Explorer 之外的大多数浏览器每天都在以惊人的速度进步并变得更加强大，但限制确实存在。

由于浏览器限制，矢量图层中的要素过多会开始变慢。要素数量没有硬性数字，但通常超过几百个要素就会在大多数计算机上开始变慢。然而，有很多方法可以解决这个问题，例如在不需要时删除要素，我们将在后面更深入地讨论性能问题。

### 其他用途

使用矢量图层，我们可以显示任何我们想要的几何对象——点、线、多边形、正方形、标记……任何你能想象的形状。我们可以使用矢量图层绘制线条或多边形，然后计算它们之间的距离。我们可以绘制形状然后使用多种格式导出数据，然后将该数据导入其他程序，例如 Google Earth。这些只是一些基本情况，而在本章中你将看到矢量图层可以多么强大。
