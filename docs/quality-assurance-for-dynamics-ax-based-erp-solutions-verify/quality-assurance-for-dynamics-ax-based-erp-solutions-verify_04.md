## 4 最佳实践—GUI

用户界面在 ERP 系统的可用性中发挥着至关重要的作用，并影响用户的工作效率。Dynamics AX 的用户界面标准主要基于以下标准：

- Dynamics AX 用户帮助最佳实践
- Windows 用户体验指南

Dynamics AX 用户界面标准的目标是确保与核心 Dynamics AX 应用程序的一致性，并最大限度地减少对 Dynamics AX 默认设置的覆盖。

我们将讨论如何实现上述目标以及需要遵守的最佳实践。阅读本章后，以下主题将变得清晰：

- 各种 GUI 最佳实践
- 对 GUI 最佳实践偏离的文档记录

### 窗口和屏幕布局

该标准的目标是在 Dynamics AX 和其他 Windows 应用程序之间提供通用性。实现这一目标可确保轻松管理 Dynamics AX 应用程序的不同窗口；因为用户在使用其他 Microsoft 应用程序（如 MS Office、Outlook 和 Internet Explorer 等）时通常了解 Microsoft 对窗口的标准。

| 序号 | 检查点 | 预期结果 |
|---|---|---|
| 1.1 | 是否有任何窗口可以通过除调整大小按钮以外的任何方式调整大小？ | 否 |
| 1.2 | 是否有任何表单在网格调整大小时会被调整大小？ | 否 |
| 1.3 | 是否有任何窗口在用户从表格视图更改为树视图或反之时会被调整大小？ | 否 |
| 2 | 是否有任何窗口无法适应 1024*768 像素的 SVGA 显示？ | 否 |
| 3 | 是否有任何窗口在默认大小时需要水平滚动？ | 否 |
| 4 | 是否有任何窗口正好打开在已打开窗口的顶部？（如果提供充分理由，测试人员可以忽略此标准。） | 否 |
| 5 | 是否有任何窗口无法调整大小？ | 否 |

### 导航窗格要求

导航窗格的 GUI 标准是为了确保导航窗格的使用方式与其他 Microsoft 应用程序（如 Outlook 等）相同。

| 序号 | 检查点 | 预期结果 |
|---|---|---|
| 1 | 导航窗格必须以应用程序窗口的特定百分比显示。如果用户调整窗口大小，导航窗格必须自动调整大小以保持百分比恒定。是否遵循此标准？ | 是 |
| 2 | 导航窗格必须具有以下两个部分：
- 收藏夹
- 主菜单
是否遵循此标准？ | 是 |

### 收藏夹

收藏夹菜单是导航窗格上的一个部分。核心 Dynamics AX 中未在收藏夹菜单上添加任何项目，但只要满足以下条件即可添加收藏夹项目：

| 序号 | 检查点 | 预期结果 |
|---|---|---|
| 1 | 在收藏夹中包含最多七个项目。此标准是否遵循？ | 是 |
| 2 | 不得使用超过两级的嵌套（缩进）。此标准是否遵循？ | 是 |
| 3 | 在收藏夹下分组项目的标准必须是 **任务类型**。此标准是否遵循？ | 是 |
| 4 | 必须为收藏夹使用清晰、简洁且易于理解的名称。不得使用晦涩的缩写或行话。此标准是否遵循？ | 是 |

## 主菜单

主菜单在导航到各种表单、报表等时发挥着关键作用。它设计成能够提高可用性（通过结构化导航），并缩短导航路径（即减少到达各种表单/报表所需的平均点击次数）。为了保持这些特性，任何定制都必须符合以下规范：

| 序号 | 检查点 | 预期结果 |
|---|---|---|
| 1 | 菜单开头（针对任何模块）的表单数量是否超过六个？ | 否 |
| 2 | 是否有任何菜单，其开头显示的表单使用频率较低？ | 否 |
| 3 | 是否有任何文件夹图标的名称不同于 Journals、Inquiries、Reports、Periodic 和 Setup？ | 否 |
| 4 | 文件夹图标是否按 Journals、Inquiries、Reports、Periodic 和 Setup 的顺序出现？ | 是 |
| 5 | 是否有任何文件夹包含超过六个表单？（不包含任何表单的文件夹是可以接受的。） | 否 |
| 6 | 主菜单中是否有任何节点的缩进级别超过 5？ | 否 |
| 7 | 是否有任何菜单图标与 Dynamics AX 标准不一致？ | 否 |
| 8 | 如果用户点击主菜单上的表单图标，请确保同一表单图标出现在新窗口的左上角。是否有任何窗口未遵循此标准？ | 否 |
| 9 | 是否有任何表单图标，其标题与对应表单上的标题不同？注意：表单标题右侧可能包含额外字符串，但它必须以表单图标中提到的标签字符串开头。 | 否 |
| 10 | 是否有任何表单不能通过单击表单图标打开？注意：有时点击图标后打开表单可能需要时间，建议测试人员耐心测试。 | 否 |
| 11 | 双击表单图标是否会打开两个相同的表单？ | 否 |

## 任务窗格要求

任务窗格（如果选择显示）在应用程序窗口右侧出现。其缺点是它减少了内容窗格的空间，因此许多用户选择不显示它。因此，UI 规范建议以用户无需选择它即可完成任务的方式使用任务窗格。任务窗格的几种建议用途可能是显示搜索结果、帮助内容等。必须遵守以下规范，以确保用户无需使用任务窗格即可完成任何任务：

| 序号 | 检查点 | 预期结果 |
|---|---|---|
| 1 | 任务窗格必须用于呈现有用但非必需的信息。任务窗格不得用于显示通知或对用户任务至关重要的信息。此标准是否遵循？ | 是 |
| 2 | 任务窗格不得用作对话框或用于设置选项。此标准是否遵循？ | 是 |
| 3 | 任务窗格不得用作与内容窗格竞争的次要工作区。内容窗格是显示与应用程序任务相关联的表单和窗口的主要工作区。此标准是否遵循？ | 是 |
| 4 | 任务窗格不得用于呈现使用户困惑的过量信息。此标准是否遵循？ | 是 |
| 5 | 任务窗格不得用于显示特定于当前所选表单或窗口的内容。任务窗格应显示适用于应用程序的一般信息或具有周边用处的信息。此标准是否对每个窗口都遵循？ | 是 |
| 6 | 考虑使用向导或替代内容格式来呈现信息或指导。是否有任何窗口未遵循此标准？注意：这是一个建议，因此在有充分理由的情况下可以忽略此检查点。 | 否 |

## 表单

精心设计的表单对可用性贡献最大，因为用户大部分时间只处理表单。Dynamics AX 将表单分为三类，所有用户界面规范必须符合特定表单类别。

| 序号 | 检查点 | 预期结果 |
|---|---|---|
| 1 | 表单必须属于三种标准表单类别之一，即两个选项卡控件（即 标题-行）、一个选项卡控件或功能窗口。不允许在单个表单中组合上述类别。是否存在此类表单？ | 否 |
| 2 | 是否有任何双选项卡控件表单不包含可移动分隔符以将表单拆分为标题和行？ | 否 |
| 3 | 表格上方的区域必须为空白或应包含一个或多个与表格中显示记录的常用筛选器或呈现格式相关的控件。是否有任何表单忽略了此标准？ | 否 |
| 4 | 是否有任何筛选控件用于根据组标题筛选记录？ | 否 |
| 5 | 表格的筛选条件不得在同一选项卡控件下的选项卡中提供。例如，包含表格的选项卡控件不得包含控制表格筛选的筛选选项卡。是否有任何表单忽略了此标准？ | 否 |
| 6.1 | 非活动筛选条件必须为空白。是否有任何表单忽略了此标准？ | 否 |
| 6.2 | 是否有任何复选框可用于激活或停用筛选控件？ | 否 |

### 最佳实践 – GUI

| 序号 | 检查点 | 预期结果 |
|---|---|---|
| 7 | 表格下方区域必须为空白或应包含以下任一项：行扩展控件 表格的相关汇总，例如列总数 行扩展控件包含属于当前所选行的信息。行扩展控件必须用于显示所有相关字段，否则需要水平滚动才能显示所有相关字段。行扩展只能用于用户垂直扫描对应列不相关的字段。是否有任何表单忽略了此标准？ | 否 |
| 8.1 | 列总数必须对数据库中的整列求和，而不仅仅是对可见部分求和。如果列的筛选器处于活动状态，则总数应针对受筛选条件控制的记录计算。是否有任何表单忽略了此标准？ | 否 |
| 8.2 | 列总数必须对数据库中受筛选器控制的整列求和。是否有任何表单忽略了此标准？ | 否 |
| 9 | 在表格的默认外观中，不得存在水平滚动。是否有任何表单忽略了此标准？ | 否 |
| 10 | 类型 1 和 2 的表单（在表单的检查点 1 中描述）不得包含 OK、Cancel 或 Help 按钮。是否有任何表单忽略了此标准？ | 否 |
| 11.1 | 表单上的按钮必须放在右侧的列中。是否有任何表单忽略了此标准？ | 否 |
| 11.2 | 按钮不应特定于选项卡。是否有任何表单忽略了此标准？ | 否 |

## 选项卡

选项卡分为两类，即网格布局和表单布局。选项卡需要遵守的标准取决于以下因素：

- 从布局角度来看的选项卡类别
- 选项卡位置
- 从使用角度来看的选项卡类型，例如设置选项卡、维度选项卡等。
- 其包含的 Windows 控件，例如树视图

选项卡必须符合以下规范：

| 序号 | 检查点 | 预期结果 |
|---|---|---|
| 1 | 任何表单中的第一个选项卡必须始终是概述选项卡。是否有任何表单忽略了此标准？注意：以下情况是这些规则的例外：- 在双选项卡控件表单中，行中的第一个选项卡必须命名为“行”，而不是“概述”。- 如果选项卡包含树视图控件，当选择树视图时，选项卡必须命名为“树”而不是“概述”。如果未选择树视图，则此选项卡应仅为“概述”。- 此标准不适用于功能窗口类型表单。 | 否 |
| 2 | 当打开任何表单时，必须显示概述选项卡。这里需要注意的是，此标准仅在存在概述选项卡时适用。在某些情况下，概述选项卡可以命名为树选项卡或行选项卡；在这种情况下，此规则分别适用于树选项卡和行选项卡。是否有任何表单忽略了此标准？ | 否 |
| 3 | 概述选项卡是否包含特定表单的记录列表？ | 是 |
| 4 | 在行选项卡控件中，第一个选项卡是否命名为“行”？注意：此规则仅适用于双选项卡控件表单，即行选项卡仅存在于此类表单中。 | 是 |
| 5 | 行选项卡是否包含在页眉选项卡控件中选择的记录的“行”列表？ | 是 |
| 6 | 任何表单（除功能窗口外）中的第二个选项卡必须始终是“常规”选项卡。此标准适用于页眉以及行（如果存在）。是否有任何表单忽略了此标准？ | 否 |
| 7 | 在功能选项卡控件中，第一个选项卡必须命名为“常规”。是否有任何功能表单忽略了此标准？ | 否 |
| 8.1 | 常规选项卡必须包含表单中最常用的控件。是否有任何表单忽略了此标准？ | 否 |
| 8.2 | 常规选项卡应显示在概述选项卡中选择的记录或在行选项卡中选择行的數據。是否有任何表单忽略了此标准？ | 否 |
| 9 | 如果任何表单上存在设置选项卡，它应为从左侧数起的第三个选项卡。是否有任何表单忽略了此标准？ | 否 |
| 10 | 如果设置选项卡相关，则必须命名为“设置”。是否有任何表单忽略了此标准？ | 否 |

## 用户帮助—帮助

Dynamics AX 帮助系统包含六种类型的帮助：

- **程序帮助**：这是按下 F1 键然后点击 **内容** 时打开的帮助。该帮助的目标是提供有关焦点屏幕的完整信息，以便用户能够知道如何完成任务。
- **表单帮助**：根据用户请求在单独窗口中打开。它描述了何时以及为何应使用此表单。
- **屏幕提示（这是什么帮助）**：这出现在文本框附近，以便用户能够知道此文本框是什么。
- **工具提示**：如果鼠标指针在命令按钮上保持静止一段时间，此类帮助会出现在命令按钮附近。
- **显式提示**：这是对当前所选对象的解释，会自动出现在表格上方。
- **状态栏消息**：状态栏消息出现在状态栏的左侧。

以下是各种帮助类型的示例布局：

## 项目

创建和维护项目的基数据

对于每个项目，都会列出项目编号、名称、发票项目、组和项目状态等信息，以及其他基数据。这也是您找到项目交易概览、项目过账设置、项目销售和成本价设置、发票信息、项目预测、WIP 定义和其他关键项目数据的地方。

可以创建四种不同的项目类型。有关这些项目特征的更多信息，请参阅“类型”。

## 项目层次结构

您创建的每个项目都可以作为父子层次结构中的父项目拥有任意数量的子项目。项目层次结构可以包含可选的层级数。每个子项目都可以从父项目继承基数据。

## 查看项目

项目以列表或树结构查看。选择或清除“树”控件复选框可在项目和树视图之间切换。

## 子项目

如果选择“子项目”复选框，则“工时”、“成本”和“收入”窗口中将显示父项目上的交易以及当前父项目的子项目上的交易。如果复选框保持空白，则这些窗口中仅显示父项目上的交易。

此外，如果选择此复选框，则在创建调整交易和发票提案时建议的项目范围内将包含子项目上的交易。

## 记录偏差

Dynamics AX 用户界面规范旨在确保高标准的用户体验和可用性；然而，在某些情况下，偏离这些规范是不可避免的。以下情况的几个例子可能是：

- 法律要求，例如遵守法律文件。
- 行业特定功能无法以符合这些规范的方式实现。

记录偏差不仅必须针对强制性要求，还必须针对建议。要记录偏差，我们需要记录以下信息：

- 为什么需要偏差？
- 头脑风暴文档，用于记录其他符合 Dynamics AX 的实现方式以及导致无法以这些方式实现时发现的限制。
