## 最佳实践检查工具

Dynamics AX 最佳实践检查工具可用于检查代码和对象是否符合 Dynamics AX 的最佳实践。此工具可以在三种不同的方式下使用：在编译时（仅当诊断级别设置为第 4 级时）、在签入时，以及在任何时间手动使用。

要将诊断级别设置为第 4 级，请转到 Tools | Options | Compiler 并将 Diagnostics level 的值设置为 Level 4。

要手动调用此工具，请转到 AOT 中的一个或多个节点，然后：

1. 右键单击。
2. 选择 Add-Ins。
3. 选择 Check Best Practices。

双击最佳实践偏差消息将打开代码编辑器。
这些消息为：

- 错误：应该一定修复的事情（在最佳实践工具输出中以红色显示）
- 警告：应该强烈考虑修复的事情（在最佳实践工具输出中以黄色显示）
- 信息：可能值得知道的事情（在最佳实践工具输出中以蓝色显示）

类别信息可以从最佳实践选项表单中控制。此表单可以从工具菜单访问。单击工具菜单中的 **Options**，然后单击 **Best Practices**。

选择 **Warning level** 以设置您希望在编译器输出窗口中看到的错误消息类型。编译器输出窗口将有三个选项 – **Errors only**、**Errors and warnings** 和 **All**。以下表格描述了这三个选项：

| 选项 | 错误 | 警告 | 信息 |
|---|---|---|---|
| 仅错误 | 是 | 否 | 否 |
| 错误和警告 | 是 | 是 | 否 |
| 全部 | 是 | 是 | 是 |

在某些情况下，我们可能需要隐藏某些代码片段中的错误或整个代码中一种或多种最佳实践偏差类型。这可以通过以下两种方式完成：

- “BP Deviation documented” 注释可用于阻止某段代码的最佳实践警告。需要注意的是，这仍然会显示最佳实践偏差，但不会作为警告显示；它将作为信息显示。此注释与普通注释一样，应按如下方式编写：
  `// BP Deviation Documented`
- 上述方法的缺点是错误消息仍作为信息显示，即仅抑制了严重性。另一种完全抑制最佳实践偏差的方法是使用 SysBPCheckIgnore 宏。以下是使用 SysBPCheckIgnore 宏的流程：
  1. 对于每个错误代码和 AOT 位置的组合，添加以下代码行
     ```
     C+= [#BP Error Code, @"AOTLocation"]
     ```
     其中 `BPErrorCode` 是 SysBPCheck 宏中列出的警告/错误的错误代码，而 `AOTLocation` 是 AOT 中应抑制其最佳实践偏差的对象的所在位置。
  2. 编译 SysBPCheck 类。
  3. 重启 Dynamics AX。
