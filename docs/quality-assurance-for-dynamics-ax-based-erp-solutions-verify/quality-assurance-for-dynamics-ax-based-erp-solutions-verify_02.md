## 1 Dynamics AX 简介

### Dynamics AX 简介

当今的商业环境竞争激烈、动态多变且动荡不安，企业生存的关键在于更接近客户并在最短时间内提供增值产品和服务。

因此，以下事项应被消除：

- 未知或不准确的作业成本
- 库存无法满足或远超生产需求
- 为获取影响员工效率的关键数据而重复劳动
- 经常设定不准确的客户期望
- 经常错过承诺的交货日期
- 运营绩效未达到经济水平
- 几乎没有或完全没有能力以任何程度的准确性预测和计划生产需求

这反过来要求：

- 企业各部门的协同运作
- 通过计算和预测各种业务参数来提高运营效率
- 通过更好的规划实现资源的高效利用
- 更好的客户关系，按时交付、及时解决问题并以合理成本满足质量标准

信息技术通过 **企业资源规划 (ERP)** 解决方案使企业能够应对上述挑战。

Dynamics AX 是微软的 ERP 解决方案，由于其特性而变得非常流行。我们将讨论 ERP 解决方案和 Dynamics AX 的关键特性。在定制期间，所有这些特性都应保留，因此我们还将通过研究与图形用户界面、技术设计、可信计算和缺陷管理相关的各种最佳实践来讨论如何在定制期间保留这些质量。这些也包括 Dynamics AX IBI 合规项目中与质量控制相关的 IBI 规范的大部分内容。

我们还将讨论通过各种测试验证不同类型特征的方法。最后，我们将讨论一些可用于测试活动的 Dynamics AX 内置工具。

本章将讨论：

- ERP 解决方案的关键特性
- ERP 解决方案的优点和缺点
- Dynamics AX 作为理想的 ERP 系统
- Dynamics AX 定制、IDE、文件系统和层系统的概述

### ERP 简介

ERP 系统是一种战略工具，可帮助企业实现上述列出的目标。它以集成方式收集各种业务流程，模拟现实世界的业务功能，并在所需的所有地方以适当的形式提供无缝集成信息。它帮助企业以最佳方式链接、利用和分配其资源，并在实时基础上控制它们。它通过简化流程、优化资源并做出快速、准确和一致的决策，使企业实现世界级绩效。

现在很明显，ERP 解决方案应具有一个基本特性——能够集成各种业务功能。然而，可用的 ERP 系统有更高的期望。以下列表总结了业务需求和 ERP 解决方案的预期特性。

- **总拥有成本 (TCO)**：ERP 解决方案不仅仅是一个工具；它是组织范围内的业务流程同步，因此是一个非常庞大的软件应用程序，可能需要数年时间才能实施。TCO 不仅包括 ERP 产品成本和定制成本，还包括在组织中带来文化变革的成本（培训等）。在如此庞大的项目中，TCO 是关键决策标准之一。




- **灵活性**：ERP 解决方案可能需要根据企业组织的需求进行修改（包括配置和编码），而这些需求可能随着业务规模、战略或法律制度的变化而随时间变化。它应能够在不同的硬件和数据库上运行，以使用公司异构的系统集合。ERP 应该可定制，以便 ERP 业务流程可以根据组织的独特业务流程进行修改。
- **可用性**：该解决方案必须对终端用户有用，以完成其使命，同时实现“工作乐趣”。这可以通过采用已知标准、一致性和直观的 UI 设计来实现。
- **业务流程的连贯性**：只有当 ERP 解决方案提供业务流程的连贯性时，其优势才能发挥出来，即信息在所有需要的地方都可用，不必重复输入相同的数据，并且现有信息在相关且可能的情况下得到重复使用。
- **模块化**：ERP 系统应具有开放的系统架构。这意味着任何模块都应具有在需要时进行接口连接或分离的能力，而不会影响其他模块。
- **集成**：企业可能已经在使用某些 IT 基础设施，并且由于某些原因（例如成本、战略原因等）可能不希望整个基础设施发生变化。应易于将新模块或外部应用程序集成到现有解决方案中。
- **可信度**：ERP 系统应值得信赖，即应具有以下属性：
  - **安全性**：确保信息和数据安全且保密。
  - **隐私**：信息安全至关重要，否则竞争对手可能会利用业务关键数据的利益以及各种业务流程的方法。因此隐私是关键要素。
  - **可靠性**：在当今极其复杂的 IT 应用（如 ERP 解决方案）中，端到端可靠性是满足客户期望并使 ERP 应用值得信赖的关键挑战。
- **响应性**：ERP 系统不仅应处理正常负载条件，还应处理异常条件，例如由于结账报告和预测报告而导致财年末的繁重工作负载。
- **国际化：** 如果 ERP 系统在多个地理位置实施或使用，ERP 解决方案必须正确国际化，具有：
  - 不同的语言和字符集。
  - 能够以每个区域使用的格式呈现数据。
- **本地化：** 每当实施 ERP 系统时，定制的主要成本发生在两件事上：根据本地需求进行本地化以及根据行业或特定部门需求进行适配。本地化 ERP 系统时需要考虑以下因素：
  - 政府、法律和市场要求：例如工资单中的社会医疗福利、企业的周工作日（因为它们在世界不同地区不同）。
  - 文化：例如，在某些地方一个人的名字可能由两部分组成——名字和姓氏——而在世界其他地区，它可能由五部分组成。
  - 标准：例如财务报告标准。
  - 格式：例如日期、时间。
  - 货币。
  - 时区。
  - 用户。
- **可扩展性：** 业务规模会随时间变化，因此小型 ERP 解决方案——几个模块、启用少量功能、少量用户、仅少量交易——应能够（并且预期！）增长。
- **代码文档：** 一旦 ERP 系统实施，它可能使用数年，因此可能由多个开发人员或公司维护。在其生命周期中，由于业务需求的变化可能需要修改，因此有必要理解各种开发人员编写的代码以便进行修改。因此需要代码文档。代码应从不同角度进行良好记录，例如代码更改、与代码更改相关的功能等。

### ERP 系统的优势

ERP 系统的优势可以分为以下类别：

- 运营控制
- 管理控制
- 战略规划

现在我们将讨论这些类别的所有优势。

### 运营控制

ERP 系统的关键优势是改善运营控制，因此提供以下好处：

- 通过更好的规划降低运营成本（从而提高资源利用率）
- 由于更好的可见性和效率，降低库存控制成本
- 由于重复工作减少而节省成本
- 减少非增值活动（精益处理）
- 由于运营高效而提高产能利用率
- 由于更好的客户期望管理而降低 CRM 成本，即满足时间表以及由于运营控制改善而节省成本
- 遵守既定流程

### 管理控制

ERP 系统的另一个关键优势是改善管理控制。ERP 系统提供更好的数据访问性，以便管理层可以实时访问信息以进行决策和管理控制。ERP 系统有助于跟踪活动的实际成本并执行基于活动的成本核算。

该类别中的一些好处如下：

- 通过更准确的实时数据以及历史数据改善决策
- 业务所有相关部门均可获得即时信息
- 企业范围内的数据标准化和准确性，因为它允许单点输入（即在该数据的源头），从而实现单一事实来源
- 减少前置时间和周期时间，从而更容易满足客户对时间线的期望

### 战略规划

ERP 系统使高层管理者能够进行战略规划，即规划未来目标和目标，并制定实现这些目标和目标的策略，同时考虑历史数据。

- 由于历史数据和分析数据的可用性，规划和预测得到改善
- 通过扩展的财务估算能力、现金流分析和各种交易监控，实现更好的财务控制

### ERP 系统的缺点

尽管我们讨论了很多 ERP 的好处，但事物都有两面性，ERP 系统也不例外。以下是 ERP 系统的几个缺点：

- **在许多情况下定制有限：** 许多 ERP 解决方案不允许在报告以外的定制，即报告中包含的信息和信息的呈现方式。这对 ERP 系统的优势造成了严重限制，因为企业肯定各不相同。没有两个企业完全相同。因此，一个真正设计良好的全球 ERP 系统应 readily 允许合作伙伴和客户进行定制，以充分发挥系统的潜力，实现其全部潜力。不幸的是，除了 Dynamics AX 之外，几乎所有其他 ERP 解决方案在定制方面都有太多限制。
- **需要重新设计业务流程：** 如前所述，几乎所有 ERP 解决方案都不允许太多定制，因此企业被迫采用该 ERP 系统建议的业务流程，这可能涉及风险。企业可能不愿意重新设计其业务流程，因为它们使用的是经过时间考验且适合其定制需求和条件的流程。由于 Dynamics AX 允许在几乎所有领域进行定制，因此不存在这种风险，因为业务流程再造的需求最小。
- **僵化：** ERP 解决方案对于特定组织可能过于僵化，这些组织是新成立的或希望在不久的将来朝新方向发展。

### Dynamics AX 简介

Microsoft Dynamics AX 是一款集成且可适应的业务管理解决方案，提供极大的灵活性和易于适应不断变化的业务需求。换句话说，它通过提供完整的易于使用的、可扩展的企业资源规划（ERP）软件包来提供竞争优势，以实现财务、客户关系、业务服务、人力资源和供应链流程的自动化和简化。

传统 ERP 供应商劝说客户不要定制软件以便于升级等。正如我们之前讨论的，每个企业都有一些独特性，这使该企业组织领先一步。这样的独特功能只能通过定制 ERP 系统来实现。如果 ERP 系统阻止企业遵循提供竞争优势的独特业务流程，就不会有人有兴趣部署这样的系统。因此 ERP 系统应易于定制。它肯定能使企业充分利用系统，实现其全部潜力。

Microsoft Dynamics AX 是一款可适应的业务管理解决方案，尤其适用于制造/分销、电子商务、批发或服务行业。它为制造商提供广泛的功能，支持在离散和批量加工制造模式下，按订单生产、按工程生产和按预测生产供应链模型。

Dynamics AX 还提供一系列财务功能，包括能够合并子公司或配送中心的账户，并让员工根据其职位级别访问会计、报告和广泛的分析工具。Dynamics AX 为您提供快速可靠的数据输入和处理所需的一切，并使您能够做出明智的决策并实现业务目标。

> Microsoft Dynamics AX 将使我们能够在今后高效有效地管理业务。它使我们能够继续发展一个成本效益高的环境，而不会有以前不得不面对的功能限制。—— Pascal Kouknas，IT 总监 Dynamics AX 和亚太区，Esselte (http://www.esselte.com) (Source: http://www.microsoft.com/casestudies/casestudy.aspx?casestudyid=1000003878)。

### Dynamics AX 作为理想的 ERP 系统

我们已经讨论了理想 ERP 系统的品质，现在我们将讨论 Dynamics AX 所具备的品质。




### 总拥有成本 (TCO)

在任何商业组织中，成本都是任何新举措的首要关注点；ERP 系统也不例外。Dynamics AX 因以下独特功能而提供成本优势：

- Dynamics AX 为 Web 和 Microsoft Windows 客户端提供相同的代码版本，这导致开发和 IT 成本更简单、更低廉，并为分布式或拥有移动劳动力的企业提供了极大的便利。
- 用于行业特定垂直领域和国家特定本地化的独立层不仅提供成本节约，还减少了实施 Dynamics AX 所需的工作量。
- 由于 Microsoft Dynamics AX 的分层技术，定制可以更轻松地构建和维护。您可以自定义某一层而不影响其他层的功能。这意味着您可以随着时间的推移以较少的业务中断、风险和费用来适应和升级您的解决方案。
- 由于功能键的缘故，任何功能都可以针对单个用户或用户组启用或禁用。这不仅提供了灵活性，还降低了总拥有成本。
- 由于 Dynamics AX 是基于通用 Microsoft 标准构建的 ERP 应用，而终端用户通常已熟悉这些标准，因此对终端用户的培训所需的工作量更少。

### 灵活性

灵活性是 ERP 解决方案中的另一个重要方面，但不幸的是大多数当前 ERP 解决方案都缺乏这一点。例如，使用 SAP 之类的 ERP 软件包，您必须遵循 SAP 对您业务的想法，他们认为您业务和战略的独特性。Dynamics AX 因以下功能而具有优势：

- **定制灵活性**：Dynamics AX 允许您更改所需的一切。企业将此视为一个很棒的功能。这是您实施的 ERP 能够随业务增长而增长的关键。选择 SAP 之类的 ERP 软件包，您必须遵循 SAP 对您业务的想法，他们认为对您业务运营的最佳方式。而在 Dynamics AX 中，您拥有控制权，并且在追求最佳业务实践的前提下，这些最佳实践可以应用于您的定制需求。这有助于企业降低总拥有成本。
- **分层编程：** Microsoft Dynamics AX 提供分层定制技术以便于构建和维护。您可以自定义某一层而不影响其他层的功能。这意味着您可以随着时间的推移以较少的业务中断、风险和费用来适应和升级您的解决方案。
- **功能键：** 功能键代码是一个很棒的系统。使用功能键，可以针对个人或用户组禁用或启用功能。

只有当终端用户能够高效使用时，任何软件或 ERP 软件包才可被视为成功。Dynamics AX 被认为是一个高度易用的 ERP 软件包，原因如下：

- **Microsoft 产品：** Dynamics AX 由 Microsoft 拥有并开发。目前 Dynamics AX 4.0 已与 Microsoft 的不同产品线高度集成，并且随着 Vista、DotNet 3.0、Commerce Server 2007、SharePoint Server 2007、Exchange 2007 和 Office 2007 的发布，所有这些产品线将与 Dynamics AX 产品更加紧密地集成。这意味着您可以从 SharePoint Excel Services 工作，并创建可直接与 Dynamics AX ERP 数据协作的电子表格；并且所有这些都可以通过信息工作者在分散控制的方式下集中管理。除此之外，Microsoft 还有整合各种 Microsoft 产品的长期愿景，例如，Microsoft 计划支持 Microsoft Office PerformancePoint Server 的完全集成，并且 Dynamics CRM 将支持与 Dynamics AX 5.0 的完全集成。
- **熟悉 Microsoft：** 使公司更高效的最好方式是使其中的人员更高效。为了实现这一目标，人们需要像 Microsoft Dynamics 这样的业务软件工具，使他们能够按自己喜欢的方式工作。当您实施 Microsoft Dynamics 时，您支持并增强了您的人们所做的工作以及他们的工作方式。Microsoft Dynamics AX 的工作方式类似于熟悉的 Microsoft 软件，如 Microsoft SQL Server、Microsoft SharePoint 产品和技术以及 Microsoft Office 产品，这意味着员工的学习曲线更短，从而能够专注于工作。

### IntelliMorph

通常，解决方案设计师或开发人员的主要关注点是 GUI 实体（表单、报表等）在所有受支持语言中都能良好运行。使用标签文件系统翻译不同标签很容易。然而，长度可能差异很大，这可能会破坏整个 GUI 设计，并且此类系统的可用性会受到损害。

在不同国家，功能可能以不同的方式使用，或者某些字段可能被隐藏或需要额外的字段。不同公司也可能出现这种情况。

考虑这样一种情况：某些业务流程可能未实施，因此必须删除其他业务流程到此业务流程的所有连接。因此，可能需要在所有相关业务流程中添加某些字段并删除某些字段。由于此类字段的添加或删除，GUI 可能会发生变化，这对用户来说非常不便。

MorphX 对上述场景有解决方案，即 IntelliMorph 技术。IntelliMorph 技术允许表单和报表自动调整显示宽度以适应单词长度，因此 GUI 保持在可呈现或可用的状态。



### 功能键

### X++ 编程语言

在 Microsoft Dynamics AX 集成开发环境中用于开发和编写类和方法使用的语言是一种面向对象的语言，类似于 Sun Microsystems 的 JAVA 和 C++。它基于 JAVA，并在代码中嵌入了 SQL。该语言对对象引用具有广泛的检查系统，既在编译时也可在运行时进行检查。如果系统中发现任何对象没有引用，则会收回其存储空间。

X++ 语言遵循 OOPS 概念，并且继承的概念与任何其他面向对象语言一样有效。它提供了一个巨大的优势，即在 Microsoft Dynamics AX 中某处对属性所做的更改应在 Microsoft Dynamics AX 中使用该对象的所有地方得到反映/继承。例如，如果数据库字段的显示属性从长度 10 改为长度 15 个字符，则在显示或使用该字段的所有窗体中都会发生变化。

用任何语言编写的语句在语法上可能是正确的，但这并不能保证它符合编程推荐的最佳实践。Dynamics AX 内置了一个名为 Dynamics AX Best Practice Check Tool 的工具。

### Dynamics AX 最佳实践检查工具

代码审查非常耗时，因为它需要将每个语句对照大量检查点进行审查。由于成本原因，手动对照如此大量的质量检查点审查代码几乎是不可能的。Dynamics AX 具有内置的代码扫描工具。它名为 Dynamics AX Best Practices Check tool 或 ABC 工具。它将代码对照超过 200 个检查点进行验证。

### Dynamics AX 层系统

Dynamics AX 提供了完全的灵活性来定制其各个方面（功能和图形用户界面等），并优雅地在其自己的容器即层中保留不同方所做的各种更改。

Dynamics AX 应用程序层是 Dynamics AX 应用程序源代码中的层级结构，确保您可以进行修改和添加，而不会干扰您所在层级以下的应用对象。

由于分层技术，Microsoft Dynamics AX 定制更容易构建和维护，该技术促进了不同合作伙伴在不同层中进行定制。您可以定制一个层中编码的功能，而不会影响其他层中编码的功能。这意味着您可以随着时间的推移以较少的业务中断、风险和费用（即更低的风险、更高的适应性和更低的 TCO）来适应和升级您的解决方案。例如，您可以选择向标准窗体添加一个字段。添加内容将保存在您当前的层级中；修订后的窗体将替换标准窗体，但您只需删除新窗体即可始终返回到您所在层级以下层级的原始窗体，因此您可以以最小的业务中断风险工作，因为您可以始终使用已正常工作的功能。

| USR (User) | End users | - 个人公司或企业内的公司可以利用此层进行特定于客户安装的定制。 |

### Dynamics AX 简介

除了这些主要应用程序层之外，还有补丁层，可以通过层名称末尾使用字母 P 与其他应用程序层区分开来。层为：SYP、GLP、DIP、LIP、BUP、VAP、CUP 和 USP。补丁层的使用不受任何预定义的 MBS 规则限制，因此可以以任何合适的方式用于支持客户/业务合作伙伴。此过程提供了在不干扰现有层的情况下发送更正的选项。

所有应用程序层都能够使用 Dynamics AX MorphX 开发套件中提供的所有工具以及所有对象类型、表、类、宏、扩展数据类型、窗体、报表等。联机帮助也包含在层技术中，以及标签系统的使用。

在每个应用程序层中都提供所有对象类型，使得应用程序层技术非常灵活和动态。

### Dynamics AX 定制文件

每个层在技术上都保存在一个单独的文件中，称为 `Ax<layer>.aod`，例如 SYS 层的 `Axsys.aod`，DIS 层的 `Axdis.aod`，等等。`.aod` 扩展名是 Application Object Data 文件的缩写。文件存储在 `Appl` 下的 `Dynamics AX Standard` 文件夹中。

除了 `Ax<layer>.aod` 之外，还有一些其他文件保存层的不同类型数据，如下表所述。

| 序号 | 命名约定 | 描述 |
|---|---|---|
| 1 | Axapd.aoi | - aoi 代表“应用程序对象索引”。<br>- 它告诉 Dynamics AX 在哪里找到每个单独的对象。<br>- 在任何定制后下次登录 Dynamics AX 时，该文件将被重建。 |
| 2 | ax<layer><language>.ald | - ald 代表“应用程序标签数据”。<br>- 每个层中每种语言的单独文件。 |
| 3 | ax<layer><language>.alc | - alc 代表“应用程序标签注释”。<br>- 每个层中每种语言的单独文件。 |
| 4 | ax<layer><language>.ali | - ali 代表“应用程序标签索引”。 |

需要注意的是，在直接复制、删除等上述文件时，不应有任何用户连接。
