在某些情况下，我们可能需要隐藏某些代码片段中的错误或整个代码中一种或多种最佳实践偏差类型。这可以通过以下两种方式完成：

- “BP Deviation documented” 注释可用于阻止某段代码的最佳实践警告。需要注意的是，这仍然会显示最佳实践偏差，但不会作为警告显示；它将作为信息显示。此注释与普通注释一样，应按如下方式编写：
  `// BP Deviation Documented`
- 上述方法的缺点是错误消息仍作为信息显示，即仅抑制了严重性。另一种完全抑制最佳实践偏差的方法是使用 SysBPCheckIgnore 宏。以下是使用 SysBPCheckIgnore 宏的流程：
  1. 对于每个错误代码和 AOT 位置的组合，添加以下代码行
     ```
     C+= [#BP Error Code, @"AOTLocation"]
     ```
     其中 `BPErrorCode` 是 SysBPCheck 宏中列出的警告/错误的错误代码，而 `AOTLocation` 是 AOT 中应抑制其最佳实践偏差的对象的所在位置。
  2. 编译 SysBPCheck 类。
  3. 重启 Dynamics AX。

## 比较工具

比较工具是 Dynamics AX 中代码审查最有用的工具之一。比较工具可用于三种不同的比较：

- 两个不同层中的同一应用程序对象
- 同一对象的两个版本（如果使用版本控制）
- 两个不同的应用程序对象
- 导入 XPO 中的代码与 AOT 层中的相同对象

在每种情况下，比较结果都显示在“比较表单”中。以下表格解释了“比较表单”。

| 符号/图标/颜色/背景 | 说明 |
|---|---|
| 带勾选标记的阴影框 | 当前节点的子节点存在差异。 |
| 红色和蓝色图标 | 当前节点内部存在差异。 |
| 黑色文本 | 当前代码行或属性或控件中两个对象之间不存在差异。 |
| 红色或蓝色图标或文本 | 当前代码行、属性或控件仅属于其中一个对象。 |
| 阴影背景 | 当前代码行或属性中两个对象之间存在差异。 |
| 浅灰色背景 | 相同的代码行出现在两个对象中，但位置不同。 |

### 比较类型

比较工具可以按前面提到的三种不同方式使用。现在我们将讨论所有三种比较方式。

### 两个不同层中的同一应用程序对象

这是为了比较在引用层中不存在的对象，或在两个层中都存在但在两个层中不同的对象。需要注意的是，如果引用层位于源层下方，则比较将在源层中的对象与引用层中的对象以及引用层下方的层中的对象之间进行。以下表格解释了图形用户界面中使用的术语：

| GUI 术语 | 说明 |
|---|---|
| 项目名称 | 在比较层过程中将创建的项目的名称 |
| 源层 | 该层用作比较的基础。如前所述，结果项目永远不能包含源层中未包含的对象。 |
| 引用层 | 与源层进行比较的层。 |

> 可以选择“OLD SYS”作为引用层，以了解新版本中哪些对象已被更改。

比较两个不同层中同一应用程序对象的步骤：

1. 单击 **工具 | 开发工具 | 版本更新 | 比较层**。
2. 输入项目名称，选择源层和引用层，然后单击 **确定**。
3. 现在已创建包含不同的应用程序对象的项目。转到该项目（您在上一步中输入的名称）。
4. 使用“Add-ins”快捷菜单上的“Compare”命令比较单个对象。
   若要查看每个对象所属层的名称，请转到 **工具 | 选项 | 开发选项卡**，然后选择 **显示所有层**。
5. 在“比较表单”中查看比较结果

### 同一对象的两个版本

仅当使用版本控制系统时，才能在同一层中比较同一对象的两个版本。

1. 转到 AOT，右键单击对象，然后单击 **Add-Ins | Compare**。
2. 选择要比较的两个版本，然后单击 **Compare**。
3. 再次单击 **Compare**。
4. 在 **比较表单** 中查看比较结果。

### 两个不同的应用程序对象

以下是比较 AOT 中两个不同应用程序对象的过程：

1. 在 AOT 中选择对象。
2. 右键单击并单击 **Add-Ins | Compare**。
3. 再次单击 **Compare**。
4. 在 **比较表单** 中查看比较结果。

## 代码分析器

代码分析器是在运行时跟踪代码执行历史的工具。代码分析器可用于以下用途：

- 测量每行、方法、对象等的执行时间
- 单元测试期间的代码覆盖率分析
- 识别性能瓶颈

代码分析器不仅可以通过图形用户界面调用，还可以通过 X++ 代码调用。我们将不讨论通过 X++ 调用它。使用代码分析器包括两个阶段：

- 收集数据
- 查看/分析数据

### 收集数据

为了收集执行数据，需要调用代码分析器，然后用户应遍历每个正在审查的功能/功能。应遵循以下步骤：

1. 通过转到 **工具 | 开发工具 | 代码分析器** 打开代码分析器工具。
2. 通过选中 **Trace Depth Enabled** 复选框并选择层级数来限制检查深度。
3. 在应用程序中导航至测试应开始的位置。
4. 在代码分析器窗口中单击 **Start**。
5. 在不同条件下使用功能，以确保每行代码至少执行一次。
6. 当所有待测试功能都已使用后，在代码分析器窗口中单击 **Stop** 按钮。
7. 在 **Summary** 对话框中编写代码分析的描述（供参考）。
8. 单击 **OK** 按钮，并在打开“Profiler runs”表单以查看数据时开始查看/分析数据的第二阶段。

> 不要选中 **Calculate line total** 复选框。

### 查看/分析数据

特定运行的数据视图可能具有不同的目标，例如性能分析、代码覆盖率分析等。代码分析器有四种不同的表单以不同格式查看数据。

每个表单都以 Ticks 显示时间计数。要将这些数据计算为毫秒或秒等任何单位，请将数据乘以“Profiler run”表单上提供的“Ticks/second”。

### 调用树表单

在此表单中，行按执行的相同顺序显示，第一个执行的行在顶部。这有助于理解表单中的流程和各种触发器。在此表单中，系统方法只有在从应用程序调用时才会出现。

### 配置文件行表单

此表单根据执行时间显示“All executed”行，执行时间最长的行在顶部。此表单也可用于查看给定测试用例集的代码覆盖率。
