
如果安装的应用程序具有独立的数据库，则必须在文档中提供数据备份和数据恢复流程。

## 可扩展性和定制

Dynamics AX 具有内置的 AOT 文档系统，其中提到了成功定制应用程序的注意事项。在 AOT 文档中，每个 AOT 元素（如表、窗体等）都对应一个节点。如果对现有元素进行定制，则必须更新相应的节点；但如果创建了新的 AOT 元素，则应在 AOT 文档中新增一个节点。

## 集成点的文档

Dynamics AX 集成点应至少涵盖以下信息；不过，强烈鼓励提供更多信息。

## 数据库升级脚本

由于 Dynamics AX 需要数据升级脚本来处理数据升级，每当进行任何更改（如发布新版本、服务包或热修复）时，如果数据模型结构需要更改，则应提供升级脚本。

## DLL 和 ActiveX 控件的文件版本控制

所有可执行文件（例如 DLL 和 ActiveX 控件文件）都应具有关联的版本元数据。这将有助于升级以及服务包或热修复的应用程序。任何升级、服务包或热修复的安装程序都会检查这些文件的所需版本是否已到位。只有在找到所需的一切后，它才会继续安装。如果未关联版本元数据，则可能出现安装故障的情况。元数据必须包含供应商公司信息，以便如果该文件出现任何类型的损坏，客户可以识别公司名称并联系以进行回归。

## 所有修改对象的描述

Dynamics AX 可以生成所有修改对象的列表。应为版本中修改的所有对象提供详细描述。描述必须包括更改如何影响应用程序。

需要注意的是，详细描述仅适用于修改的对象，而不适用于新对象或在先前版本中已定制的未更改对象。

## 删除非功能代码

应从代码库中删除任何非功能代码，因为非功能代码在理解代码以进行进一步定制或支持时可能会带来困难。

## 最佳实践—技术

完成本章后，您将了解各种编码和设计最佳实践背后的基础知识。在本章中，我们将讨论一些最重要的最佳实践。

第 1 章中讨论的理想 ERP 系统的大多数质量都是通过符合本章中讨论的技术最佳实践来实现的。Dynamics AX 最佳实践可以分为三个类别，即应用程序设计标准、共享标准和 AOT 对象标准。

## 应用程序设计标准

Dynamics AX 设计标准包括以下考虑因素：

- 代码放置
- 性能优化
- 在表中使用字段组
- 自动属性设置

## 代码放置

代码放置很重要，因为它会影响以下方面：

- 性能
- 定制
- 可重用性
- 可维护性（升级、可扩展性等）

一般指导原则是，代码应放置在尽量减少对其他层的各种调用、操作在成本最低的层执行，并且无需在多个地方编写相同代码的方式（例如，如果业务逻辑写入窗体，则也需要在 Web 客户端的企业门户中编写）。因此，我们不仅应考虑三层架构中的放置层，还应考虑代码片段的最佳 AOT（应用程序对象树）元素类型。设计完成后，我们需要考虑类中的方法和对象类型等。

## 三层架构考虑

该架构中的三个层专用于以下三种类型的工作：

- **Client**—表示层—窗体存储在此处。将客户端特定的类和方法放置在此处。
- **Object server**—业务应用程序逻辑层—应在此处、靠近数据库运行面向事务的数据库更新作业。
- **Database server**—数据库层—通过使用聚合函数、连接和其他数据库管理系统的计算功能来利用数据库服务器的强大功能。

Dynamics AX 为每个 AOT 元素都有一个属性 RunOn，表示应在哪一层执行，即 Client、AOS 或 Database server。此 RunOn 属性可能具有三个值之一，即 Client、Called from 和 Server。

Client: 对象将驻留在客户端。

Called from: 对象将驻留在使用 'new' 构造函数创建对象的层。

Server: 对象将驻留在服务器上。

现在我们将讨论如何确定 RunOn 属性值。

## 类

类的 RunOn 属性值将决定从该类创建的对象的所在位置。

- 如果父类具有除 Called from 之外的 RunOn 属性，则类的 RunOn 属性值将与父类相同，即如果父类的值为 Client 或 Server，则不能更改类的 RunOn 属性。
- 如果父类的 RunOn 属性值为 `Called from`，则可以将其更改为 `Client` 或 `Server`，如果未更改，则将保留继承的值，即 `Called from`。
- RunOn 属性的 `Called from` 值意味着对象将驻留在创建它的代码（通过调用 new 构造函数）运行的层。

## 方法

现在我们将讨论各种类型方法的执行位置。

- 类静态方法和表方法（数据库方法除外）可以具有其默认行为。
- 可以通过在方法声明中添加 `Client` 或 `Server` 修饰符关键字将方法的执行位置更改为 `Server` 或 `Client`，如下所示：
  - `server static boolean mymethod()`：使服务器成为执行位置。
  - `client static boolean mymethod()`：使客户端成为执行位置。
  - `client server static boolean mymethod()`：使 called from 成为执行位置。

下表总结了各种类型方法的执行位置：

| AOT 元素 | 默认行为 | 可以更改 |
|---|---|---|
| 类静态方法 | 默认情况下在与关联类相同的地点运行，即如果关联类的 RunOn 属性值为 `server`，则类静态方法也将在服务器上执行。 | 是 |
| 类实例方法 | 在类的对象所在位置运行。类对象按类 RunOn 属性所述驻留。 | 否 |
| 表静态方法 | 表静态方法具有 RunOn 属性为 `Called from`，因此默认情况下它们在被调用的位置运行。 | 是 |
| 表实例方法 | 表实例方法具有 RunOn 属性为 `Called from`，因此默认情况下它们在被调用的位置运行。标准方法 Insert/doInsert、Update/doUpdate 和 Delete/doDelete 在数据源所在位置的 `Server` 上运行。 | 否 |
