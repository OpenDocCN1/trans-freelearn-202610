
- 缺陷管理工具必须能够记录 bug 的原因，并且选项必须包括以下内容：
  - 不是安全漏洞
  - 缓冲区溢出或下溢
  - 算术错误（例如，整数溢出）
  - SQL/脚本注入
  - 目录遍历
  - 竞态条件
  - 跨站脚本
  - 加密弱点
  - 弱认证
  - 弱授权或不当的访问控制列表
  - 无效的密钥隐藏
  - 无限资源消耗（DoS）
  - 不正确/无错误消息
  - 不正确/无路径名
  - 规范化
  - 其他
- 缺陷管理工具应能够接受以下其中一个值作为解决方式：
  - 不采取行动
  - 将所有内容告知客户
  - 禁用或移除该功能
  - 修复它

## 缺陷生命周期

缺陷生命周期应基于项目的定制需求以及项目中使用的通信方法。关闭类别应具有充足的选项，以便可以轻松记录关闭 bug 的原因。可能的已关闭类别可能包括以下内容：

- 不是问题
- 无法重现
- 需求已更改
- 与此代码段无关
- 已验证
- 重复
- 不可重现
- 按设计
- 已推迟
- 已撤回
- 无需操作

如此广泛的已关闭类别列表将有助于识别已关闭问题如何达到关闭阶段。

## 9 Dynamics AX 工具

由于定制过程中存在特殊性，市场上大多数标准工具除非付出很大努力将其适配到 Dynamics AX 的需求，否则无法使用。幸运的是，Dynamics AX 提供了一些有用的工具：

- 用于代码分析或扫描的最佳实践检查工具
- 用于扫描代码更改的比较工具
- 用于代码覆盖率分析和性能分析的代码分析器
- 用于基准测试的基准套件

## 最佳实践检查工具

Dynamics AX 最佳实践检查工具可用于检查代码和对象是否符合 Dynamics AX 的最佳实践。此工具可以在三种不同的方式下使用：在编译时（仅当诊断级别设置为第 4 级时）、在签入时，以及在任何时间手动使用。

要将诊断级别设置为第 4 级，请转到 Tools | Options | Compiler 并将 Diagnostics level 的值设置为 Level 4。

要手动调用此工具，请转到 AOT 中的一个或多个节点，然后：

1. 右键单击。
2. 选择 Add-Ins。
3. 选择 Check Best Practices。

双击最佳实践偏差消息将打开代码编辑器。
这些消息为：

- 错误：应该一定修复的事情（在最佳实践工具输出中以红色显示）
- 警告：应该强烈考虑修复的事情（在最佳实践工具输出中以黄色显示）
- 信息：可能值得知道的事情（在最佳实践工具输出中以蓝色显示）

类别信息可以从最佳实践选项表单中控制。此表单可以从工具菜单访问。单击工具菜单中的 **Options**，然后单击 **Best Practices**。

选择 **Warning level** 以设置您希望在编译器输出窗口中看到的错误消息类型。编译器输出窗口将有三个选项 – **Errors only**、**Errors and warnings** 和 **All**。以下表格描述了这三个选项：

| 选项 | 错误 | 警告 | 信息 |
|---|---|---|---|
| 仅错误 | 是 | 否 | 否 |
| 错误和警告 | 是 | 是 | 否 |
| 全部 | 是 | 是 | 是 |
