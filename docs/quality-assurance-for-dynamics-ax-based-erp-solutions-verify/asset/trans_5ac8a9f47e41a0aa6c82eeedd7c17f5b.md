
## 最佳实践 – GUI

下表总结了用户帮助的检查点：

| 序号 | 检查点 | 预期结果 |
|---|---|---|
| 1.1 | 给定的表单帮助是否解释了表单的整体目的？ | 是 |
| 1.2 | 是否有任何表单帮助未解释如何使用表单以及其使用如何影响系统的其余部分？ | 否 |
| 2 | 是否有任何没有表单帮助的表单？ | 否 |
| 3.1 | 是否有任何没有标题的表单帮助？ | 否 |
| 3.2 | 是否有任何表单标题不包含相关的表单名称？ | 否 |
| 3.3 | 是否有任何提及的表单帮助不符合标准格式？ | 否 |
| 4.1 | 是否有任何帮助部分的标题缺失？ | 否 |
| 4.2 | 帮助中标题的格式与 Dynamics AX 风格一致。 | 是 |
| 5.1 | 表单中是否有任何文本未分为简短的段落？ | 否 |
| 5.2 | 是否有任何段落超过八行？ | 否 |
| 5.3 | 文本和子标题是否符合 Dynamics AX 标准？ | 是 |
| 6 | 是否有任何表单按钮帮助未解释该表单按钮的目的？ | 否 |
| 7 | 是否有任何表单按钮帮助未解释如何启用或禁用控件（文本框、按钮等）？ | 否 |
| 8.1 | 相关表单帮助的链接是否有效？ | 是 |
| 8.2 | 所有链接是否都放在标题 **附加信息** 下。 | 是 |
| 9 | 是否有任何帮助中未提供链接 **创建或删除** | 否 |
| 10 | 每个屏幕提示是否回答了用户的问题？（“这是什么？”和“为什么我应该使用它？”） | 是 |
| 11.1 | 是否有任何屏幕提示消息不是由标签直接指示的？ | 否 |
| 11.2 | 帮助中是否有任何标签重复（即使词语顺序已更改） | 否 |
| 12 | 是否为每个文本框、下拉框和表中的每个项目提供了屏幕提示？<br><br>注意：复选框和单选按钮不需要屏幕提示。 | 是 |
| 13.1 | 所有屏幕提示必须简要说明。是否有任何屏幕提示忽略了此标准？ | 否 |
| 13.2 | 是否有任何带标题的屏幕提示？ | 否 |
| 13.3 | 所有短语和重要词语是否以粗体显示？ | 是 |
| 13.4 | 是否有任何链接未提供相关的 Dynamics AX 窗口？ | 否 |
| 13.5 | 链接（如果存在）是否采用 Dynamics AX 格式？ | 是 |
| 14 | 是否为每个下拉框定义了帮助，为下拉框中的每个成员提供信息？<br><br>注意：此标准仅适用于具有固定数量项目的下拉框。 | 是 |
| 15 | 每个工具提示是否回答了用户的问题？（“这是什么？”和“为什么我应该使用它？”） | 是 |
| 16 | 每个工具提示是否简要说明了工具的使用（最多两行）？ | 是 |
| 17 | 是否有任何命令按钮未提供工具提示？<br><br>注意：带子菜单和子菜单项的命令按钮不需要工具提示。 | 否 |
| 18 | 工具提示格式是否符合 Dynamics AX 标准？ | 是 |
| 19 | 是否有任何状态栏消息未回答用户的问题？（即这是什么？为什么我应该使用它？） | 否 |
| 20 | 显式帮助是否符合 Dynamics AX 标准？ | 是 |

## 消息

消息的用户界面标准确保消息正确分类为三个类别之一（即错误、警告和信息），并且消息的措辞方式使用户能够从消息本身了解需要采取什么措施来解决错误情况。

| 序号 | 检查点 | 预期结果 |
|---|---|---|
| 1 | 是否有任何消息根据 Windows 用户体验（WUE）规则被错误分类为严重、警告或信息？ | 否 |
| 2 | 是否使用了除以下提及之外的其他符号来显示以下列出的消息？<br>严重消息<br>警告消息<br>信息消息 | 否 |
| 3.1 | 是否有任何属于严重或警告类别的消息未描述如何解决问题？ | 否 |
| 3.2 | 是否有任何属于严重或警告类别的消息措辞不具建设性？ | 否 |
| 4 | 是否有任何典型用户无法理解的消息？ | 否 |
| 5 | 是否有任何信息性消息具有除 OK 之外的按钮？ | 否 |
| 6.1 | 是否有任何消息框包含明确表述的问题但没有“是”和“否”按钮？ | 否 |
| 6.2 | 是否有任何消息框未提问但具有“是”和“否”按钮？ | 否 |
| 7 | 不得使用常规确认消息。确认消息可为用户认为严重的交易提供，例如更改密码或删除账户。是否有任何实例未遵循此规则？ | 否 |

## 用户帮助—向导

向导使许多流程变得非常简单。只有在向导经过精心设计时才有可能。以下向导的用户界面规范有助于实现上述目标，因此每个向导必须遵守以下规范：

| 序号 | 检查点 | 预期结果 |
|---|---|---|
| 1.1 | 是否有任何没有欢迎页面的向导？ | 否 |
| 1.2 | 是否有任何没有一个或多个内部页面的向导？ | 否 |
| 1.3 | 是否有任何没有成功完成页面的向导？ | 否 |
| 2.1 | 是否有任何欢迎页面未解释向导的目的？ | 否 |
| 2.2 | 欢迎页面上是否有任何控件？ | 否 |
| 3 | 向导页面必须分为三个部分：欢迎页面、内部页面和成功完成页面。内部页面可能以“标准”或类似“欢迎”和“成功完成页面”的“设置”形式出现。是否有任何向导未遵循此标准？ | 否 |
| 4.1 | 向导页面是否显示一致？ | 是 |
| 4.2 | 所有向导是否具有相同的样式？ | 是 |
| 4.3 | 向导中左侧的图形是否始终遵循相同的格式？ | 是 |
| 5.1 | 向导页面是否包含以下按钮？<br>- **后退**<br>- **下一步**<br>- **取消**<br><br>注意：**下一步**按钮在最后一页（完成页面）上不会出现。 | 是 |
| 5.2 | 按钮（**后退**、**下一步**和**取消**）是否对齐正确？ | 是 |
| 5.3 | 欢迎页面上**后退**按钮是否被禁用？ | 是 |
| 5.4 | 向导完成后**下一步**按钮是否被**完成**按钮替换？ | 是 |
| 6 | 是否有除本表检查点 5.1 中提及之外的任何按钮？ | 否 |
| 7 | 在用户在内部页面输入必填信息之前，**下一步**按钮必须保持禁用。向导的任何页面是否忽略了此标准？ | 否 |
| 8.1 | 所有向导页面是否使用清晰的语言编写？ | 是 |
| 8.2 | 所有向导页面是否包含有限的文本量？ | 是 |
| 8.3 | 每个向导页面是否只询问完成当前任务所需的信息？ | 是 |
| 9 | 向导是否在新窗口中打开？ | 否 |
| 10 | 向导在任何页面上是否包含超过三个窗口控件（除命令按钮外：**下一步/完成**、**后退**和**取消**）？ | 否 |
| 11.1 | 向导是否从以下可见控件之一打开：<br>- 一个标记为 **向导** 的按钮<br>- 主菜单中的 **表单** 图标<br><br>注意：如果提供理由，可忽略此检查点。 | 是 |
| 11.2 | 用户按下 *CTRL+N* 时向导是否启动？<br><br>注意：如果提供理由，可忽略此检查点。 | 否 |
| 12 | 向导页面是否包含默认值或设置？<br><br>注意：如果提供理由，可忽略此检查点。 | 是 |

## 企业门户

企业门户便于远程用户（例如销售或营销人员）通过互联网访问 Dynamics AX 功能。以下是企业门户使用的用户界面规范。

| 序号 | 检查点 | 预期结果 |
|---|---|---|
| 1 | 网站应在启用标准按钮和地址工具栏的 1024 x 768 像素屏幕大小的浏览器中清晰可见。是否有任何网站忽略了此标准？ | 否 |
| 2 | 所有顶级网页（如主页和活动中心）应具有图标和标题。是否有任何网页忽略了此标准？ | 否 |
| 3 | 在活动中心页面上，标题必须与顶部菜单上的相应名称匹配。例如，采购活动中心页面的标题在页面和菜单上都必须是 Purchase。是否有任何活动中心页面忽略了此标准？ | 否 |
| 4 | 非顶级页面的网页顶部不应使用图标或标题。这些页面的标题必须为蓝色。是否有任何网页忽略了此标准？ | 否 |
| 5 | 除主页或活动中心外，每个网页必须只使用一个表单。是否有任何网页忽略了此标准？ | 否 |
| 6 | 活动中心页面必须包含一个表单，通常是列表，以及从列表中选择任务的说明。例如，在销售活动页面上，您应具有选择销售任务（或类似说明）的说明以及销售任务列表。是否有任何活动中心页面忽略了此标准？ | 否 |
| 7 | 确保活动页面上的说明具有帮助性和指导性。例如，输入名称的说明没有帮助，而选择客户并输入项目编号和数量以计算价格的说明是有帮助的。是否有任何活动中心页面忽略了此标准？ | 否 |
| 8 | 所有字段必须按组组织。是否存在偏离此标准的现象？ | 否 |
| 9 | 如果网站可见性要求允许，则用户必须使用标准控件添加或删除网格线。是否有任何网站忽略了此标准？ | 否 |
