# # How to do it...

+   1. Jenkins stable and more recent versions are available in a YUM repository. Following is a table that provides details for configuration of Agents:

| Configuration | Details |
|---|---|
| # of executors | • Here, we can specify the number of concurrent builds that Jenkins may execute on this agent node.<br>• Agents must have at least one executor, and in case we don't want any execution, then we can configure this setting as 0. |
| Remote root directory | • An agent node requires us to have a directory dedicated to Jenkins. Specify the path to this directory on the agent.<br>• Use an absolute path only. All job configurations, build logs, and artifacts are stored on the master.<br>• Workspace is available on the agent node. |
| Labels | • Labels or tags can be utilized to group multiple agent nodes into a logical collection.<br>• The best thing is that we can use this mechanism as a pool of resources to execute build jobs in Jenkins.<br>• For example, we have multiple agents where a test infrastructure is set up. We have two or three projects whose automated testing is done by the QA team.<br>• In such a scenario, we can provide the same Test label or tag it to all agent nodes where the test infrastructure is available and then assign the same Test label to those projects.<br>• What this does is execute the build jobs on any one of the Test agents with the Test label and not without it. |
| Usage | • This setting controls how Jenkins schedules builds on specific agent nodes.<br>• Use this node as much as possible: This is the default setting where, most of the time, the Agent node will be utilized for job execution.<br>• Only build jobs with label expressions matching this node: with this setting, Jenkins will execute a build on this agent node when the project is configured to execute on this node with a label expression. |
| Launch method | • This setting controls how Jenkins starts a specific agent node.<br>• Launch agent via Java Web Start: Allows an agent to be launched using Java Web Start.<br>• Launch agent via execution of command on the master by remotely executing a process on another machine, for example, via SSH or RSH.<br>• Launch slave agents via SSH by sending commands over a secure SSH connection. |
