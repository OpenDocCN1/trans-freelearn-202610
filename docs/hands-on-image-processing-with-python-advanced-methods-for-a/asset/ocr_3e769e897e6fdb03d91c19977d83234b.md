Let’s explore these concepts:

+   - First, let’s understand the `mode` argument and its possible values, for the convolution of an *M × N* input image with a *m × n* kernel:
+     - `mode='full'`: This is the default mode, in which the output is the full discrete linear convolution of the input. It returns the full 2D convolution, including all border effects.
+     - Output shape: *(M + m − 1, N + n − 1)*.
+     - `mode='valid'`: This ignores edge pixels and only computes for those pixels with all neighbors (pixels that do not need zero-padding). The output image size is less than the input image size for all kernels (except 1 × 1). It returns only those parts of the convolution that are computed without zero-padding. Output size: *(M − m + 1, N − n + 1)*, assuming *M ≥ m* and *N ≥ n*.
+     - `mode='same'`: The output image has the same size as the input image; it is centered with regards to the `'full'` output. It returns the central part of the convolution that is the same size as the first input. Output shape: *(M, N)*.

+   - The `boundary` argument is a flag indicating how to handle image boundaries. The parameter controls how the image is extended at the borders during convolution. Possible values are as follows:
+     - `fill`: Pad input arrays with `fillvalue` (default 0). Use when edge information beyond the original image is not required.
+     - `wrap`: Circular boundary conditions, values on the left *wrap* to the right, and top and bottom, and vice versa. Use when working with periodic or cyclic data (e.g., textures that tile). You want continuity at the borders, such as for some Fourier-based applications.
