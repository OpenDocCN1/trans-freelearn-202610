## Derivative-based multiscale enhancement

Derivative-based operators, such as the Laplacian, capture high-frequency details that are essential for sharpening and enhancement. Extending this idea, image pyramids, particularly Gaussian and Laplacian pyramids, enable derivative-based enhancement across multiple spatial scales, offering fine control over both coarse and fine details.

### Gaussian pyramid: the multiscale foundation

A Gaussian pyramid represents an image at progressively lower resolutions, created by iteratively smoothing (with a Gaussian filter) and downsampling. Each level contains the image's low-frequency content (coarse structures). Formally, if G₀ is the original image:

Gᵢ₊₁ = (GaussianBlur(Gᵢ))↓₂

This structure allows selective enhancement at specific scales or as a pre-step for derivative operations.

```
# Import the Gaussian pyramid generator function
from skimage.transform import pyramid_gaussian
image = imread('images/lena.jpg')
# Create a Gaussian pyramid by successively blurring and downscaling image.
# 'downscale=2' means each level is 1/2 the width and height of previous one.
# 'channel_axis=-1' means the color channels are in the last dimension.
pyramid = tuple(pyramid_gaussian(image, downscale=2, channel_axis=-1))
# Loop over all pyramid levels and display each one
for i, p in enumerate(pyramid): # Create a subplot for each pyramid level
    plt.subplot(1, len(pyramid), i + 1), plt.imshow(p), plt.axis('off')
    plt.suptitle('Gaussian Pyramid')
```

### Laplacian pyramid: derivative representation across scales

A Laplacian pyramid can be viewed as a multiscale version of the Laplacian operator. Each level stores the difference between an image and its smoothed (expanded) version, effectively encoding the image's band-pass or detail information:

$L_i = G_i - \text{expand}(G_{i+1})$

Thus, the Laplacian pyramid decomposes the image into its high-frequency derivatives at multiple resolutions, ideal for enhancement and reconstruction.

```
from skimage.transform import pyramid_laplacian
def minmax_norm(img):
    # Perform min-max normalization on the image
    # Formula: (img - min) / (max - min)
    # This rescales pixel values to the range [0, 1]
    # Avoid division by zero, if max == min return the image unchanged
    return (img - img.min()) / (img.max() - img.min()) \
        if img.max() > img.min() else img

# Construct the Laplacian pyramid with a downscale factor of 2
pyramid = tuple(pyramid_laplacian(image, downscale=2, channel_axis=-1))
# Display each level of the Laplacian pyramid
i, n = 1, len(pyramid)
for p in pyramid:
    p = minmax_norm(rgb2gray(p)) # convert each level to grayscale & normalize
```

### Application: multiscale blending and enhancement

By blending Laplacian components of two images using a Gaussian-weighted mask, smooth, natural transitions can be achieved across scales, useful for exposure fusion and panorama blending. The process works because derivatives (Laplacian layers) are combined seamlessly before reconstruction.

Laplacian pyramids extend derivative-based enhancement into a multiscale domain, decomposing an image into coarse and fine derivatives that can be selectively enhanced or recombined. This approach forms the theoretical bridge between classical derivative-based sharpening and modern multiscale enhancement techniques used in HDR imaging, fusion, and edge-aware processing.

### Pyramid-based image blending

A classic application of pyramids is **seamless image blending**, e.g., combining an apple and an orange. Given two images (A) and (B) and a binary mask (M), we form Laplacian pyramids ($L_A$, $L_B$) and a Gaussian pyramid ($G_M$). At each level:

$L_C^i = G_M^i L_A^i + (1 - G_M^i)L_B^i$

## Choosing the right edge detector

A recurring challenge in edge detection is not implementation, but selection. Different operators respond to different image characteristics such as noise level, structural geometry (edges vs blobs vs ridges), and computational constraints. The following table provides a practical mapping from scenario to method, enabling informed decision-making:

| Scenario | Recommended method(s) | Rationale |
|---|---|---|
| Low-noise images, quick results | Sobel, Prewitt | Fast first-order gradients suffice |
| Noisy images | Canny, LoG | Built-in smoothing reduces noise sensitivity |
| Thin, well-localized edges required | Canny | Non-maximum suppression produces crisp edges |
| Blob-like structures (spots, lesions) | Hessian (DoH) | Detects structures with curvature in all directions |
| Tubular/curvilinear structures (vessels, roads) | Ridge (Frangi) | Eigenvalue analysis captures line-like patterns |
| Multi-scale edge detection | LoG, DoG | Scale-space formulation captures varying edge sizes |
| Directional edge emphasis | Kirsch | Sensitive to specific orientations |
| Real-time/low-compute environments | Sobel, PiDiNet | Lightweight and efficient |
| Complex natural scenes (semantic boundaries) | HED | Learns object-level edges |
| GPU available, high accuracy needed | HED | Deep multi-scale representation |
| Edge devices/mobile deployment | PiDiNet | Optimized for efficiency |

Table 8.4 - Choosing the right edge detector

Here’s a practical decision flow:

- If you need a quick baseline, start with Canny
- If edges are noisy, prefer Canny or LoG
- If detecting blobs (spots, lesions), use Hessian (DoH)
- If detecting vessels, cracks, ridges, use Frangi
- If you need semantic understanding, use HED
- If you need real-time deep edges, use PiDiNet

Note that edge detectors differ fundamentally in what they consider an “edge”:

- Gradient-based (Sobel, Canny): intensity discontinuity
- Second-order (LoG, DoH): curvature and zero-crossings
- Hessian-based ridge (Frangi): directional anisotropy
- Learning-based (HED, PiDiNet): data-driven boundary understanding
