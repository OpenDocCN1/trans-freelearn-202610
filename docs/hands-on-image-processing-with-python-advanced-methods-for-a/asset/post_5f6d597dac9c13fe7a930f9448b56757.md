
- **3. Second Normalization:**  
  $\hat{Z}_l = \operatorname{LayerNorm}(Z'_l)$,  
  this prepares the features for non-linear transformation.

- **4. Feed Forward Network (FFN) + Residual:**  
  $\operatorname{FFN}(x) = W_2\sigma(W_1x)$,  
  $Z_{l+1} = Z'_l + \operatorname{FFN}(\hat{Z}_l)$

The FFN operates independently on each token. It introduces non-linearity and feature transformation. The complete transformer layer can be summarized as:

*Layer = Normalization → Attention → Residual → Normalization → FFN → Residual*

The next figure (full transformer layer diagram) illustrates this pipeline, where:

- **Input tokens** $Z_l$ (patch embeddings) enter the layer
- **Self-attention** allows each token to attend globally across the image → enabling **context aggregation and long-range dependencies**.
- **Residual connections** ensure stable training and preservation of original information.
- **Layer normalization** improves convergence and numerical stability
- **FFN (MLP)** refines features at each token location independently

**The output:** $Z_{l+1}$ is a **context-aware, globally enriched representation** of the input tokens.

After stacking $L$ such layers: $Z_0 \rightarrow Z_1 \rightarrow \cdots \rightarrow Z_L$, the final representation $Z_L$ is used for downstream tasks such as **semantic segmentation**, where it is reshaped and decoded into pixel-wise predictions.

![](img/ebc2ad05fd41bdb1531c3dba43fbf8d5_534_0.png)

*Figure 10.28 – Transformer block architecture*

**Computational Complexity:** $QK^T \in \mathbb{R}^{N\times N}$. Thus, time: $\mathcal{O}(N^2 d)$ and memory: $\mathcal{O}(N^2)$, so that high-resolution images $\rightarrow$ large $N$ $\rightarrow$ expensive computation. This motivates hierarchical transformers (**SegFormer**), efficient decoders (**DPT**), and query-based methods (**DETR**, **Mask2Former**).

**From Tokens to Dense Predictions: Decoder Heads for Segmentation:** After encoding:

$Z_L \in \mathbb{R}^{N\times D}$,

which is reshaped:

$Z_L \rightarrow \mathbb{R}^{H/P \times W/P \times D}$,

different architectures map tokens to pixel predictions differently (different segmentation models adopt different decoder strategies).

## Pure ViT dense prediction — SETR

Early work such as SEgmentation TRansformer (**SETR**) demonstrated that tokens can be directly mapped to segmentation: $\hat{Y} = \text{Upsample}(W Z_L)$, with no hierarchy and minimal decoder. **SETR** treats an image as a **sequence of patches** and performs **pixel-wise segmentation using a transformer encoder without convolutions**. It's a model with **Pure ViT + Linear Decoder:** Uses pure ViT encoder, reshapes tokens to spatial grid, applies *1x1 convolution* and *bilinear upsampling* to full resolution. This is equivalent to per-token classification followed by interpolation.

**Limitation:** Poor spatial detail, weak boundary localization and high computational cost. This motivates more advanced architectures.

## Multi-scale feature fusion with DPT

The **Dense Prediction Transformer (DPT)** is a *pure Vision Transformer (ViT)* architecture adapted for dense prediction tasks such as segmentation and depth estimation. Unlike standard ViT, DPT introduces **multi-scale feature fusion**, projecting tokens back to spatial grids. Here is the key insight: Global attention $\rightarrow$ captures **scene context**, and Multi-scale fusion $\rightarrow$ restores **fine spatial detail**. **DPT** extracts features from multiple layers:

$F = \text{Fusion}(F_1, F_2, F_3, F_4), \quad \hat{Y} = \text{Upsample}(F)$

where early layers $\rightarrow$ fine details, deep layers $\rightarrow$ semantics, and fusion $\rightarrow$ accurate segmentation.

The next code snippet loads a pretrained DPT model from Hugging Face, processes an input image, and performs **semantic segmentation** by predicting a class label for each pixel. **Upsampling:** The function `torch.nn.functional.interpolate()` performs:

$\hat{Y}(x,y) = \arg\max_c L_c(x,y)$

## Query-based prediction with DETR

**DETR** (DEtection TRansformer) treats an image like a *set of objects to discover*, not a grid of pixels. It uses a fixed number of learnable object queries—think of them as “slots” asking: *is there an object for me?* — and each query directly predicts a **class label, bounding box, and mask**. Instead of labeling pixels, the model asks: *“What objects exist?”*

During training, **Hungarian matching** assigns each predicted query to a real object (one-to-one), so the model learns to produce **unique, non-overlapping detections** without post-processing like NMS. For **panoptic segmentation**, DETR simply combines these object predictions (things) with background regions (stuff) to form a complete **scene understanding**.

DETR introduces object queries:

$Attention(Q_o, Z_L, Z_L)$

Each query predicts **object class** and **mask / region**. The **DETR** reformulates segmentation as a **set prediction problem**. Given object queries Q, DETR predicts:

$\hat{Y} = \{(c_i, b_i, m_i)\}_{i=1}^N$

where $c_i$: class label, $b_i$: bounding box and $m_i$: mask. Training uses:

- **Hungarian matching:**  
  $\mathcal{L} = \sum_{i=1}^N \mathcal{L}_{\mathrm{match}}(y_i, \hat{y}_{\sigma(i)})$

- **Panoptic segmentation:** DETR extends to panoptic segmentation:  
  $\text{Panoptic} = \text{Things} \cup \text{Stuff}$

The next code snippet loads a pretrained **DETR panoptic segmentation model** (it loads the pretrained model **facebook/detr-resnet-50-panoptic** with the function DetrForSegmentation.from_pretrained()) and applies it to an input image to **segment both objects (things) and background regions (stuff)** in a single pass. It preprocesses the image, runs inference, converts the predicted segmentation map into colored regions, and overlays it on the original image for visualization.

Intuitively, DETR uses **transformer-based object queries** to look at the whole image globally and directly predict segments for the entire scene, and the post-processing step converts these predictions into a **pixel-wise panoptic mask**, which is then colorized and overlaid on the original image for visualization. This produces **segmentation map** and **segments_info**. Unlike pixel-wise models **DETR outputs object-level masks**, hence no need for **NMS (Non-Max Suppression)**.
