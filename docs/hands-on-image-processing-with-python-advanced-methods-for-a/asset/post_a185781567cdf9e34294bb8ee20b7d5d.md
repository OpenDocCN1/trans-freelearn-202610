
# Comparing runtimes

The code block in this section applies **Gaussian blurring** to an image using two different convolution methods:

- signal.convolve2d() (spatial domain convolution)
- signal.fftconvolve() (frequency domain convolution using FFT)

It then measures and compares the execution time of these methods using a wrapper function and timeit.repeat(). Since the frequency domain convolution involves a single matrix multiplication instead of a series of sliding window arithmetic computations, it is expected to be much faster.

A wrapper function named wrapper_convolve() is defined, which does the following:

- Takes a convolution function (func) as input
- Returns another function (wrapped_convolve) that, when called, applies the convolution to the image

## Why use a wrapper?

The function timeit.repeat() requires callable functions without arguments.

The wrapper ensures that the convolution function can be passed to timeit without explicitly providing arguments.

Here’s the code snippet:

```
im = np.mean(plt.imread('images/mandrill.jpg'), axis=2)
# 2D Gaussian kernel of size 11x11 with σ = 3
gauss_kernel = np.outer(signal.windows.gaussian(11, 3), \
                    signal.windows.gaussian(11, 3))
im_blurred1 = signal.convolve2d(im, gauss_kernel, mode="same")
im_blurred2 = signal.fftconvolve(im, gauss_kernel, mode='same')

def wrapper_convolve(func):
    def wrapped_convolve():
        return func(im, gauss_kernel, mode="same")
    return wrapped_convolve

wrapped_convolve = wrapper_convolve(signal.convolve)
wrapped_fftconvolve = wrapper_convolve(signal.fftconvolve)
times1 = timeit.repeat(wrapped_convolve, number=1, repeat=100)
times2 = timeit.repeat(wrapped_fftconvolve, number=1, \
                    repeat=100)
# plot im, im_blurred1, im_blurred2
```

# 2D and 3D convolution with PyTorch

As discussed, convolution is one of the most fundamental operations in deep learning and image processing, allowing us to detect and filter features such as edges, textures, and other patterns. The main difference between 2D and 3D convolutions lies in their dimensionality and how they interact with image data. In this section, let us aim to understand the underlying concepts in depth, along with their mathematical formulations and practical code examples. Start with the next table, which summarizes 2D and 3D convolutions:

| Feature | 2D Convolution | 3D Convolution |
|---|---|---|
| Dimensions | Operates on height × width | Operates on height × width × depth |
| Channels | Channels processed independently | Channels processed jointly |
| Example Use Cases | Edge detection, texture analysis | Video frame filtering, MRI/CT volumetric analysis |
| Computational Cost | Lower | Higher |
| Captures | Spatial features | Spatial + depth/temporal features |

## 2D convolution

In 2D convolution, a kernel (filter) slides across an image to compute feature responses, producing an output given by:

$$Y(i, j) = \sum_{m=0}^{M-1} \sum_{n=0}^{N-1} X(i + m, j + n) \cdot K(m, n)$$

Where

- X is the input image
- K is the convolution kernel (or filter)
- M, N are the dimensions of the kernel

In the next python demonstration, PyTorch's torch.nn.functional.conv2d() applies vertical (VK) and horizontal (HK) Sobel-like kernels to a grayscale image to detect vertical and horizontal edges. The image is reshaped to PyTorch's required format NCHW, convolved with each filter, and the outputs are displayed side by side, highlighting edges in different orientations.

> Note:
> PyTorch expects input images in the format [batch_size, channels, height, width]. This is why the image tensor is reshaped using .reshape(1, 1, H, W) or permuted using .permute(2, 0, 1) for RGB images.

# 2D versus 3D convolution

2D convolution processes each image channel independently and is computationally efficient for tasks such as edge detection and filtering, whereas 3D convolution operates across both spatial dimensions and channel/depth dimensions simultaneously, capturing inter-channel or spatiotemporal relationships for applications such as RGB feature learning, video analysis, and medical imaging, at the cost of higher computation.

Transposed convolution is widely used for upsampling feature maps, enabling applications such as image super-resolution, image enlargement, semantic segmentation (restoring feature maps to the original image size for pixel-wise prediction), generative models such as GANs for high-resolution image synthesis, and autoencoder decoders for reconstructing images from compact latent representations.

**Upsampling** increases image size using fixed interpolation or value insertion, making it simple, fast, and computationally efficient, but unable to learn from data. In contrast, transposed convolution uses learnable filters to perform upsampling, allowing it to adapt to data and reconstruct finer details at the cost of higher computational complexity. Consequently, upsampling is preferred when speed and simplicity are important, whereas transposed convolution is better suited for applications requiring high-quality image reconstruction and learned feature generation.
