
During training, the objective minimizes reconstruction error:

$$\mathcal{L}_{depth} = \frac{1}{N} \sum_{i=1}^{N} |D_i - \widehat{D}_i|$$

or scale-invariant losses such as:

$$\mathcal{L}_{si} = \frac{1}{N} \sum_{i} d_i^2 - \frac{1}{N^2} \left(\sum_{i} d_i\right)^2$$

where $d_i = \log D_i - \log \widehat{D}_i$.

The input RGB image is preprocessed using DPTImageProcessor, passed through DPTForDepthEstimation, and the network predicts a dense depth map where brighter pixels typically represent closer regions and darker pixels represent farther regions.

The processor (DPTImageProcessor) handles normalization, resizing and tensor conversion. The model (DPTForDepthEstimation) performs transformer-based depth prediction. The model is moved to GPU for acceleration.

The get_depth() function handles the complete inference pipeline: converting the image into PyTorch tensors (return_tensors="pt"), moving tensors to GPU, running the transformer model without gradient computation (torch.no_grad()), resizing the predicted depth map back to the original image size using bicubic interpolation, and normalizing the depth values into the range ([0,1]) for visualization. ## Point cloud generation and 3D reconstruction

Once depth is estimated, the 2D image can be lifted into 3D space by back-projecting each pixel into camera space, where each pixel $(u, v)$ with depth $D(u, v)$ is converted into a 3D point using the inverse camera projection model. Concretely, assuming pinhole camera geometry, the depth value provides the missing scale needed to recover spatial coordinates: each pixel is first normalized with respect to the camera intrinsics (focal length and principal point), and then scaled by its depth to obtain $(X, Y, Z)$ in 3D space. This establishes a direct one-to-one mapping between image pixels and 3D points, forming the basis of a point cloud.

A point cloud is a set of 3D points:

$$P = \{(X_i, Y_i, Z_i)\}_{i=1}^{N}$$

Each point stores spatial coordinates and RGB color.

## Camera projection geometry

For an image pixel $(x, y)$ with depth $z = D(x, y)$, the 3D coordinates are:

$$X = \frac{(x-c_x)z}{f_x},\quad Y = \frac{(y-c_y)z}{f_y},\quad \text{and}\quad Z = z,$$

where $f_x, f_y$ = focal lengths and $c_x, c_y$ = optical center. These equations invert the camera projection model.

- **Generating the point cloud:** This function `depth_to_pointcloud()` iterates through image pixels, converts depth into 3D coordinates, stores RGB colors and constructs an Open3D point cloud.
- **Multi-view fusion:** Multiple views improve geometric coverage. The code processes a list of images given by `image_paths`. Each image produces a point cloud (pcd) with the function `depth_to_pointcloud()`, which needs an image and the corresponding depth map. The clouds are merged: `combined += pcd`
- **Voxel downsampling:** Performed with the method `voxel_down_sample()`, voxelization reduces redundancy and noise. Instead of millions of points, neighboring points are aggregated into voxel cells.
- **Normal estimation:** The method `estimate_normals()` computes the surface normals, approximate local geometry, and are essential for mesh reconstruction, rendering, lighting, and surface analysis.
- **Interactive 3D visualization:** As shown in the next code snippet, Open3D visualization is replaced with Plotly (so that it’s easy to run from a Colab notebook), using the following line of code: `o3d.visualization.draw_geometries = draw_geometries` (refer to GitHub). Plotly enables browser-based rendering, zooming, rotation, and interactive exploration.

The complete reconstruction pipeline becomes:

$I \rightarrow D \rightarrow P \rightarrow S,$

where $I$ = RGB image, $D$ = depth map, $P$ = point cloud, and $S$ = reconstructed scene. This bridges 2D vision and 3D geometry. Now, refer to the following code:

import open3d as o3d

def depth_to_pointcloud(color, depth):
    h, w = depth.shape
    fx, fy, cx, cy = w / 2, h / 2, 500, 500  # Camera intrinsics (approximate)
    points, colors = [], []
    for y in range(h):
        for x in range(w):
            z = depth[y, x]
            if z <= 0:
                continue
            X, Y = (x - cx) * z / fx, (y - cy) * z / fy
            points.append([X, Y, z])
            colors.append(color[y, x] / 255.0)
    pcd = o3d.geometry.PointCloud()
    pcd.points = o3d.utility.Vector3dVector(np.array(points))
    pcd.colors = o3d.utility.Vector3dVector(np.array(colors))
    return pcd

While point cloud generation reconstructs the geometric structure of the scene from depth, it does not encode any notion of object identity, motivating the need to integrate semantic information for meaningful 3D understanding, as we shall explore in the next section.

## Semantic 3D fusion

Depth alone provides geometry but not semantic meaning. Semantic segmentation assigns a category label: $S(x,y) \in \{1,\ldots,C\}$ to each pixel. Combining depth and segmentation enables semantic 3D mapping, scene understanding, robotics, autonomous navigation, and AR/VR reconstruction.

The next code snippet uses nvidia/segformer-b0-finetuned-ade-512-512. As mentioned earlier, SegFormer combines hierarchical transformers and efficient decoding. And multi-scale fusion without positional encoding. $\text{outputs} = \text{seg\_model}(**\text{inputs})$ produces segmentation logits:

$L \in \mathbb{R}^{C \times H \times W}$

The final segmentation map is:

$S(x,y) = \underset{c}{\operatorname{argmax}}\; L_c(x,y)$

implemented using: `seg = logits.argmax(dim=1)[0]`

Each 3D point now stores: $(X,Y,Z,c)$ where $(X,Y,Z)$ = geometry and $c$ = semantic class. This transforms ordinary point clouds into semantic point clouds. Random colors are assigned to semantic classes, each object category becomes visually distinguishable in 3D space.

The function `depth_seg_to_pointcloud()` does the following:

- Estimates depth
- Predicts semantic labels
- Projects pixels into 3D
- Assigns semantic colors
- Constructs a semantic point cloud

The resulting semantic point cloud simultaneously encodes geometry, structure, and object identity. This is fundamental for autonomous driving, embodied AI, robotics, digital twins, neural scene reconstruction, SLAM systems, etc.

The complete pipeline can be summarized as:

$I \rightarrow (D,S) \rightarrow (X,Y,Z,c) \rightarrow \mathcal{P}_{semantic}$

where $I$ = RGB image, $D$ = depth, $S$ = semantic segmentation, $(X,Y,Z,c)$ = semantic 3D points and $\mathcal{P}_{semantic}$ = semantic point cloud. Now, refer to the following code snippet:
