## Hand landmark detection and gesture visualization

MediaPipe Hand Landmarker estimates 21 anatomical keypoints for each detected hand:

$H = \{(x_i, y_i, z_i)\}_{i=1}^{21}$

These landmarks correspond to finger joints, fingertips, and palm locations, providing a compact skeletal representation of the hand. The detector learns $g(I) \rightarrow H$, where $H$ encodes hand pose and fine-grained finger articulation. The pretrained hand landmark detector is initialized using the MediaPipe Tasks API:

```
options = vision.HandLandmarkerOptions(base_options=base_options, num_hands=2)
self.detector = vision.HandLandmarker.create_from_options(options)
```

which enables simultaneous tracking of up to two hands. Unlike bounding-box-based detectors, landmark models capture fine-grained finger movements and are therefore suitable for gesture recognition and sign-language analysis. The hand skeleton is represented as a graph $G = (V, E)$, where the vertices $V$ correspond to landmarks and the edges (E) define anatomical connections between joints. For example, the thumb chain is represented by (0,1), (1,2), (2,3), (3,4). These skeletal connections are encoded as:

```
HAND_CONNECTIONS = [(0,1), (1,2), (2,3), (3,4), ...]
```

Beyond visualization and analysis, landmark representations can also serve as motion descriptors for generative models. By tracking how facial or body keypoints move over time, it becomes possible to transfer motion from one subject to another, enabling realistic image animation and DeepFake generation. The next section explores this idea through the **First Order Motion Model (FOMM)**, which synthesizes motion using learned keypoint-based representations.

## Deepfake generation with the First Order Motion Model

The **First Order Motion Model (FOMM)** is a landmark generative framework for image animation that transfers motion from a driving video to a single source image. Given a source image $I_s$ and a driving frame $I_d^t$, the objective is to synthesize an animated frame:

$$I^t = G(I_s, K_s, K_d^t),$$

where $G$ is a generator network, and $K_s$ and $K_d^t$ are sparse motion keypoints extracted from the source image and driving frame, respectively.

Before running the *DeepFake* pipeline, the official *FOMM* repository is cloned from GitHub and the *Colab* environment is configured to use the Python version compatible with the pretrained model and dependencies. The repository contains the pretrained network architectures, configuration files, motion-transfer algorithms, and utility functions required for image animation.

```
!git clone https://github.com/AliaksandrSiarohin/first-order-model
```

Subsequent steps load pretrained checkpoints and use the model's keypoint detector and generator networks to transfer motion from a driving video to a static source image, producing a realistic animated DeepFake sequence. Unlike classical face animation methods that rely on manually defined facial landmarks, FOMM learns keypoints automatically:

$$K = \{(x_i, y_i)\}_{i=1}^N$$

allowing the model to discover motion-relevant regions in a *self-supervised* manner. The motion between source and driving frames is converted into a dense deformation field that warps source-image features before image synthesis. The pretrained keypoint detector and generator are loaded using:

```
generator, kp_detector = load_checkpoints(config_path='config/vox-256.yaml',
                                    checkpoint_path=filename)
```

where kp_detector estimates motion keypoints and generator synthesizes the animated output. The source image and driving video frames are resized to the model's training resolution:

```
selected_image = imread('/content/socrates.png')[..., :3]
driving_video = [resize(frame, (256,256))[..., :3] for frame in driving_video]
```

Animation is then generated using the following code snippet (refer to GitHub for complete code):

```
predictions = make_animation(resize(np.asarray(selected_image), (256,256)),
[resize(frame,(256,256)) for frame in driving_frames],
generator, kp_detector)
```

Internally, the model performs

$K_s = f_{kp}(I_s),\ K_d^t = f_{kp}(I_d^t)$

followed by motion estimation and image generation:

$M_t = \Phi(K_s, K_d^t),\ \hat{I}^t = G(I_s, M_t)$

The resulting sequence preserves the appearance and identity of the source image while reproducing the facial expressions, head pose, and motion observed in the driving video. ## Car damage detection and severity assessment using YOLOv8 segmentation

**Insurance claim assessment** traditionally relies on manual inspection of vehicle damage, which is time-consuming, subjective, and expensive. Modern computer vision systems can automate this process by localizing damaged regions, estimating their extent, and providing an objective measure of severity. In this demonstration, a segmentation version of YOLOv8 is trained on the **CarDD (Car Damage Detection)** dataset from Kaggle, which contains annotated vehicle damages such as dents, scratches, cracks, and broken parts. Unlike object detection, which predicts rectangular bounding boxes, instance segmentation predicts pixel-level masks, enabling accurate estimation of the damaged area.
