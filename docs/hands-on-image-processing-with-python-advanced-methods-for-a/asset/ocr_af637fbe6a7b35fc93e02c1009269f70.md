DETR introduces object queries:

Attention(Qₒ, Z_L, Z_L)

Each query predicts **object class** and **mask / region**. The **DETR** reformulates segmentation as a **set prediction problem**. Given object queries Q, DETR predicts:

Ŷ = {(cᵢ, bᵢ, mᵢ)}ᵢ₌₁ᴺ

where cᵢ: class label, bᵢ: bounding box and mᵢ: mask. Training uses:

+   - **Hungarian matching:**
+   
+     ℒ = Σᵢ₌₁ᴺ ℒ_match(yᵢ, ŷ_σ(i))

+   - **Panoptic segmentation:** DETR extends to panoptic segmentation:
+   
+     Panoptic = Things ∪ Stuff

The next code snippet loads a pretrained **DETR panoptic segmentation model** (it loads the pretrained model **facebook/detr-resnet-50-panoptic** with the function DetrForSegmentation.from_pretrained()) and applies it to an input image to **segment both objects (things) and background regions (stuff)** in a single pass. It preprocesses the image, runs inference, converts the predicted segmentation map into colored regions, and overlays it on the original image for visualization.

The detr_processor (another pretrained model loaded using the function DetrImageProcessor.from_pretrained()) handles **image preprocessing and post-processing** (with the processor method post_process_panoptic_segmentation())—it converts the image into tensors for the model and later converts raw outputs into a pixel-wise segmentation map—while detr_model is the **transformer-based network (ResNet-50 backbone + DETR)** that predicts segments using object queries.

Intuitively, DETR uses **transformer-based object queries** to (“looks” at the whole image globally and) directly predict segments for the entire scene, and the post-processing step converts these predictions into a **pixel-wise panoptic mask**, which is then colorized and overlaid on the original image for visualization. This produces **segmentation map** and **segments_info**. Unlike pixel-wise models **DETR outputs object-level masks**, hence No need for **NMS (Non-Max Suppression)**.
