
It outputs Q: the label probability distribution for all pixels.

The next code performs Dense CRF-based image segmentation refinement, using unary potentials derived from annotated labels and Gaussian/bilateral pairwise potentials to enforce spatial and appearance consistency, followed by mean-field inference and MAP estimation to generate the final color-coded segmentation.

## Internal iteration steps

Each iteration performs:

- 1. Message passing: Aggregate information from all pixels, corresponds to:

$$\sum_{j} \psi_p(x_i, x_j)$$

It is implemented via efficient filtering.

- 2. Pairwise filtering: Gaussian + bilateral kernels applied; efficient via high-dimensional filtering.
- 3. Compatibility transform: Apply label compatibility $\mu(x_i, x_j)$
- 4. Add Unary term: Combine with $\psi_u(x_i)$
- 5. Normalization: $Q_i(x_i) \leftarrow \frac{1}{Z_i} \exp(-\text{energy})$, ensures valid probabilities
- 6. MAP estimation: $x_i^* = \arg\max Q_i(x_i)$, corresponds to `MAP = np.argmax(Q, axis=0)` in the next code snippet. Final segmentation (labeling) = most probable label per pixel.

Finally, convert the segmentation labels obtained from MAP inference into a color-coded RGB image by assigning a distinct color to each class, thereby producing a visually interpretable segmentation result (`MAP = colorize[MAP, :]`).

## Note

Kullback–Leibler (KL) divergence measures how different one probability distribution is from another: $KL(Q || P) = \sum_x Q(x) \log \frac{Q(x)}{P(x)}$. It quantifies how much information is "lost" when we use the approximation Q instead of the true distribution P. In CRF mean-field inference, we iteratively update Q to approximate P(X | I): a decreasing KL divergence indicates that Q is getting closer to the true distribution P, i.e., the algorithm is converging.

Why CRF works well? It refines coarse segmentation and aligns labels with object boundaries — sharpens boundaries and preserves fine structures. It removes isolated noisy predictions. The next table provides a comparison between the last two graph-based methods for segmentation:

| Method | Key Idea | Strength |
|---|---|---|
| GrabCut | Graph cuts + GMM | Interactive segmentation (through global optimization) |
| CRF | Probabilistic graphical model | Boundary refinement (through context-aware refinement) |

Table 10.1: GrabCut vs. CRF method for image segmentation

While GrabCut performs interactive, data-driven segmentation through global energy minimization using color models, CRFs refine the segmentation output by enforcing spatial and contextual consistency at the pixel level, leading to sharper and more coherent object boundaries.

## Learning-based classical segmentation

This class of methods bridges classical image processing and machine learning, where segmentation is formulated as a supervised learning problem. Instead of relying purely on thresholds or gradients, these approaches learn decision boundaries from data using engineered features.

### Segmentation using classification

Trainable segmentation treats each pixel as a feature vector and predicts its label using a classifier. Given an image $I(x, y)$.

We extract features:

$f_i = \phi(I, x_i, y_i)$,

where: $f_i \in \mathbb{R}^d$: feature vector at pixel i and $\phi(\cdot)$: feature extraction function (intensity, texture, etc.). The segmentation problem becomes:

$\hat{y}_i = \arg\max_k P(y_i = k | f_i)$.

Random Forest Classifier: A Random Forest is an ensemble of decision trees:

$P(y_i = k | f_i) = \frac{1}{T} \sum_{t=1}^{T} P_t(y_i = k | f_i)$,

where T: number of trees and each tree partitions feature space using axis-aligned splits.

Here is the pipeline:

- 1. Feature Extraction → $f_i$
- 2. Training Labels → $y_i$
- 3. Classifier Training
- 4. Pixel-wise Prediction

The next code snippet implements classification-based segmentation. Here are the steps:

- 1. **Load image and define training labels:** Extract a subregion from a skin image (downloaded with `data.skin()`) for training and initialize label map $y_i$, regions are manually annotated: each integer $k$ = class label (sparse labeling → reduces annotation effort).
- 2. **Feature extraction:** $f_i = [I_i, \text{texture}_i, \text{multi-scale responses}]$

The function `partial()` creates a new function with some arguments pre-filled. Multi-scale Gaussian filtering captures structures at different scales (at **different levels of detail**):

These are image features computed at multiple spatial scales (resolutions):

- $F = \{f_{\sigma_1}(I), f_{\sigma_2}(I), ..., f_{\sigma_n}(I)\}$, where $\sigma$ = scale (e.g., Gaussian blur level)
- Small scale → fine details (edges, texture)
- Large scale → coarse structures (shapes, regions)

Typical features: intensity, edges (gradients), texture (Laplacian, Hessian) computed at different Gaussian scales.

Why is it useful? Because objects appear differently at different sizes: detect small objects → small scale and detect large objects → large scale.
