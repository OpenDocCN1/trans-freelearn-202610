
Here are the key reasons why convolution is performed on an image and why it is essential in image processing:

- **Mathematical foundation:** Convolution mathematically combines the input image with the kernel in a way that extracts or suppresses certain features
- **Computational efficiency:** Most image processing algorithms, especially those in computer vision, heavily rely on convolution due to its simplicity and efficiency
- **Versatility:** Convolution is a universal operation that can be adapted for various tasks by simply changing the kernel, allowing for a wide range of effects and transformations on an image

It is widely used in image processing and deep learning for feature extraction and filtering. In this section, we shall use convolution to apply a general-purpose filter effect on an image. This is done to achieve various effects with appropriate kernels on an image, such as smoothing, sharpening, and embossing, and in operations such as edge detection. However, depending on whether the convolution is performed in the spatial or frequency domain, the computational efficiency can vary significantly.

## Spatial domain convolution

The core of a 2D spatial convolution involves sliding a **kernel** (or filter) over an image to compute a **weighted sum** of the pixel intensities around each location. Mathematically, for an image of size M × N and a **filter** (kernel) K of size k × k, the convolution at a pixel position is computed as follows:

O(x, y) = Σₘ Σₙ K(m, n) · I(x − m, y − n)

While straightforward, this method becomes computationally expensive for large images or large kernel sizes, as the number of operations grows quadratically with the kernel size.

**Time complexity (spatial domain):** The time complexity for spatial domain convolution is O(k²MN), where k is the kernel size, and M × N is the image size. For small kernel sizes (e.g., 3x3 or 5x5), this is manageable, but for large kernels, the cost becomes prohibitive.

## Frequency domain convolution

In the frequency domain, convolutions can be performed more efficiently using the **convolution theorem**, which states that convolution in the spatial domain is equivalent to element-wise multiplication in the frequency domain. The steps are as follows:

- Transform the image I and kernel K into the frequency domain using the **Fast Fourier Transform (FFT)**.
- Multiply the Fourier-transformed image and kernel elementwise.
- Inverse the FFT to convert the result back to the spatial domain.

Mathematically, if F denotes the Fourier transform, the convolution is computed as follows:

F(I * K) = F(I) · F(K)

The major advantage here is that the FFT can compute convolutions more efficiently, especially for large kernels, because the FFT reduces the time complexity of convolution from quadratic to near-linear.

## Time complexity

The overall computational complexity of Fourier-based image processing steps can be broken down as follows:

- The **FFT** of an image of size $M \times N$ can be computed in $O(MN \log(MN))$
- Element-wise multiplication of the Fourier transforms has a time complexity of $O(MN)$
- The **Inverse FFT (IFFT)** also takes $O(MN \log(MN))$

Thus, the overall time complexity in the frequency domain is: $O(MN \log(MN))$. This is significantly more efficient than the quadratic time $O(k^2 MN)$ in the spatial domain, particularly for large images and large kernels.

## Comparison — spatial versus frequency domain

To decide when to use spatial or frequency domain filtering, it's helpful to compare their performance characteristics based on kernel size and computational efficiency. The following points summarize key differences:

- For small kernels, spatial domain convolution is often faster because the overhead of performing the FFT outweighs the benefits of element-wise multiplication. This is why direct convolution is used for kernels such as $3 \times 3$ or $5 \times 5$ in typical image filters.
- For large kernels, the frequency domain approach is more efficient. The complexity of $O(MN \log(MN))$ grows more slowly than $O(k^2 MN)$, especially when $k$ becomes large.

> **Note**
> While FFT-based convolution is efficient for large kernels, it can become memory-intensive for very large images. In such cases, advanced strategies such as *tiled FFT*, *overlap-save*, or *overlap-add* methods can be used to process the image in smaller chunks without exceeding memory limits.

## Practical applications

The choice between spatial-domain and frequency-domain convolution depends on efficiency and the task. Edge detection using small-kernel operators such as Sobel and Prewitt is typically performed in the spatial domain for real-time performance. Blurring and smoothing with large kernels, such as Gaussian blur, are often implemented in the frequency domain to reduce computational cost. Deconvolution, used in applications such as astronomical image restoration and biomedical microscopy, also commonly relies on frequency-domain techniques (e.g., Wiener and **Richardson–Lucy deconvolution**) for efficient recovery of image details from blurred observations.

## Applying convolution in the spatial domain

Now, let's demonstrate how 2D convolution can be applied to images with the following functions from a few different libraries.

### With `scipy.signal`

The `scipy` library’s signal module’s `convolve2d()` function can be used to apply 2D convolution to an image. Let us apply convolution on an image (first a grayscale image and then to an RGB color image) with a kernel (also called a filter, or a point-spread function – PSF sometimes) using this function.

### Convolution on grayscale Images (SciPy)

Let’s now demonstrate two fundamental operations in image processing: **blurring** an image (the grayscale cameraman image is used as an input image here) with a box blur filter and **detecting edges** with the Laplace kernel, implemented using 2D convolution, using the following code snippet. Here is a detailed explanation of the relevant parts of the code that you’ll find below:

1. **Defining the box blur kernel**
    - A box blur kernel is created, which is a 3x3 matrix of ones. Dividing by 9 **normalizes** the kernel so that the sum of all values in the kernel is 1. This ensures that the convolution does not amplify the brightness of the image.
    - This kernel, when applied to the image, averages the pixel values within a 3x3 neighborhood, effectively creating a smoothing or blurring effect.

2. **Defining the Laplace edge detection kernel**
    - The **Laplace kernel** is used to perform **edge detection**. It detects changes in intensity by calculating the second derivative of the image. The kernel highlights regions where the intensity shifts significantly, which typically correspond to edges.
    - In this kernel, the central pixel has a negative weight of -4, while its neighboring pixels in the four cardinal directions have a weight of +1. This arrangement emphasizes rapid changes in pixel intensity (i.e., edges).

3. **Applying convolution to the image:**
    - `signal.convolve2d()` convolves the grayscale image `im` with the kernels. Convolution slides the kernel over the entire image, replacing each pixel with the weighted average of its neighbors, thereby computing the convolved image.
    - `blur_box_kernel` applies smoothing/blurring to the input image, and the result is stored in `im_blurred`.
    - `edge_laplace_kernel` computes the difference in pixel intensity between a pixel and its neighbors, highlighting areas where the intensity changes abruptly (i.e., edges).

Now, refer to the following code snippet:

```python
%matplotlib inline
from PIL import Image
from skimage.io import imread, imshow, show
import scipy.fftpack as fp
import numpy.fft as nfp
from scipy import ndimage, misc, signal
from skimage import data, color, restoration, img_as_float
from skimage.color import rgb2gray
from skimage.transform import rescale
from skimage.metrics import peak_signal_noise_ratio as psnr
import matplotlib.pylab as plt
from matplotlib.colors import LogNorm
import numpy as np
import numpy.fft
import timeit
import warnings
warnings.filterwarnings('ignore')
im = rgb2gray(imread('images/cameraman.jpg'))
print(np.max(im))
# 0.9921568627450981
print(im.shape)
# (256, 256)
blur_box_kernel = np.ones((3,3)) / 9 # normalize the kernel
edge_laplace_kernel = np.array([[0,1,0],[1,-4,1],[0,1,0]])
im_blurred = signal.convolve2d(im, blur_box_kernel)
im_edges = np.clip(signal.convolve2d(im, edge_laplace_kernel), \
                                  0, 1)
```
