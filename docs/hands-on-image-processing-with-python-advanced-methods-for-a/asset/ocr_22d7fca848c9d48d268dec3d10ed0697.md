```
hsv = color.rgb2hsv(im) # from RGB to HSV color space
hsv[:, :, 1] = 0.5 # change the saturation
im_hsv = min_max_normalize(color.hsv2rgb(hsv)) # from HSV back to RGB
print(im_hsv.dtype)
# uint8

im_hsv = imread("images/parrot_hsv.png")

```

In the above code, the function imread() from skimage.io reads images as NumPy ndarray objects. With the default as_gray=False, images are loaded as uint8 arrays with pixel values in [0,255], whereas as_gray=True loads grayscale images as float64 arrays with values in [0,1]. The custom min_max_normalize() function performs min-max normalization to scale image intensities to a specified range, typically [0,255].

The grayscale image is converted to a three-channel image using gray2rgb(), and RGB-to-HSV color conversion is performed using skimage.color.rgb2hsv().

Next, the saturation channel is modified while preserving hue and value, demonstrating how saturation controls color vividness: high saturation produces rich colors, low saturation produces muted colors, and zero saturation yields grayscale images. The modified HSV image is converted back to RGB using hsv2rgb(), saved with skimage.io.imsave(), and visualized side-by-side using np.hstack() and plt.imshow(). Note: The HSV channel representations differ between skimage.color.rgb2hsv() and OpenCV's cv2.cvtColor(..., cv2.COLOR_RGB2HSV) primarily in their scaling conventions: in scikit-image, all three channels—Hue, Saturation, and Value—are represented as normalized floating-point values in the range [0.0, 1.0], whereas OpenCV uses integer-based scaling where Hue is mapped to [0, 179] (corresponding to 0–360° but stored at half resolution for 8-bit representation), and both Saturation and Value are stored in the range [0, 255]. Thus, scikit-image adopts a unit-interval continuous representation, while OpenCV uses an 8-bit integer representation with different scaling factors across channels.
