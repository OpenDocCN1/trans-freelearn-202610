
DiffEdit extends diffusion models by adding **Denoising Diffusion Implicit Models (DDIM)** inversion: the input image is mapped back into the latent diffusion space, enabling localized modifications. The next code snippet implements image editing with diffusion:

```
```python
import torch
from diffusers import (StableDiffusionDiffEditPipeline,
                       DDIMScheduler, DDIMInverseScheduler)
from diffusers.utils import load_image, make_image_grid

pipe = StableDiffusionDiffEditPipeline.from_pretrained( # Load pipeline
                                      "stabilityai/stable-diffusion-2-1",
                                      torch_dtype=torch.float16)
pipe.scheduler = DDIMScheduler.from_config(pipe.scheduler.config)
pipe.inverse_scheduler = DDIMInverseScheduler.from_config(
    pipe.scheduler.config)
pipe = pipe.to("cuda")
pipe.enable_vae_slicing()

img_url = "https://github.com/Xiang-cd/DiffEdit-stable-diffusion/raw/main/
assets/origin.png"
base = load_image(img_url).resize((768, 768)) # Load base image
source_prompt = "a bowl of fruits" # Source VS Target prompts
target_prompt = "a bowl of pears"
# Step 1: Generate semantic mask
mask_image = pipe.generate_mask(image=base, source_prompt=source_prompt,
                                target_prompt=target_prompt)
mask_disp = Image.fromarray((mask_image.squeeze() * 255)
                             .astype("uint8"), "L").resize((768, 768))
# Step 2: Invert image into latent space
inv_latents = pipe.invert(prompt=source_prompt, image=base).latents
# Step 3: Apply editing with target prompt
edited = pipe(mask_image=mask_image, image_latents=inv_latents,
              prompt=target_prompt, negative_prompt=source_prompt,
              guidance_scale=7.5)
              .images[0]
# Display results
make_image_grid([base, mask_disp, edited], rows=1, cols=3)
```

- **Base image:** The original image (a bowl of fruits).
- **Prompts:** The source prompt (“a bowl of fruits”) guides the mask generation; the target prompt (“a bowl of pears”) specifies the edit.

> **Note**
> 
> DDIM inversion approximately reverses the DDIM generation process, mapping a real image into the diffusion model’s latent noise trajectory and thereby enabling structure-preserving, prompt-driven image editing. While **Denoising Diffusion Probabilistic Models (DDPM)** relies on a stochastic Markovian denoising process (to be covered in detail in *Chapter 13*), **Denoising Diffusion Implicit Models (DDIM)** employs a deterministic non-Markovian formulation that achieves comparable image quality with substantially fewer sampling steps.

## Image inpainting with Diffusion models

Inpainting aims to *restore missing or corrupted parts of an image*. Unlike editing, the mask is explicitly provided by the user, and the model must fill the hole with semantically consistent content. The probabilistic formulation is:

$$\hat{x} = \underset{x}{\arg\max}\ p(x \mid y, M, p),$$

where $M$ defines the missing region and $p$ is the guiding prompt describing what should fill the region.

Diffusion-based inpainting models (e.g., Kandinsky 2.2 inpainting) are trained with masks applied randomly during training, forcing the model to hallucinate realistic completions consistent with both context and prompts. The next code snippet implements image inpainting with diffusion:

```
from diffusers import AutoPipelineForInpainting
from diffusers.utils import load_image, make_image_grid

# Load Kandinsky inpainting pipeline
pipeline = AutoPipelineForInpainting.from_pretrained(
    "kandinsky-community/kandinsky-2-2-decoder-inpaint",
    torch_dtype=torch.float16)
pipeline.enable_model_cpu_offload()
pipeline.enable_xformers_memory_efficient_attention()  # optional optimization
init_image = load_image("https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/diffusers/inpaint.png")
mask_image = load_image("https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/diffusers/inpaint_mask.png")
prompt = "a black cat with glowing eyes, cute, adorable, disney, pixar, highly detailed, 8k"  # Prompt for inpainting
negative_prompt = "bad anatomy, deformed, ugly, disfigured"
image = pipeline(  # Run inpainting
    prompt=prompt, negative_prompt=negative_prompt,
    image=init_image, mask_image=mask_image).images[0]
# Show results
make_image_grid([init_image, mask_image, image], rows=1, cols=3)
```

This section introduces editing and inpainting in a unified framework: both are prompt-guided inverse problems, but editing infers the mask automatically while inpainting requires explicit masks.

The following table provides a side-by-side comparison between image editing and image inpainting, which will help you clearly see where LaMa inpainting fits:

| Dimension | Image editing | Image inpainting |
|---|---|---|
| **Goal** | Modify or enhance parts of an image deliberately (e.g., retouch, recolor). | Fill in missing or removed regions with plausible content. |
| **User control** | High; user decides what to change and how (manual adjustments). | Low to medium; user only provides mask; model decides how to complete the region. |
| **Input** | Original image and explicit editing instructions (brush strokes, filters, etc.) | Original image and binary mask indicating holes. |
| **Output** | Adjusted version of the same image, guided by user preferences. | Semantically consistent, context-aware completion of missing areas. |
| **Techniques** | Traditional tools (Photoshop, GIMP, filters), GAN-based editors, retouching. | Deep generative models (e.g., LaMa, Partial Conv Nets, Diffusion Inpainting). |
| **Applications** | Retouching portraits, adjusting colors, object replacement, style transfer. | Object removal, restoration of damaged photos, scene completion, content repair. |
| **Evaluation** | Subjective satisfaction of desired edit; sometimes automated quality metrics. | Consistency, realism, perceptual plausibility (PSNR, SSIM, LPIPS, FID, etc.). |
| **Automation** | Typically manual or semi-automatic. | Fully automatic once mask is provided. |

*Table 9.9 – Comparing image editing and image inpainting*

This makes it clear that inpainting is a specialized subset of editing focused on *restoration/filling*, while editing is a broader concept.
