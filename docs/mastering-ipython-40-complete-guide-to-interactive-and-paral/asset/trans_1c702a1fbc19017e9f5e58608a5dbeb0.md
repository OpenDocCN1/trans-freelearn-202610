# 前言

欢迎来到 IPython 4.0 的世界，它被用于高性能和并行环境。Python 本身在这些领域逐渐受到青睐，而 IPython 正是在这些优势之上构建的。

高性能计算（HPC）有许多特性，使其与大多数其他计算领域有所不同。我们将首先简要介绍 HPC 的不同之处，以及 IPython 如何成为一项颠覆性技术。

然后我们将从 IPython 命令行开始。既然 Jupyter 已从 IPython 项目中分离出来，这就是开发者与该语言交互的主要方式。这是一个足够重要的主题，值得用两章来讲述。在第一章中，我们将重点介绍基本命令，并理解 IPython 如何执行这些命令。第二章将涵盖更高级的命令，让读者对命令行的功能打下坚实的基础。

之后，我们将讨论并行编程的一些细节。IPython parallel 是一个包含 IPython 中并行计算所需大量功能的包。它支持一套灵活的并行编程模型，如果你想利用大规模并行架构的强大能力，这一点至关重要。

并行运行但在不同处理器上的程序，尽管拥有独立的地址空间，往往仍需要交换信息。它们通过发送消息来实现这一点。我们将介绍两个消息传递系统：ZeroMQ 和 MPI，并涉及它们如何在现有程序中使用以及如何与 IPython 交互。

接下来，我们将更深入地探讨能够提高生产力的库，无论它们是 IPython 自带的还是第三方提供的。本书无法涵盖所有工具，而且新工具层出不穷，但其中一些将特别适用于并行和 HPC 项目。

第 9 章《文档》讨论了文档的不同受众及其需求。在良好文档标准的背景下，演示了如何使用带有 reStructuredText、docutils 和 Sphinx 的 docstring。

第 10 章《访问 Jupyter》介绍了 Jupyter notebook，并将其描述为一种结合数据和计算的实验室笔记本。

第 11 章《走向未来》反思了当前快速变化的节奏，并展望了未来可能的发展方向，既涉及最近 IPython 与 Jupyter 项目的分离，也涉及科学计算领域整体的一些新兴趋势。

# 本书所需准备

本书基于 2015 年 8 月至 2016 年 3 月期间的 IPython 4.0 和 4.0.1（稳定版）编写；所有示例和函数在这些版本中均应可用。当需要第三方库时，会在相应位置注明所使用的版本。鉴于 IPython 4 实现、各种第三方库以及整个领域的变化速度，很遗憾，无法保证本书中的每个示例都能在每位读者的机器上运行。再加上机器架构和配置的差异，问题只会更加严重。尽管我们努力编写简洁、可移植的代码，但读者在让个别示例在自己的系统上运行时遇到一些困难，也不应感到意外。

# 本书读者对象

本书面向希望充分利用 IPython、利用交互式计算的便捷性，使用 IPython 进行高级科学计算的 IPython 开发者。

它非常适合希望了解 IPython 4.0 的交互式和并行计算特性，以及与第三方工具和概念（如测试和结果文档化）集成的用户。

# FORTRAN 来救援——FORTRAN 所解决的问题

在计算机取得最初的成功（破解德国密码和计算对数）之后，该领域遇到了两个问题。首先，机器本身速度很慢——或者至少对于手头的新问题来说比期望的慢。其次，编写机器用来解决问题的指令（代码）花费的时间太长。

让机器本身更快主要是一个工程问题。底层基质从蒸汽和阀门发展到机电继电器，再到真空管，最后到集成电路。每一次基质的变化都提高了指令执行的速度。这种形式的进步虽然有趣，但超出了本书的范围。

一旦计算机发展到不再需要通过布线来设置程序，程序员就可以开始用编程语言以文本形式表达算法。虽然打字比布线快，但它也有自己的问题。Fortran 是最早成功解决这些问题的语言之一。

# 可读性

早期的语言通常不太人性化。编写（以及阅读）用这些语言编写的程序需要专门训练。程序员通常会在代码中添加注释，要么在代码本身中，要么在外部文档中，但问题更深层。语言本身就很晦涩难懂。

# 构建（和维护）软件的成本

如果开发者们都天赋相当、免费工作、开发时间不受限制、所有代码都没有错误，并且所有程序只需要运行一次然后就被丢弃，那么鉴于其效率和已有的库基础，Fortran 将是明显的赢家。

但商业软件并非如此开发。粗略来看，软件项目的成本可以分为以下几个部分：

- 需求和规格收集
- 开发
- 执行
- 测试和维护

# 需求和规格收集

在生成良好的需求和规格的难度方面，IPython 和 Fortran 之间没有明显区别。这些活动与语言无关。虽然预先编写好的软件包的可用性可能会影响规格的某些部分，但两种语言在将需求和规格转化为可运行系统方面具有同等能力。

# 开发

如前所述，Python 代码往往更简洁，从而带来更高的程序员生产力。再加上越来越多的开发者已经熟练掌握 Python，在缩短开发时间方面，Python 显然是赢家。

# 执行

如果在目标系统上运行成本很高（许多超级计算机就是如此），或者程序运行时间很长（某些大规模模拟如天气预报就是如此），那么 Fortran 的运行时效率是无与伦比的。当程序的开发工作基本完成，大部分时间都花在等待其运行完成上时，这一考量尤其重要。
