### 使用 %%prun

`%%prun` 魔法命令使用 Python 内置的 `cProfile` 模块。它提供了关于时间花费在何处的更多信息。特别是，它可以按函数细分执行时间。下面是一个示例：

```python
In [58]: %%prun

s = 0
for i in range(1, 1500):
    s = s + 1/math.factorial(i)
```

### 作业控制

每个 View 还包含用于控制其队列中作业的函数。这些函数与 `Client` 中提供的函数类似，但仅适用于 View 中的引擎：

| 方法 | 参数 | 作用 |
|---|---|---|
| abort | `jobs`（以下之一）：<br>`(list of) str`<br>`None`<br>`targets` | `(list of) str` 是要中止的 `msg_id` 列表。如果为 None，则中止所有作业。该操作会在 `targets` 中列出的所有引擎上发生。 |
| get_result | `indices_or_msg_ids`（以下之一）：<br>`(list of) job index`<br>`(list of) msg_ids` | 通过 `msg_id` 或历史索引获取作业结果。结果是一个 `AsyncResult` 对象。当作业被阻塞时，这很有用，因为客户端将无法访问这些信息。 |
| queue_status | `targets`（以下之一）：<br>`(list of) int`<br>`(list of) str` | 返回所列引擎队列的状态。默认返回所有队列的状态。 |
| shutdown | `targets`（以下之一）：<br>`list of ints`<br>`"all"`<br>`hub: bool` | 终止引擎进程。如果 hub 为 True，它还会终止 Hub。 |

### DirectView

`DirectView` 对象就像一个多路复用器——它有一组引擎（`targets`），并对所有引擎执行相同的操作。基本概念是，可以将 `DirectView` 视为单个引擎，只不过它会在多个引擎上并行执行。

这对函数执行的影响很简单：

- 对于 `apply*` 函数，`f`、`*args` 和 `**kwargs` 会被发送到目标组中的每个引擎。
- 对于 `map*` 函数，`f`、来自 `*sequences` 的一个条目以及 `**kwargs` 会被发送到目标组中的每个引擎。每个引擎从 `*sequences` 中获得不同的条目。如果 `*sequences` 中的元素多于引擎数，某些引擎将多次执行，每次使用不同的条目。

## 打开工具包 – IPython API

DirectView 作为一个多路复用器工作。它有一组引擎（targets），并对所有引擎执行相同的操作。这使开发人员可以将一组引擎视为一个单一实体。DirectView 的一个重要能力是让所有目标引擎上的事物保持“相同”。具体来说，DirectView 提供了数据移动机制（全局字典、scatter-gather 和 push-pull）以及环境管理机制（sync_imports 上下文管理器）。

LoadBalancedView 也允许将多个引擎视为单个引擎。然而，在这种情况下，概念模型是单个非阻塞引擎，而不是一组引擎。控制器可以非阻塞地向 LoadBalancedView 提交多个作业。而 LoadBalancedView 本身则依赖调度器来实际执行作业。这不会改变相对于 DirectView 的环境管理状况，但确实需要外部数据移动工具，如 MPI 或 ZeroMQ。
