# 前言

用户体验是任何游戏的关键组成部分，这不仅包括我们游戏的故事和玩法，还包括图形运行的流畅程度、连接多人服务器的可靠性、对用户输入的响应速度，甚至包括最终应用程序文件的大小，因为移动设备和云下载非常普遍。得益于 Unity 等工具，游戏开发的门槛已大幅降低，Unity 提供了大量有用的开发功能，同时仍对个人开发者友好。然而，由于游戏行业竞争激烈，玩家期望我们提供的最终产品质量水平与日俱增。我们应该预期，游戏的每个方面都会受到玩家和评论家的审视。

性能优化的目标与用户体验紧密相关。优化不佳的游戏可能导致帧率低、卡顿、崩溃、输入延迟、加载时间长、运行时行为不一致且抖动、物理引擎故障，甚至电池功耗过高（移动设备上常被忽视的指标）。仅出现其中一个问题，就可能成为游戏开发者的噩梦，因为评论往往会关注我们做得不好的那一点，而忽略我们做好的所有方面。

性能优化的一个目标是充分利用可用资源，包括 CPU 资源（如消耗的周期数、使用的主内存空间，即 RAM）以及图形处理单元（GPU）资源（包括其自身的内存空间，即 VRAM、填充率、内存带宽等）。然而，性能优化最重要的目标是确保没有任何单一资源在不合适的时间造成瓶颈，并且最高优先级的任务能够优先处理。即使是微小的间歇性卡顿和性能迟缓，也会将玩家从体验中拉离，破坏沉浸感，限制我们创造预期体验的潜力。另一个考虑是，我们节省的资源越多，就能在游戏中实现更多活动，从而创造更有趣、更动态的游戏玩法。

同样重要的是，决定何时退后一步，停止进行性能增强。在时间和资源无限的世界里，总会有让游戏变得更好、更快、更高效的方法。在开发过程中，必须有一个时刻我们决定产品已达到可接受的质量水平。否则，我们就有可能陷入反复实施改动的困境，这些改动几乎没有或没有实际效益，而每次改动也都有引入更多错误的风险。
