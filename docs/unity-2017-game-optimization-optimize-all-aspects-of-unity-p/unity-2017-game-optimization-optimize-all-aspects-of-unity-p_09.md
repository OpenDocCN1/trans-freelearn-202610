# 前言

决定是否值得修复性能问题的最佳方法是回答这个问题：“用户会注意到吗？”。如果答案是“不”，那么性能优化将是徒劳的。软件开发中有一句老话：

> 过早优化是万恶之源。

过早优化是重构和重写代码以提升性能的重大罪过，却没有任何证明这是必要的。这可能意味着在没有证明性能问题存在的情况下进行更改，或者仅仅因为我们相信性能问题可能源于某个特定区域，而在未得到证实之前就进行更改。

当然，这句常见格言的原始版本（由 Donald Knuth 提出）接着说，我们仍应编写代码以避免更直接和明显的性能问题。然而，项目后期的真正性能优化工作可能需要大量时间，我们既应计划时间来恰当地打磨产品，又应避免在没有可验证证据的情况下实施更昂贵、更耗时的更改。此类错误在软件开发者群体中造成了令人沮丧的大量无效工时。

本书旨在为您提供检测和修复 Unity 应用程序中性能问题所需的工具、知识和技能，无论这些问题源自何处。这些瓶颈可能出现在 CPU、GPU 和 RAM 等硬件组件中，也可能出现在物理、渲染和 Unity 引擎本身等软件子系统中。

优化游戏性能将使它们在充斥着每天新增高质量游戏的市场中，有更大机会脱颖而出并取得成功。
