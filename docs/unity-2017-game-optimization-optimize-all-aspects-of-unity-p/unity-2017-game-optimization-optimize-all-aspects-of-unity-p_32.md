这就带我们来到了本书的结论。希望你享受这次旅程。重申一下，也许本书中最重要的提示是，在做任何更改之前，务必通过基准测试验证性能瓶颈的来源。我们最不想浪费时间在代码库中追逐幽灵，而 5 分钟的分析器测试可以为我们节省一整天的工作。在很多情况下，解决方案需要进行成本效益分析，以确定我们是否在任何其他领域牺牲太多，从而冒着增加更多瓶颈的风险。请确保你对瓶颈的根本原因有合理的了解，以避免将其他性能指标置于风险之中。同时重申本书中第二重要的提示，在做出更改后，务必进行分析和测试，以确保其产生了预期的效果。

性能增强全在于解决问题，由于现代计算机硬件的复杂性，小的调整可以带来巨大的回报，这可以非常有趣。有许多技术可以实施以提高应用程序性能或加快我们的工作流程。有些技术如果没有必要的经验和技能来花费合理的时间来实施，就很难完全实现。在大多数情况下，如果我们花时间去找到并理解问题的根源，修复方法相对简单。所以，大胆前行，利用你的知识库，让你的游戏尽可能出色。
