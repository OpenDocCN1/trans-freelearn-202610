

## 前言

第 4 章，启动你的艺术，帮助你理解美术资产背后的底层技术，并学习如何避免导入、压缩和编码方面的常见陷阱。

第 5 章，更快的物理，是关于调查 Unity 内部物理引擎在 3D 和 2D 游戏中的细微差别，以及如何正确组织物理对象以提高性能。

第 6 章，动态图形，对渲染管线进行了深入探讨，以及如何改进在 GPU 或 CPU 上遭受渲染瓶颈的应用程序，如何优化光照、阴影和粒子效果等图形效果，优化 Shader 代码的方法，以及针对移动设备的一些特定技术。

第 7 章，虚拟速度和增强加速，专注于虚拟现实 (VR) 和增强现实 (AR) 这两种新的娱乐媒介，并包括针对为这些平台构建的应用程序特有的几种性能优化技术。

第 8 章，精通内存管理，探讨了 Unity 引擎、Mono 框架的内部工作原理，以及这些组件内部如何管理内存，以保护我们的应用程序免受过多的堆分配和运行时垃圾回收的影响。

第 9 章，战术技巧和窍门，以 Unity 专业人士用于改进项目工作流程和场景管理的大量有用技术结束本书。

## 本书所需内容

本书的大部分内容将侧重于适用于 Unity 2017 的功能和增强。本书中探讨的许多技术可以应用于 Unity 5.x 项目及更早版本，但功能列表可能看起来不同。这些差异将在适用的地方予以突出显示。

## 本书适用人群

本书面向中级和高级 Unity 开发者，他们拥有大多数 Unity 功能集的经验，以及那些希望最大化游戏性能或解决特定瓶颈的人。无论瓶颈是由持续的 CPU 过载、运行时 CPU 峰值、慢速内存访问、内存碎片、垃圾回收、不良的 GPU 填充率或内存带宽引起的，本书都将教你识别问题来源所需的技术，并帮助探索多种减少其对应用程序影响的方法。

涉及脚本和内存使用的部分需要熟悉 C# 语言，涉及 Shader 优化的部分需要基本了解 Cg。

## 追踪性能问题

大多数软件产品的性能评估是一个非常科学的过程。首先，我们确定支持的最大/最小性能指标，例如允许的内存使用量、可接受的 CPU 消耗量、并发用户数量等。接下来，我们针对为目标平台构建的应用程序版本，在特定场景下对应用程序进行负载测试，并在收集仪器数据的同时进行测试。收集这些数据后，我们分析并搜索其中的性能瓶颈。如果发现问题，我们完成根本原因分析，对配置或应用程序代码进行更改以修复问题，并重复此过程。

尽管游戏开发是一个非常艺术的过程，但它仍然非常技术化，因此有充分的理由以类似客观的方式对待它。我们的游戏应该有一个目标受众，这可以告诉我们游戏可能运行在什么样的硬件限制下，并可能告诉我们需要满足的具体性能目标（特别是在主机和移动游戏的情况下）。我们可以对应用程序进行运行时测试，从多个子系统（CPU、GPU、内存、物理引擎、渲染管线等）收集性能数据，并将其与我们认为可接受的数据进行比较。我们可以使用这些数据来识别应用程序中的瓶颈，进行额外的仪器测量，并确定问题的根本原因。最后，根据问题的类型，我们应该能够应用多种修复措施来改善应用程序的性能，使其更符合预期的行为。
