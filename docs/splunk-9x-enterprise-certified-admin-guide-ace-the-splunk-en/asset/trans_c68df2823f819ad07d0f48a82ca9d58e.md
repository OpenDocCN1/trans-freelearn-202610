

## 3. Splunk 中的用户、角色和身份验证

Splunk Enterprise 遵循**基于角色的访问控制（RBAC）**方法，该方法允许用户访问 Splunk 实例，但限制了用户能看到的内容以及他们可以执行的操作。作为 Splunk 系统管理员，熟悉 Splunk 的默认用户角色，并学习如何创建自定义角色以满足组织的特定需求，这一点非常重要。你还可能会被考察对角色继承（允许为单个用户分配多个角色）的理解，以及如何管理用户的索引访问权限。展示你能够使用 LDAP、SAML 等方法在 Splunk 中设置身份验证，这一点也很重要。这些技能在 Splunk Enterprise Admin 认证考试中会被测试，因为它们对于在 Splunk 环境中有效管理用户权限和访问至关重要。

以下是在采用 RBAC 方法时涉及的关键组成部分，我们将在本章中讨论这些内容，以及如何通过 Splunk Web 和 Splunk CLI 对它们进行配置：

-   用户
-   角色
-   身份验证方法

### 用户

如前几章所述，Splunk Enterprise 实例提供了多种界面——即 Splunk Web、Splunk CLI 和 RESTful API。所有界面都必须通过允许用户通过身份验证和授权安全登录来加以保护。身份验证方法将在本章末尾进行说明。组织可以通过配置角色、能力、对象级权限和**基于角色的访问控制（RBAC）**，使其与各个用户的岗位职责保持一致，从而有效管理用户授权。然后，用户可以根据分配到的 Splunk 角色来执行管理任务（特权用户）或普通用户任务（创建报告、警报、仪表板等）。在 Splunk 中，必须为用户分配至少一个角色。

### 创建新用户

可以通过 Splunk Web 或 Splunk CLI 创建新用户。这两种方式都需要管理员帐户详细信息来验证 Splunk 实例。系统管理员至少应了解以下详细信息才能完成用户创建过程：用户的全名，以及可以为用户分配的角色或用户在 Splunk 平台上需要具备的能力。

让我们看一下 CLI 命令，该命令用于添加名为 supportuser 的用户，密码为 changeme2，并分配 custom 角色 supportgroup。这里，admin:changeme 是管理员帐户用户名和密码，用 :（冒号）分隔：

```
./splunk add user supportuser -password changeme2 -role supportgroup -auth admin:changeme
```

类似地，还有更多 CLI 命令可用于编辑现有用户、解锁用户、重置用户密码等。你可以参阅 https://docs.splunk.com/Documentation/Splunk/9.0.0/Security/ConfigureuserswiththeCLI 上的 Splunk 文档了解更多详细信息。

下面让我们看看角色及其与用户的关联。

### 角色

角色被分配给用户，且用户至少必须被分配一个角色。角色包含一组能力，这些能力定义了用户可以在 Splunk 平台上执行哪些操作。换句话说，能力只不过是指定给某个角色的权限列表——例如，运行搜索、运行计划搜索、运行实时搜索等。

除了能力之外，角色还提供可配置选项，用于指定允许用户查询哪些索引、通过搜索过滤器方法进一步限制用户，以及设置配额，如磁盘空间限制和用户级搜索限制。以下截图显示了角色包含的可配置选项列表：

### 创建新角色

我希望你现在对角色及其重要性有了全面的了解，并且知道 Splunk 的默认角色。在本节中，让我们了解创建自定义角色的必要性，并逐步完成角色创建过程。

例如，为了理解新自定义角色的需求，我们考虑两个不同的索引：`web-access-data` 索引包含网站访问日志数据，`building-access-data` 索引包含建筑门禁日志数据。网站访问日志数据仅允许应用程序支持团队访问，建筑门禁日志数据仅允许建筑安全团队访问。在这种情况下，将为这两个团队创建两个不同的角色。

可以将 Splunk 默认角色分配给用户；然而，这取决于用户需要访问哪些索引、应允许哪些能力，以及磁盘配额、搜索配额等资源的分配。如果现有角色不满足用户需求，系统管理员可以通过可选地继承现有 Splunk 角色来创建新角色。继承现有 Splunk 角色的新角色会继承父角色的能力、索引访问权限和资源限制。

Splunk 不建议更改默认角色。如果你想编辑默认角色，建议的方法是克隆现有角色并更改所需的可配置选项。以下截图显示了**新建角色**创建表单：

![](img/5319cbd6f078c6cda7fac6347f77a07d_68_0.png)

上述截图显示了要分配给角色的名称，以及五个选项卡：**继承**选项卡用于选择现有角色，**能力**选项卡用于选择角色的能力，**索引**选项卡用于选择角色可访问的索引，**限制**选项卡用于对索引字段设置搜索过滤器，最后，**资源**选项卡用于限制角色级别和用户级别允许的磁盘空间和搜索配额。点击**创建**按钮将创建一个新角色，该角色将出现在**角色**网页上，如*图 3.5* 所示。

能力是应用于用户的细粒度权限，其列表相当长。你可以参阅 https://tinyurl.com/bdffj2s6 上的文档获取完整列表。另一个查看它们的地方是 https://tinyurl.com/2p8nvat9 上的 authorize.conf **规范（spec）**，其中包含最新的能力列表，因为这些列表可能会发生变化。

到目前为止，你已经了解了通过 Splunk Web 创建/编辑现有角色的过程。一般来说，Splunk Enterprise 在文件系统上包含与 Splunk Web 中显示的每个设置相对应的配置文件（.conf）。Splunk 会将你在 Splunk Web 中所做的每一项更改写入配置文件。让我们看一下 authorize.conf 文件，其中包含*图 3.6* 中每个选项卡的角色配置详细信息。

让我们看一下 admin 角色的示例 authorize.conf 片段。role_admin 在 Splunk 术语中被称为节（stanza），节的格式为 `role_<角色名称>`：

```
[role_admin]
# === 继承的角色 ===
importRoles = power;user
# === 能力 ===
accelerate_datamodel   = enabled
admin_all_objects      = enabled
### 许多此类能力已启用
# === 其他设置 ===
srchIndexesAllowed = *;_*
srchIndexesDefault = main;os
srchFilter          = *
srchDiskQuota       = 10000
srchJobsQuota       = 50
```

默认情况下，authorize.conf 文件位于 $SPLUNK_HOME/etc/system/default 目录中。如果你想通过配置方式创建新角色，Splunk 建议在 $SPLUNK_HOME/etc/system/local 系统目录或 `$SPLUNK_HOME/etc/apps/<app-name>/local` 应用本地目录中创建本地目录。为了使对配置文件所做的更改生效，建议重启 Splunk 实例。

有关所有 Splunk 配置文件的完整规范，请访问 $SPLUNK_HOME/etc/system/README 目录。你会找到扩展名为 .spec 和 .example 的文件。关于角色就介绍到这里。我建议你通过 Splunk Web 和 authorize.conf 规范文件来实践创建角色，以熟悉相关术语。请逐一浏览*图 3.6* 中显示的每个选项卡。
