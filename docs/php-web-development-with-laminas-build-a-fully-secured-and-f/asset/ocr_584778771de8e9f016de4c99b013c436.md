Yes, the SchoolClass->getByCode method is very similar to the SchoolClass->getByName method. It's good if you've noticed that. Don't worry because we will eliminate the repetition later. But now we need to focus on updating the school classes through the web interface. Since the page with the edit form was changed, let's change the save .php file, which is in charge of the persistence.

# Altering save.php

This file will be coded as follows:

```
<?php
use School\\SchoolClass;
require 'vendor/autoload.php';
$code = ($_POST['code'] ?? null);
$name = ($_POST['name'] ?? null);
$schoolClass = new SchoolClass((int)$code, $name);
$schoolClass->save();
header('Location: index.php');
```

Observe that we have only changed the incoming parameter code. The value of this parameter is what determines whether the operation is an insert or an update. With this change, you can now alter the name of inserted school classes. Try to insert several school classes and then, change the names of some of them.

And now, the moment everyone was waiting for – the removal of school classes.

# Creating the delete.php file

According to our component diagram and the hyperlink in the list.php file, the removal operation has to be inside the delete.php file. Let us create it:

# delete.php

```
<?php
use School\\SchoolClass;
require 'vendor/autoload.php';
$code = ($_GET['code'] ?? null);
$schoolClass = SchoolClass::getByCode((int)$code);
$schoolClass->delete();
header('Location: index.php');
```
