要查找RTSP问题，请将Wireshark实例通过端口镜像连接到遇到问题的客户端；如果有多个客户端，则将其连接到公共链路或服务器。

- 1. 要查看所有RTSP流量，请使用TCP端口554过滤数据包；对应的过滤器是`tcp.port==554`。

### 提示

过滤器`tcp.port == 554`会显示该端口上的所有流量，而过滤器`rtsp`只显示Wireshark识别为RTSP头的数据包。

- 2. 要查看RTSP请求和响应，请按本章前文所述，从**统计**菜单中选择**RTSP | 数据包计数器**。错误响应是代码值高于400的响应。

- 3. 查找4xx或更高的RTSP响应代码。为此，可以配置显示过滤器`rtsp.status >= 400`。

## 工作原理...

与SIP（用于信令，而RTP用于媒体传输）一样，RTSP控制的流可以使用任何传输协议；在许多情况下，它们也使用RTP。该协议在语法和操作上故意与HTTP相似，并使用相同的语法。

最常见的RTSP方法（命令）如下（C-客户端，S-服务器）：

| 命令 | 方向 | 功能 |
|---|---|---|
| OPTIONS | C到S或S到C | 确定服务器/客户端的能力 |
| DESCRIBE | C到S | 获取媒体流的描述 |
| ANNOUNCE | C到S或S到C | 宣布新会话的描述 |
| SETUP | C到S | 创建媒体会话 |
| PLAY | C到S | 开始媒体传输 |
| RECORD | C到S | 开始媒体录制 |
| PAUSE | C到S | 暂停媒体传输 |
| REDIRECT | S到C | 重定向到另一台服务器 |
| TEARDOWN | S到C | 立即执行拆除 |

响应类别如下：

| 代码系列 | 类型 | 含义 |
|---|---|---|
| 1xx | 信息性 | 请求已收到，继续处理 |
| 2xx | 成功 | 操作已成功接收、理解并被接受 |

## 更多内容...

在下面的截图中，您可以看到一个典型的RTSP流：

![](img/da40f92928403866599198344271d63e_925_0.png)

典型的RTSP流按以下顺序处理：

- 1. 向服务器发送**DESCRIBE**请求，要求从该服务器检索请求URL所标识的演示或媒体对象的描述，服务器回复**200 OK**。
- 2. **GET_PARAMETER**请求检索URI中指定的演示或流的参数值。
- 3. 发送**SETUP**请求以打开音频流，并用**200 OK**确认。
- 4. 发送**SETUP**请求以打开音频流，并用**200 OK**确认。
- 5. 向服务器发送**PLAY**请求以开始播放流。
- 6. 向服务器发送**SET_PARAMETER**请求，以设置URI指定的演示或流的参数值。
- 7. 流开始使用RTP播放。

在下面的截图中，我们看到了流的分解过程：

![](img/da40f92928403866599198344271d63e_925_1.png)

流的分解过程如下：

- 1. 向服务器发送**SET_PARAMETER**，以设置URI指定的演示或流的参数值。
- 2. 向服务器发送第二个**SET_PARAMETER**请求。
- 3. 发送**TEARDOWN**命令以关闭连接。

## 第13章 排除带宽和延迟问题

本章包含以下方案：

- - 测量通信链路上的总带宽
- - 通过网络连接测量每个用户和每个应用的带宽和吞吐量
- - 使用Wireshark监控抖动和延迟
- - 发现与延迟/抖动相关的应用问题

## 简介

在测量通信线路时，我们应该注意四个主要参数：**带宽**、**延迟**、**抖动**和**数据包丢失**。虽然有些应用需要高带宽，但也有其他应用对延迟和抖动更敏感。数据包丢失会影响所有类型的应用，但有些应用对其更敏感，有些则不那么敏感。

在本章中，我们将学习如何测量这些参数，如何检查由此引起的网络问题，以及如何在可能的情况下解决它们。

## 测量通信链路上的总带宽

在本方案中，我们将了解如何测量通信线路上的总带宽。首先当然是要与服务提供商核实通信线路。检查它是对称线路还是非对称线路；如果是非对称线路，请检查两个方向上的带宽是多少。

## 准备工作

您可能需要测试两种情况：

- - 当您测量两个办公室之间的通信线路时：在这种情况下，将您的笔记本电脑（或网络上的任何PC）连接到局域网，并确认线路另一端是否有服务器或另一台PC
- - 当您测量到互联网的通信线路时，请确保您在**服务提供商（SP）**端或**互联网服务提供商（ISP）**端有一台测试服务器

## 如何操作...

要检查通信线路上的带宽，请按照以下步骤操作：

- 1. 询问以下详细信息：
  1. 询问SP线路带宽是多少。
  2. 如果是到互联网的线路，除了前一步外，还要询问ISP到互联网的带宽是多少。
- 2. 在远程位置找到服务器、PC或笔记本电脑。

### 提示

使用PC或笔记本电脑进行测试时，请不要忘记PC本身应足够强大以生成流量。一台标准的Windows 7机器每个TCP连接大约能生成200 Mbps；当打开多个连接时，可能会遇到其他限制，如磁盘性能等。因此，建议先在局域网上试传输（实际上没有带宽限制），然后再测试SP或ISP线路。如果使用FTP，请使用高效的FTP工具（例如FileZilla）。当然，最好的方法是使用测试设备（如果可用）。专门的测试设备可从许多供应商处获得，例如VeEX、Fluke Networks和IXIA。

- - 如果您想测试两个站点之间的带宽，请在编号为1和2或编号为1和3的节点之间下载然后上传一个大文件。足够大的文件应能在线路上加载一段可观的时间，即一分钟或更长时间。例如，如果您想测试10 Mbps（兆比特每秒）的线路，请使用至少10/8 = 1.25 MB（兆字节）的文件。
- - 如果您想测试到互联网的连接，通常可以先在服务提供商（下图中编号为1到4）上进行测试，然后再到互联网服务提供商（下图中编号为1到5）上进行测试。

### 提示

如果可能，最好使用IP或UDP测试，因为复制文件是通过TCP进行的，所以可能会遇到影响测试的TCP问题。为此，请使用Iperf或其他可以生成IP或UDP流量的测试工具。

在下图中，您可以看到两个通过服务提供商（SP）线路连接的本地网络。左侧站点通过防火墙连接到互联网。到互联网的连接通过服务提供商（SP，服务器4）到达互联网服务提供商（ISP，服务器5）。

![](img/da40f92928403866599198344271d63e_932_0.png)

按照以下步骤测量通信线路上的带宽：

- 1. 使用Wireshark的“统计 | IO 图”进行测试。

### 提示

不要忘记Wireshark在处理高带宽线路时有其自身的局限性。在这种情况下，您可以将其配置为使用多个文件。就我个人而言，在监控200-300 Mbps及更高带宽的线路时，我更喜欢使用其他工具（例如Omnipeek）。

- 2. 测试企业网络时，您可以使用诸如Iperf（http://sourceforge.net/projects/iperf/）之类的软件工具。
