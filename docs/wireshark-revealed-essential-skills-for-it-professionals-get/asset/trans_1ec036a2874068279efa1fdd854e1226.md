

## Introduction

Wireshark 最强大的功能之一是能够分析网络现象并为其提供可能的原因。 除了其他工具之外，它还能为我们提供有关网络性能和问题的详细信息。 在本章中，我们将学习专家系统。 它是一个工具，可为我们提供对网络现象（包括事件和问题）的更深入分析。 在本书后面，我们将提供有关如何使用 **Expert Infos** 窗口以及其他工具来查找和解决网络问题的详细配方。

在第一个配方中，我们将学习如何使用 **Expert Infos** 窗口。 在接下来的配方中，我们将了解您可能遇到的大多数事件的可能原因。

## The Expert Infos window and how to use it for network troubleshooting

**Expert Infos** 窗口为我们提供了 Wireshark 发现的事件和网络问题的列表。 在本配方中，我们将学习如何启动 **Expert Infos** 窗口以及如何引用各种事件。

### Getting ready

启动 Wireshark，并开始实时捕获或打开现有文件。

### How to do it...

要启动 **Expert Infos** 窗口，请执行以下步骤：

导航到 **Analyze** 菜单并单击 **Expert Info**。 以下窗口将打开：

![](img/da40f92928403866599198344271d63e_546_0.png)

现在您可以选择任意一个上部栏： **Errors:**、 **Warnings:**、 **Notes:**、 **Chats:**、 **Details:** 或 **Packet Comments:**。

### Tip

栏右侧的数字显示此类别中的事件数量。

上部栏为您提供以下信息：

- **Errors:** 这些是严重问题，主要是畸形数据包或协议头中缺少字段。 这些可以是各种类型的畸形数据包，例如畸形 SPOOLSS、GTP 或其他。 这些也可以是校验和错误，例如 IPv4 校验和错误。

  在以下屏幕截图中，您可以看到畸形的 TCP 和 SSL 数据包：

  ![](img/da40f92928403866599198344271d63e_547_0.png)

  在以下屏幕截图中，您可以看到另一种类型的错误，即协议（在本例中为 **BOOTP/DHCP**）选项错误，即 Wireshark 识别出数据包中缺少字段时：

  ![](img/da40f92928403866599198344271d63e_547_1.png)

- **Warnings:** 警告表示应用程序或通信中的问题，例如 TCP 零窗口、TCP 窗口已满、先前段未捕获、乱序段等，这些都是协议行为不自然的情况。 您可以在以下屏幕截图中看到一个示例：

  ![](img/da40f92928403866599198344271d63e_548_0.png)

- **Notes:** 当 Wireshark 指示可能导致问题但仍在协议正常行为范围内的事件时，就会显示注释。 例如，TCP 重传将显示在这里，因为尽管它是一个会减慢网络速度的严重问题，但它仍属于 TCP 的正常行为。 此处的其他事件有重复 ACK、快速重传等。

- **Chats:** 此选项卡提供有关常规工作流程的信息，例如 TCP 连接开始（SYN）、连接结束（FIN）、连接重置（RST）、HTTP POST、HTTP 代码等。

- **Details:** 此选项卡按有序列表提供所有事件。 在旧版本的 Wireshark 中，这直接位于 **Analyze** 菜单下。

- **Packet Comments:** 您可以手动为每个数据包添加注释。 此列将显示捕获文件中的所有注释。

要为数据包添加注释，请右键单击它并选择 **Packet Comment…**。 将打开一个窗口，您可以在其中添加或更改注释。 您可以在以下屏幕截图中看到这一点：

![](img/da40f92928403866599198344271d63e_549_0.png)

要转到数据包捕获窗格中的事件，只需单击 Expert Infos 窗口中事件下的该数据包即可，它会带您前往该位置。

### Note

需要注意的是，虽然警告事件可能无关紧要，但注释事件可能会严重影响网络。 始终深入了解问题细节，查看其来源以及其含义。

### There's more...

专家信息严重性也可以通过显示过滤器进行过滤并在数据包窗格中显示。 要根据显示过滤器查看事件，请执行以下步骤：

1. 单击显示过滤器窗口右侧的 **Expression...**。
2. 向下滚动以获取 **Expert** 消息（您只需输入单词 `expert` 即可到达）。

如以下屏幕截图所示，您将获得以下过滤器：

```
expert.message, expert.group, and expert.severity:
```

![](img/da40f92928403866599198344271d63e_551_0.png)

- `expert.group` 指专家消息组。 此过滤器根据其类型对问题进行分类，例如校验和问题、TCP 序列相关问题等。 请看以下屏幕截图，您将看到这些问题的列表：

  expert.group 中的主要类别如下：

  - **Checksum**: 表示校验和无效。
  - **Sequence**: 表示 TCP 序列相关问题。
  - **Response**: 表示应用程序响应代码问题（4xx 响应代码）。
  - **Request**: 表示应用程序请求。
  - **Undecoded**: 表示解剖器无法解码的数据。
  - **Reassemble**: 表示在重新组装时出现问题（通常是片段丢失时）。
  - **Malformed**: 表示畸形数据包或解剖器问题，并且该数据包的解剖被中止。
  - **Debug**: 表示调试（不应出现在发布版本中）。
  - **Protocol**: 表示违反协议规范（例如缺少字段、长度错误等），该数据包的解剖可能仍会继续。
  - **Comment**: 表示已为其添加注释的数据包（可以通过右键单击数据包并选择 Packet Comment … 选项来添加注释）。

- `expert.message` 指特定的消息。 在这里，例如，您可以配置一个过滤器来显示包含或匹配特定字符串的消息。
- `expert.severity` 指具有特定严重性的消息，即错误、警告、注释等。

您还可以选择在 **Expert Info** 窗口上显示事件严重性。

1. 导航到 **Edit | Preferences…**。
2. 选择 **User Interface**。
3. 在右窗格的下半部分，标记 **Display LEDs in the Expert Infos dialog tab labels:** 复选框，如以下屏幕截图所示：

   ![](img/da40f92928403866599198344271d63e_553_0.png)

4. 单击 **OK**。
5. 打开 **Expert Infos** 窗口，严重性 LED 将出现在每个栏上。

![](img/da40f92928403866599198344271d63e_553_1.png)

严重性级别 LED 也将出现在 Wireshark 主窗口的左下角。

## Error events and understanding them

在本配方中，我们将深入了解错误和事件类型、校验和错误、畸形数据包和其他类型的错误，以及我们可以从中了解的内容。

### How to do it...

1. 从 **Analyze** 菜单打开 **Expert Infos**，单击 **Expert Info**。
2. 单击 **Errors:** 栏（应默认打开）。 您将获得以下窗口（所有事件均为示例）：

   ![](img/da40f92928403866599198344271d63e_558_0.png)

在前面的窗口中，您可以看到以下两种类型的错误：

- **Checksum errors:** 这些可能出现在以太网、IP 或其他协议中。 在这种情况下，这可能是由于真实错误或卸载造成的。
- **Malformed packets:** 这些通常出现在应用程序协议中。 在这种情况下，也可能是由于真实问题或解剖器错误造成的。
