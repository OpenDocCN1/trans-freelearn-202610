## Lists Group Related Items

HTML supports two main list types.

**Unordered lists** use the `<ul>` tag:

```
<ul>
  <li>Milk</li>
  <li>Bread</li>
  <li>Eggs</li>
</ul>
```

This means a list in which order does not matter.

**Ordered lists** use the `<ol>` tag:

```
<ol>
  <li>Preheat the oven</li>
  <li>Mix ingredients</li>
  <li>Bake for 30 minutes</li>
</ol>
```

This means *steps in a specific sequence*.

Each **list item** lives inside `<li>`.

## Tables Structure Data, Not Layout

Tables are for data, not page layout:

```
<table>
  <tr>
    <th>Name</th>
    <th>Age</th>
  </tr>
  <tr>
    <td>Alex</td>
    <td>32</td>
  </tr>
</table>
```

Conceptually:

- `<table>` wraps the data
- `<tr>` is a **table row**
- `<th>` is a **table header** cell
- `<td>` is a **table data** cell

Tables are best when showing:

- Prices
- Schedules
- Statistics
- Comparisons

Using tables to position content for layout is an outdated practice and causes accessibility problems.

## HTML Elements Nest Inside One Another

HTML elements form a tree structure.

Example:

```
<body>
  <section>
    <h2>About me</h2>
    <p>I write books.</p>
  </section>
</body>
```

Here:

- `<section>` lives inside `<body>`
- `<h2>` and `<p>` live inside `<section>`

This nesting is how browsers understand relationships between content.

## Using `<div>` as a Generic Container

Sometimes you need to group several pieces of content together without adding any specific meaning. That is what the `<div>` element is for.

A `<div>` is a generic block-level container. It does not tell the browser or a screen reader what the content means. It simply groups content together.

For example:

```
<div>
  <h2>About this book</h2>
  <p>This book teaches web development with AI as a learning partner.</p>
</div>
```

This can be useful when you want to style or script a group of elements later with CSS or JavaScript.

But `<div>` should not be your first choice when a semantic element fits better. If the content is a section of the page, use `<section>`. If it is navigation, use `<nav>`. If it is a paragraph, use `<p>`. If it is the page footer, use `<footer>`.

A good beginner rule is this: use `<div>` when you need a container, not when you need meaning. A page full of `<div>` elements can still work, but it tells humans and tools much less about the structure of the content. Semantic elements make your HTML easier to read, easier to maintain, and more accessible.

## HTML Describes Meaning, Not Appearance

For beginners, this distinction makes the rest of the web technology stack easier to understand.

HTML answers questions like:

- Is this a heading?
- Is this a paragraph?
- Is this navigation?
- Is this a list of items?
- Is this tabular data?

HTML does not answer:

- Should this be blue?
- Should this be centered?
- Should this animate?

That separation is deliberate. It keeps the web flexible, accessible, and device-independent.

**Good practice:** Do not try to memorize every HTML tag. Start by asking what each piece of content is. Is it the main heading? A paragraph? A navigation link? A list of steps? A table of data? Once you can answer those questions, the tags become easier to choose, and AI-generated HTML becomes easier to review.

## What Good Structure Gives You

When HTML is written properly:

- Browsers can display it correctly on any screen size
- Search engines understand the content
- Screen readers can navigate the page
- CSS and JavaScript become easier to apply later

A page can look fine in a browser while still having poor structure or accessibility.

Well-structured HTML is easier to maintain. Bad HTML creates maintenance problems almost immediately.

## HTML DOM (Document Object Model)

The HTML **DOM** (**Document Object Model**) is how the browser represents an HTML page internally after it has been loaded. Instead of thinking of your page as plain text, the browser turns it into a tree of objects that it can understand, manipulate, and render.

Let’s see how it works with a simple HTML example:

```
<!DOCTYPE html>
<html>
  <head>
    <title>My Page</title>
  </head>
  <body>
    <h1>Hello</h1>
    <p>This is a paragraph.</p>
  </body>
</html>
```

When the browser reads the preceding code, it does not keep it as raw text. It parses the HTML and builds a tree structure, where each element becomes a node:

```
Document
 └── html
      ├── head
      │    └── title
      │         └── "My Page"
      └── body
           ├── h1
           │    └── "Hello"
           └── p
                └── "This is a paragraph."
```

Here is how to think about this:

- `Document` is the root of everything
- Each HTML element becomes a node in the tree
- Elements can have child nodes (like `<body>` containing `<h1>` and `<p>`)
- Text inside elements also becomes nodes

This structure reflects the nesting you write in HTML. If you nest elements incorrectly, the DOM will also be incorrect, which can lead to confusing behavior.

What the browser actually does (step by step):

1. It downloads the HTML file
2. It reads it from top to bottom
3. It parses each tag and creates nodes
4. It builds the DOM tree in memory
5. It uses that tree to render the page

The DOM is not just for display. CSS uses the DOM to decide what to style, and JavaScript uses the DOM to read and change the page dynamically after the page is initially rendered. For example, JavaScript can do things like:

- Change text inside `<h1>`
- Add new elements
- Remove elements
- Respond to user actions

HTML is the source document. The DOM is the browser’s live tree built from that document. Once the page is loaded, the browser works with the DOM, not your original HTML file. The DOM is the browser’s internal representation of your HTML as a tree of objects. If your HTML structure is clean and logical, the DOM will be easy to work with. This is why logical thinking about structure matters more than raw typing speed.

## The Beginner Takeaway

If you remember only one thing from this chapter, it should be this:

HTML is about what content is, not how it looks.

Once you understand that distinction, HTML, CSS, and JavaScript make more sense as separate tools.
