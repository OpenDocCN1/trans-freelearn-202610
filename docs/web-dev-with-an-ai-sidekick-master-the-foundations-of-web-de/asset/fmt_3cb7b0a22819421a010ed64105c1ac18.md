
In the next section, we will use `DigitalOcean` as our hosting provider. It offers a straightforward way to create and manage virtual servers, with predictable pricing and strong documentation. More importantly, it allows us to focus on understanding deployment rather than wrestling with infrastructure complexity.

## Why `DigitalOcean` is a good fit for `TallyApp`

I chose to use `DigitalOcean` as my host provider because it sits in a useful middle ground between too abstract platforms that hide everything and hyperscale clouds that overwhelm beginners with options and pricing complexity.

For a project like `TallyApp`, it is arguably useful for learning because it forces you to understand what is happening during deployment, without drowning you in enterprise concerns.

The biggest advantage is simplicity. You can go from zero to a public server in minutes using a `Droplet`, which is just a virtual machine. That maps nicely to how `Django` is traditionally deployed, using tools like `Gunicorn` and `Nginx`.

The documentation is strong and beginner-friendly. `DigitalOcean` has spent years building tutorials specifically for common stacks like `Django`, including step-by-step guides for `Ubuntu`, `Gunicorn`, and `Nginx`. You can read the `DigitalOcean` documentation tutorials at the following link: [https://www.digitalocean.com/community/tutorials](https://www.digitalocean.com/community/tutorials).

`DigitalOcean` VPS also gives you full control. You will learn how web servers, reverse proxies, and application servers fit together, rather than relying on a black-box platform.

### The downsides you should be aware of

The trade-off for simplicity is that you are responsible for more things yourself.

You are managing a server. That means:

* Applying security updates
* Configuring firewalls
* Managing processes and services
* Handling scaling manually

There is no automatic scaling. If your site suddenly gets popular or attacked, a single `Droplet` can become overwhelmed.

You still own application security because it is not fully managed. Unlike platforms such as `Heroku` or `Vercel`, `DigitalOcean` does not automatically handle many application-level protections. You need to configure them.

Backups and monitoring are optional add-ons. They are not fully integrated by default unless you enable them.

### Is it suitable for a public demo like `TallyApp`?

Yes, with one condition: you must add a thin layer of protection in front of it. A single low-cost `Droplet` is perfectly capable of running a `Django` app with light to moderate traffic. For a book companion site, that is usually more than enough.

However, exposing a raw server directly to the internet is not ideal. Without additional protection, it will quickly receive:

* Bot traffic scanning for vulnerabilities
* Login brute-force attempts
* Crawlers and scrapers
* Occasional traffic spikes

This is where combining `DigitalOcean` with a proxy layer becomes important.

### What protection `DigitalOcean` provides

`DigitalOcean` gives you infrastructure-level security, but not full application protection.

Included protections:

* Basic network isolation through virtual private networking
* Cloud firewalls to restrict inbound traffic by port and IP
* Secure Shell (`SSH`) key authentication instead of passwords
* Datacenter-level physical security
* `DDoS` protection at the infrastructure level (limited and not deeply configurable)

These are useful server-level protections, but they do not protect against:

* Application-layer attacks (for example, login abuse)
* `XSS` or `CSRF` issues
* Misconfigured `Django` settings
* Bot traffic targeting your endpoints

Some useful features are available but require enabling or additional cost, as shown in `Table 15.2`:

| **Feature** | **Description** |
| --- | --- |
| Backups | Automatic backups typically cost around 20% of the `Droplet` price. |
| Monitoring and alerts | Basic monitoring is available, but you need to configure alerts yourself. |
| Load balancers | Start at around $12 per month. Useful if you scale beyond a single server. |
| Managed databases | More expensive than self-hosting `PostgreSQL`, but reduce operational risk. |

`Table 15.2`: `DigitalOcean` features that can be enabled

## The missing piece: edge protection

`DigitalOcean` gives you the server, but it does not filter every bad request before it reaches your app. This is where adding `Cloudflare` (or a similar service) in front of your `Droplet` enhances your protection.

With even a free `Cloudflare` plan, you get:

* `CDN` caching for static content like `CSS` stylesheets and images
* Basic `DDoS` protection
* Bot filtering
* `TLS` termination (`HTTPS` handled at the edge)

At a low cost, you can add:

* Rate limiting (for login and forms)
* Web Application Firewall (`WAF`) rules

When paired with a simple edge service like `Cloudflare` and good `Django` configuration, `DigitalOcean` plus `Cloudflare` and correct `Django` settings is enough for a small public `TallyApp` deployment.

## Deploying step-by-step

You will benefit more from understanding deployment than from taking the shortest path to a working server.

We will standardize on the following target stack: a small `Droplet` for the app server, `Ubuntu` `LTS`, `SQLite` for database simplicity, `Nginx` as reverse proxy, `Gunicorn` for `Django`, `Uncomplicated Firewall (UFW)`, and optional backups. That is suitable for a public demo app with modest traffic.

### Create a `DigitalOcean` `Droplet`

Now we can create a `Droplet` to host our website project:

1. Register a `DigitalOcean` account at the following link: [https://cloud.digitalocean.com/](https://cloud.digitalocean.com/)
2. On your account’s `Projects` page, you will already have a default project, often named `first-project`. We can leave this as-is.
3. Click `Create`, and then click `Droplets`, as shown in `Figure 15.3`:

![](Images/B34553_15_03.png)

`Figure 15.3`: Creating a `Droplet`

4. Select a region, either close to most of your expected visitors, or close to you. I chose `New York`.
5. Select an image for your operating system. I chose `Ubuntu 24.04 (LTS) x64`.
6. Select the `Droplet` size. I chose:
   * Basic (shared CPU)
   * Regular SSD
   * $12 per month
   * 2 GB / 1 CPU
   * 50 GB SSD Disk
   * 2 TB transfer
7. Optionally, enable an automated backup plan. I chose `Daily Backups` at a cost of $3.60 per month. Backups are kept for one week. For the time window, I chose midnight to 4 a.m. in the Eastern US time zone.
8. Select an authentication method. I chose `SSH`. Click `Add SSH Key` and follow the instructions. You must name the `SSH` key (I used `tallyapp-sshkey`) and it will create two files. The file without `.pub` is your private key. Keep it private. The `.pub` file is the public key you copy to `DigitalOcean`.

You can learn more about how to connect to `Droplets` using `SSH` at the following link: [https://docs.digitalocean.com/products/droplets/how-to/connect-with-ssh/](https://docs.digitalocean.com/products/droplets/how-to/connect-with-ssh/)

9. Click `Create Droplet`.
10. Note the `IP` address assigned to your server, as shown in `Figure 15.4`:

![](Images/B34553_15_04.png)

`Figure 15.4`: Your server’s `IP` address

11. At the command prompt or terminal, enter the command to connect to your remote server using the private `SSH` key file you created earlier, the default `root` user account, and the `IP` address of the remote server:

```
ssh -i tallyapp-sshkey root@167.99.52.197
```
