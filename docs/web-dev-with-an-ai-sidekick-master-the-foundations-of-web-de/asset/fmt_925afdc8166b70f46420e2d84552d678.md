
# SQL Joins and Aggregates

```sql
SELECT t.name AS series_name,
       s.season_no,
       e.episode_no,
       e.name AS episode_name
FROM titles t
JOIN seasons s  ON s.title_id = t.title_id
JOIN episodes e ON e.season_id = s.season_id
WHERE t.name = 'Star Trek: The Next Generation'
ORDER BY s.season_no, e.episode_no;
```

Each `JOIN` keyword connects tables using primary keys and foreign keys. You are not merging tables blindly. You are following relationships defined in the schema.

`titles t` and `seasons s` are examples of a table alias. It is shorthand that gives a table a temporary name for the duration of the query. `t` is an alias for the `titles` table. For the rest of the query, `t` and `titles` mean the same thing.

When queries involve joins, repeating full table names quickly becomes annoying. Also, when multiple tables have columns with the same name, aliases are required to disambiguate.

For example, both `titles` and `seasons` contain a `title_id` column. Without aliases, the database cannot know which one you mean, as shown in the following code:

```sql
SELECT title_id
FROM titles
JOIN seasons ON seasons.title_id = titles.title_id;
```

The preceding code is ambiguous and will fail.

We can clarify what we mean with table aliases, as shown in the following code:

```sql
SELECT t.title_id
FROM titles t
JOIN seasons s ON s.title_id = t.title_id;
```

Now the query is unambiguous.

## Querying many-to-many relationships

Actors and titles have a many-to-many relationship through the `credits` table. This table is where the relationship lives.

To list the acting cast of a film we need to join four tables (`credits`, `titles`, `people`, and `roles`), as shown in the following code:

```sql
SELECT t.name AS title,
       p.full_name,
       c.character_name
FROM credits c
JOIN titles  t ON t.title_id = c.title_id
JOIN people  p ON p.person_id = c.person_id
JOIN roles   r ON r.role_id = c.role_id
WHERE t.name = 'The Matrix'
  AND r.role_name = 'actor'
ORDER BY p.full_name;
```

This query shows why junction tables matter. The character name belongs to the relationship between a person and a title, not to either table on its own.

## Types of joins

Joins are how SQL recombines related data stored in separate tables. Each `JOIN` type answers a slightly different question about how rows from two tables should be matched. The differences matter, because they control which rows appear in the result and which are excluded.

### INNER JOIN

An `INNER JOIN` returns only rows where a match exists in both tables. This is the most commonly used join and is often what people mean when they just say `JOIN`. In fact, you can just use `JOIN` instead of the full syntax `INNER JOIN`, as shown in the following code:

```sql
SELECT t.name, s.season_no
FROM titles t
JOIN season s ON s.title_id = t.title_id;
```

This returns only titles that actually have seasons. If a title has no seasons, it does not appear at all. Think of `INNER JOIN` as *only where both sides agree*.

### LEFT JOIN (LEFT OUTER JOIN)

A `LEFT JOIN` returns all rows from the left table, and matching rows from the right table. If there is no match, the right-side columns are returned as `NULL`:

```sql
SELECT t.name, s.season_no
FROM titles t
LEFT JOIN seasons s ON s.title_id = t.title_id;
```

This returns every title, even films or series with no seasons. For those rows, `season_no` will be `NULL`. `LEFT JOIN` is used when the left table represents the thing you care about, and the right table is optional.

**Good practice**: A very common mistake is putting conditions on the right table in the `WHERE` clause, which turns a `LEFT JOIN` back into an `INNER JOIN`. Conditions that apply to the joined table should usually go in the `ON` clause instead.

### RIGHT JOIN (RIGHT OUTER JOIN)

A `RIGHT JOIN` is the mirror image of a `LEFT JOIN`. It returns all rows from the right table, and matching rows from the left table:

```sql
SELECT t.name, s.season_no
FROM titles t
RIGHT JOIN seasons s ON s.title_id = t.title_id;
```

In practice, `RIGHT JOIN` is rarely needed. The same result can almost always be expressed more clearly by swapping table order and using `LEFT JOIN` instead. Many teams avoid `RIGHT JOIN` entirely for readability.

**Warning!** `RIGHT JOIN` was added to SQLite in version 3.39.0 back in 2022. If you're using an older SQLite version or certain tools that bundle older versions, `RIGHT JOIN` may not work. You can always rewrite a `RIGHT JOIN` as a `LEFT JOIN` by swapping the table order.

### FULL JOIN (FULL OUTER JOIN)

A `FULL JOIN` returns:

- Rows that match on both sides
- Rows that exist only in the left table
- Rows that exist only in the right table

Where no match exists, columns from the missing side are `NULL`.

```sql
SELECT t.name, s.season_no
FROM titles t
FULL JOIN seasons s ON s.title_id = t.title_id;
```

This is useful for reconciliation and comparison queries, such as finding records that exist in one table but not the other.

**Warning!** SQLite does not support `FULL JOIN` directly. In SQLite, it must be simulated with a `UNION` of `LEFT JOIN` and `RIGHT JOIN` logic.

### CROSS JOIN

A `CROSS JOIN` produces the Cartesian product of two tables. Every row from the first table is paired with every row from the second table.

```sql
SELECT t.name, r.role_name
FROM titles t
CROSS JOIN roles r;
```

If there are 5 titles and 3 roles, the result has 15 rows.

`CROSS JOIN` is rarely used accidentally, because the result size grows very quickly. When it is used deliberately, it is usually for generating combinations, test data, or reference matrices.

### SELF JOIN

A `SELF JOIN` is not a separate join type, but a pattern. It is any join where a table is joined to itself using aliases.

```sql
SELECT t1.name, t2.name
FROM titles t1
JOIN titles t2
  ON t1.universe = t2.universe
  AND t1.title_id <> t2.title_id;
```

This compares rows within the same table. Self joins are common in hierarchies, comparisons, and graph-like relationships.

## Aggregates: asking summary questions

SQL is very good at answering questions about groups of rows. Some commonly used functions include the following:

- `COALESCE(expression1, expression2, ...)`: returns the first non-`NULL` value from a list of expressions. You give it two or more values or expressions, and it picks the first one that is not `NULL`. `COALESCE(universe, 'Standalone')` means, *if universe has a value, use it. If it is NULL, use 'Standalone' instead*.

- `COUNT(*)`: Returns the number of rows in the result set or in each group. It counts rows, not values, and it includes rows even if some columns contain `NULL`.
