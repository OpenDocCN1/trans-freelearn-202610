
# Study: AI Assistance and Learning Outcomes

**AI-assisted group**: Participants could use an AI coding assistant during the task.

**Control group**: Participants did not have AI assistance but could use documentation and web search.

Each participant completed two feature-building tasks using Trio. After finishing, they all took a quiz designed to measure mastery of the concepts they had just worked with. The quiz covered debugging, code reading, code writing, and conceptual understanding.

## Key Findings

* On average, developers who used AI scored significantly lower on the post-task quiz (about 50 percent) compared to those who coded without AI (about 67 percent). This represented a 17 percent gap, roughly equivalent to two letter grades in a typical academic setting.
* The biggest differences were observed on debugging and conceptual understanding questions, indicating that AI use was associated with weaker mastery of those skills.
* The AI-assisted group finished the coding tasks only slightly faster, but this time difference was not statistically significant.
* Qualitative analysis showed that some participants spent substantial time composing AI prompts (up to 30 percent of total time in some cases), which ate into potential efficiency gains.

## Researcher Conclusions

* AI assistance can undermine learning when people are acquiring a new, unfamiliar skill. Relying on the assistant to generate and debug code appears to reduce the cognitive effort that builds deep understanding.
* Not all AI use is the same. Some participants who used AI mainly to ask conceptual questions or request explanations alongside generated code performed much closer to the control group. Those who offloadeds and trending info pulled from social feeds; often associated with memes |

Chatbots like ChatGPT, Gemini, Claude, Perplexity, or Grok focus mainly on natural language interaction. They handle writing, summarizing, general research, and can also support coding queries, but coding assistance is just one of many tasks. They are best used as code and framework learning mentors.

AI coding assistants such as GitHub Copilot, Codex, or Cursor are optimized for developer workflows. They integrate with code editors and IDEs, suggest completions, generate project-specific code, and can assist with debugging and tests.

GitHub Copilot lets you choose between multiple coding AI models. For example, Copilot itself, Anthropic’s Claude, and OpenAI’s Codex. This means you’re not locked into a single model; you can pick whichever agent best fits your task.

Ollama and similar local LLM frameworks let you run a wide variety of LLMs on local desktop or server hardware. Models like `Qwen3-Coder`, `StarCode2`, `Codestral`, `Devastral`, and so on are open source and optimized for coding tasks. You can run them locally through Ollama without ever sending data to the cloud.

If you care about data privacy, offline use, full control, and avoiding cloud APIs, then you want local LLM frameworks like Ollama with open-source coding models. **Bring Your Own Key (BYOK)** model support is a fast-moving feature set, and some capabilities may differ between chat, inline chat, and completions.

If you want the easiest start, use Copilot Free (cloud). You get a monthly allowance without configuring any keys.

If you want the best quality and do not mind API spend, keep Copilot models for day-to-day coding and optionally add your OpenAI API key so you can use specific provider models when needed.

If you want to avoid per-request costs and keep data local, run Ollama and select it via VS Code’s model management so Copilot Chat can use a local model for many tasks.

I have written an online-only article to cover use of local models in detail: `https://github.com/markjprice/markjprice/blob/main/with-ai/local-models.md`

Local setups are better in specific areas:

* **Privacy**: No code leaves your machine. Useful for proprietary or sensitive work
* **Cost (long-term)**: No per-token billing. Heavy usage becomes cheaper over time
* **Latency**: Instant response for small models. No network dependency
* **Control**: You can fine-tune. You can customize behavior

A practical setup is to use both cloud and local models, but for different jobs:

* Use cloud models when you need stronger reasoning, larger context, or help comparing design options
* Use local models when the task is small, private, or repetitive: explaining syntax, drafting a helper function, refactoring one file, or sketching tests

**Good practice**: If the task requires judgment, not just generation, use a cloud model.
