
# Event Handlers and Arrow Functions

The second argument is a function. This function is called the `event handler`:

```
() => {
  counter = counter + 1;
  renderCounter();
}
```

This is an `arrow function`. It defines a small, anonymous function with no parameters. You are not calling it yourself. The browser will call it automatically every time the button is clicked.

`counter` is a variable that lives outside the function. Each click increases its value by one. Because the function runs again on every click, the value keeps increasing over time.

Typically, `renderCounter` reads the current value of counter and writes it into the DOM so the user can see the new number.

One detail matters here: timing. None of the code inside the arrow function runs until the user clicks the button. JavaScript finishes loading the page, sets up the event listener, and then waits. When the click happens, the browser calls the handler function at the right moment.

In plain English, this code means: *When the increment button is clicked, increase the counter by one and then update the display to match.*

# Conditionals: if / else with Booleans and comparisons

Decisions in JavaScript are made using `conditional statements`. The most common is the `if` statement. It allows your code to choose between different paths based on whether something is `true` or `false`.

For example, you might check whether a form field is empty before allowing submission. This is how JavaScript chooses one path instead of running the same code every time.

This section uses the input field and checks whether the user typed anything. It also introduces comparisons and truthiness in a beginner-friendly way.

In `index.html`, after the existing `<script>` elements, add a new `<script>` element to reference a new code file named `conditionals.js`, as shown in the following code:

```
<script src="conditionals.js"></script>
```

In the same folder as the HTML file, create the code file named `conditionals.js`, and enter the following code:

```
const nameInput = document.querySelector("#nameInput");
const helloBtn = document.querySelector("#helloBtn");
statusElement.textContent = "Status: Demonstrating conditionals.";
helloBtn.addEventListener("click", () => {
  const typedName = nameInput.value; // string (possibly empty)
  if (typedName.trim() === "") {
    messageElement.textContent = 
      "Message: Please type your name first.";
  } else {
    messageElement.textContent = 
      `Message: Hello, ${typedName}!`;
  }
});
```

Note the following about the preceding code:

* `trim()` removes leading or trailing whitespace so `" "` counts as empty.
* `===` checks equality without type coercion, which avoids lots of confusing bugs.

`Good practice`: Type coercion is JavaScript's habit of automatically converting values from one type to another when it thinks it can make an operation `work`. This usually happens silently, without errors or warnings, which is why it causes so much confusion for beginners. The loose equality operator, `==`, allows type coercion. If the two values are different types, JavaScript will try to convert one or both of them before comparing. This was intended to be convenient, but it creates surprises and bugs that are hard to spot. The strict equality operator, `===`, does not allow type coercion. Both the type and the value must match exactly for the comparison to be `true`. Use the strict equality operator for comparisons unless you have very good reasons not to.

# Loops: repeating work and iterating arrays

Loops allow you to repeat an action multiple times. Instead of writing the same line of code again and again, you tell JavaScript how many times to run it or to keep running until a condition changes. Loops are especially useful when working with arrays or groups of elements on a page.

This section updates the message and logs multiple times, then loops through an array.

In `index.html`, after the existing `<script>` elements, add a new `<script>` element to reference a new code file named `loops.js`, as shown in the following code:

```
<script src="loops.js"></script>
```

In the same folder as the HTML file, create the code file named `loops.js`, and enter the following code:

```
statusElement.textContent = "Status: Demonstrating loops.";
// A simple for loop counts from 1 to 5.
let output = "Counting: ";
for (let i = 1; i <= 5; i++) {
  output += i + " ";
  console.log("i is", i);
}
messageElement.textContent = "Message: " + output.trim();
// Looping through an array (list)
const languages = ["HTML", "CSS", "JavaScript", "Python"];
for (let i = 0; i < languages.length; i += 1) {
  console.log(`Language ${i}:`, languages[i]);
}
```

Note the following about the preceding code:

* The `for` loop has three parts: start (`let i = 1`), condition (`i <= 5`), and step aka increment (`i++`).
* Arrays use `length`, and indexes start at `0`.

# Error handling

Errors are a normal part of writing JavaScript. You will see them constantly while learning, and you will still see them in production code.

So far, you have relied on the browser console to show errors. That is useful, but sometimes you also want to handle errors in your code so your program can fail gracefully instead of crashing. JavaScript provides a built-in way to do this using `try` and `catch`.

A `try` block contains code that might fail. If an error occurs, JavaScript stops running that block and jumps to the `catch` block:

```
try {
  const result = riskyOperation();
  console.log(result);
} catch (error) {
  console.error("Something went wrong:", error);
}
```

The preceding code means: try to run the `riskyOperation()` function and log the result, but if something breaks, catch the error and handle it.

As another example, you might try to find an element named `status` and change its text content to display a message to the user:

```
const element = document.querySelector("#status");
try {
  element.textContent = "Updated safely";
} catch (error) {
  console.error("Failed to update element:", error);
}
```

In the preceding code, if `element` is `null`, trying to access `textContent` would normally throw an error and stop execution. With `try` and `catch`, you can handle that situation instead of letting it crash silently or unpredictably.

That said, in this specific case, a simple `if (element)` check is usually better. Use `try` and `catch` when you cannot easily predict or prevent the error.

## Throwing your own errors

You can also create errors deliberately using `throw`. This is useful when you detect an invalid situation:

```
function greet(name) {
  if (!name) {
    throw new Error("Name is required");
  }
  return `Hello, ${name}!`;
}
```
