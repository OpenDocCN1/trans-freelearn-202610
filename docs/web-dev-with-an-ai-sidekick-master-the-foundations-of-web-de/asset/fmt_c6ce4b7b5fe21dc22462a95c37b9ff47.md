## Links

SQL is standardized, but every database has extensions and edge cases. When in doubt, always check the official documentation for the database you are actually using. Trust vendor documentation first, blogs second, and copy-pasted snippets last.

Below are reliable, official SQL reference guides and documentation sites. They are maintained by the database vendors or core project teams and reflect actual behavior instead of myths propagated on sites like LinkedIn.

### Cross-database and standards-oriented references

These are useful for readers who want a broader or more neutral view of SQL.

- ISO SQL standard overview: <https://www.iso.org/standard/76583.html>
- W3Schools SQL reference (non-official, but approachable and searchable): <https://www.w3schools.com/sql/>
- MDN SQL overview: <https://developer.mozilla.org/en-US/docs/Glossary/SQL>

### SQLite

SQLite is extremely well documented, and its docs are unusually readable.

- Official SQLite documentation home: <https://www.sqlite.org/docs.html>
- SQL language reference (good for learning about SQLite-specific behavior and extensions): <https://www.sqlite.org/lang.html>
- `SELECT` statement reference: <https://www.sqlite.org/lang_select.html>
- Data types and type affinity (important for understanding SQLite's flexibility): <https://www.sqlite.org/datatype3.html>
- SQLite command-line tool documentation: <https://www.sqlite.org/cli.html>

### PostgreSQL

PostgreSQL has one of the most comprehensive and rigorous SQL documentations available. It is verbose, but extremely precise.

- PostgreSQL official documentation home: <https://www.postgresql.org/docs/>
- PostgreSQL SQL command reference (alphabetical): <https://www.postgresql.org/docs/current/sql-commands.html>
- Indexes and performance concepts: <https://www.postgresql.org/docs/current/indexes.html>

### SQL Server (T-SQL)

Microsoft SQL Server uses Transact-SQL (T-SQL), which extends standard SQL with procedural features.

- SQL Server documentation home: <https://learn.microsoft.com/sql/sql-server/>
- T-SQL language reference: <https://learn.microsoft.com/sql/t-sql/language-reference>
- Transactions and locking: <https://learn.microsoft.com/sql/t-sql/language-elements/transactions-transact-sql>

## Summary

In this chapter, you learned that SQL is not mainly about clever syntax. It is about describing the data you want and relying on the database engine to work out how to retrieve or change it safely. That is why relational databases care so much about schema design, keys, constraints, and transactions. Good SQL starts with a good model.

You worked through the core pieces that make relational systems usable: tables, rows, columns, primary keys, foreign keys, normalization, `NULL`, and constraints. You then used those ideas in practice with SQLite, writing queries that filter, sort, join, group, and summarize data. You also saw how to change data safely and why transactions and indexes matter once a system becomes real rather than toy-sized.

Databases are unforgiving when the model is wrong. A confused schema leads to awkward queries, brittle joins, and performance work based on guesswork. A sound schema does not make every query easy, but it removes a lot of unnecessary difficulty. Start with the data model, then write the query that fits it.

Specifically, you learned:

- What SQL is and is not, including the idea that SQL is declarative and set-based rather than step-by-step
- How tables, rows, and columns model real-world concepts, and why repeating data leads to bugs and inconsistencies
- How primary keys give rows identity and foreign keys define and enforce relationships between tables
- How constraints such as `NOT NULL`, `UNIQUE`, `CHECK`, and foreign keys prevent invalid data from entering the database
- How to run SQL queries cross-platform using tools like SQLiteStudio, VS Code, and the SQLite command-line tool
- How to write `SELECT` queries to retrieve data, filter rows, sort results, and limit output predictably
- How to combine related data using different types of `JOIN`, and how to tell which rows appear in the result
- How to summarize data using `GROUP BY`, aggregate functions like `COUNT` and `AVG`, and filtering with `HAVING`
- How to insert new data, update existing data, and delete rows safely using `INSERT`, `UPDATE`, and `DELETE`
- Why transactions matter, and how they prevent databases from ending up in a "half-worked" state
- What indexes are, how they speed up reads while slowing writes, and how query plans explain database behavior

In the next chapter, you will learn about Python, a high-level, general-purpose programming language known for its readable syntax and large standard library, widely used for web development, data analysis, automation, and scripting. That is a good transition, because Python gives you a general-purpose language for building application logic, while this chapter has focused on the data layer that logic depends on.
