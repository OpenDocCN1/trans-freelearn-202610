## Control Flow

### The `for` Loop

This reads naturally: `for each title in titles`. You are not managing counters or indexes. Python handles iteration for you.

### Looping with `range`

When you do need a sequence of numbers, `range` provides it:

```
for i in range(3):
    print(i)
```

This produces `0`, `1`, and `2`. `range` is commonly used when repeating an action a fixed number of times or when working with indexes.

### The `while` Loop

A `while` loop repeats as long as a condition remains `true`:

```
count = 0
while count < 3:
    print(count)
    count += 1
```

Unlike `for`, `while` loops require you to manage state explicitly. They are useful when you do not know in advance how many iterations are needed, but they are easier to misuse if the condition never becomes `false`.

### Controlling Loops with `break` and `continue`

`break` exits the loop immediately:

```
for title in titles:
    if title == "The Matrix":
        break
    print(title)
```

`continue` skips the rest of the current iteration and moves on to the next one:

```
for title in titles:
    if title.startswith("The"):
        continue
    print(title)
```

Both should be used sparingly. If a loop needs many `break` and `continue`, it often signals that the logic should be simplified or moved into a function.

Python loops are simple by design. The power comes from iterating over meaningful values instead of low-level mechanics, which keeps code readable as programs grow.

## Input and Output

Finally, let’s review basic input and output, which let programs interact with the outside world. The most common output function is `print`, as shown in the following code:

```
print("Hello, Python")
```

To get input from the user, Python provides the `input` function. It always returns a string, as shown in the following code:

```
name = input("What is your name? ")
print("Hello,", name)
```

If you need a number like an integer, then you must convert the input explicitly using the `int` or `float` functions, as shown in the following code:

```
age = int(input("How old are you? "))
```

This explicitness is intentional. Python prefers clarity over guessing what you meant.

At this point, you should understand how Python code is structured, how values are stored in variables, how basic types work, and how simple logic and interaction are expressed. These fundamentals will appear in every example that follows.

In the next section, data structures will build directly on these ideas and show how Python handles collections of information rather than single values. These data structures let you model real-world information directly in code, instead of juggling isolated values one at a time.

# Data Structures

So far, you have worked with single values stored in variables. That is useful, but real programs almost always deal with collections of data: a list of names, a set of options, a mapping from usernames to email addresses, or a sequence of values that changes over time.

Python’s built-in data structures are one of the main reasons the language feels productive so quickly. They let you model real-world information directly, without ceremony.

Python’s core built-in data structures are `list`, `tuple`, `dict`, and `set`. You will use `list` and `dict` constantly, `tuple` occasionally, and `set` when the problem fits.

We will start with `list`, because they are the most familiar and the most flexible.

## `list`

A `list` is an ordered collection of values. You create a `list` using square brackets, with items separated by commas, as shown in the following code:

```
numbers = [1, 2, 3, 4, 5]
names = ["Alice", "Bob", "Charlie"]
```

`list` can hold values of different types, although mixing types without a good reason is usually a bad idea, as shown in the following code:

```
mixed = [1, "two", 3.0]
```

**Good practice**: Python allows mixed types in a `list` by design, but doing so makes your code harder to understand, more error-prone, and less maintainable due to loss of predictability. When a `list` contains a single, consistent type, you can make assumptions about what operations are valid. For example, if a `list` contains only integers, you can safely add, compare, or sort them without extra checks. For most beginner-level and production code, a simple rule is that a `list` should contain items of the same kind, even if Python does not enforce it.

You access items in a `list` using an index. Python uses zero-based indexing, which means the first item is at position 0:

```
names[0]   # "Alice"
names[1]   # "Bob"
```

You can also use negative indexes to count from the end:

```
names[-1]  # "Charlie"
```

`list` are mutable, which means you can change them after creation. You can replace items, add new ones, or remove existing ones, as shown in the following code:

```
names.append("Diana")
names[1] = "Robert"
```

This mutability is why `list` is often used to represent things that grow, shrink, or change over time.

## `tuple`

A `tuple` looks like a `list`, but it uses parentheses (round brackets) instead of square brackets, as shown in the following code:

```
coordinates = (51.5074, -0.1278)
```

`tuple` are ordered collections like `list`, but they are immutable. Once created, you cannot change their contents. This makes `tuple` useful for data that should not change, such as coordinates, configuration values, or fixed records.

To read an item from a `tuple`, you use the same syntax as with a `list`, as shown in the following code:

```
coordinates[0]  # 51.5074
```

If you try to assign a new value, Python will raise an error. This is a feature, not a limitation. It lets you express what the code should do clearly.

## `dict`

The most important and distinctive data structure in Python is the `dict`. A `dict` stores key–value pairs like `"age": 42`, as shown in the following code:

```
user = {
    "name": "Mark",
    "age": 42,
    "is_admin": True
}
```

Instead of accessing values by position, you access them by key. Keys are usually strings, and values can be anything. You retrieve values using the key name, as shown in the following code:

```
user["name"]      # "Mark"
user["age"]       # 42
```

You can add or update entries by assignment, as shown in the following code:

```
user["email"] = "mark@example.com"
user["age"] = 43
```

`dict` is helpful because it maps naturally to how we think about structured data. JSON, which is used everywhere on the web, maps almost directly to Python `dict` and `list`. If you understand `dict` well, many web and data tasks suddenly become much easier.

## `set`

Then there are `set`. A `set` is an unordered collection of unique values. You create a `set` using curly braces, like a `dict` but without key–value pairs, as shown in the following code:

```
tags = {"python", "web", "data"}
```

`set` automatically removes duplicates, as shown in the following code:

```
numbers = {1, 2, 2, 3}
# numbers is {1, 2, 3}
```

`set` is useful when you care about membership rather than order. For example, checking whether a value exists in a collection is fast and expressive with `set`, as shown in the following code:

```
"python" in tags   # True
```
