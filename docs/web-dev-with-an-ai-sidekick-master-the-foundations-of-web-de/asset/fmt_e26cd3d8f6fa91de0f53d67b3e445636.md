
## DOM API Reference

- `element.value`: Gets or sets the current value of an input or select, for example, in a `<form>` element.
- `element.addEventListener(event, handler)`: Registers a function to run when an event occurs:
```
btnAddTodo.addEventListener("click", handler)
```
- `event.target`: The element that originally triggered the event.
- `element.closest(selector)`: Finds the nearest ancestor (or itself) matching a selector:
```
target.closest("li")
```
- `document.createElement(tagName)`: Creates a new element in memory (not yet in the DOM):
```
document.createElement("li")
```
- `element.append(...nodes)`: Appends one or more nodes as children.
- `element.remove()`: Removes the element from the DOM.
- `element.classList`: Read-only list of CSS classes on an element.
- `classList.toggle(className)`: Adds or removes a class depending on current state:
```
document.body.classList.toggle("dark")
```
- `element.dataset`: Accesses `data-*` attributes as a JavaScript object, for example, `<li data-done="true">`:
```
li.dataset.done = "true"
```
- `element.style.property`: Sets inline CSS styles directly on an element:
```
li.style.opacity = "0.75"
```
- `element.type`: Indicates the type of an input element:
```
target.type === "checkbox"
```
- `element.checked`: Boolean indicating whether a checkbox is checked.
- `element.setAttribute(name, value)`: Sets an HTML attribute on an element:
```
checkbox.setAttribute("aria-label", "Mark done")
```
- `element.focus()`: Moves keyboard focus to the element.
- `element.length`: Returns the number of items in a list or array.
- `instanceof`: Checks whether a value is an instance of a given class:
```
target instanceof HTMLButtonElement
```

A useful tip to remember is that almost all DOM work follows the same pattern: select something, read or change a property, and react to events. Once you understand that pattern, the list above becomes a lookup rather than something to memorize.

## Links

Here are the most authoritative and widely accepted JavaScript references you should know about. These are not blogs or opinion pieces. They are the sources that define how JavaScript actually works.

### MDN JavaScript Guide

MDN Web Docs is the de facto standard documentation for JavaScript on the web. It is maintained by Mozilla with contributions from browser vendors and the wider web community.

[https://developer.mozilla.org/en-US/docs/Web/JavaScript/Guide](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Guide)

This is the best starting point for learners. It explains JavaScript concepts progressively, with examples and clear language. It is especially strong on fundamentals like variables, functions, scope, objects, and the DOM.

### MDN JavaScript Reference

This is the encyclopedic reference. Every global object, method, operator, and syntax form lives here. When you want to know exactly what something does, this is where you end up.

[https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference)

### ECMAScript Language Specification

ECMAScript is the formal standard that defines JavaScript. It is maintained by Ecma International, specifically **Technical Committee 39** (**TC39**). Browsers implement this specification.

[https://tc39.es/ecma262/](https://tc39.es/ecma262/)

This document is precise, exhaustive, and not written for beginners. You do not read it cover to cover. You consult it when you want to understand edge cases, exact semantics, or why JavaScript behaves the way it does in strange situations.

For readers who are curious but not masochistic, MDN often links directly to relevant parts of the spec and explains them in human terms. That is the healthiest way to approach it.

### MDN JavaScript Best Practices

This guide focuses on writing readable, maintainable JavaScript rather than clever code. It covers naming, structure, avoiding common mistakes, and writing code that ages well.

[https://developer.mozilla.org/en-US/docs/Learn/JavaScript/Best_practices](https://developer.mozilla.org/en-US/docs/Learn/JavaScript/Best_practices)

### MDN Using Strict Mode

Strict mode removes some of JavaScript’s worst historical footguns and makes errors fail loudly instead of silently. Even if you do not introduce it formally yet, this page explains why JavaScript behaves the way it does.

[https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Strict_mode](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Strict_mode)

### Airbnb JavaScript Style Guide

This is one of the most cited JavaScript style guides in the industry. You do not have to agree with every rule, but it strongly promotes consistency, clarity, and avoiding error-prone patterns. Many linters and tools are built around it. While not an official standards body, it is influential because large teams actually use it.

[https://github.com/airbnb/javascript](https://github.com/airbnb/javascript)

### Google JavaScript Style Guide

Another conservative, production-focused guide that emphasizes readability and long-term maintainability over cleverness.

[https://google.github.io/styleguide/jsguide.html](https://google.github.io/styleguide/jsguide.html)
