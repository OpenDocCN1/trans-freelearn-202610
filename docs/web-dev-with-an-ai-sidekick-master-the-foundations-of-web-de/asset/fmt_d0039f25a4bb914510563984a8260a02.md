
# GitHub Copilot Setup and Configuration

At the end of this section, you will have GitHub Copilot running in VS Code for inline completions and chat. You will also have a second path configured so Copilot Chat can use either:

* The built-in Copilot models (including the free plan if you qualify)
* Your own model provider, including a local Ollama model, to avoid per-request API costs

VS Code’s `BYOK` model support is part of how Copilot Chat can be powered by third-party providers (including Ollama for local models).

## Prerequisites

* VS Code installed
* A GitHub account you can sign into from VS Code. You can sign up at the following link: [https://docs.github.com/en/get-started/start-your-journey/creating-an-account-on-github](https://docs.github.com/en/get-started/start-your-journey/creating-an-account-on-github)
* Pick one of the following options:
    * GitHub Copilot Free plan (no API key required)
    * An OpenAI API key or another supported provider key for BYOK
    * A local model runtime like Ollama for local inference

`Warning!` GitHub Copilot inline suggestions (the autocomplete you accept with `Tab`) are not the same thing as `Copilot Chat`. VS Code’s BYOK model system is primarily about powering chat and editing experiences with different model providers. Some BYOK capabilities may not apply to completions in the same way. Treat local-model support as a chat-first (and edit-first) path, not a guaranteed replacement for every Copilot feature.

## Install and Sign In to Copilot in VS Code

1. Open VS Code and trigger Copilot setup by clicking the Copilot icon in the status bar.
2. Sign in with GitHub. Follow the sign-in prompts. If your GitHub account already has Copilot access, VS Code uses it. If you do not have a subscription, VS Code can enroll you into the Copilot Free plan (with monthly usage limits).
3. Verify Copilot is active. Open any code file, type a few characters, and pause. If Copilot is active, you should see gray `ghost text` suggestions you can accept (usually `Tab`).
4. Open the `Copilot Chat` view and confirm it responds. In VS Code, Copilot Chat uses a model picker in the chat input area as shown in `Figure 11.1`:

# GitHub Copilot Tips

Here are some tips to improve your experience with GitHub Copilot:

* **Use the model picker intentionally in Chat.** Copilot supports multiple models, and the model you pick affects latency, accuracy, and cost multipliers (premium requests). For quick Q&A or lightweight edits, a faster model is often enough. For complex refactors or reasoning-heavy debugging, switch to a stronger model when you need it.
* **Know what burns premium requests.** On plans that include premium requests, the newest frontier models often cost more per request (Copilot documents this as multipliers). If you’re on Free, be conservative: do exploration with cheaper models, then spend premium calls on the final `do it right` pass.
* **Ask for structured outputs to reduce token churn.** Copilot Chat gets better (and cheaper) when you constrain it. Examples:
    * “List three approaches and recommend one.”
    * “Give a patch-style diff for these two files.”
    * “Only change the methods touched by this failing test.”
* **Watch your privacy knobs in VS Code.** If you’re writing proprietary code, review Copilot settings in VS Code and tighten anything you are not comfortable with.

# Ensure You Have an OpenAI API Key Available

This section is for readers who want to use their own provider key from OpenAI or another supported provider to power chat and coding experiences in VS Code:

1. Create and store your OpenAI API key. Create an API key in your OpenAI account and store it in a password manager. Do not hardcode it into source control.
2. Open VS Code’s language model management UI by running the command to manage models. For example, in the Command Palette, select the menu item `Chat: Manage Language Models`.
3. Add your provider key like OpenAI. Choose `Bring your own language model key`. Select `OpenAI` or another provider and then paste the key.

# Docker for Consistent Server Setup

Docker is a way to package an application and everything it needs including runtime, OS libraries, dependencies, and configuration defaults into a repeatable unit called an `image`. You then run that image as a `container`.

The practical benefit for TallyApp is consistency: developers on Windows, macOS, and Linux can run the same Django stack with the same versions and the same behavior, without spending hours fighting local setup differences.

## Important Concepts

Here are the important concepts that you need to know about Docker:

* **Images**: A built, immutable template. You typically build one for your Django app. Prebuilt images are used for common services like database engines and management software.
* **Containers**: A running instance of an image. Containers can be started, stopped, and replaced easily.
* **Dockerfile**: A text file describing how to build an image. It contains layer-by-layer instructions to choose the base image, install dependencies, copy code, and how to start the process.
* **Docker Compose**: A way to define and run a multi-container application with a single command. For example, the web container might be your Django project, a `db` container might host the PostgreSQL database engine, and so on.
* **Volumes**: Persistent storage managed by Docker. This matters most for databases. If you do not use a volume for PostgreSQL, your data disappears when the database container is replaced.
* **Networks**: Compose automatically creates a private network so containers can talk to each other by service name. For example, the Django container can reach the database at hostname `db`.
* **Ports**: The doorways you expose to your host machine. You might map container port 8000 to host port 8000 so you can open the site in your browser.
