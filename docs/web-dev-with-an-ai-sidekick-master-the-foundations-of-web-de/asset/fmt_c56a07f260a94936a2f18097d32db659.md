
# SQL Fundamentals

## Tables and Relationships

A table is made up of **rows** and **columns**. Each row represents a single record, such as one film or one person. Each column represents a single attribute of that record, such as a title, release year, or birth year. Every table has a **primary key**, which uniquely identifies each row. This is how the database keeps track of individual records without relying on names or other values that might change.

Relational databases are built around relationships between tables. Instead of duplicating data, tables reference each other using **foreign keys**. For example, an episode row does not repeat the show's name and release year. Instead, it stores a reference to the show's primary key. This keeps data consistent and avoids subtle bugs where the same fact exists in multiple places with slightly different values.

## SQL Overview

**SQL** is a language for asking for data and shaping the result. **SQL** stands for **Structured Query Language**, but the word *query* is a little too narrow. SQL is used not only to read data, but also to insert it, update it, delete it, and define the structure of the database itself. Subsets of SQL include the following:

### Subsets of SQL

* **Data Definition Language (DDL)**: This is used to define or modify the structure of your database. These commands deal with the containers (tables, views, indexes) rather than the actual data inside them. Key Commands: `CREATE`, `ALTER`, `DROP`, `TRUNCATE`. Analogy: Building the shelves in a library.

* **Data Manipulation Language (DML)**: This is the subset you likely use most often. It is used to add, modify, or delete the actual data records (rows) within the tables. Key commands: `INSERT`, `UPDATE`, `DELETE`. Analogy: Putting books onto the shelves or changing their covers.

* **Data Query Language (DQL)**: This is focused entirely on retrieving data. While some people group `SELECT` under DML, it is technically its own category because it doesn't manipulate the data, it only fetches it. Key command: `SELECT`. Analogy: Reading a book from the shelf.

There are more sub-languages like **Data Control Language (DCL)**, used for security and permissions with key commands like `GRANT` and `REVOKE`, and **Transaction Control Language (TCL)** that allows you to group multiple changes into a single transaction that either succeeds or fails as a whole. TCL has key commands like `COMMIT` and `ROLLBACK`. But I don't want to overwhelm you too soon!

## Core SQL Characteristics

Core SQL is not a programming language in the usual sense. The core SQL language has no loops, no `if` statements in the way Python or JavaScript does, and no concept of step-by-step control flow. You do not tell the database how to find the data. You describe the result you want, and the database engine decides the most efficient way to get there. That is why SQL is called declarative rather than procedural. You declare the outcome, not the procedure. You describe the result you want, not the steps to get there.

## Good Practice

Although SQL is primarily a declarative language, most real-world database systems also include procedural extensions. Procedural SQL exists because real applications sometimes need logic to do batch processing, data validation, and enforcement beyond simple constraints, and complex transformations during migrations or ETL processes. Procedural SQL keywords include: `DECLARE`, `SET`, `IF`, and `WHILE`. Use SQL the way it was intended: describe the result you want and let the database engine handle the details. Procedural features exist for edge cases, not as the default approach.

## SQL Dialects

While the ISO/ANSI SQL standard provides a blueprint for how SQL should work, almost every database company adds its own flavor or dialect. These dialects exist because different databases were built for different needs.

Here are a few important dialects and how they differ:

### T-SQL (Transact-SQL)

**T-SQL (Transact-SQL)** is used by Microsoft SQL Server. T-SQL is SQL Server's procedural extension to SQL. It adds variables, control-flow statements, error handling, and stored procedure support, so database code can include more application-like logic. It focuses on high-performance business logic and deep integration with the Windows ecosystem.

### PL/SQL (Procedural Language/SQL)

**PL/SQL (Procedural Language/SQL)** is used by Oracle Database. This dialect is widely considered the most sophisticated. It is heavily influenced by Ada (a strict programming language used in defense and aviation). It is built for massive, mission-critical enterprise systems where data integrity is the top priority.

### PostgreSQL (PL/pgSQL)

**PostgreSQL (PL/pgSQL)** is used by PostgreSQL. PostgreSQL is often favored by people who care about standards and advanced SQL features.

## How SQL is Used to Query Data

### Querying Data

Querying data means asking the database questions. SQL queries usually start with `SELECT`. A `SELECT` statement specifies:

* Which columns you want
* Which table or tables the data comes from
* Which rows should be included
* How the results should be sorted or grouped

For example, a simple query might say: *Give me the names and release years of all films released after 2000, sorted by year.* The SQL would look something like the following code:

```sql
SELECT title, year FROM films WHERE year > 2000 ORDER BY year
```

You are not telling the database how to scan the table, which index to use, or how to order operations. You are only describing the result set.

When a database receives a SQL query, it goes through several steps internally. It parses the SQL text, checks that the tables and columns exist, checks permissions, and then builds a query plan. The query plan is the strategy the database chooses to answer the query. Two identical queries can run very differently depending on indexes, data size, and the database engine, but the SQL you write does not change.

### Modifying Data

SQL is also used to modify data. `INSERT` adds new rows. `UPDATE` changes existing rows. `DELETE` removes rows. These statements follow the same declarative idea. You describe which data should be affected and what the new values should be, and the database handles the mechanics safely and consistently.

For example, to delete all films released before the year 2000, use the following code:

```sql
DELETE FROM films WHERE year < 2000
```

### Why This Separation Matters

Because SQL describes the result rather than the step-by-step procedure, the same query can be used against a tiny table or a much larger one. Whether it performs well then depends on the schema, indexes, and the database engine's query plan. Poorly designed tables lead to awkward queries and performance problems, no matter how good your SQL looks.
