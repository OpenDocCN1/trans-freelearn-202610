
# Most useful functions accept parameters

Most useful functions accept **parameters**. Parameters are variables that receive values from the caller. They let the function work with different data each time it is called, as shown in the following code:

```
def greet(name):
    print("Hello,", name)
greet("Alice")
greet("Bob")
```

In the preceding code, `name` is a parameter. When you call `greet("Alice")`, the value `"Alice"` is passed into the function and assigned to `name`.

## Returning values from functions

Functions can also return values using the `return` statement. Returning a value sends data back to the caller and ends the function immediately, as shown in the following code:

```
def add(a, b):
    return a + b
result = add(3, 4)
print(result)
```

Functions do not only perform actions. They can compute a result and hand it back to the caller.

A function can have multiple `return` statements, but only one will run per call, as shown in the following code:

```
def check_age(age):
    if age >= 18:
        return "Adult"
    else:
        return "Minor"
```

As soon as `return` executes, the function exits.

## Local variables and scope

Variables defined inside a function are local to that function. This means they exist only while the function is running and cannot be accessed from outside, as shown in the following code:

```
def example():
    x = 10
    print(x)
example()
# print(x)  # This would cause an error
```

This concept is called **scope**. Local variables help prevent accidental interference between different parts of a program. If everything were global, even small programs would become fragile very quickly.

Functions can call other functions, including ones you have written yourself, as shown in the following code:

```
def square(n):
    return n * n
def print_square(n):
    result = square(n)
    print(result)
print_square(5)
```

This kind of composition is normal in Python. Small functions that do one thing well are easier to test and easier to reuse than large functions that try to do everything at once.

## Default parameter values

It is also worth noting that Python allows **default parameter values**, as shown in the following code:

```
def greet(name, greeting="Hello"):
    print(greeting, name)
greet("Alice")
greet("Bob", "Hi")
```

Defaults make functions flexible without making them complicated.

# Grouping data and behavior with classes

So far, your Python code has been organized around variables and functions.

That works well for small scripts. But as programs grow, you often need a way to group related data and behavior together. That is what classes are for.

A **class** lets you define a new kind of object that has:

- **Data** (called attributes)
- **Behavior** (called methods)

Here is a basic class:

```
class Task:
    def __init__(self, title):
        self.title = title
        self.completed = False
    def mark_complete(self):
        self.completed = True
```

This class is a template for creating task objects.

Now you can create and use a task:

```
task = Task("Write Chapter 8")
print(task.title)        # Write Chapter 8
print(task.completed)    # False
task.mark_complete()
print(task.completed)    # True
```

### The `__init__` method

The `__init__` method runs when you create a new object:

```
task = Task("Write Chapter 8")
```

It is used to set up the initial state of the object:

- `self` refers to the current object
- `self.title` and `self.completed` are attributes stored on that object

The `__init__` method defines what data each instance of the class starts with. `self` is the object you are working with.

When you write:

```
task.mark_complete()
```

Python turns that into:

```
Task.mark_complete(task)
```

So `self` is the instance being passed in. You do not need to name it `self`, but you should. It is a strong convention and every Python developer expects it.

### Making objects printable

By default, printing an object is not very helpful:

```
print(task)
```

You might see something like:

```
<__main__.Task object at 0x...>
```

You can improve this by defining a special method:

```
def __str__(self) -> str:
    status = "✓" if self.completed else "✗"
    return f"{status} {self.title}"
```

Now:

```
print(task)
```

produces:

```
✗ Write Chapter 8
```

Let's break down the method:

- `__str__` is a special method name that Python calls when converting an object to a string
- `self` is the instance
- `-> str` is a type hint that says this method returns a string

So, whenever you see `def __str__(self) -> str:` in a class, it means: *When Python needs a string representation of this object, call this method and expect a string back*.

You will see this pattern often in real Python code, especially in frameworks like Django.

### Methods are functions inside a class

A method is a function defined inside a class:

```
def mark_complete(self):
    self.completed = True
```

The only difference is that it operates on an instance (`self`).

This means everything you learned about functions still applies, including parameters, return values, and control flow. The difference is that methods usually work with the object's internal data.

### Adding more structure

You can expand the class naturally:

```
class Task:
    def __init__(self, title, priority="medium"):
        self.title = title
        self.completed = False
        self.priority = priority
    def mark_complete(self):
        self.completed = True
    def is_high_priority(self):
        return self.priority == "high"
    def __str__(self) -> str:
        status = "✓" if self.completed else "✗"
        return f"{status} [{self.priority}] {self.title}"
```

Now the object has multiple attributes, multiple methods, and a clear string representation.

### Why classes matter for Django

You do not need classes for simple scripts.

But Django uses classes everywhere.

For example:

- Database models are classes
- Views are often classes
- Forms are classes

A Django model might look like this:

```
class Task(models.Model):
    title = models.CharField(max_length=200)
    completed = models.BooleanField(default=False)
    def __str__(self):
        return self.title
```

If you understand attributes, methods, `__init__`, and `__str__` then this code is not mysterious and scary. It is just a class with some framework-specific behavior.

**Good practice**: Use classes when you are modeling something with state (like a task, user, or order), you want to group related data and behavior, or you want multiple instances of the same kind of object. Avoid classes when a simple function or dictionary is enough or adding a class would make the code harder to follow.

# Python's optional type hints

**Type hints** are optional annotations that describe the expected types of variables, parameters, and return values. They help with clarity and tooling, but they do not change how Python runs.

Type hints let you document purpose directly in the code:

```
def total_runtime(minutes: list[int]) -> int:
    return sum(minutes)
```

The preceding code says:

- `minutes` parameter is expected to be a list of integers
- `total_runtime` function is expected to return an integer

The code still runs exactly the same with or without the hints. Python does not enforce them at runtime. They are for humans and tools, not for the interpreter.

Type hints were added to address real problems in larger Python codebases. A function signature with type hints tells the reader how it is meant to be used without reading the implementation.
