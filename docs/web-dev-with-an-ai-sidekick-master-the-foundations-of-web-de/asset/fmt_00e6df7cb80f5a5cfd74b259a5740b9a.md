
The `<title>` element is the SVG equivalent of `alt` text on an `<img>`. It should be the first child inside `<svg>`, so assistive technologies can find it reliably, as shown highlighted in the following code:

```xml
<svg viewBox="0 0 120 120" 
     role="img" aria-labelledby="icon-title"
     xmlns="http://www.w3.org/2000/svg">
  <title id="icon-title">Success checkmark</title>
  <circle cx="60" cy="60" r="50" fill="#e6f4ea" />
  <path d="M 35 60 L 55 80 L 85 40" stroke="#1e8e3e" 
        stroke-width="6" fill="none" />
</svg>
```

### Good practice

Keep `<title>` short and descriptive, similar to `alt` text. Describe the meaning, not the shape. “Success checkmark” is better than “green circle with a tick”.

## Adding longer descriptions with `<desc>`

If the SVG contains more complex information, such as a chart or diagram, use `<desc>` for a longer explanation, as shown highlighted in the following code:

```xml
<svg viewBox="0 0 200 120"
     role="img" aria-labelledby="chart-title chart-desc"
     xmlns="http://www.w3.org/2000/svg">
  <title id="chart-title">Monthly sales</title>
  <desc id="chart-desc">
    Bar chart showing steady growth from January to June, with the highest sales in June.
  </desc>
  <!-- chart shapes here -->
</svg>
```

Think of `<desc>` as the equivalent of a figure caption or summary. It gives context that wouldn’t fit in a short label.

## Linking text with `aria-labelledby`

The `<title>` and `<desc>` elements only become useful when assistive technologies are explicitly told to use them. That’s what `aria-labelledby` does:

```html
aria-labelledby="chart-title chart-desc"
```

Keep these details in mind:

* The value is a space-separated list of IDs.
* Order matters. The text will be read in that order.
* You can include just `<title>`, or both `<title>` and `<desc>`.

## Declaring the SVG as an image with `role="img"`

SVG elements are not always treated as images by default, especially inline SVG. Adding `role="img"` tells assistive technologies to treat the SVG as one image:

```html
<svg role="img" ...>
```

The preceding attribute ensures:

* Screen readers treat the SVG as a single image.
* The label from `aria-labelledby` is announced properly.

## Hiding decorative SVGs

If an SVG adds no meaning and is purely decorative, it should be hidden from assistive technologies to avoid noise:

```xml
<svg aria-hidden="true" ...>
  <!-- decorative shapes -->
</svg>
```

Use this for:

* Background flourishes.
* Divider graphics.
* Icons that duplicate nearby text, for example, a trash icon next to the word *Delete*.

Do not combine `aria-hidden="true"` with accessible labels. If it’s hidden, it should be completely ignored.

## Inline SVG vs `<img>` SVG

There’s an important distinction:

* `<img src="icon.svg" alt="...">` uses standard HTML accessibility.
* Inline `<svg>` requires ARIA, `<title>`, and `<desc>`.

If you don’t need to style or manipulate the SVG, using `<img>` is often simpler and safer. Inline SVG is more flexible but comes with more responsibility.

### Good practice

If the SVG communicates something, label it clearly. If it doesn’t, hide it completely. Treat `<title>` like `alt`, and `<desc>` like a caption.
