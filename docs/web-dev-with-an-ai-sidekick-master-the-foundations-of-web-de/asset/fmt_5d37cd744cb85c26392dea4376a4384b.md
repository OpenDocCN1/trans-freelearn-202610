
# CSS Box Model and Layout

As shown in Figure 3.2, each box consists of:

- **Element Content**: The text or image itself
- **Padding**: Space inside the element, around the content
- **Border**: A *line* around the padding
- **Margin**: Space outside the element, separating it from other elements around it

![](Images/B34553_03_02.png)

Figure 3.2: The CSS box model

Try this example CSS:

```css
.card {
  width: 300px;
  padding: 16px;
  border: 5px dashed #333;
  margin: 20px;
}
```

One important detail: `width: 300px;` sets the width of the content area, not the total visible width of the box. Because this card also has `padding: 16px;` on both sides and a `5px` border on both sides, the full rendered width is `300` + `16` + `16` + `5` + `5` = `342px`, plus any outside margin. This is the default CSS box model and one of the most common beginner surprises.

Later in this chapter, you will see how `box-sizing: border-box;` changes this behavior so the declared width includes padding and border.

And here's the HTML to add:

```html
<h2>Box model example</h2>
<div class="card">
  <h3>Card Title</h3>
  <p>This is a simple content card. This is a simple content card. This is a simple content card. This is a simple content card. This is a simple content card.</p>
</div>
```

Experiment by changing padding and margin values. Watch how the space inside and outside the element changes. You will use this idea throughout the chapter and later layout work.

`margin: 0 auto;` centers an element horizontally because of how the browser calculates margins when the element has a constrained width. This is shorthand for:

```css
margin-top: 0;
margin-bottom: 0;
margin-left: auto;
margin-right: auto;
```

The vertical margins are fixed at zero, while the horizontal margins are set to `auto`. This only works if the element:

- Is a block-level element, and
- Has a width that is less than the available space

If the element already fills the entire width of its container, there is no extra space to distribute and nothing to center. When left and right margins are set to `auto`, the browser calculates how much horizontal space is left over after accounting for the element's width.

`margin: 0 auto;` does not center vertically because vertical margins do not participate in the same automatic space distribution logic. There is no concept of "split the leftover height" for margins in normal document flow.

You can think of `margin: 0 auto;` as telling the browser to split the remaining horizontal space evenly on both sides of this box.

If there is no space to split, nothing moves. That explains most common cases.

Add the following CSS incrementally. Do not paste it all in at once. Add a rule, refresh, observe, repeat:

```css
body {
  font-family: Arial, Helvetica, sans-serif;
  background-color: #f5f5f5;
  color: #222;
}
div.container {
  max-width: 800px;
  margin: 0 auto;
  padding: 20px;
  background-color: white;
}
a {
  text-decoration: none;
  color: #0066cc;
}
a:hover {
  text-decoration: underline;
}
```

Note the following about the preceding code:

- The `body` selector applies to the entire page. `font-family` sets the default font stack. The browser will first try `Arial`, then `Helvetica`, and finally any generic `sans-serif` font. This is a common font stack for simple, readable text. `background-color: #f5f5f5;` gives the whole page a very light gray background. `color: #222;` sets the default text color to a very dark gray instead of pure black, which is easier on the eyes.
- The `div.container` selector targets `<div class="container">`. `max-width: 800px;` limits the width of the content to 800 pixels, even on large screens, which improves readability by preventing overly long lines. `margin: 0 auto;` means no top/bottom margin and the browser evenly distributes space so the container is horizontally centered. `padding: 20px;` adds space inside the container so content doesn't touch the edges. `background-color: white;` creates a white card effect against the light gray page background.
- The `a` selector (for hyperlinks) removes the default underline from links and sets a custom blue color. The `a:hover` selector applies when a pointing device hovers over a link with the mouse and adds the underline back, giving users a visual cue that the text is interactive.

**Good practice**: Removing the underline for links by default and adding it dynamically on hover means links are only identifiable by color when not hovered. This makes links harder to identify for users with color vision deficiencies. A more accessible approach is to keep the underline (or add another visual distinction beyond color like font weight or a `border-bottom`, or sufficient contrast between the link color and surrounding text) in the default state.

You have not learned everything in this CSS yet, and that is fine. Here, you are learning a repeatable debugging process, not memorizing fixes. You should now see how CSS changes plain HTML into a page with clearer spacing, color, and typography.

## The four-sides model

In CSS, many properties apply to the four sides of a box. Rather than inventing four unrelated properties, CSS uses a directional system based on top, right, bottom, and left. Once you understand this pattern, a large chunk of CSS suddenly becomes predictable instead of arbitrary.

Most layout-related CSS properties operate on the same four edges: Top, Right, Bottom, and Left. These directions always follow the same clockwise order, which matters when shorthand syntax is used.

### Properties that support directional variants

The most common properties with `-top`, `-right`, `-bottom`, and `-left` forms are spacing like `margin` and `padding`.

Each has:

- `margin-top`, `margin-right`, `margin-bottom`, `margin-left`
- `padding-top`, `padding-right`, `padding-bottom`, `padding-left`
- `border-top`, `border-right`, `border-bottom`, `border-left`

Borders also have sub-properties:

- `border-top-width`, `border-top-style`, `border-top-color`
- And equivalents for the other sides

Positioning offsets (when `position` is not `static`): `top`, `right`, `bottom`, `left`.

Note the naming pattern in corner rounding:

- `border-top-left-radius`
- `border-top-right-radius`
- `border-bottom-right-radius`
- `border-bottom-left-radius`

### Shorthand vs longhand

Most of these properties support shorthand notation as well as longhand.

Take margin as the canonical example. To set all four sides to `20px`:

```css
margin: 20px;
```

To set top and bottom to `10px`, and left and right: `20px`:

```css
margin: 10px 20px;
```

To set top to 10px, left and right to `20px`, and bottom to `30px`:

```css
margin: 10px 20px 30px;
```

To set top to `10px`, right to `20px`, bottom to `30px`, and left to `40px`:

```css
margin: 10px 20px 30px 40px;
```

The order is always: top → right → bottom → left.

A useful mnemonic is *clockwise starting at the top*.

The same rules apply to `padding`, `border-width`, and `border-radius` (with some quirks for corners).
