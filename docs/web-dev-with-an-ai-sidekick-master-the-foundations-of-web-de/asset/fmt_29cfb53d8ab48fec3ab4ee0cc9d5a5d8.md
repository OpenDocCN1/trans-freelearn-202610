The most important idea is that tests are executable decisions about behavior. `AI` can help write the code, but you still have to decide what the application must guarantee.

A good software project starts before anyone writes code. It starts with understanding the goal. What are you building? Who is it for? What problem is it meant to solve? And just as important, what are you choosing not to build?

In this chapter, we move from isolated examples to the first working version of `TallyApp`. It is realistic enough to teach planning, structure, data modeling, permissions, forms, and testing, but still small enough to finish.

`TallyApp` is a survey platform. Approved users can create and publish surveys. Members of the public can complete them anonymously. Survey creators can review both individual responses and aggregated results. This type of website is familiar, practical, and large enough to force real design decisions without overwhelming you with unnecessary complexity or turning into a product you could spend a year building.

## Defining the Scope and Goals of the Project

Before installing anything or writing code, be explicit about what you are building and, just as importantly, what you are not. A clear scope makes technical decisions easier and keeps the project focused as it grows.

The project you will build is a web project called `TallyApp`. At a high level, `TallyApp` allows people to create surveys, share them publicly, collect responses, and analyze the results. This is similar to many real-world applications and gives us plenty of opportunities to explore backend logic, frontend presentation, data modeling, and visualization without drifting into unnecessary complexity.

### User Journeys

`TallyApp` supports three main user journeys.

#### User Journey 1: Create and Publish a Survey

An authenticated user can create a survey with a title and description, add questions, and choose different question types such as multiple choice and free-form text answers. Once the survey is ready, it can be published and given a public link that can be shared with others. This part teaches data modelling, forms, validation, and permissions.

#### User Journey 2: Take a Survey

Anyone with the public link can view the survey and submit responses without needing an account. The interface is intentionally simple and task-focused. Respondents answer questions and submit the form, and their responses are stored reliably. This part of the project highlights `URL` design, templates, form handling, and protecting against invalid or duplicate submissions.

#### User Journey 3: View and Analyze Results

The survey creator can view aggregated results, such as counts and percentages for multiple-choice questions, as well as individual responses for free-text questions. Results are presented using tables and charts, so patterns are easy to spot. This part of the application introduces reporting queries, basic analytics, and data visualization.

### Project Limits

It is also important to define boundaries. `TallyApp` is not a full enterprise survey platform. We are not building user billing, team collaboration, advanced permissions, or complex branching logic between questions. These omissions are deliberate. They keep the focus on learning how to design and build a complete web application rather than chasing more features or building something we can monetize.

### Why a Survey Project?

The best way to learn web development is to work on real projects that you would use yourself or that at least spark an interest in you.

If you are a student or a professional developer who has no choice over the projects or technologies that you implement, how can you work on a real project that needs the technologies you are interested in learning about?

#### Attributes of a Good Learning Project

To help us learn all the different technologies that web developers need to know these days, we need a project that:

- Genuinely needs a mix of technologies and skills.
- Is cool, fun, and practical, so it will stretch our skills both from an engineering perspective as well as creatively.
- Is as real as possible, and that we would use ourselves.
