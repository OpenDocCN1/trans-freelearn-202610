
# SVG Shapes, Strokes, and Fills

## Basic Shape Attributes

*   For a rectangle, you specify the top-left corner `x` and `y`.
*   For a circle, you specify the center point using `cx` and `cy`, plus the radius `r`.
*   For a line, you specify start (`x1`, `y1`) and end (`x2`, `y2`) points.

## Color and Strokes

Color and strokes feel like CSS, but they're SVG attributes.

*   `fill` is the interior color of a shape.
*   `stroke` is the outline color.
*   `stroke-width` is the thickness of that outline.

## Presentation Attributes

In SVG, the properties that control how shapes are painted are collectively called `presentation attributes`. Most of them map directly to CSS properties, and in modern SVG, you should think of them as CSS first, attributes second.

### Stroke Properties (the outline of shapes)

`stroke` controls how the outline of a path, line, circle, and so on is drawn, for example, what color or paint is used for the outline. Possible values:

*   `none`
*   Any CSS color value: `black`, `red`, `#ff0000`, `rgb(255,0,0)`, `hsl(...)`
*   `currentColor` (inherits from `color`)
*   `url(#id)` a reference to a gradient or pattern defined in `<defs>`

For example:

```
stroke: #333;
```

`stroke-width` controls the thickness of the stroke. Stroke is centered on the path by default. Possible values:

*   A number with or without units: `1`, `2.5`, `4px`
*   Percentages are allowed but uncommon

For example:

```
stroke-width: 4;
```

`stroke-linecap` controls how the ends of open paths are drawn. Possible values:

*   `butt` (flat end, default)
*   `round`
*   `square`

For example:

```
stroke-linecap: round;
```

`stroke-linejoin` controls how corners between segments are drawn. Possible values:

*   `miter` (sharp corner, default)
*   `round`
*   `bevel`

For example:

```
stroke-linejoin: round;
```

`stroke-miterlimit` limits how sharp a miter join can be before it turns into a bevel. It applies only when `stroke-linejoin` is set to `miter`. Possible values:

*   Any number greater than or equal to `1`

For example:

```
stroke-miterlimit: 4;
```

`stroke-dasharray` creates dashed lines. Possible values:

*   `none`
*   A list of numbers: `5, 5 10, 10 5 2 5`

Numbers alternate between dash length and gap length. For example:

```
stroke-dasharray: 8 4;
```

`stroke-opacity` controls the opacity of the stroke only. Possible values:

*   Number from `0` to `1`

For example:

```
stroke-opacity: 0.6;
```

### Fill Properties (the interior of shapes)

These control how closed shapes are filled.

`fill` controls what paint is used inside the shape. Possible values:

*   `none`
*   Any CSS color value
*   `currentColor`
*   `url(#id)` (gradient or pattern)

Default is `black` if not specified.

For example:

```
fill: cornflowerblue;
```

`fill-opacity` sets the opacity of the fill only. Possible values:

*   Number from `0` to `1`

For example:

```
fill-opacity: 0.5;
```

`fill-rule` controls how SVG decides what *inside* means for complex or self-intersecting paths. Possible values:

*   `nonzero` (default)
*   `evenodd`

You will encounter this mostly with icons. Example:

```
fill-rule: evenodd;
```

### Shared Painting and Visibility Properties

These affect both `fill` and `stroke`, or how the painting behaves overall.

`opacity` controls overall opacity of the element, affecting both `fill` and `stroke`. Possible values:

*   Number from `0` to `1`

For example:

```
opacity: 0.8;
```

`paint-order` controls whether `fill` or `stroke` is drawn first. Possible values:

*   `normal` (`fill` first, then `stroke`)
*   Any combination of `fill`, `stroke`, `markers`

For example:

```
paint-order: stroke fill;
```

This is useful when you want the stroke to sit behind the fill.

### Inheritance and Special Values

These are not SVG-only, but they matter a lot in SVG.

`currentColor` uses the element's color property as the paint value. For example:

```
svg {
  color: #0066cc;
}
path {
  stroke: currentColor;
}
```

This makes SVG icons behave like text icons.

`inherit` explicitly inherits from the parent.

Example:

```
stroke: inherit;
```

## Hands-on Mini-task: Badge Icon

Make a `badge` icon: a circle with a smaller circle inside it, plus a checkmark line, as shown in `Figure 4.2`:

![](Images/B34553_04_02.png)

Figure 4.2: A checkmark drawn with SVG

In the web page, add a new `<svg>` element and tweak the numbers until it looks right to you:

```
<svg width="180" height="180" xmlns="http://www.w3.org/2000/svg">
  <!-- Outer circle -->
  <circle cx="90" cy="90" r="70" fill="#e6f4ea" 
          stroke="#1e8e3e" stroke-width="6" />
  <!-- Inner circle -->
  <circle cx="90" cy="90" r="52" fill="white" />
  <!-- Checkmark (two lines) -->
  <line x1="60" y1="95" x2="82" y2="115" 
        stroke="#1e8e3e" stroke-width="10" stroke-linecap="round" />
  <line x1="82" y1="115" x2="122" y2="70" stroke="#1e8e3e" 
        stroke-width="10" stroke-linecap="round" />
</svg>
```

If it doesn't look centered or balanced, change one number at a time. This is one of the best ways to build intuition for SVG coordinates.

# Scaling, Grouping, and Styling Graphics

So far, you've been drawing SVG using fixed pixel sizes. That works, but it misses one of SVG's biggest strengths: scalability. The key to scalable SVG is separating the drawing's internal coordinate system from the size it appears on the page. That's what `viewBox` does.

## Scaling with viewBox

The `viewBox` attribute defines an internal grid that your shapes live in. It has four numbers: `min-x`, `min-y`, `width`, and `height`. Most of the time, the first two are `0 0`.

Here's the same SVG as before, rewritten to use a `viewBox` instead of relying purely on width and height:

```
<svg viewBox="0 0 300 120" width="100%" height="auto"
     xmlns="http://www.w3.org/2000/svg">
  <rect x="10" y="10" width="280" height="100" fill="#f2f2f2" />
  <circle cx="90" cy="60" r="35" fill="cornflowerblue" />
  <line x1="160" y1="25" x2="280" y2="95" 
        stroke="black" stroke-width="4" />
</svg>
```

What changed conceptually:

*   `viewBox="0 0 300 120"` says *pretend this SVG is drawn on a 300 by 120 grid*.
*   The browser scales that grid up or down to fit whatever size the SVG is displayed at.
*   Your coordinates stay the same, but the rendered size adapts to the layout.

SVG icons stay sharp on phones, laptops, and 4K screens without needing multiple image assets. If you remember only one SVG rule, remember this: most production SVG almost always uses `viewBox`.

The `preserveAspectRatio` attribute controls what happens when the viewBox's aspect ratio doesn't match the SVG's display size. The default value, `xMidYMid meet`, scales the graphic uniformly and centers it within the available space. If you want the SVG to stretch to fill its container (ignoring aspect ratio), use `preserveAspectRatio="none"`. For most icon and illustration use cases, the default behavior is what you want. This is why most SVGs resize without extra work.
