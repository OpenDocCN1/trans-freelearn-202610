
# Accessibility and CSS

CSS plays a significant role in accessibility. For example, choosing sufficient color contrast between text and background helps users with visual impairments. Avoiding fixed font sizes allows users to scale text more easily. Ensuring that focus states (such as outlines on links and buttons) are visible supports keyboard navigation.

Accessibility is not an optional extra or a final step. It should be considered from the beginning of the design and development process. Following WCAG guidance leads to websites that are more inclusive, easier to use, and often better designed overall.

The following links will help you learn WCAG:

* **Explains the *why* behind accessibility before diving into rules:** [https://www.w3.org/WAI/fundamentals/accessibility-intro/](https://www.w3.org/WAI/fundamentals/accessibility-intro/)
* **Quick reference:** [https://www.w3.org/WAI/WCAG22/quickref/](https://www.w3.org/WAI/WCAG22/quickref/)

# Colors, Fonts, and Layout

In beginner projects, simple design choices usually work better than adding more decoration. Good design is mostly about restraint. CSS gives you enormous power, and the hardest part is knowing when to stop.

## Working with Color

The syntax of color in CSS is simple, but choosing colors well is harder. You set a value, the browser paints pixels. The difficulty is not syntax, it is consistency and contrast.

CSS supports several color formats, but you should focus on two: color names like `red` or `darkblue`, and hexadecimal values:

```
color: red;
color: #336699;
```

Named colors like `red` and `blue` exist mainly for quick experiments. Real projects use hexadecimal values because they are precise and predictable.

Hex colors are written as `#RRGGBB`, where each pair controls the intensity of red, green, and blue.

```
body {
  background-color: #f5f5f5;
  color: #222222;
}
```

This combination already improves readability compared to pure black on pure white, which is harsh on the eyes.

You can also use color functions:

```
color: rgb(255, 99, 71);
color: rgba(255, 99, 71, 0.5);
color: hsl(120, 60%, 50%);
color: hsla(120, 60%, 50%, 0.7);
```

**Prompt:** Please explain the color functions `rgb`, `rgba`, `hsl`, and `hsla`, especially how to set alpha or transparency.

A few strong rules that will save you from ugly pages:

* Do not use too many colors. Two or three core colors is plenty for most beginner projects.
* Ensure text contrast is high enough. WCAG 2.1 AA requires a minimum contrast ratio of 4.5:1 for normal text and 3:1 for large text (18pt+ or 14pt bold). Light gray text on a white background looks fashionable and reads terribly.
* Use color to communicate meaning, not decoration. Links, errors, warnings, and highlights should use color meaningfully and consistently.

## Fonts and Typography

Typography often affects readability more than color does. Poor font choices make a site feel amateur faster than almost anything else.

Start simple. System fonts are your friend:

```
body {
  font-family: Arial, Helvetica, sans-serif;
}
```

This tells the browser to use `Arial` if available, otherwise `Helvetica`, otherwise any generic sans-serif font. It loads instantly and looks clean on every platform.

Browsers use a sensible default font size (typically 16px), and users may adjust this for readability. Instead of overriding it with fixed pixel values, prefer relative units such as percentages or `rem` (root `em`, explained later) so that user preferences are respected. You should usually trust the browser default font size and build on top of it, not override it. For example, either set it to `100%` or slightly larger for a home page on a marketing site:

```
html {
  font-size: 112.5%; /* ~18px equivalent */
}
```

**Good practice:** Setting `font-size` on `body` affects most text because font size is inherited by default, and most elements are inside `<body>`. You will see this a lot in code examples, and LLMs often follow that old practice. But `<body>` does not define the root font size and therefore it does not control `rem` units. To control `rem` and default `font-size`, use the `html` selector.

Line height is as important as font size. Dense text feels hostile. Slightly generous spacing feels calm and readable:

```
body {
  line-height: 1.6;
}
```

Headings should clearly contrast with body text, but not shout:

```
h1, h2, h3 {
  line-height: 1.3;
}
h1 {
  font-size: 2rem;
}
h2 {
  font-size: 1.5rem;
}
```

**Good practice:** Avoid setting everything in bold or uppercase. Most beginner sites look bad because they try to be dramatic with fonts instead of readable. Readability wins.

## Layout Fundamentals

HTML stacks elements vertically by default. CSS layout is about controlling width, spacing, and alignment so the page has a clear structure.

Start by constraining the content width of your main content block:

```
main {
  max-width: 800px;
  margin: 0 auto;
  padding: 20px;
}
```

This single rule does several things:

* Prevents text lines from becoming too wide
* Centers the content horizontally
* Adds breathing room around the content

This pattern appears in almost every professional website.

Spacing is more important than borders and backgrounds. If you divide your main content into multiple sections, then add extra margin at the bottom of each section:

```
section {
  margin-bottom: 40px;
}
```

White space is not wasted space. It is how the eye understands structure. White space helps readers distinguish sections, hierarchy, and grouping. When you need columns, resist the urge to force things with margins. Use layout tools designed for the job.

For example, define a class style:

```
.layout {
  display: flex;
  gap: 20px;
}
```

Then apply the class style to elements like `<div>` elements:

```
<div class="layout">
  <aside>Sidebar content</aside>
  <main>Main content</main>
</div>
```

You will learn Flexbox properly later, but even now you can see how it produces clean, predictable layouts without hacks.

The `gap` property controls the space between items in a layout container, most commonly Flexbox and Grid. It exists to solve a very old and annoying problem in CSS: spacing elements evenly without hacks.

When a container uses Flexbox, `gap` defines the amount of space between flex items, not around the outside of the container. For example, with the following CSS:

```
.container {
  display: flex;
  gap: 20px;
}
```

In the following HTML, each item will be separated by exactly 20 pixels. You do not need margins on the children. You do not need special rules for the last item:

```
<div class="container">
  <div>One</div>
  <div>Two</div>
  <div>Three</div>
</div>
```

With Flexbox, you can set different values for row and column gaps:

```
gap: 10px 20px;
```
