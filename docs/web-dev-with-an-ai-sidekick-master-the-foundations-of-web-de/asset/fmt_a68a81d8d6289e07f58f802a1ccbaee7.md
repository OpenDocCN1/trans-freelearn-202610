
# CSS Styling Overview

## Internal and External CSS

```html
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <title>My First CSS</title>
  <style>
    p {
      color: blue;
    }
  </style>
</head>
<body>
  <p>This paragraph is blue.</p>
</body>
</html>
```

Internal CSS is easier to maintain than inline CSS, but it still ties style definitions to a single HTML file, so if you need the same styles in multiple web pages, you will have to duplicate them.

Good practice: External CSS should be your default while learning because it keeps structure and presentation separate. Later, you may see small internal styles used for performance, especially for above-the-fold CSS, but do not start there. This is because the styles are downloaded with the web page and defined in the `<head>` so styling is applied to the content immediately as it is rendered.

External CSS is written in a separate `.css` file and linked to your HTML. After downloading the web page, the browser downloads the CSS file and applies its styles to the content.

Let’s see an example:

1. Create a new folder named `Chapter03`.
2. In the `Chapter03` folder, create a new folder named `StyleBasics`.
3. In the `StyleBasics` folder, download the file called `index.html` from the following link: [https://github.com/markjprice/web-dev-ai/blob/main/Code/Chapter03/StyleBasics/index.html](https://github.com/markjprice/web-dev-ai/blob/main/Code/Chapter03/StyleBasics/index.html)
4. In VS Code, open the `StyleBasics` folder.
5. In the `StyleBasics` folder, create a new file called `styles.css` and add style definitions:

```css
p {
  color: green;
}
```

6. In `index.html`, in the `<head>` element, add a link to the CSS file:

```html
<link rel="stylesheet" href="styles.css">
```

7. Live preview the page. The paragraph should now be green, as shown in Figure 3.1:

Figure 3.1: External CSS file changing the color of paragraphs to green

If nothing changes, check the filename, check the path, and make sure the `<link>` tag is inside `<head>`.

From this point on, assume all CSS lives in an external stylesheet unless explicitly stated otherwise.

Good practice: External CSS is what you should use by default. It allows you to define your styles once and reuse them throughout all the web pages in a website.

## Selectors and rules

A CSS rule has two main parts: a selector and a declaration block:

```css
p {
  color: navy;
  font-size: 18px;
}
```

In the preceding code:

* `p` is the selector. It tells the browser which elements to target.
* Everything inside the curly braces `{ }` is the declaration block.
* Each declaration is a property like `color` or `font-size` and a value like `navy` or `18px`, separated by a colon and ending with a semicolon.
* This rule applies navy color and 18px font size to all `<p>` elements on the page.

Try adding these rules to your stylesheet file:

```css
h1 {
  color: darkslateblue;
}
p {
  color: green;
  font-size: 18px;
  line-height: 1.8;
}
```

The preceding code shows an example of element selectors. These select all elements for the same tag type. In these examples, the rules apply to all `<h1>` elements and all `<p>` elements. But what if you want to select only a subset of headings and paragraphs? We can use two other types of selector to do this.

## Classes and IDs

Targeting every paragraph or heading is rarely enough. You often want to style specific elements differently. A CSS class can be reused across multiple elements. You can add this example to your web page and stylesheet files.

The HTML to add:

```html
<h2>Example of a class selector</h2>
<p class="intro">This will be bold and 14px.</p>
<p>This is regular content.</p>
```

The CSS to add is shown in the following code:

```css
.intro {
  font-size: 14px;
  font-weight: bold;
}
```

A class selector always starts with a dot like `.intro` in the preceding code.

A class or ID name is an identifier. The key rules are:

* It must not contain spaces.
* It may contain letters, digits, hyphens, and underscores.
* It must not start with a digit.
* It may start with a letter or a hyphen.
* It is case-sensitive, but relying on case differences is a bad idea.

There are practical naming conventions too:

* Use lowercase only because mixing case adds cognitive load and invites bugs.
* Use hyphens, not underscores, because hyphens are the dominant convention in CSS and match property naming like `font-size` and `background-color`.
* Name things by purpose, not appearance. For example, `.red-text` is bad, `.error-message` is good. This guideline saves trouble later.

An element’s ID should be unique within the page. An ID selector should therefore only select that one element on the page and apply its style to it.

The HTML to add is shown highlighted in the following code:

```html
<h1 id="main-title">My Styled Web Page</h1>
```

The CSS to add is shown in the following code:

```css
#main-title {
  text-transform: uppercase;
}
```

An ID selector starts with a hash like `#main-title` in the preceding code. Use IDs sparingly. Classes scale better and are easier to reuse.

Good practice: Avoid IDs for styling because they can only be applied to one element. Even if you currently only have one element that needs a style, you probably want to apply it using a class instead. That way, if you later add another element that needs the same style, you can easily apply it.

## The cascade and specificity

CSS stands for Cascading Style Sheets, and the cascade matters. When multiple rules target the same element, the browser must decide which one wins.

Consider the following CSS:

```css
p {
  color: black;
}
.intro {
  color: darkgreen;
}
```

And this HTML:

```html
<p class="intro">Hello world</p>
```

The element selector sets paragraphs to `black`. The class selector rule says to color any element with the class of `.intro` in `darkgreen`. Which one wins?

The paragraph will be colored dark green, not black, because class selectors are more specific than tag selectors.

Specificity rules get very complicated, so let’s simplify them:

* Element selectors are weakest
* Class selectors override element selectors
* ID selectors override both
* Inline styles override everything else

```
Element < Class < ID < Inline
```

Order also matters. If two rules have equal specificity, the one written later in the stylesheet wins. For example, the following CSS has two class rules:

```css
.intro {
  color: darkgreen;
}
.branding {
  color: darkred;
}
```

If we have an element that has both classes applied:

```html
<p class="intro branding">Hello world</p>
```

Then the `.intro` style is applied first, and then the `.branding` style is applied next, making the text color `darkred`.

To apply multiple classes to the same element then use spaces as separators. The order of the class names in the class attribute does not matter. Both `class="intro branding"` and `class="branding intro"` have the same effect.

Specificity explains many “why isn’t my CSS working?” moments.
