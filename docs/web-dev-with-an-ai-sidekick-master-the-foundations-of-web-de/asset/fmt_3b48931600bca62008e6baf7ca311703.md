
This sets row gap first, column gap second. With Grid, you can explicitly set `row-gap` and `column-gap`.

# Responsive design

So far, everything you have styled assumes a comfortable desktop screen. These days, that assumption is wrong more often than it is right. Websites are viewed on phones, tablets, laptops, ultra-wide monitors, TVs, and everything in between. Responsive design is how you make one site adapt without breaking or forcing users to zoom and scroll sideways. Responsive design is mostly standard CSS applied with flexible sizing and layout decisions.

## What responsive design actually means

Responsive design does not mean *designing for mobile* and then stretching things for desktop. It means creating layouts that respond to available space.

A responsive page:

* Adjusts layout based on screen width
* Keeps text readable at all sizes
* Avoids horizontal scrolling
* Does not rely on fixed pixel widths everywhere

If your layout only works at one screen size, it is fragile.

## The viewport and why it matters

Every responsive web page starts with this line in the `<head>` section:

```
<meta name="viewport" content="width=device-width, initial-scale=1.0">
```

Without it, mobile browsers pretend they are much wider than they are and then scale the page down. The result looks tiny and broken.

With it, CSS pixels map more closely to the actual screen size. You only need to add this once, but forgetting it breaks everything that follows.

## Try it out: simulate mobile devices in your browser

You do not need a physical phone to test responsive layouts. In Chrome, open `Developer Tools` (`F12`), then click the device toolbar icon or press `Ctrl` + `Shift` + `M`.

Select a device like `iPhone` or `Pixel`, then resize the viewport. Watch how your layout changes as your media queries apply.

This is the fastest way to debug responsive CSS.

## Flexible layouts instead of fixed widths

The fastest way to ruin responsiveness is hard-coding widths everywhere.

For example, it is bad practice to set a fixed width:

```
main {
  width: 1200px;
}
```

It is much better to set a maximum width and let the width scale with the available width, with automatic margins and a sensible fixed padding for spacing inside content elements:

```
main {
  max-width: 1200px;
  margin: 0 auto;
  padding: 20px;
}
```

The preceding layout:

* Shrinks on small screens
* Stops growing on very large ones
* Stays centered and readable

Percentages and flexible units adapt naturally:

```
.container {
  width: 90%;
}
```

This allows content to breathe without pinning it to a specific device size.

## Responsive typography

Text should scale with the screen, but not dramatically.

Instead of tying everything to pixels, use relative units where appropriate.

You can set a font size for the root element of the page (`<html>`) as a starting point:

```
html {
    font-size: 100%;
}
```

And then set the sizes of other page elements using relative sizes:

```
h1 {
  font-size: 2rem;
}
```

`rem` stands for *root em*. It is relative to the font size of the root element, which defaults to `16px` in most browsers. So `2rem` would be `32px` at the default size. If you change the root font size, all `rem` values scale proportionally.

There’s also `em`, which is relative to the font size of the parent element, not the root. `rem` is generally preferred because it’s more predictable since it always refers to the same base, regardless of nesting. This improves accessibility and keeps proportions consistent.

Line length matters more than font size. Long lines are hard to read, especially on wide screens. That is why constraining content width is part of responsive design.

## Fluid font sizing with clamp()

So far, font sizes have been fixed relative to a base value. In responsive design, you can also make text scale smoothly between sizes instead of jumping at breakpoints.

CSS provides the `clamp()` function for this:

```
h1 {
  font-size: clamp(1.5rem, 2.5vw, 2.5rem);
}
```

This means:

* The font will never be smaller than `1.5rem`
* It will scale based on the viewport width (`2.5vw`)
* It will never grow larger than `2.5rem`

As the screen gets wider, the text grows gradually. On smaller screens, it shrinks, but stays readable. This approach avoids sudden jumps in size at media query breakpoints and can produce smoother, more natural typography.

Think of `clamp()` as setting boundaries: flexible within limits. You do not need to use `clamp()` as a beginner yet, but you will see it in CSS because it combines flexibility with control.

## Media queries

Media queries let you apply CSS only when certain conditions are true. Most commonly, this means screen width:

```
@media (max-width: 768px) {
  body {
    background-color: #ffffff;
  }
}
```

This rule only applies when the viewport is 768 pixels wide or less, roughly tablet and phone territory.

A practical example building on your earlier layout:

```
.layout {
  display: flex;
  gap: 20px;
}
@media (max-width: 768px) {
  .layout {
    flex-direction: column;
  }
}
```

On larger screens, content sits side by side. On smaller screens, it stacks vertically. Same HTML. Same CSS file. Different behavior based on space.

## Mobile-first thinking

A common beginner mistake is designing for desktop first and then trying to *fix* mobile with dozens of overrides.

A better approach is mobile-first design:

* Write simple styles that work on small screens
* Add enhancements for larger screens

That often looks like this:

```
.layout {
    display: flex;
    flex-direction: column;
    gap: 20px;
}
@media (min-width: 768px) {
    .layout {
        flex-direction: row;
    }
}
```

The default works everywhere. Larger screens get more complex layouts. This approach produces cleaner CSS and fewer surprises.

## Images and responsiveness

Images are a frequent source of layout breakage.

At minimum, every image should be constrained:

```
img {
  max-width: 100%;
  height: auto;
}
```

This prevents images from overflowing their containers and blowing up layouts on small screens.
