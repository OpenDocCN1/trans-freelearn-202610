
# Bash Fundamentals

## Why Bash?

* Why Bash scripts can run `Python`, `Docker`, `Git`, or any other tool
* Why errors often come from the program you launched, not from `Bash` itself
* Why the same `Bash` command behaves the same on macOS, Linux, WSL, and servers

`Bash` gives you direct, scriptable control over your development environment. You do not need to know everything it can do, but understanding the basics will make many everyday tasks faster, clearer, and less mysterious.

## Key Concepts

* **Terminal**: window (just input/output)
* **Shell (Bash)**: interpreter (understands commands)
* **Programs**: actual tools (`ls`, `python`, `docker`)

## Common Syntax Across Commands

`Bash` commands usually follow a predictable shape: a **command name**, followed by **options** (sometimes called flags), followed by arguments. Making this clear early helps you recognize patterns without needing to memorize everything.

For example:

```
ls -l src
```

* `ls` is the command (to list files)
* `-l` is an option (to use long, detailed format)
* `src` is an argument (the name of a folder to list)

```
docker run -p 8000:8000 image-name
```

* `docker` is the command (to use Docker)
* `run` is a subcommand (what you want Docker to do)
* `-p` is an option (publish a port)
* `8000:8000` is an argument (map local port to container port)
* `image-name` is an argument (the name of an image to run)

You do not need to memorize all the options yet. Focus on recognizing this space-delimited structure, as it will make new commands much easier to understand later.

## Stateful Commands

`Bash` is stateful, meaning that when you type commands, `Bash` maintains context. Your current working directory, environment variables, and command history all persist from one command to the next.

This is why `cd` (change directory) matters, why a command can work one moment and fail the next, and why restarting a terminal sometimes fixes things. New developers often assume each command runs in isolation. It does not.

## Command History and Editing

One useful result of `Bash` being stateful is that it remembers what you have done. Every command you type is stored in your command history, which means you rarely need to retype long or complex commands.

### Repeat Previous Commands

Press the ↑ (up arrow) key to cycle backward through previous commands:

```
docker run -p 8000:8000 my-image
```

If you just ran this command and want to run it again, press ↑ and press `Enter`. This is especially helpful when working with long commands or when you are experimenting and need to retry something.

### Search Your Command History

Instead of scrolling back line by line, you can search your command history:

1. Press `Ctrl` + `R`
2. Start typing part of a previous command, for example `docker`
3. `Bash` will show the most recent matching command

Press `Enter` to run it, or keep pressing `Ctrl` + `R` to cycle through matches.

### Edit Commands Before Running Them

When you recall a command using ↑ or `Ctrl` + `R`, you can edit it before pressing `Enter`. Developers do this constantly:

```
docker run -p 8000:8000 my-image
```

You might change just the port:

```
docker run -p 5000:5000 my-image
```

This is much faster and less error-prone than typing the whole command again.

### Why This Helps

Beginners often think they need to type every command from scratch. In practice, experienced developers rely heavily on command history to:

* Retry commands after fixing an error
* Make small adjustments to previous commands
* Explore and experiment more quickly

This is another example of how `Bash` maintains state between commands. Your history, current directory, and environment all persist, which is why the terminal becomes more useful the longer you use it.

You do not need to memorize every command. Focus on understanding what commands do, and let the `history` feature help you reuse them efficiently.

## Tab Completion

`Tab` completion is a feature provided by the shell, not the terminal. When you press `Tab`, the shell tries to autocomplete what you're typing, based on context:

* File and folder names
* Command names
* Options and flags (for some tools)

With `Bash`, basic completion works out of the box (files, folders, commands), but more advanced completion (like `Git` branches, `Docker` options) depends on `bash-completion` being installed.

`Zsh` is much more full-featured by default, with better suggestions, sometimes menu-style completion. `Zsh` is often enhanced further with frameworks like Oh My Zsh.

Across `Bash`, `Zsh`, and most environments, you can usually press `Tab` to complete file and folder names, and press `Tab` twice to show available options, and completion based on the current directory.

## Splitting Long Commands Across Lines

Some commands can become long and difficult to read, especially when they include multiple options or arguments. Instead of writing everything on one line, you can split a command across multiple lines using a backslash (`\`).

The backslash tells `Bash` that the command continues on the next line.

For example, instead of writing:

```
docker run -p 8000:8000 -v $(pwd):/app -e DEBUG=true my-image
```

You can write it like this:

```
docker run \
  -p 8000:8000 \
  -v $(pwd):/app \
  -e DEBUG=true \
  my-image
```

This makes the command easier to read and modify, especially when copying from documentation or working with complex setups.

Important rules:

* The backslash must be the very last character on the line
* Do not add spaces after the backslash
* `Bash` treats all lines as one continuous command

If you forget the backslash, `Bash` will try to run each line as a separate command, which usually leads to errors.

Many real-world commands, especially with tools like `Docker`, `Git`, or cloud CLIs, can become long and hard to manage. Splitting them across lines helps you:

* Understand each part of the command
* Avoid mistakes when editing
* Copy and paste commands more safely

You will often see this style in documentation and scripts. Even though it looks like multiple lines, `Bash` still runs it as a single command.

## Commands Can Be Combined

`Bash` works especially well with text. Everything is text in and text out. Commands write to standard output, errors go to standard error, and those streams can be redirected or connected together. The **pipe operator** `|` sends one command's output to another command's input:

```
ls -la | grep ".py"  # List only Python files
cat log.txt | wc -l  # Count lines in a file
```

Redirection using `>` or `>>` sends output to a file:

```
echo "Hello" > file.txt   # Write (overwrites)
echo "World" >> file.txt  # Append
```

These two operators let small commands work together.

You do not need to learn pipes and redirection in depth yet, but keep in mind that commands can be chained together, which is why the shell feels composable rather than monolithic.

## Creating Shortcuts with Aliases

As you start using the command line more often, you will notice that you type the same long commands repeatedly. `Bash` provides a simple way to create shortcuts for these commands using something called an alias.

An **alias** is just a short name that expands into a longer command.
