
Here, the missing colon at the end of the `if` statement causes a syntax error before the program even runs.

An `IndentationError` is specific to Python and occurs when indentation is inconsistent or invalid, as shown in the following code:

```
if True:
print("Hello")
```

Python expects the indented block after the colon. Errors like this are common when copying and pasting code or mixing tabs and spaces.

A `TypeError` happens when you use a value in a way that does not make sense for its type, as shown in the following code:

```
age = "30"
age + 5
```

Python cannot add a string and an integer, so it raises a `TypeError`. The error message usually explains exactly what types were involved.

A `ValueError` occurs when a value is the right type but has an invalid value:

```
age = int("thirty")
```

Here, Python knows how to convert strings to integers, but "thirty" is not a valid number.

But what if your code runs without throwing an error and still gives results that you do not expect? That's where debugging skills become vital.

## Debugging

**Debugging** starts with forming a simple hypothesis: what did I expect to happen, and what actually happened? Then you test that hypothesis by inspecting the program's state.

One of the simplest and most effective debugging tools is still the `print` function, as shown in the following code:

```
print(age)
print(type(age))
```

Printing values at key points in your program helps you confirm whether variables contain what you think they do. This approach is not elegant, but it is honest and effective, especially for beginners.

## Make incremental changes

Another important habit is making small changes and re-running the program often. If you change ten things at once and something breaks, you do not know which change caused the problem. If you change one thing and re-run, the cause is obvious.

VS Code also provides basic debugging support through breakpoints and variable inspection, but you do not need to master the debugger yet. Understanding error messages and using simple print statements will take you surprisingly far.

One final idea to internalize is that error messages are part of Python's documentation. They are written by humans and are meant to be read. When Python says something is not defined, incompatible, or invalid, it is almost always telling the truth. Your job is to connect that message to the code you wrote.

## Handling runtime errors safely

`try` / `except` blocks are how Python handles runtime errors safely. They let you protect parts of your program that might fail and decide what should happen instead of letting the program crash.

A `try` block contains code that might fail. When something goes wrong, Python does not continue. It raises an exception, which means it stops normal execution and signals that an error has occurred.

If an exception occurs, Python stops executing the `try` block immediately and looks for a matching `except` block to handle the problem:

```
try:
    age = int(input("How old are you? "))
except ValueError:
    print("Please enter a number.")
```

In the preceding code, if the age conversion succeeds, the `except` block is skipped. If it fails because the user enters something that cannot be converted to a number and the `int` function raises a `ValueError`, the program prints a friendly message instead of crashing.

User input is one of the most common sources of errors. Users type unexpected values, press `Enter`, or paste nonsense. We can handle this common issue easily:

```
try:
    quantity = int(input("Quantity: "))
    price = float(input("Price: "))
    total = quantity * price
    print(f"Total: {total}")
except ValueError:
    print("Invalid input. Please enter numbers only.")
```

Here, both conversions are protected. If either fails, the program handles it gracefully.

File operations fail for reasons outside your control: missing files, permissions, or disk issues. Again, we can handle these situations:

```
try:
    with open("config.txt", "r", encoding="utf-8") as file:
        text = file.read()
except OSError:
    print("Could not read configuration file.")
```

Without the `try` / `except`, the program would crash even though the error is not necessarily fatal.

Catching specific exception types is important. This avoids hiding unrelated bugs. Good practice is to specify which error type you expect:

```
try:
    result = 10 / value
except ZeroDivisionError:
    print("Cannot divide by zero.")
```

Other errors will still stop the program. Specific exceptions make error handling clearer and safer.

Good error handling anticipates what can go wrong, catches only what it understands, and leaves everything else visible so problems can be fixed properly.

# Modules, imports, and packages

As programs grow, putting all your code into a single file quickly becomes unmanageable. Python solves this problem with **modules**. A module is simply a Python file. Any `.py` file can be used as a module, and modules let you organize code and reuse it across multiple programs.

## Importing standard modules

At the most basic level, you make a module available in your current code file by *importing the module*, as shown in the following code:

```
import math
```

The preceding code tells Python to load another module and make its contents available to your program. In this case, `math` is part of Python's standard library, which means it ships with Python itself.

Once imported, you access names inside a module using dot notation, as shown in the following code:

```
import math
result = math.sqrt(16)
print(result)
```

Here, `math.sqrt` refers to the `sqrt` function defined inside the `math` module. This explicit naming is intentional. It avoids confusion about where functions come from and makes code easier to read.

Python also allows you to import specific names from a module:

```
from math import sqrt
result = sqrt(16)
```

This is shorter, but it comes with a trade-off. When you import names directly, it can be harder to tell where they originated, especially in larger programs. For beginners, using `import module_name` and dot notation is usually clearer.

## Defining your own modules

Modules are not limited to the standard library. You can import your own Python files as well. Suppose you have two files in the same folder:

Here is a file named `helpers.py`:

```
def greet(name):
    print("Hello,", name)
```

Here is a file named `main.py`:

```
import helpers
helpers.greet("Alice")
```
