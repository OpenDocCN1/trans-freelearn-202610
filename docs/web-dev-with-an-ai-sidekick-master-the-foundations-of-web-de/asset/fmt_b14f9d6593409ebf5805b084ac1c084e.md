# Setting up Django

Before writing any Django code, you need a working Python environment and a clean project setup. Django runs anywhere Python runs, so the steps are broadly the same on Windows, macOS, and Linux. The main differences are command syntax and file paths, which will be pointed out where relevant.

## Creating and activating a virtual environment

Next, we will create a virtual environment for your Django project. This isolates your project’s dependencies from the rest of your system and avoids version conflicts later.

Create a folder named `Chapter09`. Inside that folder, run the virtual environment command:

* On Windows, run: `python -m venv .venv`
* On macOS and Linux, run: `python3 -m venv .venv`

This creates a `.venv` folder containing a private Python installation for this project.

Now activate the virtual environment:

* On Windows, run: `.venv\Scripts\activate`
* On macOS and Linux, run: `source .venv/bin/activate`

When activation succeeds, your terminal prompt will usually change to show the virtual environment name:

```
(.venv) C:\web-dev-ai\Code\Chapter09>
```

From this point on, any Python packages you install will be limited to this project.

## Creating Django projects

At the command prompt or terminal, create your first Django project and name it `scribble` by running the following command:

```
django-admin startproject scribble
```

This creates a new folder called `scribble` with Python files like `manage.py` inside. The outer `scribble` folder is simply a container. The inner `scribble` folder holds the project configuration, including settings, URL configuration, and server startup code. At this stage, do not worry about memorizing these files. You will revisit them as they become relevant.

To confirm everything works, change into the outer `scribble` project directory using `cd scribble` and then run the development server using the following command:

```
python manage.py runserver
```

# Django URL patterns and routing

URLs are the entry point to every Django request. Before a view runs and before a template is rendered, Django must decide which piece of code should handle an incoming HTTP request. That decision is made by Django’s URL routing system.

At a high level, Django works like this: a request arrives with a path such as `/posts/hello-django/`. Django compares that path against a list of URL patterns, from top to bottom, until it finds the first match. The matching pattern determines which view function or class is called and what data is passed into it.

## URL patterns

URL patterns are defined using the `path()` function. A minimal example looks like this:

```
from django.urls import path
from .views import post_list
urlpatterns = [
    path("", post_list, name="post_list"),
]
```

Note the following about the preceding code:

* The empty string `""` represents the root of whatever URL prefix this file is included under.
* The `name` argument is more important than it first appears. It gives the URL a stable identifier that you can refer to elsewhere without hard-coding paths.
