
# Django Models and Migrations

## Migrations

Once you define or change a model, you need to apply the change to the database. Django does this using `migrations`. Think of `migrations` as version control for your schema.

Run the following command to create migration files that describe the schema change:

```
python manage.py makemigrations
```

Note the following output:

```
Migrations for 'blog':
  blog\migrations\0001_initial.py
    + Create model Post
```

Run the following command to apply those migrations to the database:

```
python manage.py migrate
```

Note the following output:

## Relationships

Relationships between models are one of Django's main strengths. Here are the three most common relationship types.

### One-to-Many Relationships

`One-to-many` uses `ForeignKey`. For example, an author can have many posts:

```
class Author(models.Model):
    name = models.CharField(max_length=100)
    def __str__(self) -> str:
        return self.name
class Post(models.Model):
    author = models.ForeignKey(Author, on_delete=models.CASCADE, related_name="posts")
    title = models.CharField(max_length=200)
    body = models.TextField()
    created_at = models.DateTimeField(auto_now_add=True)
    def __str__(self) -> str:
        return self.title
```

`on_delete=models.CASCADE` means if an author is deleted, their posts are deleted too. Django forces you to choose an `on_delete` behavior because databases need a clear rule for referential integrity.

### One-to-One Relationships

`One-to-one` uses `OneToOneField`. This is common for profile-style extensions, where each user has exactly one profile:

```
from django.contrib.auth.models import User
class Profile(models.Model):
    user = models.OneToOneField(User, on_delete=models.CASCADE)
    bio = models.TextField(blank=True)
```

### Many-to-Many Relationships

`Many-to-many` uses `ManyToManyField`. For example, posts can have many tags and tags can belong to many posts:

```
class Tag(models.Model):
    name = models.CharField(max_length=50, unique=True)
    def __str__(self) -> str:
        return self.name
class Post(models.Model):
    title = models.CharField(max_length=200)
    tags = models.ManyToManyField(Tag, blank=True, related_name="posts")
```

## Creating, Updating, and Deleting Model Data

Once you have defined some models, you can create, update, and delete instances of them using the following standard functions:

* `<model_name>.objects.create(<required_parameters>)`: Creates and returns a new instance (object) of the specified model
* `<model>.save()`: Save field changes to this model instance
* `<model>.delete()`: Delete this model instance

You can query a model using the following standard functions:

* `<model_name>.objects.filter(...)`: Returns a QuerySet with objects that match the criteria specified
* `<model_name>.objects.order_by(...)`: Returns a QuerySet with objects sorted by the field(s) specified

A `QuerySet` is a representation of a database `query`, not yet the results. Instead of immediately fetching data, a QuerySet describes what data you want, and Django only runs the actual SQL when the results are needed. This allows you to filter, sort, and combine queries incrementally while still producing a single efficient database query once you need the results.

Django `QuerySets` are lazy. Building a `QuerySet` does not hit the database until you actually evaluate it, for example, by iterating over it, slicing it, or converting it to a list. This is why you can chain filters without paying a cost for each step.

A common way to evaluate a QuerySet is to pass it to the `list` function:

```
list(<queryset>)
```

## Managing Data with the Django Shell

With models in place, Django gives you a Pythonic way to work with your data. Open the Django shell:

```
python manage.py shell
```

At the `>>>` prompt, try some basic operations:

1. Start by importing some classes:

```
from django.contrib.auth.models import User
from blog.models import Author, Post
from django.utils.text import slugify
```

2. Create a user (required for `Author`):

```
user = User.objects.create_user(
    username="mark",
    email="mark@example.com",
    password="testpassword123"
)
```

3. Create an author profile and reference the user you created:

```
author = Author.objects.create(
    user=user,
    display_name="Mark",
    bio="Author and Django enthusiast"
)
```

4. Create a blog post and reference the author:

```
post = Post.objects.create(
    author=author,
    title="Hello, Django",
    slug=slugify("Hello, Django"),
    body="This is my first post.",
    status="published"
)
```

### Prompt

What is the `slugify` function and the `slug` class used for in Django?

1. Show the `post` object:

```
post
```

2. Query recent posts:

```
recent_posts = Post.objects.order_by("-created_at")[:5]
list(recent_posts) # convert the queryset to a list
```

3. Query published posts:

```
published_posts = Post.objects.filter(status="published")
list(published_posts)
```

4. Show the SQL that Django will run:

```
print(published_posts.query)
```

5. Update an existing post:

```
post.title = "Hello, Django (Edited)"
post.slug = slugify(post.title)
post.save()
```

6. Delete a post:

```
post.delete()
```

7. Exit the shell:

```
exit()
```

The `objects` attribute is Django's model manager. It provides query-building methods like `create`, `get`, `filter`, `exclude`, and `order_by`.
