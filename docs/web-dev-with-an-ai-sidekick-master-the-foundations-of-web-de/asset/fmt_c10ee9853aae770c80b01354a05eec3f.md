
3. It installs dependencies only if a `requirements.txt` file exists.

4. It applies migrations every time.

5. It starts the server.

Each step is something you were already doing manually.

## Why automation scripts matter

You are not writing code for its own sake. You are capturing a process:
* This is how this project should be started.

That has a few benefits:

* You do not forget the steps.
* You avoid subtle environment issues.
* You reduce typing and small mistakes.
* You make the workflow obvious to someone else reading the project.

If someone else clones your repository, they do not need instructions like "run these five commands." They can just run:

```
./run_dev.sh
```

## Adding a configurable port for the server

You can make the script slightly more flexible by accepting a port number:

```
PORT="${1:-8000}"
echo "Starting server on port $PORT..."
python manage.py runserver "$PORT"
```

Now you can run:

```
./run_dev.sh 5000
```

or fall back to the default:

```
./run_dev.sh
```

This is a typical use for Bash in a project: take a setup routine you already know and save it as a script.

**Good practice**: This script assumes a Unix-like environment (Linux, macOS, or WSL on Windows). On native Windows without WSL, activation uses a different path (`.venv\Scripts\activate`). In real projects, teams often provide separate scripts or use tools that handle cross-platform differences.

# Using AI for shell help

The command line has a reputation for being hostile, largely because error messages can be terse and documentation often assumes prior knowledge. AI tools can make the command line easier to learn. Used properly, they act like an on-demand explainer rather than a magical command generator.

A sensible way to use AI with Bash is to ask why something works or fails, not just what to type. For example, if you see a command in documentation that you do not understand, you can ask:

* Please explain what this Bash command does, piece by piece:

```
docker run -p 8000:8000 -v $(pwd):/app my-image
```

A good AI response will break the command into flags, arguments, and substitutions, helping you build intuition rather than encouraging blind copying.

## Help with syntax

AI is also helpful for syntax reminders. Bash has many small rules that are easy to forget, such as spacing around brackets or how variables are expanded. Instead of searching through man pages, you can ask targeted questions like:

* How do I loop over all `.txt` files in Bash and print their names?
* What does `set -e` do in a Bash script, and when should I avoid it?

## Help with errors

When a script fails at the command prompt, pasting the error message and a small, relevant snippet of the script often leads to useful explanations:

* This Bash script exits immediately with `permission denied`. Why?
* Here is my script and the error output. What is wrong with it?

This works particularly well because Bash errors are often indirect. The line that fails is not always the line that caused the problem, and AI tools are good at spotting those patterns.

If you're trying out your scripts in a code editor like VS Code, then you don't even have to copy and paste into your preferred chatbot. GitHub Copilot Chat will inspect your active terminal session automatically, as the terminal context is included as part of your conversation. It shows the last command, working directory, and exit code for each open terminal.

**Prompt**: Please explain common Bash error messages like `permission denied` or `command not found`.

## Beware that AI has limited context

That said, there are limits. AI chatbots like ChatGPT and Gemini that run in a web browser do not see your file system, environment variables, or installed software. If a suggested command deletes files or modifies system state, it will do so just as eagerly as if a human had written it. Treat AI output as advice, not authority.

VS Code with GitHub Copilot, Rider with its AI Assistant, and CLI tools like Claude Code and OpenAI Codex do have lots of tools to gather context so are much better at providing dynamic relevant help. You will work with these more in later chapters.

Before running an AI-suggested command, make sure you can say what it reads, what it writes, and what it might delete or change. If you cannot explain that much, ask the AI to break the command down first.

That makes AI most useful as a command explainer, not as a source of commands to paste blindly.

**Prompt**: How can I safely debug a Bash script step by step?

## References

Bash has been around for decades, and its documentation reflects that maturity. Some resources are reference-heavy, others are more tutorial-oriented. It is useful to know which to reach for depending on whether you are learning or troubleshooting.

### GNU Bash Reference Manual

The authoritative source is the GNU Bash Reference Manual. This is the specification-level documentation for Bash and is maintained as part of the GNU Project. You can read it online at the following link:

[https://www.gnu.org/software/bash/manual/bash.html](https://www.gnu.org/software/bash/manual/bash.html)

This manual is exhaustive. It explains Bash syntax, built-in commands, variables, quoting rules, redirection, job control, and scripting features in precise terms. You would not normally read it cover to cover, but it is excellent when you need to understand exactly how something behaves.

### Bash man page

Closely related is the Bash `man` page, which is what you see when you type:

```
man bash
```

This is more concise and is often quicker when you just need a reminder about syntax or options. For `man` pages on specific commands, enter `man <command>`, for example:

```
man ls
man cd
man rm
```
