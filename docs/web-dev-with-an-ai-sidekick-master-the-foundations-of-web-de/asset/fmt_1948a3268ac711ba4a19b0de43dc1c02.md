
# Git Setup and Workflow for TallyApp

## Creating .gitignore

Create a file named `.gitignore` at the root of your project and add:

```
.venv/
__pycache__/
*.py[cod]
*.sqlite3
.env
.DS_Store
```

This ignores virtual environments, Python bytecode, SQLite databases, environment variable files, and operating system clutter.

**Good practice**: If you use SQLite for development, ignoring `db.sqlite3` is recommended. Your database state should be reproducible from migrations, not committed as a binary file.

You should now see that fewer files will be committed, as shown in *Figure 11.7*.

**Warning!** Do not ignore `*.md` files. Markdown files are often used for documentation, README files, architecture notes, and even AI prompts. In many projects, they are part of the source of truth, not generated output. Ignoring them would mean losing important context and documentation from your repository. A good rule of thumb is this: only ignore files that can be recreated automatically (like virtual environments, caches, or compiled files). If a file contains human-written knowledge, it should almost always be committed.

## Making Your First Commit

Once Git is initialized:

1. Navigate to **Source Control** where you will see a list of untracked files.
2. Click the **+** icon next to **Changes** to stage everything, as shown in *Figure 11.7*:

![](Images/B34553_11_07.png)

*Figure 11.7: Stage All Files*

3. Enter a commit message like: `Initial TallyApp project scaffolding`, and then click **Commit**, as shown in *Figure 11.8*:

![](Images/B34553_11_08.png)

*Figure 11.8: Source Control panel showing 0 Changes, 10 Staged Changes, and the commit message box*

**Good practice**: A commit should describe intent, not mechanics. Good messages explain what changed and why. Examples for TallyApp: Add Survey model and admin registration, Create survey CRUD views and templates, Add login protection to survey pages, Improve styling of survey list.

## The Daily Git Workflow

As you build TallyApp, follow this loop:

1. Make sure you have no changed files.
2. Make a small change.
3. Run the app and verify it works.
4. Stage all files.
5. Write a clear commit message.
6. Commit.

This discipline makes your history readable and makes debugging easier later.

In Source Control:

* Files under **Changes** are modified but not staged.
* Files under **Staged Changes** will be included in the next commit.

You can stage individual files using the **+** icon.

## Creating a Branch for a Feature

Branches let you experiment without risking the `main` branch.

To create a branch:

1. Click the branch name in the bottom-left of VS Code, usually `main`, as shown in *Figure 11.9*:

![](Images/B34553_11_09.png)

*Figure 11.9: Creating a new Git branch*

2. Select **Create new branch**, and type a name like: `feature/home-page`, and then press *Enter*.
3. At the command prompt or terminal, create a new feature:

```
python manage.py startapp homepage
```

4. In `tallyapp/settings.py`, add the app, as shown highlighted in the following code:

```
INSTALLED_APPS = [
    'django.contrib.admin',
    'django.contrib.auth',
    'django.contrib.contenttypes',
    'django.contrib.sessions',
    'django.contrib.messages',
    'django.contrib.staticfiles',
    "homepage",
]
```

5. In `homepage/views.py`, add statements to import some types, and define two functions, as shown highlighted in the following code:

```
from django.contrib.auth.decorators import login_required
from django.contrib.sessions.models import Session
from django.shortcuts import render
from django.utils import timezone
# Create your views here.
def _active_authenticated_user_count() -> int:
    """
    Approximation: count non-expired sessions that have an authenticated user id.
    This counts sessions, not unique users. One user on two devices counts twice.
    """
    now = timezone.now()
    active_sessions = Session.objects.filter(expire_date__gt=now)
    count = 0
    for s in active_sessions:
        data = s.get_decoded()
        if data.get("_auth_user_id"):
            count += 1
    return count
def home(request):
    context = {
        "active_user_count": _active_authenticated_user_count(),
    }
    return render(request, "homepage/home.html", context)
```

What this *signed-in users* number really means: It counts users with a valid, unexpired session. It does not guarantee they are actively using the site this second. It may count the same person multiple times (phone + laptop). It can stay non-zero for a while even if people close the browser, because sessions often expire hours or days later. This approach loads all sessions from the database, which works fine for a small project but would be too slow for a production site with thousands of sessions. The leading underscore in the function name `_active_authenticated_user_count` is a Python convention that signals that this function is an internal helper, not part of the public API.

6. In the `homepage` folder, create a `urls.py` file:

```
from django.urls import path
from .views import home
urlpatterns = [
    path("", home, name="home"),
]
```

7. In `tallyapp/urls.py`, add a reference to the new feature, as shown highlighted in the following code:

```
from django.contrib import admin
from django.urls import path, include
urlpatterns = [
    path('admin/', admin.site.urls),
    path("", include("homepage.urls")),
]
```

8. Create `templates/base.html`:

```
<!DOCTYPE html>
<html>
<head>
    <title>{% block title %}My Django Site{% endblock %}</title>
</head>
<body>
    <header>
        <h1>My Django Site</h1>
    </header>
    <main>
        {% block content %}{% endblock %}
    </main>
</body>
</html>
```

9. Create `templates/homepage/home.html`:

```
{% extends "base.html" %}
{% block title %}Home · TallyApp{% endblock %}
{% block content %}
<div class="card">
  {% if user.is_authenticated %}
    <p class="muted">Hi {{ user.username }}. You're signed in.</p>
  {% else %}
    <p class="muted">You're not signed in yet. Log in to admin.</p>
    <div class="card-actions">
      <a class="btn primary" href="/admin">Log in</a>
    </div>
  {% endif %}
  <hr style="border:0;border-top:1px solid rgba(255,255,255,0.14); margin:16px 0;">
  <p class="muted">
    Signed-in users right now (approx): <strong>{{ active_user_count }}</strong>
  </p>
</div>
{% endblock %}
```

10. Now commit as before.

Your work on the `home-page` feature is isolated and you can switch between it and the `main` branch at will.

## Merging a Branch

To merge back into `main`:

1. Switch back to `main`.
2. Open the **Command Palette** and choose **Git: Merge Branch**.
3. Select your feature branch.

If no conflicts exist, Git creates a merge commit.

## Connecting to a Remote Git Server

A remote Git server provides backup and enables collaboration:

1. In **Source Control**, click **Publish Branch**, as shown in *Figure 11.10*:

![](Images/B34553_11_10.png)

*Figure 11.10: VS Code showing the “Publish Branch” button*

2. Sign in when prompted, and then select the **public TallyApp** repository.
3. After publishing, your commits are pushed to GitHub.
