
# The Browser Console

The browser console is the first debugging tool you should reach for when writing JavaScript. Logging data to the console lets you see what your code is doing while it runs, without changing what appears on the page. When something behaves strangely, the console is usually the first place you should look.

## Writing to the Console with `console.log()`

The most common way to write to the console is `console.log()`. You pass values into it, and the browser prints them to the console in the order they are received, as shown in the following code:

```javascript
console.log("Hello from JavaScript");
```

When this statement runs, the text appears in the **Developer Tools Console**. It does not affect the page itself at all.

## Logging Variables

You can log variables to see their current values. This is extremely useful when you are unsure whether a variable contains what you expect:

```javascript
let age = 42;
console.log(age);
```

The console will display `42`. If it does not, you know the problem is not further down the code. That is how you narrow down where the bug is.

## Logging Multiple Values

You can log multiple values in a single call. JavaScript will print them left to right, separated by spaces:

```javascript
console.log(typeof age, age);
```

Here is what is happening step by step:

1. First, `typeof age` is evaluated. The `typeof` operator returns a `string` describing the type of the value stored in the variable named `age`, such as `"number"`, `"string"`, or `"boolean"`.
2. Second, `age` itself is evaluated to its current value.
3. Finally, both results are passed into `console.log`, which prints them together. In the console, you would see something like the following output:

```
number 42
```

This pattern of logging to the console is very common because it answers two questions at once: what is the value, and what type is it?

## Combining Strings and Labels with Values

Strings and labels are often combined with values to make logs easier to read, as shown in the following code:

```javascript
console.log("Age:", age);
console.log("Type of age:", typeof age);
```

This is especially helpful once you have many logs and need to scan the output quickly.

## Other Console Methods

There are also related console methods that are worth knowing, even if you mostly use `console.log`, as shown in the following code:

```javascript
console.warn("This is a warning");
console.error("This is an error");
```

Warnings and errors are styled differently in the console, making them stand out. This can help when scanning large amounts of output.

A practical rule of thumb is to log early and log often while learning, then remove or reduce logs once your code works. Logging is not a sign of weakness or inexperience. It is how you make invisible program state visible.

## Using Template Literals for Custom Output

Template literals allow you to embed variables and expressions directly inside a `string`, instead of manually concatenating pieces together.

Inside a template literal, anything written as `${...}` is evaluated as JavaScript. The result is converted to a `string` and inserted at that position. For example, the following code:

```javascript
let message = `Message: Title is "${pageTitle}", clicks = ${clicks}.`;
```

The preceding code statement builds a readable message by inserting variable values into a string. Let’s break the statement down:

* The text is wrapped in backticks, not quotes. Backticks define a template literal.
* `Message: Title is "` is just literal text.
* `${pageTitle}` is replaced with the current value stored in the `pageTitle` variable.
* `", clicks = "` is more literal text.
* `${clicks}` is replaced with the current value stored in the `clicks` variable.
* `.` is the final literal character.

If `pageTitle` is `"Playground"` and `clicks` is `1`, the final `string` that JavaScript produces is:

```
Message: Title is "Playground", clicks = 1.
```

## Variables for Storing Data

Variables are how you store information so you can use it later. In up-to-date JavaScript, you will mostly see variables declared with `let` and `const`. A variable is a named place in your computer’s memory where your program stores a value. That value might be a number, some text, a `true` or `false` value, or something more complex like an object.

### Good Practice: `var` vs `let`/`const`

You’ll encounter `var` in older JavaScript code and AI-generated snippets. `var` was the original way to declare variables, but it has confusing scoping behavior because variables declared with `var` are function-scoped, not block-scoped, which means they can leak out of `if` blocks and loops. Modern JavaScript uses `let` and `const` instead. If you see `var`, mentally replace it with `let`.

For example, you might store a user’s name or a counter that tracks how many times a button has been clicked. `let` is used when the value is expected to change. `const` is used when the variable should always point to the same value.

### Good Practice: Choosing `let` or `const`

A common beginner mistake is using `const` everywhere and then being surprised when JavaScript refuses to let the value change. The rule of thumb is simple. If the value will change, use `let`. If it should not, use `const`.

This example shows how reassignment works and why a `const` variable cannot be reassigned a new value.

In `index.html`, after the existing `<script>` element, add a new `<script>` element to reference a new code file named `variables.js`, as shown highlighted in the following code:

```html
<script src="code-order.js"></script>
<script src="variables.js"></script>
```

In the same folder as the HTML file, create the code file named `variables.js`, and enter the following code:

```javascript
statusElement.textContent = "Status: Demonstrating variables.";
let clicks = 0; // This value can change.
const pageTitle = "Playground"; // This value will never change.
messageElement.textContent = `Message: Title is "${pageTitle}", clicks = ${clicks}.`;
clicks = clicks + 1;
console.log("After increment, clicks =", clicks);
messageElement.textContent = `Message: Title is "${pageTitle}", clicks = ${clicks}.`;
// Try uncommenting the next line to see the error.
// pageTitle = "New Title";
```

Note that `variables.js` uses `statusElement` and `messageElement` even though they were declared in `code-order.js`. This works because all the `<script>` tags share the same global scope. It’s as if all the code were in one giant file. For now, you can think of it as one shared global scope. This is convenient for learning but becomes problematic in larger projects. In later chapters, you’ll learn about JavaScript modules, which give each file its own private scope.

Refresh the web page and note the following:

* The variable named `clicks` changes from `0` to `1`.
* The variable named `pageTitle` does not change. You can still change the page title in the DOM, but the variable `pageTitle` cannot be reassigned.

## Scope: Where Your Variables Live

Scope describes where a variable can be accessed in your code. In other words, it answers the question: where does this variable exist, and who can use it?
