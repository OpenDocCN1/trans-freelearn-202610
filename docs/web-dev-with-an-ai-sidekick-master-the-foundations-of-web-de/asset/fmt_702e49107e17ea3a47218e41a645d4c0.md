
## Exiting the SQLite command prompt

To exit the SQLite command prompt, do the following:

- On Windows, press `Ctrl` + `C` twice.
- On macOS, press `Ctrl` + `D`.

## Setting up SQLite for macOS and Linux

On macOS, SQLite is included in the `/usr/bin/` directory as a command-line application named `sqlite3`.

On Linux, you can get set up with SQLite using the following command:

```
sudo apt-get install sqlite3
```

SQLite can be downloaded and installed for other OSs from the following link: https://www.sqlite.org/download.html.

## Creating a Media sample database for SQLite

Now we can create a sample database for SQLite using a SQL script:

1. Create a folder named `Chapter07`.
2. Download the script to create a `Media` database for SQLite from the following link and save it to your local `Chapter07` folder: https://github.com/markjprice/web-dev-ai/tree/main/Code/Chapter07/Media.sql.
3. Start a command prompt or terminal in the `Chapter07` folder:
   - On Windows, start **File Explorer**, right-click the `Chapter07` folder, and select **New Command Prompt at Folder** or **Open in Terminal**.
   - On macOS, start **Finder**, right-click the `Chapter07` folder, and select **New Terminal at Folder**.
4. Execute the SQL script using SQLite to create a `Media.db` database file, as shown in the following command:

```
sqlite3 Media.db -init Media.sql
```

**Warning!** If you get the error `cannot open: "Media.sql"`, then you need to specify the path to the SQL script or copy it to the current directory because it is not being found in the current directory.

5. When the work is done, you will see the SQLite command prompt `sqlite>`, as shown in the following output:

```
-- Loading resources from Media.sql
SQLite version 3.51.2 2026-01-09 17:27:48
Enter ".help" for usage hints.
sqlite>
```

6. To exit the SQLite command prompt, do the following:
   - On Windows, press `Ctrl` + `C` twice.
   - On macOS or Linux, press `Ctrl` + `D`.
7. You can leave the command prompt or terminal window open because you will use it again soon.

# Writing queries and joining tables

This section focuses on reading data from one or more tables. Writing queries is about asking the database clear questions and getting back predictable, useful results. We will use the `Media` database you have already created.

## Tools for running queries

SQLite has good tooling on every major platform, and you do not need much to get started. Below are the most practical cross-platform options, what they are good at, and when you would use each one.

### SQLite command-line tool

The `sqlite3` CLI is the reference tool that ships with SQLite itself. It runs on macOS, Linux, and Windows, and it behaves consistently everywhere.

It is worth using because:

- Zero abstraction between you and SQL
- Excellent for learning, debugging, and scripting
- Good for running schema files and seed scripts
- Makes it very clear what SQL is doing, without UI noise

Typical usage looks like the following command:

```
sqlite3 media.db
```

Then, at the SQLite prompt `sqlite>`, you enter SQL statements and special commands like `.tables` (to list all the tables in the database) or like `.schema` to view schema/structure. For example, enter the following command:

```
.tables
```

You should see a list of the six tables, as shown in the following output:

```
credits   episodes  people    roles     seasons   titles
```

Now show the schema, aka the structure of the `titles` table, as shown in the following command:

```
.schema titles
```
