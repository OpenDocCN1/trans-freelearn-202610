
# TallyApp – 项目简介

## 1. 概述

### 项目目标
TallyApp 是一个 Web 应用程序，允许经过批准的用户创建调查并公开发布。公众成员无需注册即可参与调查。调查创建者可以查看个别回复和汇总结果。

### 解决的问题
TallyApp 允许个人或组织使用多种类型的调查问题快速收集结构化反馈，而无需构建自定义软件。

---

## 2. 目标用户

### 调查创建者
- 必须使用有效的电子邮件地址注册账户。
- 必须经过管理员批准才能创建调查。
- 可以创建、发布和结束调查。
- 可以查看结果（个别和汇总）。

### 调查参与者
- 无需注册。
- 可以匿名提交回复。

### 目标用户的主页
- 描述网站功能。
- 两个大按钮用于：
    1. 创建调查（注册或登录）
    2. 参与调查

---

## 3. 核心功能（版本 1 范围）

### 认证与授权
- 定义一个名为 `SurveyCreators` 的自定义组，其成员资格授权调查创建功能。
- 调查创建者注册。
- 用户创建调查前需要管理员批准；用户获批后将被添加到 `SurveyCreators` 组。
- 登录和登出。
- 只有 `SurveyCreators` 组的成员才能创建调查。

### 调查创建
- 创建或编辑调查，包含：
  - 标题
  - 描述
  - 开始日期
  - 可选的结束日期
  - 发布状态
  - “显示在主页”标志（默认：true）
- 未发布的调查没有结果。
- 调查发布后不能编辑。
- 调查不能取消发布。
- 调查可以提前结束。此操作不可逆。
- 调查可以是开放式的（无结束日期）。
- 一旦结束，用户无法参与调查。
- 调查包含零个、一个或多个问题项，可通过调查编辑页面添加、编辑或移除。
- 每个调查都有一个唯一的公共 URL，在创建后立即显示在调查编辑页面上。
- `start_date` 在未来的已发布调查无法参与，并显示带有开始日期的警告页面。

### 问题类型
每个调查可以包含以下类型的多个问题：
1. 单选题
2. 多选题
3. 文本输入（自由形式）
4. 矩阵评分，带有评分范围，例如针对一个或多个项目的 1 到 5 分

问题/选项创作 UI 必须完全实现。
- 混合问题类型的动态表单处理。

### 公共调查访问
- 公共主页列出已发布的调查（如果“显示在主页”为真），并提供参与调查的公共 URL。
- 调查在列表视图中支持分页。
- 公共用户可以提交回复。
- 调查可能显示“截至目前”的结果。

### 结果
调查创建者可以：
- 查看汇总结果。
- 查看个别回复。
- 即使调查仍在进行中也可查看回复。
- 查看适合结果的饼图和条形图。
- 查看按电子邮件/IP/会话划分的重复提交报告。

### 图形、样式和品牌
- 用于编辑页面的徽标和调查草图插图的 `SVG` 资源。
- UI 使用 `CSS` 和 `SVG` 文件为 TallyApp 提供微妙的品牌标识：渐变标题或导航栏、彩色徽标 `SVG`、浅色调背景区域。

### 数据存储
- `SQLite` 数据库。
- 具有清晰外键关系的关系模型。

### 测试
- 基本单元测试：
  - 模型行为
  - 权限
  - 发布规则
  - 调查回复提交
- 使用 `Playwright` 进行端到端测试：
  - 每个用户故事。

## 4. 非目标（超出范围）
- 无支付功能。
- 无社交认证。
- 无实时更新（无 `WebSockets`）。
- 无高级分析。
- 无 `CSV` 导出。
- 无 `REST API`。
- 除管理员批准和标准用户外，无角色系统。

---

## 5. 用户故事
1. 作为用户，我想注册以便创建调查。
2. 作为管理员，我想在用户创建调查前批准他们。
3. 作为已批准用户，我想创建并发布调查。
4. 作为调查创建者，我想提前结束调查。
5. 作为公共访客，我想在不注册的情况下完成调查。
6. 作为调查创建者，我想查看汇总结果和个别回复。

## 6. 数据模型（高层）

### 用户
- 扩展 `Django` 的内置 `User` 模型。
- 有一个名为 `SurveyCreators` 的自定义组，其成员资格授予创建、编辑和删除调查功能的访问权限。

### 调查
- 创建者（指向 `User` 的 `ForeignKey`）
- 标题
- 描述
- 开始日期
- 可选的结束日期
- 发布标志
- 显示在主页标志
- 创建时间戳
- 提前结束标志（可选）

### 问题
- 调查（`ForeignKey`）
- 文本
- 问题类型（单选、多选、文本）
- 排序字段

### 选项
- 问题（`ForeignKey`）
- 文本
- 排序字段

### 回复
- 调查（`ForeignKey`）
- 可选的电子邮件标识符
- 提交时间戳

### 答案
- 回复（`ForeignKey`）
- 问题（`ForeignKey`）
- 选中的选项（`ManyToMany` 或中间模型，视情况而定）
- 文本答案（用于文本问题）

## 7. 技术约束
- `Python 3.14`
- `Django 6.x`
- `SQLite` 数据库
- 简洁、现代、移动端友好的响应式 UI
- 服务端渲染模板
- 无需 JavaScript 框架

---

## 8. 安全与权限
- 只有经过批准的用户才能创建调查。
- 只有调查创建者（和管理员）可以查看他们自己调查的结果。
- 公共用户可以提交回复。
- 调查发布后不能修改。
- 只有管理员可以批准用户创建调查。

---

## 9. 完成定义
- 用户可以注册和登录。
- 管理员可以批准用户。
- 经过批准的用户可以创建和发布调查。
- 公共用户可以提交回复。
- 调查创建者可以查看结果。
- 分页功能正常。
- 基本单元测试通过。
- 应用程序在本地使用 `SQLite` 运行无错误。
