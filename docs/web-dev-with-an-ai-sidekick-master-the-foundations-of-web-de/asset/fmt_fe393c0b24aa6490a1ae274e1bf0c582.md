## SVG fundamentals for drawing shapes

SVG is an HTML-friendly drawing format. You can use it in five common ways:

* **Inline SVG**: Write the SVG markup directly in your HTML. This lets CSS and JavaScript reach the SVG elements directly, which is useful for interactivity and theming:

```
<svg width="120" height="120" viewBox="0 0 100 100">
  <circle cx="50" cy="50" r="40"></circle>
</svg>
```

* **External SVG**: Link to an external file like `logo.svg`:

```
<a href="logo.svg">Go to SVG file</a>
```

* **Image element**: No CSS or JavaScript interaction with SVG internals. Simplest and safest for static graphics:

```
<img src="logo.svg" alt="Simple teal square logo" 
     width="120" height="120">
```

* **Object element**: SVG is interactive but lives in its own document context:

```
<object data="logo.svg" type="image/svg+xml" 
        width="120" height="120">
  Your browser does not support SVG.
</object>
```

* **CSS background**: Purely decorative with no interaction or accessibility:

```
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <title>CSS Background SVG</title>
  <style>
    .box {
      width: 120px;
      height: 120px;
      background-image: url("logo.svg");
      background-size: cover;
      background-repeat: no-repeat;
      border: 1px solid #ccc;
    }
  </style>
</head>
<body>
<h1>CSS Background SVG Example</h1>
<div class="box"></div>
</body>
</html>
```

In this chapter, we will start with inline SVG because it gives you the clearest view of how the SVG building blocks work.

The `<svg>` element is a container with its own coordinate system.

What you’re seeing here is a rectangle (`<rect>`) drawn into a 300 by 120 *canvas*, as shown in *Figure 4.1*. The rectangle starts at (10, 10) and is 280 pixels wide and 100 pixels tall. SVG coordinates start at the top-left corner, with x increasing to the right and y increasing downwards, which will feel familiar if you’ve done any layout work in CSS.

In SVG, later elements are drawn on top of earlier ones. Add a couple more shapes to understand layering, as shown in *Figure 4.1* and shown highlighted in the following code:

```
<svg width="300" height="120" 
     xmlns="http://www.w3.org/2000/svg">
  <!-- Background rectangle -->
  <rect x="10" y="10" width="280" height="100" fill="#f2f2f2" />
  <!-- Circle on top of the background -->
  <circle cx="90" cy="60" r="35" fill="cornflowerblue" />
  <!-- A line drawn on top of both -->
  <line x1="100" y1="45" x2="280" y2="95" 
        stroke="black" stroke-width="4" />
</svg>
```

A few key concepts you used:

1. The `<svg>` element defines the drawing area.
   * `width` and `height` set the size on the page.
   * `xmlns="http://www.w3.org/2000/svg"` is an XML namespace that tells the browser *this is SVG markup*.
   
   In a standalone `.svg` file, this attribute is required. However, when SVG is written inline inside an HTML5 document (with `<!DOCTYPE html>`), the `xmlns` attribute is optional because the HTML5 parser handles namespaces automatically. You’ll often see it omitted in real-world inline SVG.

2. Shapes are elements.
   * `<rect>` draws rectangles.
   * `<circle>` draws circles.
   * `<line>` draws straight lines.

3. Positioning uses simple coordinates from the top-left corner (0, 0).
