## SELECT: the shape of a query

Every read query starts with `SELECT`. A `SELECT` statement answers four basic questions:

* What columns do I want? You can list the column names that you want, or use `*` to mean all of them.
* Where does the data come from? You must specify which table(s) you want to query.
* Which rows should be included? You can optionally filter which rows should be included using a `WHERE` clause.
* How should the results be ordered or grouped? You can optionally sort the results using an `ORDER BY` clause.

A minimal query looks like this:

```sql
SELECT name, release_year
FROM titles;
```

The preceding code asks the database to return two columns from every row in the `titles` table. The database does not guarantee the order of rows unless you explicitly ask for one.

**Good practice**: Start each SQL keyword on a new line to make the query easier to scan and understand.

## Filtering rows with WHERE

Most queries care about only some rows. The `WHERE` clause filters the result set, as shown in the following code:

```sql
SELECT name, release_year
FROM titles
WHERE kind = 'film';
```

This returns only films, excluding TV series. The database evaluates the condition for every row and keeps only those that match.

You can combine conditions using `AND` and `OR`, as shown in the following code:

```sql
SELECT name, release_year
FROM titles
WHERE kind = 'film'
  AND release_year >= 2000;
```

This reads naturally: films released from 2000 onwards.

## Sorting results with ORDER BY

If you care about order, you must say so explicitly, as shown in the following code:

```sql
SELECT name, release_year
FROM titles
ORDER BY release_year;
```

By default, ordering is ascending. You can reverse it, as shown in the following code:

```sql
SELECT name, release_year
FROM titles
ORDER BY release_year DESC;
```

You can also sort by multiple columns, as shown in the following code:

```sql
SELECT name, kind, release_year
FROM titles
ORDER BY kind, release_year DESC;
```

This groups films and series together and sorts each group by year.

## Limiting the number of rows in the results

When exploring data, it is often useful to limit how many rows you see, as shown in the following code:

```sql
SELECT name, release_year
FROM titles
ORDER BY release_year DESC
LIMIT 3;
```

This returns only the three most recent titles. This is especially useful with large tables.

**Good practice**: If a query uses `LIMIT` and the result matters, it should almost always have an `ORDER BY` because without `ORDER BY`, `LIMIT` does not mean “the first N rows” in any meaningful sense. `LIMIT 3` does not mean *the first three titles you inserted* or *the oldest* or *the newest*. It means *any three rows*.

## Selecting calculated values

SQL can return expressions, not just stored columns, as shown in the following code:

```sql
SELECT name,
       release_year,
       release_year + 10 AS ten_year_anniversary
FROM titles;
```

This does not modify the data. It simply shapes the output. Calculated columns are part of the result set, not the table.
