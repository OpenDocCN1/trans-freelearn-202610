
# Virtual Environments

The basic rule is simple:

* One project equals one virtual environment
* Each environment has its own dependencies
* Projects do not interfere with each other

Python includes built-in support for virtual environments through the `venv` module, so no extra tools are required.

## Creating a Virtual Environment

Creating a virtual environment is usually done from the command line, inside your project folder, as shown in the following command:

```
python -m venv .venv
```

This creates a folder called `.venv` containing a copy of the Python interpreter and supporting files. The name `.venv` is a convention. The leading dot makes the folder less visually noisy, and many tools recognize it automatically.

**Good Practice**: The dot prefix for the folder name is a convention. You can name the folder anything. Using `venv` is the older and still very common convention. Many tutorials and official examples use `venv`, so it aligns well with most learning materials. The downside is that the folder appears alongside your source code in alphabetical order, which some people find visually noisy, especially in larger projects.

Using `.venv` follows the Unix convention that directories starting with a dot are hidden by default on macOS and Linux. This keeps the project root visually cleaner and reinforces the idea that the virtual environment is an implementation detail rather than application code. Tools such as VS Code, Poetry, and some Python linters and formatters explicitly look for `.venv` and will auto-detect it without extra configuration. The trade-off is that hidden directories can be confusing for beginners. For professional projects, especially those using Python tooling and aiming for a tidy project root, `.venv` is increasingly popular.

Once created, the environment must be activated. Activating an environment is different depending on your OS:

* On Windows, enter the following command:
```
.venv\Scripts\activate
```

* On macOS and Linux, enter the following command:
```
source .venv/bin/activate
```

After activation, the terminal prompt usually changes to show the environment name. This is your visual cue that the environment is active. From this point on, running `python` or `pip` refers to the virtual environment, not the system-wide Python.

When you install packages inside an active environment, they are isolated to that project:

```
pip install requests
```

Another project, with a different environment, will not see that package unless it installs it explicitly.

## VS Code and Virtual Environments

VS Code integrates well with virtual environments. When a `.venv` folder exists, the Python extension will usually detect it and offer to use it automatically. You can also select it manually using the Python interpreter selector in the bottom-right corner of the editor. Once selected, running Python files from VS Code uses the virtual environment interpreter behind the scenes.

At this stage, you do not need to know the advanced features. What matters is understanding why virtual environments exist and recognizing them when you see them.

You will often encounter files like `requirements.txt` or commands like:

```
pip install -r requirements.txt
```

These are simply ways to describe and reproduce the packages installed in a virtual environment. They make it possible for someone else, or a deployment system, to recreate the same setup reliably.

**Good Practice**: Do not install project dependencies into your system Python once you start using virtual environments regularly. Mixing approaches leads to confusion very quickly.

In short, virtual environments allow many projects to coexist on the same machine without conflict. You do not need to use them for every tiny experiment, but for anything that matters or lasts longer than a single session, they are the correct default. Understanding this now will save you hours of frustration later.

# File Input and Output

So far, most of your Python programs have lived entirely in memory. When the program ends, all its data disappears. File input and output, usually shortened to file I/O, is how programs read data from disk and write data back so it can be reused later.

At the most basic level, working with files involves three steps:

1. Open a file.
2. Read from it or write to it.
3. Close it.

Python hides much of this ceremony for you, but the underlying model is still the same.

## Writing Text to a File

The simplest way to write text to a file is to open it in *write* mode. If the file does not exist, Python creates it. If it does exist, Python overwrites it.

For example, to open or create a new file named `example.txt`, and write a short message to it, as shown in the following code:

```
with open("example.txt", "w", encoding="utf-8") as file:
    file.write("Hello, file")
```

Note the following about the preceding code:

* The `with` statement is important. It ensures the file is properly closed even if something goes wrong. You should treat `with` as the default way to work with files. The `with` statement isn't only for files, it's used for database connections, network requests, and any context manager, which is any object that can set up and tear down resources automatically.
* The `"w"` mode means write. There are other modes, but these are the most common:
  * `"w"` write, replacing the file
  * `"a"` append, adding to the end of the file
  * `"r"` read, which is the default

If you want to add content instead of replacing it, use append mode, as shown in the following code:

```
with open("example.txt", "a", encoding="utf-8") as file:
    file.write("\nAnother line")
```

## Reading Text from a File

Reading works the same way, but with the *read* mode, as shown in the following code:

```
with open("example.txt", "r", encoding="utf-8") as file:
    contents = file.read()
print(contents)
```

This reads the entire file into a single string. For small files like configuration files, logs, or simple data files, this is perfectly reasonable.

You can also read line by line, which is useful for larger files, as shown in the following code:

```
with open("example.txt", "r", encoding="utf-8") as file:
    for line in file:
        print(line.strip())
```

Each line includes a trailing newline character, which is why `strip()` is often used.

## Files Are Just Big Strings

One important idea to internalize is that text files are just strings on disk. When you read a file, you get a string. When you write to a file, you are writing a string. Everything you learned in the strings section applies directly here.

That is why formats like CSV, JSON, and even HTML are approachable in Python. They are text first, structure second.

* JSON arrays map to Python lists
