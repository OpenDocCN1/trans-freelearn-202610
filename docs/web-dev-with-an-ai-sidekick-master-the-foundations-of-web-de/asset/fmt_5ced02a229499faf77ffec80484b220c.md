
* Prefer CSS over inline attributes for `fill` and `stroke`. It keeps SVG maintainable.
* Use `currentColor` for icons whenever possible. It’s the cleanest integration with the rest of the page. When you change the color of other elements on the page, especially text, then your icons will adopt that color too.
* Learn `stroke-dasharray` and `stroke-dashoffset`. They let you create animations that look far more complex than they are.

You don’t need to memorize all of this. Know what exists and then look it up when needed. Or ask your AI to do what you already know is possible. Once paths make sense, the rest of SVG becomes less mysterious.

Producing the markup is rarely the main difficulty. The harder job is deciding what the graphic should communicate, how it should scale, and how it fits with the rest of the page.

# SVG as a reusable design system

Up to now, every SVG you’ve written has been fairly literal: shapes appear once, styles are applied directly, and the drawing is mostly static. `<defs>` lets SVG work more like a small library of reusable parts. It lets you define things once and reuse them many times.

`<defs>` itself does not render anything. It’s a container for *definitions*: shapes, gradients, patterns, filters, and symbols that can be referenced elsewhere.

## Defining and reusing shapes with `<defs>` and `<use>`

The simplest use of `<defs>` is to define a shape once and reuse it multiple times with `<use>`, as shown in the following code and *Figure 4.10*:

```xml
<svg viewBox="0 0 300 120" width="300" 
     xmlns="http://www.w3.org/2000/svg">
  <defs>
    <path
      id="star"
      d="
        M 50 0
        L 61 35
        L 98 35
        L 68 57
        L 79 91
        L 50 70
        L 21 91
        L 32 57
        L 2 35
        L 39 35
        Z
      "
    />
  </defs>
  <use href="#star" x="20" y="15" fill="#f4c430" />
  <use href="#star" x="120" y="15" fill="#ff8c00" />
  <use href="#star" x="220" y="15" fill="#e63946" />
</svg>
```

![](Images/B34553_04_10.png)

*Figure 4.10: Three differently colored stars that reuse the same shape*

In the preceding example:

* The `star` path is defined once inside `<defs>`.
* Each `<use>` creates a copy of that path.
* You can position (x, y), fill, scale, rotate, and style each instance independently.

This is useful for icons, repeated UI elements, charts, and decorative motifs.

**Warning!** Modern SVG uses `href`, not `xlink:href`. You’ll still see older examples online and SVG files exported from design tools using `xlink`, but you shouldn’t copy those anymore. It works but is deprecated in SVG 2.

## Gradients: paint that isn’t flat

Gradients are defined in `<defs>` and referenced using `url(#id)` as a `fill` or `stroke`.

Here’s an example of a linear gradient filling a rectangle, as shown in *Figure 4.11*:

```xml
<svg viewBox="0 0 300 120" width="300" 
     xmlns="http://www.w3.org/2000/svg">
  <defs>
    <linearGradient id="sunset" x1="0%" y1="0%" x2="100%" y2="0%">
      <stop offset="0%" stop-color="#ff6a00" />
      <stop offset="50%" stop-color="#ffb703" />
      <stop offset="100%" stop-color="#ffd166" />
    </linearGradient>
  </defs>
  <rect x="20" y="20" width="260" height="80" fill="url(#sunset)" />
</svg>
```

![](Images/B34553_04_11.png)

*Figure 4.11: A linear gradient filling a rectangle*

Key concepts in the preceding code:

* A gradient is a named paint.
* `stop` elements define color transitions.
* Gradients can be reused across multiple shapes.

Here’s an example of a radial gradient:

```xml
<defs>
  <radialGradient id="spotlight" cx="50%" cy="50%" r="50%">
    <stop offset="0%" stop-color="white" />
    <stop offset="100%" stop-color="#90dbf4" />
  </radialGradient>
</defs>
<circle cx="150" cy="60" r="45" fill="url(#spotlight)" />
```

Radial gradients are good for highlights, bubbles, and soft UI accents.

## Patterns: repeating designs as paint

Patterns let you fill shapes with repeating graphics instead of colors or gradients. SVG patterns are often cleaner than trying to fake the same effect with background images or repeated CSS rules.

```xml
<svg viewBox="0 0 300 120" width="300" 
     xmlns="http://www.w3.org/2000/svg">
  <defs>
    <pattern id="diagonal-stripes" width="10" height="10"
      patternUnits="userSpaceOnUse"
      patternTransform="rotate(45)"
    >
      <rect width="10" height="10" fill="#f1faee" />
      <line x1="0" y1="0" x2="0" y2="10" 
            stroke="#457b9d" stroke-width="4" />
    </pattern>
  </defs>
  <rect x="20" y="20" width="260" height="80" 
        fill="url(#diagonal-stripes)" />
</svg>
```

Note the following about the preceding code:

* A pattern defines a tile.
* SVG repeats that tile automatically.
* Patterns can contain any SVG content: shapes, paths, even text.

Patterns are excellent for charts, backgrounds, accessibility-friendly fills, and subtle UI textures.

## Combining `<use>` with gradients and patterns

Once everything is defined in `<defs>`, you can reuse them with short references:

```xml
<use href="#star" x="40" y="20" fill="url(#sunset)" />
<use href="#star" x="140" y="20" fill="url(#diagonal-stripes)" />
```

Change a gradient, pattern, or base shape once, and every reference updates with it.

Here’s what to remember:

* `<defs>` is your library of definitions.
* IDs are used for naming and referencing.
* `<use>` is instantiation for a shape.
* `url(#id)` is referencing for paint.

That may sound grand, but it’s genuinely how SVG is built in real projects.

## Reusable icons with `<symbol>`

When building reusable SVG graphics such as icons, `<symbol>` is often a better choice than using `<defs>` with individual shapes.

A `<symbol>` element defines a reusable graphic, similar to `<defs>`, but with one important difference: it can have its own `viewBox`. This means the symbol behaves like a self-contained SVG.

For example:

```xml
<svg style="display: none;">
  <symbol id="icon-star" viewBox="0 0 24 24">
    <path d="M12 2l3 7h7l-5.5 4.5L18 21l-6-4-6 4 1.5-7.5L2 9h7z"/>
  </symbol>
</svg>
```

You can then reuse it anywhere using `<use>`:

```xml
<svg width="24" height="24">
  <use href="#icon-star"></use>
</svg>
```

Why `<symbol>` is useful:

* It allows each icon to define its own coordinate system using `viewBox`
* It keeps icons consistent and scalable
* It avoids repeating SVG markup across your page

Many icon systems use `<symbol>` together with `<use>` so the same icon markup does not have to be repeated. Think of `<defs>` as a storage container, and `<symbol>` as a reusable component with its own layout rules.

# Making SVG accessible

SVG is part of the DOM, which means it participates in accessibility in ways that plain images do not. That’s a good thing, but it also means you need to be deliberate. An SVG without accessible text is effectively invisible to screen reader users, while a poorly labeled SVG can be noisy and confusing.

The goal is simple: if the SVG conveys meaning, provide a clear text alternative. If it is purely decorative, hide it from assistive technologies.
