## Example 1: Selecting Elements and Changing Text

### What This Example Teaches

* DOM selection with `querySelector`
* Writing UI with `textContent`
* Responding to button clicks

### Code: `example1.js`

Add the following code to a file named `example1.js`, which is referenced by the `<script>` element at the bottom of the web page:

```javascript
const statusText = document.querySelector("#statusText");
const btnSetStatus = document.querySelector("#btnSetStatus");
const btnClearStatus = document.querySelector("#btnClearStatus");
btnSetStatus.addEventListener("click", () => {
  const now = new Date();
  statusText.textContent = `Status: Updated at ${now.toLocaleTimeString("en-GB")}`;
});
btnClearStatus.addEventListener("click", () => {
  statusText.textContent = "Status: Waiting…";
});
```

### Good Practice

Use `textContent` (not `innerHTML`) to set text in the DOM. `textContent` treats everything as plain text, which is safe. `innerHTML` interprets strings as HTML so if that string comes from user input, an attacker could inject malicious code. Only use `innerHTML` when you fully control the content and understand the risks.

## Handling Missing Values: `null` and `undefined`

As you start working with the DOM, you will occasionally run into situations where a value is missing. JavaScript represents this using two special values: `null` and `undefined`.

They look similar, but they mean slightly different things.

### `null` in the DOM

In the context of the DOM, `null` means nothing was found. `null` is an explicit “no value” result. It is often returned by APIs when something does not exist.

For example:

```javascript
const element = document.querySelector("#doesNotExist");
console.log(element); // null
```

In this case, the browser searched the page for an element with that ID and did not find one, so it returned `null`. If you try to use that result as if it were a real element, your code will fail:

```javascript
element.textContent = "Hello"; // Error
```

Beginners hit this DOM mistake often.

A safe pattern is to check for `null` before using the value:

```javascript
if (element !== null) {
  element.textContent = "Hello";
}
```

Or more concisely:

```javascript
if (element) {
  element.textContent = "Hello";
}
```

### `undefined` in JavaScript

`undefined` means no value has been assigned. So `undefined` means a variable exists, but no value has been assigned to it:

```javascript
let message;
console.log(message); // undefined
```

It can also appear when you access something that does not exist:

```javascript
const user = { name: "Mark" };
console.log(user.age); // undefined
```

Here, the `user` object exists, but the `age` property does not, so JavaScript returns `undefined`.

### Key Differences

The difference is subtle but useful:

* `null` usually comes from APIs or functions to indicate “nothing found.”
* `undefined` usually means “this value was never set” or “does not exist.”

In everyday code, you often treat them the same way: as signals that something is missing.

### Good Practice When Working with the DOM

When you select elements from the page:

* Assume `querySelector` might return `null`
* Check before using the result if there is any doubt

For example:

```javascript
const btn = document.querySelector("#myButton");
if (!btn) {
  console.warn("Button not found");
} else {
  btn.addEventListener("click", () => {
    console.log("Clicked");
  });
}
```

This kind of defensive check becomes more important as your pages grow and your JavaScript interacts with more dynamic content.

When something mysteriously breaks in JavaScript, it is often because a value was `null` or `undefined` and your code tried to use it anyway. Once you recognize those two values, these bugs become much easier to spot and fix.

With `null` and `undefined` covered, the next examples can focus on changing the page safely.
