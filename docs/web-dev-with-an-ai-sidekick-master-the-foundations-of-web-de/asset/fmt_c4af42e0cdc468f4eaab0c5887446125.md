
## Navigation commands

Let’s start by focusing on just `pwd`, `ls`, and `cd` first. The rest will make more sense once navigation feels natural.

### pwd – print working directory

`pwd` tells you where you are in the file system. This matters because most commands operate relative to the current directory:

```
pwd
```

Typical output would be something like:

```
/Users/mark/projects/my-site
```

Whenever a command fails with *file not found*, `pwd` is often the first thing to check. Many problems turn out to be caused by running a command in the wrong directory.

### ls – list directory contents

`ls` shows you what files and folders exist in the current directory. Common options include `-l` for a detailed listing and `-a` to show hidden files:

```
ls -la
```

### cd – change directory

`cd` changes your current working directory. For example, to move into a folder called `src`:

```
cd src
```

To go up one level, use:

```
cd ..
```

To return to your home directory:

```
cd ~
```

Getting comfortable with `cd` is essential, because almost everything else depends on being in the right place.

## Creating things

Now let’s see two commands to make a directory or a file.

### mkdir – make directory

`mkdir` creates a new directory:

```
mkdir scripts
```

You can create nested directories in one step using `-p`:

```
mkdir -p app/static/css
```

This is common when setting up project structures.

### touch – create a file

`touch` creates an empty file if it does not already exist:

```
touch app.py
```

If the file already exists, `touch` simply updates its timestamp. Developers often use it to quickly create placeholder files.

## Moving, copying, and deleting

You often need to move, copy, or delete filesystem items.

### cp – copy files and directories

`cp` copies files from one location to another:

```
cp settings.example.json settings.json
```

To copy a directory and its contents, use the `-r` (recursive) option:

```
cp -r templates templates_backup
```

### mv – move or rename files

`mv` moves files or directories. It is also used for renaming:

```
mv old_name.py new_name.py
```

or:

```
mv build/ dist/
```

There is no separate rename command. Renaming is just a move within the same directory.

### rm – remove files and directories

`rm` deletes files:

```
rm debug.log
```

To remove a directory and everything inside it, use `-r`:

```
rm -r temp/
```

This command does not send files to a recycle bin. Once deleted, they are usually gone. This is one of the reasons developers treat `rm -r` with respect.

## Showing text

Lastly, let’s see how to output a file or a string to the console.

### cat – display file contents

`cat` prints the contents of a file to the terminal:

```
cat README.md
```

It is useful for quickly inspecting small text files, configuration files, or logs without opening an editor.

### echo – print text

`echo` outputs text to the terminal:

```
echo "Hello, Bash"
```

It is often used in scripts to show progress messages or to test variables and command output.

These commands form the foundation of almost everything you will do in Bash. Once they feel familiar, reading shell-based instructions becomes much easier, and writing simple scripts starts to feel natural.

## Working with web resources

Now let’s see some network commands.

### curl – transfer data from or to a server

`curl` is used to make HTTP requests from the command line. It is commonly used to download data, test APIs, or interact with web services:

```
curl https://example.com
```

This fetches the content of the URL and prints it to the terminal.

To save the response to a file, use the `-o` option:

```
curl -o index.html https://example.com
```

You can also send data, for example when working with APIs:

```
curl -X POST -d "name=Mark" https://example.com/api
```

Developers often use `curl` to debug APIs, check responses, or automate requests in scripts.

### wget – download files from the web

`wget` is designed for downloading files from the internet. It is especially useful for saving files directly to disk:

```
wget https://example.com/file.zip
```

This downloads the file and saves it with its original name.

To save it with a different name, use `-O`:

```
wget -O archive.zip https://example.com/file.zip
```

Unlike `curl`, `wget` is focused on downloading and can resume interrupted downloads, which is useful for large files.

## Writing a simple script

So far, you have been typing one command at a time into the terminal. A Bash script is simply a way to save a sequence of commands into a file and run them together. This is useful whenever you notice yourself repeating the same steps over and over, or when you want to document a process in a form that the computer can execute.

For example, let’s say you’ve been working with Django and you find yourself repeating the same three commands in order, over and over again:

1. Change to the project directory:

```
cd project
```

2. Activate the virtual environment:

```
source .venv/bin/activate
```

3. Run the web server:

```
python manage.py runserver
```

If you create a script file named `run_dev.sh` that contains these three commands, then three steps become one:

* Run the script:

```
./run_dev.sh
```

A script replaces repeated typing with a single command.

### Script files

A Bash script is just a plain text file. By convention, it usually has a `.sh` extension, although the extension itself is not technically required. Let’s start with a minimal example.

Create a new file called `run_dev.sh`:

```
touch run_dev.sh
```

Open it in VS Code and add the following commands:

```
#!/usr/bin/env bash
echo "Starting development environment..."
python manage.py runserver
```

The first line is called the **shebang**. It tells the operating system which program should be used to run the file. In this case, it says use `Bash`. The `env` form is preferred because it works across different systems where Bash might live in slightly different locations.

The remaining lines are just normal Bash commands, exactly the same as if you had typed them into the terminal by hand.

### Making script file executable

Before you can run the script, you need to make it executable:

```
chmod +x run_dev.sh
```

If you forget this step and try to run the script, you will typically see an error like:

```
$ ./run_dev.sh
bash: ./run_dev.sh: Permission denied
```

This happens because the file exists, but the operating system does not have permission to execute it as a program. Adding the execute permission with `chmod +x` resolves this.

Now you can run it like this:

```
./run_dev.sh
```
