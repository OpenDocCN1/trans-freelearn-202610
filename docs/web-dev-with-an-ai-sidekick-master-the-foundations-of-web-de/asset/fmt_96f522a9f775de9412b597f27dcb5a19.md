
## Python Release Phases

Python releases go through five phases, as described in the following points:

1. **Early development (feature phase)**: Before the first beta, the next full release can accept new features, bug fixes, and security fixes.
2. **Pre-release (beta phase)**: After the first beta, no new features can go in, but feature fixes (including significant changes to new features), bug fixes, and security fixes are accepted for the upcoming feature release.
3. **Stable maintenance (bugfix phase)**: Once a version has been fully released, bug fixes and security fixes are accepted. New binaries are built and released roughly every two months. This phase is also called maintenance mode or stable release.
4. **Security-only support**: After two years (18 months for versions before 3.13), only security fixes are accepted and no more binaries are released. New source-only versions can be released as needed.
5. **End-of-life**: Five years after a release, support ends. The release cycle is frozen; no further changes are allowed.

The descriptions come from the official Python release lifecycle page in the Python Developer Guide at the following link: [`https://devguide.python.org/versions/`](https://devguide.python.org/versions/)

At the time of writing in April 2026, as shown in *Figure 8.1* and explained in the following points:

* Python versions 2.6 to 3.9 have all reached their end-of-life and are therefore not supported
* Python versions 3.10 to 3.12 are all in their security phases meaning that although they are supported, they only get security fixes
* Python versions 3.13 and 3.14 are in their bugfix phase meaning they are actively supported with new binaries that you can download and install every two months

## Trying out the Python interactive shell

As a quick sanity check, let's try out the Python interactive shell.

At a command prompt or terminal, enter the following command:

```
python
```

Or:

```
python3
```

You should see the `>>>` prompt, which means that Python is running and ready. Try performing a simple calculation, as shown in the following command and output:

```
>>> 2+2
4
```

To exit the Python interactive shell, enter the following command:

```
>>> exit()
```

You can also press *Ctrl* + *D* on macOS and Linux, or *Ctrl* + *Z* then *Enter* on Windows.

A working Python installation is the first thing you need. Once Python runs reliably from the command line, the rest of the chapter can focus on learning the language itself, not fighting the environment.

In the rest of this chapter, you will move from understanding what Python is to actually using it. You will start with the basic rules and syntax that define how Python code works, and then you will explore Python's core data structures.

# Syntax and basics

Python's syntax is purposely small. There are fewer rules to memorize than in most languages, but the rules that do exist matter a lot. This section focuses on the core building blocks you will use in almost every Python program: indentation, statements, variables, basic types, expressions, comments, and simple input and output.

## Writing Python code files and running them

Python code is usually written in plain text files with a `.py` extension. Each file is a Python program, also called a script. VS Code is just an editor, but the Python extension connects it to the Python interpreter installed on the system.

Create a `Chapter08` folder, with a subfolder named `python-basics`. Open the `python-basics` folder in VS Code using **File** | **Open Folder**.

Opening a folder, rather than a single file, matters because VS Code uses the folder as the working context for running code and managing settings.

Next, in the `python-basics` folder, create a new file called `hello.py`.

**Good practice**: File names should be lowercase, use underscores instead of spaces, and avoid special characters. This convention is not enforced by Python, but it is widely followed and prevents subtle problems later.

In `hello.py`, write the simplest Python script, as shown in *Figure 8.2* and in the following code:

```
print("Hello, Python")
```

![](Images/B34553_08_02.png)

Figure 8.2: Writing Python code files in VS Code

You can (1) select the Python interpreter version by clicking in the status bar, and (2) run the code file by clicking the **Run Python File** button in the top-right of the code editor, as shown in *Figure 8.2*.

This file is not a project or an application. It is just a simple script. A sequence of instructions that Python will execute from top to bottom.

In VS Code, open the terminal with **Terminal** | **New Terminal**. This terminal opens in the folder you selected earlier. This is important because Python will look for files in the current directory.

In **Terminal**, enter the following command:

```
python hello.py
```

If that does not work, use:

```
python3 hello.py
```

The difference depends on how Python was installed, and both are normal. The result should appear immediately in the terminal, as shown in the following output:

```
Hello, Python
```

![](Images/B34553_08_03.png)

Figure 8.3: Viewing the output of running the Python code file in VS Code Terminal

VS Code did not run Python itself. It asked the operating system to run the Python interpreter, passed it the file name, and displayed the output. Remembering that chain will help later when debugging.

## Running Python files with the UI

When a Python file is open, there is a ▶ button in the top-right corner of the code editor. Clicking it runs the current file using the selected Python interpreter and shows the output in the terminal. This button is doing the same thing as typing the command manually. It is not a different execution mode. If something fails here, it would also fail in the terminal.

In the bottom-right corner of VS Code, the Python version is shown in the status bar. If you click it, you can select which Python interpreter to use when you have multiple versions installed at the same time.

Python does not automatically re-run code when you save. The loop is always:

1. Edit the code file
2. Save the changes to the code file
3. Run the code file again

Modify the program slightly, as shown in the following code:

```
name = input("What is your name? ")
print("Hello,", name)
```

Run it again and show how input flows through the terminal, as shown in *Figure 8.4*:

![](Images/B34553_08_04.png)

Errors are normal and expected. If Python encounters something it cannot understand, it stops and prints a traceback. For now, the most important skill is reading the last line of the error message, which usually explains what went wrong and on which line.

You've now learned the basics of how to write Python code in `.py` files, how to edit those files in VS Code, and then run them using the Python interpreter via the terminal or the **Run Python File** button.
