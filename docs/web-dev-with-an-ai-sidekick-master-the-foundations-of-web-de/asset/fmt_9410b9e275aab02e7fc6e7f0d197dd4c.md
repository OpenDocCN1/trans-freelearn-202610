## Icons are paths

Almost every SVG icon you've ever used is made of paths. When you copy an icon from a design tool or an icon library, you usually get one or more `<path>` elements.

Here's a simple heart icon drawn as a single path, as shown in the following code and *Figure 4.9*:

```svg
<svg viewBox="0 0 120 120" width="160" xmlns="http://www.w3.org/2000/svg">
  <path
    d="
      M 60 100
      C 20 70, 20 30, 50 30
      C 65 30, 60 45, 60 45
      C 60 45, 55 30, 70 30
      C 100 30, 100 70, 60 100
      Z
    "
    fill="#e63946"
  />
</svg>
```

![](Images/B34553_04_09.png)

*Figure 4.9: A heart drawn using a path*

This looks complex, but the key insight is this: you almost never write paths like this by hand.

SVG is a good example of the theme running through this book: the typing is not the hard part. You rarely need to memorize path commands or type long coordinate strings by hand. The useful skill is knowing what the shape represents, how it should scale, how it should respond to CSS or JavaScript, and what you can safely change when the design changes.

Designers draw them in tools like Illustrator, Figma, or Inkscape, and you paste the resulting SVG into your HTML.

AI can also help generate starting points, but developers still need to judge the result and, in many cases, may still work with designers. You can ask your chatbot to create the SVG for you. Your job as a web developer is to understand enough to style, scale, animate, and tweak them safely.

## Styling and animating paths

Paths respond to the same CSS ideas you already know:

```css
.icon path {
  fill: none;
  stroke: #333;
  stroke-width: 4;
}
.icon path:hover {
  stroke: #0077cc;
}
```

You can also do things that feel almost magical, like animating a path so it looks like it's being drawn. This works by animating `stroke-dasharray` and `stroke-dashoffset`, and it's one of SVG's party tricks.

## Converting shapes into path commands

Friendly, readable elements like `<rect>` and `<circle>` are great for learning and for simple graphics. But in real-world SVG, especially icons and illustrations, almost everything ends up as `<path>`.

Why? Because `<path>` can describe any shape, while elements like `<rect>` and `<circle>` are limited. Converting basic shapes into paths helps you see how SVG represents drawings internally.

### Converting a rectangle into a path

Start with a simple rectangle:

```svg
<rect x="20" y="20" width="100" height="60" fill="skyblue" />
```

This draws a rectangle starting at `(20, 20)`.

Now let's convert it into a path step-by-step:

1. Move to the top-left corner
2. Draw lines around the edges
3. Close the shape:

```svg
<path
  d="
    M 20 20
    L 120 20
    L 120 80
    L 20 80
    Z
  "
  fill="skyblue"
/>
```

How those numbers were calculated:

* Top-left: `(20, 20)`
* Top-right: `(20 + 100, 20)` therefore `(120, 20)`
* Bottom-right: `(120, 80)`
* Bottom-left: `(20, 80)`

So a rectangle is four lines plus `Z`.

### Rectangle with rounded corners

A `<rect>` can also have rounded corners using `rx` and `ry`:

```svg
<rect x="20" y="20" width="100" height="60" rx="10" fill="skyblue" />
```

To replicate this with a path, you need curves. Typically, you'd use arc commands (`A`), but here's a simplified version to show the idea:

```svg
<path
  d="
    M 30 20
    L 110 20
    Q 120 20 120 30
    L 120 70
    Q 120 80 110 80
    L 30 80
    Q 20 80 20 70
    L 20 30
    Q 20 20 30 20
    Z
  "
  fill="skyblue"
/>
```

This uses quadratic curves (`Q`) to round the corners. It's more verbose, but much more flexible.

### Converting a circle into a path

Here's a circle:

```svg
<circle cx="80" cy="60" r="40" fill="tomato" />
```

To convert a circle to a path, you use arc commands (`A`):

```svg
<path
  d="
    M 80 60
    m -40 0
    A 40 40 0 1 0 80 100
    A 40 40 0 1 0 80 20
  "
  fill="tomato"
/>
```

Breakdown:

1. `M 80 60` means move to center
2. `m -40 0` means move left to edge of circle
3. The first `A` means draw half the circle
4. The second `A` means complete the circle

This looks complicated, and that's exactly the point: paths can describe almost any shape, but not human-friendly to write from scratch.

### Why convert shapes to paths?

You are not expected to manually convert shapes like this in day-to-day work. But understanding it gives you several practical advantages.

As you saw earlier, icons from design tools are almost always `<path>` elements. Knowing how basic shapes map to paths helps you read and tweak them without guessing.

Paths unlock features that shapes don't support. You can:

* Animate parts of a shape
* Morph one shape into another
* Combine shapes into a single outline
* Apply advanced effects more easily

For example, animating a rectangle border is trivial as a path, but awkward with `<rect>`.

When everything is a path, you can combine shapes into one element, apply a single stroke or animation, and simplify complex SVG structures. That gives the browser fewer elements to track and gives you fewer places to edit later.

Tools like Figma, Illustrator, and Inkscape export everything as paths. If you don't understand paths, you're effectively copy-pasting blind.
