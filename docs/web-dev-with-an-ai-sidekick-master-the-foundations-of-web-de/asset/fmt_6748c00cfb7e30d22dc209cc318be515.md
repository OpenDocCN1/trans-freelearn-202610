
## Understanding Scope

Understanding scope helps you avoid bugs where a variable is unexpectedly missing, overwritten, or shared more widely than you intended.

There are three main kinds of scope in JavaScript that you will encounter in this chapter.

### Global Scope

A variable in **global scope** is accessible from anywhere in your script.

In the examples earlier, variables such as `statusElement` and `messageElement` were declared in one file and then used in another:

```javascript
const statusElement = document.querySelector("#status");
```

Because both the `<script>` elements run on the same page, they share the same global scope. That is why `variables.js` can use variables declared in `code-order.js`.

This is convenient for small examples, but it becomes risky in larger applications because any script can change those values.

### Function Scope

Variables declared inside a function exist only inside that function:

```javascript
function makeGreeting(name) {
  const message = `Hello, ${name}!`;
  return message;
}
```

In the preceding code, `message` only exists inside `makeGreeting`. If you try to use it outside the function, JavaScript will throw an error. This is useful because it keeps temporary values contained and prevents accidental interference with other parts of your code.

### Block Scope

**Block scope** applies to variables declared with `let` and `const` inside curly braces `{}`, such as in `if` statements or loops:

```javascript
if (true) {
  const secret = "hidden value";
  console.log(secret); // Works here
}
console.log(secret); // Error: secret is not defined
```

The `secret` variable only exists inside the `if` block.

This is one of the reasons `let` and `const` are preferred over `var`. The older `var` keyword ignores block boundaries and can lead to confusing bugs.

### Scope and Event Handlers

Event handlers introduce another layer of scope:

```javascript
let counter = 0;
incrementBtn.addEventListener("click", () => {
  counter = counter + 1;
});
```

In the preceding code example:

* `counter` lives in the outer (global) scope
* The `() => {}` arrow function creates its own scope
* The function can still access `counter` because it was defined outside

This behavior is called a **closure**. You do not need to master that term yet, but it explains why event handlers can remember variables defined earlier.

Keep variables in the smallest scope that makes sense:

* Use block scope (`let` or `const`) for temporary values.
* Use function scope to organize logic.
* Use global scope sparingly, especially as your programs grow.

If a variable is accessible everywhere, it can be changed from anywhere. That is where subtle bugs start to appear.

You will soon see that some operations, such as `document.querySelector()`, can return a special value called `null` when nothing is found. Mastering scope helps you understand where values come from, and understanding values like `null` helps you handle cases where something is missing.

## Data Types: Number, String, Boolean, Array, and Object

JavaScript has a handful of core data types you will use all the time:

* **Numbers** are used for counts and calculations.
* **Strings** are used for text and are written inside quotes.
* **Booleans** are either `true` or `false` and are used for decisions.
* **Arrays** are ordered lists of values.
* **Objects** group related values together under named properties.

This section shows common data types and how they behave.

In `index.html`, after the existing `<script>` elements, add a new `<script>` element to reference a new code file named `data-types.js`, as shown in the following code:

```html
<script src="data-types.js"></script>
```

In the same folder as the HTML file, create the code file named `data-types.js`, and enter the following code:

```javascript
statusElement.textContent = "Status: Demonstrating data types.";
const age = 54;                       // number
const firstName = "Mark";             // string
const isMember = true;                // boolean
messageElement.textContent = `Message: ${firstName} is ${age} years old. Member: ${isMember}.`;
console.log(typeof age, age);
console.log(typeof firstName, firstName);
console.log(typeof isMember, isMember);
// Two types you'll use constantly:
const favoriteShows = ["Andor", "Heated Rivalry"]; // array (list)
const user = { name: "Mark", age: 42 }; // object (grouped properties)
console.log("Array example:", favoriteShows);
console.log("Object example:", user);
```

## Functions: Reusable Code, Parameters, Return Values

A **function** is a reusable block of code that performs a specific task. You define a function once, then call it whenever you need it. This keeps your code readable and avoids repetition. Functions make JavaScript reusable.

Functions can accept inputs, called parameters, and they can return results. Even when JavaScript code looks complicated, it is usually just functions calling other functions.

This example will define functions, call them, and then use return values to update the page.

In `index.html`, after the existing `<script>` elements, add a new `<script>` element to reference a new code file named `functions.js`, as shown in the following code:

```html
<script src="functions.js"></script>
```

In the same folder as the HTML file, create the code file named `functions.js`, and enter the following code:

```javascript
statusElement.textContent = "Status: Demonstrating functions.";
function makeGreeting(personName) {
  return `Hello, ${personName}!`;
}
function showMessage(text) {
  messageElement.textContent = `Message: ${text}`;
}
const greeting = makeGreeting("Captain Picard");
console.log("Greeting returned from function:", greeting);
showMessage(greeting);
```

Note the following about the preceding code:

* `makeGreeting()` returns a `string` value.
* `showMessage()` performs an action.

## Hooking Up Event Handlers

`addEventListener()` is a method available on DOM elements. It lets you listen for a specific event and register a function to run when that event happens. You are not running the function now. You are handing it to the browser so it can run it later.

For example:

```javascript
incrementBtn.addEventListener("click", () => {
  counter = counter + 1;
  renderCounter();
});
```

The first argument, `"click"`, is the event type. It tells the browser which kind of event you care about. In this case, it is a mouse or a touch click on the button.
