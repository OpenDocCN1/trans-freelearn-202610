## Initial remote server set up

You are about to enter commands to update OS packages, add yourself as a Linux user, enable the firewall, and so on:

1. Update packages and be patient for a few minutes while this happens:

```
apt update && apt upgrade -y
```

2. Add a user named tallyapp:

```
adduser tallyapp
```

3. Give yourself admin rights:

```
usermod -aG sudo tallyapp
```

4. Switch to your account:

```
su - tallyapp
```

5. Allow SSH through the firewall:

```
sudo ufw allow OpenSSH
```

6. Enable firewall:

```
sudo ufw enable
```

7. Install system dependencies (Python `pip`, virtual environment support, Sqlite, Nginx, and Git):

```
sudo apt install -y python3-pip python3-venv nginx git sqlite3
```

8. Clone your project from its public GitHub repository:

```
git clone https://github.com/yourusername/tallyapp.git
```

Alternatively, you can clone my TallyApp source code repository, found at the following link: [https://github.com/markjprice/tallyapp](https://github.com/markjprice/tallyapp)

9. Change to the app folder:

```
cd tallyapp
```

10. Create a virtual environment:

```
python3 -m venv .venv
```

11. Activate the virtual environment:

```
source .venv/bin/activate
```

12. Install Python dependencies:

```
pip install -r requirements.txt
```

13. Install Gunicorn:

```
pip install gunicorn
```

14. Create a `.env` file:

```
nano .env
```

15. Define some environment variables:

```
DEBUG=False

ALLOWED_HOSTS=your_domain,your_server_ip
```

16. Apply migrations (this will create the SQLite database file `db.sqlite3`) and collect static files:

```
python manage.py createsuperuser
```

17. Test Gunicorn by entering the following at the terminal or command prompt:

```
gunicorn --bind 0.0.0.0:8000 tallyapp.wsgi:application
```

18. Enter the following link at the terminal or command prompt:

```
http://your_server_ip:8000
```

19. Stop Gunicorn by pressing `Ctrl` + `C`.

20. Configure Gunicorn as a service by creating a configuration file:

```
sudo nano /etc/systemd/system/gunicorn.service
```

21. Modify the contents of the `gunicorn.service` file:

```
[Unit]
Description=gunicorn daemon
After=network.target
[Service]
EnvironmentFile=/home/tallyapp/tallyapp/.env
User=tallyapp
Group=www-data
WorkingDirectory=/home/tallyapp/tallyapp
ExecStart=/home/tallyapp/tallyapp/.venv/bin/gunicorn \
    --workers 1 \
    --bind unix:/home/tallyapp/tallyapp/gunicorn.sock \
    tallyapp.wsgi:application
[Install]
WantedBy=multi-user.target
```

22. Start and enable Gunicorn:

```
sudo systemctl start gunicorn
sudo systemctl enable gunicorn
```

23. Configure Nginx:

```
sudo nano /etc/nginx/sites-available/tallyapp
```

24. Modify the file:

```
server {
    listen 80;
    server_name your_domain your_server_ip;
    location /static/ {
        root /home/tallyapp/tallyapp;
    }
    location / {
        include proxy_params;
        proxy_pass http://unix:/home/tallyapp/tallyapp/gunicorn.sock;
    }
}
```

25. Enable Nginx:

```
sudo ln -s /etc/nginx/sites-available/tallyapp /etc/nginx/sites-enabled
sudo nginx -t
sudo systemctl restart nginx
```

26. Configure firewall for web traffic:

```
sudo ufw allow 'Nginx Full'
```

27. Enable HTTPS:

```
sudo apt install certbot python3-certbot-nginx
```

## Backing up your SQLite database

With SQLite, your entire database is a single file at the following location on the host server:

```
/home/tallyapp/tallyapp/db.sqlite3
```

If this file is lost or corrupted, your data is gone, so backups are essential.

You can back up the database file using the following command:

```
sqlite3 db.sqlite3 ".backup 'db-backup.sqlite3'"
```

**Warning!** Do not use a simple copy (`cp`) command. Copying the file may be acceptable only when the app is stopped or quiet. Use SQLite's `.backup` command or Online Backup API for a live database. SQLite documents its Online Backup API for copying a live database at the following link: [https://sqlite.org/backup.html](https://sqlite.org/backup.html)

You could create a `backups` directory:

```
mkdir -p ~/backups
```

Then perform a backup with timestamp:

```
sqlite3 /home/tallyapp/db.sqlite3 \
  ".backup /home/tallyapp/backups/db-$(date +%F-%H-%M).sqlite3"
```

Example output:

```
db-2026-03-24-14-30.sqlite3
```

### Automating backups with cron

So far, you have created backups manually. That is fine for testing, but in a real deployment, you need backups to happen automatically and consistently. This is where `cron` comes in.

`cron` is a built-in Linux scheduler that runs commands at specified times. It is extremely reliable and widely used for routine maintenance tasks like backups, log rotation, and cleanup.

To edit your scheduled tasks, run:

```
crontab -e
```

If this is your first time using it, you may be asked to choose an editor (select `nano` for simplicity). This opens your personal crontab file.

Each line in a crontab file has five time fields followed by the command:

```
* * * * * command
│ │ │ │ │
│ │ │ │ └── Day of week (0–7, where 0 and 7 = Sunday)
│ │ │ └──── Month (1–12)
│ │ └────── Day of month (1–31)
│ └──────── Hour (0–23)
└────────── Minute (0–59)
```

This matters because small mistakes here can mean backups never run or run too often.

To add a job every `6` hours, add the following line:

```
0 */6 * * * sqlite3 /home/tallyapp/db.sqlite3 ".backup /home/tallyapp/backups/db-$(date +\%F-\%H-\%M).sqlite3"
```

The preceding code works as follows:

* `0 */6 * * *`: Runs at minute 0, every 6 hours (midnight, 6am, 12pm, 6pm).
* `sqlite3 /home/tallyapp/db.sqlite3`: Works with your SQLite database file.
* `".backup /home/tallyapp/backups/db-$(date +\%F-\%H-\%M).sqlite3"`: Backs up the database file with a timestamp like: `db-2026-04-02-12-00.sqlite3`. The `%` characters are escaped (`\%`) because `cron` treats `%` specially. Without escaping, the command will break.
