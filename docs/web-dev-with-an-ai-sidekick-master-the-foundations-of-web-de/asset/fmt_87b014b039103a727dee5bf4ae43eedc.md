
However, many interesting directions remain for expanding the application.

The best way to practice spec-driven workflows is to keep adding small, clearly defined features.

Here are several ideas that would make engaging exercises.

## Exercise Ideas

### Interactive Map Location Questions

Instead of selecting a country from a dropdown list, respondents could choose their location on a map.

Imagine a question such as: *Where are you participating from?*

The interface could display a globe or world map where users click their location.

The response would store latitude and longitude coordinates. Survey analytics could then display responses geographically, showing clusters of participation across different regions.

**Prompt**: Design a specification for geographic survey responses using a map interface.

### Drag-and-Drop Ranking Questions

Some surveys ask users to rank items in order of preference.

For example: *Rank these programming languages by how much you enjoy using them.*

A drag-and-drop interface could allow respondents to reorder items visually:

1. Python
2. JavaScript
3. Go
4. Rust

The result would store the ranking order in the database.

This kind of question type introduces interesting data modeling challenges.

**Prompt**: Design a specification for drag-and-drop ranking questions in a survey app and explain the data modeling challenges involved in ranking questions.

### Survey Branching Logic

More advanced surveys show different questions depending on earlier answers.

Example: *Do you own a car?*

- Yes → show questions about driving habits
- No → skip to public transport questions

This feature introduces conditional logic in the survey engine and forces you to think carefully about how questions and responses are structured.

**Prompt**: Design a specification for adding branching logic to a survey system.

### Real-Time Response Dashboards

Survey creators might want to see responses updating live while participants are answering.

This could be implemented using WebSockets, Django Channels, or live updating charts.

Watching responses accumulate in real time makes the application feel much more dynamic.

**Prompt**: Explain how WebSockets could be used to create real-time survey response dashboards.

### Survey Themes and Styling

Another visual improvement would allow survey creators to customize the appearance of their surveys.

Possible features include:

- Color themes
- Custom logos
- Light and dark modes

This would give you a reason to practice CSS custom properties, theme classes, and light/dark styling.

**Prompt**: Please show me how to add theming support to a Django web application.
