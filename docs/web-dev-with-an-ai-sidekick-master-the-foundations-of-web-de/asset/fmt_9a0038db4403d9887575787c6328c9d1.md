
# Optimizing AI Tool Usage

AI tools often impose usage limits, especially on free or lower-tier plans. A few habits reduce wasted prompts and help you avoid running out halfway through a task.

First, be deliberate with your prompts. Instead of sending multiple small, vague requests, combine them into a single, clear and well-structured prompt. This reduces back-and-forth and gets you closer to a useful result in one response. (In a distributed architecture, this principle is known as: *Be chunky, not chatty*.)

Second, iterate efficiently. Rather than restarting from scratch, refine previous prompts or ask the AI to improve its own answer. Building on existing context uses fewer requests and produces better results.

Third, avoid unnecessary experimentation when working on real tasks. It's easy to burn through usage by trying many variations. When you have a clear goal, stay focused and direct.

Finally, switch tools or modes when appropriate. Some platforms offer different models, free tiers, or fallback options. Knowing when to use a lighter model versus a more advanced one can help you stay within limits.

The key idea is to treat AI interactions as a resource. Thoughtful, well-structured prompts not only improve quality but also help you stay productive without running into caps.

## Project Structure Overview

Browse the folder structure and note the following:

* `tallyproject/` is the project that holds global configuration like `settings.py` and `urls.py`
* `surveys/` is an app that contains actual functionality like models, views, and business logic
* `templates/` is for shared layouts and base templates
* `static/` is for CSS, JS, and images used across the site
* `db.sqlite3` is the SQLite database in the project root
* `manage.py` is the main way you interact with the project, for example:

```
python manage.py runserver
python manage.py migrate
```

* `requirements.txt` defines the Python dependencies and allows the project to be recreated with: `pip install -r requirements.txt`
* `package.json`, `playwright.config.js`, and `e2e` are JavaScript-based end-to-end web UI configuration and folders, with `app.spec.js` containing the actual Playwright tests

### Surveys App: URL Configuration

The `surveys` folder is an app feature for managing surveys, where `urls.py` defines all the URL patterns:

```
urlpatterns = [
    path("", HomePageView.as_view(), name="home"),
    path("creator/", SurveyListView.as_view(), name="survey_list"),
    path("creator/surveys/new/", SurveyCreateView.as_view(), name="survey_create"),
    path("creator/surveys/<int:pk>/", SurveyDetailView.as_view(), name="survey_detail"),
    path("creator/surveys/<int:pk>/edit/", SurveyUpdateView.as_view(), name="survey_update"),
    path("creator/surveys/<int:pk>/publish/", SurveyPublishView.as_view(), name="survey_publish"),
    path("creator/surveys/<int:pk>/clone/", SurveyCloneView.as_view(), name="survey_clone"),
    path("creator/surveys/<int:pk>/end/", SurveyEndView.as_view(), name="survey_end"),
    path("creator/surveys/<int:pk>/results/", SurveyResultsView.as_view(), name="survey_results"),
    path("creator/surveys/<int:pk>/responses/", SurveyResponsesView.as_view(), name="survey_responses"),
    path("creator/surveys/<int:survey_pk>/questions/new/", QuestionCreateView.as_view(), name="question_create"),
```
