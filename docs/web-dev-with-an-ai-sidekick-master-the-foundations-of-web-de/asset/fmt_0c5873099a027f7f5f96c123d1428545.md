
# Workshop Challenge

## Page 1: workshop.html

Create a file called `workshop.html` that includes:

*   An ordered list of workshop sessions (at least four items).
*   **What you’ll learn** section: Use an `<h2>` heading. Include an unordered list of skills or topics.
*   **Schedule** table: Use an `<h2>` heading. Include a `<table>` with columns for: Time, Topic, Format (Lecture, Hands-on, Break).
*   Add a link to the signup page: `<a href="signup.html">Sign up for the workshop</a>`.

## Page 2: signup.html (workshop sign up)

Create a file called `signup.html` that includes the document structure:

*   Proper `<head>` and `<body>`
*   A clear page `<title>`

The requirements for the form are:

*   Your page must include a `<form>` element with `method="post"` and a realistic action value (for example `/signup`).
*   Inside the form, include:
    *   Personal details like full name (text input, required) and email address (email input, required).
    *   Experience level as a set of radio buttons: Beginner, Some experience, Advanced. (All radio buttons must share the same `name` to be a group.)
    *   Topics of interest with at least three checkboxes (for example HTML, CSS, Python, JavaScript).
    *   Additional notes as a `<textarea>` for comments or questions.
    *   Submit button.
*   Navigation with a link back to `workshop.html`.

## Rules of the challenge

*   Every input that should be submitted must have a `name`.
*   Every form control must have a `<label>` element.
*   Headings must follow a logical order.
*   Tables are for data only.
*   Do not use `<div>` to replace meaningful elements you’ve already learned.

If you want to push a little further:

*   Add `required` to appropriate inputs.
*   Add a `<select>` dropdown for **How did you hear about this workshop?**
*   Add placeholder text to text inputs.

Try submitting the form in `Live Preview` and observe what happens.

You’ve completed the challenge successfully if:

*   Both pages open correctly in `Live Preview`.
*   The link from `workshop.html` to `signup.html` works.
*   The form enforces required fields.
*   Submitting the form produces a browser response (even if it errors).

# Other markup languages

HTML is the markup language most closely associated with the web, but it belongs to a wider family of languages that use tags to describe content. Understanding this family will help you see that HTML isn’t random or magical. It’s one practical solution that emerged from a longer history.

## What “markup language” means

A **markup language** is a system for adding annotations to text so that a computer can understand what different parts of that text represent. In other words, markup answers questions like:

*   Is this text a heading or a paragraph?
*   Is this a list item or a table cell?
*   Is this content data, structure, or metadata?

Markup languages do not execute logic. They describe structure and meaning. That puts `HTML` in the same conceptual category as languages like `XAML` and `SVG`.

`HTML` is a domain-specific markup language designed for one job: describing documents meant to be viewed in a web browser.

`HTML` is intentionally forgiving. Browsers try very hard to display something sensible even if the markup is imperfect. That design choice is one of the reasons the web spread so quickly.

**XML** (**eXtensible Markup Language**) came later and took a different approach. Where `HTML` is opinionated and forgiving, `XML` is strict about syntax, extensible (you define your own tags), and focused on data, not presentation.

An example of `XML` is shown in the following code:

```
<book>
  <title>Python Programming</title>
  <author>Mark</author>
  <pages>320</pages>
</book>
```

There are some key differences between `XML` and `HTML`:

*   Every tag must be closed either with a closing tag (`<book>...</book>`) or as a self-closing tag (`<br />`) because, unlike `HTML5`, which allows unclosed void elements, `XML` will not allow them.
*   Tags must be properly nested.
*   There is no predefined set of tags.
*   `XML` does not define how things should look.

`XML` is commonly used for configuration files, data interchange, document formats, and APIs (especially historically).

## SVG: markup for graphics

**SVG** (**Scalable Vector Graphics**) is another markup language, but for graphics instead of documents. `SVG` uses tags to describe shapes, paths, text, and transformations, as shown in the following code:

```
<svg width="100" height="100">
  <circle cx="50" cy="50" r="40" />
</svg>
```

There are important things to understand about `SVG`:

*   It is `XML`-based.
*   It describes *what the graphic is*, not how to draw pixels.
*   It scales cleanly at any resolution.

`SVG` can be embedded directly inside `HTML` documents, which is why learning `HTML` structure makes `SVG` easier to understand later. You will learn about `SVG` in [*Chapter 4*](#04.xhtml#_idTextAnchor212), *SVG – Drawing Scalable Graphics*.

## A very short history of markup languages

`HTML` was not the first markup language:

1.  Early document systems based on **Standard Generalized Markup Language** (**SGML**) inspired structured markup long before the web. It is the grandparent of most markup languages, including `HTML`, `XML`, and anything derived from them. `SGML` is a meta-language, not a markup language in the everyday sense. That means `SGML` does not define a fixed set of tags. Instead, it defines rules for creating your own markup languages.
2.  `HTML` was created to describe scientific documents with links. As browsers became more powerful, and became important for commerce and industry, `HTML` grew features. `HTML` is an `SGML` application.
3.  `XML` emerged to provide a strict, general-purpose markup format. `XML` is a simplified descendant of `SGML`.
4.  `SVG` emerged to describe graphics in a resolution-independent way. `SVG` inherits `SGML` ideas via `XML`.
5.  **XAML** (**Extensible Application Markup Language**) is a markup language created by Microsoft for defining user interfaces in desktop and cross-platform applications, rather than web pages. `XAML` is most commonly used with **WPF** (**Windows Presentation Foundation**), `WinUI`, `.NET MAUI`, and `Avalonia`.

They are not competitors. They are variations on the same idea: structured markup with meaning, applied to different domains.

## Why beginners should care

`HTML` is not unique because it uses tags. It’s unique because it uses markup to describe documents meant for the web. Other markup languages exist for other jobs.

`HTML` just happens to be the one that holds the web together.

`SGML` is not something you learn to use. It is something you learn about. It’s the root of the markup family tree. Everything else makes more sense once you know where it came from.
