

## 使用 Deployer 工具部署

Deployer 工具是一个命令行工具，主要用于在 Geronimo 中安装和卸载应用程序。该工具位于 **bin** 目录下，根据操作系统不同为 `deploy.bat` 或 `deploy.sh`。

工具语法为：

```
deploy.[bat|sh] [general options] command [command options]
```

要安装新的 WAR 文件，我们使用 deploy 命令：

```
deploy -user system -password manager deploy d:\temp\HelloWorldServlet.war
```

我们会得到以下关于安装成功的确认屏幕：

![](img/5b721cfaa97eb697efc92e3914f62fca_59_0.png)

请注意，使用命令行工具安装时获得的信息比使用管理控制台安装时更多。我们可以看到模块名称以及从提示中得到的上下文根。模块名称很重要，因为它用于卸载应用程序。卸载命令为：

```
deploy -user system -password manager undeploy sample/HelloWorldServlet/1.0/car
```

另一个重要命令是 `list modules`，它显示当前在应用程序服务器中运行的所有已安装模块。deploy 命令的其他所有命令都可以在 Geronimo 文档中找到。

deployer 工具可能是部署的最有用方式。它允许自动化部署过程，并且我们可以最大限度地减少手动错误。更不用说，让脚本进行部署比手动使用管理控制台安装要快得多、快得多。

## 使用热部署部署

热部署是最简单的安装方法。在这里，我们只需将示例 WAR 文件复制到 Geronimo 的 **deploy** 目录，Geronimo 就会完成其余工作。我们可以使用 deployer 工具的 `list modules` 命令来验证安装。

卸载也很简单。我们从 deploy 目录删除 WAR 文件，Geronimo 就会卸载应用程序。

热部署对于快速且可能不太规范的应用程序安装很有用。在现实生活中，可能最好使用 deployer 命令行工具，因为它具有脚本功能，以及由此产生的部署过程自动化。

#### 配置 Web 应用程序

![](img/5b721cfaa97eb697efc92e3914f62fca_66_0.png)

上下文根值得注意（在上面的屏幕截图中可见）。我们在测试应用程序时需要它。

另一个 XML 文件 web.xml 非常重要，我们都知道。这个 XML 将保存 DWR servlet 定义和其他可能的初始化参数。以下代码显示了我们将使用的 web.xml 文件的完整内容：

```xml
<?xml version="1.0" encoding="UTF-8"?>
<web-app xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
    xmlns="http://java.sun.com/xml/ns/javaee"
    xmlns:web="http://java.sun.com/xml/ns/javaee/web-app_2_5.xsd"
    xsi:schemaLocation="http://java.sun.com/xml/ns/javaee http://java.sun.com/xml/ns/javaee/web-app_2_5.xsd"
    id="WebApp_ID" version="2.5">
    <display-name>DWREasyAjax</display-name>
    <servlet>
        <display-name>DWR Servlet</display-name>
        <servlet-name>dwr-invoker</servlet-name>
        <servlet-class>
            org.directwebremoting.servlet.DwrServlet
        </servlet-class>
        <init-param>
            <param-name>debug</param-name>
            <param-value>true</param-value>
        </init-param>
    </servlet>
    <servlet-mapping>
        <servlet-name>dwr-invoker</servlet-name>
        <url-pattern>/dwr/*</url-pattern>
    </servlet-mapping>
    <welcome-file-list>
        <welcome-file>index.html</welcome-file>
        <welcome-file>index.htm</welcome-file>
        <welcome-file>index.jsp</welcome-file>
        <welcome-file>default.html</welcome-file>
        <welcome-file>default.htm</welcome-file>
        <welcome-file>default.jsp</welcome-file>
    </welcome-file-list>
</web-app>
```

我们已经在第 3 章的配置部分看到了 servlet 定义。我们在这里使用相同的 `debug` 参数。Servlet 映射是常用的 `/dwr/*`。

我们记得 DWR 不能在没有 `dwr.xml` 配置文件的情况下运行。因此我们需要创建配置文件。我们使用 Eclipse 在 **WEB-INF** 目录中创建一个新的 XML 文件。以下内容是用户界面骨架所需的。它已经包含了我们基于 DWR 的菜单的 `allow` 元素。

```xml
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE dwr PUBLIC
    "-//GetAhead Limited//DTD Direct Web Remoting 2.0//EN"
    "http://getahead.org/dwr/dwr20.dtd">
<dwr>
    <allow>
        <create creator="new" javascript="HorizontalMenu">
            <param name="class" value="samples.HorizontalMenu" />
        </create>
    </allow>
</dwr>
```

在 `allow` 元素中，有一个用于我们在这里要实现的水平菜单 Java 类的 creator。我们在这里使用的 creator 是 new creator，这意味着 DWR 将使用空构造函数为客户端创建 Java 对象。名为 `class` 的参数保存完全限定的类名。
