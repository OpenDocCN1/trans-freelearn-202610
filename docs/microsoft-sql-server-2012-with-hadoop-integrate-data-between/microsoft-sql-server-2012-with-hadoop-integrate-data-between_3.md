# 1. 大数据和 Hadoop 简介

突然之间，大数据成为了热门话题。从大型企业级到小型初创公司，每家公司都为大�据提供了资金。过去几年中，存储和硬件成本大幅降低，使企业能够存储和分析数据，而之前这些数据由于存储和处理挑战而被丢弃。就数据世界而言，从未有像现在这样令人兴奋的时代。我们看到显著趋势的融合正在从根本上改变行业，并在社交、移动、高级分析和机器学习等领域开启了技术创新的新纪元。我们正在目睹数据爆炸，其中我们试图从中获取洞察的数据种类具有全新的规模和范围。在本章中，我们将深入了解什么是大数据，以及在实施大数据解决方案时 Apache Hadoop 框架如何在其中发挥作用。阅读完本章后，你将能够理解：

- 什么是大数据，为什么是现在

### 大数据 – 有什么大不了的？

关于大数据有很多讨论——估计世界上数字信息的总量每五年增长十倍，其中 85% 的数据来自新的数据类型，例如传感器、RFID、Web 日志等。这为那些利用这些新数据来识别新机遇和创新领域的企业提供了巨大的机会。





然而，仅拥有一个支持数据趋势的平台只是当今挑战的一部分；你还需要使其更容易被人们访问，以便他们能够获得洞察并做出更好的决策。如果我们思考用户体验，凭借我们在网络上所能做的一切，通过社交媒体网站的体验，我们以新的方式发现、分享和协作，用户对他们的业务和生产力应用的期望也在发生变化。

我们首先要回答的第一个问题是一个简单的定义性问题：大数据与传统的庞大数据仓库有何不同？国际数据公司（International Data Corporation）提出了最广泛接受的大数据分类理论，即三个 V：

- **Volume**：数据量正在爆炸式增长。在过去几十年中，计算和存储容量呈指数级增长，推动硬件和存储成本降至接近零并使其成为商品。当前的数据处理需求正在演变，要求在数分钟甚至数秒内使用行业标准硬件分析 PB 级和 ZB 级的数据。
- **Variety**：数据的种类正在增加。所有数据都在被存储，并且近 85% 的新数据是非结构化数据。数据可以是推文的形式，也可以是具有可变属性和元素的 JSON，用户可能只想处理其中的部分内容。
- **Velocity**：数据的速度正在加快业务节奏。得益于新的客户交互点和技术，数据捕获已变得几乎即时。实时分析比以往任何时候都更重要。数据传输速率与数据消费速率的比例持续远高于后者；应对数据的速度仍然是一个挑战。想想一款软件，它能让你以思维的速度发送消息或打字。

如今，每个组织都很难在其内部管理和跟踪正确的数据集，当他们需要查找系统外部的数据时，挑战就更大了。典型的分析师花费太多时间从成千上万个来源中搜索正确的数据，这会严重影响生产力。我们将从搜索的世界转向发现的世界，在那里信息会根据你是谁以及你在做什么工作而带给用户。今天从未有过如此丰富且有用的外部可用信息。挑战在于你如何发现可用的内容以及如何连接到它？

要回答当今这类问题，你需要新的方式来发现和探索数据。我们的意思是，数据可能存在于多个不同的领域，例如：

- **Personal data:** 这是我创建的，或由我的同行创建的，但与当前任务相关的数据。
- **Organizational data:** 这是在整个组织中维护和管理的数据。
- **Community data:** 这是外部数据，例如整理好的第三方数据集，已共享到公共领域。示例包括 Data.gov、Twitter、Facebook 等。
- **World data:** 这是全球舞台上可用的所有其他数据，例如来自传感器或日志文件的数据，正是为此出现了 Hadoop 等大数据技术。

通过结合个人、企业、社区和世界数据所需的数据，你可以获得更深入的业务洞察和趋势。你可以连接并组合来自数百个可信数据提供商的数据——数据包括人口统计数据、环境数据、财务数据、零售和体育数据、社交数据如 Twitter 和 Facebook，以及数据清洗服务。你可以通过自助工具，例如 PowerPivot，将此数据与你的个人数据结合使用，你可以使用参考数据通过 SQL Server 2012 清洗你的企业数据，或在你的自定义应用程序中使用它。

现有的 RDBMS 解决方案如 SQL Server 在管理具有挑战性的数据量方面表现良好，但在数据是非结构化或半结构化且具有可变属性时，如前所述，它们就力不从心了。当前世界似乎几乎痴迷于社交媒体情绪、推文、设备等等；如果没有合适的工具，你的公司就会在数据的海洋中迷失。你需要能够释放大数据带来的新价值浪潮的能力。所有和每一位数据，无论类型或结构如何，你都应该能够轻松监控和管理。这就是为什么组织倾向于构建一个几乎涵盖所有数据的端到端数据平台以及易于使用的分析工具。无论数据类型、位置（本地或云端）或大小如何，你都拥有熟悉的工具与高性能技术的结合，从数据存储、处理一直到可视化来满足你的业务需求。大数据的益处不仅限于 **Business Intelligence (BI)** 专家或数据科学家。只要有合适的工具，你组织中的几乎每个人都可以进行分析和做出更明智的决策。

## Introduction to Big Data and Hadoop

在传统的业务环境中，用于驱动你的报告机制的数据通常来自数据库中的表。然而，越来越有必要用来自组织外部的数据来补充这些数据。这可能是商业上可用的数据集，例如可在 Windows Data Market 及其他地方获得的数据集，也可能是来自不太结构化来源的数据，例如馈送、电子邮件、日志文件等。在大多数情况下，你需要在将其加载到现有数据库之前清洗、验证和转换这些数据。**Extract, Transform, and Load (ETL)** 操作可以使用大数据解决方案对非结构化或半结构化数据执行模式匹配、数据分类、去重和汇总操作，以生成熟悉的行列格式的数据，可导入到数据库表中。以下图示将为你提供大数据的概念视图：

大数据需要一定程度的机器学习或复杂统计处理来产生洞察。如果你必须使用非标准技术来处理和托管它，那它很可能就是大数据。

大数据实现中的数据存储通常被称为 NoSQL 存储，尽管这在技术上并不准确，因为某些实现确实支持类似 SQL 的查询语言。NoSQL 存储通常比关系存储便宜得多，并且通常支持一次写入功能，只允许追加数据。要在这些存储中更新数据，你必须删除并重新创建相关文件。这种限制最大化了性能；大数据存储实现通常以吞吐量而非容量来衡量，因为这通常是存储和查询效率最显著的因素。这种方法还提供了更好的性能并保留了数据更改的历史记录。

> 然而，极其重要的是要指出，除了支持所有类型的数据之外，将数据在非关系存储（如 Hadoop）和关系数据仓库（如 SQL Server）之间移动，是大数据客户使用模式的关键之一。在整本书中，我们将探讨如何集成 Hadoop 和 SQL Server，并使用 SQL Server BI 套件对任何数据进行强大的可视化。

### The Apache Hadoop framework

Hadoop 是一个开源软件框架，支持数据密集型分布式应用程序，可通过 Apache 开源社区获得。它由分布式文件系统 HDFS（Hadoop 分布式文件系统）和一种称为 MapReduce 的分布式分析处理方法组成。它用 Java 编写，基于 Linux/Unix 平台。

它现在被广泛用于处理数据流，这些数据流的规模甚至超过了最大的企业数据集。无论是传感器、点击流、社交媒体、基于位置的数据还是其他以大量形式生成和收集的数据，Hadoop 通常都会出现以处理和分析它。Hadoop 的真正魔力在于它能够将处理或计算逻辑移动到数据所在的位置，而与传统系统不同，传统系统侧重于扩展的单台服务器，将数据移动到该中央处理单元并在那里处理数据。这种模型在当今行业希望为商业智能挖掘的数据量、速度和种类面前是行不通的。因此，Hadoop 凭借其强大的容错可靠文件系统和高度优化的分布式计算模型，是大数据世界中的领导者之一。

Hadoop 的核心是其存储系统和分布式计算模型：





## HDFS

Hadoop 分布式文件系统是对主机操作系统文件系统的程序级抽象。它负责在集群上存储数据。数据被拆分为块并分布在集群中的多个节点上。

## MapReduce

MapReduce 是一种用于使用计算机集群上的分布式计算处理大型数据集的编程模型。MapReduce 包含两个阶段：将数据划分为大量独立的处理单元（称为 Map），然后将这些独立进程产生的结果合并为统一的结果集（称为 Reduce）。在 Map 和 Reduce 之间，会发生 shuffle 和 sort。Hadoop 集群在系统上成功配置后，具有以下基本组件：

## NameNode

这也称为集群的 Head Node/主节点。主要来说，它在处理分布在各节点上的数据期间保存 HDFS 的元数据；它跟踪节点中每个 HDFS 数据块。

> NameNode 是 Hadoop 集群中的单点故障。

## Secondary NameNode

这是一个可选的节点，你可以在集群中拥有它以在 NameNode 宕机时备份 NameNode。如果配置了 Secondary NameNode，它会定期保存 NameNode 配置的快照，以便在需要时作为备份使用。然而，切换到 Secondary NameNode 并没有自动方式；如果主 NameNode 宕机，需要人工干预。这本质上意味着如果 NameNode 宕机，你的集群会出现明显的停机时间。

## DataNode

这些是集群中存储实际 HDFS 数据块的系统。数据块在多个节点上进行复制，以提供容错和高可用性解决方案。

## JobTracker

这是在 NameNode 上运行的服务，用于管理 MapReduce 作业并分发各个任务。

## TaskTracker

这是在 DataNodes 上运行的服务，用于实例化并监控提交的各个 Map 和 Reduce 任务。

此外，还有许多 Hadoop 的支持项目，每个项目都有其独特的目的，例如，向 Hadoop 系统提供输入数据、用于在 Hadoop 之上进行即席查询的数据仓库系统等等。以下是一些值得提及的项目：

## Hive

Hive 是主 Apache Hadoop 项目的支持项目，是 MapReduce 之上的抽象，它允许用户在不开发 MapReduce 应用程序的情况下查询数据。它为用户提供了一种类 SQL 的查询语言，称为 Hive 查询语言（HQL），用于从 Hive 存储中获取数据。这使得具有 SQL 技能的人更容易快速适应 Hadoop 环境。

## Pig

Pig 是 MapReduce 的另一种抽象，使用名为 PigLatin 的数据流脚本语言。这受到了已有脚本技能的程序员的青睐。你可以在名为 Grunt 的命令行 Pig shell 中交互式运行 PigLatin 语句。你也可以将一系列 PigLatin 语句组合成脚本，然后作为一个单元执行。这些 PigLatin 语句由 Pig 解释器用于生成 MapReduce 作业，并在 HDFS 数据上执行。

## Flume

Flume 是 Hadoop 之上的另一个开源实现，它为数据在生成时进入 HDFS 提供数据摄取机制。

## Sqoop

Sqoop 提供了将数据导入和导出到关系数据库表（例如 SQL Server）和 HDFS 的方法。

## Oozie

Oozie 允许创建 MapReduce 作业的工作流。这对从事工作流和通信基础解决方案的开发人员来说很熟悉。

## HBase

HBase 是 Hadoop 数据库，一种 NoSQL 数据库。它是 Hadoop 之上的另一种抽象，提供了对 HDFS 数据的近实时查询机制。

## Mahout

Mahout 是一个机器学习库，包含聚类和分类算法。机器学习研究的一个主要重点是自动学习识别复杂模式并基于数据做出智能决策。

## Summary

在本章中，我们了解了什么是大数据以及为什么它是行业迫切需求之一。需要处理的数据多样性已将信息技术推向了以前从未想象过的高度。能够利用大数据解析任何和所有数据的组织将能够更有效地区分并为业务创造新价值，无论是收入增长、成本节约还是创造全新的商业模式。例如，金融公司使用机器学习构建更好的欺诈检测算法，超越涉及费用频率和位置的简单业务规则，还包括个人的定制购买模式，最终带来更好的客户体验。

就大数据实现而言，这些新需求挑战了传统的数据管理技术，并要求采用新方法使组织能够有效地管理、丰富并从任何数据中获得洞察。Apache Hadoop 是大数据行业无可置疑的领导者之一。整个生态系统及其支持项目为用户提供了一个高度可靠、容错的框架，可用于对非结构化和半结构化数据进行大规模并行分布式处理。

在下一章中，你将看到如何使用 Sqoop 连接器将 Hadoop 数据移动到 SQL Server 2012 以及反之。Sqoop 是另一个开源项目，旨在从 Hadoop 到任何关系数据库管理系统进行双向导入/导出数据；我们将看到它作为 Hadoop 与 SQL Server 2012 之间数据集成第一步的使用。
