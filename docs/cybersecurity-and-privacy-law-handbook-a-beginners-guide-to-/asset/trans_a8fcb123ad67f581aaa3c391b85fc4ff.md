
## VA/PT

过去的章节中提到了风险管理以及如何处理漏洞等内容。就公司而言，漏洞问题经常与技术差距有关，其中最相关（因此也不安全）的方面与缺少更新有关。在这种情况下，漏洞管理是你能够做到的唯一事情，以便对公司边界有清晰的了解。

## VA

VA（Vulnerability Assessment 的缩写）是对信息系统安全缺陷的系统性分析。它评估系统对已知漏洞的易受攻击性，对这些漏洞给出严重程度评级，并在必要时提供补救或缓解建议。

VA 可以避免的风险包括以下内容：

- SQL 注入、XSS 注入以及更多代码注入威胁
- 由于身份验证技术存在缺陷而导致权限提升
- 带有不安全设置的软件，例如可猜测的管理员密码

VA 有多种形式。它们包括以下内容：

- Host assessment – 对可能遭受攻击的任务关键型服务器进行评估，如果它们未经过彻底测试或未从经过测试的机器映像创建
- Network and wireless assessment – 对旨在防止未经授权访问私有或公共网络以及网络可访问资源的政策和程序进行评估
- Assessment of databases and large data systems for vulnerabilities and misconfigurations, identification of rogue databases and unsecured development/test environments, and classification of sensitive data throughout an organization's infrastructure
- Application scans — 使用自动化前端扫描或静态或动态源代码分析来识别在线应用程序及其源代码中的安全缺陷

### Vulnerability identification (testing)

漏洞识别（测试）

如果您准备启动您的 VA 机器，就该出发了，即使我强烈建议您寻求帮助（内部或外部）。在外部评估的情况下，您合作的公司必须签署保密协议（NDA），因为他们可以看到不应泄露的安全问题。我还建议您向测试人员提供有关公司基础设施的所有信息：没有人会明确告诉您，但如果他们盲目操作，就有损坏某些设备的风险，而且由于他们不知道自己处理的资产类型，这是您的责任。

本步骤的目的是汇编应用程序漏洞的详尽清单。安全分析师通过使用自动化技术扫描或手动测试和分析来评估应用程序、服务器和其他系统的安全性。此外，分析师使用漏洞数据库、供应商漏洞通知、资产管理系统和威胁情报源来发现安全缺陷。

### Vulnerability analysis

漏洞分析

本阶段的目的是发现第一步中识别出的漏洞的根本原因和来源。

它包括识别每个漏洞负责的系统组件以及漏洞的根本原因。例如，过时的开源库版本可能是漏洞的根本原因。这为修复提供了明确的途径——升级库。

### Risk assessment

风险评估

本阶段的目的是按重要性对漏洞进行排序。它包括安全专家根据以下标准为每个漏洞授予排名或严重程度评分：

- 哪些系统受到影响？
- 哪些数据处于危险之中？
- 哪些组织职能面临风险？
- 攻击或入侵的简易性
- 攻击的严重性
- 漏洞可能造成的危害

### Remediation

补救

本阶段的目的是关闭安全漏洞。通常，安全人员、开发团队和运营团队会合作找到修复或缓解每种风险的最有效方法。

具体的纠正措施可能包括以下内容：

- 引入新的安全方法、技术或流程
- 实施运营或配置变更
- 开发和部署安全缺陷的修复程序

VA 不能是一次性事件。组织必须将此流程操作化并定期重复，才能取得成功。DevSecOps，即促进安全、运营和开发团队之间协作的做法，同样至关重要。

### Vulnerability evaluation instruments

漏洞评估工具

VA 工具的目的是自动检测可能攻击您应用程序的新威胁和当前威胁。工具示例包括以下内容：

- 用于测试和复制已知攻击模式的 Web 应用程序扫描器。
- 用于查找不安全端口、协议和网络服务的协议扫描器。
- 网络扫描器，有助于网络可视化以及检测警告信号，例如 stray IP 地址、伪造的数据包和来自单个 IP 地址的异常数据包产生。
- 作为推荐做法，定期对所有重要 IT 系统进行自动扫描。这些扫描的结果应纳入组织的 VA 持续流程中。

## PT

PT（Penetration Testing 或 Pentesting 的缩写）涉及经批准的模拟攻击，以评估计算机系统的安全性。渗透测试人员使用与攻击者相同的工具、策略和程序来识别并说明系统漏洞的商业影响。通常，PT 会复制可能影响公司的多种攻击。它可以确定系统是否足够 resilient 以承受来自授权和未授权位置以及各种系统角色的攻击。在适当的范围内，PT 可以探测系统的各个方面。

### What advantages does PT offer?

PT 有哪些优势？

理想情况下，软件和系统应以避免严重安全漏洞为目的而创建。PT 提供了这一目标实现程度的洞察。PT 可以帮助公司做到以下几点：

- 定位系统性漏洞
- 评估控制措施的强度
- 支持数据隐私和安全合规性（例如 PCI DSS、HIPAA 或 GDPR）
- 为管理层提供现有安全态势和预算目标的定性和定量证据

### How much access do penetration testers have?

渗透测试人员有多少访问权限？

根据 PT 的目标，测试人员会被授予对目标系统的不同程度的访问或了解。在某些情况下，PT 团队从一开始就采用单一策略。有时，随着对系统的理解在 PT 过程中增长，测试团队会调整其方法。PT 有三个访问级别：

- Opaque box：团队对目标系统的核心架构一无所知。它像黑客一样行事，寻找可从外部利用的漏洞。
- **Semi-opaque box:** 团队熟悉一个或多个凭证集。它还熟悉目标的内部数据结构、代码和算法。渗透测试人员构建测试用例可能基于全面的设计文档，例如目标系统的架构图。
- **Transparent box:** 渗透测试人员可以访问系统和系统制品，例如源代码、二进制文件、容器，有时甚至是系统服务器。这种方法在最短时间内提供了最大程度的确定性。

### What are the steps of PT?

PT 的步骤是什么？

渗透测试人员模仿具有恶意意图的对手的攻击。为此，他们通常实施以下步骤：

- **Reconnaissance:** 从公开和私有来源收集尽可能多的目标信息，以指导攻击方法。互联网搜索、域名注册信息检索、社会工程学、非侵入式网络扫描，甚至垃圾翻找都是来源示例。这些数据有助于渗透测试人员识别目标的攻击面和潜在漏洞。根据 PT 的范围和目标，侦察可能简单到拨打电话以探索系统的功能。
- **Scanning:** 利用专用软件，渗透测试人员调查目标网站或系统是否存在漏洞，例如开放服务、应用程序安全问题和开源漏洞。根据侦察和测试期间的发现，渗透测试人员使用各种工具。
- **Gaining entry:** 攻击者的动机可能包括窃取、修改或销毁数据、转移资金，或仅仅损害公司的声誉。对于每个测试场景，渗透测试人员评估获得系统访问权限的最有效工具和策略，无论是通过 SQL 注入、恶意软件、社会工程学还是其他方法进行的漏洞利用。
- **Preserving access:** 一旦渗透测试人员获得对目标的访问权限，他们的模拟攻击必须保持连接足够长的时间以外泄数据、更改数据或滥用功能。展示可能的影响至关重要。

### What forms of PT exist?

PT 有哪些形式？

为了实现最佳风险管理，需要对 PT 采取全面方法。这需要测试环境的各个方面：

- **Web application testers:** 评估安全保护的有效性并搜索漏洞、攻击模式和其他可能导致 Web 应用程序渗透的潜在安全缺陷。
- **Mobile applications:** 使用自动化和广泛的手动测试，测试人员在移动应用程序二进制文件及其配套的服务器端功能中搜索漏洞。典型的服务器端 Web 服务漏洞与会话管理、加密困难以及身份验证和授权问题等有关。
