# 第 11 章：评估

策略、标准和程序是网络安全计划不可或缺的一部分。这些策略文档用于奠定你打算如何运行网络安全计划的基础。从信息安全到资产管理和软件开发，策略被用来记录你如何为组织运行特定计划。

**策略** 旨在作为高层级文档，用于描述你实施安全控制的意图。这些文档的编写方式应使你能自由分发它们，或将其发布在公共站点上，而无需担心泄露过多信息。其意图是能够在组织与客户或第三方供应商之间无需 NDA 的情况下分发文档。

**标准** 是用于描述意图的 *内容* 的文档。例如，加密标准应包含要使用的适当加密算法和位强度。该文档也旨在阻止使用遗留协议，因为它们可能容易受到某些弱点的攻击而导致攻击。

**程序** 是实施某事的 *方法*。它是一套分步说明，用于如何适当配置特定技术。把这份文档写好很重要，因为你可能有从未配置过硬件或软件的初级分析师，他们需要协助来完成配置。其意图是以这样的方式编写文档，使分析师无需他人太多帮助即可完成配置。

这些文档应拆分为不同的控制族并分离开来，以便你可以自由分发策略，而标准和程序则需要 NDA。审计员还将要求你创建文档，以支持关于 IT 资源配置的声明。这就是为什么为计划的各个方面编写策略文档极其重要的原因。

在最后一章中，我们将讨论对计划执行评估。此评估旨在帮助你了解网络安全计划目前的状况；这称为 **当前状态**。这是计划所提供的一切在某一时间点的快照。然后我们将制定战略路线图或未来状态。这是我们希望将计划带向的方向。在本章中，我们将讨论以下主题：

*   执行评估
*   捕获当前状态
*   创建未来路线图

内容很多，让我们开始吧！

## 执行评估

评估有三种不同的执行方式；它们是第一方、第二方和第三方评估。它们各自的执行方式截然不同，但最终都能达到相同的结果。这些评估旨在发现计划中的缺陷。这些缺陷随后可转化为目标或项目，以改善网络安全态势。

### 第一方评估

**第一方评估** 可以是一种有趣且令人兴奋的方式来了解你的环境。第一方评估由你、你的团队或组织内部的内部审计部门执行。此类评估可以突出你做得正确的许多方面，但也有助于发现计划中的差距。





## 第一方评估

执行第一方评估的一个缺点是，它可能不如第三方评估那样被广泛接受。这是因为第一方评估是由您或您的组织执行的。这往往会导致评分偏高，或安全控制措施被忽视。您也可能因为这是您的项目而给自己打分比别人更优。也很难判断回答问题时是否存在偏见。这就是为什么客户和供应商通常接受第三方评估，而不是第一方评估。

执行第一方评估时，请务必排除偏见。偏见可能会在您对某个特定控制措施给自己和项目打分过高时悄然产生。请务必在回答问题或对特定控制措施自我评分时采取无偏见的方法，因为这可能会提供一种虚假的安全感。

同时也要熟悉您打算用于评估的网络安全框架。这在询问关于框架中使用的控制目标的问题时会有所帮助。您需要以一种让桌面上（会议上）的每个人都能理解的方式提问。这是为了让每个人更容易理解所提问题的目的。

如果您打算使用 NIST CSF 作为评估框架，请熟悉其控制措施及您打算如何使用它们。想出多种询问框架本身问题的方式。请记住，您通常希望提出的问题不一定是开放式的，但也不仅仅是简单的*是*或*否*。

如果您是组织的新成员，我强烈建议您无论如何都要进行一次第一方评估。这是了解您共事的人员，以及了解正在使用的技术栈和安全栈的好方法。如果不这样做，如果您不知道起点在哪里，怎么知道未来状态会是什么样子？

请记住，框架包括技术、物理和管理控制。您需要将每天所做的一切记录下来；这包括策略、标准和程序。在培训新员工和向审计员提供答案时，您将需要这些信息。给自己个方便，不要忽视或轻视这一步。

解决贵部门本地的策略、标准和程序是提高分数的绝佳第一步。从第 2 层级进阶到第 3 层级将要求这些策略文档现在覆盖整个组织。这将需要开发一个计划，以维持继续执行策略所需的成熟度水平。

## 第二方评估

**第二方评估**由您的客户或供应商执行。第二方评估旨在帮助您了解目前与您及您的组织有业务往来的组织的安全状况。他们也有既得利益，确保您的组织正在保护敏感信息。例如，您可能有客户将敏感信息存储在您的组织中，他们希望确保您的网络安全计划尽最大能力保护他们的信息。

为了更好地了解您的网络安全文化，他们通常会发送一份问卷供您填写。这份问卷可能包含涉及数据治理、策略和程序、数据保护以及网络安全最佳实践的多个主题。您可能也会收到基于这些问题的发现，您必须对此作出回应。例如，可能会要求您更改事件响应策略，或在发生影响其信息的事件时包含对客户的通知。

您可能还打算审计您合作的供应商，以确保他们满足所需的 SLA。这些通常包括您是否满足要求，例如可追溯性、正常运行时间或环境有多整洁。如果未满足 SLA，这往往会导致合同纠纷。审查您的合同，以确保您满足他们的要求。

我知道有几家大型组织会派员工飞往现场进行评估。这不仅是为了确保他们写在纸上的内容是正确的，也是为了亲眼看到已实施的控制措施。这要么有助于支持他们的网络安全主张，要么暴露他们的缺陷。

## 第三方评估

**第三方评估**由外部方执行。这通常由审计公司或托管安全服务提供商执行。虽然第三方评估是首选方法，但它也是成本最高的。这通常需要一个由不同专业人员组成的团队聚在一起为您执行评估。

这通常是执行评估的首选方法，因为它完全消除了您在评估完成后评分中的偏见。也正是因为这个原因，它是最广泛被接受的方法。客户和供应商可能因为这种偏见而不接受第一方评估。

第三方评估公司可能有也可能没有合适的员工来根据您给定的框架执行审查。与供应商合作，确定您是否甚至可以根据打算使用的框架执行评估。虽然四大审计公司可能能够根据 NIST CSF 执行评估，但较小的公司可能因缺乏专业知识而无法做到。请确保您与能够按照您的要求执行评估的正确供应商合作。

第三方评估人员通常会提供一份关于框架合规性的报告，或者至少提供一份包含其评分和发现的幻灯片。其他框架（如 ISO 27001）在满足所有要求后，将为您提供认证。这可用于与供应商和客户共享。但是，在向任何人提供此类信息之前，您应该先签署保密协议 (NDA)。

某些法规要求可能会要求您进行第三方评估。这时您需要与合规公司合作，代表您执行评估。例子包括 PCI DSS、FedRAMP、GDPR 和 CMMC 的某些级别。

第三方评估人员会要求提供若干项目，包括策略、标准、程序、架构图和系统配置。审计员可能还想评估您的日志并分析您的防火墙规则，以确保它们符合您的标准。

他们可能想在您的网络中运行扫描；这也将包括您的系统和服务。这些将涉及扫描配置、漏洞，以及基线是否存在任何偏移。这将确保您在整个环境中维护标准化配置。

最后，适当界定评估范围。如果评估范围仅限 IT，请将其控制在 IT 范围内。如果是为了 PCI，请确保其保持在持卡人数据环境内。还要确保范围环境与网络其余部分之间有防火墙。这将帮助您保持在范围内，并降低成本，因为他们不评估整个环境。

现在，如果您决定自己执行评估，有几件事您必须考虑。这些包括以下内容：

*   委托函
*   项目启动
*   执行评估
*   执行差距分析
*   收尾

## 执行自我评估




# 自我评估指南

在执行自我评估（或第一方评估）时，必须准备好以下几项内容。这些不仅是为了让他人知晓你正在进行评估，更能起到“免责保护”的作用。下面我们来看看第一方评估包含哪些内容。

## 约定函

你需要获得 CEO 或授权人员的批准，才能开展评估。**约定函**旨在授权你按自己的判断执行评估。你可能需要对 IT 系统和服务执行特定类型的安全检查或扫描，这可能会导致系统宕机。所有这些都必须在约定函中明确说明。

**约定函**应具体陈述你的评估意图和预期产出。如果你计划使用基于技术的扫描器来确定系统和服务的配置，通过问答会话进行评估，且需要**主题专家**（`SMEs`）参与，则所有这些都必须在函件中详述。

约定函还应包含进度安排。该安排旨在指导你打算做什么以及何时做。例如，你可能打算在周初访谈所有 `SMEs`，而在周末执行扫描。或者，你可能想回顾之前的评估结果，并查看架构图、当前批准的策略和程序。所有这些都应在约定函中列出。

## 项目启动

**项目启动**是评估过程的开始。此时你开始通过询问 `SMEs` 他们如何根据框架执行工作职能来启动问卷。你需要将他们的回答记录在文档中以供后续审查。

同样，`SMEs` 对框架的熟悉程度不如你，因此要确保以受众能理解的方式提问。这可能意味着你需要扩展问题，包含示例或场景以帮助 `SME` 充分回答。但不要引导 `SME` 按特定方式回答，否则会导致答案偏颇。

## 执行评估

此阶段是实际执行评估的过程。你向 `SMEs` 提问并对 IT 资源执行扫描。请继续将约定函作为流程的指南或大纲。该文档详细记录了你与高管领导团队达成的共识。

避免单一回答型问题，例如“`Are backups performed?`”。虽然这可能是问题的核心，但不允许 `SME` 扩展回答。应提出更多开放式问题，例如“`How are backups performed?`”。这不仅允许不止是是/否的回答，还能让 `SME` 讨论备份流程的方法论。

倾听现场人员和 `SME` 的发言，因为他们可能提供额外信息；同时密切关注非语言线索。这有助于回答问题或澄清特定流程，也能凸显某功能需要额外支持才能正常运行的地方。

这也是运行扫描的时机。扫描旨在提供 IT 资源配置情况的信息。你可以使用漏洞扫描器等工具，或使用互联网安全中心 `CIS-CAT` 扫描服务。还有其他免费扫描器可用，如 `DISA STIGs`。这些工具旨在检查系统或服务的配置，并提供对威胁形势的洞察。

你还可以执行其他类型的扫描，如**开源情报**（`OSINT`），或检查 DNS 配置。这两类扫描都能提供组织使用服务类型的宝贵信息，还能凸显不应被互联网访问的敏感文件或信息。发现此类信息有助于定位数据泄露或服务器配置错误。

如果尚未进行，此时还应审查漏洞扫描报告、渗透测试结果、架构图，以及策略、标准和程序。此类评估不仅关注系统配置或备份执行情况，旨在审查评估范围内环境的所有文档。

## 执行差距分析

评估结束时，你应已获得所有问题的答案并审查完所有文档。现在收尾评估并执行**差距分析**。**差距分析**用于确定环境现状及需改进之处。

这是流程中的关键步骤，因为它会凸显你的不足，以便你制定项目计划解决未完成事项。这也被视为你的当前状态（稍后详述）。你需要按严重程度对发现结果进行排序，并开始制定解决这些发现的行动计划。

## 收尾

**收尾**或退出面谈是向高管领导团队讨论发现并汇报的环节。退出面谈用于强调组织的成就和做得正确的地方，以及讨论后续步骤。

你也可以将发现分为多个类别。例如，若计划基于 `NIST CSF` 进行评估，可按功能或类别细分评分。此评分有助于识别需协助的特定领域。评分示例如下：

| `DE.CM-01` | 25 |
| `DE.CM-02` | 75 |
| `DE.CM-03` | 50 |
| `DE.CM-06` | 50 |
| `DE.CM-09` | 25 |

披露结果时，务必按重要性排序。制定项目计划，说明如何通过启动各类项目来缩补差距、缓解发现。同时询问业务方最重视什么。可能存在先解决特定发现的业务理由。

对所有类别执行此操作并生成评分。这将提供框架的总体评级。该评分将在我们捕获当前状态并着眼制定战略时变得重要。

# 捕获当前状态



现在我们已经完成了评估，是时候确定我们的当前状态了。您的当前状态是评估生成的总体得分以及在审查任何文档时发现的任何缺陷的综合结果。

如*表 11.1*所示，我们应该拥有我们评估所依据的所有类别和子类别的得分。这些得分不仅包括技术控制，还包括管理控制。技术控制是我们想到控制时最可能想到的东西。这些是防火墙、路由器、服务器以及我们能想到的任何其他物理设备。

管理控制是我们往往不会想到的。这些是需要编写的策略，用以支持我们为技术控制所做的工作。除了我们试图实施的 IT 资源或流程的其他文档外，我们还需要包含架构图。

所有这些信息都可以在电子表格或数据库中进行跟踪。这是为了确保您适当地跟踪信息。此外，请确保您的跟踪机制也包含您的未来状态。

务必在制定当前状态时与您的高管领导团队合作。利用这段时间更好地了解他们从评估中获得的目标和目的是什么。这将因多种原因派上用场，但主要是为了让您在评估调查结果的结果时知道优先处理什么。

根据贵组织愿意承担的风险等级对结果进行排序。您可能会显示在检测功能上排名很好，但在响应和恢复方面似乎严重不足。如果您的组织需要将精力重新集中在事件响应上，现在就是改变方向的时候。这些是您需要与高层领导进行的对话。

# 创建您的未来路线图

现在我们已经完成了当前状态的分析，并根据*表 11.2*中找到的评分模型给自己打分，我们现在应该开始确定我们的未来状态。未来状态是我们计划在未来三到五年内达到的状态。我们不仅需要采用基于风险的方法来制定策略，还需要确保我们提出的目标是可实现的。

首先，您需要考虑如何以最少的精力减少最大量的风险。这不是因为您懒惰；而是因为您试图以最少的资源减少尽可能多的风险。这可能包括引入新的密码标准、编写新策略或开发架构图。

长期项目，例如引入`multifactor authentication (MFA)`、将所有应用程序与`single sign-on (SSO)`集成或引入新的日志记录标准，仍然可以规划，但它们需要时间来实施。与您的各个团队合作，确保为这些项目分配资源。这些项目也将有助于降低贵公司的组织风险量。

我们还需要再次考虑与高管领导团队和董事会的对话。这些群体中的每一个都将为您需要实现的目标和截止时间定下基调。如果您的任务是完善事件响应和检测流程，那么在与框架的响应和恢复功能对齐时，这将成为您未来战略的一部分。

## SMART 目标

为战术和战略项目制定目标。这将有助于为计划分配资源和截止日期。有几种不同的方法可以做到这一点。**SMART 目标**通常用于此目的：

*   **具体**：这是您试图实现的确切目标。无论是实施新的防火墙规则，还是安装 Linux Web 服务器，这就是您正在为之努力的事情。
*   **可衡量**：您如何确定项目的成功或失败？这涉及建立指标或数字，以更好地了解您实现目标的进度。
*   **可达成**：您的目标能实现吗？您能在规定的时间内实现您的具体目标吗？
*   **相关性**：目标是否与您的业务目标一致？这需要高管领导团队的意见。没有他们的支持，您的项目或计划可能无法推进。
*   **时限性**：目标或目的需要有截止日期。没有这个，当您没有截止日期要满足时，很难衡量进度。

SMART 目标可以如下所示：

*   **具体**：制定实施事件响应计划的方法
*   **可衡量**：在评分模型中获得至少 3.0 分
*   **可达成**：每六个月设定接触点以重新评估我们的分数以确定进度
*   **相关性**：高管领导团队对勒索软件事件的发生表示了更大的关注
*   **时限性**：在未来 18 个月内使恢复和响应功能获得 3.0 分

## 未来状态评分模型

就像我们在*表 11.1*中给自己打分一样，我们现在应该拥有其余类别的得分。这构成了我们的当前状态。我们现在需要评估我们自己和我们的资源，并将我们的目标与我们创建的 SMART 目标对齐。这将使我们能够制定未来状态得分。这个未来状态就是我们的战略路线图将包含的内容。

如果您刚开始，可能没有基础，需要从头建立。在这样做时，重要的是要记住，您不仅需要引入新的技术控制，还需要完善管理控制。这将包含大量新技术和文档。

对框架中找到的其余功能执行此操作，以提供您旨在达到的分数。同样，在创建未来状态得分时，也要与您的高管团队合作。他们可能希望您更多地与他们的业务目标和高管团队想要采取的方向保持一致。

关注最新趋势，并了解威胁和风险。过去几年来，人们越来越关注供应链风险管理和社会工程学。虽然您可能想专注于从检测和响应中获得的网络安全的激动人心的方面，但您可能想专注于身份管理。

如果您尚未这样做，有几个项目应该启动。这包括创建企业风险管理仪表板。您可以拆分出本地风险管理仪表板，这可能是特定于项目的。当您开始识别与环境相关的风险时，请跟踪这些风险并制定`Plan of Action and Milestones (POA&M)`以补救缺陷。

随着您继续构建那些本地化风险仪表板，将较高或有风险的项目上浮到企业仪表板。该仪表板将监督应每月审查的风险。当您关闭这些风险时，将它们标记为已关闭；切勿删除它们。



这将使您能够提供用于关闭已识别风险的流程和项目的历史视图。您需要保留此信息以备审计之需。拥有良好的风险识别流程也将有助于提高透明度。请记住，您无法实现零风险——这是不可能的。但是，您必须处理那些对保护您的组织有意义的风险。

另一个值得推行的好策略是**身份和访问管理**（**IAM**）。推广单点登录的使用，并在所有地方强制实施 MFA。您需要制定良好的政策和程序，让所有人在安全方面达成共识。一旦发现某人的账户被盗用，请立即采取行动。

同时，以扎实的密码管理理解作为 IAM 策略的后盾。与 IAM 应用程序的供应商合作，强制实施以下措施：

*   减少或消除常用密码的数量
*   不允许在密码中使用用户名
*   教育用户了解使用宠物或孩子名字作为密码的危险

推广使用通行密钥来向 IT 资源进行身份验证。通行密钥是向给定 IT 资源进行身份验证的新方式。通行密钥的开发旨在通过 `FIDO2` 协议提供一种更安全的系统访问方式。它本质上创建了一个用于身份验证的公钥/私钥对。

使用通行密钥代替密码的最大优势在于，每个通行密钥对于特定资源都是唯一的。这防止了跨多个账户重复使用密码。它还能防止账户被接管，因为同样，通行密钥的公钥必须向身份验证服务注册。如果您被骗进入一个仿冒的钓鱼页面并被要求输入凭据，您无法提供，因为您注册的是通行密钥而非密码。

# 总结

在本最后一章中，我们讨论了如何进行评估，以及制定当前和未来状态的路线图。这些路线图用于了解您的当前环境，并制定未来三到五年安全计划发展的战略规划。

关于如何进行评估，各有利弊。如果您决定自行进行评估，这称为第一方评估。这是了解您环境的成本最低（尽管有趣）的方法。

请注意首先需要创建的文档。您需要有一份委托函，声明您被允许执行评估。这应详细说明您进行评估的意图以及您打算如何开展。如果您决定执行配置扫描，请确保这一点也在函件中说明。

评估完成后，根据本书前面讨论的分级风险模型为自己评分。这将让您了解当前的安全状况。您应收集评估中出现的所有缺陷，因为我们将把它们转化为未来的项目。

这些项目将构成您的未来状态，即您想要达到的目标。在计算当前状态时，也要计算未来状态的评分。这将显示您的目标所在。同时制定 `SMART` 目标，以确保您保持在正轨上且目标切实可行。

可能有些项目不需要过多资源，却能大幅降低组织面临的风险。与您的高管团队和董事会合作，就他们认为应纳入整改清单的项目提供指导。确保您的战略未来目标与业务目标保持一致。
