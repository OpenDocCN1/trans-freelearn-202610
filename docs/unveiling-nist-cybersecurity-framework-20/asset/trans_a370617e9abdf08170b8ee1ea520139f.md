
# 保护技术 (PR.PS)

还有一些功能用于限制软件在机器上能做什么和不能做什么。当您只希望特定应用程序在系统上运行时，就会出现这种情况，这通常被称为应用程序的 `allow-listing`（允许列表）。实现这一点的最佳方法是降低用户的权限，并仅安装用户执行工作所需的必要应用程序。

## PR.PS-03

*硬件的维护、更换和移除应与风险相称。*

硬件与软件一样，都有使用寿命，通常为 3–5 年。更换周期的长短可能因制造商而异；但请注意，硬件不会永远耐用，即使我们希望它能。硬件组件会损坏，系统可能会显得变慢，或者您可能无法再升级设备上的固件。

当硬件最终达到其使用寿命终点时，您必须安全地处置它。这并不意味着将其扔进垃圾桶并购买新设备；它必须得到妥善处置。许多硬件制造商都制定了关于如何安全处置设备的指南。相关文档介绍了如何从系统中移除硬盘并将其擦除，以便无法再从中检索任何信息。

最好的方法是与专门从事硬件处置或回收的第三方供应商合作。这些企业将接收您的旧设备并妥善处置，同时安全地清除硬盘上的任何信息。通常，该企业会提供一份证书，证明所有设备均已处置且硬盘上不再残留信息。这很重要，因为它为最后持有设备的人员及执行的操作创建了书面记录或保管链。

同样，请确保您已建立扫描机制以监控环境中的系统。这可以通过 `Simple Network Management Protocol` (`SNMP`) 或其他类型的监控协议来监控。您的 `CMDB` 还应包含设备是什么、采购日期、到期日期以及最新安装的固件版本等记录。这将帮助您制定采购新设备的继任计划，或将工作负载迁移到云 `SP`。

## PR.PS-04

*生成日志记录并使其可用于持续监控。*

一般来说，如果设备连接到您的网络，它就应该记录日志。许多系统默认记录日志，例如操作系统，而其他系统则需要您激活日志记录功能。

您必须制定计划，确定如何记录日志以及日志应存储在何处。通常，系统上线时没有关于日志发送去向的计划。这可能意味着某些系统在本地记录日志，而其他系统将日志发送到 `SIEM` 系统。您还可能遇到不同系统具有不同日志保留期限的情况。有些可能保留一个月，有些更长，有些可能完全停止了日志记录。您需要进行评估以确定当前的日志记录状态。

您还需要确定要保留日志多长时间。多项法规要求规定，在将日志卸载到异地存储设施之前，必须保留一定的时间。一个通用的经验法则是：磁盘上至少保留 90 天的日志，热存储（可随时检索）中保留 180 天的日志，异地保留长达一年的日志。

这也应在您的保留策略中注明。如果确定需要日志来确定事件的结果，而组织没有日志，就会陷入麻烦。如果您在没有策略的情况下删除日志，可能会被视为篡改证据。

在日志解决方案中，还有其他一些要求您需要关注。例如，用户应被要求登录系统才能查看日志。除此之外，您还应要求 `MFA`。管理员不应有权从系统中删除日志；只有日志系统本身应具备根据既定策略删除日志的能力。用于存储日志的存储介质必须加密。最后，必须有完整性检查，以确保存储的日志条目未被篡改。这通常通过创建事件的哈希值来执行。

日志本身有多种不同的格式；但是，您应关注某些特征。日志应包含事件发生的时间戳。每条日志都应有序列号，以便您追踪事件。这也是为了确保日志文件本身没有丢失条目。如果是基于网络的设备，它应同时包含源 IP 和目标 IP，以及可能的端口号。用户账户也应伴随事件，以便追溯到特定用户。

## PR.PS-05

*防止未经授权的软件安装和执行。*

我们之前提到过这一点；然而，在用户在设备上的权限方面，我们必须采取最小权限方法。在许多情况下，以本地管理员身份登录是不必要的，并可能导致系统不稳定。软件应经过数字签名和验证，以确保所安装应用程序的真实性。

还有其他方法可以保护软件安装。可以设置 `Mobile device management` (`MDM`)（移动设备管理）来提供公司或企业应用商店，仅允许从中安装获批的应用程序。`MDM` 软件还允许您控制软件版本。例如，当您拥有仅能在特定版本的 `Java` 上运行的应用程序时，这会有所帮助。

## PR.PS-06

*安全软件开发实践被集成，且其性能在整个软件开发生命周期中受到监控。*

如果您的组织为内部资源或外部客户开发软件，它应该有一个相关的生命周期。在开发过程中有许多方法可以保护您的代码，并管理代码在不再使用时如何处置。让我们来看看。

您应该在整个生命周期中对代码进行数字签名，以防止对手篡改。许多基于 `SaaS` 的 `Git` 提供商允许您使用 `GNU Privacy Guard` (`GPG`) 对提交和标签进行数字签名。这对于进一步确定是谁向存储库提交了代码非常重要。当您对提交进行签名时，您还将收到一个 `Verified` 标签，进一步表明该提交是由经过验证的人员提交的。

在向代码存储库进行身份验证时，您应该使用 `Secure Shell` (`SSH`) 密钥以及 `MFA`。这两种身份验证方法也将有助于确定对存储库进行身份验证的用户。然后，您可以使用 `SSH` 密钥在本地计算机和存储库之间传输代码。

一旦不再需要代码，就应将其丢弃。您可能需要在丢弃前保留代码数年。这将要求您将其存储在异地的加密卷中以妥善保管。您还需要确保代码不再对开发人员可用。这将有助于确保代码一旦退役，就无法再被使用。

# 技术基础设施韧性 (PR.IP)

我们将探讨对网络进行分段以促进资源更好隔离的方法，同时确定确保高可用性的方法。这将包括物理组件，如电源和环境温度。
