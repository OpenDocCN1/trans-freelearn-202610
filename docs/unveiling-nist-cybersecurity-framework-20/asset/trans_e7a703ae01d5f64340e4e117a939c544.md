

# 风险管理概述

NIST 接着将正向风险描述为**实现、分享、强化和接受**，而负向风险应对则包括**缓解、接受、规避和转移**。正向风险是指在环境中执行风险降低的优势或机会。正向风险连同负向风险，也应录入**风险登记册**以便跟踪。

定期重新评估你的**网络风险态势**非常重要。这样做是为了确保你走在正确的轨道上。这应包括你如何评估**风险容忍度**，以及谁负责接受风险。

接下来，我们将了解 `C-SCRM`。这很重要，原因你将在下一节看到。

# `C-SCRM` (GV.SC)

如果你关注网络安全新闻，就会注意到供应链管理中存在大量网络风险。第三方软件和服务是组织的易攻击目标，因为深入调查供应商网络风险的做法仍不普遍。然而，`SolarWinds` 开发的软件，以及许多开源工具（如 `PyTorch`）都容易受到此类攻击，我们应持续关注此项工作。

作为网络安全专业人员，你有责任确保你无法控制或不控制的 IT 资源至少经过**审查**。此审查过程将凸显供应商的网络安全态势及 `BCP`/`DR 策略`，并帮助你更好地了解你所使用的软件是如何开发的。

## GV.SC-01

> *`C-SCRM` 计划及其战略、目标、政策和流程已建立，并获组织相关方认同。*

如果计划已存在，现在是评估你如何评估第三方供应商的时候了。此评估将揭示计划的现状，以及如何为未来与这些第三方及其他意向合作伙伴的合作对其进行调整。

该战略应包含你如何审查第三方，以确保其满足或超越你的网络安全态势期望。如果你决定与供应商签订合同，应制定计划以了解其网络安全态势。无论你是想采用 `SIG Lite` 或 `COBIT` 等问卷，还是采用与你的网络安全框架紧密对齐的问卷（如 `NIST CSF` 或 `ISO 27001`），你都需要为审查过程选择一种。

许多组织会前往供应商托管软件的设施实地考察，以便更好地了解其态势。这是最好但也最昂贵的途径，因为这可能意味着派遣一名或多名员工前往供应商现场进行评估。

制定政策和标准可确保组织中的其他人在了解网络安全态势方面跟随你的步伐。你最不希望看到的情况是 IT 部门正在执行审查流程，而财务部门却在未询问安全态势的情况下直接接受了供应商的条款和条件。

许多云服务供应商（如 Microsoft 和 Amazon）会在其网站上发布其网络安全认证证书（如 `ISO 27001`）。这是为了让有意与供应商签约的一方能更好地了解其态势。这可以减轻评估的需求，因为文档已可供审阅。大型云服务供应商不像小型供应商那样会填写问卷，也永远不会填写，所以在选择合作对象时要慎重。

还应成立第三方风险管理委员会。该委员会的职责是审查供应商带来的企业风险。组建委员会时，应包含全组织各部门人员，而不仅限于 IT 部门。该委员会将审查所有新加入组织的供应商，以及当前正在合作的供应商。

## GV.SC-02

> *供应商、客户和合作伙伴的网络安全角色和职责已确立、沟通，并在内部和外部进行协调。*

角色和职责详细规定了在特定计划中谁负责什么。在此例中，我们应与所有参与 `C-SCRM` 计划的人员共同创建一份 `RACI` 图表。

在 `GV.SC-01` 中，我们简要提到了创建负责第三方风险管理的风险管理委员会。该委员会应设主席或负责管理计划的人员，以及负责计划所有其他方面的人员。该委员会还应有来自 `ELT` 的发起人，以确保委员会获得有效履职所需的支持和监督。

此 `RACI` 图表可规定主席对风险管理计划的所有方面负最终责任，而其他部门可能负责审查直接与其相关的问卷。每个部门应负责审查问卷并接受咨询，以确保问题的答案在风险阈值之内，而委员会外的人员在审查过程完成后只需被告知即可。

此外，确保这些流程有文档记录，以便其他人在引入新供应商时知道该做什么。如前所述，如果某部门自行引入新供应商却不询问其如何保护你的组织免遭信息盗窃或丢失，这对任何人都没有好处。

最后，应建立一套机制，允许其他部门选择组织已审查过的可合作的第三方。无论这汇总到企业风险仪表盘中，还是形成一份简单的可选供应商清单，组织内部人员都应有途径选择供应商，并有标准说明为何可选择该供应商。

例如，你可能已审查一家金融公司并与其合作。选择这家金融公司是为了向其提供全体员工用于退休目的的敏感银行信息。然而，该金融公司现请求在你的网络中放置一台服务器用于批量文件传输。虽然你可能仅针对传输敏感数据审查了这家金融公司，但允许他们在你的网络中放置文件服务器并由其管理，这构成了一项新风险。

这将需要另一条工作流，因为你现在有了一个可远程管理你环境中系统的供应商。其他供应商亦然——如果你或另一部门决定采购不同的产品和服务，这将需要对他们的安全态势进行又一次评估。

## GV.SC-03

> *`C-SCRM` 融入网络安全和企业风险管理、风险评估及改进流程中。*

正如我们之前创建企业风险管理计划和风险登记册时所做的那样，我们必须对供应商做同样的事。在审查过程中，必然会有未按我们期望回答的问题，或我们担心控制措施缺失的情况。如果你决定仍要与该供应商开展业务交易，相关网络风险应录入风险登记册。

一旦识别出这些风险，应着手处理，以便由你的组织和供应商共同完成整改。这是双方公司的**共同责任**，因为双方都有共同利益，确保交付的产品和服务尽可能安全。
