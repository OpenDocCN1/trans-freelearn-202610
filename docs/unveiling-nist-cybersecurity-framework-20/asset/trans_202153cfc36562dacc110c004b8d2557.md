## 摘要

`Govern`（治理）功能包含大量内容。首先，我们了解到必须确保我们的网络安全项目向 `ELT` 传达正确的信息，并将我们的项目与这些举措保持一致。我们必须确保审查公司的使命和愿景声明，以及其业务目标，以便了解这些目标是什么。一旦理解了这些，我们就可以将我们的项目与这些目标对齐。

我们还了解到，我们需要围绕项目的运行情况建立 `KPI` 或指标。这将突出显示哪些方面行之有效，哪些领域需要改进。将这些与 `ELT` 或委员会的执行发起人分享，以便他们了解项目运行得如何。

创建带有关联 `RACI` 图表的章程很重要，这样人们才能了解对他们的期望。这些章程随后被用来指导需要开发的各种项目，以支持您的整体网络安全项目。网络安全只是组织变革的催化剂。这种变革将带来更多需要开发的项目，以维持整体网络安全项目。

策略和风险管理是为维持组织内网络安全而将创建的众多项目中的两个。这种变革将影响公司内的多个部门。从 `HR` 到财务，您将需要与这些部门及其他许多部门密切合作，以确保项目顺利高效地运行。

这些变化还将影响您与第三方供应商的合作方式。项目需要确保采购的产品和服务在其既定的 `SLA` 范围内按预期运行。在评估供应商的安全状况时，需要进行额外的审查。向这些供应商发送问卷，并要求他们提供证据，证明他们遵循了既定的指南。当他们未达到您的期望时，让他们承担责任。

最后，更新与第三方供应商的合同条款，让他们知道对他们的期望。这些条款将确保如果他们确实不再遵守您的政策和标准，您有权选择与供应商合作使其恢复合规，或者完全终止合同。请记住，发生事件时，报纸上出现的不会是他们的名字；您公司的名字也会在其中。

在下一章中，我们将讨论 `Identify`（识别）功能，以及在您的环境中记录所有内容的必要性。这包括记录已知和未知设备，并将它们放入配置管理数据库中。

# 4. Identify（识别）

在上一章中，我们了解了 `Govern`（治理）功能及其在整个组织中评估和沟通风险的重要性。我们还强调了拥有企业风险登记册、网络安全供应链风险管理和监督的重要性。收集网络安全项目周围的指标不仅能突出您需要资源的地方，还能宣传那些积极的风险。

从环境中识别和移除风险对项目的成功至关重要。一旦识别出风险，您就需要一个地方来跟踪它。风险登记册可用于跟踪组织中的网络风险。我建议为每个范围界定的环境设置一个风险登记册。这使得登记册易于管理，同时能快速找到风险。一旦您开发了单独的风险登记册，生成一个企业风险登记册或风险管理仪表板。该仪表板将提供一种方式来突出显示环境中发现的关键风险，并允许您和您的团队有效地修复这些风险。

在本章中，我们将讨论 `Identify`（识别）功能。`Identify` 功能之所以独特，是因为它要求您跟踪组织中的所有软硬件资产。除了识别资产外，您还必须准确记录环境中的所有内容，执行风险评估，并改进这些流程。您无法保护您看不见的东西。如果您不保持对已知和未知设备的准确统计，您如何知道环境中有什么和没有什么？

在本章中，我们将涵盖以下内容：

## 资产管理 (ID.AM)

重申我之前提到的，您无法保护您看不见的东西。为了有效保护您的组织，您必须掌握环境中的内容。这要求您了解连接到网络的各种硬件和软件类型，以及更重要的是，您如何保护这些资产。

其中一些也将为后续章节的成功奠定基础。当我们开始奠定资产管理的基础时，我们也将对这些资产进行分类和优先级排序。这将有助于事件响应或灾难恢复场景，因为您将知道什么对组织最重要。

### ID.AM-01

> “*组织维护其管理的硬件清单。*”

这有时说起来容易做起来难。我们必须全面审视环境，了解什么连接到了它。我们通常只考虑硬件或软件，但编程硬件的固件呢？这也应该被纳入清单，以确保它也像环境的其他部分一样得到更新。我们还需要清点网络中未知的设备。例如，网络安全专业人员对插入网络的非法接入点大惊小怪，这是有充分理由的。我们不希望不安全的接入点被插入网络，允许任何拥有 Wi-Fi 网卡的人都能连接。这也需要被跟踪和清点。

捕获此信息的最佳方法是使用 `configuration management database`（配置管理数据库，`CMDB`）。`CMDB` 用于捕获跟踪环境内硬件所需的所有信息。在 `CMDB` 中，您将需要捕获 IP 地址、主机名、MAC 地址、位置以及负责维护设备的人员。您还必须捕获硬盘空间大小或安装了多少内存。您应该捕获 CPU 的制造商、型号、速度和系统架构。对于网络设备，您可能想知道电路编号或设备的管理 IP。

您还将需要捕获所有笔记本电脑和台式机。这些与安装在组织中的服务器同样重要。如果笔记本电脑丢失或被盗，这将派上用场。这样，您就可以知道设备的配置以及硬盘是否已加密。
