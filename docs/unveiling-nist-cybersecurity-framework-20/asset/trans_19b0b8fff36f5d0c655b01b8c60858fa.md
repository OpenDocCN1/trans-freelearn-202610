

# 遏制与根除

我们需要遏制事件，防止其在网络中蔓延。这可能包括使用防火墙、关闭网段之间的端口以及应用补丁。如果我们知道利用了哪个漏洞，就可以查看漏洞管理系统，报告其他系统是否受影响。一旦确定，我们就可以继续进行补丁修复或实施补偿控制。我们还可以确定是否可以在没有所提供服务的情况下运行，并关闭该系统。

我们还需要寻求第三方供应商的协助。通过联系您的 MSP（托管服务提供商）、执法部门和 ISAC（信息共享与分析中心），您可以获得他们的帮助，了解这些服务是否有其他客户受到类似问题的影响。您还可以与取证公司合作，帮助了解问题的根本原因。所有这些信息对于遏制事件都至关重要。

## RS.MI-02：事件已根除

现在事件已被遏制，我们需要将其从环境中清除。再次查看您的漏洞管理系统，确定是否有类似漏洞影响其他系统。这可以很好地指示攻击下一步可能去向。您还应制定临时纠正措施和永久纠正措施计划。

**临时纠正措施（ICA）** 计划可在响应的遏制阶段开始制定，也可在开始根除时制定。短期内，ICA 旨在记录遏制和根除不利事件时执行的操作。这可以是临时修复，例如实施额外的防火墙规则或关闭某项服务。ICA 还可能包括修补漏洞，以进一步防止感染发生或蔓延。

**永久纠正措施（PCA）** 则更为复杂，通常在事件发生后实施。PCA 可能要求您为新工具争取资金或实施新流程。这些可能是无法在短期内实施的长期项目。PCA 旨在成为解决差距或发现问题的永久性方案。

继续让您的 MSP、执法部门、ISAC 以及您可能使用的任何其他第三方资源参与进来。他们将帮助指导您完成恢复运行所需的流程。集思广益，效果更佳。这将使您受益，同时帮助社区内的其他人了解发生了什么。

事件或事故平息后，开始检查 ICA 阶段实施的措施，并移除任何临时缓解措施。这旨在使您恢复到已知的良好环境，并符合先前建立的基线。然而，这也是调整基线的时候，如果新的监控服务是作为 PCA 的一部分实施的。

# 总结

在本章中，我们讨论了多个与如何响应不利事件相关的主题。我们涵盖了大量关于捕获何种信息、如何捕获以及何时捕获的内容。我们不仅需要捕获有关事件的所有信息，还必须通过使用不同类型的加密来保护这些信息。

我们了解到，捕获所有必要信息以便在需要时能够重演步骤非常重要。这包括涉及事件的人员、地点以及该期间发生的事情。我们还了解到，我们需要捕获事件的元数据。这包括时间戳、IP 地址、用户名和持续时间。我们还需要要求日志中的事件具有关联的序列号。这样，我们就知道日志没有丢失。

正如本章所学，我们也必须保护事件日志。这需要使用加密。我们可以使用哈希算法来确保文档的完整性，或使用数字签名来验证真实性。在许多情况下，SIEM 会为每个传入事件创建一个哈希值，进一步证明记录事件的完整性。

我们讨论了为与内部和外部利益相关者讨论问题而创建各种危机沟通计划的重要性。我们可能还有责任向供应商、客户和监管机构报告事件。例如，HIPAA 规定必须在 60 天内通知受影响者。您将需要一个计划来说明如何沟通和应对这些问题。

最后，我们讨论了 ICA 和 PCA。ICA 是为遏制和根除事件而实施的临时或过渡性缓解措施。ICA 可能是临时防火墙规则或系统和服务的关闭。这些只是临时的，事件平息后可能需要移除。

PCA 是实施的永久性解决方案。PCA 可能是基于项目的，需要数月才能实施。这些也可以是新创建的政策和程序。正如本章所学，可能需要时间来充分规划缓解事件并防止其再次发生所需的所有 PCA。

在下一章中，我们将讨论 *恢复* 功能。该功能旨在提供关于如何从事件中恢复的指导。这可以包括备份恢复，并确保我们的系统恢复正常运行。

# 第 8 章：恢复

我们在 [*第 7 章*](#B21915_07.xhtml#_idTextAnchor163) 中介绍了如何响应事件。这包括收集日志文件、创建对事件进行分类和响应的政策和程序、创建危机沟通计划，以及制定 ICA 和 PCA。为了总结所有这些，我们需要创建事件的文档或摘要以及发生的情况。此时间线将包含多种类型的信息，并且必须受到保护。

首先，我们需要分析进入 SIEM 的日志文件，以确定该事件是否应被视为不利事件。我们必须在 SIEM 中开发规则，以捕捉环境中不利事件的特征或签名。一旦触发签名，我们需要确定事件的阈值或严重性。

如果事件被确定为事故，我们需要启动事件响应计划。该计划将调动事件响应团队开始对事故进行分级。这将需要制定 ICA 和 PCA。ICA 用作临时解决方案，可以包含遏制和根除事故的临时解决方案。

ICA 可用作遏制事故的临时解决方案。这可以包括临时防火墙规则或服务停用。PCA 提供防止未来事故发生的永久性解决方案。PCA 可能是实施解决方案或更改流程的长期项目。

现在我们将研究 NIST CSF 的最后一个功能，**恢复**。为此，我们将深入探讨从事故中恢复所需的内容。这将包括执行恢复流程、恢复备份，以及验证环境是否恢复到已知的工作状态。我们还需要向内部和外部利益相关者传达我们的活动。
