# 身份管理、认证和访问控制（`PR.AA`）

在该控制系列中，我们将介绍身份如何创建和管理，以及如何证明身份与使用该身份的人相匹配。身份不一定非要绑定到个人；它们也可以是基于系统的身份。我们必须确保每个身份都是唯一的，并且每个身份仅分配给一个实体。

## `PR.AA-01`

组织管理授权用户、服务和硬件的身份和凭据。

管理用户凭据有多种方式。大多数组织使用提供身份存储的系统。身份存储包含用户名、密码、组和其他安全相关信息。然后，该身份存储通过 `LDAP` 与其他下游系统以标准方式通信。

凭据有几种不同类型。有与用户或员工绑定的基本凭据，通常仅包含密码或 PIN 码。还有共享凭据，用于“破玻璃”应急流程。这些通常是用于登录系统并执行某些提权任务的管理员账户。

工单通常伴随凭据请求。这是为了给在受监管行业（如 CMMC、PCI 和 HIPAA）工作的人员提供书面记录。IT 部门会处理由不同部门（如人力资源部）发起的请求，以入职新用户或从身份存储中移除旧用户。

每个身份都应是唯一的，因为不应有两个人拥有相同的用户名。如果不止一个人拥有同一个账户，就会产生冲突。也就是说，服务账户也应是唯一的，并为退役目的进行跟踪。如果您继续在多个系统中使用相同的服务账户，您将开始对该账户产生全方位的依赖。如果没有适当的跟踪，一旦发生问题（例如需要更改密码），您将不知道在哪里更改服务的密码。这可能导致严重的安全隐患。

如果您在使用的凭据之上部署了证书，则员工离职时需要吊销这些证书。在许多情况下，加密证书可用作密码的替代品，或与密码结合使用。基于证书的认证通常与员工入职时提供的工牌绑定。

保护用户凭据至关重要，因为这些身份能够登录系统。如果凭据丢失或被盗，攻击者可能在您不知情的情况下登录您的系统。这些攻击往往导致系统沦陷或勒索软件事件。

## `PR.AA-02`

根据交互上下文，对身份进行验证并将其绑定到凭据。

有很多方法可以证明身份。您可以要求提供证明或验证某人就是他们声称的那个人，方法是要求出示驾照、社保卡、水电费账单或护照。您也可以通过验证某人的政府带照片身份证来亲自证明其身份。这些都是证明某人身份的不同方法，但您如何知道哪种方法合适？

在授予某人访问您系统的权限之前，您应始终验证其身份，无论是要求他们到办公室进行物理身份验证，还是使用识别卡。这是确保您环境安全的必要步骤。验证通过后，IT 部门即可为新员工提供用于登录 IT 资源的凭据。

## `PR.AA-03`

对用户、服务和硬件进行认证。

现在我们的员工有了凭据，我们必须将他们认证到给定的系统或服务。有几种不同的方法可以实现这一点。我们可以根据其任务相关的风险，要求对给定设备仅进行单因素认证或多因素认证（`MFA`）。我们还必须阻止与他人共享凭据，因为这违背了拥有唯一凭据的初衷。

我们通常认为认证就是向 IT 资源提供用户名和密码。这是最简单的认证方法，仅要求用户提供他们知道的东西。但随着计算机多年的发展，破解密码的技术也随之进步。

用户也会因记忆不同密码而感到疲劳。这是由于他们有权访问多个系统和服务，因此对多个应用程序使用相同的密码。针对 LinkedIn 和 Facebook 等第三方服务的威胁导致其客户密码泄露，通常是未加密的。这导致了密码喷射攻击，即使用这些泄露中发现的相同密码针对其他基于 SaaS 的应用程序。

这促使许多在线服务采用 `MFA`。除了用户知道的某样东西外，他们还必须拥有某样实物或验证某项特征，通常是指纹或视网膜扫描。传统 `MFA` 系统使用一种物理设备，该设备具有轮换的一次性密码（`OTP`）或 PIN 码供您输入。现代系统使用推送通知到您持有的手机。兼容 `FIDO` 的物理设备（如 `YubiKey`）也是一种可用的 `MFA` 类型。`FIDO` 是一种较新的认证标准，旨在消除密码。它使用公钥/私钥认证，其中 `SP` 保存您的公钥，而您保存私钥。

`MFA` 允许更高级别地证明被认证者的身份。如果有人获得了密码并尝试认证，由于需要第二因素，他们仍然无法成功。

然而，`MFA` 也并非没有问题。`推送疲劳` 是指攻击者反复向服务进行认证，淹没 `MFA` 提供商，连续发送多个推送通知，希望用户按下“确定”按钮。`SIM 卡交换` 也是一种威胁，攻击者试图将受害者的电话号码关联到他们持有的号码上。尽管存在这些风险，但仍然重要的是在任何可能的地方使用 `MFA` 来降低弱密码的风险。
