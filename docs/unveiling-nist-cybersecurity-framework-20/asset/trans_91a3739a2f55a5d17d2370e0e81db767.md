
# 网络分段

扁平网络易于设置、易于维护，也易于被攻破。为什么？因为你没有过滤两个或多个端点之间的任何流量。一旦 IT 资源被攻破，攻击者便可利用该设备跳转到网络内的其他系统。

包括 PCI 在内的多个监管合规机构已强制要求组织将其 PCI 持卡人数据环境与网络的其余部分隔离开来。如果没有适当的分段，整个基于服务器的网络（而不仅仅是存放 PCI 数据的系统）都将受制于 PCI 要求。

最佳实践涉及对整个网络进行分段。如果你有服务器网络、用户网络和无线网络，这些都应由防火墙隔开，限制对其他网络的访问。组织还应设有访客网络，该网络将与环境的其余部分完全隔离。

物联网、运营技术，甚至移动设备也应拥有各自的网络。关键在于 VLAN 的接口应驻留在防火墙或路由器上，这将允许对从一个资源流向下一个资源的流量进行有状态包检测。

在你的局域网内创建好各种网络后，请确保创建了适当的防火墙规则或**访问控制列表**（**ACL**），以限制对其他网络的访问。这也包括出站规则。你的 Active Directory 控制器需要互联网访问权限吗？大概率不需要。如果是这种情况，则防火墙规则应阻止所有出站流量。

## PR.IP-02

*组织的技术资产受到保护，免受环境威胁。*

在开设并运营自己的数据中心，或选择一个数据中心来放置资源之前，你需要进行广泛的调研。数据中心遍布全球；然而，你必须确保已采取充分的防护措施。

例如，组织可能将其 IT 资源放置在国家或全球易受飓风、干旱、洪水甚至山火影响的地区。这些威胁都会影响数据中心本身的运营。如果你将资源放置在一个位于飓风多发区的数据中心，你就得担心电网瘫痪或可能发生的洪水。沙漠听起来可能是建数据中心的好地方；然而，你得担心过热、制冷不足，以及为节约能源而可能发生的轮流停电。数据中心也有不同的等级，你也应予以关注。

在选择数据中心时要关注冗余性。它应拥有多个**互联网服务提供商**（**ISP**）、发电机，以及冗余的**供暖、通风和空调**（**HVAC**）。有些数据中心可能跨州建设，可接入两个或更多电网。在为你的资源和信息选择合适的位置时，应考虑所有这些因素。

## PR.IP-03

*已实施机制，以在正常和不利情况下满足弹性要求。*

在评估系统安全性时，你还需要考虑**机密性、完整性和可用性**（**CIA**）三要素。**CIA 三要素**的一部分是可用性，以及它如何影响特定的 IT 资源。在安全审查期间，询问有关需求和可用性的业务相关问题。这是为了确保系统按预期正常运行。

有些设备不需要 24x7 全天候运行，这完全没问题。然而，许多业务相关系统确实需要这一点，例如充当店面的 Web 服务器或需要持续运行的数据库。确保环境中内置了冗余，以满足业务需求。

系统可能需要负载均衡，或在主资源离线时具备切换到备用资源的能力。网络设备和服务器将具备容纳多个电源的能力，并允许你将这些电源连接到不同的**配电单元**（**PDU**）。你也可能拥有冗余网络接口卡，并让它们在交换机堆栈中的多个交换机间进行负载均衡。或者，你可能只是在地下室某处让一台服务器运行在单个 PDU 上。这完全取决于权衡风险，以及当系统离线时你选择采取什么行动。

## PR.IP-04

*充足的资源容量以确保可用性得以维持。*

你需要建立资源监控以满足此控制目标。这可以通过使用 SNMP 或其他监控相关协议来实现。你需要确保满足当前和未来需求的业务期望。例如，考虑一家在线零售商，其冗余集群中有两套系统，大多数时间都能应付，除非出现流量激增。这可能发生在假期前后，零售商可能不得不考虑扩充分配的资源数量。

你也可以监控网络容量，以确保有足够的带宽满足需求。大型组织通常至少有一个（如果不多）具有备份要求的数据中心。如果你要跨 WAN 复制这些备份，请确保有足够的带宽容量以便复制能适当进行。设置 SNMP 监控网络接口流量将有助于应对这些情况。你可能还需要因资源不足或新需求而为系统增加更多 CPU 或内存。

也要围绕未来容量建立指标或计划。如果你已设置 SNMP 进行监控，请查看历史图表以确定是否需要额外资源。此外，查看过去的容量规划，以确定你是否在正轨上，或者是否需要增加更多资源——例如，利用负载均衡器将计算事务的负载分散到多台服务器上。这将确保系统不会因容量不足而过载并失效。

# 总结

本章涵盖了大量内容，何不回顾一下？我们最初介绍了身份：它是什么、如何分配唯一身份以及如何保护它们。每个用户都应拥有唯一标识符和密码，以保护在线服务账户。我们进一步引入了 MFA，它在提供增强验证或证明身份属于特定用户的同时，进一步保护身份免受攻破。我们还讨论了保护磁盘上、传输中和使用中的数据。这些技术利用某种形式的加密，无论是利用全盘加密还是用于在途数据传输的 TLS。我们还讨论了保护驻留在内存中的信息的必要性，以防攻击者在文件打开或使用时访问它。

备份也被讨论了，以及其被保护和加密的必要性。备份包含来自每个 IT 资源的所有信息，因此在考虑传输和存储时应格外小心。看看你能做些什么来保护备份，确保它们被加密并存储在安全的位置。备份本身也应定期检查，以确保你能成功恢复它们。

接着，我们探讨了硬件和软件的维护。这需要一个 CAB。该委员会负责管理和监督环境中发生的所有变更。每个 IT 资源上的变更都应被跟踪，以确保配置漂移不发生，或者一旦发生，也能被跟踪并纳入系统。在监控配置漂移时，你要确保它不会在 IT 人员不知情的情况下发生。
