

# PR.DS-11

*创建、保护、维护并测试数据备份。*

我们必须尽快保护数据，尤其是在数据不再需要时。现代操作系统会在数据不再需要时尽快将其从内存中移除。这是为了在丢弃数据前保护数据免遭篡改。请查看设备的系统和硬件规格，包括正在使用的硬盘加密应用程序，以防范内存攻击。

这不仅要求笔记本电脑和台式机尽快将此类信息从内存中移除，也适用于网络设备，尤其是执行 `Transport Layer Security` (`TLS`) 卸载的设备。`TLS 卸载` 通常用于负载均衡设备，因为连接必须被解密，以便设备决定将流量转发至何处。我们也可以利用 `TLS 卸载` 进行数据或信息发现，以确定离开我们网络的文件类型。

无论应用何种场景，加密都会被分解以确定如何处理流量。如果攻击者获得了对负载均衡设备的访问权限，这将令人担忧，因为他们将能够搜刮内存，不仅获取敏感信息，还可能获取该期间使用的任何解密密钥。执行这些事务时务必格外小心，以防敏感信息落入错误之手。

在确定特定 IT 资源的安全控制措施时，请确保也对该资源进行备份以满足业务期望。这是为了确保驻留在该系统上的数据得到相应备份。并非所有备份策略都相同；不同系统对执行和测试备份有不同的要求。

在讨论备份策略时，您需要了解业务需求。某些一级系统可能需要按分钟备份以保存数据库事务日志，而二级或三级系统可能只需每天备份一次。这完全取决于业务部门制定的要求。

测试备份与备份本身同等重要。您可能每天都在备份系统，这很棒，但如果备份失败了怎么办？您一开始真的有备份吗？定期测试备份。许多组织每季度测试备份，而其他组织可能每年测试一次。这完全取决于您愿意承担的风险等级。如果您的数据库备份策略是每五分钟执行一次，那么这表明这些备份很重要，测试频率应高于可能一个月只用一次的三级系统。这并非意味着三级系统不重要，而是说它不如数据库重要。

许多备份策略包括同时使用增量备份和全量备份。增量备份更快且占用存储空间更少，最终意味着成本更低。全量备份顾名思义，是对整个系统、文件夹或文件的完整备份。恢复耗时较短；然而，成本高昂且占用最多存储空间。请与业务部门讨论以确定其期望，并制定最合理的策略。

备份中充满敏感信息（无论是 PII、PCI、HIPAA、IP 还是其他被视为敏感的数据）本不足为奇。正如我们保护驻留在硬盘上的数据一样，备份也应加密，以防止数据意外丢失或被盗。加密备份应贴标签并以安全方式存储。组织还会执行多次备份，或复制单个备份副本并分发到多个地理位置分散的数据中心。这是为了确保备份冗余，以便在某设施发生物理故障时，能从其他地方获取备份副本。

为了保护数据免受窃取者访问，我们必须对绝大多数甚至所有操作利用加密。加密带来诸多益处，补丁和配置管理亦是如此，我们将在下一节详细了解。

# 平台安全 (PR.PS)

正如我们识别硬件和软件一样，我们也必须维护它们。需要打补丁以解决软件漏洞和错误。一旦硬件和软件达到生命周期结束，应将其从环境中移除。在着眼于遗留软件和系统的移除时，我们也需要审视软件开发生命周期，以确保其得到适当维护。

## PR.PS-01

*建立并应用配置管理实践。*

当我们首次接收 IT 资源或安装软件时，通常会附带系统默认设置。虽然系统默认值在设置新设备时提供了便利，但不更改这些默认值会引入不必要的风险。在将系统默认设置投入生产环境前，我们必须更改它们。

我们都见过并用过系统默认值。在认证提示符下是否曾输入过 `admin` 和 `password`？登录网络设备时是否曾用 `cisco` 作为用户名和密码？这些都是系统默认值的例子。它们易于使用、猜测且可在互联网上找到。这可能导致未经授权的用户和攻击者在您不知情的情况下登录您的网络。

在将设备投入生产前，应更改这些及其他系统默认值。有可用工具可帮助识别应更改的系统默认值。*互联网安全中心* 为多种不同 IT 资源（如操作系统、网络设备、防火墙和数据库）制定了强化基准。

您还应监控环境以检测与强化基线的任何偏差。这是为了确保未发生配置漂移，且资源保持在风险容忍度范围内。此外，保留所有更改的日志。这将需要创建 `变更咨询委员会` (`CAB`)。

该咨询委员会将负责批准或拒绝对系统所做的任何更改。`CAB` 将出于历史目的跟踪对系统所做的所有更改，并确保在适当时间进行更改。通常，系统更改在无人知晓的情况下进行，可能导致混乱。

## PR.PS-02

*根据风险维护、替换和移除软件。*

如前所述，所有软件都遵循一个生命周期。此生命周期将包含多个阶段；然而，软件可以且总有一个结束日期。您的环境中是否仍在运行 Windows 2003？此软件需及时升级以安装错误修复和修复漏洞。所有这些都应与您愿意承担的风险程度相称。

制定补丁管理生命周期策略，纳入补丁应用的时间。补丁管理生命周期策略还应包括正常维护之外的软件漏洞修补。这包括应立即修补的高危或严重漏洞。您的补丁管理也可能规定禁止修补的日期和时间。这通常是必要的，以确保财务系统在发薪日等时段在线。

建立机制限制用户在其机器上能做和不能做的事。这可以包括移除管理权限。这可以减轻笔记本电脑或台式机上发生的配置漂移量，因为用户没有安装自己软件的能力。
