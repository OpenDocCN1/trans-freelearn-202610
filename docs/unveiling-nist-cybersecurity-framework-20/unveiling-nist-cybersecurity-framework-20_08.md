# 5. 保护




我们在第 4 章中详细了解了识别功能。通过了解什么连接到了您的网络、什么没有连接，以及硬件、软件、已知设备和未知设备，您可以建立自己的信息数据库。该数据库称为配置管理数据库（`CMDB`），可与您网络安全产品组合中的其他服务配对使用。这包括利用漏洞管理系统丰富信息，或将其与灾难恢复和事件响应计划结合使用。关于漏洞数量、从发现到修复的时间范围以及对组织的风险等指标至关重要。这种协作方法可增强您对事件的响应能力。在本章中，我们将介绍保护功能。我们将探讨几种不同的控制措施，例如如何开展安全意识培训、如何保护敏感信息，以及如何增强 IT 资源的韧性。我们将继续利用之前建立的相同系统（如您的 `CMDB`）来构建先前的控制系列。

本章将涵盖以下控制措施：

*   身份管理、认证和访问控制
*   意识与培训
*   数据安全
*   平台安全
*   技术基础设施韧性

# 身份管理、认证和访问控制（`PR.AA`）

在该控制系列中，我们将介绍身份如何创建和管理，以及如何证明身份与使用该身份的人相匹配。身份不一定非要绑定到个人；它们也可以是基于系统的身份。我们必须确保每个身份都是唯一的，并且每个身份仅分配给一个实体。

## `PR.AA-01`

组织管理授权用户、服务和硬件的身份和凭据。

管理用户凭据有多种方式。大多数组织使用提供身份存储的系统。身份存储包含用户名、密码、组和其他安全相关信息。然后，该身份存储通过 `LDAP` 与其他下游系统以标准方式通信。

凭据有几种不同类型。有与用户或员工绑定的基本凭据，通常仅包含密码或 PIN 码。还有共享凭据，用于“破玻璃”应急流程。这些通常是用于登录系统并执行某些提权任务的管理员账户。

工单通常伴随凭据请求。这是为了给在受监管行业（如 CMMC、PCI 和 HIPAA）工作的人员提供书面记录。IT 部门会处理由不同部门（如人力资源部）发起的请求，以入职新用户或从身份存储中移除旧用户。

每个身份都应是唯一的，因为不应有两个人拥有相同的用户名。如果不止一个人拥有同一个账户，就会产生冲突。也就是说，服务账户也应是唯一的，并为退役目的进行跟踪。如果您继续在多个系统中使用相同的服务账户，您将开始对该账户产生全方位的依赖。如果没有适当的跟踪，一旦发生问题（例如需要更改密码），您将不知道在哪里更改服务的密码。这可能导致严重的安全隐患。

如果您在使用的凭据之上部署了证书，则员工离职时需要吊销这些证书。在许多情况下，加密证书可用作密码的替代品，或与密码结合使用。基于证书的认证通常与员工入职时提供的工牌绑定。

保护用户凭据至关重要，因为这些身份能够登录系统。如果凭据丢失或被盗，攻击者可能在您不知情的情况下登录您的系统。这些攻击往往导致系统沦陷或勒索软件事件。

## `PR.AA-02`

根据交互上下文，对身份进行验证并将其绑定到凭据。

有很多方法可以证明身份。您可以要求提供证明或验证某人就是他们声称的那个人，方法是要求出示驾照、社保卡、水电费账单或护照。您也可以通过验证某人的政府带照片身份证来亲自证明其身份。这些都是证明某人身份的不同方法，但您如何知道哪种方法合适？

在授予某人访问您系统的权限之前，您应始终验证其身份，无论是要求他们到办公室进行物理身份验证，还是使用识别卡。这是确保您环境安全的必要步骤。验证通过后，IT 部门即可为新员工提供用于登录 IT 资源的凭据。

## `PR.AA-03`

对用户、服务和硬件进行认证。

现在我们的员工有了凭据，我们必须将他们认证到给定的系统或服务。有几种不同的方法可以实现这一点。我们可以根据其任务相关的风险，要求对给定设备仅进行单因素认证或多因素认证（`MFA`）。我们还必须阻止与他人共享凭据，因为这违背了拥有唯一凭据的初衷。

我们通常认为认证就是向 IT 资源提供用户名和密码。这是最简单的认证方法，仅要求用户提供他们知道的东西。但随着计算机多年的发展，破解密码的技术也随之进步。

用户也会因记忆不同密码而感到疲劳。这是由于他们有权访问多个系统和服务，因此对多个应用程序使用相同的密码。针对 LinkedIn 和 Facebook 等第三方服务的威胁导致其客户密码泄露，通常是未加密的。这导致了密码喷射攻击，即使用这些泄露中发现的相同密码针对其他基于 SaaS 的应用程序。

这促使许多在线服务采用 `MFA`。除了用户知道的某样东西外，他们还必须拥有某样实物或验证某项特征，通常是指纹或视网膜扫描。传统 `MFA` 系统使用一种物理设备，该设备具有轮换的一次性密码（`OTP`）或 PIN 码供您输入。现代系统使用推送通知到您持有的手机。兼容 `FIDO` 的物理设备（如 `YubiKey`）也是一种可用的 `MFA` 类型。`FIDO` 是一种较新的认证标准，旨在消除密码。它使用公钥/私钥认证，其中 `SP` 保存您的公钥，而您保存私钥。

`MFA` 允许更高级别地证明被认证者的身份。如果有人获得了密码并尝试认证，由于需要第二因素，他们仍然无法成功。

然而，`MFA` 也并非没有问题。`推送疲劳` 是指攻击者反复向服务进行认证，淹没 `MFA` 提供商，连续发送多个推送通知，希望用户按下“确定”按钮。`SIM 卡交换` 也是一种威胁，攻击者试图将受害者的电话号码关联到他们持有的号码上。尽管存在这些风险，但仍然重要的是在任何可能的地方使用 `MFA` 来降低弱密码的风险。

## `PR.AA-04`

身份断言受到保护、传输和验证。





# 访问控制 (PR.AA)

## SAML 2.0 和身份提供者

身份验证应防止会话劫持、密码喷射和 MFA 推送疲劳，并确保通信加密。这些只是选择单点登录提供商时需要考虑的几项保障措施。已制定了一些标准来协助解决此问题，其中之一是**安全断言标记语言 (SAML) 2.0**。SAML 2.0 通过**身份提供者 (IdP)** 提供身份验证。IdP 用于对用户进行一次性身份验证，然后向 SP 提供令牌断言。

IdP 和 SP 之间的通信受到保护，免受攻击，并且您可以强制实施 MFA。使用 SAML 提供商的另一个好处是，您可以要求用户重新进行身份验证，从而在发生账户接管事件时终止所有活动会话。

## PR.AA-05

*访问权限、授权和授权在策略中定义、管理、执行和审查，并融入最小权限和职责分离原则。*

当我们向员工授予凭证时，我们为他们提供对特定资源的访问权限。随着时间的推移，这些凭证可能会获得所谓的**权限蔓延**，即调往不同部门或晋升的员工保留了对其不再需要的系统的访问权限。通常，当这种情况发生时，员工使用的凭证会保留其旧权限，同时获得新权限。我们必须考虑将凭证限制为员工完成日常工作所需的权限。

我们还可以考虑**基于属性的访问控制 (ABAC)**，它考虑的因素远不止用户名和密码或 MFA 的使用。ABAC 可以考虑用户或所用凭证的位置、一天中的时间、他们试图访问的内容以及他们的访问意图，无论是读取还是写入文档。

我们应安排时间让员工审查访问权限。这将有助于减少特定用户拥有的权利数量，进一步保障网络安全。用户访问审查应至少每年进行一次，或在提出更改用户账户权限的新请求时进行。

## PR.AA-06

*对资产的物理访问得到管理、监控和执行，与风险相称。*

我们不仅需要保护 IT 资源的逻辑方面，还需要保护物理方面。数据中心安全应始终考虑保护资产的新方法，因为许多逻辑安全配置可能被绕过。管理员账户可通过插入服务器的物理 CD 进行重置，网络设备可通过将注册表设置为特定值来绕过，或通过按住按钮 10 秒来重置设备。

许多数据中心不仅会物理上保护环境，还会实施多项政策和标准，规定人员如何在设施内被陪同。例如，员工可能想进入数据中心维修故障设备。我们应检查他们是否被允许进入数据中心。通常会执行额外的背景调查，以检查试图进入设施的人员是否可信。我们甚至可以决定员工是否可以独自进入设施，或者是否必须由数据中心官员陪同。

我们还必须确立员工进入设施的理由。这通常通过工单完成，因中断而请求访问设施。即使他们已被授予设施访问权限，也不意味着他们可以随时进出数据中心。必须有正当理由。

无论员工能否进入设施，我们仍需验证其身份。这意味着要求员工出示工牌，在签到表上签名并说明访问原因，以及出示授予其进入设施权限的工单号及其访问原因。

这对客人和供应商同样适用。许多客人或供应商若无人陪同，不应被允许进入数据中心。如果他们不为您的公司工作，您可能不希望任何人在无人陪同的情况下访问数据中心。

设施应部署多项防护措施，包括安全摄像头、保安和报警系统。这是为了监控环境，并在出现问题时提供可追溯性。进入服务器室时，我们还可以设置人员闸，要求在进入前进行最后一次授权。在高安全环境中，我们可以使用锁定的机柜，仅提供特定机柜的钥匙。设备上也可使用 RFID 标签，如果服务器被移出设施，则触发警报。

有必要在物理和虚拟层面验证一个人是否为其所声称的人员。这是为了确保正确的个人执行预定职责。安全意识和培训也是教育用户在面对威胁或已识别风险时应采取的适当步骤的关键一步。让我们了解如何做。

# 意识与培训 (PR.AT)

贵公司的员工是网络安全方面的眼睛和耳朵。他们是您的第一道防线。员工往往会在您之前发现针对您设施的新威胁。安全意识和培训不仅面向网络安全专业人员，而是面向公司的每个人。

## PR.AT-01

*为人员提供意识和培训，使其具备知识和技能，能够在考虑安全风险的前提下执行通用任务。*

**安全意识**与**安全培训**是有区别的。**安全意识**旨在在设施内提供通用的网络安全意识。这可能意味着在整个组织张贴传单或海报，宣传网络安全主题。这主要面向 IT 部门以外的人员。

另一方面，**安全培训**则更有针对性，或专注于提供特定领域深入知识的网络安全主题。例如，我们可能了解网络钓鱼诈骗或二维码被恶意利用的危险。一个重点安全培训主题将是培训我们的防火墙管理员使用我们刚刚部署的新防火墙。

网络安全意识活动应定期开展。最佳频率是至少每月一次；时间再长，研究表明人们面对风险时会失去对该做什么的关注 [*1*]。研究表明，每年仅开展一次安全意识项目，与完全不做任何事情一样无效。这就是为什么定期开展这些项目是有益的。

通过网络钓鱼演练跟进您的意识项目，以强化在与电子邮件交互时保持谨慎的必要性。随着网络钓鱼攻击的增加，您需要确保员工接受过培训，知道在收件箱中遇到网络钓鱼邮件时该怎么做。

如前所述，重点培训也是必要的，但这通常针对 IT 相关员工。培训每年至少为您的 IT 和网络安全员工开展一次。也许您需要派他们去上一堂关于使用防火墙的课程，或提供关于新安装的**入侵检测系统/入侵防御系统 (IDS/IPS)** 设备的培训。重点培训也比意识培训昂贵。根据所请求的培训类型，成本可能高达数千美元。这对特定员工是可以接受的，但不适用于全体员工。




您还可以考虑为员工举办关于网络安全主题的演示。这是一种有趣且具有成本效益的方式，无需购买安全意识培训计划即可对员工进行安全相关主题的培训。请务必紧跟新趋势以及攻击者试图获取网络访问权限的新手段。虽然这可能节省资金，但使用供应商提供的培训仍然可能有益。

## PR.AT-02

*专业岗位人员将获得意识教育和培训，以便他们具备相关知识和技能，在考虑安全风险的前提下执行相关任务。*

在创建网络安全意识计划时，您应注意组织内的几个专业岗位。为高管领导团队、财务、人力资源、法务或组织中的其他部门制定课程非常重要，因为他们在 IT 和网络安全方面面临相似但不同的挑战。

虽然通用的网络安全意识计划将满足培训员工的需求，但也必须了解这些领域对业务有不同的关注点。财务部门可能关注银行或电汇转账，而人力资源成员可能关注医疗记录或直接存款转账。针对这些部门的专业领域进行有针对性的关注，在专注于安全意识计划时可能会有所帮助。

这些重点培训领域不必每月进行。重要的是要记住，这将是在您现有的意识计划之外进行的。您可以有几个月的通用意识培训，并零星地对这些部门的风险领域进行更有针对性的审视。

网络安全意识还应包括受信任的第三方、供应商或其他有权访问您网络的人员。请记住，这些人员被视为员工增补或您的 IT 或其他部门员工的延伸。他们应被要求接受与其他员工一样的必要培训。第三方供应商还应被要求审查并签署公司政策和标准，以便他们了解在使用公司设备和设施时什么是可接受的，什么是不可接受的。

在涵盖了意识教育和培训的需求后，我们现在需要了解如何保护数据。

# 数据安全 (PR.DS)

保护静态数据、传输中数据和使用中数据并非易事。但值得庆幸的是，有内置工具可让我们保护数据在所有阶段的安全。

## PR.DS-01

*静态数据的机密性、完整性和可用性得到保护。*

加密是该控制系列的核心。为确保我们充分保护信息，我们必须首先加密数据所在的驱动器。这很重要，原因有很多，但最大的原因是确保如果设备丢失或被盗，无法从硬盘驱动器中检索数据。

从未加密的硬盘驱动器获取信息易如反掌。您可以在任何当地的 IT 或电脑商店购买设备，通过 USB 将驱动器连接到另一台计算机并读取其中的信息。如果硬盘驱动器已加密，则不会出现这种情况。要解密驱动器，您需要密钥。

确保您环境中的每个驱动器都使用全盘加密进行加密。Microsoft 使用名为 `BitLocker` 的程序；对于 Apple 设备，有 `FileVault`；对于 Linux，有 `LUKS`。这些程序将为您管理设备加密，以便您可以使用硬盘驱动器上的信息，完成后再次加密您的文件。始终使用可用的最新加密算法。这是为了防止有人对设备执行侧信道攻击，在没有密码的情况下获取访问权限。

此外，确保您正在加密可移动媒体，如外部硬盘驱动器或拇指驱动器。这些设备的加密与内部硬盘驱动器同样重要。如果这些设备包含敏感数据，如 `知识产权` (`IP`) 或 `个人身份信息` (`PII`) 数据，其丢失也将对您的数据安全产生重大影响。根据丢失数据的严重程度，您可能需要发布声明。

## PR.DS-02

*传输中数据的机密性、完整性和可用性得到保护。*

保护 `传输中数据`（两个或多个系统之间传输的信息）与保护 `静态数据`（存储在本地硬盘驱动器或拇指驱动器上的数据）同样重要，原因有很多。正如将外部驱动器挂载到计算机并读取其内容易如反掌一样，`Wireshark` 等应用程序也使读取未加密的传输中数据变得易如反掌。

`Wireshark` 能够从网络线路上读取数据包并确定正在使用的协议。我们可以重建访问过的网页，甚至重放视频或声音，所有这些都来自该应用程序。加密传输中的数据可防止这种情况发生。

必须编写政策和标准，以反映保护敏感数据的需求。这应包括要使用的正确加密算法和位强度。还应包括严格禁止的加密方式。这些政策文件随后用于强制执行风险数据的保护。

不仅传输中的数据应加密，我们还需要验证消息或文档在传输过程中未被篡改。实现这一点的唯一方法是通过哈希。如前所述，哈希是描述特定时间文件的加密值。如果文件曾被修改，该哈希值会发生变化，反映出文档不再与原始文档相同。

数字签名也可用于确定文件本身的真实性。数字签名是与软件或其他文件关联的加密文件，表明它是由供应商或您组织中的某人创建的。它需要使用私钥来创建签名，该私钥受保护在受保护的保管库或 `硬件安全模块` (`HSM`) 中。

您还应建立机制，限制敏感数据离开设施。您应在环境中标记或标记敏感数据以识别数据类型。然后，在文件被适当标记后，对这些文件应用限制，以防止它们通过电子邮件或其他文件传输协议（如 `SSH 文件传输协议` (`SFTP`)）跨互联网发送。这不要与 `文件传输协议安全` (`FTPS`) 混淆。

还应制定政策，限制在开发或测试环境中使用敏感信息。这些环境通常没有与生产系统相同的安全控制。由于宽松的网络安全控制，这使敏感信息面临风险。测试/开发环境应使用经过清理的信息，以防止数据意外泄露。

## PR.DS-10

*使用中数据的机密性、完整性和可用性得到保护。*

硬盘驱动器加密使用对称算法来保护静态数据。这种对称算法使用单个密码来加密和解密驱动器上的信息。访问文件时，驱动器将解密文件以便应用程序使用，完成后将重新加密文件回驱动器。这在我们的安全中留下了一个漏洞，因为文件在使用时不受保护。




# PR.DS-11

*创建、保护、维护并测试数据备份。*

我们必须尽快保护数据，尤其是在数据不再需要时。现代操作系统会在数据不再需要时尽快将其从内存中移除。这是为了在丢弃数据前保护数据免遭篡改。请查看设备的系统和硬件规格，包括正在使用的硬盘加密应用程序，以防范内存攻击。

这不仅要求笔记本电脑和台式机尽快将此类信息从内存中移除，也适用于网络设备，尤其是执行 `Transport Layer Security` (`TLS`) 卸载的设备。`TLS 卸载` 通常用于负载均衡设备，因为连接必须被解密，以便设备决定将流量转发至何处。我们也可以利用 `TLS 卸载` 进行数据或信息发现，以确定离开我们网络的文件类型。

无论应用何种场景，加密都会被分解以确定如何处理流量。如果攻击者获得了对负载均衡设备的访问权限，这将令人担忧，因为他们将能够搜刮内存，不仅获取敏感信息，还可能获取该期间使用的任何解密密钥。执行这些事务时务必格外小心，以防敏感信息落入错误之手。

在确定特定 IT 资源的安全控制措施时，请确保也对该资源进行备份以满足业务期望。这是为了确保驻留在该系统上的数据得到相应备份。并非所有备份策略都相同；不同系统对执行和测试备份有不同的要求。

在讨论备份策略时，您需要了解业务需求。某些一级系统可能需要按分钟备份以保存数据库事务日志，而二级或三级系统可能只需每天备份一次。这完全取决于业务部门制定的要求。

测试备份与备份本身同等重要。您可能每天都在备份系统，这很棒，但如果备份失败了怎么办？您一开始真的有备份吗？定期测试备份。许多组织每季度测试备份，而其他组织可能每年测试一次。这完全取决于您愿意承担的风险等级。如果您的数据库备份策略是每五分钟执行一次，那么这表明这些备份很重要，测试频率应高于可能一个月只用一次的三级系统。这并非意味着三级系统不重要，而是说它不如数据库重要。

许多备份策略包括同时使用增量备份和全量备份。增量备份更快且占用存储空间更少，最终意味着成本更低。全量备份顾名思义，是对整个系统、文件夹或文件的完整备份。恢复耗时较短；然而，成本高昂且占用最多存储空间。请与业务部门讨论以确定其期望，并制定最合理的策略。

备份中充满敏感信息（无论是 PII、PCI、HIPAA、IP 还是其他被视为敏感的数据）本不足为奇。正如我们保护驻留在硬盘上的数据一样，备份也应加密，以防止数据意外丢失或被盗。加密备份应贴标签并以安全方式存储。组织还会执行多次备份，或复制单个备份副本并分发到多个地理位置分散的数据中心。这是为了确保备份冗余，以便在某设施发生物理故障时，能从其他地方获取备份副本。

为了保护数据免受窃取者访问，我们必须对绝大多数甚至所有操作利用加密。加密带来诸多益处，补丁和配置管理亦是如此，我们将在下一节详细了解。

# 平台安全 (PR.PS)

正如我们识别硬件和软件一样，我们也必须维护它们。需要打补丁以解决软件漏洞和错误。一旦硬件和软件达到生命周期结束，应将其从环境中移除。在着眼于遗留软件和系统的移除时，我们也需要审视软件开发生命周期，以确保其得到适当维护。

## PR.PS-01

*建立并应用配置管理实践。*

当我们首次接收 IT 资源或安装软件时，通常会附带系统默认设置。虽然系统默认值在设置新设备时提供了便利，但不更改这些默认值会引入不必要的风险。在将系统默认设置投入生产环境前，我们必须更改它们。

我们都见过并用过系统默认值。在认证提示符下是否曾输入过 `admin` 和 `password`？登录网络设备时是否曾用 `cisco` 作为用户名和密码？这些都是系统默认值的例子。它们易于使用、猜测且可在互联网上找到。这可能导致未经授权的用户和攻击者在您不知情的情况下登录您的网络。

在将设备投入生产前，应更改这些及其他系统默认值。有可用工具可帮助识别应更改的系统默认值。*互联网安全中心* 为多种不同 IT 资源（如操作系统、网络设备、防火墙和数据库）制定了强化基准。

您还应监控环境以检测与强化基线的任何偏差。这是为了确保未发生配置漂移，且资源保持在风险容忍度范围内。此外，保留所有更改的日志。这将需要创建 `变更咨询委员会` (`CAB`)。

该咨询委员会将负责批准或拒绝对系统所做的任何更改。`CAB` 将出于历史目的跟踪对系统所做的所有更改，并确保在适当时间进行更改。通常，系统更改在无人知晓的情况下进行，可能导致混乱。

## PR.PS-02

*根据风险维护、替换和移除软件。*

如前所述，所有软件都遵循一个生命周期。此生命周期将包含多个阶段；然而，软件可以且总有一个结束日期。您的环境中是否仍在运行 Windows 2003？此软件需及时升级以安装错误修复和修复漏洞。所有这些都应与您愿意承担的风险程度相称。

制定补丁管理生命周期策略，纳入补丁应用的时间。补丁管理生命周期策略还应包括正常维护之外的软件漏洞修补。这包括应立即修补的高危或严重漏洞。您的补丁管理也可能规定禁止修补的日期和时间。这通常是必要的，以确保财务系统在发薪日等时段在线。

建立机制限制用户在其机器上能做和不能做的事。这可以包括移除管理权限。这可以减轻笔记本电脑或台式机上发生的配置漂移量，因为用户没有安装自己软件的能力。




# 保护技术 (PR.PS)

还有一些功能用于限制软件在机器上能做什么和不能做什么。当您只希望特定应用程序在系统上运行时，就会出现这种情况，这通常被称为应用程序的 `allow-listing`（允许列表）。实现这一点的最佳方法是降低用户的权限，并仅安装用户执行工作所需的必要应用程序。

## PR.PS-03

*硬件的维护、更换和移除应与风险相称。*

硬件与软件一样，都有使用寿命，通常为 3–5 年。更换周期的长短可能因制造商而异；但请注意，硬件不会永远耐用，即使我们希望它能。硬件组件会损坏，系统可能会显得变慢，或者您可能无法再升级设备上的固件。

当硬件最终达到其使用寿命终点时，您必须安全地处置它。这并不意味着将其扔进垃圾桶并购买新设备；它必须得到妥善处置。许多硬件制造商都制定了关于如何安全处置设备的指南。相关文档介绍了如何从系统中移除硬盘并将其擦除，以便无法再从中检索任何信息。

最好的方法是与专门从事硬件处置或回收的第三方供应商合作。这些企业将接收您的旧设备并妥善处置，同时安全地清除硬盘上的任何信息。通常，该企业会提供一份证书，证明所有设备均已处置且硬盘上不再残留信息。这很重要，因为它为最后持有设备的人员及执行的操作创建了书面记录或保管链。

同样，请确保您已建立扫描机制以监控环境中的系统。这可以通过 `Simple Network Management Protocol` (`SNMP`) 或其他类型的监控协议来监控。您的 `CMDB` 还应包含设备是什么、采购日期、到期日期以及最新安装的固件版本等记录。这将帮助您制定采购新设备的继任计划，或将工作负载迁移到云 `SP`。

## PR.PS-04

*生成日志记录并使其可用于持续监控。*

一般来说，如果设备连接到您的网络，它就应该记录日志。许多系统默认记录日志，例如操作系统，而其他系统则需要您激活日志记录功能。

您必须制定计划，确定如何记录日志以及日志应存储在何处。通常，系统上线时没有关于日志发送去向的计划。这可能意味着某些系统在本地记录日志，而其他系统将日志发送到 `SIEM` 系统。您还可能遇到不同系统具有不同日志保留期限的情况。有些可能保留一个月，有些更长，有些可能完全停止了日志记录。您需要进行评估以确定当前的日志记录状态。

您还需要确定要保留日志多长时间。多项法规要求规定，在将日志卸载到异地存储设施之前，必须保留一定的时间。一个通用的经验法则是：磁盘上至少保留 90 天的日志，热存储（可随时检索）中保留 180 天的日志，异地保留长达一年的日志。

这也应在您的保留策略中注明。如果确定需要日志来确定事件的结果，而组织没有日志，就会陷入麻烦。如果您在没有策略的情况下删除日志，可能会被视为篡改证据。

在日志解决方案中，还有其他一些要求您需要关注。例如，用户应被要求登录系统才能查看日志。除此之外，您还应要求 `MFA`。管理员不应有权从系统中删除日志；只有日志系统本身应具备根据既定策略删除日志的能力。用于存储日志的存储介质必须加密。最后，必须有完整性检查，以确保存储的日志条目未被篡改。这通常通过创建事件的哈希值来执行。

日志本身有多种不同的格式；但是，您应关注某些特征。日志应包含事件发生的时间戳。每条日志都应有序列号，以便您追踪事件。这也是为了确保日志文件本身没有丢失条目。如果是基于网络的设备，它应同时包含源 IP 和目标 IP，以及可能的端口号。用户账户也应伴随事件，以便追溯到特定用户。

## PR.PS-05

*防止未经授权的软件安装和执行。*

我们之前提到过这一点；然而，在用户在设备上的权限方面，我们必须采取最小权限方法。在许多情况下，以本地管理员身份登录是不必要的，并可能导致系统不稳定。软件应经过数字签名和验证，以确保所安装应用程序的真实性。

还有其他方法可以保护软件安装。可以设置 `Mobile device management` (`MDM`)（移动设备管理）来提供公司或企业应用商店，仅允许从中安装获批的应用程序。`MDM` 软件还允许您控制软件版本。例如，当您拥有仅能在特定版本的 `Java` 上运行的应用程序时，这会有所帮助。

## PR.PS-06

*安全软件开发实践被集成，且其性能在整个软件开发生命周期中受到监控。*

如果您的组织为内部资源或外部客户开发软件，它应该有一个相关的生命周期。在开发过程中有许多方法可以保护您的代码，并管理代码在不再使用时如何处置。让我们来看看。

您应该在整个生命周期中对代码进行数字签名，以防止对手篡改。许多基于 `SaaS` 的 `Git` 提供商允许您使用 `GNU Privacy Guard` (`GPG`) 对提交和标签进行数字签名。这对于进一步确定是谁向存储库提交了代码非常重要。当您对提交进行签名时，您还将收到一个 `Verified` 标签，进一步表明该提交是由经过验证的人员提交的。

在向代码存储库进行身份验证时，您应该使用 `Secure Shell` (`SSH`) 密钥以及 `MFA`。这两种身份验证方法也将有助于确定对存储库进行身份验证的用户。然后，您可以使用 `SSH` 密钥在本地计算机和存储库之间传输代码。

一旦不再需要代码，就应将其丢弃。您可能需要在丢弃前保留代码数年。这将要求您将其存储在异地的加密卷中以妥善保管。您还需要确保代码不再对开发人员可用。这将有助于确保代码一旦退役，就无法再被使用。

# 技术基础设施韧性 (PR.IP)

我们将探讨对网络进行分段以促进资源更好隔离的方法，同时确定确保高可用性的方法。这将包括物理组件，如电源和环境温度。

## PR.IP-01

*网络和环境受到保护，免受未经授权的逻辑访问和使用。*



# 网络分段

扁平网络易于设置、易于维护，也易于被攻破。为什么？因为你没有过滤两个或多个端点之间的任何流量。一旦 IT 资源被攻破，攻击者便可利用该设备跳转到网络内的其他系统。

包括 PCI 在内的多个监管合规机构已强制要求组织将其 PCI 持卡人数据环境与网络的其余部分隔离开来。如果没有适当的分段，整个基于服务器的网络（而不仅仅是存放 PCI 数据的系统）都将受制于 PCI 要求。

最佳实践涉及对整个网络进行分段。如果你有服务器网络、用户网络和无线网络，这些都应由防火墙隔开，限制对其他网络的访问。组织还应设有访客网络，该网络将与环境的其余部分完全隔离。

物联网、运营技术，甚至移动设备也应拥有各自的网络。关键在于 VLAN 的接口应驻留在防火墙或路由器上，这将允许对从一个资源流向下一个资源的流量进行有状态包检测。

在你的局域网内创建好各种网络后，请确保创建了适当的防火墙规则或**访问控制列表**（**ACL**），以限制对其他网络的访问。这也包括出站规则。你的 Active Directory 控制器需要互联网访问权限吗？大概率不需要。如果是这种情况，则防火墙规则应阻止所有出站流量。

## PR.IP-02

*组织的技术资产受到保护，免受环境威胁。*

在开设并运营自己的数据中心，或选择一个数据中心来放置资源之前，你需要进行广泛的调研。数据中心遍布全球；然而，你必须确保已采取充分的防护措施。

例如，组织可能将其 IT 资源放置在国家或全球易受飓风、干旱、洪水甚至山火影响的地区。这些威胁都会影响数据中心本身的运营。如果你将资源放置在一个位于飓风多发区的数据中心，你就得担心电网瘫痪或可能发生的洪水。沙漠听起来可能是建数据中心的好地方；然而，你得担心过热、制冷不足，以及为节约能源而可能发生的轮流停电。数据中心也有不同的等级，你也应予以关注。

在选择数据中心时要关注冗余性。它应拥有多个**互联网服务提供商**（**ISP**）、发电机，以及冗余的**供暖、通风和空调**（**HVAC**）。有些数据中心可能跨州建设，可接入两个或更多电网。在为你的资源和信息选择合适的位置时，应考虑所有这些因素。

## PR.IP-03

*已实施机制，以在正常和不利情况下满足弹性要求。*

在评估系统安全性时，你还需要考虑**机密性、完整性和可用性**（**CIA**）三要素。**CIA 三要素**的一部分是可用性，以及它如何影响特定的 IT 资源。在安全审查期间，询问有关需求和可用性的业务相关问题。这是为了确保系统按预期正常运行。

有些设备不需要 24x7 全天候运行，这完全没问题。然而，许多业务相关系统确实需要这一点，例如充当店面的 Web 服务器或需要持续运行的数据库。确保环境中内置了冗余，以满足业务需求。

系统可能需要负载均衡，或在主资源离线时具备切换到备用资源的能力。网络设备和服务器将具备容纳多个电源的能力，并允许你将这些电源连接到不同的**配电单元**（**PDU**）。你也可能拥有冗余网络接口卡，并让它们在交换机堆栈中的多个交换机间进行负载均衡。或者，你可能只是在地下室某处让一台服务器运行在单个 PDU 上。这完全取决于权衡风险，以及当系统离线时你选择采取什么行动。

## PR.IP-04

*充足的资源容量以确保可用性得以维持。*

你需要建立资源监控以满足此控制目标。这可以通过使用 SNMP 或其他监控相关协议来实现。你需要确保满足当前和未来需求的业务期望。例如，考虑一家在线零售商，其冗余集群中有两套系统，大多数时间都能应付，除非出现流量激增。这可能发生在假期前后，零售商可能不得不考虑扩充分配的资源数量。

你也可以监控网络容量，以确保有足够的带宽满足需求。大型组织通常至少有一个（如果不多）具有备份要求的数据中心。如果你要跨 WAN 复制这些备份，请确保有足够的带宽容量以便复制能适当进行。设置 SNMP 监控网络接口流量将有助于应对这些情况。你可能还需要因资源不足或新需求而为系统增加更多 CPU 或内存。

也要围绕未来容量建立指标或计划。如果你已设置 SNMP 进行监控，请查看历史图表以确定是否需要额外资源。此外，查看过去的容量规划，以确定你是否在正轨上，或者是否需要增加更多资源——例如，利用负载均衡器将计算事务的负载分散到多台服务器上。这将确保系统不会因容量不足而过载并失效。

# 总结

本章涵盖了大量内容，何不回顾一下？我们最初介绍了身份：它是什么、如何分配唯一身份以及如何保护它们。每个用户都应拥有唯一标识符和密码，以保护在线服务账户。我们进一步引入了 MFA，它在提供增强验证或证明身份属于特定用户的同时，进一步保护身份免受攻破。我们还讨论了保护磁盘上、传输中和使用中的数据。这些技术利用某种形式的加密，无论是利用全盘加密还是用于在途数据传输的 TLS。我们还讨论了保护驻留在内存中的信息的必要性，以防攻击者在文件打开或使用时访问它。

备份也被讨论了，以及其被保护和加密的必要性。备份包含来自每个 IT 资源的所有信息，因此在考虑传输和存储时应格外小心。看看你能做些什么来保护备份，确保它们被加密并存储在安全的位置。备份本身也应定期检查，以确保你能成功恢复它们。

接着，我们探讨了硬件和软件的维护。这需要一个 CAB。该委员会负责管理和监督环境中发生的所有变更。每个 IT 资源上的变更都应被跟踪，以确保配置漂移不发生，或者一旦发生，也能被跟踪并纳入系统。在监控配置漂移时，你要确保它不会在 IT 人员不知情的情况下发生。




我们还希望确保受保护的设备在需要时可用。可利用负载均衡器等机制以及 SNMP 等监控协议，以确保系统运行正常，并能监控资源问题。

在下一章中，我们将了解 `Detect`（检测）功能。该功能旨在帮助我们确定可能遇到的各种检测类型、如何处理它们，以及将它们发送到 SIEM 系统或日志收集器的重要性。
