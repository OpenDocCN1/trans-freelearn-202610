
> 此技术也可用于返回结果或不返回结果的 SELECT 语句。

![](img/cb8c75b631b4e1f7afe5a0d39becfda9_245_0.png)

这将产生以下效果：

- 可以访问同一数据库（当前数据库）的所有用户都将可以访问该书签。

- 用户将能够删除该书签。

## 表的默认初始查询

在之前的示例中，我们根据自己的喜好选择了书签标签。然而，按惯例，如果书签的名称与表名相同，则在为该表点击 Browse 时会执行它。因此，我们将不会看到该表的正常 Browse 结果，而是会看到书签的结果。

## 书签

假设我们有兴趣查看（默认在 Browse 模式下）页数少于 300 的书籍。我们首先生成适当的查询，这可以很容易地从 Search 页面完成，然后我们在结果页面上使用 book 作为标签。

```
SELECT `isbn`, `title`, `page_count`, `author_id`
FROM `book`
WHERE `page_count` <300
LIMIT 0, 30
```

## 多查询书签

单个书签也可以存储多个查询（用分号分隔）。这主要对非 SELECT 查询有用。例如，假设我们需要定期清理作者数据，从电话号码中删除无效区号。此操作总是会随后显示 author 表。

为实现此目标，我们存储一个书签（在发送执行之前），其中包含以下查询：

```
update author set phone = replace(phone,'(123)','(456)');
select * from author;
```

在书签中，我们可以放置许多数据修改语句，如 INSERT、UPDATE 或 DELETE，可选择跟随一个 SELECT 语句。堆叠大量 SELECT 语句不会产生预期结果，因为我们只能看到最后一个 SELECT 语句获取的数据。

## 书签执行

选择第一个书签并点击 Go 会执行存储的查询并显示其结果。书签执行后的页面没有创建书签的另一个对话框，因为这将是多余的。

> 我们得到的结果不一定与创建书签时相同。它们反映了数据库的当前内容。只有查询被存储为书签。

## 书签操作

有时，我们可能只想确定书签的内容。这是通过选择一个书签并选择 **仅查看** 来完成的。只会显示查询。然后我们可以点击 **编辑** 并重新处理其内容。这样做时，我们将编辑原始书签查询的副本。为了保留这个新编辑的查询，我们可以将其保存为书签。同样，即使我们选择相同的书签标签，这也会创建另一个书签，除非我们明确要求替换原始书签。

书签可以用 **删除** 选项擦除。删除书签时没有确认对话框。删除后只会显示一条消息：**书签已被删除。**

## 书签参数

如果我们再次查看我们创建的第一个书签（查找所有 **作者 1** 的书籍），我们意识到虽然它很有用，但仅限于查找同一作者。

特殊的查询语法使能够向书签传递参数。此语法利用了 SQL 注释在 /* 和 */ 之间会被 MySQL 忽略的事实。如果 /*[VARIABLE]*/ 构造存在于查询中的某个位置，它将在执行时使用召回书签时提供的值进行扩展。

## 创建参数化书签

假设我们想查找给定作者的所有书籍，但我们不知道作者的名字。我们首先输入以下查询：

```sql
SELECT author.name, author.id, book.title
FROM book, author
WHERE book.author_id = author.id
/* AND author.name LIKE '%[VARIABLE]%' */
```

注释字符（/* */）之间的部分稍后将被扩展，并且标签将被删除。我们将此查询标记为名为 **按名称查找作者** 的书签并点击 **执行**。查询的第一次执行只是存储书签，同时检索所有作者的所有书籍，因为这次我们没有向查询传递参数。

在此示例中，WHERE 子句中有两个条件，其中一个包含特殊语法。如果 WHERE 子句中唯一的条件需要参数，我们可以使用类似 WHERE 1 /* and author_id = [VARIABLE] */ 的语法。
