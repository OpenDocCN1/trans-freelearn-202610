
## 在服务器上保存导出文件

与其通过 HTTP 在网络上传输导出文件，可以直接将其保存到 Web 服务器的文件系统中。这可能更快，并且对执行时间限制不那么敏感，因为从服务器到客户端浏览器的整个传输过程被绕过。最终，可以使用 FTP 或 SFTP 等文件传输协议来检索文件，因为将其留在同一台机器上并不能提供良好的备份保护。

在服务器上保存导出文件之前，必须在 Web 服务器上创建一个特殊目录。通常，这是 phpMyAdmin 主目录的子目录。我们将使用 save_dir 作为示例。该目录必须具有特殊权限。首先，Web 服务器必须对该目录具有写入权限。此外，如果 Web 服务器的 PHP 组件以安全模式运行，则 phpMyAdmin 脚本的所有者必须与 save_dir 相同。

在 Linux 系统上，假设 Web 服务器以组 apache 运行，并且脚本由用户 "marc" 拥有，以下命令即可解决问题：

```
# mkdir save_dir
# chown marc.apache save_dir
# chmod g=rwx save_dir
```

> 适当的拥有权和权限掩码高度取决于所选择的 Web 服务器和所使用的 SAPI（服务器应用程序编程接口）（请参阅 http://en.wikipedia.org/wiki/Server_Application_Programming_Interface），它会影响目录和文件的创建和访问方式。PHP 可能使用脚本的所有者作为访问用户，也可能是 Web 服务器本身的用户/组。

我们还必须在 $cfg['SaveDir'] 中定义 './save_dir' 目录名。这里我们使用相对于 phpMyAdmin 目录的路径，但绝对路径同样适用。

“另存为文件”部分将出现一个新的“保存到服务器...”部分：

单击 Go 后，我们将收到确认消息或错误消息（如果 Web 服务器没有保存文件的必要权限）。

## 用户特定的保存目录

我们可以在 $cfg['SaveDir'] 参数中使用特殊字符串 %u。该字符串将被已登录的用户名替换。例如，使用

```
$cfg['SaveDir'] = './save_dir/%u';
```

这将给我们一个屏幕上的选择，**保存到服务器上的 /save_dir/marc/ 目录**。这些目录（每个潜在用户一个）必须存在并且必须具有适当的权限，如上一节所述。

## 内存限制

生成导出文件会使用一定量的内存，这取决于表的大小和所选的选项。$cfg['MemoryLimit'] 参数可以包含正在运行的 PHP 脚本使用的内存量的限制（以字节为单位）。默认情况下，该参数设置为 0，表示没有限制。请注意，如果 PHP 已激活安全模式，更改 $cfg['MemoryLimit'] 没有任何效果。相反，强制执行的限制来自 php.ini 中的 memory_limit 指令。

## 8 导入结构和数据

在本章中，我们将学习如何将为备份或传输目的而创建的导出数据带回。导出数据也可能来自其他应用程序的作者，并且可能包含这些应用程序的整个基础结构和一些示例数据。

当前的 phpMyAdmin 版本（3.1）可以直接导入包含 MySQL 语句的文件（通常具有 .sql 后缀，但不一定如此）和 CSV 文件（逗号分隔值，尽管分隔符不一定是逗号）。未来的版本可能能够导入更多格式的文件。还有一个 MySQL LOAD DATA INFILE 语句的接口，使我们能够加载包含数据（也称为 CSV）的文本文件。第 6 章中介绍的二进制字段上传可以说属于导入家族。

> 在此上下文中，导入和上传是同义词。

可以从多个面板访问导入功能：

- 可从主页、数据库视图或表视图访问的 **导入** 菜单
- 在 **查询窗口** 内提供的 **导入文件** 菜单（如第 12 章所述）

在 2.11.0 版本中添加了一个功能：导入文件可能包含 DELIMITER 关键字。这使 phpMyAdmin 能够模仿 mysql 命令行解释器。DELIMITER 分隔符用于界定包含存储过程的文件部分，因为这些过程本身可能包含分号。

导入界面的默认值在 $cfg['Import'] 中定义。

在检查实际导入对话框之前，让我们讨论一些限制问题。

## 传输限制

当我们导入时，源文件通常位于我们的客户端机器上；因此，它必须通过 HTTP 传输到服务器。此传输需要时间并使用可能在 Web 服务器的 PHP 配置中受限的资源。

而不是使用 HTTP，我们可以使用 FTP 等协议将文件上传到服务器，如“Web 服务器上传目录”部分所述。此方法绕过了 Web 服务器的 PHP 上传限制。

## 时间限制

首先，让我们考虑时间限制。在 config.inc.php 中，$cfg['ExecTimeLimit'] 配置指令默认将任何 phpMyAdmin 脚本（包括文件上传后处理数据的脚本）的最大执行时间分配为 300 秒（五分钟）。值为 0 可移除限制，理论上可让我们无限时间完成导入操作。如果 PHP 服务器以安全模式运行，修改 $cfg['ExecTimeLimit'] 将没有任何效果。这是因为在 php.ini 或用户相关的 Web 服务器配置文件（如 .htaccess 或虚拟主机配置文件）中设置限制优先于此参数。

当然，实际花费的时间取决于两个关键因素：

- Web 服务器负载
- MySQL 服务器负载

> 文件在客户端和服务器之间传输所花费的时间不计入执行时间，因为 PHP 脚本仅在文件已接收到服务器后才开始执行。因此，$cfg['ExecTimeLimit'] 参数仅对处理数据（如解压缩或发送到 MySQL 服务器）所使用的时间产生影响。

## 其他限制

系统管理员可以使用 php.ini 文件或 Web 服务器的虚拟主机配置文件来控制服务器上的上传。

upload_max_filesize 参数指定可通过 HTTP 上传的上限或最大文件大小。这很明显，但另一个不太明显的参数是 post_max_size。由于 HTTP 上传是通过 POST 方法完成的，因此此参数可能会限制我们的传输。有关 POST 方法的更多详细信息，请参阅 http://en.wikipedia.org/wiki/Http#Request_methods。

memory_limit 参数用于防止 Web 服务器子进程占用过多的服务器内存——phpMyAdmin 也作为子进程运行。因此，正常文件上传的处理，特别是压缩转储，可能会因给此参数一个较小的值而受到影响。这里无法推荐首选值；该值取决于上传数据的大小。内存限制也可以通过 config.inc.php 中的 $cfg['MemoryLimit'] 参数进行调整，如第 7 章所述。

最后，必须通过将 file_uploads 设置为 on 来允许文件上传。否则，phpMyAdmin 甚至不会显示“文本文件位置”对话框。显示此对话框毫无用处，因为稍后会被 Web 服务器的 PHP 组件拒绝连接。

## 部分导入

如果文件太大，有几种方法可以解决这种情况。如果我们仍有权访问原始数据，我们可以使用 phpMyAdmin 生成较小的 CSV 导出文件，选择“转储 n 行，从记录 # n 开始”对话框。如果不可能，我们将不得不使用文本编辑器将文件拆分为较小的部分。另一种可能性是使用上传目录机制，该机制访问 $cfg['UploadDir'] 中定义的目录。本章后面将解释此功能

在最近的 phpMyAdmin 版本中，部分导入功能也可以解决此文件大小问题。通过选择“允许中断...”复选框，如果导入过程检测到接近时间限制，它将自行中断。我们还可以指定要从开头跳过的查询数量，以防我们成功导入若干行并希望从该点继续。

## 临时目录

在某些服务器上，可以设置一个名为 open_basedir 的安全功能，其方式会阻碍上传机制。在这种情况下，或出于任何其他原因，当上传有问题时，可以将 $cfg['TempDir'] 参数设置为临时目录的值。这很可能是一个 phpMyAdmin 主目录的子目录，Web 服务器允许将上传的文件放在其中。
