# 14 书签

本章介绍查询书签——链接表基础设施的一项功能。能够为查询标记标签并按标签召回，可以节省大量时间。书签是以下类型的查询：

- 永久存储
- 可查看
- 可擦除
- 与一个数据库相关
- 仅在用户意愿下记录
- 有标签
- 默认私有（仅创建者可用），但可能公开

书签也可以有一个可变部分，如本章后面 Passing a parameter value to a bookmark 部分所述。

没有用于管理书签的书签子页面。相反，书签的各种操作可在特定页面上进行，例如结果页面或查询框页面。

## 比较书签和查询历史功能

在第 12 章中，我们了解了 SQL 历史功能，它会自动存储查询（临时或永久）。历史中存储的查询与书签之间存在相似之处。毕竟，这两个功能都旨在为以后执行而存储查询。然而，在存储方式和触发查询记录的操作方面存在重要差异。

永久历史中存储的查询数量有一个可配置的限制（参见第 12 章）；然而，书签的数量没有限制。此外，历史功能按发送时间的逆序显示查询。然而，书签按标签显示（不直接显示查询文本）。最后，历史中的查询存储是自动的，而查询作为书签保存则是通过用户的明确请求。

总结一下，自动查询历史在我们既不打算召回查询，也不希望记住输入了哪些查询时很有用。这与书签功能形成对比，在书签功能中，我们有意要求系统记住一个查询，甚至为其命名（标签）。因此，我们可以用书签做更多事情，而不是查询历史，但两者各有重要性。

## 书签创建

创建查询有两个时机——在查询执行后（这种情况下我们不需要提前计划其创建）或在将查询发送到 MySQL 服务器执行之前。以下各节将探讨这两种选项。

## 在成功查询后创建书签

初始书签创建由 Bookmark this SQL query 按钮实现。该按钮仅在执行生成结果的查询后出现（当至少找到一行时）；因此，这种创建书签的方法仅存储 SELECT 语句。例如，第 13 章中看到的多表查询生成器产生的复杂查询，如果找到一些结果，可以通过这种方式存储为书签。

让我们看一个例子。在 book 表的 Search 页面中，我们选择希望在结果中显示的字段，并按以下屏幕截图所示输入搜索值：

![](img/cb8c75b631b4e1f7afe5a0d39becfda9_243_0.png)

点击 Go 后，我们看到结果页面显示了一个书签对话框。我们仅为此书签输入一个标签，然后点击 Bookmark this SQL query 将此查询保存为书签。书签保存在由 `$cfg['Servers'][$i]['bookmarktable']` 定义的表中。

![](img/cb8c75b631b4e1f7afe5a0d39becfda9_243_1.png)

此书签对话框可在任何包含结果的页面上看到。作为测试，我们只需为某个表点击 **Browse** 以获取结果，然后将此查询存储为书签即可。然而，将一个只需点击一下即可轻松完成的查询存储在书签中并没有多大意义。

## 在发送查询前存储书签

有时，即使查询没有找到任何结果，我们也可能想存储一个书签。如果匹配的数据尚未存在，或查询不是 SELECT 语句，则可能出现这种情况。为此，我们在 Database 视图、Table 视图和查询窗口的 **SQL** 选项卡中提供了 **Bookmark this SQL query** 对话框。

现在我们进入 **book** 表的 **SQL** 子页面，输入一个查询，并直接在 **Bookmark this SQL query** 字段中输入 **books in French** 书签标签。如果此书签标签以前使用过，除非我们选择 **Replace existing bookmark of same name** 复选框，否则将创建具有相同名称的新书签。书签带有内部标识号以及用户选择的标签。

![](img/cb8c75b631b4e1f7afe5a0d39becfda9_244_0.png)

点击 **Go** 后，查询将被执行并存储为书签。即使查询没有找到任何内容也没关系。这就是我们如何为非 SELECT 查询（如 UPDATE、DELETE、CREATE TABLE 等）生成书签的方式。



> 此技术也可用于返回结果或不返回结果的 SELECT 语句。

## 公共书签

我们创建的所有书签默认都是私有的。当创建书签时，我们登录时使用的用户名会与书签一起存储。假设我们选择让每个用户访问此书签，如以下屏幕截图所示：

![](img/cb8c75b631b4e1f7afe5a0d39becfda9_245_0.png)

这将产生以下效果：

- 可以访问同一数据库（当前数据库）的所有用户都将可以访问该书签。
- 用户从书签中看到有意义的结果的能力取决于他们对书签中引用的表所拥有的权限。
- 用户将能够删除该书签。

## 表的默认初始查询

在之前的示例中，我们根据自己的喜好选择了书签标签。然而，按惯例，如果书签的名称与表名相同，则在为该表点击 Browse 时会执行它。因此，我们将不会看到该表的正常 Browse 结果，而是会看到书签的结果。

## 书签

假设我们有兴趣查看（默认在 Browse 模式下）页数少于 300 的书籍。我们首先生成适当的查询，这可以很容易地从 Search 页面完成，然后我们在结果页面上使用 book 作为标签。

```
SELECT `isbn`, `title`, `page_count`, `author_id`
FROM `book`
WHERE `page_count` <300
LIMIT 0, 30
```

![](img/cb8c75b631b4e1f7afe5a0d39becfda9_246_0.png)

## 多查询书签

单个书签也可以存储多个查询（用分号分隔）。这主要对非 SELECT 查询有用。例如，假设我们需要定期清理作者数据，从电话号码中删除无效区号。此操作总是会随后显示 author 表。

为实现此目标，我们存储一个书签（在发送执行之前），其中包含以下查询：

```
update author set phone = replace(phone,'(123)','(456)');
select * from author;
```

在书签中，我们可以放置许多数据修改语句，如 INSERT、UPDATE 或 DELETE，可选择跟随一个 SELECT 语句。堆叠大量 SELECT 语句不会产生预期结果，因为我们只能看到最后一个 SELECT 语句获取的数据。

## 从书签列表中召回

这些书签现在可以很容易地在以下页面找到：

- 表视图：marc_book 中任何表的 SQL 子页面
- 查询窗口：SQL-History 选项卡
- 在浏览 pma_bookmark 表时（请参阅后面的“通过浏览 pma_bookmark 表执行书签”部分）
- 数据库视图：marc_book 数据库的 SQL 子页面

![](img/cb8c75b631b4e1f7afe5a0d39becfda9_247_0.png)

召回书签时有三种选择——Submit、View only 和 Delete（Submit 为默认值）。

## 书签执行

选择第一个书签并点击 Go 会执行存储的查询并显示其结果。书签执行后的页面没有创建书签的另一个对话框，因为这将是多余的。

> 我们得到的结果不一定与创建书签时相同。它们反映了数据库的当前内容。只有查询被存储为书签。

## 书签操作

有时，我们可能只想确定书签的内容。这是通过选择一个书签并选择 **仅查看** 来完成的。只会显示查询。然后我们可以点击 **编辑** 并重新处理其内容。这样做时，我们将编辑原始书签查询的副本。为了保留这个新编辑的查询，我们可以将其保存为书签。同样，即使我们选择相同的书签标签，这也会创建另一个书签，除非我们明确要求替换原始书签。

书签可以用 **删除** 选项擦除。删除书签时没有确认对话框。删除后只会显示一条消息：**书签已被删除。**

## 书签参数

如果我们再次查看我们创建的第一个书签（查找所有 **作者 1** 的书籍），我们意识到虽然它很有用，但仅限于查找同一作者。

特殊的查询语法使能够向书签传递参数。此语法利用了 SQL 注释在 /* 和 */ 之间会被 MySQL 忽略的事实。如果 /*[VARIABLE]*/ 构造存在于查询中的某个位置，它将在执行时使用召回书签时提供的值进行扩展。

## 创建参数化书签

假设我们想查找给定作者的所有书籍，但我们不知道作者的名字。我们首先输入以下查询：

```sql
SELECT author.name, author.id, book.title
FROM book, author
WHERE book.author_id = author.id
/* AND author.name LIKE '%[VARIABLE]%' */
```

注释字符（/* */）之间的部分稍后将被扩展，并且标签将被删除。我们将此查询标记为名为 **按名称查找作者** 的书签并点击 **执行**。查询的第一次执行只是存储书签，同时检索所有作者的所有书籍，因为这次我们没有向查询传递参数。

在此示例中，WHERE 子句中有两个条件，其中一个包含特殊语法。如果 WHERE 子句中唯一的条件需要参数，我们可以使用类似 WHERE 1 /* and author_id = [VARIABLE] */ 的语法。
