Each project contains a default security group that allows all egress traffic but denies all ingress traffic. Security groups are frequently used to open ports that users may need to access for talking to applications outside OpenStack, as well as to prevent unnecessary east-west traffic between different applications on the same subnet—thus adding an additional layer of protection.

Security group rules are stateful and allow established traffic. An example of this would be allowing ingress TCP port 22 for SSH. This rule automatically allows established return traffic. Another example is allowing egress ICMP for pinging out. This will automatically allow return traffic so the user can see a reply to their ping.
