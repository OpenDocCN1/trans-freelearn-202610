
# 使用 Apex 共享的 Flow

在本章中，我们将讨论一个非常重要的功能：通过 Flow 共享记录，这个功能除了使用 Apex 编程之外，没有其他实现方式。借助 Apex 共享，我们可以编写 Apex 代码来实现复杂且动态的共享设置。现在，通过 Flow，这项功能已经可用，因此作为管理员，你无需编写代码即可执行这些操作。对管理员来说，这个主题稍微有点高级。了解 Flow Builder 中提供了此功能会有所帮助，一个很好的用例是动态地为用户添加或删除访问权限。

在我们深入探讨用于 Apex 共享的 Flow 的细节之前，让我们快速回顾一下在 Salesforce 中可用于与用户共享记录的不同选项。我们将仅在自定义对象的上下文中讨论这一点，因为 Salesforce 提供了通过针对各个自定义对象的 Apex 共享原因来进行 Apex 管理共享的选项。

在本章中，我们将涵盖以下小节：

- Salesforce 中的数据共享选项
- 使用 Apex 管理共享来共享数据
- 探索真实业务场景
- 测试我们的实际场景

尽管我们说无需代码，但我们仍需要在某种程度上理解代码，并了解一些开发工具。我将通过截图详细地讲解这些内容，以便在你计划实施时，能对每个步骤及其含义有很好的把握。我还会逐步引导你测试这个场景，因为我们需要其他工具来验证结果。

有了这些背景，让我们以管理员身份来看看 Salesforce 中当前可用的数据共享选项。

## Salesforce 中的数据共享选项

组织的关键需求之一是在其软件系统中能够访问并控制业务记录。你的组织应该能够完全控制谁能访问你的业务数据。与所有其他系统一样，Salesforce 允许你让特定用户查看某个对象，并限制他们可以查看的单独记录。你可以通过四种方式管理记录级访问权限，除非你通过**组织级默认值（OWD）**将所有对象设为公开，否则你需要组合使用多种方式。

在高层面上，以下选项无需 Apex 编程即可为你的用户启用访问权限：

- **OWD**：指定用户相互之间可以访问对方数据（记录）的默认访问级别。我们有三个选项，以及**通过层级结构授予访问权限**选项。（**通过层级结构授予访问权限**选项是一个 OWD 设置，用于控制任何自定义对象通过层级结构进行共享访问。要使 Salesforce 自定义对象成为私有对象，请在 OWD 设置中禁用此选项。它只能为自定义对象更改。）
- **私有**：如果未选中**通过层级结构授予访问权限**，则只有所有者可以访问记录；如果选中，则角色层级中位于所有者之上的用户可以访问此记录。
- **公开只读**：所有用户都可以查看该记录。
- **公开读写**：所有用户都可以编辑该记录。
- **角色层级**：授予对层级中较高位置用户所拥有记录的访问权限。**角色层级**通过 OWD 上的**通过层级结构授予访问权限**启用。如果你勾选了层级中所有者之上的用户角色，你就可以访问该记录。
- **共享规则**：自动例外，仅用于向其他用户授予记录的访问权限。你可以根据记录所有者或条件共享记录，并且可以将其共享给公共组、角色和下属，访问级别为只读或读写。
- **手动共享**：这种共享类型允许特定记录的所有者与其他用户共享记录。记录所有者可以通过客户团队或机会团队手动设置对单个记录的记录级访问权限。

我在这里列出了一些选项，以便让你有所了解。此外，我们还有默认客户团队、默认机会团队、经理组、隐式共享等等。

现在，让我们看看是否有这样的场景：你希望只有一小部分用户能够访问自定义对象中的记录。你能想到使用前面描述的现成功能来实现这个用例的方法吗？

## 使用 Apex 管理共享共享数据

Apex 管理共享提供了通过 Apex 或 SOAP API 以编程方式支持特定共享需求的能力。

我们可以在熟悉 Apex 编程的技术团队成员的帮助下以编程方式实现这一点，或者我们可以使用 Flow。记录触发的 Flow 能够访问 Share 对象并对其进行更改。因此，你现在可以通过 Flow 单击即可授予或撤销用户的特定访问权限。

> **注意**
> 使用 Apex 共享的 Flow 与 Apex 代码无关。在 Flow 出现之前，我们可以通过点击以以下四种方式之一（OWD、角色层级、共享规则或手动共享）共享记录，另一种选择是使用 Apex 代码以编程方式共享记录。在创建 Apex 管理共享时，我们需要为各个自定义对象创建 Apex 共享原因，以指示如何以及为何对记录实施共享。Flow 使用与 Apex 代码相同的功能，我们正在将相同的 Apex 共享原因重新用于 Flow 和 Apex。

## 探索真实业务场景

业务需求是创建用于捕获客户敏感数据以进行验证的功能。由于数据的高度敏感性，我们希望将访问权限限制为联系记录所有者和客户记录所有者。

业务需求如下：

- 你的业务需要一个对象来跟踪联系人的敏感信息，例如他们的税务 ID、出生日期、密码和签名验证图像。
- 只有联系人所有者和客户所有者才能访问这些记录。
- 如果联系记录的所有权发生变化，我们需要移除先前所有者的访问权限，并为新所有者启用访问权限。
- 联系人所有者将获得读/写访问权限，而客户所有者将获得只读访问权限。对于此场景，我们假设联系人和客户所有者不是同一个人。
- 借助 Flow，你将能够无需编码即可启用此动态共享功能。

有了这些业务需求，我们首先需要一个计划。从概念上端到端地映射此过程。以下是我们为满足此业务需求所需采取的步骤：

1. 创建一个 Salesforce 对象（添加一个标签页并将其分配给一个应用程序，以便有访问权限的用户可以访问记录）。
2. 创建一个 Apex 共享原因。
3. 将之前创建的对象设置为私有。
4. 在此新对象上创建一个记录触发的 Flow：
   - A. 与旧所有者取消共享。
   - B. 与新所有者共享。
5. 保存并激活你的 Flow。

让我们通过截图详细查看这些步骤。

### 步骤 1 – 创建 Salesforce 对象

这是保存联系人敏感信息记录的对象。

要在 Salesforce 中创建新对象，请转到 设置 | 创建 | 对象 | 新建自定义对象。

我们创建了一个新的自定义对象，其标签和字段如下所列。根据需求，此自定义对象保存敏感信息，并且只应与联系人和客户所有者共享：

- 自定义对象标签 = **联系人敏感信息**
- 自定义字段：
  - **联系人姓名**
  - **联系人敏感信息名称**
  - **出生日期**
  - **密码**
  - **签名验证图像**
  - **税务 ID**

通过 OWD 将自定义对象设为私有将创建一个名为 `<Custom Object>__Share` 的共享对象。在我们的场景中，它将是 `Contact_Sensitive_Info__Share`。

`<Object>__Share` 对象在 Salesforce UI 中不可见；我们需要通过开发者控制台访问它们。参见图 7.4。

![](img/0c5ea2dc593e6f900cb4283ebfb6bf02_105_0.png)

图 7.4 – Contact_Sensitive_Info_Share 对象 – 此表中的用户可以访问记录

要打开开发者控制台，请单击右上角的齿轮图标并选择开发者控制台。在查询编辑器中，我添加了以下查询以查看 Contact_Sensitive_Info__Share 对象的结果：

```sql
SELECT Id, ParentId, UserOrGroupId, AccessLevel, RowCause FROM
Contact_Sensitive_Info__Share
```

我们的 Apex 共享原因标签将捕获在 RowCause 字段中。这样，技术团队成员就可以识别与用户共享记录的原因。

### 步骤 4 – 在新对象上创建记录触发的 Flow

要创建记录触发的 Flow，请按照以下步骤操作：

1. 转到 Flow 并创建一个新 Flow。
2. 然后，在标签为“联系人敏感信息”的对象上创建一个记录触发的 Flow。
3. 接下来，添加一个决策元素，以判断现有记录是已更新还是新记录。
4. 添加一个删除记录元素，以从 Contact_Sensitive_Info__Share 对象中移除共享。在此步骤中，我们与旧所有者取消共享。
