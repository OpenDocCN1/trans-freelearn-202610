# ### 同时查询文件系统和 Drupal 插件

可以在同一个查询中查询两个内容源，这在构建包含来自不同来源的内容的列表页面时非常有利。

我们的查询将包含属于两个插件的调用和字段。我们将得到一个单一的响应，其中包含来自两个来源的结果，按其根名称分隔。在这种情况下，Drupal 内容将包含在 `allNodeArticle` 数组下，而文件系统内容将包含在 `AllMarkdownRemark` 数组下。

正如我们已经看到的，我们可以前往 `http://localhost:8000/___graphql` 并运行以下查询：

```
query MyQuery {
  allNodeArticle {
    edges {
      node {
        title
        body {
          value
        }
      }
    }
  }
  allMarkdownRemark {
    edges {
      node {
        frontmatter {
          title
          date
          excerpt
        }
        html
      }
    }
  }
}
```

此查询将返回以下结果：

```
```
{
  "data": {
    "allNodeArticle": {
      "edges": [
        {
          "node": {...}
        }
      ],
    "allMarkdownRemark": {
      "edges": [
        {
          "node": {...}
        }
      ]
    }
  }
}
```
```

正如我们所见，我们在同一个查询结果中同时获得了来自 Drupal 和文件系统的两个不同来源的内容。

# React 组件

Gatsby 在底层使用 React，因此可以利用 React 的所有功能。React 组件大多是一个返回某些内容的 JavaScript 函数。通过利用 GraphQL，开发人员可以使用 Gatsby 的源插件将数据传递到页面。属性通常发送到组件，然后事件向上传递。这些模式——props 向下，事件向上，或数据向下，动作向上——在多个 JavaScript 框架中使用，并且非常容易理解。一旦创建了 React 组件，它可以被导入到另一个组件中以便轻松重用。

# 标签约定

如前一节所述，一旦创建了组件，就可以在 Gatsby 中像使用自己的 HTML 标签一样调用或使用它，因此对于熟悉 HTML 标签工作的人来说使用起来很熟悉。这对于可读性很有用，因为输出看起来像 HTML 而不是 JavaScript 代码。使用 React 组件的约定是将组件名称封装在 HTML 标签中。它必须以大写字母开头。

为了说明这个概念，例如，如果我们有一个名为 books 的组件，我们可以按如下方式将其包含在项目中：

```
<Books />
```
