### 为什么选择 GROQ？

数据存储是定义 Sanity 的最重要部分。Sanity 是为结构化内容而构建的，其丰富程度超过简单的二维表格。同样，GROQ 旨在比用于查询数据库的传统 SQL 更强大且更易用。GROQ 代表图导向查询语言（Graph Oriented Query Language），因此，正如名称所暗示的那样，它是一种用于查询图的语言，而图能够表示更复杂的数据结构。

GROQ 有四个主要特性：

- **富有表现力的筛选：** 这允许我们使用可读的语法构建查询。如果我们正在查找名为 Will's Pub 的场所，那么我们只需使用以下表达式，它等同于：类型为场所且场所名称为 Will's Pub：

  ```
  _type == "venue" && name == "Will's Pub"
  ```

- **连接（Joins）：** GROQ 可以连接多个文档，并将结果组合在一起。
- **整形（Shaping）：** 你可以决定包含哪些内容字段，或者重命名字段名称，重新格式化结果数据结构，甚至可以使用父文档的值在投影内进行额外的筛选。

  尽管这种获取信息的方式对于许多熟悉 SQL 数据库的数据库开发人员来说是一种相当大的范式转变，但随着经验的积累，GROQ 可以变得非常容易使用。此外，由于 GROQ 是开源的，所有代码都可以被检查。
- **简洁性：** 与标准 SQL 相比，GROQ 更简洁，冗词更少。在大多数情况下，语法更简练——就像 ES6 比 ES5 更简练一样。

### GROQ 与 SQL

GROQ 的简洁性使用初始星号表示`选择所有文档`，而在标准 SQL 中默认选择的是单个表。虽然 SQL 是一种传统的关系型数据库，这意味着你需要预先决定数据库的结构，并将其划分为表。在存储任何数据之前，程序员必须定义表、列名以及该表内列的类型。当向关系型数据库添加数据时，程序员必须以每列声明的格式传递数据；任何多余的数据或不匹配格式的数据都不会存储在数据库中。

Sanity 的内容模型是一个无模式数据库，这意味着你不需要定义表和列。系统以键/值对或 JSON 的形式存储数据，基本上是一列的表。程序员能够将任何格式的数据添加到数据库中，更改现有数据，例如从布尔值改为字符串，并在不声明新列的情况下添加新的数据类型。

现在让我们探索查询 SQL 和 GROQ 时的差异：

| SQL | GROQ |
| --- | --- |
| `select * from table;` | `*` |
| `select * from content_table where type="movie";` | `*[_type == "movie"]` |

传统的基于 SQL 的数据库查询应包含以下语法：

```
select * from table;
```

让我们看看 GROQ：

```
*
```

```
"name": "IT Conference",
"venue": {
  "_ref": "65929c5e-f2df-4483-b2e4-4f10a654adf8",
  "_type": "reference"
},
1: { ... },
2: { ... }
]
```

请注意，结果被包裹在 `result` 中。它们由基于零的数组表示，共有三个结果，因此是 0、1 和 2。

请注意，id 是一个通用唯一标识符（UUID）。这使得文档在整个数据集中都是唯一的，这与数据库表索引不同，后者从 1 开始索引，且仅在单个表内唯一。

`_rev` 键是该文档修订版或版本的标识符。

由于 `venue` 是相关文档，`_ref` 是对该文档 `_id` 的引用。请注意，`venue` 是嵌套的，并且代表一个完整的文档。

### 选择所有即将举行的活动

在此查询中，我们将通过添加 `dateAndTime` 条件来选择所有即将举行的活动：

```
*[_type == "event" && dateAndTime >= now()] | order(dateAndTime asc)
```

我们使用 `now()` 函数传递当前日期值，该函数返回当前日期。我们也可以将 `dateAndTime` 值作为 YYYY-MM-DD 格式的字符串传递。

我们还按日期对结果进行排序。我们将显示所有即将举行的活动，从最近的活动开始。

### 选择所有过去的活动

对于即将举行的活动，我们使用 `now()` 函数获取当前日期值，并获取所有过去的活动：

```
*[_type == "event" && dateAndTime < now()] | order(dateAndTime asc)
```

它将按日期对结果进行排序，从最近的活动开始。

### 选择即将举行的虚拟会议和非虚拟会议

我们之前的查询按日期返回了所有活动，但并未按虚拟会议字段进行筛选。我们在活动模式中的虚拟会议字段是一个布尔值。我们可以向 GROQ 查询添加条件，如果活动是虚拟的则设置 `virtual == true`，如果活动不是虚拟的则设置 `virtual == false`：

- 选择虚拟活动：

  ```
  *[_type == "event" && dateAndTime >= now() && virtual == true] | order(dateAndTime asc)
  ```

- 选择非虚拟活动：

  ```
  *[_type == "event" && dateAndTime >= now() && virtual == false] | order(dateAndTime asc)
  ```

我们已经看到了如何从数据集中选择所有字段。接下来，我们将学习如何选择特定字段以减小结果的大小。

### 选择特定活动字段

结果取决于我们在哪里显示内容。我们可能不需要所有字段，而只需要某些字段。通过此查询，我们仅获取所有即将举行的活动的 `name`、`dateAndTime` 和 `body` 字段。

我们在投影中传递字段名称：

```
*[_type == "event" && dateAndTime >= now()] | order(dateAndTime asc) | {name, dateAndTime, body}
```
