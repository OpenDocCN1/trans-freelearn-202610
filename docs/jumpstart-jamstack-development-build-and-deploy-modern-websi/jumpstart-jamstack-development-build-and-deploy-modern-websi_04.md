## Jamstack 的历史

欢迎来到 **Jamstack**。这种全新的 Web 开发范式激发了信息技术行业的兴奋，并变得越来越流行，不断有围绕它成立的新公司。本书是少数专注于 Jamstack 实用和动手经验教程之一。

在本章中，我们将首先回顾 Web 的历史，介绍 Jamstack，并讨论其优势。为了了解 Jamstack 如何演变为今天的样子，我们需要回顾超过二十年的万维网历史。Web 设计和 Web 开发，这两个从万维网演变而来的主要行业，发展成了两个非常流行且利润丰厚的职业，但情况并非总是如此。

## Jamstack 的演变

通过查看万维网的演变，从其最核心的组件 **超文本标记语言 (HTML)** 开始，可以很容易地解释 Jamstack 的演变。

## HTML

最初的网页仅由带有 HTML 标签的文本组成，提供标记指令并具备将页面链接在一起的能力。事实上，普通人常误以为 HTML 是一种编程语言，但从根本上说，它只是一系列代表格式指令的符号。它仍然被包含在编程语言列表中，与 C 和 Java 等实际编程语言并列。尽管它迅速演变，现在包含了可访问性和语义功能，但它仍然仅仅是一种标记语言。这意味着它不过是标记而已。然而，在其最早版本中，它只提供一般的格式说明。

例如，我们可以使用 h1 标签来表示页面的页眉，这会使文本显得更大，或者使用 bold 标签使文本加粗。每个页面由文本、链接和 HTML 标签组成。

以下代码片段提供了这样一个示例：

```html
<html>
<head>
<title>My Webpage</title>
</head>
<body>
<h1>Welcome to my webpage.</h1>
</body>
</html>
```




随着网站上的网页数量增长，每周甚至每天的任务都涉及手动更新多达 50 个页面。每当需要在网页的共享部分（如页眉、页脚或导航窗格）进行更改时，这些重复的操作被证明相当繁琐。

让我们研究一下为此问题设计的一些解决方案。

### 服务器端包含

一种试图补救这种重复手工工作的方法被称为 **服务器端包含**，或 **SSI**。该标记元素被创建以允许网页设计师包含页面的片段（例如页眉），而无需重复内容和标记。然后，在页面生成时，该标签将被替换为产生的 HTML 输出。

例如，网页上的三个链接，Home、About Us 和 Contact Us，将具有以下标记：

```
<a href="home.html">Home</a>
```

```
<a href="about_us.html">About Us</a>
```

```
<a href="contact_us.html">Contact Us</a>
```

此 HTML 可以放在名为 navigation.ssi 的文件中。包含将按如下方式调用：

```
<!--#include virtual="navigation.ssi" -->
```

在 Web 服务器处理之后，页面上显示的结果与前面的示例所示相同。接下来，又使用了另一种类似的方法来允许生成动态内容。

### 通用网关接口

**通用网关接口** 或 **CGI**，允许用 Perl 等语言编写的程序包含在网页中，提供附加功能，例如页面计数器。HTML 页面中调用此代码的实际位置再次将被替换为产生的 HTML 输出。

一个计算页面访问者数量的 Perl 脚本被放置在 cgi-bin 目录中并按如下方式调用：

```
<p>This page has been visited
```

```
<!--#exec cgi="/cgi-bin/counter.pl"--> times.</p>
```

这将在网页上产生以下结果：

```
`<p>This page has been visited 5349 times.</p>`
```

数字 5349 由此代码产生并显示在页面上。

### 表单

Web 开发历史中另一个重要部分是 **表单**。表单允许简单的网页转变为实际的 Web 应用程序。Web 表单复制了桌面应用程序中传统表单的功能。Web 表单还使终端用户，而不是网站管理员，能够添加内容——例如，在论坛中，使用提交表单。

在网站的公开部分，这些表单的提交随着网站规模的快速增长而增加了更多内容。网站很快就有效地成为软件应用程序，而不仅仅是带有标记的文件集合。很快，除了提供简单的页面之外，Web 服务器模块被创建来预处理整个页面作为程序。

### 网页预处理器

现代 Web 开发演进的另一个有趣部分是使用整个页面预处理器的能力，例如 PHP。事实上，这种语言递归地称为 **PHP: Hypertext Preprocessor**，解释了它所做的工作。这些文件具有不同的文件扩展名，Web 服务器（如 Apache）可以将整个页面作为实际程序进行处理并输出为 HTML 标签和内容。

接下来，让我们进入现代时代：**内容管理系统（CMS）。**

### 内容管理系统

很快，MySQL 等数据库被包含在经济实惠的 Web 主机计划中，以便网站管理员可以轻松使用它们。可以查询数据库表，结果将丰富并为许多动态生成的页面增添意义。这为第一个 CMS 奠定了基础。

通过允许网站管理员和历史上称为 *webmasters* 的人管理数据库中的内容，*dashboards* 或 *control panels* 被创建。这些管理工具是与实际网站完全分开的基于 Web 的软件应用程序，允许网站内容从网站本身轻松创建、编辑和删除。

再次，这导致网站在规模和复杂性方面迅速增长。

### WordPress

**WordPress** 迅速成为使用最广泛的 CMS。扩展 WordPress 功能的插件集合被开发出来，任何人都可以开发和安装插件。这意味着在任何时候，WordPress 网站可能同时安装了数百个不同的插件。

其中大多数由雄心勃勃的志愿者维护，新功能被快速添加。这种现象导致了快速的发布周期，并且每个插件同时使用许多不同版本。

### Ajax

另一个主要创新是 Ajax 的创建，或 *Asynchronous JavaScript and XML*。Ajax 允许页面从远程源获取信息，然后使用结果更新该页面的内容、布局或样式，而无需重新加载页面。这种 *instant update* 使仍需要重新加载页面的网站显得笨重缓慢。网站再次缓慢演变为更接近成为软件应用程序，类似于桌面应用程序或单页应用程序。

### JavaScript 框架

随着这种动态页面操作的复杂性增长，**JavaScript 框架** 诞生了。这些有助于减少开发时间并强制执行最佳实践。它们还提供了可以在尽可能多的浏览器版本中发挥功能的 JavaScript 代码。仍有高达 100 种变体的浏览器，如 Internet Explorer、Firefox、Opera 和 Google Chrome 运行在台式电脑、平板电脑和移动设备上。

### 云的兴起

随着网络的普及，Web 主机成本下降。非常低成本的 Web 主机可用性迅速增加，因为许多公司进入了市场。网站托管公司和云提供商看到了这一机会，使几乎任何技术技能很少的人都能以非常低的成本创建网站。

正如历史所表明的那样，就像汽车一样，有时最好的发明也会带来许多问题。就像汽车的发明和演变导致了碰撞、交通堵塞以及安全和安全问题一样——网站也是如此！由于互联网上大多数网站是由业余爱好者创建并托管在安全性不足的服务器上，服务器上的漏洞很快被发现然后被利用。

使用过时或不安全的 WordPress 插件、不安全的 JavaScript 以及 Web 服务器的一般错误配置的组合，被入侵的网站随后可被用于通过利用 **简单邮件传输协议（SMTP）** 发送垃圾邮件。这些利用者将电子邮件地址和电子邮件内容插入数据库表，然后以自动方式每小时发送数千封电子邮件，希望说服人们花钱。通过限制用户可以访问服务器上的哪些工具、锁定目录、不允许重复登录尝试以及其他技术来确保服务器安全，以减少安全风险。

然而，确保网站的所有插件都是最新的开销很快变得难以承受。诸如某个插件的版本 3.12.26 与另一个插件的版本 6.8.14 不兼容的情况变得司空见惯。网络慢慢变得像西部荒野一样！

### 高速访问

随着高速互联网变得普遍，连接速度增加到家庭电脑上接近 50-100 **兆比特每秒（Mbps）**，通过 **数字用户线路（DSL）** 和有线互联网。网页设计师在单个网页上放置的信息量、图像、媒体文件、JavaScript 以及任何其他内容方面获得了更大的自由度。这导致了以前快速加载的网站变慢。

此外，页面需要多个步骤才能实际动态生成。实时运行的代码和数据库查询需要在每个请求上进行解释。由于交付单个网页所需的步骤太多，页面时间变慢了。正如历史所示，新的解决方案总会出现以解决新问题。这个解决方案被称为 **Jamstack**。

让我们开始剖析它是什么。

### Jamstack 的兴起

Jamstack 代表了 Web 设计初期所有美好的东西，以及现代 Web 开发所有美好的东西。静态站点生成，有时也称为静态站点生成，简单地意味着生成一个由页面组成的网站，这些页面本质上只是文件，仅此而已。没有后端预处理器，也没有数据库，所有的服务器复杂性都被抽象掉了。





## Jamstack 缩写词解析

Jamstack 缩写代表 **JavaScript, APIs, 和 Markup**。由于静态站点页面无法通过任何实时预处理生成，页面的所有动态方面都必须通过 JavaScript 实现，JavaScript 将执行所有页面交互。

JavaScript 将使用 **应用程序编程接口 (APIs)** 与外部系统（如搜索引擎）通信。使用 API 是一种现代方式，可以利用预先构建的外部 **软件即服务 (SAAS)**，例如 Algolia 的搜索 API，或使用另一个原本会与静态站点位于同一服务器上的软件应用程序。将通信限制在 API 中可使较大系统中的每个组件保持独立且可重用。

最后，Markup 代表页面本身。如前所述，HTML 是一种用于创建网页的语言。有时，Markdown 会被错误地用作 Markup 的替代。Markdown 实际上是用于生成标记的一种记法之一；然而，生成标记的方式有很多种。

## Jamstack 优势

现在，让我们来了解 Jamstack 的优势。

### 速度

如前所述，静态页面的优势之一是每个页面实际上都是文件系统上的一个文件。如网页设计的早期一样，每个文件都通过 Web 服务器加载。唯一的瓶颈是访问文件、读取它，然后通过 Web 服务器发送其内容的速度。

**内容分发网络 (CDN)** 是一个遍布全球的众多服务器网络。这意味着页面将从距离网站用户最近的服务器进行最优提供，从而降低网络延迟。这为终端用户提供了整体更快、更好的体验。

所有的 **层叠样式表 (CSS)** 和 JavaScript 通常都会被压缩或以一种方式进行最小化，该方式会删除不必要的字符、空格、制表符、换行符和其他非必要项。使用最少的字符并将其组合到一个或多个文件中，以减少涉及的文件数量。

未压缩的 JavaScript 看起来像这样：

```
<javascript>
function multiplyTwoNumbers(number1, number2) {
return number1 * number2;
}
var result = multiplyTwoNumbers(2, 3);
</javascript>
```

压缩后的 JavaScript 看起来像这样：

```
<javascript>
function a (b, c) {return b*c;} var d=a (2, 3);
</javascript>
```

### 更不易出错

大多数 Jamstack 系统都有一个构建过程，该过程会在构建页面的过程中检查所有 HTML、JavaScript 和 CSS 的正确性，因此严重的编码错误会导致构建失败，不会让错误进入生产环境。

### 安全

使用安全的 **超文本传输安全协议 (HTTPS)** 而不是旧的 **超文本传输协议 (HTTP)** 意味着所有传输的信息都是安全的，因为它从端到端都是加密的。

此外，由于静态页面通过 *无服务器* 主机服务提供，因此没有任何后端系统或数据库被入侵的可能。不再需要花费宝贵的时间来保持服务器、库、登录访问和邮件服务的安全并始终保持最新版本，甚至也不必担心各种版本之间的冲突。

### 开发者体验

在 Jamstack 中开发意味着使用流行的现代编程语言，例如 JavaScript、TypeScript 和 **ECMAScript 6 (ES6)** 变体。Jamstack 开发者还可以利用现代查询语言如 GraphQL，以及 ReactJS 和 VueJS 等库和框架。他们还可以使用 Hugo 和 GatsbyJS 等静态站点生成器。

## 我们的 Jamstack

到目前为止应该很清楚，Jamstack 并不是一个技术栈，而是一种 Web 开发范式。可以随意使用 Jamstack 生态系统中各种组件的任意组合。对于本书，我们将使用三种最流行的软件应用程序和服务来制作一个 Jamstack 网站：GatsbyJS、Sanity.io 和 Netlify。我们还将提供几个示例，使用其他 Jamstack 工具进行比较。

### GatsbyJS

Jamstack 中最受欢迎的部分之一，实际上是一个静态站点生成器，就是 GatsbyJS。

**GatsbyJS**（称为 Gatsby）是开源的，并使用 React JavaScript 库从各种来源编译和构建静态页面。这些来源可能简单到文件系统；一组 Markdown 文件；传统的 CMS 如 WordPress 或 Drupal；或无头 CMS 如 Contentful 或 Sanity。

### Sanity.io

由于 *Jamstack 方式* 的 Web 开发摒弃了单一的单体 CMS，网站所需的实际内容与将对其进行格式化和交付的工具是分开的。

**Sanity.io**（称为 Sanity）是一个结构化内容平台。有一个名为 Sanity Studio 的开源 CMS，它使内容生产者如作家、编辑和摄影师能够轻松创建灵活且模块化的丰富内容，而无需理解编程和标记语言。

### Netlify

网站的实际 *托管* 将在无服务器系统上完成。

**Netlify** 是一项服务，使开发者能够享受完全自动化的编译和部署到 Netlify 的 CDN 上，快速安全地将内容推送到世界各地的服务器。

## 开始使用 Jamstack

现在我们已经了解了 Jamstack 的历史及其优势，接下来我们将查看在本书记述的上下文中使用 Jamstack 所需的工具。

### 安装

为 Jamstack 开发环境安装所有组件并配置一切正常运行对新技术开发者来说会令人望而生畏，因此最好的方法是参考每个组件的网站以获取最新的安装和配置文档。

本书附带一个 GitHub 仓库，其中包含执行所有示例所需的所有代码。因此，首先需要安装的是 Git 版本控制系统。对 Git 不熟悉的用户会发现大量信息、速查表和帮助论坛，但大多数基本操作只需四五个命令即可完成。许多代码编辑器，如 WebStorm，已将命令内置到用户界面中。

为确保安装过程是最新的，提供仓库中的 README.md 文件将提供安装说明和指向每个项目当前文档的链接。

## 先决条件

为了使用本书中的示例，需要几种 Web 开发工具，列于此处：

- Terminal
- Node.js 和 **node package manager** (`npm`)
- Git
- 一个 **集成开发环境** (**IDE**) 或文本编辑器

需要 Terminal 环境来执行命令。应使用哪个 Terminal 应用程序将取决于所使用的操作系统。

Node.js 允许在 Terminal 中运行 JavaScript，而不仅仅是在浏览器中。

npm 对于 Sanity 和 Gatsby 的安装是必要的。这允许安装许多由 JavaScript 功能组成的包。

Git 命令行版本控制系统对于 Gatsby 的安装至关重要，也用于下载本书中的示例。

最后，需要一个提供代码语法高亮和代码检查的 IDE，该检查会持续分析代码的正确性。如果不可能，则需要一个文本编辑器来修改源代码文件。截至本文撰写时，Visual Studio Code 和 WebStorm 是两个流行的 IDE 选择。
