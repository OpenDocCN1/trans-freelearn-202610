## 了解 Hyper

在本节中，我们将探索 Tableau 的数据处理引擎，以及它如何在企业中实现结构化且有机的数据挖掘过程。自 Tableau 10.5 发布以来，我们可以使用 Hyper——一种高性能数据库，让我们能比以往更快地查询源数据。即使是高级开发人员，通常也不太了解 Hyper，因为它不是日常活动中显而易见的一部分；然而，如果您想真正掌握如何为 Tableau 准备数据，这种理解至关重要。

Hyper 最初于 2008 年在慕尼黑大学作为一个研究项目启动。2016 年，Tableau 收购了它，并将其设立为 Tableau 专门的数据引擎团队，保留其在慕尼黑的基地和员工。最初在 Tableau 10.5 中，Hyper 仅针对提取替换了早期的数据处理引擎。实时连接仍不受 Hyper 影响，但 Tableau Prep Builder 现在也运行在 Hyper 引擎上，未来将有更多用例。正如 [tableau.com](http://tableau.com) 所述：“*Hyper 可在几秒内对海量数据进行切片和剖析，您将看到查询速度最高提升 5 倍，提取创建速度最高提升 3 倍*。”如果您还想了解更多，还可以通过 API 调用在您偏好的编程语言中使用 Hyper：[https://help.tableau.com/current/api/hyper_api/en-us/docs/hyper_api_reference.html](https://help.tableau.com/current/api/hyper_api/en-us/docs/hyper_api_reference.html)。

但是什么让 Hyper 如此之快？让我们揭开它的面纱一探究竟！

### Tableau 数据处理引擎

Hyper 创始人的共同愿景是创建一个高性能的下一代数据库——一个系统、一种状态、无妥协、无延迟。他们做到了——如今，Hyper 可以同时服务于通用数据库用途、数据摄取和分析。

内存价格呈指数级下降。CPU 也是如此；晶体管数量遵循摩尔定律增长，而其他特性却停滞不前。内存变得便宜，但处理能力仍需提升。

摩尔定律是英特尔联合创始人戈登·摩尔提出的观察：芯片上的晶体管数量每两年翻一番，而成本减半。关于摩尔定律的信息可在 Investopedia 上找到：[https://www.investopedia.com/terms/m/mooreslaw.asp](https://www.investopedia.com/terms/m/mooreslaw.asp)。

在试验 Hyper 时，创始人发现手写的 C 代码比任何现有的数据库引擎都快，因此他们想到将 Tableau 查询转换为 C 代码并同时优化，所有这些都在后台完成，Tableau 用户不会察觉。这种转换和优化是有代价的；传统数据库引擎可以立即开始执行代码。Tableau 需要先将查询转换为代码，优化代码，再编译为机器代码，然后才能执行。关键问题是：它仍然更快吗？正如 Tableau Public 和其他工作簿上的许多测试所证明的，答案是肯定的！

此外，如果预估某查询在不编译为机器代码的情况下执行会更快，Tableau 拥有自己的**虚拟机**（**VM**），查询将在其上立即执行。除此之外，Hyper 可利用 99% 的可用 CPU 算力，而其他并行进程只能利用 29% 的可用 CPU 算力。这归功于独特创新的碎片驱动并行化技术。

想了解更多关于碎片驱动并行化信息的读者，可以在 [https://15721.courses.cs.cmu.edu/spring2016/papers/p743-leis.pdf](https://15721.courses.cs.cmu.edu/spring2016/papers/p743-leis.pdf) 找到一篇论文，该论文后来成为 Hyper 引擎的基础。

如果您想了解更多关于 Hyper 引擎的信息，我强烈推荐观看以下视频：[https://youtu.be/h2av4CX0k6s](https://youtu.be/h2av4CX0k6s)。

Hyper 将传统数据仓库操作的三个步骤并行化：

*   事务和**持续数据摄取**（**联机事务处理**，或 **OLTP**）
*   **分析**（**联机分析处理**，或 **OLAP**）
*   **超越关系**（**联机超关系处理**，或 **OBRP**）

同时执行这些步骤使 Hyper 更高效、性能更强，这与传统系统将这三个步骤分离并依次执行形成对比。
