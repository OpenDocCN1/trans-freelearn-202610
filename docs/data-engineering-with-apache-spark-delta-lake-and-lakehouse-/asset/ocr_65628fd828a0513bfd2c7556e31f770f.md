Notice the use of the template file and parameter files in the deployment script. The paths for template and parameter files are sent as arguments to this script. +   3. It's the moment of truth. Invoke the following command in Azure Cloud Shell and watch it roll. The script will spin up the entire infrastructure in a matter of minutes. This is the magic of IaC. Make sure you replace the value of <HOME_DIR> in the following command as per your environment:

```
IAC_ENVIRONMENT=prod
HOME_DIR_PATH=<HOME_DIR>
sh Data-Engineering-with-Apache-Spark-Delta-Lake-and-Lakehouse/project/infra/electroniz_isc.sh IACRESOURCEGROUPNAME=elz_prod RESOURCEGROUPNAME=elz_prod LOCATION=eastus TEMPLATE_FILE_PATH=$HOME_DIR_PATH/Data-Engineering-with-Apache-Spark-Delta-Lake-and-Lakehouse/project/infra PARAMETERS_FILE_PATH=$HOME_DIR_PATH/Data-Engineering-with-Apache-Spark-Delta-Lake-and-Lakehouse/project/infra/parameters/$IAC_ENVIRONMENT
```

Notice the use of the IAC_ENVIRONMENT and PARAMETERS_FILE_PATH arguments in the preceding command can enforce the reusability aspect of the IaC scripts. To build multiple environments, you simply need to create one folder per environment in source control and reference it in the preceding command.
