In addition to all of the functionality that the BDC provided, BCS provides the ability to write to data sources as well. This allows us to leverage SharePoint's User Interface to modify the data in other systems such as ERPs and CRMs. In addition to writing via Database connections, we can also write to .NET objects and Web/WCF Services. In many Database Scenarios, we can get away with these types of functions without writing any code. Interacting with .NET objects and Web Services will in all likelihood involve some code to be written.

# Determining the right solution

So how do we know which approach to take? It really comes down to architectural direction from within our own organizations. If one of our architectural tenants includes reducing the amount of custom coding within our systems, then using BizTalk has a strong case.

If your organization is not adverse to custom coding and perhaps does not already have a BizTalk license, then using some of these other techniques outside of BizTalk has a lot of merit.
