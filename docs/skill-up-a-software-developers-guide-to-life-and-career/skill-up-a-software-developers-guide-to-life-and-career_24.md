## 第24章 避开银弹，打造可扩展的自由职业项目

一个代码库就能完成你签约承接的自由职业项目中的很大一部分工作，这种想法听起来是不是很诱人？没关系，你可以诚实地说“是”，无论你现在是活跃的自由职业开发者，还是将来会成为其中一员。

在我开始自由职业之旅时，每当我遇到一个大型功能需求，第一件事就是看是否有现成的代码库能满足这个需求。在开发领域，这类代码库被称为银弹。

然而，尽管让插件或代码库承担项目的大部分工作听起来很诱人，但根据我的经验，这种做法最终比从零开始构建这些组件还要耗时。

### 银弹的问题

我们先来看一个实际案例。几年前，我接了一个车队管理项目。需求清单包括以下功能：

- 对多个数据库表具备完整的CRUD能力
- 创建一个能够搜索每个数据库表各种属性的搜索引擎
- 能够使用筛选器下钻数据
- 以及与报表仪表板相关的若干其他项目

项目开始后，我开始研究能够充当银弹并处理关键功能的代码库。几天后，我遇到了一个名为 rails admin 的 RubyGem。这个 rails admin gem 非常强大。它包含的功能包括：



- 轻松查询数据库表
- 实现自定义过滤器以运行高级查询
- 导出记录到 Excel/CSV
- 从仪表板添加新记录
- 编辑/删除记录

正如你可能已经注意到的，这个代码库看起来与我当时项目的需求集合非常契合。

### 银弹式定制

我很快着手构建应用程序。并且将 rails admin gem 集成作为项目的基础组件。客户在演示期间非常兴奋。他们绝对喜欢这个应用程序，并且对我能如此快速地构建应用感到震惊。

那么，问题出在哪里？问题开始出现时，客户开始要求新功能。在试用应用程序几周后，他们提出了诸如以下的功能请求：

- 能够保存常用查询
- 导出到与他们的会计系统兼容的罕见文件格式
- 集成税务 API 以计算折旧

这些新功能对于车队管理系统来说都是相对常见的请求。只有一个问题。因为我围绕 rails admin 代码库构建了整个应用程序，所以我受限于 gem 提供的功能。而这是一个问题，因为 rails admin 事实证明难以修改。

事实上，经过数周的繁琐工作后，我得出的结论是，从头构建整个系统所需的时间比定制 gem 本身还要少。因此，最终结果是我浪费了大量时间，项目被延迟了，这一切都因为我以为某个单一的银弹代码库能够处理应用程序的很大一部分。

### 成为代码库的精准射手

那么，这是否意味着我建议你完全远离代码库？不，完全不是！自由职业之所以可行（对客户来说也负担得起）部分原因在于你不必从头创建应用程序 100% 的功能。

相反，我学会了在集成代码库时保持选择性。让我们看看我在项目中经常使用的几个代码库：

- **Pundit**，用于构建权限结构。Pundit 是一个轻量级代码库，易于定制，并且不会将你锁定在狭窄的权限功能集合中。
- **Devise**，用于身份验证。从头编写身份验证系统耗时耗力。Devise gem 允许 Rails 开发者快速集成注册、登录、注销等功能，以及诸如安全密码检索等高级组件。此外，Devise 是可定制的，我很少遇到它无法满足应用程序需求的情况。

你是否注意到这些代码库如何像特定功能的辅助库一样运作？我将代码库集成到项目中的规则是，我挑选出有助于项目小元素的包。而我避开那些承诺能处理项目功能大块部分但难以定制的银弹。
