## 第 57 章。如何练习编程技巧并提升作为开发者的能力？

无论你是编程新手还是已经从事多年，练习都很重要。你练习编程技能越多，你就会越好。你有多种练习编程技巧的选项。这些选项将帮助你提升技能并不断作为开发者进步。

### 参与结对编程

编程不必是孤立的活动。与其独自承担，不如参与结对编程。由于结对编程是人们在一台电脑上共同工作，因此它是学习不同解决问题策略和处理流程的好方法。只要你选择了合适的搭档，这种练习方式会让你迅速成为更好的程序员。

### 利用开源软件

开源软件是练习编程技巧的好方法。首先阅读各种开源项目的代码。这将帮助你理解程序员是如何打造如此成功的项目的。

然后，参与各种开源项目。在你工作的过程中，人们会给你即时反馈。偶尔听到批评可能很难接受，但它会帮助你精进技能，从而让你成为更好的程序员。

### 访问 Reddit 上的 DailyProgrammer 子版块

Reddit 是一个充满分享想法和互相帮助的人的社区。你可以通过 DailyProgrammer 子版块加入其中（[https://www.reddit.com/r/dailyprogrammer/](https://www.reddit.com/r/dailyprogrammer/)）。该子版块每周发布三个编程挑战。第一个挑战相对简单，然后难度会逐渐增加。社区会评审解决方案并提供反馈。利用这个子版块在享受乐趣的同时提升你的技能。

### 参加在线课程

有时你不需要重返校园来提升编程技能。**大规模开放在线课程（MOOCs）**是提升技能的绝佳方式。你可以按自己的节奏学习并练习需要改进的技术，而不会感到仓促。最棒的是，你可以在课程中获得反馈，这将帮助你成为更好的程序员。

如果你想学习如何最好地利用 Rails 框架，可以查看我的 *Professional Rails Course*（[https://www.udemy.com/professional-ruby-on-rails-coding-course/](https://www.udemy.com/professional-ruby-on-rails-coding-course/)）。

### 代码 kata

kata 这个术语最早由 *Dave Thomas* 在书中引入，*The Pragmatic Programmer*。他从武术中借用并将其应用于编程世界。要进行代码 kata，你需要取一个小的需求并创建代码。然后一遍又一遍地重复，改进它直到完美。这是一种在练习编码的同时让代码变得更好的简单方法。

### 总结

不要犯 ofs 的错误。之所以没有明确的答案，是因为开发本质上是一门艺术。因此，关于编程的这个问题与询问什么造就伟大艺术家类似。

### 成为伟大开发者的技巧

为准备本章，我询问了各种开发者，我阅读了博客文章，并收听了许多讨论该主题的播客。正如我所预料，成为一名伟大程序员的要素是广泛的。

在本章中，我想概述我发现最有效的流程和要求。以下六个特质概括了伟大开发者中发现的关键特征。我还包含了在日常工作中与这些属性配合使用的一些实用策略。

### 攻克困难功能

从最具挑战性的特质开始，我发现我作为开发者的进步唯一方式就是攻克具有挑战性的概念。

我发现自己令人不安地容易陷入一种例行公事中，反复执行相同的任务。我已经从事开发多年，因此我拥有一个我很 comfortable 构建的工具和功能库。

然而，我发现如果我只是不断构建我已经很 comfortable 创建的功能，我就不会成长为开发者。只有当我下定决心并致力于完成从未做过困难任务时，我才会变得更好。

要求攻克困难练习并不是仅与开发相关的概念。*Anders Ericsson* 和 *Robert Pool* 合著的书籍 *Peak* 研究了音乐、体育和几乎所有其他熟练职业中的巅峰表现者。研究结果显示，个人只有在攻克具有挑战性的概念时才会显示出进步。这意味着如果小提琴家每天演奏相同的音乐并且从不挑战自己，他们的技能就会停滞。

对开发者来说也是同样的概念。如果你想成为一名伟大开发者，你需要不断攻克困难主题。如果你不知道从哪里开始寻找具有挑战性的功能来构建，请访问你最喜欢的网站。你可以查看 Twitter、Airbnb 或 Pinterest。从那里你可以列出你从未构建过的先进功能。示例包括组件，如：无限滚动、异步通知或多页身份验证。

### 社区贡献

随着编程行业的增长，开源社区呈指数级扩张。世界上最流行的语言和框架，如 Python 和 Ruby，并非由公司创建，而是由对公共利益感兴趣的程序员创建的。

根据你的经验水平，社区贡献会差异很大。如果你是高级工程师，你可以构建一个开源代码库或为一种编程语言构建功能。然而，即使你几乎没有任何经验，你仍然可以贡献。新开发者可以帮助刚开始编码的其他人。




回馈开发者社区固然很好，但参与贡献也能带来巨大的益处。如果你正在构建一个其他开发者会看到的代码库，你很可能会格外小心，确保代码库经过充分测试且功能正常。这种开发方式会让你成为更优秀的程序员，并对你长远发展有所帮助。

### 艺术性

在开发过程中，很容易陷入项目日常的琐碎细节，而忘记编程的核心其实是一门艺术。代码要具有艺术性，就必须优雅；而要优雅，就必须简洁。我曾参与过的一些最优秀的项目，最终都拥有最直截了当的代码库。然而，编写简洁的代码并不像你想象的那么容易。Sandi Metz 曾这样评价简洁代码：

> “新手程序员还没有能力写出简洁的代码。”

爱因斯坦曾这样谈论简洁：

> “如果你不能向一个六岁孩子解释清楚，那说明你自己也没真正理解。”

这似乎是一个奇怪的概念。然而，如果你曾尝试构建一个保持易于理解的代码设计的复杂项目，你就会明白这是真的。作为开发者，你进步越大，你的工作就应该越直截了当。

### 工匠精神

工匠精神与艺术性密切相关，但有一个重要的区别。当你是一名工匠时，你会真正为自己的工作感到自豪。

多年来，我遇到过各种各样的开发者——从把每个项目都当作流水线上的零件来对待的程序员，到确保自己处理的每个代码文件都像艺术品一样的开发者。

就我个人而言，我发现将这两种概念结合起来最为有效。与许多其他概念一样，工匠精神并不局限于编程。从小到大，我的父亲——他曾是美国职业棒球大联盟的球员，现在是一名教练——一直教导我要拥有他所谓的“卓越精神”。这意味着无论我做什么或正在做什么，我都必须为之自豪。他会告诉我，如果我花时间去做一件事，那就不如把它做好。

虽然我觉得自己对自己的工作感到自豪，但工匠精神是我最难把握的概念之一。我觉得这一原则很有挑战性，因为很难在编写良好的代码和完美的代码之间找到平衡。正如俗话所说，*完美是伟大的敌人*。因此，确保你努力正确地设计你的代码库是很重要的。

然而，不要强迫自己追求完美。拥有“没有任何项目是真正完成”的心态也很重要。这意味着如果你试图达到完美，你会不断感到沮丧。这主要是因为你的代码库永远不会达到一个可以被视为“完成”的阶段。

#### 史蒂夫·乔布斯的工匠精神

说到工匠精神，很少有人能像史蒂夫·乔布斯那样对自己的工作抱有同样的自豪感。这是他对工匠精神的看法：

> “当你是一个木匠，正在制作一个漂亮的五斗柜时，你不会在背面用一块胶合板，即使它靠着墙，没人会看到。你知道它就在那里，所以你会在背面用一块漂亮的木头。为了让你晚上睡得安稳，美学和品质必须贯穿始终。”

——史蒂夫·乔布斯

### 适应变化

如果你参与过任何真实的代码项目，你可以证明唯一不变的真理就是：变化。伟大的开发者通过他们如何适应应用程序不断变化的需求来区别于新手。新程序员在应对变化时有两种常见的挣扎方式：

- *代码设计缺乏灵活性。* 这意味着当项目中添加新需求时，他们需要完全重新配置代码以支持额外的功能。
- *为错误的未来做规划。* 开发者可能对最终项目的样子有了一种心智模型，但这种预估很少与现实相符。想象一下，你正在构建一个会计应用程序，你认为客户最终会要求系统完全基于项目。你会根据你脑海中的工作流层级来做设计决策。然而，如果你错了，你将被迫重新配置整个应用程序。

这两种陷阱在编码之旅中都很常见。然而，一位伟大的开发者会在无设计和过早设计之间找到平衡。

通过构建结构良好的代码库，优秀的程序员编写的模块具有灵活的接口，能够适应变化。他们也理解项目需求会变化，并且他们编写的代码具有低耦合性。

这意味着应用程序中某个功能的更改应该对其他部分影响很小甚至没有影响。例如，回到会计应用程序，如果工资模块需要更改，不应该要求你重写人事管理功能。

### 不懈学习

最后，在回答“成为一名伟大的程序员需要什么？”这个问题时，我将讨论不懈学习的重要性。

实现你的开发目标的最重要因素之一是对知识的渴望。幸运的是，你对这一要求有100%的控制权。无论你作为程序员有多少经验，你永远不会达到一个可以停止学习的阶段。总会有改进的流程、新的框架和新的语言需要学习。

我问过一些与我共事的高级开发者，他们是如何组织学习方法的。他们给出了以下建议：

- *每年学习一门新语言或框架。* 这也意味着你在那一年里要构建一个生产级应用程序。跟着教程做并构建“Hello World”应用很容易。然而，当你创建一个真实的程序时，你会被迫解决具有挑战性的结构问题。
- *每天阅读多本书。* 我个人每天阅读十几本与开发相关的书。事实上，我在本书中讨论的许多主题都直接来源于我当时阅读的内容。
- *跟随高级教程。* 与我共事的许多开发者承认，他们更喜欢通过阅读其他程序员的博客来学习新的编码技术。网上有许多指南可供你学习，它们会教你如何在应用程序中构建高级功能。
- *订阅新闻通讯。* 我订阅了许多每周发送给我的新闻通讯，包括关于 Ruby、Rails 和 JavaScript 的通讯。这类通讯是了解语言变化的好方法。它们精选了来自网络的一些最佳博客文章和教程。

### 总结

我希望这是一个有帮助的章节，并能帮助你回答这个问题：“成为一名伟大的程序员需要什么？”
