

## 教程

过去几年里，在线教育领域呈指数级增长。无论你想学习 Java 还是 Ruby，你都能找到无数教程来帮助你理解编程。这些工具本身最不可能让你成为一名专业开发者，因为达到专业水平需要数年时间，通常还需要你在各种真实项目上实践。

然而，教程可以成为学习编程的绝佳入门方式。除了提供构建应用的分步指南外，屏幕录像教程也非常适合展示特定语言或框架能构建出何种类型的应用。当我学习一门新语言时，我会观看整套教程系列，甚至不尝试输入代码。我这样做是为了熟悉该语言的能力。

教程的一个弱点是，很难复制你的个人环境。例如，如果你正在学习几年前的一份 Java 编程语言教程，那么讲师使用的语言版本很可能与你不同。这会导致一些令人困惑的错误，而在没有帮助的情况下，许多人会因挫败感而放弃编程梦想。

但不要让这吓退你使用教程。我承认有许多教程帮助我自学开发。我也强烈推荐它们作为一个很好的起点，尤其是在你想从零开始学习如何编程时。

## 阅读

接下来是阅读。市面上的编程书籍数量多到足以填满图书馆。我甚至写过几本！

我喜欢阅读编程书籍，因为它们允许我按自己的节奏进行。当我观看视频教程时，通常意味着我每天需要抽出固定时间来观看视频。然而，有书的话我可以读几段，也可以读几章。当你有一份全职工作并且业余学习编程时，书籍是极好的资源。

这是因为它们允许你按自己的节奏学习。书籍在以后需要查阅特定主题时也很有用。此外，当你阅读编程书籍时，我强烈建议你编写并运行书中的代码。这会比单纯阅读更好地帮助你记住编程语言语法。

记住，大多数人的阅读记忆保留率极低。然而，如果你将阅读与在学习过程中实际编写代码结合起来，你会看到好得多的效果。

阅读编程书籍时另一个技巧是，在编写代码时不要看书。例如，如果你正在阅读我的 Ruby 编程书，你在学习如何使用面向对象编程时会看到代码片段。如果你强迫自己在整个过程中不看书就输入代码，你会发现你的记忆保留率会大幅提升。

## 真实项目

学习如何从零开始编程的最后一项是构建真实项目。在你完成了一些教程并阅读了几本书后，你就可以尝试动手构建应用了。

一个自然的问题是：“*我应该构建什么类型的项目？*”这个问题其实没有对错之分。如果你有一个商业想法，那么你可以尝试用你新获得的编程知识来构建它。

你也可以尝试重建现有应用，例如创建一个 Pinterest 克隆。我发现创建克隆网站这种技术非常有益，因为它让我专注于构建功能，而不必浪费时间去想点子。

例如，当我学习 Swift 编程语言时，我构建了一个 Instagram 克隆。很多年前，当我学习 HTML 和 CSS 时，我从零开始重建了 Google 首页。关于构建真实项目最重要的是要记住要挑战自己。没有任何开发者是通过复制他们已经很熟悉的功能来提升的。相反，确保你挑战自己实现从未创建过的功能。

## 编程很难

最后说一点，不要让任何人告诉你不同：编程很难！从设置开发环境到构建功能应用，编程在每个阶段都会给你带来挑战。

## 但你可以学习编程

然而话虽如此，你可以成为一名开发者。并没有天生的神奇程序员基因。归根结底取决于：

- 你有多坚定
- 你是否愿意持续工作
- 你在学习方面的策略有多好

## 第 48 章。如何选择开发者专长？

通过多年的培训开发者，我发现对程序员来说，决定自己的专长并专注于此至关重要。在本章中，我将与你分享我个人如何看待可用的不同开发者方向和专业领域。

你很可能在开发者职业生涯中不止一次做出这个选择，所以我建议你始终观察并意识到职业生涯中可以做出的选择。

### 如何选择开发者专长？

软件开发的世界如此庞大，以至于一个人不可能精通流程的每个方面。设想我走近一位世界级的田径教练并说我想为奥运会训练并在田径项目中赢得金牌。教练很可能会扫我一眼然后自嘲地笑。但之后他的第一个问题会是：*“你想训练哪个项目？”* 他会问这个问题，因为 100 码短跑的训练制度与跳高截然不同。

同样，作为一名开发者，你至少需要一次，很可能多次，缩小你的关注范围，确定未来几年你想成为什么类型的开发者。

我将带你了解每种开发者类别，以便你了解它们包含的内容。

### #3 – 前端开发者

在选择开发者专长时，第三层选择是前端部分。直到不久前，前端开发者被认为是一整天都在处理 HTML 和 CSS 的人。他们的主要目标是让应用看起来*漂亮*。

然而，随着客户端框架的出现，前端开发者的定义发生了巨大变化。这些框架，例如 Angular 和 React，使得前端程序员能够用很少的服务器端交互构建完整的应用。

这些应用完全在浏览器中渲染，因为它们是用 JavaScript 编写的。每当应用需要获取额外数据时，它只需与 API 通信。我常用的一个模式是构建多个服务器端 Ruby 应用，然后使用一个 Angular 前端应用在浏览器中渲染用户界面。

因此，如果你喜欢构建用户会直接交互的应用，并且不害怕与 API 合作，前端开发可能就是适合你的选择。
