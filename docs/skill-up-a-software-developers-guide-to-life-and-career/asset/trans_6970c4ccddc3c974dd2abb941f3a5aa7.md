

你应该已经对这份工作的薪资水平有一个大致的了解，如果你正在为它面试。你可以在它被提供给你之后再担心工资，当面试官认为你最优先考虑的是你将赚多少钱时，这从来都不是一件好事，因为他们会假设如果你另一家组织给你一个适度的加薪，你就会离开公司。

“期望我工作什么类型的时间？”

面试官和管理者讨厌这个问题！根据工作内容，你应该已经知道这一点。然而，你可以通过问类似“这个职位一个典型的工作日是什么样的？”这样的问题来重新表述这个问题。

最后，永远不要问“我的表现如何？”或“我有这份工作吗？”。问你表现如何听起来就像你在三年级刚完成拼写测试一样，并不能体现出多少自信。而如果你有这份工作，他们会告诉你。等待并在一周后跟进面试官，你将被视为一个成熟且经验丰富的候选人。

## Summary

我希望这篇指南对你有所帮助，并能帮助你制定在求职面试中提出最佳问题的策略。面试的许多方面在开始时是未知的，然而你始终有能力控制你提出的问题，因此提前准备好一份问题清单以便你在面试过程中保持一定的掌控力是很有益的。

## Chapter 63. Answering in an Impossible Interview

### Questions

你希望在面试中如何被问到这个问题：

> *“对 1 万亿个数字进行排序需要多长时间？”*

或

> *“在某一时刻天上有多少架飞机？”*

如果这听起来不像你的乐趣所在，你并不孤单，许多组织已经停止提问不可能或看似不可能的问题；然而，仍然有一些面试官喜欢问它们，所以我认为讨论这个问题会很有帮助。

首先，如果你被问到这些问题中的一个，面试官的首要目标并不是看你是否知道答案，而是观察你的解决问题的能力。通常，最好的方法是采取系统性的策略，以便你能展示出你有条理的思考过程。

### Answering impossible interview questions – case studies

让我们以第一个问题为例：“对 1 万亿个数字进行排序需要多长时间？”在你建立一个基准案例之前，这似乎是一项具有挑战性的任务，例如：“对 10 个数字进行排序需要多长时间？”

如果你了解算法，你很可能会选择使用排序算法，例如 Quicksort，因为它平均排序时间为 O(n lg n)，这将是 O(100 lg 100) 在用总整数数替换 n 之后。所以，实际上对 1 万亿个整数进行排序是微不足道的，因为它将是 O(1,000,000,000,000 lg 1,000,000,000,000)。

在这个问题中，面试官首先希望确保你了解流行的算法，并且你清楚地了解哪种算法适合该任务。

对于“在某一时刻天上有多少架飞机？”这是一个估算问题，实际答案根本不重要，相反面试官想看到你如何逐步分析问题以及你有多注重细节。

对于这个问题，我会先向面试官提出筛选问题，例如：是全世界的飞机还是仅美国的？这是否只包括商业飞机还是私人喷气式飞机和军用飞机？以及能表明你知道如何正确思考回答该问题所需每个参数的问题。

从那里将问题分解为子问题；例如，如果面试官说他们只想要美国空中商业飞机的清单，那么你可以开始估算每个机场每小时有多少航班起飞，设定航班的平均持续时间，等等。然后你可以将该基准案例乘以美国机场的估计数量，你就会得到你的估算值，更重要的是你会向面试官展示你已经思考过这个问题。

## Good answers to your greatest weakness

现在让我们看看在面试中关于你最大弱点的问题的一些很好的回答：

- *行动缓慢：* 这是一个有趣的回答，因为如果你就此止步，这可能是一个糟糕的回答，因为它可能会告诉面试官你很胆怯，这将是一个不良的性格特征。然而，如果你接着说你在开始一项任务之前非常注重细节，并且想要有一个明确的策略来推进，这正是我想要在我的团队中拥有的员工！
- *对自己过于苛刻：* 这会告诉面试官你在乎你的工作，并且做得好对你来说非常重要。确保跟进说明你如何改进自己，以便你仍然努力成为工作中的工匠，但不要为无关的原因责怪自己。
- *可以很安静：* 这是我最喜欢听到的事情之一，前提是个人接着说他或她可以很安静，因为他或她认为在给出答案之前倾听项目或挑战的所有细节很重要。这告诉我这个人会注重细节，并且不会因为太忙于思考接下来要说什么而错过关键项目。

我希望这些策略能帮助你回答“你的最大弱点是什么？”这个问题。祝面试顺利！

## Chapter 65. Enterprise Software Job Strategy and Guide

如果你是一名开发者，并且曾与初创公司或自由客户合作过，你会发现企业软件工作的世界在好和具有挑战性的方面都相当不同。

在 **enterprise software industry** 工作有一些优点，即大型组织通常稳定，有开发流程，并且允许你专注于特定功能，而不是必须涵盖软件功能的全部范围。

企业开发独有的一些挑战是，对于开发者来说通常有相当多的官僚程序。如果你习惯于能够抓取任何代码库并将其放入你的应用程序中，你会发现企业对你引入的外部库非常挑剔。例如，我就在几天前刚与一位企业软件开发者交谈，他表达了他的沮丧，因为他的公司花了两个月才允许他使用 jQuery 库，而 jQuery 是应用程序领域最常用的用户界面库之一。

那么申请企业软件工作时应该准备哪些类型的问题呢？

- 关于你如何与 **formal processes** 合作的问题。
  根据公司的正式程度，你很可能需要解释你如何与不同的项目管理流程合作，例如 Scrum、极限编程，以及诸如此类的流程。
- 在大型企业中，软件错误可能导致数百万美元的损失，因此 **testing systems** 通常相当彻底。考虑到这一点，请确保你准备好回答与单元测试和行为驱动开发相关的问题。
- 考虑到我们生活在一个 **Microsoft-based enterprise world**，拥有扎实的关于你如何理解与 Windows 服务器、Active Directory 以及诸如
SharePoint 等工具集成的方式的知识将非常重要。我个人曾被问到我将如何将 Active Directory **single sign on (SSO)** 集成到 Ruby on Rails 应用程序中，以及如何在 Windows 服务器上运行 Rails，在各种面试中。并且如果你了解 Rails 开发系统，你会知道这些根本不是标准要求。
- 与大多数开发职位一样，你还需要对该职位的 **technical skills** 有扎实的理解。这通常包括能够对与面向对象原则相关的问题以及流行算法的讲解给出准确的答案。

面试的技术部分很可能特定于工作。例如，如果你申请的是前端企业软件工作，他们可能不会问你关于 Quicksort 的问题，但他们会问你如何正确管理 JavaScript 回调。

## Summary

希望这四个方面的提问能帮助你准备并对申请企业软件工作充满信心，祝面试顺利！
