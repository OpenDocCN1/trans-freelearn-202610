### 银弹式定制

我很快着手构建应用程序。并且将 rails admin gem 集成作为项目的基础组件。客户在演示期间非常兴奋。他们绝对喜欢这个应用程序，并且对我能如此快速地构建应用感到震惊。

那么，问题出在哪里？问题开始出现时，客户开始要求新功能。在试用应用程序几周后，他们提出了诸如以下的功能请求：

- 能够保存常用查询
- 导出到与他们的会计系统兼容的罕见文件格式
- 集成税务 API 以计算折旧

这些新功能对于车队管理系统来说都是相对常见的请求。只有一个问题。因为我围绕 rails admin 代码库构建了整个应用程序，所以我受限于 gem 提供的功能。而这是一个问题，因为 rails admin 事实证明难以修改。

事实上，经过数周的繁琐工作后，我得出的结论是，从头构建整个系统所需的时间比定制 gem 本身还要少。因此，最终结果是我浪费了大量时间，项目被延迟了，这一切都因为我以为某个单一的银弹代码库能够处理应用程序的很大一部分。

### 成为代码库的精准射手

那么，这是否意味着我建议你完全远离代码库？不，完全不是！自由职业之所以可行（对客户来说也负担得起）部分原因在于你不必从头创建应用程序 100% 的功能。

相反，我学会了在集成代码库时保持选择性。让我们看看我在项目中经常使用的几个代码库：

- **Pundit**，用于构建权限结构。Pundit 是一个轻量级代码库，易于定制，并且不会将你锁定在狭窄的权限功能集合中。
- **Devise**，用于身份验证。从头编写身份验证系统耗时耗力。Devise gem 允许 Rails 开发者快速集成注册、登录、注销等功能，以及诸如安全密码检索等高级组件。此外，Devise 是可定制的，我很少遇到它无法满足应用程序需求的情况。

你是否注意到这些代码库如何像特定功能的辅助库一样运作？我将代码库集成到项目中的规则是，我挑选出有助于项目小元素的包。而我避开那些承诺能处理项目功能大块部分但难以定制的银弹。

## 第 25 章. 自由职业者管理高级功能的指南

每个自由职业者在某个时候都会遇到的问题是管理高级功能。而我所说的高级功能是指客户要求你构建你从未构建过的功能，当这种情况发生在你身上时。

注意我说的 *when* 而不是 *if*？那是因为每个自由职业者，无论多么有经验，都曾被要求构建他们从未创建过的事情。

### 管理高级功能

多年来，我被要求构建各种各样的功能。其中一些我有经验，其他的……就没那么多。一个很好的例子是几年前，当我被要求构建一个 GPS 跟踪 iPhone 应用时。客户希望跟踪他们在外勤的员工并允许他们远程提交工单。听起来是个好主意，对吧？我也这么认为。只是有几个问题：

- 当时，我还没有构建过任何移动应用程序，更不用说生产级应用了
- 我对实时 GPS 跟踪的经验极少

由于缺乏经验，我的第一反应是放弃这个项目。然而，客户是一家财富 500 强公司，当时我确实有长期计划来构建我的移动作品集。更不用说这份工作支付超过 10 万美元。考虑到这些因素，我接受了这个 offer。

### 总结

因此，当客户要求你构建一个你完全没有经验的功能时，我的建议是与该领域的专家合作。本章中我给出的例子专门针对自由职业者对构建功能几乎没有任何经验的情况。

也有我被要求构建一个我有经验的功能，但我不愿承诺构建生产级应用程序的情况。在那些情况下，我聘请了一位导师来回答我在开发过程中遇到的问题，而那些项目进行得相当不错。它们还有额外的好处，即教会了我如何构建我经验有限的高级功能。

总之，在为客户管理高级功能时，不要让你的缺乏经验阻止你获得工作。作为自由职业者，你可以访问几乎无限的资源来帮助你构建任何项目。

### 一个警告

在你出去接手十几个你完全不知道如何构建的工作之前，让我加一句警告。

我见过自由职业者甚至大型软件开发机构采取这样一种做法：认为他们只需雇佣外包人员来为他们做所有工作。这种做法每次都会失败。

要与外部承包商合作，你需要每天与他们合作。你是否注意到本章中我处理的移动应用程序的前提之一是我与移动开发者有清晰的沟通渠道？

如果我只是给他一份需求清单然后等待成品，项目就会惨败。与承包商合作通常与自己写代码一样耗时。所以，不要认为外部承包商是会为你做所有工作的魔法子弹。

## 第 26 章. 自由职业者访谈 – 接手遗留应用程序的实用技巧

在本章中，我采访了一位我非常尊敬的自由职业开发者 Derek Harrington。事实上，当我决定推出 DevCamp 时，我不得不放弃了我的一批自由职业客户。而 Derek 是我把大部分客户交给的人。基于我多年来与他的经验，我知道他会很好地照顾客户，并且他们会对他的专业知识感到满意。

在本章中，我向 Derek 提出了一些与自由职业相关的问题。具体来说，我们讨论了接手遗留应用程序的实用技巧。

Derek 的技巧当然可以适用于任何开发者，无论你是自由职业者还是不是在你目前的情况下——这就是为什么我建议任何开发者都学习 Derek 对这种常见编码情况的自由职业方法！

### 你接手遗留应用程序时做的第一件事是什么？

编写测试。当你识别出需要重构的代码部分时，先编写规范来覆盖该功能的功能，然后重构代码并确保你的测试仍然通过。

### 过去在接手遗留应用程序时，对你有效还有哪些其他实用技巧？

在评估遗留代码库时，如果你能接触到之前的开发者，就利用他/她。依靠他们获取信息。问诸如“他会怎么做不同？”、“他真的很想重构但从未有时间处理的代码片段是什么？”、“代码中他/她最自豪的部分是什么？”之类的问题。
