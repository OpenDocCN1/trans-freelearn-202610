
## 实现网络压缩

在 MongoDB 中启用压缩非常简单，且只需最少的配置更改。您可以在建立与数据库的连接时，通过连接字符串指定首选的压缩算法：

```
mongodb://hostname/?compressors=snappy,zlib
```

建立连接时，客户端和服务器会协商从提供的列表中选择最佳的相互支持的压缩算法。如果指定了多个算法（如前例所示），它们将按从左到右的偏好顺序进行评估。

默认情况下，MongoDB 部署已配置为启用压缩；然而，除非客户端指定 compressors 配置，否则客户端与集群之间的消息不会被压缩。使用适合您特定需求的算法启用网络压缩，可以在保持出色性能的同时降低 MongoDB 部署的网络利用率。

## 无服务器环境的连接策略

由于其临时性和独特的执行模型，在无服务器环境中管理连接会带来独特的挑战。本节探讨了针对无服务器函数（AWS Lambda、Azure Functions、Google Cloud Functions）的全面 MongoDB 连接策略，涵盖临时执行上下文、冷启动、扩容期间的连接突发以及资源限制等基本挑战，然后介绍实用的实现模式，包括连接池优化、函数处理程序外部的初始化技术以及在调用之间保持连接持久性的方法——所有这些都旨在帮助您构建具有可靠 MongoDB 连接性的弹性、高效的无服务器应用程序，同时最大限度地降低成本并提高性能。

无服务器函数按设计是临时的，带来了独特的连接管理挑战：

- **临时执行：** 函数启动、处理请求，并可能在任何时候被终止
- **冷启动：** 新的函数实例必须建立新的连接
- **连接突发：** 许多并发函数调用可能导致连接峰值
- **资源限制：** 函数实例具有内存和 CPU 限制

对于无服务器环境而言，最关键的模式是在函数处理程序外部初始化 MongoDB 客户端和连接池。让我们看一下以下示例，以便更好地理解：

```
const { MongoClient } = require('mongodb');
// MongoClient now auto-connects so no need to store the connect()
// promise anywhere and reference it.
const client = new MongoClient(process.env.MONGODB_URI);

export const handler = async() => {
  const databases = await client.db('admin').command({ listDatabases: 1 });
  return {
    statusCode: 200,
    databases: databases
  };
};
```

此代码演示了针对 AWS Lambda 专门优化的 MongoDB 连接模式的实现，但也可以改编用于其他无服务器环境。

MongoClient 实例在函数处理程序的范围之外创建，这将允许其被重用。故意在处理程序末尾排除 client.close() 应可使连接池在后续调用中保持活跃，从而降低“热”函数调用的延迟。

无服务器环境的连接池通常需要与传统应用程序不同的配置：

- **较小的池大小：** 从较小的 maxPoolSize（3-5 个连接）开始，因为每个函数实例都有自己的池
- **更低的空闲超时：** 设置更短的 maxIdleTimeMS 限制，以便更快地释放未使用的连接
- **避免过多的最小池：** 使用 minPoolSize: 0 以防止维护可能未使用的连接
- **设置适当的等待队列超时：** 与函数执行时间限制相匹配

在无服务器环境中采用适当的连接策略可以帮助缓解这些临时函数典型的一些挑战。通过使用优化的参数在函数处理程序外部策略性地初始化连接池，开发人员可以缓解冷启动和连接突发，确保持久、低延迟的数据库交互。

## 摘要

有效的 MongoDB 连接管理对于构建高性能、弹性应用程序至关重要。在本章中，我们探讨了网络堆栈如何成为数据库架构的关键基础，从延迟、连接频繁变化和饱和等基本网络因素到 MongoDB 的线协议和连接生命周期的技术细节。

连接池是最具影响力的优化技术，通过重用 TCP 连接并在多个操作之间分摊身份验证成本，显著提高应用程序性能。正确实现需要了解客户端池配置参数和相应的服务器端限制。MongoDB 的 maxIncomingConnections 参数与操作系统文件描述符限制之间的关键关系值得特别关注，因为这些设置共同决定了高峰流量期间的连接容量。

不同的计算环境需要特定的连接管理方法。对于无服务器部署，请在函数处理程序外部初始化连接池，并使用具有适当超时值的较小池。在分布式架构中，根据网络特征调整超时设置，并在可能的情况下利用感知本地性的路由。

对客户端指标（如池利用率和等待队列时间）进行定期监控，结合来自 serverStatus 的服务器端指标，可以全面了解连接健康状况。这种可观测性使您能够通过早期检测和适当的规模调整来防止级联故障。

通过在整个技术堆栈中实施这些技术原则，您将开发出即使在具有挑战性的网络条件下也能保持一致性能的 MongoDB 应用程序，确保随着数据量和用户群的扩大，可靠性和高效的资源利用。

下一章深入探讨 MongoDB 的索引和查询模式，检查查询执行生命周期，分析 explain 输出，并通过日志诊断慢查询。它还涵盖了掌握 MQL 语义与适当的索引使用，并利用专用集合和功能来优化整体数据库性能。
