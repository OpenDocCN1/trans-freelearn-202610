Together, these features offer a robust and reliable foundation for building real-time applications that respond to data changes, while maintaining consistency and resilience, even in the face of disconnections or server failures.

# How change streams work: From write operations to events

Change streams are built on MongoDB’s replication infrastructure. Understanding this connection helps explain both their capabilities and limitations. At a high level, a client application is notified of a change through the following steps:

+   1. Part of the client application performs a write operation on a MongoDB collection.
+   2. The operation is recorded in the primary’s oplog.
+   3. The change stream feature monitors the oplog for majority-committed entries.
+   4. Raw oplog entries are transformed into a more developer-friendly format.
+   5. Events are delivered to client applications through an open cursor.
